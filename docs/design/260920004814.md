# キューブの強化を停車時に展開するタイルで見せる

## 背景

プレイの手応えに穴がある。緊張が薄い。通貨に使い道がない。単調にアイテムを集める作業感がある。これらは「集めたものが向かう先、すなわち目的ループが無い」1つの穴の側面である。loot は価値になり通貨になるが、そこで行き止まる。

このゲームの正体は痩せたサバイバル、すなわち単一の重量→燃料経済・overworld 主軸・別ステージなし・安全希少・パーマデス・キーボードで軽い、北へ賭けて進むロードトリップである。強化の対象として乗り物は自然で、強化がフィールドにタイルとして見えれば飾りの空間を持たずとも達成感が出る。

「自分の空間を育てる」拠点系はこの正体と対立してきた。歩ける内部を実装したが、別ステージ機構・残存する Depth:1 層・安全な部屋の3点で撤去済み。多タイルのリグは表示は理想だが、多タイル移動の実装が重い。そこで**移動は1タイルのまま、表示だけをタイルレベルにする**。停車時にモジュールを展開し、運転時は畳む。

## 要件

- 拾った素材と通貨の出口をキューブの強化にし、収集に意味を与える。
- 強化は乗り物の到達能力に限る。航続・積載・走破・堅牢・道具。安全すなわち暖・シェルター・安全睡眠は与えない。安全希少を守る。
- 停車時に強化がフィールドのタイルとして見え、歩いて近づいて使える。タイルレベルの達成感と hands-on を出す。
- 運転時はモジュールを畳み、キューブは1タイルとして動く。多タイル移動を実装しない。
- モジュールは拡大でき、拡大すると展開に広い空きタイルが要る。止める地形が拠点の使い方を縛る。
- 別ステージ・深さ層・第二の容量軸を足さない。重量→燃料を単一の資源軸に保つ。キーボードで軽く保つ。
- 死で強化を失う。パーマデス。

## 設計

キューブに取り付けた強化モジュールの集合を1つの保存対象 component に集約する。

```go
// CubeUpgrades はキューブへ取り付けた強化モジュールの集合。保存対象で、死で失う。
type CubeUpgrades struct {
	Modules []CubeModule // 取り付け済み。展開中に各モジュールを footprint ぶんタイル展開する
}

// Deployed はキューブが展開中であることを表すマーカー。付いていれば展開中、無ければ収納中。
// 徒歩・運転と同じく明示状態で、運転は収納中のみ許す。
type Deployed struct{}

// CubeModule は取り付けた1モジュール。Tier を上げると展開 footprint と効果と重量が増える。
type CubeModule struct {
	ID     CubeModuleID
	Tier   int                       // 拡大段
	Offset consts.Coord[consts.Tile] // キューブからの相対配置。展開のたびにこの位置へ復元する
}

// CubeModuleID は強化モジュールの同定子。効果・見た目・footprint・重量・コストの定義はデータ側に持つ。
type CubeModuleID string
```

### 収納中と展開中の2モード

キューブは徒歩・運転と並ぶ明示状態として、収納中と展開中の2モードを持つ。`Deployed` マーカーの有無で表す。

- **収納中**。キューブは1タイル。既存の運転で動ける。収納・Auction のクイックメニューは従来どおり開ける。
- **展開中**。各モジュールを保存した `Offset` の位置へ spawn する。収納タイル・作業台タイル・燃料タイルが見え、隣接して調べると使える。作業台など本格機能はここで使う。運転はできない。モジュールタイルは通行可能で、プレイヤーも敵も入れる。囲って安全にはしないので、展開中の野営に敵は踏み込める。
- **遷移は停車中の明示アクション**。停車中のキューブで展開・収納を選ぶ。運転を始めるには先に収納する。畳むのは1アクションで、モジュール単位の手作業は要らない。
- **展開は全か無か**。展開時にキューブと全モジュールの占有タイルがすべて空いているかを判定する。空きとは、通行可能な地形で壁・不可通行の物・敵がいないこと。プレイヤーの立ち位置は障害にしない。すべて空いていれば保存した配置をそのまま復元し、1タイルでも塞がれていれば展開を拒否する。部分展開はしない。これで保存配置を毎回そのまま復元でき、位置の所有が保たれる。
- **地形が展開場所を縛る**。広く広がる配置ほど広い開けた場所が要る。コンパクトに組めば多くの場所で展開でき、贅沢に広げれば全開できる場所が限られる。止める場所の選択と地形読みが生まれる。
- **展開タイルは導出**。保存せず `CubeUpgrades` と `Deployed` から spawn して導出し、収納で despawn する。見えるタイルはその投影。
- **`Deployed` は保存しない**。実行時マーカーなので `skipComponents()` へ入れ、ロード時は収納中から始める。`Driving` と同じ扱い。保存する真実は `CubeUpgrades` だけになる。

### 配置編集

- **追加時は自動、並べ替えは任意**。モジュールを取り付けると近傍の空き `Offset` を自動で割り当てる。位置を変えたいときだけ停車中の配置編集モードを開いてカーソルで並べ替え、`Offset` を保存する。展開のたびにこれを復元する。毎回の配置操作は強いない。
- **向きは固定**。配置はワールド軸で回転しない。復元も全か無か判定も1通りで軽い。プレイヤーはコンパクトに組んで狭所へ対応する。
- **有界**。`Offset` はキューブから小半径に収める。際限ない散開を防ぎ判定を有界にする。重なりは編集時に弾く。配置の大きさは展開に要する開けた場所の広さに直結し、コンパクトか贅沢かはプレイヤーの設計判断になる。

### 拡大と展開スペース

- モジュールの Tier を素材で上げると、展開 footprint が大きくなり効果と重量も増える。
- 展開は全か無かなので、配置全体が収まる開けた連結タイルが要る。Tier を上げ配置が大きいほど広い空きが要り、森や廃墟の狭所では展開できず、開けた場所で全開する。止める地形が拠点の使い方を縛る。
- 狭所でも展開したいなら配置を小さく設計する。モジュール単位の部分展開はしない。コンパクトか贅沢かはプレイヤーの選択で、全開は開けた場所の報酬になる。

### 経済と緊張

- **材料 sink**。強化と拡大は拾った素材で払う。同じ素材が燃料・修理・道具と競合し、投資と生存がトレードオフになる。
- **重量と燃費**。モジュールは Tier で重くなり、既存の重量比例 `DriveFuelCost` を押し上げる。畳んでいても重量は効くので、充実と機動のジレンマは常にある。
- **露出**。展開するほど自分が広がって無防備になる。腰を据えるほど隙が増える。
- **通貨は副 sink**。Auction は行商で買えないモジュール部品や弾薬・希少燃料に限り、到達距離への投資と読み替える。
- **パーマデス**。死で `CubeUpgrades`・積荷・北進を失う。保存はラン単位。

効果は読み取り時に導出し焼かない。航続や燃費や積載は `Modules` から都度計算する。

## なぜこの形か

- **正体に沿って達成感を出す**。空間の所有でなく、乗り物の能力が伸び、それが停車時にタイルで見えることを達成感の源にする。痩せたサバイバルの賭けと矛盾しない。
- **多タイル移動を避ける**。大変なのは多タイル移動であって多タイル表示ではない。停車時だけ展開し運転時は1タイルに畳むことで、移動を無改造に保ちつつタイルレベルの表示を得る。
- **位置の所有を保つ**。プレイヤーが設計した相対配置を展開のたびに復元する。展開を全か無かにすることで、地形で削らず保存配置をそのまま出せる。配置の設計そのものが自分の空間になる。
- **地形を資源にする**。全 footprint が収まる開けた場所でしか展開できないので、止める場所の選択と地形読みが生まれる。コンパクトか贅沢かの配置設計が、展開できる場所の広さと引き換えになる。多タイル移動なしで拠点の戦術性を足せる。
- **安全希少を守る**。強化を乗り物の能力に限り、展開タイルを露天に置くので、キューブが育っても外の北は危険なままである。
- **単一軸を保つ**。強化は重量→燃料の同じ軸に乗る。第二の容量軸もパズルも足さず、キーボードで軽い。

## 採用しなかった方法

- **歩ける内部（異空間）**。所有・hands-on・拠点リズムを完全に満たすが、別ステージ機構・Depth:1 層・安全な部屋の3点で過去に撤去済み。同じ轍を踏む。
- **多タイルで運転する連結リグ**。表示は理想だが多タイル移動の実装が重い。停車展開で表示だけ取り、移動は避ける。
- **グリッド収納**。重量とは別の第二の容量軸を持ち込み他機構を変え、パズル性は狙いでなく、キーボードで扱いにくい。
- **単一タイルへの overlay 装飾**。1マスに重ねるだけではタイルレベルの手応えが出ない。停車展開でタイルとして見せる。
- **自動フィット配置・開く向きだけ選ぶ**。手間は最小だが位置の所有が薄い。全か無かの展開なら保存配置をそのまま復元でき地形とも衝突しないので、位置の所有を取れる手配置を採る。
- **恒久チル、すなわち死で強化を残す**。緊張が失われる。パーマデスで周ごとに全喪失させる。

## コメント

要決定のサブ項目を残す。いずれも人の判断が要る。

- モジュールの初期セットと Tier ごとの footprint・コスト曲線。balance で詰める。
- 拡大で footprint が伸び隣の配置と重なる場合の扱い。編集モードへ促すか自動でずらすか。
- 展開拒否の見せ方。空きが足りないときのメッセージや目印。
- 展開/収納の spawn/despawn の実装。既存の prop spawn を流用できるか要調査。
- 運転中の表示の妥協。1タイルの小 overlay 目印を足すか。
- Auction の統廃合。balance の凍結ゲートへの影響は着手時に再 pin する。
