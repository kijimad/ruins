# キューブに圧縮中と展開中の状態を足す

## 背景

プレイの手応えに穴がある。緊張が薄い。通貨に使い道がない。単調にアイテムを集める作業感がある。これらは「集めたものが向かう先、すなわち目的ループが無い」1つの穴の側面である。狙いは、乗り物キューブを強化の対象にし、強化がフィールドにタイルとして見えることで達成感を出すこと。ただし強化の progression は大きいので、まず土台となる**圧縮中と展開中の状態**だけを足す。

このゲームの正体は痩せたサバイバル、すなわち単一の重量→燃料経済・overworld 主軸・別ステージなし・安全希少・パーマデス・キーボードで軽い、北へ賭けて進むロードトリップである。歩ける内部は過去に別ステージ機構・Depth:1 層・安全な部屋の3点で撤去済み。そこで別ステージでなく、停車時に既存機能をフィールドのタイルとして展開し、運転時は1タイルに畳む状態を導入する。多タイル移動は実装しない。

今回のスコープは展開状態の土台のみ。プレイヤーが積む強化モジュール・拡大・素材 sink・配置編集は、この状態の上に載せる将来の層として最後に触れる。

## 要件

- キューブに圧縮中と展開中の2モードを足す。徒歩・運転と並ぶ明示状態にする。
- 展開中は、キューブの既存機能を**固定レイアウトのタイル**としてフィールドに出し、歩いて近づいて使えるようにする。1マスに詰めたメニューを空間へ開く。
- 運転は圧縮中のみ許す。展開中は運転できない。
- 展開は全か無か。固定レイアウトの全タイルが空いていれば展開し、1タイルでも塞がれていれば拒否する。
- 展開タイルは実行時のみで保存しない。安全地帯にしない。展開中も露天で敵が踏み込める。
- 別ステージ・深さ層・第二の容量軸を足さない。多タイル移動を実装しない。キーボードで軽く保つ。

## 設計

キューブが展開中であることをマーカーで表す。徒歩・運転と同じ明示状態にする。

```go
// Deployed はキューブが展開中であることを表すマーカー。付いていれば展開中、無ければ圧縮中。
// 実行時マーカーで保存しない。運転は圧縮中すなわち Deployed が無いときのみ許す。
type Deployed struct{}
```

### 圧縮中と展開中

- **圧縮中**。キューブは1タイル。既存の運転で動ける。収納・Auction のクイックメニューは従来どおり開ける。
- **展開中**。キューブの既存機能を固定レイアウトのタイルへ spawn する。収納タイル・Auction タイル・給油タイルが見え、隣接して調べると使える。運転はできない。タイルは通行可能で、プレイヤーも敵も入れる。囲って安全にはしないので展開中の野営に敵は踏み込める。踏み込まれても展開タイルは壊れない。
- **遷移は停車中の明示アクション**。停車中のキューブで展開・圧縮を選ぶ。運転を始めるには先に圧縮する。畳むのは1アクション。
- **展開は全か無か**。野営 `CubeDeployCampRadius` 内、すなわちチェビシェフ距離2の 5x5 から中心を除いた範囲が空いているかを判定する。空きとは、通行可能な地形で壁・敵、そしてフィールドのアイテムや prop が無いこと。草の prop も塞ぐ物として扱う。プレイヤーの立ち位置は障害にしない。すべて空いていれば展開し、1タイルでも塞がれていれば拒否する。部分展開はしない。判定範囲を圧縮時の畳み込み範囲と同じにするので、展開できたら野営全体は空だと保証され、圧縮で畳む物はすべてプレイヤーが後から置いた物になる。草が濃くて展開できないときはプレイヤーが手で草を壊して場所を空ける。地形と置かれた物が展開場所を縛り、開けた場所を作る判断が生まれる。
- **展開状態は保存する**。`Deployed` マーカー、展開中にフィールドへ出した貨物、圧縮中の `LocationStowed` 貨物をすべて保存し、展開中でも圧縮中でも保存時の状態のまま復元する。エリアを囲むレーザー壁は `Deployed` から毎フレーム導出するので保存不要で、宙に浮いた投影も生じない。

### レイアウト

- 今回は固定レイアウト。既存機能のタイルをキューブの周りの決まった相対位置へ置く。プレイヤーは配置を編集しない。
- 位置はキューブを中心とした野営 `CubeDeployCampRadius` 内に取り、全か無か判定を有界にする。キューブ自身のタイルには重ねない。

## なぜこの形か

- **土台を先に入れる**。強化 progression は大きいので、まず圧縮中と展開中の状態と全か無かの展開だけを固めて、後から強化を上へ載せる。状態を単一マーカーに隔離しておけば将来の追加が安い。
- **正体を守る**。別ステージでなく状態、深さ層でなく主軸マップ上のタイル、安全な部屋でなく露天の展開にする。多タイル移動は避け、移動は1タイルのまま。
- **全か無か**。固定レイアウトが収まる場所でのみ展開することで、判定が単純で有界になり、地形読みの戦術性が多タイル移動なしで生まれる。
- **安全希少を守る**。展開タイルを露天に置き、暖・シェルターを与えないので、展開しても外の北は危険なままである。

## 採用しなかった方法

- **歩ける内部（異空間）**。別ステージ機構・Depth:1 層・安全な部屋の3点で過去に撤去済み。同じ轍を踏む。
- **多タイルで運転する連結リグ**。移動の実装が重い。停車展開で表示だけ取り、移動は避ける。
- **グリッド収納**。重量とは別の第二の容量軸とパズルとキーボード操作が合わない。
- **今回から強化 progression を入れる**。モジュール追加・拡大・素材 sink・配置編集は展開状態の上に載る層で、土台を固めてから足す。下の「将来」を参照。

## 将来: 強化 progression（今回スコープ外）

展開状態の上に、プレイヤーが積む強化を載せる。ここは実装しないが、土台をこの方向へ縛らないための記録。

- 取り付けた強化モジュールの集合を保存 component `CubeUpgrades` に持ち、素材で取り付け・拡大する。強化は乗り物の到達能力に限り、暖・シェルター等の安全は与えない。
- 展開中はモジュールを保存した相対配置 `Offset` へ復元する。配置は停車中の編集モードで決め、全か無かで復元する。拡大すると footprint が広がり、より開けた場所でしか全開できない。
- モジュールには重量があり、畳んでいても `CubeWeight`→`DriveFuelCost` に効く。充実と機動がトレードオフになる。素材 sink が生存と競合し、パーマデスで失う。
- 強化は溶接機・工作台などの **prop** として野営へ配置する。ここが現在の往復と噛み合う。今は stow を `Item` だけに絞り、草・木などの自然物 prop を除いている。プレイヤーが置いた設備 prop はこの往復に含めたいので、自然物と設備を区別する印、例えば配置可能を表すマーカーを設備側に付け、stow はアイテムとその印を持つ prop を畳み込むよう広げる。展開時の復元も貨物と同じ相対オフセットに乗せられる。
- メタ持ち越しはさらに別の層で、これも将来。

### 燃料とアイテムの往復

展開は装飾タイルを置かない。野営そのものは、プレイヤーが置いたアイテムである。圧縮でそれを畳んで持ち運び、展開で置いた配置のまま出し直す。貨物は燃料タンクと別ロケーションにして混ぜない。

- キューブメニューの汎用アイテム収納は廃し燃料投入専用にする。燃料投入は可燃物だけを受け入れ、運転燃料に充てる。燃料は `LocationInStorage` に入る。
- 貨物は燃料と別ロケーションで分ける。圧縮で野営内のフィールドアイテムを `LocationStowed` へ移す。これは Backpack/Storage/Equipped/Field と排他のロケーションで、燃料タンク `LocationInStorage` とは別枠。よって `CubeFuelTotal`/`ConsumeCubeFuel` は燃料タンクだけを見れば貨物が混ざらない。展開で `LocationStowed` を外しフィールドへ戻す。貨物の重量は `CubeWeight`→`DriveFuelCost` に効くので、積むほど燃費は悪化する。
- 置いた配置を保つ。`LocationStowed` はキューブからの相対オフセットを持ち、展開で `キューブ位置＋オフセット` へ戻す。運転で移動しても配置を保って野営を再現する。
- 畳み込む範囲はキューブ中心のチェビシェフ半径2、斜めも含む。容量に入る分だけ畳み込み、超過分は足元に残す。容量判定はキャッシュでなく実測の総重量、すなわち燃料と貨物の合算を基準にバッチ内で加算する。
- 展開はタイルを置かないので地形の空きは要らず常に成功する。`LocationStowed` はロケーションとして保存される。ロードは圧縮中から始まるので貨物は畳まれた状態で復元される。展開中に保存した場合は貨物がフィールドに残り、次の圧縮で畳み直す。
- キューブは出荷場所も兼ねる。出荷は落札済み(`AuctionSold`)の品だけを集荷する。燃料タンク `LocationInStorage` を出荷元と共有するため、燃料を出荷しないよう落札済みに限る。貨物は `LocationStowed` で分離済みなので出荷対象に混ざらない。

### パフォーマンス

`Deployed` と `LocationStowed` の2コンポーネント追加で ECS のアーキタイプ分割が増え、ベンチで `aiinput` の `ProcessAll` が最大+28%回帰する。エンティティ数に比例するが、現行の規模では実フレーム予算に収まるので許容する。将来さらにコンポーネントを足す前に、アーキタイプ分割のコストをまとめて見直す。

### 将来: 燃料タンクとオークションの分離（オークション撤去後）

貨物は `LocationStowed` で燃料タンク `LocationInStorage` から分離済み。残る同居は燃料とオークション出荷待ちで、両者が `LocationInStorage` を共有し `AuctionSold` で区別している。オークションは撤去予定なので、撤去すれば `LocationInStorage` は燃料タンク専用になり、出荷を落札済みに限る但し書きも消える。撤去まではこのまま据え置く。

## コメント

当初の要決定は、樽を撤去して野営をアイテムの相対往復とエリアを囲むレーザー壁で表す設計へ切り替えたことで、ほぼ解消した。

- 固定レイアウトの形・spawn/despawn・クイックメニューとタイル interact の重複は、タイルを置かない設計にしたので不要になった。
- 展開拒否の見せ方は「Not enough open space to deploy.」をログに出す。エリアの目印はレーザー壁が兼ねる。
- 残る検討は運転中の表示だけ。今はキューブを常に1タイルで表す。小 overlay 目印を足すかは将来検討する。
