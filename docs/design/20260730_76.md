# ダイス表記による確率指定の共通化

## 背景

確率の表現力を上げ、より奥深い体験を得たい。現状は「一様抽選」しか表現できず、`3d6` のように
中央へ寄る分布や、`2d4+1` のような複合を指定できない。

現状の抽選は次のように散らばっている。

- **同一の一様抽選式が3箇所に重複**している。いずれも `min + rng.IntN(max-min+1)`。
  - `internal/world/lifecycle/disassembly.go` の `rollAmount`。分解産出個数の `amount`..`amountMax`。
  - `internal/mapspawner/spawner.go` の収納戦利品個数 `lootCountMin`..`lootCountMax`。
  - `internal/mapplanner/lib.go` の `SpawnEntry.PackSize`。敵/アイテムのパック数 `packMin`..`packMax`。
- **`Dice` 型は既に存在するが未公開で局所的**。`internal/mapplanner/interior/content.go` に
  `Dice{Base, Sides, Bonus}` と private な `roll` があり、内装の配置個数だけがダイス方式。
  文字列パーサは無く、データは `Dice{Base: 2, Sides: 4}` の構造体リテラル直書き。
- doc73 に「個数のダイス表記は導入せず amount/amountMax の一様抽選にした。ダイスパーサが
  存在せず」と乖離ノートが残る。本 doc はその保留を解消する。PR #547 レビューでの
  kijimad の「今後別PRでやるべき」を受けた別PR。

**文字列スカラを Go 側でパースする前例がある**。`consts.ParseWeight` は `scalar Weight extends string`
なTypeSpecフィールド `"500 g"` を `Milligram` へ変換する。ダイス表記 `"1d3+1"` はこれと同型で作れる。

## 要件

- 共通の `Dice` 型を1つ定義し、文字列 `"1d3+1"` とパース相互変換する。表記はどこでも同じ。
- どこでも使える。分解産出・収納戦利品・スポーンパック数・内装配置を同じ型へ集約する。
- 決定的に抽選する。既存の `world.Config.RNG` を引数で渡す。共有RNGを汚さない。
- 既存挙動を壊さず移行する。一様抽選 `[a,b]` はダイスで無損失に表現できる。
- serde 安全。保存対象コンポーネントに載っても壊れない。struct は int 3つのみ。

## 設計

### Dice 型（`internal/consts`）

`Weight`(=`Milligram`) と同じ package へ、型・パーサ・抽選・表示をまとめて置く。既存の
`interior.Dice` はこの公開型へ差し替え、局所定義を消す。

```go
// Dice は個数抽選。Base 個の Sides 面ダイスの和に Bonus を足す。1d3+1 は {Base:1, Sides:3, Bonus:1}。
// 定数個数は Sides<=0 とし、そのとき値は Bonus になる。5固定は {Sides:0, Bonus:5}。
type Dice struct {
	Base  int
	Sides int
	Bonus int
}

// ParseDice は "1d3+1" "2d4" "d6" "5" のような表記を Dice へ変換する。動的入力用。
func ParseDice(s string) (Dice, error)

// MustParseDice は失敗時に panic する。固定リテラル・テスト値用。regexp.MustCompile と同じ発想。
func MustParseDice(s string) Dice

// Roll は Base 個の Sides 面ダイスの和に Bonus を足す。Sides<=0 は定数 Bonus。
func (d Dice) Roll(rng *rand.Rand) int

// Min は取りうる最小値。Sides<=0 なら Bonus、そうでなければ Base*1 + Bonus。
func (d Dice) Min() int

// Max は取りうる最大値。Sides<=0 なら Bonus、そうでなければ Base*Sides + Bonus。
func (d Dice) Max() int

// String は正規化表記を返す。ParseDice(d.String()) == d を満たす。表示・往復・ゴールデンに使う。
func (d Dice) String() string
```

### 文字列文法

空白なしの1トークン。大文字小文字を問わず `d`/`D` を面区切りとする。

| 表記 | Dice | 意味 |
|---|---|---|
| `1d3+1` | `{1, 3, 1}` | 3面1個 + 1。範囲 2..4 |
| `2d6` | `{2, 6, 0}` | 6面2個。範囲 2..12、中央寄り |
| `d6` | `{1, 6, 0}` | Base 省略は1。範囲 1..6 |
| `3d4-1` | `{3, 4, -1}` | 4面3個 - 1。範囲 2..11 |
| `5` | `{0, 0, 5}` | 定数5。Sides<=0 |

パースは `strings` で足りる。`regexp` は依存を増やすので使わない。`ParseWeight` と同じ方針。
`Base<0`・`Sides<0`・`Base>0 かつ Sides==0` のような矛盾入力はエラーにし、`validate.go` の
raw 検証に載せる。

### 一様抽選からの無損失移行

一様抽選 `[a,b]` は `1d(b-a+1) + (a-1)` と等価なので、既存データを機械的に移せる。

| 現行 amount/amountMax | ダイス表記 | Dice |
|---|---|---|
| `amount=1, amountMax=3` | `1d3` | `{1, 3, 0}` |
| `amount=2, amountMax=4` | `1d3+1` | `{1, 3, 1}` |
| `amount=5`（max無し） | `5` | `{0, 0, 5}` |

分布は現行と完全一致する。表現力の拡張、たとえば `2d3` の台形分布は、移行後に個別データを
書き換えて初めて効かせる。移行そのものは挙動不変にする。

### スキーマ（TypeSpec → 生成）

`scalar Dice extends string` を `oas/typespec/types.tsp` に追加する。`Weight` と同型。
`req.tsp` の該当フィールドを置換し、`make generate` で `models.gen.go`・`openapi.yml` を再生成する。

```
// types.tsp
scalar Dice extends string;  // "1d3+1" 表記。consts.ParseDice でパースする

// req.tsp（例: DisassemblyYield）
model DisassemblyYield {
  material: string;
  count: Dice;        // 旧 amount / amountMax を1フィールドへ集約
  chance?: Percent;
}
```

raw 層（`internal/raw/raw.go`）で `consts.ParseDice(*y.Count)` して `oapi` → 内部表現へ変換する。
`ParseWeight` の呼び出しと同じ流路。

### 抽選の集約

重複していた3箇所を `Dice.Roll` へ寄せる。`min + rng.IntN(max-min+1)` の手書きを消す。

```go
// 変更前（3箇所で同じ式）
lootCount = countMin + rng.IntN(countMax-countMin+1)

// 変更後
lootCount = dice.Roll(rng)
```

### 内装 Dice の昇格

`interior.Dice` と private `roll` を削除し、`consts.Dice`・`Roll` へ差し替える。内装の
`content_catalog.go` の構造体リテラルはそのまま `consts.Dice{...}` になる。将来は文字列表記へ寄せられる。

### 将来: 武器ダメージのダイス化（別フェーズ・別PR）

確率の奥深さの本命。現状 `calculateDamage` は「武器固定 `damage` + `rng.IntN(6)+1`」で、
振れ幅が常に1..6に固定されている。武器ごとに `damage: "1d6"` `"2d4"` `"1d10"` と指定できれば、
軽武器は安定・重武器は大振れといった性格差を確率で表現できる。ただしバランス再調整と
戦闘ゴールデンへの波及が大きいので、本 doc では基盤 Dice の提供までとし、適用は別フェーズにする。

## 採用しなかった方法

- **新規 `internal/dice` パッケージ**。単一責務としては綺麗だが、`Weight` を `consts` に置く既存
  前例に反し、同種のドメイン数値型が分散する。`consts` へ寄せて一貫させる。ただし `consts` は
  現状 RNG を import しない純粋な値/変換 package なので、`Roll(rng)` で `math/rand/v2` 依存が
  増える。stdlib で循環もないため許容する。パースだけ `consts`・roll は呼び出し側という分離案も
  あるが、型と振る舞いが離れて使いにくいので採らない。`Percent.ApplyInt` が既に振る舞いを持つ
  前例に倣う。
- **amount/amountMax を残し Dice を別フィールドで追加**。二重表現になり、どちらが有効かで混乱する。
  無損失移行できるので置換する。
- **`interior.Dice` を残す**。型が重複し、表記が二本立てになる。公開型へ統合する。
- **`regexp` でパース**。`ParseWeight` 同様 `strings` で足りる。依存を増やさない。
- **武器ダメージまで一括で本 doc に含める**。バランスと戦闘ゴールデンへの波及が大きく、基盤と
  同一PRにすると差分が読みにくくレビュー困難。基盤提供と適用を分ける。

## コメント

- パッケージ配置は **`consts`**、武器ダメージのダイス化は **別フェーズ** で確定した（2026-07-30）。
  型は `Weight` と並べて `consts` に置き、`Roll(rng)` で増える `math/rand/v2` 依存は許容する。
- `String` が `ParseDice` の逆になる正規化を必ずテストし、ゴールデンや save 往復で表記が揺れないようにする。
