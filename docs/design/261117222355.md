# 初期スポーンの墜落現場

## 背景

新しいゲームは、帯の中央の列・開始の行のチャンクの真ん中に一番近い歩けるマスから始まる。参考 codebase: `internal/overworld/driver.go` の `startInitialBand`。開始チャンクに何があるかは見ていないので、置かれる場所はチャンクの分類のくじしだいである。

seed を1000個回して開始チャンクの種別を数えると、次のようになった。

| 開始チャンク | 割合 |
|---|---|
| 荒れ地 | 41% |
| 研究所の区域 | 26% |
| 軍の基地 | 11% |
| 町の区域 | 10% |
| 発電所 | 7% |
| 農場 | 3% |
| 点在ランドマーク | 3% |

研究所の区域は横がいつも帯の全幅の7チャンクで、縦も6〜8チャンクあり、開始の行の入る最初のリージョンに置かれやすい。そのため、最初から研究所の中で始まることが多い。開始地点は、くじの結果で研究所の奥にも荒れ地の真ん中にもなり、最初の数ターンの体験がそろわない。

筋書きは、キューブの故障で極寒の惑星に墜落した宇宙の旅人が、北を目指して生き延びる、というものである。参考 codebase: `docs/design/260912190416.md`。ところが開始地点には、墜落したことを示す物が何も無い。

初期の持ち物は、プレイヤーの行と職業の `startingItems`・`startingEquips` で持たせている。地上に置かれる物は無い。

## 要件

- 新しいゲームは、必ずキューブが墜落した現場から始まる。
- 墜落現場は、文字でなく、物の置き方で筋書きを語る。えぐれた地面、焦げ跡、散らばった残骸、壊れた貨物など。
- 墜落現場には敵を置かない。最初の数ターンは、敵に追われずに現場を調べ、道具を拾い、火で暖まれる。隣のチャンクの区域に置かれた敵が歩いてくることは許す。
- 墜落現場は、最初の手順の練習を兼ねる。火で暖まる、残骸を解体して素材を取る、怪我を手当てする、食べる、寝る、戦う、の道具が手の届くところにある。
- 墜落現場は屋外で、屋根を持たない。キューブを安全地帯にしない今の方針に合わせる。
- 開始チャンクに研究所や軍の基地のような区域が重なっても、半端な区域を作らない。
- 生成は今までどおり、位置と seed の純関数のままにする。

## 設計

### 開始チャンクを墜落現場の専用の種別にする

チャンクの分類に、墜落現場の種別を足す。開始チャンクは必ずこの種別になり、ほかのどの地物より優先する。

```go
const (
	chunkWasteland  chunkType = "wasteland"
	chunkSettlement chunkType = "settlement"
	chunkUrban      chunkType = "urban"
	chunkLandmark   chunkType = "landmark"
	chunkCrashSite  chunkType = "crash_site" // キューブが墜落した開始の現場
)
```

開始チャンクは、帯の中央の列 `cols/2` と開始の行 `SpawnChunkY` で決まる。どちらも帯の形から決まり、seed に依らないので、分類は位置の純関数のままである。開始チャンクを作る処理は1つの関数にまとめ、分類とドライバの開始位置の両方から使う。

```go
// spawnChunkOf は帯の列数 cols と開始の行 spawnRow から開始チャンクを返す
func spawnChunkOf(cols, spawnRow consts.Chunk) consts.Coord[consts.Chunk]
```

今の分類の関数は開始の行を受け取らないので、引数に足す。地図の記号を描く `chunkPlace` がすでに開始の行を受け取っているのと同じ形にする。

```go
func chunkTypeAt(raws rawschema.Raws, runSeed uint64, c consts.Coord[consts.Chunk], cols, spawnRow consts.Chunk) chunkType
func classifyChunk(raws rawschema.Raws, runSeed uint64, c consts.Coord[consts.Chunk], cols, spawnRow consts.Chunk) (chunkType, districtRegion)
func districtAt(raws rawschema.Raws, runSeed uint64, c consts.Coord[consts.Chunk], cols, spawnRow consts.Chunk) (districtRegion, bool)
```

地物の中から呼ぶときは、今の `spawnRowOf(world)` で開始の行を引いて渡す。`spawnRowOf` は帯が無いと0を返すので、帯を作らずに地物を呼ぶテストでは、チャンク `(cols/2, 0)` が墜落現場になる。そうしたテストは開始の行を引数で明示して渡す。

区域が開始チャンクに重なるときは、その区域を丸ごと出さない。区域どうしの重なりを `overlapsAny` で丸ごと外しているのと同じ扱いで、塀や街路の途中に墜落現場が刺さった半端な区域を作らない。外した区域と重なっていた下位の区域は、今の `overlapsAny` が上位の区域を引き直して比べるので、外したままになる。区域どうしの今の連鎖と同じ性質で、開始の近くは区域が出にくくなる。開始の近くは墜落現場と荒れ地で始まるのが目的に合うので、この性質のままにする。

### 地物の判定を分類にそろえる

今の地物のうち、分類 `chunkTypeAt` を見ているのはランドマークと散布だけである。集落は当選くじと区域だけを、道は区域だけを見ている。分類に墜落現場を足しただけでは、開始チャンクが集落の当選なら墜落現場に村が重なり、道も墜落現場を横切る。

| 地物 | 今の判定 | 変える判定 |
|---|---|---|
| 集落 `settlementFeature` | 当選くじと `districtAt` | `chunkTypeAt` が集落か |
| 道 `roadFeature` | `districtAt` | `chunkTypeAt` が市街地か墜落現場なら描かない。区域は開始チャンクに重ならないので、`districtAt` の判定をこれ1つにまとめられる |
| 地図の道 `buildRoadOverlay` の `markRoadPath` | 道の通るチャンクを全て印す | 墜落現場のチャンクは印さない |
| 道の結線 `crossingRoads`・道沿いの判定 `outdoorZoneAt` | 集落の当選くじの勝者と区域 | 変えない |
| 散布 `scatterCatalogForChunk` | 荒れ地のチャンクだけを散らす | 墜落現場のチャンクも荒れ地のカタログで散らす |
| 区域 `urbanFeature` | `districtAt` | 変えない。`districtAt` が開始チャンクに重なる区域を外す |
| ランドマーク・散布 | `chunkTypeAt` | 変えない |

集落も分類で判定すれば、地物の優先度は分類の1か所で決まる。今後の特例も、分類を直すだけで済む。

道の結線は変えず、墜落現場のチャンクの中だけ道を描かない。墜落現場の当選の集落は置かれないが、今も区域に隠れた集落の勝者は道の端点のまま残っているのと同じ扱いになる。道は墜落現場の縁で途切れ、そこから北の集落へ延びるので、「道をたどって北へ」という最初の目標を景色で示せる。結線を変えないので、道沿いの判定 `outdoorZoneAt` も変えずに済む。`outdoorZoneAt` は区域を `regionIn` で直接見るので、開始チャンクに重なって外された区域も、周りのチャンクを道沿いにし続ける。今も区域どうしの重なりで外された区域に同じことが起きており、新しい食い違いではないので、この性質のままにする。

墜落現場の絵は屋外で、チャンクより小さい。絵の外が草も岩も無い素の土にならないよう、墜落現場のチャンクも荒れ地のカタログで散布する。

散布と野外の戦利品は、土の地面 `earth` で、まだ占有されていないマスに置かれる。開始位置は散布の後に決まるので、絵の真ん中やキューブの置き場所が土の地面のままだと、木や岩が乗って開始位置とキューブがずれ、野外の戦利品も乱数で落ちる。そこで、墜落現場の地面には、えぐれた地面や焦げた地面のような、土でないタイルを使う。散布も野外の戦利品も現場の中には入らず、絵の外の余白にだけ置かれる。現場の中の物は、絵とパレットで置いた物だけに決まる。

### 墜落現場は手描きの施設の絵で作る

墜落現場は施設の1つとして、raw の `facilities` に行を持ち、手描きの絵とパレットで作る。候補は、ランドマークと同じく、施設の行を指して重みを持つ行にする。

```cue
// 開始チャンクに置く墜落現場の候補
#CrashSite: {
	// 施設の id。施設の絵の facility が指す
	id!:    #EntityID
	id_ref: _facilityIDs[id] @rawgen(-)
	// 開始チャンクでこの墜落現場を引く重み
	weight!: int32 & >=1
}

#Raws: {
	// 墜落現場は必ず置くので、候補は1つ以上要る
	crashSites!: [#CrashSite, ...#CrashSite]
}
```

```toml
[[facilities]]
id = "crash_site"
enemyTable = "ruins_area"
zones = []

[[crashSites]]
id = "crash_site"
weight = 1
```

開始チャンクの地物は、墜落現場の候補を seed で引き、絵をチャンクの真ん中に置く。施設の絵の置き方 `spawnFacility` と、戦利品・収納の中身の引き方は、施設と同じものを使う。

施設の絵を選ぶ `planFacility` は、街路へ入口を向けるため、半々の確率で絵を90°回し、半々で左右反転する。墜落現場ではこの変換をせず、`loader.FacilityChunk` で絵をそのまま使う。変換すると、絵の東側が北・南・西のどれかへ移り、キューブを置く東側を空けておく約束が崩れる。墜落現場の絵は縦横とも奇数マスにし、絵の真ん中のマスがチャンクの真ん中にちょうど来るようにする。

地物の一覧には、ランドマークと同じく、区域 `urbanFeature` の後で道 `roadFeature` の前に入れる。施設を置く地物より前の地物は土の地面以外を置かない、道は他の地物の後、散布は最後、という今の順の約束に合わせる。

施設の行は敵の表を必ず持つが、敵の表が使われるのは絵に敵のマスがあるときだけである。ランドマークの施設と同じく、敵の表は既存の `ruins_area` を指し、墜落現場の絵には敵のマスを置かない。

### 中身はパレットで置く

墜落現場の中身は、パレットの地形・置物・床の戦利品・敵で置く。新しいコードは要らない。

| 目的 | 置く物 | パレットの欄 |
|---|---|---|
| 墜落を語る | えぐれた地面、焦げた地面、散らばった残骸。地面は土でないタイル | `terrain`・`props` |
| 火で暖まる | 燃えている残骸 | `props` |
| 解体の練習 | 解体できる残骸の置物。道具で素材が取れる | `props` |
| 手当て・食べる・寝る・戦う | 壊れた貨物の容器に、包帯・食料・寝袋・簡単な武器 | `props` の収納と、専用の戦利品の表 `crash_site_cargo` |

壊れた貨物の容器の中身は、墜落現場専用の戦利品の表 `crash_site_cargo` から引く。施設の収納と同じく、パレットの置物が `lootTable` で表を指す。ほかの施設の表を使い回すと、最初に手に入る物が施設の品ぞろえの変更に引きずられる。専用の表にすれば、練習に使う物を墜落現場の都合だけで決められる。

収納の中身は、表から重みで、引く回数 `lootCount` だけ引く。表に包帯・食料・寝袋・簡単な武器を別々の行で並べると、どれかが出ない回がある。そこで、表には1行だけを置き、その行が4種を全て確率 100 で持つアイテムコレクションを指す。表の行は、アイテムグループとアイテムコレクションを同じ id の空間で指せる。引く回数は1回にし、危険度の範囲は全域にして、開始チャンクの深さで外れないようにする。墜落現場の施設の行は荒らされた確率 `lootedChance` を持たないので、容器はいつも中身が入っている。

```toml
[[itemCollections]]
id = "crash_site_supplies"
name = "墜落した貨物の中身"
[[itemCollections.entries]]
id = "bandage"
chance = 100
pack = "1d1"
# 食料・寝袋・簡単な武器も同じく chance = 100

[[itemTables]]
id = "crash_site_cargo"
name = "墜落した貨物"
[[itemTables.entries]]
id = "crash_site_supplies"
weight = 1
minDanger = 0
maxDanger = 100
```

壊れた貨物の容器は、墜落で外へ散らばった荷物である。キューブに最初から入れている既定の貨物 `StowDefaultCubeCargo` は、展開すると貨物が現れる往復を見せるためのもので、別に残す。

燃えている残骸は、熱源 `heatSource` と光源 `lightSource` を持ち、燃料を持たない置物にする。今の焚き火の置物 `fire` は、燃えている状態 `Burning` を着火の行動でだけ付ける。パレットで置くと `Burning` を持たないので燃え尽きはしないが、燃料をくべる対象からも外れ、見た目は焚き火なのにくべられない。そこで、見た目の違う専用の置物にする。解体できる残骸は、置物の解体の欄 `#Prop.disassembly` で、道具の種類と取れる素材を決める。新しい置物の行は足すが、振る舞いは既存のものを使う。

### 開始位置は絵の真ん中にする

墜落現場の絵をチャンクの真ん中に置き、絵の真ん中を歩ける地面にする。チャンクの幅 `chunkW` に対し、奇数マスの幅 `n` の絵の原点は `chunkW/2 - n/2` にする。24 マスのチャンクなら、絵の真ん中がチャンクの 12 マス目にちょうど来る。今の「チャンクの真ん中に一番近い歩けるマス」がそのまま現場の中心になるので、開始位置の印の欄は足さない。燃えている残骸のような通れない置物を真ん中に描くと開始位置がずれるので、真ん中を歩ける地面にすることは絵の約束としてテストで守る。キューブは開始位置から東へ2マスの付近に置くので、その付近も歩ける地面にし、キューブが残骸の向こうへ回り込んで置かれないことも守る。キューブは今までどおりプレイヤーの近くの歩けるマスに置くので、墜落したキューブのそばで目を覚ます形になる。

## 採用しなかった方法

- **建物の避難所にする**: 開始の拠点として分かりやすいが、極寒の惑星に墜落した旅人という筋書きと合わず、屋根のある安全な場所を最初から与えることにもなる。墜落現場なら、筋書きを最初の画面で語り、屋外で寒さにさらされる。
- **区域を残し、開始チャンクだけを墜落現場に置き換える**: 研究所の敷地の中に墜落現場が入り、塀や街路の途中に刺さる。半端な区域を作らない今の原則に反する。
- **区域を開始地点から数チャンク離す**: 最初は荒れ地に囲まれ、少し歩くと建物に着く。ただ、区域の置き方に開始地点の特例を足すことになり、「最初の体験をそろえる」とは別の問題である。
- **絵に開始位置の印を置く**: マスに開始位置の欄を足す必要がある。絵を真ん中に置けば、今の開始位置の決め方で現場の中心に立てる。
- **初期の持ち物を増やす**: 持ち物は職業の行で決まり、物の置き方で筋書きを語ることも、拾う練習もできない。
- **開始チャンクの特例を地物でなくドライバに置く**: 開始のときだけ墜落現場を置くと、チャンクの中身が位置と seed だけで決まらなくなる。地図の記号やエリア名は分類から引いているので、地物の判定も分類にそろえれば、地図と実体が食い違わない。
- **分類の関数に開始の行を渡さず、world から引く**: 引数は増えないが、分類が world に依存し、地図の記号を描く `chunkPlace` のように raws と位置だけで呼べなくなる。
- **墜落現場の当選の集落を道で結ばない**: 結線は `(r-1, r)` と `(r, r+1)` の鎖なので、リージョン r を挟む2本の道がどちらも消え、最初に見つける道が1リージョン分遠くなる。道沿いの判定 `outdoorZoneAt` も直すことになる。
- **墜落現場に弱い敵を置く**: 練習の相手になるが、開始位置の隣に湧くと最初の1手より前に殴られる。最初の数ターンは、敵に追われずに現場を調べられるほうがよい。
- **散布が施設の占有を避ける**: 施設の絵が占めたマスを散布へ渡せば、地面を土のままにできる。ただ、地物どうしで状態を渡す仕組みが要り、地物が互いを知らない今の形から外れる。地面を土でないタイルにすれば、散布の判定を変えずに済む。
- **墜落現場の絵も回転・反転する**: 見た目は変わるが、キューブを置く東側を空ける約束が変換の4通りで崩れる。中心から周り数マスを全て空ける約束にすれば変換に強くなるが、絵の自由が減り、テストも4通りに増える。墜落現場は1つの絵から始めるので、変換しないほうが単純である。
- **開始位置から一定のマスの中に敵がいないことを守る**: 隣のチャンクの区域の敵まで含めて守れるが、区域の置き方に開始の周りの特例を足すことになる。墜落現場の中に敵を置かないことで、最初の数ターンの目的は満たせる。
- **貨物の容器にほかの施設の戦利品の表を使い回す**: 表を足さずに済むが、最初に手に入る物が施設の品ぞろえの変更に引きずられ、練習に使う物がそろわなくなる。
- **燃えている残骸に今の焚き火の置物を使う**: パレットで置いた焚き火は燃えている状態を持たず、燃料をくべる火と見た目が同じなのに振る舞いが違う。

## コメント

- 墜落現場の中身の具体的な配置は、絵を描きながら決める。
- 墜落現場の候補は最初は1つで始め、絵を足すたびに `crashSites` に行を足す。
- `crashSites` を必須にするので、raw を最小限に組み立てて検証するテストにも行が要る。
- 開始チャンクに重なって外れた区域は、道の経路が塀を避ける `fencedDistrictsBetween` の対象からも外れるので、開始の近くを通る道の折れ方が変わる。地図の道も同じ経路の関数を通るので食い違いは出ないが、道や地上の golden は撮り直す。
- 地図の記号とエリア名は分類から毎回引き直すので、すでに始まっているセーブでは、探索済みの開始チャンクの記号とエリア名が、実体の建物と違う墜落現場に変わる。未リリースなので考えない。
