# メニューを世界にだけ透過させる平坦なメニュー層

## 背景

メニューを半透明にして、後ろのゲーム世界を透かして見せたい。ただし条件がある。メニュー同士が重なっても、透けるのは世界だけで、下のメニューは透けない。重なった領域では最前面のメニューだけが見え、透明度が二重にかかって世界が過度に暗くなることもない。

現状の描画はこの要件を満たせない。描画ループは全 state を1つの `target` に下から順に重ねる。スタック[0] は世界を描く `DungeonState`、[1..] は世界の上に push されたメニュー群で、下の state も上の下で描き続ける。

```go
// internal/maingame/game.go 現状。世界もメニューも同じ target へ順に重ねる
for _, state := range game.StateMachine.GetStates() {
	if err := state.Draw(game.World, target); err != nil {
		log.Fatal(err)
	}
}
```

透け感は今、パネルのナインスライス PNG にベイクされたアルファと、モーダル外周を透明にする小細工（`internal/engine/states/lib.go` の `wrapModalRoot`「外周は背景を持たず透明にし、周囲に後ろのフィールドを覗かせる」）で出している。1つの Screen 内のオーバーレイも、Active なものを全て同じ ebitenui UI に `AddWindow` するため合成される。すなわち下のオーバーレイも上の下で描かれる（`internal/menurt/screen.go`）。

このまま各メニューを画面へ順にアルファ合成すると、必ず破綻する。メニュー B を「A が載った状態の画面」に対して合成するので、B 越しに A が透け、かつ世界の減衰が二重にかかる。透明度をパネルごとに持たせる方式では、下メニュー透けと二重掛けは構造的に避けられない。

なお、かつての背景ブラー機構はこの世界とメニューの境目、描画ループの `i == 0` の直後、に差し込まれていた。PR #596 で撤去済みで残骸はない。本 doc はその境目に、ブラーとは別方式で戻ってくる。

## 要件

- メニューは世界に対して半透明にする。透過率は均一にする。
- 重なった領域は最前面のメニューだけを見せ、下のメニューは隠す。
- 透明度の二重掛けを起こさない。世界の減衰は重なり枚数によらず一定にする。
- 可読性のため、薄い暗色スクリムをメニュー層に内蔵する。動きの激しい世界の上でも文字が読めるようにする。
- 入力とフォーカスの挙動は変えない。本 doc は描画のみの変更で、入力の最前面限定は現状のまま。
- 世界すなわちスタック[0] は不透明のまま描く。

## 設計

方針は「平坦化してから一度だけ透過」。透明度をメニュー1枚ごとに持たせず、メニュー層と世界の最終合成に一元化する。個々のパネルは層の中では不透明にして互いを隠す。これが「透明だがメニュー同士は透けない」を両立させる唯一の形になる。

### 描画フロー

1. スタック[0]（世界）は従来どおり `target` に描く。
2. スタック[1..] のメニュー群とその全オーバーレイを、画面サイズのオフスクリーン `menuLayer` に**不透明**で重ねる。重なりは上のメニューが下を上書きするので、下メニューは隠れる。メニューの無い隙間はアルファ0のまま。
3. `menuLayer` を、世界を描いた `target` に**一度だけ**、大域アルファ `menuAlpha` で合成する。

```go
// internal/maingame/game.go 変更後
states := game.StateMachine.GetStates()
states[0].Draw(game.World, target) // [0]=世界は不透明のまま target へ
if len(states) > 1 {
	layer := game.menuLayer.Begin(bounds.Dx(), bounds.Dy()) // 透明クリアした層
	for _, s := range states[1:] {
		s.Draw(game.World, layer) // 不透明パネルで層へ重ねる。重なりは上が下を上書き
	}
	game.menuLayer.Composite(target, menuAlpha) // 世界へ一度だけ透過合成
}
```

メニュー state の `Draw` は受け取った描画先へそのまま描くので、`menurt.Screen` もオーバーレイも `layer` へ自然に描かれる。差し替えは描画ループ1箇所に閉じ、`menurt` 側の変更は要らない。

### メニュー層の型

`screeneffect.Pipeline` と同じく、画面サイズのオフスクリーンを使い回す小さな型にする。責務は層の確保・透明クリア・大域アルファ合成に限る。

```go
// internal/maingame/menulayer.go 新規
// menuLayer はメニュー群を不透明で平坦化してから、世界へ一度だけ透過合成する層。
type menuLayer struct {
	img *ebiten.Image // 画面サイズのオフスクリーン。毎フレーム透明クリアして使い回す
}

// Begin は画面サイズ分を確保し透明にクリアして返す。サイズ変化時は作り直す。
func (m *menuLayer) Begin(w, h int) *ebiten.Image

// Composite は層を dst へ大域アルファで一度だけ重ねる。
func (m *menuLayer) Composite(dst *ebiten.Image, alpha float64)
```

```go
// Composite の要点。透明度は最後の1回だけに持たせる
op := &ebiten.DrawImageOptions{}
op.ColorScale.ScaleAlpha(float32(alpha))
dst.DrawImage(m.img, op)
```

### 透明度とスクリムの一元化

透明度は最後の合成にのみ持たせ、層の中のパネルは不透明にする。パネル自体を半透明にすると `panel_alpha × menuAlpha` の二重掛けが復活し、下メニューも透けるため。

可読性のスクリムは、不透明パネルの背景色にわずかな暗色を混ぜて実現する。層合成で世界は `1 - menuAlpha` だけ滲むので、その滲みが文字のコントラストを落とさないよう、パネル基調を少し暗くして沈める。ブラーは使わず、暗さはパネル色と `menuAlpha` の2つで決まる。

```go
// internal/widgets/theme/colors.go 変更方針。層内は不透明にし、透過は層合成へ一元化
// 変更前            → 変更後
// PanelBackground  A:220 → A:255（わずかに暗色を混ぜる）
// WindowBackground A:240 → A:255
// Overlay          A:200 → A:255
```

半透明前提のパネル画像（`internal/resources/ui.go` の `list-idle-trans.png` 等）は、メニュー層では不透明版に切り替える。`wrapModalRoot` の外周透明の小細工は、世界の透過を層アルファが均一に肩代わりするので撤去する。

```go
// internal/maingame/consts か theme に定数で置く。値は VRT で詰める初期値
const menuAlpha = 0.82 // メニュー層を世界へ合成する大域アルファ
```

### retro シェーダとの順序

`menuLayer` の合成は `screenPipeline.End` の前、すなわち CRT シェーダより手前で行う。メニューにもシェーダがかかり、現状の見えかたを保つ。

### メニュー判定

世界とメニューの境目はスタックの index で決める。[0] が世界、[1..] がメニュー。撤去済みブラーが `i == 0` を境目にしていた前例に倣う。判定用のマーカー interface は再導入しない。

## 採用しなかった方法

- **素の透過のみ（A案）**: 実装は最小だが、動きの激しい世界の上で文字が読みにくい。撤去したブラーが解決していた問題に逆戻りするため、スクリム内蔵の B 案を採る。
- **ブラー再導入（C案）**: 最も読みやすいが、撤去した機構を別実装で戻すことになり重い。スクリムで可読性が足りるなら過剰。
- **トップのメニューだけ描き下を完全に隠す**: 透過は自明に世界に対してだけになるが、重ならない部分の下メニューも消えて情報が失われる。重なっても下の見える部分は残したいので不可。
- **各パネルにアルファを持たせる per-menu 透過**: 二重掛けと下メニュー透けが構造的に避けられない。透明度は層合成へ一元化する。
- **マーカー interface で世界とメニューを判定**: index 方式で足りるので YAGNI。撤去した `states.Configurable` を復活させない。

### 実装で設計から変えた点

- **`wrapModalRoot` の外周透明は撤去しない**。層方式では、パネル画素は不透明で層アルファにより世界が滲み、外周のパネル外領域は層で α=0 のまま世界が全て見える。どちらも要件どおりで、外周透明はむしろ正しい。当初の撤去方針は取り下げた。
- **不透明化は theme の色定数でなく、メニュー限定の不透明ナインスライス `Panel.ImageOpaque` で行う**。`Panel.Image` は HUD の武器スロットと共有し、HUD は世界側に描くため、共有 PNG を不透明化できない。メニューが使う箇所だけを不透明変種に差し替えた。
- **別途スクリムを塗る必要はない**。暗いパネルを 0.82 で世界へ合成すれば、世界の 18% の滲みが自然に沈み、可読性が保てる。スクリムは暗いパネル色と `menuAlpha` の2つに内蔵される。
- **タイトルのメインメニューは据え置く**。ベース state すなわちスタック[0]で層アルファが効かず、不透明化すると独自背景が透けなくなる副作用だけが出るため。
