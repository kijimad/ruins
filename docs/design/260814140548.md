# 背の低い家具を通行可能にして移動コストで体系化する

## 背景

背の低い家具を通行可能にし、乗り越えて進めるが手間取るようにしたい。敵を家具に登らせて余計に AP を消費させ、こちらが多く行動できる、といった戦術的利用を狙う。

調査の結果、この振る舞いを実現する**機構は既に完全に実装済み**だった。新規の仕組みは要らない。欠けているのは家具データの一貫性と設計指針である。

### 既存機構

```go
// internal/components/field.go
// PassCost はフィールド上のタイルの移動コストを修正する。ベースコストへの加算値
type PassCost struct {
	Value int // 移動コスト加算値。0で変化なし、50でコスト+50
}
```

- `activity/activity_manager.go` の `consumePassCost` が、移動アクションのとき移動先タイルの `PassCost` を合算し AP コストへ加算する。基準移動コストは `StandardActionCost = 100`。
- AP は毎ターン `min(現在AP + Speed, MaxAP)` で回復する。よって passCost +50 は Speed 100 の敵にとって約 0.5 手分、+100 なら約 1 手分の遅延になり、戦術として意味を持つ。
- 敵 AI も同じ `activity.Execute` 経由で移動する。ランタイムの敵追跡 `aiinput/planner.go` はプレイヤー方向の候補を順に試し `CanMoveTo` が真の最初のタイルへ進む**貪欲追跡**で、コストを見て迂回しない。ゆえに進行方向にある低い家具を避けず踏み、AP を余計に払う。「登らせて浪費させる」戦術はこの非コスト認識性の上に成立する。
- tsp `Prop.passCost` と `raw.go` の変換は配線済み。`blockPass` と `passCost` は併用禁止で検証される。通行不可なら通行コストは無意味だからである。
- `states/look_around.go` の `drawPassCost` が Look 時に「Move cost」を表示する。

### 現状データの不整合

通行可の家具に passCost を付けたプロップは既に4つある。しかし場当たり的で、同種の家具が別挙動になっている。

| プロップ | blockPass | passCost | 問題 |
|---|---|---|---|
| `sofa` | false | なし | ソファを**タダで素通り**できる |
| `prop_chair` | false | なし | 椅子をタダで素通りできる |
| `pallet` | false | なし | パレットをタダで素通りできる |
| `bedside_table` | false | なし | 小机をタダで素通りできる |
| `chair` | true | なし | 一方でこちらの椅子は通れない |
| `table` | true | なし | 大机も通れない |
| `carpet` | false | 10 | 段階の基準が不明な値 |
| `construction_sign` | false | 30 | 同上 |
| `moving_stone` / `rock` | false | 50 | 同上 |

同じ「椅子」が `chair` は通行不可、`prop_chair` は無コスト素通りと矛盾する。passCost 値も 10/30/50 と基準のない羅列である。

## 要件

1. 背の低い家具は通行可能にし、`PassCost` で移動コストを付ける。乗り越えて進めるが手間取る。
2. 背の高い家具は従来通り `blockPass` で通行不可にする。背丈で通行性を決める。
3. 敵もコストを払う。プレイヤーは家具を挟んで敵に登らせ、AP を浪費させる戦術を取れる。既存機構で成立するため、要件として明文化し壊さない。
4. passCost は意味のある**段階**を持つ。値を家具ごとに自由設定せず、少数の段階語彙から選ぶ。表記ゆれとバランス崩れを防ぐ。
5. 既存のアドホックな passCost プロップと、無コスト素通りプロップを本カテゴリへ整理する。

## 設計

新コンポーネントは作らず、既存 `PassCost` を再利用する。設計の実体は**データの分類規則**である。

### 通行性の二分

家具を背丈で2区分し、`blockPass` と `passCost` の排他で表現する。排他は raw の既存検証が保証する。

- **低い家具** = `blockPass` なし + `passCost` あり。乗り越えられる。椅子・机・木箱・樽・ベッド・ソファなど腰高以下。
- **高い家具** = `blockPass` あり。通行不可。棚・ロッカー・冷蔵庫・自販機・樹木など見上げる高さ。

### コスト段階

基準移動 `StandardActionCost = 100` への加算値を3段階に固定する。家具はこの語彙から選ぶ。

| 段階 | passCost | 加算後の移動AP | 目安 | 該当例 |
|---|---|---|---|---|
| 軽 | 25 | 125 | 敷物・床の散乱物 | carpet, pallet, rubble, debris |
| 中 | 50 | 150 | 椅子・木箱・樽・小机 | chair, crate, barrel, bedside_table, bench |
| 重 | 100 | 200 | ソファ・大机・ベッド | sofa, desk, table, bed, two_seat_sofa |

段階と Speed 回復の関係を戦術の物差しとする。重の家具は加算後 200 AP で、Speed 100 の敵にはほぼ 2 手分。敵が登坂に 1 ターンを費やす間にプレイヤーは 1 手多く動ける。値はいずれも仮値で、実プレイで調整する。

### 分類の適用

現状の不整合を段階語彙で解消する。

- 無コスト素通りを解消する。`sofa`→重100、`prop_chair`→中50、`pallet`→軽25、`bedside_table`→中50。
- 既存 passCost 値を段階へ整列する。`carpet` 10→軽25、`construction_sign` 30→中50、`moving_stone`/`rock` 50→中50。石と標識は家具ではないが「乗り越え障害」として同じ語彙で統一する。
- 低い家具のはずが `blockPass=true` のものを低い家具化する。候補は `chair` `black_chair` `crate` `wooden_crate` `bench` `two_seat_sofa` `table` `prop_table` `work_desk` `desk` `bed` `barrel` `white_barrel` `green_drum` `red_drum`。どれを低くするかは背丈判断が要るため needs-decision とし、進捗で個別に確定する。
- `chair` と `prop_chair`、`table` と `prop_table` のような重複は、低い家具化にあわせて挙動を揃える。統廃合は本 doc のスコープ外とし、まず挙動の一貫化を優先する。

### 敵 AI との相互作用

ランタイム敵追跡は非コスト認識の貪欲追跡であり、低い家具を避けない。これは戦術成立の前提である。AI をコスト認識の経路探索に変えると敵が家具を迂回し、「登らせて浪費させる」戦術が壊れる。あえて貪欲のままにする方針を明記する。

## 採用しなかった方法

- **新規 `Furniture` / `Height` コンポーネント**: 通行コストは `PassCost`、視界の高さは既存 `BlockView` で表現できる。別コンポーネントは二重管理になり不採用。分類はデータ規則で足りる。
- **AI をコスト認識経路探索にする**: 敵が家具を迂回し、登らせて浪費させる戦術が消える。貪欲追跡のまま維持する。
- **家具ごとに passCost を自由設定**: 基準のない値の羅列となり、carpet=10/sign=30 のような現状の不統一を再生産する。3段階の語彙に固定する。
- **家具で乗り越え時にダメージ・罠**: 「手間取る」だけで戦術は成立する。ダメージは体調・トラップの別概念であり今回のスコープ外。
- **低い家具も blockPass 一択にする**: 通行できないと戦術の土台が消える。低い家具は通行可にする。
- **可視化強化を本 doc に含める**: Look で Move cost は既に見える。ゲームログ等の追加可視化は別 doc とし、本 doc はカテゴリ体系化に絞る。
