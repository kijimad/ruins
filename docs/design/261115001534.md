# 地上の生成が置くタイルを、行の欄と性質から決める

## 背景

地上の生成は、置くタイルの id をコードの定数で持っている。

| 箇所 | 定数 | 問うていること |
|---|---|---|
| `streetTerrain` | 街路 `road`、植え込み `grass_green` | 区域の街路に何を置くか |
| `drawHut` | 床 `floor`、壁 `dwall` | 小屋に何を置くか |
| `scatterEarthTiles` | `dirt` と砂3種の一覧 | 草や木を立てられる地面か |
| `replaceDirtTile` | `dirt` との比較 | 道で上書きしてよい地面か |
| `NewOverworldFieldPlanner` | 下地 `dirt` | 地上の下地に何を置くか |

区域と目印は raw に行を持つのに、置くタイルだけがコードにある。タイルを替えるたびにコードを直すことになる。また「草を立てられる地面か」をタイルの id の一覧で判定すると、地面の種類を足すたびに一覧を直すことになる。

## 要件

1. 区域と目印が置くタイルは、その行が持つ。
2. 地面の性質で判定する箇所は、タイルの行の欄で判定する。
3. 全体に1つしかない値は、使うパッケージの定数に残す。2026-11-11 の決定に従う。道のタイル `road` がこれに当たる。
4. 地図の外を表す `void`、厚い壁を虚空にする処理、雪の層の絵 `snow` は、コードの意味そのものなので定数のまま残す。ダンジョンの生成は対象外にする。

## 設計

### 区域が街路と植え込みのタイルを持つ

```cue
#District: {
	// ...
	// 街路のタイル
	street!:    #EntityID
	street_ref: _tileIDs[street] @rawgen(-)
	// 街路の両端に置く植え込みのタイル。省くと植え込みを置かず、建物と道の間を空けない
	verge?: #EntityID
	if verge != _|_ {
		verge_ref: _tileIDs[verge] @rawgen(-)
	}
}
```

植え込みの有無を表していた `verge?: bool` を、植え込みのタイルの id に置き換える。id があれば植え込みを置く。

```go
// streetTiles は区域の街路に置くタイル。verge が空なら植え込みを置かない
type streetTiles struct {
	street string
	verge  string
}

// streetTerrain は街路の帯のマス (x, y) に置くタイルを返す
func streetTerrain(x, y consts.Tile, s streetTiles) string
```

### 目印が小屋の床と壁のタイルを持つ

```cue
#Landmark: {
	// ...
	// 小屋の床と壁のタイル。drawer=hut のときだけ使い、そのとき必須
	hutFloor?: #EntityID
	hutWall?:  #EntityID
	if drawer == "hut" {
		hutFloor!:    _ @rawgen(-)
		hutWall!:     _ @rawgen(-)
		hutFloor_ref: _tileIDs[hutFloor] @rawgen(-)
		hutWall_ref:  _tileIDs[hutWall] @rawgen(-)
	}
}
```

Go の型を生成する都合で、欄は最上位に任意で宣言し、小屋のときだけ必須にする制約を条件の節に書く。

### 土の地面をタイルの行の欄で示す

```cue
#Tile: {
	// ...
	// 草や木を立てられ、道で上書きしてよい土の地面か
	earth?: bool
}
```

- `dirt` と砂の `sand_orange`、`sand_red`、`sand_pink` に付ける。今の `scatterEarthTiles` と同じ集合にする。
- 散布は、この欄を持つタイルにだけ草や木を立てる。
- 道は、この欄を持つタイルだけを上書きする。今は `dirt` だけを上書きしているが、砂は地上に置いていないので挙動は変わらない。

### 地上の下地は区分の行が持つ

地上のチャンクは、道沿い `roadside` と奥地 `wild` の区分を持ち、それぞれ `scatterZones` の行がある。下地のタイルをこの行に持たせる。

```cue
#ScatterZone: {
	// ...
	// チャンクの下地のタイル
	ground!:    #EntityID
	ground_ref: _tileIDs[ground] @rawgen(-)
}
```

区分は位置と seed の純関数なので、生成計画より前に決められる。`chunkgen` が区分の行から下地を引き、計画の型に入れて渡す。

```go
type PlannerType struct {
	// ...
	// 全面を埋める下地のタイル。地上の計画だけが使い、空ならエラーにする
	Ground string
}

// FillGround は全面を計画の下地 MetaPlan.Ground で埋める
type FillGround struct{}
```

- 地上の計画は、全面を `dirt` で埋める `FillAll` の代わりに `FillGround` を使う。
- 下地を渡し忘れると `ErrGroundNotSet` で落ちる。黙って既定の土に戻さない。
- 区分の下地は `earth` 欄を持つタイルに限る。道と散布は土の地面の上にしか置かないので、土でない下地では黙って何も置かれなくなる。読み込みの検査で落とす。
- 生成のギャラリーとテストは、地上の計画を直接呼ぶので下地を明示する。デバッグの進入先には地上の計画が無い。

## 採用しなかった方法

- **役割ごとにタイルを引く表を1つ作る**: 例えば `street` という役割に `road` を引く表。コードは役割名を定数で持つことになり、定数の置き場所が変わるだけになる。
- **地上の生成の設定を表す行を新しく作り、下地と道を持たせる**: 全体に1つの値を raw に置かない、という 2026-11-11 の決定に反する。下地は区分ごとの値として区分の行に置ける。道は全体に1つなので定数に残す。
- **区分の下地が土の地面かを CUE の参照で検査する**: 土のタイルだけの id の集合を作って参照させれば宣言的に書ける。ただ、参照切れと土でない下地の区別がエラーから読めなくなるので、Go の読み込みの検査に置く。
- **土の地面をタイルの id の一覧で持ち続ける**: 地面の種類を足すたびに一覧を直すことになる。性質は行の欄に置けば、データを足すだけで済む。

## コメント

- 道のタイル `road` は、森の生成と地上の道の両方が使うので `consts` に残す。
- 下地を区分ごとに替えられるようになれば、奥地を草の地面にするといった変化をデータだけで作れる。
