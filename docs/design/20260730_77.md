# 拡張可能な移動拠点を中核に据える

## 背景

design.md の原点は、凍った日本のキャラバン交易サバイバルで、必須目的をあえて定めないことでロールプレイの自由を成立させる、というものである。

長らく、帯の一方向強制移動やターン制限が、ロールプレイの自由や拠点への愛着と衝突して見えて迷っていた。議論の末に、迷いの正体が分かった。確信を「キャラバン」という皮に結びつけていたことである。皮はどこか恣意的なので、皮を疑うたびに全部が揺れた。

錨を下ろすべきは皮でなく、皮が抽象していた楽しみのほうだった。この doc は、まず守るべき楽しみを仕様として固定し、その上で現在の器を記録する。器が変わっても、楽しみへの錨は残る。実際、器はキャラバンの隊列から押すキューブへ、内装は建設から家具付けへと変わったが、下の楽しみの仕様はそのつど満たしたまま進めた。

## 要件

### 守るべき楽しみ

これが本当の仕様である。どんな器を選んでも、以下を満たすなら合格とする。

1. **育つ家への愛着** — 投資し、個性を与え、持続する我が家
2. **家を連れて行ける** — 移動しても愛着を失わない。積み上げた家が常に共にある
3. **代償のある蓄積** — 集めるのは楽しい、ただし必ず対価を払う。「何を残すか」が本物の決断になる
4. **意味のある仲間** — 明確な役割を負い、彼らへの愛着が生まれる
5. **賭けのある前進** — 一方向、背後に破滅、安全な籠城なし。緊張して前へ進む推進力
6. **旅の中の自由** — 何をするか、どう生きるかを選び、システムがそれを表現する
7. **停まって暮らす律動** — 停泊して家を使い、道具を使い、また進むリズム

### 避けるべき反・楽しみ

- 単調な作業、いわゆるトイル。際限のない最適化や運搬の細作業
- 移動の抽象化による、一続きの手触りの喪失
- 多タイルの乗り物が持つ実装の複雑さ
- ターン制限のような盤外のハードルールによる、鎖の感触

## 設計

現在の器は、押して進める1つのキューブである。

### 器 — 押すキューブと異次元の内装

- **外**: キューブは専用レーン上の単タイル。左右にしか押せず、ほぼ戻らない。単タイルなので通常のエンティティと同じ扱いで、特別な物理を持たない
- **中**: キューブの内側は異次元の静止した空間。扉をくぐって入る。ここに物を置き、道具を置く

多タイルの複雑さは「歩いて入れる」と「動く」を同時に成立させることから生まれる。キューブはこれを分ける。守るべき不変条件は「回転しない」「移動中に内部を歩かない」の2つで、外で押すのは単タイル、中で歩くのは静止した異次元、という分離がそれを満たす。動く多タイル剛体は存在しない。

外のレーンでの押しはタクタイルなままで、抽象化しない。プレイヤーはキューブを離れて周囲のチャンクを徒歩で探索し、戻って押す。内装は異次元という世界内の虚構で正当化されるので、扉をくぐる感覚であり管理画面ではない。

### 皮 — 無地のキューブに確定する

見た目は無地のキューブに固定する。これは最小の皮であり、凝った絵・大きな器の描画・物語の下地を、まとめて先送りにするための選択である。中が広い謎の箱は異次元の内装をそれ自体で正当化し、説明されない箱は穴に見えない。

代償として、凍った日本というテーマへの手触りの結びつきは今は薄くなる。これは意識的に払う対価である。錨は皮でなく楽しみに置いてあるので、まず押しの機構が楽しみを届けるかをキューブで確かめ、美術と物語への投資はそれが証明された後に行う。機構が先、皮は後。物語の統合は破棄でなく先送りで、後から蔵でも遺物でも被せ直せる。

### 内装 — 建てず、置いて表現する

部屋は建てない。内装は単なる空間で、そこに item や prop を置くことで部屋を表現する。料理器具を置いた一角が台所になり、溶接機を置けば工房になる。部屋の意味は、建てた構造でなく、置いた物から立ち上がる。

- **効果は「置いてあること」から出す。配置からは出さない**。ストーブがあれば暖、溶接機があれば溶接ができる。どこに置いたかは効かせない。自由配置は、位置が何かを最適化した瞬間にトイルへ戻る。presence ベースに徹すれば、家具付けは純粋な自己表現でトイルにならない
- **空間は固定で寛容**。異次元なので広さは最初から余裕があってよい。実質の上限は面積でなく重量が担う。空間を増やしたいなら、建設でなく、より大きなキューブを得るなど非建設の手段にする
- **既存の機構を流用する**。このゲームには prop も item も配置・相互作用の仕組みもある。専用の建設システムを作らず、内装マップに既存の prop エンティティを置く形で済ませる

置くのは世界内の所作で、拾った品を部屋に持ち込んで据える。建設待ち行列のような計画メニューは無い。プレイヤーが読むべき一覧は、総重量と前線への余裕を映す HUD の数字だけである。飾るのは手触り、読むのは重量、と役割が分かれる。

### 重量押し経済 — 1つの数字が全部を担う

この器の心臓は、押しコストという単一の数字である。押しコストは総重量と押し手の力で決まり、別々に設計していた要求を同時に解く。

- **移動圧力**: 押すのは高コストで、歩行の10倍規模のAPを食う。余裕を持って押さないと、いくら前線が遅くても呑まれる。ハードなターン制限は要らない。移動が重い決断で、滞在は無料、遅い凍結がいつか押しを強いる
- **代償のある蓄積**: 置いた物すべてが重量になり、押しがさらに遅くなる。無限の溜め込みが、恣意的な重量上限でなく移動コストとして自分を罰する。あらゆる獲得が「この重さを押す価値があるか」の決断になる
- **仲間の価値**: 押す力そのもの。人数を集め強化すると押しが軽くなる

押しは1タイルずつでよい。1歩ごとに歩行の10倍規模のAPを費やすので、踏むたびに重さが体感できる。連打の煩わしさは、通常移動と同じく押しっぱなしで解く。押し続ければプレイヤーの実時間では高速に進むが、ゲーム内のコストは1タイルあたり不変で、連打でも長押しでも同じAPを食う。実時間の手間とゲーム内のコストを切り離す考え方である。長押し中もターンが進み寒波が迫るので、コストは目に見えたまま、余裕が削れていくのが分かる。

**ブレーキには釣り合う引力が要る**。押しコストは重い物に代償を課すが、良い決断になるのはプレイヤーが重い物を本気で欲しがるときだけである。飛ばせるだけなら最適解は空のキューブを軽く押すになる。だから設計の半分は、道具や戦利品を「重さを承知で連れて行きたい」ものにすることに向く。ブレーキと引力は一対で、片方だけでは成立しない。

### 労働と仲間 — 押し力が主の役割

建設が無いので、仲間の役割は押し力・戦闘・運搬になる。押しコストを軽くするために人数を集め強化する。solo でも押せて暮らせる、ただし押しは重い。建てる物が無いので「仲間がいないと拡張できない」問題は生じない。規模はそのまま旅のスタイルの表現になり、一匹狼は簡素、大所帯は賑わう。

### 圧力 — 寒波と押しコスト

移動を強いる圧力は、盤外のハードルールでなく、押しコストと迫る寒波の組み合わせで発生させる。

- 押しが高コストなので無限の最適化は成立しない。反トイルの終端圧をこれが担う
- 背後は凍り、戻っても無に帰す。レーンが一方向なこととあわせ、後戻りとバックトラック・ファーミングを封じる
- 置く物は旅の道すがら拾う。戻れないので採取は機会主義に留まり、専用の grind にならない

これは以前保留していた「寒波は一方向ロック無しでトイルを止められるか」への、具体的な機構としての答えでもある。ロックは無い。移動は重量で高コストで、遅い凍結がいつか押しを強いる。残るのは押しの重さと前線速度のチューニングで、遊んで確かめる。

### 防衛 — 行わない

キューブそのものを守る防衛機構は設けない。賭けと緊張は、押しの余裕を切らせば前線に呑まれること、および徒歩で巡るチャンクでの遭遇戦から生まれる。キューブは安全な我が家・保管庫のままにし、守る対象としては扱わない。スコープを絞り、押しと寒波の緊張に一本化する。

## データ定義

置ける物のための専用の種別 enum やラッパー型は設けない。ECS なので、キューブは専用レーン上の位置コンポーネントを持つエンティティで、内装は prop エンティティを置く空間になる。置いた物の効果も重量も、各エンティティが既存のコンポーネントから出す。ストーブは暖のコンポーネントを持つ prop、というだけで足りる。

```go
// PushCost は総重量と押し手の力から、1タイル押すのに要するAPを返す。
// 総重量は内装に置いた prop エンティティの重量コンポーネントの合計で、
// 重量に応じて重く、押し手が多いほど軽い。
func PushCost(totalWeight, pushPower int) int
```

## 変更箇所

本 doc は概念の記録で、以下は実装の見取りである。着手時に個別 doc へ分割する。

| 領域 | 内容 |
|---|---|
| 器 | レーン上の単タイル・キューブ、異次元内装への出入り、外は押し・中は静止 |
| 重量押し経済 | 総重量、1タイルあたり押しコスト、押しっぱなし移動、前線への余裕の可視化 |
| 内装 | 空間へ item/prop を置いて表現、効果は presence ベース、空間は固定で寛容 |
| 労働と仲間 | 仲間の押し力・戦闘・運搬、solo の基準速度、街での代替 |
| 圧力 | 押しコストと寒波、採取の機会主義、一方向レーン |
| 既存系との接続 | 帯・チャンク・オーバーワールド・prop・item との整合 |

## 採用しなかった方法

- **建設システム、資材と労働で建てる** — 部屋を建てる仕組みを持つと、材料集めと配置の細作業がトイルへ近づき、仲間がいないと建てられない問題も抱える。空間に既存の item/prop を置いて表現すれば足り、YAGNI にも適う
- **キャラバン・橇の隊列の器** — 運搬を可視化する利点があったが、キューブの重量押し経済のほうが蓄積の代償・移動圧力・仲間の価値を1つの数字に統合でき、より直接で体感的。機構と皮は分離できるので、これは皮の選択であって機構の否定ではない
- **サンドボックス化** — 滞在を全面的に許す。テーマの心臓である迫る凍結を捨て、賭け金の発生装置を失い、埋めるべき空間も激増する
- **移動を抽象アイコンやメニューにする** — 実装は安いが、一続きの手触りを失う。キューブは外の押しをタクタイルに保つことでこれを避ける
- **多タイルの乗り物** — 走行しながら中を歩ける器。最も豊かだが実装が複雑すぎる。キューブは外を単タイル、中を異次元に分けて複雑さの本体を避ける
- **配置が効果を最適化する位置依存** — 隣接ボーナスや動線効率は、逃げ出した拠点建築のトイルへ戻る。効果は置いてあることから出し、配置は表現に留める
- **ターン制限などハードなロック** — 従来は反トイルのためにロックしていたが、押しコストと遅い寒波の経済的圧力が同じ役割を、鎖の感触なしに担う

## コメント

- 迷いが何度も再燃したのは、確信を皮に結びつけていたためだった。楽しみに錨を下ろすと、器は合否を見るだけの交換可能な実験になり、危機にならない。キャラバンからキューブへ、建設から家具付けへと替えても、そのつど要件節の7つに通して進められた
- 建設を消したことで、長く行き来した「リストか手触りか」の対立も解けた。建設待ち行列が無いので、家具付けは純粋な世界内の所作になり、残る一覧は重量と余裕を映す HUD の数字だけになる
- 異次元の内装は、以前「同じ世界の手触りを失う」として却下した入れ替え式の内装インスタンスと同型である。今回受け入れられるのは、却下の理由だった移動の抽象化が無く、外の押しがタクタイルに保たれ、内装が虚構で正当化されるからである
- 皮は無地のキューブに確定した。キューブの防衛機構は設けない。賭けは押しの余裕と寒波、および徒歩探索の遭遇戦が担う
- これは意思決定の記録である。コンセプトに迷ったら、まず要件節の楽しみへ戻る
