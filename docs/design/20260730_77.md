# 拡張可能な移動拠点を中核に据える

## 背景

design.md の原点は、凍った日本のキャラバン交易サバイバルで、必須目的をあえて定めないことでロールプレイの自由を成立させる、というものである。

長らく、帯の一方向強制移動やターン制限が、ロールプレイの自由や拠点への愛着と衝突して見えて迷っていた。議論の末に、迷いの正体が分かった。**確信を「キャラバン」という皮に結びつけていた**ことである。皮はどこか恣意的なので、皮を疑うたびに全部が揺れた。

錨を下ろすべきは皮でなく、皮が抽象していた楽しみのほうだった。キャラバンは目的でなく、ある種の楽しみを盛る器にすぎない。守るべきはその楽しみで、器が何であるかは交換可能である。この doc は、まず守るべき楽しみを仕様として固定し、その上で現在の器を記録する。器が変わっても、楽しみへの錨は残る。

## 要件

### 守るべき楽しみ

これが本当の仕様である。どんな器を選んでも、以下を満たすなら合格とする。

1. **育つ家への愛着** — 投資し、個性を与え、持続する我が家
2. **家を連れて行ける** — 移動しても愛着を失わない。積み上げた家が常に共にある
3. **代償のある蓄積** — 集めるのは楽しい、ただし必ず対価を払う。「何を残すか」が本物の決断になる
4. **意味のある仲間** — 明確な役割を負い、彼らへの愛着が生まれる
5. **賭けのある前進** — 一方向、背後に破滅、安全な籠城なし。緊張して前へ進む推進力
6. **旅の中の自由** — 何をするか、どう生きるかを選び、システムがそれを表現する
7. **停まって暮らす律動** — 停泊して家を開き、道具を使い、また畳んで進むリズム

### 避けるべき反・楽しみ

- 単調な作業、いわゆるトイル。際限のない最適化や運搬の細作業
- 移動の抽象化による、一続きの手触りの喪失
- 多タイルの乗り物が持つ実装の複雑さ
- ターン制限のような盤外のハードルールによる、鎖の感触

## 設計

現在の器は、押して進める1つのキューブである。キャラバンの隊列を、より統合された機構へ置き換えたものだが、上の楽しみの仕様はそのまま満たす。

### 器 — 押すキューブと異次元の内装

- **外**: キューブは専用レーン上の単タイル。左右にしか押せず、ほぼ戻らない。単タイルなので通常のエンティティと同じ扱いで、特別な物理を持たない
- **中**: キューブの内側は異次元の静止した空間で、扉をくぐって入る。ここに部屋を建て、物を格納し、料理器具や溶接機などの使える道具を置く

多タイルの複雑さは「歩いて入れる」と「動く」を同時に成立させることから生まれる。キューブはこれを分ける。**外で押すのは単タイル、中で歩くのは静止した異次元**。両者は決して同時に起きないので、動く多タイル剛体は存在しない。

外のレーンでの押しはタクタイルなままで、抽象化しない。プレイヤーはキューブを離れて周囲のチャンクを徒歩で探索し、戻って押す。内装は異次元という世界内の虚構で正当化されるので、扉をくぐる感覚であり管理画面ではない。

### 皮 — 無地のキューブに確定する

見た目は無地のキューブに固定する。これは最小の皮であり、次の3つの負債をまとめて先送りにするための選択である。

- 凝った絵が要らず、単タイルで済む。蔵や神輿のような大きな器の描画やフットプリントの噛み合わせを考えなくてよい
- 中が広い謎の箱は、異次元の内装をそれ自体で正当化する。文化的な下地を要さない
- 説明されない箱は穴に見えない。物語の負債も後に回せる

代償として、凍った日本というテーマへの手触りの結びつきは、今は薄くなる。蔵のようには世界に属さない。これは意識的に払う対価である。

錨は皮でなく要件節の楽しみに置いてあるので、まず押しの機構が楽しみを本当に届けるかをキューブで確かめ、美術と物語への投資はそれが証明された後に行う。機構が先、皮は後。物語の統合は破棄でなく先送りで、後から蔵でも遺物でも被せ直せる。

### 重量押し経済 — 1つの数字が全部を担う

この器の心臓は、押しコストという単一の数字である。押しコストは総重量と押し手の力で決まり、今まで別々に設計していた要求を同時に解く。

- **移動圧力**: 押すのは高コストで、歩行の10倍規模のAPを食う。余裕を持って押さないと、いくら前線が遅くても呑まれる。ハードなターン制限は要らない。移動が重い決断で、滞在は無料、遅い凍結がいつか押しを強いる
- **代償のある蓄積**: 荷が増えると重くなり、押しがさらに遅くなる。無限の溜め込みが、恣意的な重量上限でなく移動コストとして自分を罰する。あらゆる獲得が「この重さを押す価値があるか」の決断になる
- **仲間の価値**: 押す力そのもの。人数を集め強化すると押しが軽くなる。何もゲートせず切実に欲しい

重量は、しまった戦利品と重い道具から出す。家の構造からは出さない。だから広く快適な内装は安く持て、重い物を溜め込むことだけが移動を鈍らせる。緊張を溜め込みに集中させ、家の広さには乗せない。

押しは1タイルずつの連打にしない。1回の押しで次のノードまで、意味ある一区間を進む重い決断にする。でないと移動が単なる作業になり、余裕対前線の緊張も計画できない。

### 拡張 — 離散モジュールと満足化する位置依存

内装は離散のモジュールで拡張する。ストーブ、作業台、寝床、収納棚などで、それぞれ作者が作り込んだ部品としてアイテムで入手・作成する。

- **効果は最適化の勾配を持たない**。局所的に位置が効くのは構わない。だが隣接シナジーや、距離と台数で連続的に増減する効果は作らない。閾値・二値にして、範囲に入れば終わり、にする
- **自由建築にしない**。タイル単位で好きに組めるようにすると、そこにトイルが侵入する。部屋・設備は離散のモジュールに留める
- 実質の上限は、面積の固いキャップでなく重量による押しコストが担う。異次元なので空間は寛容でよい

トイルと愛着を分ける境界は、位置が効くか否かでなく、配置に最適化の勾配があるか否かにある。まともなプレイヤーが「これで十分」と手を止め、価値を取り逃した気がしないなら安全である。

### 計画と建設 — リストは制約の計器盤、配置はテンプレ

建てるものはリスト、すなわち建設予定の待ち行列で選ぶ。リストは単なるメニューでなく、制約の見える化ダッシュボードとして機能する。モジュールごとに重量・押しコストへの寄与・工数を並べ、拡張のトレードオフを一目で読ませる。総重量と押しコストと前線への余裕を常に読めるようにする。

- **配置はテンプレ嵌め込み**。作り込んだレイアウトにモジュールを嵌める。アルゴリズムの first-fit は乱雑に見えるので使わない。作者が外観を制御し、プレイヤーは中身を制御する
- **建設はターンを投入すると背後で進む**。プレイヤーは拘束されず、その間に探索・採取・防衛ができる
- **誰がやってもオート**。solo でも仲間がいても同一の仕組みで、特別扱いを持たない

### 外観 — 自動配置を救うのは authoring

配置を委ねると外観が乱れる懸念がある。救うのはアルゴリズムでなく authoring である。ティアごとの作り込みテンプレに嵌め、モジュールの絵はどの組み合わせでも一貫して読めるよう設計し、繋ぎを自動で描いて寄せ集めに見せない。代償は、同じ構成なら同じ外観になり配置の個性が減ること。ただしこの方式の個性は元々「何を持つか」に置いたので一貫している。

### 労働 — 仲間は速度であってゲートでない

押しと建設の労働はキューブが持つ量として一本化し、仲間はその一供給源にすぎない。資材があれば一人でも押せて建つ、ただし遅い。仲間は押しを軽くし建設を速める。街では出来合いモジュールの購入や日雇いで労働を金で代替できる。

これにより仲間ゼロは行き止まりでなく、ただ遅いだけになる。全滅しても能力は死なず、一人生き残りが細々と進み建て直す、回復可能で物語的な失敗状態になる。中核の快楽を、失いうる資源の背後に隠さない。規模はそのまま旅のスタイルの表現になり、一匹狼は簡素、大所帯は広壮になる。

### 圧力 — 寒波と押しコスト

移動を強いる圧力は、盤外のハードルールでなく、押しコストと迫る寒波の組み合わせで発生させる。

- 押しが高コストなので無限の最適化は成立しない。反トイルの終端圧をこれが担う
- 背後は凍り、戻っても無に帰す。レーンが一方向なこととあわせ、後戻りとバックトラック・ファーミングを封じる
- 資材は旅の道すがら拾ったもので建てる。戻れないので採取は機会主義に留まり、専用の grind にならない

これは以前保留していた「寒波は一方向ロック無しでトイルを止められるか」への、具体的な機構としての答えでもある。ロックは無い。移動は重量で高コストで、遅い凍結がいつか押しを強いる。残るのは押しの重さと前線速度のチューニングで、遊んで確かめる。

### 防衛 — 未決の判断

停泊中に迫る何かからキューブを守る局面は、楽しみの一つになりうる。ただしキューブの内装は異次元の安全な袋なので、防衛の形が2つに分かれ、どちらを採るか未決とする。

- **キューブ防衛**: レーン上の単タイルのキューブを守る。内装は戦場にならない。実装は簡潔
- **内装侵入**: 敵が内装へ侵入できるようにし、部屋を通って迎え撃つ。手触りは濃いが、内装マップでの戦闘という実装が要る

## データ定義

```go
// MobileBase は押して進める移動拠点。外は単タイル、中は異次元の内装。
type MobileBase struct {
	LanePos  int          // 専用レーン上の位置。押すと進む
	Weight   int          // 総重量。しまった物と道具の合計。押しコストを決める
	Modules  []BaseModule // 異次元内装に建てた、または予定するモジュール
	Deployed bool         // 内装に入っているか
}

// BaseModule は内装の離散拡張要素。効果は最適化の勾配を持たない。
type BaseModule struct {
	Kind   ModuleKind // ストーブ・作業台・寝床・収納など
	Built  bool       // 建設済みか。未建設は予定として待ち行列にある
	Cost   Materials  // 建設に要する資材
	Labor  int        // 建設に要する労働量。ターン投入で減る
	Weight int        // この設備が総重量に加える分。リストの計器盤に出す
}

// ModuleKind は拡張要素の種別。効果は種別ごとに定義する。
type ModuleKind string

// PushCost は総重量と押し手の力から、1区間押すのに要するAPを返す。
// 重量に応じて重く、押し手が多いほど軽い。
func PushCost(weight, pushPower int) int
```

## 変更箇所

本 doc は概念の記録で、以下は実装の見取りである。着手時に個別 doc へ分割する。

| 領域 | 内容 |
|---|---|
| 器 | レーン上の単タイル・キューブ、異次元内装への出入り、外は押し・中は静止 |
| 重量押し経済 | 総重量、押しコスト、区間単位の押し、前線への余裕の可視化 |
| 内装拡張 | 離散モジュール、効果は最適化勾配なし、重量は戦利品と道具から |
| 計画と建設 | リストの制約計器盤、テンプレ嵌め込み配置、ターン投入の背後進行 |
| 外観 | ティア別レイアウトテンプレ、繋ぎの自動描画 |
| 労働 | 仲間の押し力と建設 throughput、solo の基準速度、街での代替 |
| 圧力 | 押しコストと寒波、資材の機会主義的採取、一方向レーン |
| 防衛 | キューブ防衛か内装侵入かの判断 |
| 既存系との接続 | 帯・チャンク・オーバーワールドとの整合 |

## 採用しなかった方法

- **キャラバン・橇の隊列の器** — 移動拠点を複数の単タイル車の隊列で表す。運搬を可視化する利点があったが、キューブの重量押し経済のほうが、蓄積の代償・移動圧力・仲間の価値を1つの数字に統合でき、より直接で体感的と判断した。ただし機構と皮は分離できるので、これは皮の選択であって機構の否定ではない
- **サンドボックス化** — 滞在を全面的に許す。テーマの心臓である迫る凍結を捨て、賭け金の発生装置を失い、埋めるべき空間も激増する
- **移動を抽象アイコンやメニューにする** — 実装は安いが、一続きの手触りを失う。キューブは外の押しをタクタイルに保つことでこれを避ける
- **多タイルの乗り物** — 走行しながら中を歩ける器。最も豊かだが実装が複雑すぎる。キューブは外を単タイル、中を異次元に分けて複雑さの本体を避ける
- **自由建築、最適化の勾配を持つ位置依存** — タイル単位の自由建築や隣接ボーナスは、逃げ出した拠点建築のトイルへ戻る。離散モジュールと満足化する局所効果に留める
- **ターン制限などハードなロック** — 従来は反トイルのためにロックしていたが、押しコストと遅い寒波の経済的圧力が同じ役割を、鎖の感触なしに担う

## コメント

- 迷いが何度も再燃したのは、確信を皮に結びつけていたためだった。楽しみに錨を下ろすと、器は合否を見るだけの交換可能な実験になり、危機にならない。要件節の楽しみのリストが、その錨である
- 異次元の内装は、以前「同じ世界の手触りを失う」として却下した入れ替え式の内装インスタンスと同型である。今回受け入れられるのは、却下の理由だった移動の抽象化が無く、外の押しがタクタイルに保たれ、内装が虚構で正当化されるからである
- 皮は無地のキューブに確定した。テーマへの手触りを今は薄くする対価を承知で、美術と物語の投資を機構の証明後へ先送りする選択である。防衛の形だけは未決で、内装を戦場にしたいかどうかの美学の判断による
- これは意思決定の記録である。コンセプトに迷ったら、まず要件節の楽しみへ戻る
