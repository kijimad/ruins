# キャラバンを拡張可能な移動拠点として中核に据える

## 背景

design.md の原点は、凍った日本のキャラバン交易サバイバルで、必須目的をあえて定めないことでロールプレイの自由を成立させる、というものである。

長らく迷っていたのは、帯の一方向強制移動とターン制限が、このロールプレイの自由や拠点への愛着と衝突して見えることだった。移動の強制は自由を奪っているのではないか、いっそサンドボックスにすべきか、と何度も揺れた。

議論を通して、迷いの構図そのものが見えた。「拠点への愛着」には2種類が混在していた。

- **場所への愛着**: ここは私の場所だ、私が育て、帰ってくる
- **移動する家への愛着**: この乗り物・隊・積荷を私が育て、私の物語を背負う

この2つは別の快楽で、別の地形を要求する。片方を選ばされることへの抵抗が、迷いの正体だった。そして**拡張可能な移動拠点は、この2つを融合できる唯一の形**である。改良して帰ってくる場所を、連れて行く器の中に持つ。ここに着地して納得が来た。

本 doc はその到達点を記録する。実装の細部より、どの制約の下で何を選んだかを残す。

## 要件

- 拠点への愛着を、場所と移動する家の融合として成立させる
- 世界を抽象化しない。一続きの手触りある空間を保つ。移動や拠点がアイコンやメニューに化けない
- 多タイルの乗り物が持つ実装の複雑さを避ける
- 単調な作業、いわゆるトイルを再導入しない
- 仲間の有無で中核の快楽をゲートしない

## 設計

### 器 — 畳む/展ける二形態

拠点は移動する形と、歩いて入れる形の2状態を持つ。

- **移動形**: 規模に比例した橇・荷車の隊列。各単位は単タイルで、縦列で follow する。帯を連続で、途切れず、同じ手触りのまま進む。単タイルなので通常のエンティティと同じ扱いで、特別な物理を持たない。役畜や仲間が牽き、荷と乗員は各車が積む
- **野営形**: 立ち止まって野営を張ると、隊列が世界内に展開して拠点タイルになる。工房や寝床を歩き回れる。この形は動かない

多タイルの複雑さは「歩いて入れる」と「動く」を同時に成立させることから生まれる。二形態はそれを状態で分ける。**動く形は単タイルの集まり、歩ける形は静止**。この不変条件を守る限り、動く多タイル剛体は存在しないので、座標変換も回転も移動参照系も要らない。狭所では隊列を単列に詰めて捌く。

畳む/展けるは世界内の所作でありターンを消費する。管理画面へ抜けるのではないので抽象化にはならない。配置は記憶され、野営を張ると前回の状態が丸ごと復元される。毎回の停泊で建て直さない。

隊列そのものが畳んだ野営である。展けば隊列が野営に開き、畳めば野営が隊列に戻る。**隊列の長さが野営の規模を表す**。これにより「大荷物をどう運ぶか」は後付けの荷物処理でなく、育てた拠点が街道でのシルエットの成長として現れる、拡張の可視化になる。凍った日本では橇が雪上の重量物運搬の自然な答えで、テーマにも合う。牽くには役畜や人手が要るので、荷が大きいほど牽き手が要り、仲間や役畜の数が拡張ペースをそっと律速する。

### 拡張 — 離散モジュールと満足化する位置依存

拠点は離散のモジュールで拡張する。ストーブ、作業台、寝床、収納棚、見張り台などで、それぞれ作者が作り込んだ部品としてアイテムで入手・作成する。

- **効果は最適化の勾配を持たない**。局所的に位置が効くのは構わない。ストーブは範囲内を暖める、見張り台は接近路を警戒する。だが「隣接で+10%」のようなシナジーや、距離と台数で連続的に増減する効果は作らない。閾値・二値にして、範囲に入れば終わり、にする
- **総面積は段階制のパッドで制御する**。小・中・大とティアで広がり、無限拡張にしない
- **自由建築にしない**。タイル単位で好きに組めるようにすると、そこにトイルが侵入する

トイルと愛着を分ける境界は、位置が効くか否かでなく、配置に最適化の勾配があるか否かにある。まともなプレイヤーが「これで十分」と手を止め、価値を取り逃した気がしないなら安全で、常にもっと良くできると感じるならトイルである。配置はテンプレが担うのでプレイヤーは並べない。効果に最適化の勾配が無く、かつテンプレが定位置へ嵌めるので、レイアウトのトイルは二重に閉じる。

位置依存は、逃げ出した拠点建築のトイルへ戻る坂道でもある。満足化に留める線引きが、その坂のガードレールになる。局所効果の勾配は浅く保ち、完璧な配置が無難な配置をわずかしか上回らないよう調律する。

### 計画と建設 — リストは制約の計器盤、配置はテンプレ

建てるものはリスト、すなわち建設予定の待ち行列で選ぶ。何を持つか、何を先に建てるかを決める。リストは単なるメニューでなく、**制約の見える化ダッシュボード**として機能する。モジュールごとに使用面積・燃料・工数を並べ、拡張のトレードオフを一目で読ませる。サバイバルの資源経済を計器盤で読ませるのがリストの本来の仕事である。

- **配置はテンプレ嵌め込み**。パッドのティアごとに作り込んだレイアウトを用意し、モジュールをその定位置に嵌める。アルゴリズムの first-fit は乱雑で意図の無い見た目になるので使わない。作者が外観を制御し、プレイヤーは中身を制御する
- **建設はターンを投入すると背後で進む**。プレイヤーは建設に拘束されず、その間に探索・採取・防衛ができる。座って進捗を見張る死に時間を作らない
- **誰がやってもオート**。solo でも仲間がいても同一の仕組みで、特別扱いを持たない

### 外観 — 自動配置を救うのは authoring

リストで配置を委ねると外観が乱れる懸念がある。救うのはアルゴリズムでなく authoring である。

- ティアごとの作り込みテンプレに嵌めるので、見た目に意図が宿る
- モジュールの絵は、どの組み合わせでも一貫して読めるよう設計する。幌・柵・通路のような繋ぎを自動で描き、寄せ集めに見せない
- 中央の車を軸に野営が放射状に広がる構図にすると、中身が何であれ焦点のある絵になる

代償は、同じモジュール構成なら同じ外観になり配置の個性が減ること。ただしこの方式の個性は元々「何を持つか」に置いたので一貫している。

### 労働 — 仲間は速度であってゲートでない

建設の労働はキャラバンが持つ量として一本化し、仲間はその一供給源にすぎない。

- 資材があれば、プレイヤー一人でも時間とともに建つ。ただし遅い
- 仲間は throughput を増やす。並行して速く建てる
- 街では出来合いモジュールの購入や日雇いで、労働を金で代替できる

これにより仲間ゼロは行き止まりでなく、ただ遅いだけになる。全滅しても能力は死なず、一人生き残りが細々と建て直す、回復可能で物語的な失敗状態になる。中核の快楽を、失いうる資源の背後に隠さない。

### 役割分担

手触りと簡潔さを両立させる境界を明示する。

- **住むのはタクタイル**: ストーブに寄って暖を取る、作業台の前でクラフトする、寝床で休む。使う体験は世界内の相互作用のまま
- **計画はリスト**: 次に何を建てるかの意図と、面積・燃料・工数の制約を計器盤で読む
- **配置はテンプレ**: どこに建つかは作り込んだレイアウトが決める

全部をリストで完結させると、拠点が絵つきメニューに退化して手触りが飾りになる。住む体験はタクタイルに残す。計画をリストに寄せるのは、資源経済を一目で読ませるためで、住む手触りを削るためではない。

### 圧力との関係

移動を強いる圧力は、ターン制限のような盤外のハードルールでなく、寒波という世界内の力として発生させる。

- 寒波が迫るので、無期限の最適化は成立しない。反トイルの終端圧をこれが担う
- 背後は凍り、戻っても無に帰す。後戻りとバックトラック・ファーミングをこれが封じる
- 資材は旅の道すがら拾ったもので建てる。戻れないので採取は機会主義に留まり、専用の grind にならない

ここで建設と圧力が噛み合う。**建設は滞在を要し、寒波は滞在を制限する**。一人だと大きな設備に長い野営が要り、その間ずっと寒波に露出する。仲間がいれば短い滞在で建てられ露出が減る。仲間の価値は「寒の時計に追われずに家を育てられること」に凝縮し、何もゲートせずに切実に欲しくなる。

さらに拡張には建設費だけでなくランニングコストが乗る。大きい野営ほど暖房の燃料を食い、牽くのに役畜や人手が要る。**拡張はタダでなく、常時のコストとして補給と寒波の圧力に接続する**。大きくするほど快適で有能になるが、燃料の消費が増えて滞在の自由が縮む。この常時コストが拡張を自己制御的にし、無限に肥大しない。リストの計器盤はこの経済網を読ませる。

一方向の強制移動ロックは、この寒波と役割が重なる。反トイル・終端・戻り禁止を寒波が担えるなら、ロックは冗長で、自由を奪う感触だけを生む残滓かもしれない。ただしこれは断定でなく検証事項とする。後述する。

### 愛着とロールプレイ

愛着の的は、間取りの設計でなく、選んだモジュールの集まり、道連れ、道中の履歴、そこで暮らした時間に置く。

野営の規模はそのまま旅のスタイルの表現になる。一匹狼は簡素な野営、大所帯は広壮な拠点。同じ仕組みが両方を描く。仲間ゼロは封じるべき穴でなく、表現すべき一つの生き方になる。

## データ定義

拠点と拡張の骨子を型で示す。効果を持つのはモジュールで、局所的な位置は効いてよいが最適化の勾配は持たない。配置はテンプレが定位置へ嵌めるので、プレイヤーは座標を指定しない。

```go
// CampModule は拠点の離散拡張要素。効果は最適化の勾配を持たない。
type CampModule struct {
	Kind     ModuleKind // ストーブ・作業台・寝床・収納・見張り台など
	Built    bool       // 建設済みか。未建設は予定として待ち行列にある
	Cost     Materials  // 建設に要する資材
	Labor    int        // 建設に要する労働量。ターン投入で減る
	Area     int        // 使用するパッド面積。リストの計器盤に出す
	FuelBurn int        // 常時の燃料消費。0なら消費しない。リストの計器盤に出す
}

// ModuleKind は拡張要素の種別。効果は種別ごとに定義する。
type ModuleKind string

// Camp は移動拠点の状態。移動形の隊列と野営形の拠点で同じ実体を指す。
type Camp struct {
	PadTier  int          // 段階制の総面積。展開時の上限を決める
	Modules  []CampModule // 所持・予定するモジュールの一覧。これが計画リストを兼ねる
	Deployed bool         // 展開中か。falseなら単タイルの隊列
}
```

## 変更箇所

本 doc は概念の記録で、以下は実装の見取りである。着手時に個別 doc へ分割する。

| 領域 | 内容 |
|---|---|
| 器の二形態 | 単タイルの隊列と静止野営形、畳む/展ける所作、配置の記憶と復元、隊列長=規模 |
| モジュール | 種別定義、効果は最適化勾配なし、面積・燃料・工数、段階制パッド |
| 計画と建設 | リストの制約計器盤、テンプレ嵌め込み配置、ターン投入の背後進行 |
| 外観 | ティア別レイアウトテンプレ、繋ぎの自動描画、車を軸の構図 |
| 労働 | 仲間の throughput、solo の基準速度、街での代替、牽き手の律速 |
| 圧力 | 寒波の終端圧、資材の機会主義的採取、燃料のランニングコスト、一方向ロックの要否検証 |
| 既存系との接続 | 帯・チャンク・オーバーワールドとの整合、野営防衛 |

## 採用しなかった方法

- **サンドボックス化** — 滞在を全面的に許す。テーマの心臓である迫る凍結を捨て、汎用サバイバルへ拡散し、賭け金の発生装置を失う。埋めるべき空間も激増する
- **抽象アイコンやメニューのキャラバン** — 実装は最も安いが、同じ世界の手触りを失う。この一点で早期に却下していた
- **入れ替え式の内装インスタンス** — 移動を抽象アイコンにし、停止時に別マップの内装へ切り替える。手触りの連続を切るため同様に却下
- **多タイルの乗り物** — 走行しながら中を歩ける器。最も豊かだが実装が複雑すぎる。二形態はこの複雑さの本体だけを回避する
- **プレイヤーによる手動配置・自由建築** — 間取りの自己表現は魅力だが、タイル単位の自由建築は最適化のトイルを招く。配置をテンプレに委ね、プレイヤーは中身のリストを決める形にする。世界内でゴーストを手ずから置く案も検討したが、リストは面積・燃料・工数の制約を計器盤として読ませる利点が勝ると判断した
- **最適化の勾配を持つ位置依存、隣接ボーナス** — 拠点の数値を配置で際限なく詰められると、まさに避けたい無限いじりが生まれる。局所的な満足化する位置依存は残すが、シナジーや連続的な勾配は入れない
- **一方向ロックの維持を自明とすること** — 従来は反トイルのためにロックしていたが、寒波が同じ役割をより良く担える疑いがある。維持を前提にせず、検証にかける

## コメント

- 迷いの構図は「場所への愛着」と「移動する家への愛着」の二択を強いられていたことだった。移動拠点はその融合であり、だから長い迷いの出口になった
- 未解決の検証がひとつある。「寒波は一方向ロック無しでトイルを止められるか」。ロックを外し寒波圧だけにした版で、事前に予測を書いてから、滞在と移動の手触りを測る。寒波が無視できる速さだとトイルが戻るので、噛み具合の調律問題に変わりうる
- これは意思決定の記録である。以後コンセプトに迷ったら、まずここへ戻る
