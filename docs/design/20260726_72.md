# 隊員は戦闘の仲間とする —— 生産の労働者ではない

## 背景

doc 71 で隊の活動システムを企画する過程で、隊への機能拡張の参照フレームを広く検討した。当初は
定住型コロニーシミュレーションの語彙、すなわち作業優先度・採掘/加工/生産の隊員ジョブ・設営
システム・係を構想したが、操作モック `docs/plan/mock/dwell_interference.html` での検証と検討を
経て、**参照フレームそのものが定住ゲームの前提に引きずられていた**と判明した。

検討で露呈した事実。

- 設営は「深さを選ぶ」一瞬の判断のあとは自動で進み、コンテンツにならない。都度の配置は反復操作になる
- 隊員が経済を回すほどプレイヤーは監督席に下がり、冒険の主役が簒奪される。凍った世界の寂寥という
  トーンも、忙しい村のジオラマに変質する
- 作業優先度表は、課題が絶えず湧き続ける構造があって初めて意味を持つ装置で、ruins の逗留にはその
  湧出構造が無い。捌く負荷の無い格子は空の管理画面になる

結論として、本作は移動する隊の冒険が主語であり、隊員は本質的に戦闘面の存在である。大量生産・
自動運搬は要素に入れない。

## 設計

### 隊員の定義 —— 戦闘の仲間

```
隊員 = 戦闘力 + 育成投資の器(スキル・装備・身体改造) + 積載 + 生存の物語
```

- 隊員は**戦闘の仲間**である。隣で戦い、育ち、死ぬ
- プレイヤーがやるのは、装備と改造を与える・食料を持たせる・連れて行く相手を選ぶ・ポリシーを決める。
  作業割当はしない
- 愛着の源は成長と生存。使い込んだ隊員の数値が上がる快感と、失ったときの喪失。雑用を眺めることでは
  ない。戦闘と旅だけで愛着の核を成立させることは十分に可能である
- 現行実装、戦闘4ポリシー・使用ベース成長・装備/改造・積載分担は既にこのモデルの形をしている。
  gap は幅でなく深さにある

### 不採用の確定

以下は検討の結果、明示的に不採用とする。

- 生産チェーン。採掘→精製→生産の隊員ジョブ
- 係・作業優先度リスト
- 設営システム。段階設営・レイアウトテンプレート・集積点ネットワーク
- 自動運搬の拡張。既存の回収・分配ポリシーは維持するが、これ以上拡張しない

### 残す要素と深める方向

| 要素 | 位置づけ |
|---|---|
| doc 71 の空腹+プール自動飲食 | 世話に相当する維持コストの圧であって労働ではない |
| 既存の回収・分配ポリシー | 従者の範疇。現状維持で拡張しない |
| 積載分担 | 兵站の柱。誰が何を担ぐかは配分判断であって隊員労働ではない |
| 救護 | 新規。倒れた仲間を担ぐ。担ぐか置くかの判断が冒険内のドラマになる |
| 焚き火・休息 | 1アクションの演出。隊が火を囲み、団欒のログが稀に流れる |

深める方向は戦闘面に集中する。ポリシー表現の充実、将来は「条件→行動」の規則列方向。直接命令の
磨き込み。スキル成長の提示、上がった瞬間が見えて嬉しいこと。その先に特性・関係という感情の核。
いずれも戦闘と旅の中で起きる。

### 同座の不変条件

隊は帯の中に同座する。分散拠点・別動隊は作らない。離すと視点のないゲームの文法、俯瞰・ジョブ
ボード・タイマーが要求され始め、別のゲームになるため。帯アーキテクチャと隊は相似形であり、
視界外シミュレーション・遠隔命令 UI・長距離自律 AI は永久に不要になる。

### 前線に呑まれる喪失の許可

帯シフトの西端破棄は前線の凍結壁そのものであり、隊員がそこへ取り残される喪失をドラマとして許可する。

- 健康な隊員は前線接近で自主退避する。予測可能で人間的
- ドラマは「動けない負傷者を担ぐか、置いていくか」に集中させる。選んだ損失として刺さる形にする
- 十分な警告を前提とする。HUD の前線距離、ログのエスカレーション、名前のある失敗
- 実装時は worldstream の KeepPlayerAndSquad が隊員を無条件救済している現状を見直す

### NPC 品質の原則 —— 開かれたシミュレーションを AI に航行させない

隊員 AI の体感品質は次の式で決まる。プレイヤー向けに設計された開かれたシミュレーション全体を
AI に航行させると、この式の分母が最大化し、AI は永遠に追いつかなくなる。

```
NPC の体感品質 = 行動語彙の狭さ × 失敗の可読性   (シミュレーションの深さは分母に入る)
```

- **閉じた語彙契約**。隊員は列挙された行動だけに触れる。開かれたアイテム空間・自由な判断を与えない
- **非対称の勇気**。仕組みは共有し、意思決定空間は非対称にする。対称性を誇りにしない
- **失敗に名前を付ける**。隊員が失敗しうる状況を列挙し、名前・ログ・表示を与える。名前があれば
  ドラマ、なければジャンク
- **構造で保証する**。射線・通路の問題を賢い AI で解かない。見て分かる規則と、生成側の通路保証で
  環境から消す
- **接触面の宣言**。新システムは「NPC 接触面」、触れないか規則1本か、と「帯リベース接触面」、
  位置状態のシフト対応、を宣言する

### 設計の見取り図

多数の NPC×流動的な状況×深い個体管理は、同時に全てを取れないトリレンマである。本作は
「約10人・流動・薄い制御」を選ぶ。流動下で多数を回す実証済みの勝ち筋は**割当を空間に埋め込む**
ことであり、メニューで個体を差配する方式は流動に耐えない。リーダーが世界に対して置く・指す、
隊員がそれに応じる、という既定方針はこの勝ち筋の側にある。深い個体管理はターン制の停止時間の
中でだけ許す。

## 採用しなかった方法

- **定住シミュレーション型の作業優先度・生産システム** —— 課題の湧出構造が無く格子が空になる。
  定住前提の道具は移動する隊に移植できない
- **段階設営・レイアウトテンプレート** —— 反復オーバーヘッドの精緻化だった。設営は1アクションの
  演出に縮退させる
- **係の1人1役** —— 優先度リスト以前に、割り当てるべき労働そのものを不採用にしたため消滅
- **プレイヤーと対称のシミュレーション** —— NPC 品質の式の分母を最大化する選択。非対称を貫く
- **手伝い、リーダー作業への自動アシスト** —— 保留。生産の縮小により対象作業が薄い。必要が
  実証されてから再検討する
