# 木から薪を得る。素手は遅く、斧は速い

## 背景

序盤は燃料が足りない。燃料の熱量は素材と重さから導かれ、WOOD は 1kg あたり 200 である。WOOD 素材のアイテムなら、焚き火にもキューブの駆動にも使える。

野外には木の prop が多く散布されている。wild ゾーンでは、散布の重みの約半分が `tree_a` と `tree_b` である。木は HP を持ち、殴って壊せる。しかし木には分解定義がないので、壊しても何も落ちない。見た目は燃料の山なのに、手に入るものがない。

分解定義を持つ prop は、殴り壊すと確定枠が 30% の確率で落ちる。これは工具のない序盤を救うための経路である。工具で分解すると、確定枠は必ず出て、確率枠とボーナス枠も加わる。木に分解定義を足せば、素手でも斧でも燃料が取れるようになる。

## 要件

- 木を素手で殴り倒すと、薪が必ず落ちる
- 素手は時間がかかる。斧での伐採は速く、量も多い。このトレードオフを残す
- 薪は燃料として使える。専用の燃料機構は作らず、素材と重さから熱量を導く既存の経路に乗せる
- 他の prop の破壊回収の確率は変えない

## 設計

### 薪アイテム

薪 `firewood` を新しく作る。WOOD 素材で 1kg にする。熱量は 200 で、地面の火では 100 ターン燃える。既存の `hardwood` は 3kg の建材なので、燃料には使わない。

```toml
[[items]]
description = "Split wood for burning."
name = "Firewood"
id = "firewood"
material = "WOOD"
spriteKey = "firewood"
spriteSheetName = "field"
value = 3
weight = "1 kg"
```

### 分解定義に破壊回収の確率を持たせる

分解定義に、省略可能な `destroySalvageChance` を足す。殴り壊したとき、確定枠はこの確率で落ちる。省略すると、今の既定値 `lifecycle.DestroySalvageChance` の 30 を使う。木だけ 100 にする。

```tsp
// 変更前
model Disassembly {
  toolCategory: ToolCategory;
  baseAP: DisassemblyBaseAP;
  yields: DisassemblyYield[];
  bonus?: DisassemblyBonus[];
}

// 変更後
model Disassembly {
  toolCategory: ToolCategory;
  baseAP: DisassemblyBaseAP;
  yields: DisassemblyYield[];
  bonus?: DisassemblyBonus[];
  /** 殴り壊したときに確定枠が出る確率。省略すると既定値を使う */
  destroySalvageChance?: DisassemblyChance;
}
```

`RollDisassemblyYields` の破壊回収の判定は、既定値の代わりに定義の値を使う。

```go
// 変更前
if !full && rng.IntN(100) >= DestroySalvageChance {

// 変更後
if !full && rng.IntN(100) >= destroySalvageChance(def) {
```

### 伐採の工具カテゴリ

`ToolCategory` に `chopping` を足し、斧系の武器に分解工具の定義を付ける。

```tsp
enum ToolCategory {
```

### 木の分解定義

`tree_a`、`tree_b`、`big_tree` に分解定義を付ける。

```toml
[props.disassembly]
toolCategory = "chopping"
baseAP = 1500
destroySalvageChance = 100
[[props.disassembly.yields]]
id = "firewood"
count = "1d2"
[[props.disassembly.yields]]
id = "firewood"
count = "1d2"
chance = 60
```

`big_tree` は baseAP を 2500 にし、確定枠を 2d2、確率枠を 1d3 にする。

| 経路 | 1 本あたりの時間 | 1 本あたりの薪 | 燃焼ターン/作業ターン |
|---|---|---|---|
| 素手で殴り倒す | 長い。木の HP を拳で削り切るまで | 確定枠のみ | 低い |
| 斧で伐採する | 短い。baseAP を工具グレードで短縮する | 確定枠、確率枠、ボーナス枠 | 素手の 3 倍以上 |

素手の比率は 1 を超えていればよく、燃料不足は解消する。比率が低いほど、殴っている時間が長くなる。

素手の 1 打あたりの期待ダメージは約 11 で、HP 20 の木は 2 打で倒れる。これでは素手の比率が斧を上回る。木の HP を上げて、素手の遅さを打数で表す。

| 木 | HP | 素手の打数 | 素手の比 | 斧の作業ターン | 斧の比 |
|---|---|---|---|---|---|
| `tree_a`、`tree_b` | 330 | 29.5 | 5.1 | 12.0 | 21.2 |
| `big_tree` | 550 | 49.1 | 6.1 | 20.0 | 22.0 |

### prop を殴ったときのスキル経験値

武器スキルは、命中すれば対象の種類を問わず経験値が入る。木の HP を上げると、反撃せずどこにでもある木が安全なスキル稼ぎの的になる。

prop が相手のときは、`skill.GainExpScaled` で基本経験値を 10% にする。経験値には最低 1 の下限があるので、prop を殴ると 1 打あたり常に 1 入る。敵を殴ると、能力 10 なら Lv0 で 15、Lv30 で 2 入る。序盤から中盤の稼ぎは抑えられるが、Lv50 以上では差がなくなる。終盤は 1 レベルに要る打数がもともと多いので、この差は許容する。

```go
// propSkillEfficiency は prop を殴ったときの武器スキル経験値の倍率
const propSkillEfficiency consts.Percent = 10
```

### 産出の期待値

balance レポートが抽選と同じ確率を使えるよう、`lifecycle.ExpectedDisassemblyYields` を足す。産出の当選確率は `yieldChance` の 1 か所で決め、抽選と期待値の両方が使う。工具分解の確定枠では乱数を引かず、既存の抽選列を保つ。

### balance レポート

`balance/logistics.go` に、木 1 本あたりの次の値を足す。

- 素手と斧それぞれの作業ターン
- 得られる薪の期待値と燃焼ターン
- 燃焼ターン/作業ターンの比率

数値を変えると `docs/balance/baseline.md` の差分に出るようにする。

### 居座りへの扱い

木は多いので、木が尽きることで居座りを止めることはできない。地図は位置の純関数で導出しているので、伐った木を保存しない限り、チャンクを移れば木はまた手に入る。

居座りの抑止は、この doc では扱わない。北ほど木を減らす別の設計で扱う。今は食料が足りているので、時間のコストが空腹として効く抑止も弱い。

## 採用しなかった方法

- **破壊回収を全 prop で確定にする**: 家具の救済バランスまで変わる。工具で分解する価値も薄れる
- **素手でも伐採作業をできるようにする**: 殴り壊しと同じことをする動詞が二重になる
- **殴るたびに枝を少しずつ落とす**: 被ダメージの経路に採取が混ざり、責務が濁る
- **`hardwood` を燃料に流用する**: 3kg で序盤の背包に重い。説明も建材向けである
- **prop を殴ってもスキルを伸ばさない**: 殴ることに経験の手応えが全くなくなる。少しずつは伸びるほうがよい
- **伐った木を再生させない**: 地図を位置から導出する設計を崩し、地形の保存が要る。チャンクを移れば済むので抑止にもならない
