# 窓を視線が通る開閉可能な開口部にする

## 背景

屋内に生成される窓は、現在は前壁タイル DWall の上に載る静的な装飾 prop である。窓 prop 自身は `blockView=false`・`blockPass=false` で何も遮らないが、下の DWall タイルが `BlockView` と `BlockPass` を持つため、窓の位置は視線も通行も遮る。また窓は開閉できず、通行にも関与しない。

視線は `internal/systems/vision.go` の `buildBlockViewIndex` が `BlockView` を持つエンティティを集めて Bresenham で判定する。通行は `internal/world/query/singleton.go` の `buildSpatialIndex` が `BlockPass` を集めて判定する。視線と通行は独立した2属性で、消費側も別経路である。

窓は扉とほぼ同じで、唯一の違いは「視線を常に通す」点だけである。扉は壁の切れ目に扉エンティティを立て、閉状態で通行と視界を遮り、ぶつかると開く。窓はこの扉機構をほぼそのまま使える。

## 要件

- 窓は開閉できる。
- 開閉で通行が決まる。閉は通れない、開は通れる。
- 視線は開閉どちらの状態でも常に通す。

## 設計

窓を「視線を通す扉」として実装する。既存の `Door` コンポーネント、`InteractionDoor`、開閉アクティビティ `OpenDoorBehavior`・`CloseDoorBehavior`、`lifecycle.OpenDoor`・`CloseDoor`・`updateDoorState`、扉ロックをそのまま再利用し、差分を1つのフラグに閉じる。あわせて窓を「壁の上の装飾」から「壁の切れ目＝開口部」へ格上げし、扉の戸口と同じく窓タイルを床の切れ目にする。これで下の DWall が消え、視線が通る土台になる。

### コンポーネント

`Door` に視線を常に通すフラグを足す。true のとき開閉に関わらず `BlockView` を付けない。

変更前:

```go
type Door struct {
	IsOpen      bool            // 開いているかどうか
	Orientation DoorOrientation // 扉の向き
	Locked      bool            // ロック中は開閉不可
}
```

変更後:

```go
type Door struct {
	IsOpen      bool            // 開いているかどうか
	Orientation DoorOrientation // 扉の向き
	Locked      bool            // ロック中は開閉不可
	SeeThrough  bool            // 開閉に関わらず常に視線が通す窓。true のとき BlockView を付けない
}
```

`Door` は `genspec/registry.go` に型として登録済みで、生成コードは型のみを参照しフィールドを列挙しない。よってフィールド追加に登録表の変更は不要で、`make generate` は差分ゼロの確認に回す。`Door` は永続化対象だが `skipComponents()` 非対象で、追加は単純 bool なので serde 往復に影響しない。旧セーブに窓は無く移行も不要である。

### 開閉トグル

`updateDoorState` で `SeeThrough` を分岐に使う。窓はスプライトが1種類のみで開閉で差し替えられないため、スプライト差し替えも抑止する。

```go
func updateDoorState(world w.World, doorEntity ecs.Entity, orientation gc.DoorOrientation, isOpen bool) error {
	doorComp := world.Components.Door.Get(doorEntity)
	// BlockPass/BlockView の Add/Remove は archetype を変え doorComp ポインタを無効化するため、
	// 変更前にフラグをローカルへ退避する。Ark strict semantics。
	seeThrough := doorComp.SeeThrough
	doorComp.Orientation = orientation
	doorComp.IsOpen = isOpen

	if !seeThrough {
		// スプライト差し替えは扉のみ。窓は単一スプライト window を両状態で維持する
		// ... 既存の door_*_open / door_*_closed 差し替え ...
	}

	if isOpen {
		// BlockPass は常に外す
		if !seeThrough {
			// BlockView も外す。窓は元々 BlockView を持たない
		}
	} else {
		// BlockPass は常に足す
		if !seeThrough {
			// BlockView も足す
		}
	}
	return nil
}
```

窓は開で `BlockPass` を外すだけ、閉で `BlockPass` を足すだけになる。`BlockView` は一切触らない。

### 生成関数

`SpawnDoor` を土台に `SpawnWindow` を新設する。`BlockView` を付けない点と、スプライトと `SeeThrough` が差分である。

```go
func SpawnWindow(world w.World, pos consts.Coord[consts.Tile], orientation gc.DoorOrientation) (ecs.Entity, error) {
	return world.Components.AddEntity(world.ECS, &gc.EntitySpec{
		Name:            &gc.Name{Name: "窓"},
		Description:     &gc.Description{Description: "開閉できる窓。閉じていても視線は通る"},
		GridElement:     &gc.GridElement{Coord: pos},
		SpriteRender:    &gc.SpriteRender{SpriteSheetName: fieldSpriteSheet, SpriteKey: "window", Depth: gc.DepthNumTaller},
		Fixed:           &gc.Fixed{},
		BlockPass:       &gc.BlockPass{}, // 初期は閉。BlockView は付けない
		LocationOnField: &gc.LocationOnField{},
		Door:            &gc.Door{IsOpen: false, Orientation: orientation, SeeThrough: true},
		Interactable:    &gc.Interactable{Interactions: []gc.InteractionKind{gc.InteractionDoor}},
	})
}
```

### 開口部化 Site モデル

窓を扉の戸口と同じ開口部として扱い、窓タイルを壁でなく床の切れ目にする。`Site` に窓の集合を持たせ、`Walls()` から除外する。

```go
type Site struct {
	// ... 既存 ...
	Windows map[Vec]bool // 視線を通す開口部の前壁タイル。Walls から除外し床の切れ目にする
}
```

`facadeElements` を回す箇所で `Ref=="window"` の位置を `Windows` に集める。`shutter` は壁のまま集めない。窓のスプライト `Placed` と開口部集合の単一ソースを `facadeElements` に保つ。`Walls()` の skip 条件に `Windows[v]` を足す。

### overworld 生成

`furnishBuilding` で、部屋戸口の扉ループの後に `Site.Windows` を走査し、各位置で `lifecycle.SpawnWindow` を呼ぶ。向きは扉と同じ `doorOrientation` で決める。窓タイル自身だけが `wallSet` から抜けるので、軸方向の隣接は壁のまま残り向き判定は機能する。`placed` ループでは `Ref=="window"` をスキップし、装飾 prop としての二重生成を防ぐ。VRT 描画用に `spriteFiles` の `window` は残す。

### golden パリティ

`sprite_golden_test.go` の `renderStage` の基底タイル分岐に窓を追加し、開口部として描く。窓スプライトは従来どおり上乗せする。ゲーム内と VRT の見た目を一致させる。

## 採用しなかった方法

- **専用 `Window` コンポーネント＋独自アクティビティ**: 開閉アクティビティ一式を重複させる。`Door.SeeThrough` なら既存の開閉・ロックを無償で使える。DRY でなく不採用。
- **raw の `window` prop に `[props.door]`＋独自フラグを足し `SpawnProp` で生成**: raw スキーマ変更と再生成が要り、向きが Horizontal 固定。屋内扉も raw 経路を使っておらず一貫しない。不採用。
- **窓を壁の上の装飾のまま、壁タイルの `BlockView` だけ外す**: 壁タイルは `BlockPass` も持つため通行が状態非依存に固定され、開閉で通行を変えられない。成立せず不採用。

## コメント

- **開いた窓は通行可能な外壁の開口部になる**。扉を介さず建物へ出入りできる。要件「通行は開閉で決まる」の直接の帰結である。初期状態を閉にすることで影響を限定する。「視線が通るドア」として開閉できる窓にする方針を採り、この挙動は許容する。
- **扉ロック `LockAllDoors`・`UnlockAllDoors`・`InteractionDoorLock` は全 `Door` を掃く**ので窓も開閉される。ガードにより窓は `BlockPass` のみ切り替わり `BlockView` は不変。挙動としては許容だが認識しておく。
- **Ark ポインタ無効化**に注意する。`updateDoorState` で `SeeThrough` を変更前に退避する。守らないと既存扉と同種のバグになる。
- **shutter は不透明のまま**にする。閉じたシャッターは視線を遮るのが自然なので、変更対象は `window` のみとする。
- **golden の変更は広範**になる。全屋内建物で窓の基底タイルが壁から開口部へ変わる。回帰ではないが、VRT のトレランスで色変化が隠れうるため、該当 golden を削除して強制再生成し差分を目視する。
