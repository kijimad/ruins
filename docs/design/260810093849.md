# アイテム行を共通ビルダに集約しアイコンを表示する

## 背景

アイテムを一覧表示するメニューは複数ある。いずれも各行を文字列セルで組み、視覚的なアイコンが無い。名前を読まないと何のアイテムか判別できず、スキャン性が低い。

アイテムは全てフィールド表示用のスプライトを持つ。`NewItemSpec` が `EntitySpec.SpriteRender` を必ず設定し、未指定でも既定 `field/field_item` を割り当てるため、実行時に `world.Components.SpriteRender.Get(entity)` が必ず引ける。この既存スプライトを名前の左に小さく出せば識別性が上がる。

ただしアイコンを各メニューへ個別に足すと同じコードが散る。アイテムを扱うメニューは行の作り方が三者三様に見えて、実は共通度が高い。行レベルで1つのビルダへ集約し、そこにアイコンを持たせれば、対象メニュー全てに一度で伝播し、将来のアイテムメニューも自動でアイコンを得る。

### 現状のアイテム一覧メニュー

| # | メニュー | 行を組む箇所 | 列構成 | entity 保持 | 描画基盤 |
|---|---|---|---|---|---|
| 1 | アイテム/アクション | `states/item_action_state.go buildItemList` | 名前×個数, 重量 | ○ `itemActionEntry.Entity` | `renderMenuList` |
| 2 | 収納 | `states/storage_menu.go buildActiveListContainer` | 名前×個数, 重量 | ○ `storageItemData.Entity` | `renderMenuList` |
| 3 | 商人売買 | `states/shop_menu.go buildItemContainer` | 名前×個数, 価格, 重量 | ○ `shopItemData.Entity` | `renderMenuList` |
| 4 | クラフト | `states/craft_menu.go buildItemContainer` | 合成可否, レシピ名 | ✕ `RecipeID string` | `renderMenuList` |
| 5 | 装備スロット | `states/character_view.go buildEquipList` | スロット名, 装備名 | ○ | `renderMenuList` |
| 6 | 装備候補選択 | `states/character_view.go buildEquipSelectWindow` | 名前のみ | ○ | 独自 |

阻む構造:

- **行が文字列専用**。`menuRow.Cells []string`、`states/lib.go:129`、から `renderMenuList`、`states/lib.go:149`、を経て `styled.NewTableRow(values []string, ...)`、`widgets/styled/table.go:74`、へ渡り各セルは `widget.NewText` になる。画像 widget を差す口が無い。
- **共有のアイテム行型・ビルダが無い**。`itemActionEntry`、`storageItemData`、`shopItemData` はメニュー別に定義され、`itemActionEntry` と `storageItemData` は Entity/Name/Weight/Count がほぼ同一のコピーになっている。
- **entity/SpriteRender から画像を得る公開ヘルパが無い**。フィールド描画の `RenderSpriteSystem.getImage` は private・System 依存で UI から呼べない。`widget.NewGraphic` はコードベースで未使用。

## 要件

- アイテムを名前×個数で並べるメニュー、#1 アイテム・#2 収納・#3 商人売買、を**単一のアイテム行ビルダ**へ通す。
- そのビルダが行の先頭に「アイコン＋名前×個数」を組む。アイコンは entity の `SpriteRender` から解決する。スプライト未指定のアイテムは既定 `field_item` がそのまま出る。
- メニュー固有の列、重量・価格、はビルダに trailing として渡し、後続セルに置く。
- 既存の行高・ページング・選択ハイライト・見出し行を壊さない。共通基盤の拡張は後方互換にし、アイコンを使わない他メニューは無改変で通す。
- #4 クラフト・#5 装備スロット・#6 装備候補は対象外とする。「名前×個数」パラダイムから外れ、共通ビルダの利が薄い。
- 対象メニューの golden 画像を再生成する。

## 設計

下から積む。(A) 画像解決 → (B) 画像セル widget → (C) 行パイプラインのアイコン列対応 → (D) 共通アイテム行ビルダ → (E) 各メニューの適用。

### A. アイテム → 画像の解決ヘルパ（新規）

`SubImage` と同じ `internal/components/sprite.go` に、`SpriteSheet` と `SpriteRender` だけを引数に取る純粋関数を置く。ebiten 依存は `SubImage` で既にあるため package の責務を広げない。

```go
// SpriteImage は SpriteRender が指すスプライトの部分画像を返す。
// シートかキーが見つからなければ ok=false
func SpriteImage(sheets map[string]SpriteSheet, sr *SpriteRender) (*ebiten.Image, bool)
```

### B. 画像セルの widget 化ヘルパ（新規）

`internal/widgets/styled` に、`*ebiten.Image` を行高に収まる正方アイコンにするヘルパを足す。`widget.NewGraphic` を使う最初の箇所になる。

```go
// NewSpriteCell は img を一辺 size のアイコン widget にする。
// スプライト原寸はタイル大でも size に収まるよう縮小して描く
func NewSpriteCell(img *ebiten.Image, size int) *widget.Graphic
```

縮小は `NewSpriteCell` 内で吸収する。原寸のフィールドスプライトはタイルサイズで行高 `tableRowHeight = 20`、`widgets/styled/table.go:22`、より大きいため、`size` へ収まるよう拡縮した画像を Graphic に渡す。ここが唯一の見た目調整点になる。

### C. 行パイプラインのアイコン列対応（機構）

行データにオプションのアイコンを1つ持たせる。`nil` ならアイコン列は空セルにする。

```go
// 変更前: states/lib.go
type menuRow struct {
	Cells  []string
	Header bool
}

// 変更後: 先頭アイコンをオプションで持つ
type menuRow struct {
	Icon   *ebiten.Image // nil 可。テーブルがアイコン列を持つとき各行の先頭セルへ描く
	Cells  []string
	Header bool
}
```

`renderMenuList` はテーブルがアイコン列を持つかを行データから判定し、持つ場合は各行へ、`Icon` があれば `NewSpriteCell`、無ければ空セル、を先頭に追加する。GridLayout の列数は `len(colWidths)` で、`renderMenuList` は列数不一致で panic する、`states/lib.go:155-158`、ため、呼び出し側はアイコン列込みの `colWidths`・`aligns` を渡す。見出し行・空行埋めも先頭セルを持ち列数を揃える。`styled.NewTableRow` は文字列 API を保ったまま先頭アイコンセルを受けられるよう拡張する。

### D. 共通アイテム行ビルダ（中心）

`menuRow` は states 内の非公開型なので、ビルダも `states/lib.go` に置く。名前・個数・アイコンは全て entity から解決し、呼び出し側は追加列だけ渡す。

```go
// itemMenuRow は アイテム entity から共通の先頭部 [アイコン + 名前×個数] を組み、
// メニュー固有の trailing 文字列セルを後続に付けた menuRow を返す。
func itemMenuRow(world w.World, e ecs.Entity, trailing ...string) menuRow {
	name := query.GetEntityName(e, world)
	count := stackCount(world, e) // Stackable が無ければ 1
	icon, _ := gc.SpriteImage(world.Resources.SpriteSheets, world.Components.SpriteRender.Get(e))
	return menuRow{
		Icon:  icon,
		Cells: append([]string{nameWithCount(name, count)}, trailing...),
	}
}

// itemMenuColumns は 先頭 [アイコン, 名前] の共通幅・align に、
// メニュー固有の trailing 列を足した colWidths/aligns を返す。
func itemMenuColumns(trailing []menuColumn) (colWidths []int, aligns []styled.TextAlign)
```

先頭2列、アイコンと名前、の幅・align を共通化することで、対象メニュー間でアイコンと名前の見た目が揃う。アイコン幅は行高と同じ正方にする。

### E. 各メニューの適用

3メニューの `buildXxx` は自前で `menuRow{Cells: []string{...}}` を組むのをやめ、`itemMenuRow` を呼ぶ。

```go
// #1 item_action buildItemList
rows[i] = itemMenuRow(world, it.Entity, it.Weight)
// #2 storage buildActiveListContainer
rows[i] = itemMenuRow(world, d.Entity, d.Weight)
// #3 shop buildItemContainer
rows[i] = itemMenuRow(world, d.Entity, query.FormatCurrency(price), weight)
```

列定義も `itemMenuColumns` に寄せ、各メニューは trailing 列、重量や価格、だけを指定する。行高 `tableRowHeight` は変えず、アイコンを行高へ縮小して収めるので他メニューの行高は影響を受けない。

## 採用しなかった方法

- **メニュー個別にアイコン列を足す**: #1/#2/#3 に同じアイコン解決・列組みが3箇所散る。行レベルの共通ビルダへ集約するほうが、アイコンを1箇所に書け、将来のアイテムメニューも自動で得る。ユーザー方針の「行レベル共通化」に沿う。
- **#4 クラフト・#5 装備スロット・#6 装備候補も同じビルダへ乗せる**: #4 はレシピで entity を持たずアイコン解決経路が別、#5 は「スロット名/装備名」、#6 は裸の名前で個数整形が無い。名前×個数パラダイムから外れ、無理に統合すると分岐が増える。対象外にする。
- **`renderMenuList` を使わず item 用の行描画を新設する**: ページング・選択・見出し・空行埋めを重複実装する。共通基盤にアイコン列をオプトインで通すほうが DRY。
- **グローバル `tableRowHeight` を上げてスプライトを原寸表示する**: 全メニューの行高が変わり golden が広範に崩れる。アイコンを行高へ縮小する。
- **名前セルにインライン画像を混ぜる**: `widget.NewText` は文字列専用で画像を混在できない。別セルにする。
- **`query` に entity→画像ヘルパを置く**: `query` はゲームデータ層で ebiten 画像依存を持ち込みたくない。`SubImage` と同じ `components/sprite.go` に純粋関数として置く。

## コメント

- 挙動を変えるのは #1/#2/#3 のアイテム一覧のみ。共通基盤、`lib.go`・`styled/table.go`、の拡張は後方互換で、アイコンを使わない他メニューは無改変で通す。
- `itemActionEntry` と `storageItemData` は Entity/Name/Weight/Count がほぼ同一の重複型。共通ビルダが entity から名前・個数を解決する形にすると、これらの Name/Count フィールドは表示用途では不要になる。本 doc ではビルダ導入に続けて、この重複型の一本化まで行う、下記 F。`shopItemData` は entity から都度引く方針でフィールドを持たないため、統合対象は `itemActionEntry` と `storageItemData` の2つ。
- `SpriteImage` の公開で、将来 `RenderSpriteSystem.getImage` と HUD の `drawWeaponSprite` の重複解決ロジックをここへ集約できる。本 doc の対象外だが、置き場所はそれを見越して `components/sprite.go` にする。
- 変更後は `make check` で検証し、対象メニューの golden を `make updategolden` で再生成する。VRT のトレランスがアイコン追加を隠さないよう、該当 golden は削除して強制再生成する。
