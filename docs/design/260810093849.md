# 一覧のセルをアイコンを持てる型にし、アイテム・装備にアイコンを表示する

## 背景

アイテムや装備を一覧表示するメニューは複数あり、各行を文字列セルで組んでいて視覚的なアイコンが無い。名前を読まないと識別しづらい。アイテムは全てフィールド用スプライトを持つので、それを名前の近くに小さく出せば識別性が上がる。

当初はアイテムメニュー、アイテム/収納/売買、に「行の先頭アイコン」を足す形で実装した。しかし次の要求でこの抽象が破綻した。

- **構造の違うメニューに広げられない**。装備スロットは `{スロット名, 装備名}` で、アイコンを装備名の隣に置きたい。先頭固定のアイコン列では表現できない。
- **アイコンが任意の列に要る**。将来はアイテムスプライト以外に、各パラメータのアイコンを値の隣に出したい。アイコンは特定の列に固定されない。
- **先頭アイコンの機構がフットガンだった**。`menuRow.Icon` と `menuListOpts.HasIcon` と列数調整 `dataCols-1` の三点が噛み合って初めて正しく、売買メニューで HasIcon の立て忘れにより列数不整合で panic した。

結論は「行を共通化する」のではなく「**セルの抽象を上げる**」。行が先頭に特別なアイコンを持つのをやめ、**セルが文字列かアイコンのどちらかを表せる**ようにする。すると行は一様な `[]Cell` になり、アイコンは任意の列に置け、パラメータアイコンもそのまま乗り、列数の特別扱いもフットガンも消える。

## 要件

- 一覧のセルを、文字列またはアイコンを表せる `styled.Cell` にする。行は `[]Cell` に一様化する。
- アイコンは任意の列に置ける。アイテムメニューは名前の左、装備メニューは装備名の左、将来のパラメータはその値の隣。
- アイテムメニュー、アイテム/収納/売買、と装備スロット一覧に、対象アイテムのスプライトアイコンを表示する。スプライトは entity の `SpriteRender` から解決する。空きスロットはアイコン無し。
- 既存の行高・ページング・選択ハイライト・見出し行を壊さない。アイコンを使わない他メニュー、選択肢・設定・メインメニュー・クラフト・職業・隊列・コンポーネントデバッグ・詳細モーダルの性能表、は文字列セルのまま同じ見た目で通す。
- 先頭アイコン専用の機構、`menuRow.Icon`・`menuListOpts.HasIcon`・`renderItemMenuList`・列数の `dataCols` 調整、を撤去する。列数はセル数と常に一致する。
- 対象メニューの golden を再生成する。

## 設計

### A. アイテム → 画像の解決ヘルパ（既存のまま）

`internal/components/sprite.go` の `SpriteImage(sheets, sr) (*ebiten.Image, bool)` を使う。全アイテムが `SpriteRender` を持つので entity から解決できる。

### B. セル型と描画（`internal/widgets/styled/table.go`）

セルを文字列かアイコンのどちらかを表す型にする。

```go
// Cell は一覧の1セル。Icon が非 nil ならアイコンセル、nil なら文字列セル。
// 将来アイコンと文字列を1セルに併記したくなったら両方を持たせて拡張できる
type Cell struct {
	Text string
	Icon *ebiten.Image
}

func TextCell(s string) Cell            { return Cell{Text: s} }
func IconCell(img *ebiten.Image) Cell   { return Cell{Icon: img} } // img が nil なら透明セル
func TextCells(ss ...string) []Cell     // 文字列だけの行を手早く組む
```

`NewTableRow` と `NewTableRowColored` は `values []string` をやめ `cells []Cell` を取る。各セルは `Icon` が非 nil なら `NewSpriteCell(cell.Icon, tableRowHeight)`、nil なら `NewText(cell.Text)` で描く。列幅・align は従来どおり列ごとの配列で受ける。`NewTableHeaderRow` は見出し専用で文字列のまま。先頭アイコン専用の `NewTableRowWithIcon` と `add*` の icon 引数は撤去する。`NewSpriteCell` は残す。

### C. 一覧パイプライン（`internal/states/lib.go`）

`menuRow` の `Icon` を廃し、`Cells` を `[]styled.Cell` にする。

```go
type menuRow struct {
	Cells  []styled.Cell
	Header bool
}
```

`menuListOpts.HasIcon`・`dataCols`・`withIconHeader`・`renderItemMenuList` を撤去する。`renderMenuList` は `len(row.Cells) == len(colWidths)` を一様に検査する。空行埋めは `styled.TextCells` の空白セル。アイコン列も普通の1列として `colWidths` に含める。列数がセル数と常に一致するので、売買で踏んだ列数不整合の panic はクラスごと消える。

### D. アイテム行ヘルパ（`internal/states/lib.go`）

`itemMenuRow` は entity から `[アイコンセル, 名前×個数セル]` を組み、trailing の文字列セルを足す。列は普通の列指定にする。`itemMenuColumns` の `HasIcon` 前提は消え、先頭に `[アイコン列, 名前列]` を置く通常の列ヘルパになる。

```go
func itemMenuRow(world w.World, e ecs.Entity, trailing ...string) menuRow {
	name := query.GetEntityName(e, world)
	count := query.GetEntityCount(world, e)
	icon, _ := gc.SpriteImage(world.Resources.SpriteSheets, world.Components.SpriteRender.Get(e))
	cells := append([]styled.Cell{styled.IconCell(icon), styled.TextCell(nameWithCount(name, count))}, styled.TextCells(trailing...)...)
	return menuRow{Cells: cells}
}
```

item/storage/shop は `renderMenuList` を直接呼ぶ。`renderItemMenuList` は不要。

### E. 装備スロット一覧（`internal/states/character_view.go buildEquipList`）

行を `{スロット名, アイコン, 装備名}` にし、アイコンを装備名の左へ置く。空きスロットは `Entity == nil` なので `styled.IconCell(nil)` の透明セルにする。

```go
columnWidths := []int{120, itemIconColumnWidth, 220}
// 各スロット
var icon *ebiten.Image
if slot.Entity != nil {
	icon, _ = gc.SpriteImage(world.Resources.SpriteSheets, world.Components.SpriteRender.Get(*slot.Entity))
}
rows[i] = menuRow{Cells: []styled.Cell{styled.TextCell(slot.SlotLabel), styled.IconCell(icon), styled.TextCell(slot.ItemName)}}
```

### F. 文字列セル専用メニューの移行

`renderMenuList` を使う他メニューと `views.RenderSpecRows` は、`menuRow{Cells: []string{...}}` や `NewTableRow(values)` を `styled.TextCells(...)` へ機械的に置換する。見た目は不変。

## 採用しなかった方法

- **先頭アイコン列のまま装備も乗せる**: アイコンが装備名の隣に来ず、パラメータアイコンにも広がらず、`HasIcon` フットガンが残る。局所パッチで抽象の是正にならない。
- **`menuRow` に `Cells []string` と `Icons []*ebiten.Image` の並行配列を持たせる**: アイコン無しメニューを無改変にできるが、セルの属性が増えるたびに並行配列が増える。セルを構造体にするほうが将来のパラメータ表示、色・幅の付与に素直に伸びる。
- **セルを任意の ebitenui widget にする**: 最大限柔軟だが過剰。実需は文字列とアイコンで足りる。YAGNI。まず `Cell{Text, Icon}` に留める。

## コメント

- 当初の「行の先頭アイコン」実装、`menuRow.Icon`・`HasIcon`・`renderItemMenuList`、はこの設計で置き換える。売買の panic はこの機構の脆さが原因だったので、置き換えは将来対応であると同時に既存バグ源の除去でもある。
- アイコンの出所は `Cell.Icon` の `*ebiten.Image` に閉じる。アイテムスプライトでもパラメータアイコンでも、解決関数を分けるだけで同じセルに入る。
- `SpriteImage` の公開で、将来 `RenderSpriteSystem.getImage` と HUD の `drawWeaponSprite` の重複解決をここへ集約できる。本 doc の対象外。
- 変更後は `make check` で検証し、対象メニューの golden を `make updategolden` で再生成する。VRT のトレランスが更新を隠さないよう該当 golden は削除して強制再生成する。文字列専用メニューと詳細モーダルの golden は見た目不変で変わらないはず。変わったら移行に取りこぼしがある。
