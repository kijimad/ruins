# キューブUI強化。運転中の燃料ゲージと燃料メニューの熱量列

## 背景

キューブは移動拠点かつ乗り物で、運転は収納物の熱量を燃料として消費する。現状 UI に燃料の情報が薄く、次の2つの不足がある。

- **運転中に残燃料が見えない**。燃料切れは移動しようとした瞬間に "Out of fuel" ログで初めて分かる。`ConsumeCubeFuel` は収納アイテムを丸ごと単位で削るため、あと何タイル走れるかの手応えが無い。運転HUDには HP・体温・気温・重量ゲージは出るが燃料ゲージが無い。参考 codebase: `internal/systems/hud_extractor.go`、`internal/widgets/hud/game_info.go`、`internal/world/query/cube.go` `CubeFuelTotal`。
- **燃料メニューで熱量が見えない**。キューブの燃料投入画面は汎用 `StorageMenuState` を可燃物フィルタで再利用しており、列は「アイコン｜名前×個数｜重量」。どのアイテムが燃料として効率的かを、熱量そのもので比べられない。参考 codebase: `internal/states/cube_menu.go`、`internal/states/storage_menu.go`。

キューブの達成感は「見える乗り物強化」で与える方針で、内部を歩ける安全地帯は作らない。燃料ゲージと熱量列はこの方針に沿う可視化強化で、新たな安全や携行拠点を与えない。参考 memory: cube-visible-upgrades-not-interior、no-portable-safe-zone-survival。

## 要件

1. **運転中の燃料ゲージ**。プレイヤーが `Driving` 状態のときだけ、HUD の既存ゲージ列に燃料ゲージを1本足す。運転していないときは出さない。燃料は運転にしか関わらないため、常時表示は HUD を汚す。
2. **燃料メニューの熱量列**。キューブ燃料メニューで各行に熱量を重量の左へ出す。汎用収納メニューには熱量列を出さない。燃料投入という文脈でだけ熱量が意味を持つ。

## 設計

### 熱量は保持せず都度算出する既存設計を踏襲する

熱量は専用コンポーネントを持たず、`Material` と `Weight` から純関数で導出する。この設計は変えない。導出可能な一時状態は component にしない方針に沿う。参考 memory: derivable-state-not-component。

```go
// internal/world/query/fuel.go 既存
func HeatContent(world w.World, e ecs.Entity) consts.Heat // Material×Weight から算出。可燃でなければ 0

// internal/world/query/cube.go 既存
func CubeFuelTotal(world w.World, cube ecs.Entity) consts.Heat // 収納物の HeatContent 総和
```

### 要件1。運転中の燃料ゲージ

#### 満量基準

ゲージは充填率 0..1 を要るが、キューブに「最大燃料量」フィールドは無い。重量容量 `CubeWeightCapacityKg = 500` は上限だが、これを満タン基準にすると理論最大熱量が巨大になりゲージは常にほぼ空になる。そこで表示専用の基準定数を1つ置き、それに対する比でゲージを描く。車の燃料計がタンク容量に対する比であるのと同じ発想で、ここではタンク容量を設計側の定数で与える。

```go
// internal/consts に追加
const FuelGaugeFullHeat Heat = 3000 // 燃料ゲージが満タン表示になる熱量。値は暫定
```

暫定値3000の裏付けは走行コスト `DriveFuelCost = DriveFuelBase + DriveFuelPerKg × kg` との対比で見る。`DriveFuelBase = 5`、`DriveFuelPerKg = 1` なので、空のキューブは1タイル5熱量で満タン相当が約600タイル、100kg 積みは1タイル105熱量で約28タイル、容量上限500kg では1タイル505熱量で約6タイルになる。満タンの手応えを空キューブで数百タイル、満載で数タイルに置くのが暫定の狙い。確定はこの対比を出発点に実プレイで詰める。

```go
// internal/world/query/cube.go に追加
// FuelGaugeRatio は運転HUDの燃料ゲージ充填率。満量基準に対する現在熱量の比を 0..1 に丸める。
func FuelGaugeRatio(fuel consts.Heat) float64
```

`FuelGaugeRatio` は熱量だけを引数に取る薄い純関数として切り出す。`hud_extractor` に割り算を直書きしても1行で済むが、満量基準の丸めとゼロ除算回避を単体テストで固定するために関数に分ける。

#### データ経路

HUD は `ExtractHUDData` が抽出し `GameInfoData` に積んで `game_info.go` が描く。運転中フラグと燃料充填率を `GameInfoData` に足す。

```go
// internal/widgets/hud/data.go の GameInfoData に追加
Driving   bool    // 運転中か。true のときだけ燃料ゲージを描く
FuelRatio float64 // 燃料ゲージ充填率 0..1
```

`PlayerDriving` はプレイヤーの `Driving` を comma-ok で返す薄いクエリ。無ければ足す。描画は既存 `gaugeWidget` を再利用し、`drawGauges` の `FlexItem` に燃料行を条件付きで1本挿す。色は残量警告のため満で琥珀、空へ近づくと赤へ補間する。HPゲージの補間と同じ手法で燃料用の色を theme に足す。

### 要件2。燃料メニューの熱量列

キューブ燃料メニューは `StorageMenuState` の可燃物フィルタ版で、汎用収納メニューと実装を共有する。「熱量」という燃料ドメインの知識を汎用メニューへ持ち込まないため、列を汎用の注入オプションにし、熱量列の定義は呼ぶ側の `cube_menu` に閉じる。収納メニューは列の意味を知らず、様式とセル文字列を呼ぶ側が渡す。

```go
// internal/states/storage_menu.go に追加
func WithColumn(style styled.Col, cell func(w.World, ecs.Entity, int) string) StorageOption
```

```go
// internal/states/cube_menu.go の Fuel 選択で熱量列と間隔列を注入する。fuelHeatCell が束の総熱量を返す
NewStorageMenuState(cube, WithItemFilter(isFuelItem), WithStoreOnly(), WithTitle(fuelTitle),
	WithColumn(styled.Num(), fuelHeatCell), WithColumn(styled.Fit(), emptyCell))
```

行データに熱量を持たせ、列とセルを条件分岐する。列とセルの順序は常に一致させる。熱量の総量は束の個数を掛ける。重量が総量表示なのに揃える。`consts.Heat.String()` は炎アイコン付き整数で、数値列は i18n を通さない既存規約のまま。

## なぜこの形か

- **満量基準を表示専用定数に閉じる**。ゲージは残量の相対把握が目的で、絶対量の厳密さは要らない。基準を定数1つに閉じれば、燃料に人工的な最大値フィールドを持たせず、保存もダーティ管理も増えない。導出可能な状態は保存しない不変条件を守る。
- **熱量列をオプションで局所化する**。汎用収納メニューは無改変のまま、燃料という文脈でだけ列が増える。共有実装に無条件で列を足すと関係ない画面へ波及する。フィルタと同じ「呼ぶ側が文脈を渡す」形に揃える。
- **既存ゲージと行ビルダーを再利用する**。`gaugeWidget` と `itemMenuColumns/itemMenuRow` をそのまま使い、新種の描画経路を作らない。列とセルは同じ順序で組み、片方だけずれる不整合を避ける。

## 採用しなかった代替

- **満量基準を重量容量から理論最大熱量で導く**。`HeatOf(最良燃料, 500kg)` を最大にする案。値が巨大で現実の積載と乖離し、ゲージが常にほぼ空になる。基準として使えない。却下。
- **ゲージを残り走行タイル数で描く**。`fuel / DriveFuelCost(重量)` で残タイルを比にする案。走行コストが現在のキューブ重量に依存するため、燃料を燃やさず貨物を積むだけでゲージが動く。燃料計として直感に反する。残タイルは将来、ゲージ脇の数値ラベルとして足す余地はあるが本案では見送る。
- **満量基準を運転開始時の燃料量にする**。走り出し時点を満タンとする案。ステートフルで保存が要り、`no-save-backward-compat` と `derivable-state-not-component` に反する。却下。
- **熱量列を汎用収納メニューにも常時出す**。実装は最小だが、燃料と無関係な収納画面に熱量が並び意味を持たない。可燃でないアイテムは 0 が並ぶだけで邪魔。却下。
- **焚き火メニューにも熱量列を足す**。焚き火メニューは既に熱量を火の効率で割った「追加燃焼ターン数」を出しており、熱量の生値より行動に直結する。要件は「重さの左」で、重さを出すのはキューブ燃料メニューだけ。対象外。

## コメント

- **満量基準 `FuelGaugeFullHeat = 3000` は暫定**。ここが唯一の needs-decision。運転の実プレイでゲージの手応えを見て調整する。バランス値一元化の将来方針に沿い、確定後は consts leaf へ寄せる余地がある。参考 memory: balance-consts-centralize-deferred。
- 燃料ゲージは運転中のみ。降車で `Driving` が外れると次フレームの抽出で自然に消える。
- キューブ燃料メニューは投入タブだけにする。燃料は入れたら即残数になり取り出さないため、取り出しタブは意味を持たない。`WithStoreOnly` で汎用収納メニューと分ける。
- `Driving`・`FuelRatio` を `GameInfoData` に相乗りさせる。運転HUDが今はゲージ1本で済む最小スコープだからで、給油ログや燃費表示など運転専用の要素が増えたら、`GameInfoData` から運転HUD専用のデータ構造とウィジェットへ分離する。
- 将来の水濡れデバフや燃料種別ごとの演出とは独立。本案は可視化に閉じる。
