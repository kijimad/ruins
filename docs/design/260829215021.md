# 焚き火と直交的な火: 寒さを生き延びる熱源

## 背景

本作は寒さを主題にするゲームで、プレイヤーは体温を保って生き延びる。体温は `HealthStatus.BodyTempOffset` が平熱からのずれを持ち、`TemperatureSystem` が環境有効温度から毎ターン更新する。環境より体が冷えれば低体温が進み、放置すると発症する。

暖房の土台は既にある。`HeatSource{Radius, Warmth}` を持つエンティティは `heatSourceWarmthAt` が半径内をチェビシェフ距離で線形減衰して集約し、`bodyTempRate` を通して体温を平熱へ押し戻す。熱源は平熱未満のときだけ効く。`bonfire` prop も既にあり `HeatSource` を持つが、置いた瞬間から永久に暖かい静的な物で、着火も燃料もない。

これでは「火を絶やさぬよう燃料をくべ続ける」という寒冷生存の核が生まれない。火を焚き火専用のハードコードにせず、燃えるという性質を多くのものへ広げた直交的な要素にする。燃焼を「燃料の熱量を火へ移し、火が熱を出す」一様な過程にすれば、現実らしさと拡張性が同時に得られる。

方針を先に置く。第一に、火はどこでも熾せる。地面に直に燃料を燃やせて、その火が体を温める。第二に、燃焼効率を持たせる。効率は火の持ちに効き、熱の強さは変えない。地面直の火は効率が低く薪をすぐ食う。効率を上げる据え付けのかまどは将来の拡張とし、今回は実装しない。第三に、タイルからタイルへ広がる延焼は主眼でないため入れない。直交性はデータに宿し、伝播には宿さない。第四に、本作は寒さ専用なので高体温の方向を撤去し、体温ゲージの最大を適温にする。

## 要件

- 燃えているものは半径内のプレイヤーを強く温める。体温は適温を超えないので、近づきすぎても高体温にならず安全である。
- 火種の道具を所持し、隣接タイルに任意の燃焼物があるとき、コンテキストメニューから火をつけられる。火は隣接タイルに立ち、足元は自分が燃えるので対象にしない。火をつけたタイルの燃焼物はすべて残ターン数へ畳み込まれる。
- 燃料の補充は給油メニューで行う。火に隣接して開き、持ち物の燃料を選ぶと即座に残ターン数へ加わる。くべた燃料は取り戻せない。投げる操作は要らない。
- 消火の手段は持たない。燃料をくべなければ残ターン数が減って自然に燃え尽きる。
- 燃焼効率を持つ。効率は燃焼時間に効き、熱の強さと広さは固定にする。地面直の火は効率が低い。
- 燃えるものは熱量が違う。可燃性は `Fuel` を持つかで判定し、燃えないものは持たない。
- 火は焚き火専用でなく直交的な性質にする。専用のオブジェクトも専用UIも持たない。
- 携帯できる火は持たない。火は地面のタイルに宿る。燃料アイテムは持ち運べ、燃やすと消費される。
- 光は火の責務にしない。照明はライトと電力の別系統が担う。本設計は暖房だけを扱う。
- 火の状態、予想燃焼時間は、給油メニューのタイトルと観察メニューで見せる。
- 体温の最大を適温にする。高体温と暑い環境ペナルティを撤去する。

## 調査結果

新設と流用の境目を実測で確認した。

- 体温は `HealthStatus.BodyTempOffset`、更新は `internal/systems/temperature.go` の `TemperatureSystem`。低体温 `ConditionHypothermia` と高体温 `ConditionHyperthermia` が実装済み。オフセットは `bodyTempMin=-5.0` から `bodyTempMax=5.0` にクランプする。
- 熱源は `internal/components/heat_source.go` の `HeatSource{Radius, Warmth}`。集約は `heatSourceWarmthAt` で距離線形減衰。熱源は `offset < 0` のときだけ効く安全設計。
- 火・燃焼・延焼・燃料の機構は component も system も存在しない。焚き火の暖房は延焼機構と無関係にゼロから設計できる。
- 位置は `GridElement`、prop 生成は `SpawnProp`、相互作用は `Interactable` と `InteractionKind` と `ExecuteInteraction` の三点。`ExecuteInteraction` は default を置かない網羅分岐。
- コンテキストメニューは `OpenInteractionMenu` から `GetSameTileManualActions` を呼び、プレイヤーの足元タイルの対象だけを扱う。隣接タイルは見ない。隣接の可燃物へ火をつけるには、対象を隣接へ向ける一手を足す必要がある。
- アイテム消費は `Consumable`。観察は examine の面が既にある。距離クエリは `internal/geometry` の `ChebyshevDistance` が揃う。

## 設計

### データの形

燃えるという性質を持つものと、今まさに燃えているものを分ける。前者は多くのアイテムが持ち、後者は火がついたタイルのエンティティが持つ。

```go
// Fuel は燃やせるものが持つ性質。多くのアイテムに付き、燃やしたときの熱量を表す。
// 木・紙・油で値が違う。火を焚き火専用にしないための核で、燃焼はこの熱量を火へ移す一様な過程になる。
type Fuel struct {
	HeatContent int // 燃やしたとき Fire の残量へ足す熱量。1 が1ターンぶんの燃焼に相当する
}

// Fire は今まさに燃えているエンティティに付く。地面のタイルに宿る。火は燃料を貯め込まず、
// 残ターン数だけを持つ。着火や給油のときに燃料の熱量が効率で割り引かれて Remaining へ畳み込まれる。
// Fire がある間だけ同じエンティティの HeatSource が暖房として効く。
type Fire struct {
	Remaining int // あと何ターン燃えるか。毎ターン減り、0 以下で外れて鎮火する
}
```

`HeatSource{Radius, Warmth}` は熱の profile として今のまま残す。`Fire` が暖房の on と off を、`HeatSource` が半径と強さを持つ。この2部品に分けると、地面直の火も将来のかまども同じ組み合わせで表せ、焚き火のための特別なコードパスが要らない。

### 可燃性は Fuel の有無で判定する

燃えるかどうかは `Fuel` を持つかで決める。燃えないものは `Fuel` を持たない。可燃フラグと熱量を別々に持たず、1つのコンポーネントが「燃えるか」を有無で、「どれだけ熱を出すか」を `HeatContent` で同時に担う。コンポーネントの有無を能力とみなす ECS の定石に沿う。`HeatContent` は常に正とし、燃えるが熱ゼロの `Fuel` は作らない。判定が有無だけで完結し、値のゼロ判定が要らなくなる。

何が燃えるかは raw の付け方で決める。薪だけを燃料にする厳しさから、食料や木の装備まで燃やせる緩さまで、機構を変えずに可燃物の範囲を振れる。食料に付ければ食べるか燃やすかの生存の葛藤が生まれ、付けなければ専用の燃料だけが燃える。

### 熱は固定、効率は燃焼時間に効く

温めの強さと広さは `HeatSource{Radius, Warmth}` が決め、全ての火で固定にする。燃料を燃やすと延びるのは `Fire.Remaining` すなわち燃える長さだけで、profile は変わらない。大きく育てて広く温めるのでなく、火を絶やさぬよう燃料を継ぐ、という単純な緊張にする。

燃焼効率は、同じ燃料からどれだけの燃焼時間を得るかの倍率にする。燃料をくべるとき、その燃料の熱量へ効率を掛けた燃焼時間を残ターン数へ足す。

効率はパーセントの整数で持ち、`HeatContent` へ掛けて100で割る。全て整数で閉じ、切り捨てで丸める。

```go
// 燃料を燃やし始めるとき: Fire.Remaining = その燃料の HeatContent * 効率 / 100
const groundBurnEfficiency = 50 // 地面直の火の効率をパーセントで。100 が等倍、地面直は低効率で薪をすぐ食う
```

効率は燃えている場所から引く。地面直の火は定数 `groundBurnEfficiency`、将来のかまどはかまどが持つ効率を使う。悪い効率はすぐ燃え尽き、良い効率は長持ちする。熱の強さは同じなので、良い火の見返りは暖かさでなく薪の節約になる。`Fire` は最上段の残量だけを持ち、効率値は保持しない。燃料を燃やし始めるたびに場所から引くので、後からかまどを足しても同じ機構に載る。

### 暖房は火がついている間だけ効く

`heatSourceWarmthAt` を、`Fire` を持つエンティティの `HeatSource` だけ集約するよう変える。火が消えたタイルは `HeatSource` を持っても `Fire` を持たないので、暖房として数えない。

```go
// 変更前: HeatSource と GridElement を持つものを集約する
// 変更後: さらに Fire を持つ、すなわち燃えているものだけを集約する
```

体温への効き方、距離線形減衰、平熱未満だけ効く安全ゲートは変えない。半径と減衰の実測が既に決定論なので、条件を一つ足すだけで載る。

### 火を熾す

火種の道具を所持し、隣接タイルに任意の燃焼物があるとき、コンテキストメニューへ着火を出す。燃焼物とは `Fuel` を持つものを指し、焚き火という専用の対象は無い。方向で対象の隣接タイルを選ぶ。足元は自分が燃えるので対象にしない。火は隣接タイルに立つ。

火がつくと、そのタイルにある燃焼物はすべて残ターン数へ畳み込まれて消費される。そのタイルへ `Fire` を持つ火エンティティが立ち、燃え始める。

今のコンテキストメニューは足元タイルしか見ないため、隣接タイルを対象にする一手を足す。火種は再利用できる道具にし、着火は確実に成功する最小形から始める。成功率や火種の消費は将来の調整余地として残す。生成する `HeatSource` の半径と強さは全ての火で共通の固定値にする。

既存の `bonfire` prop は、あらかじめ置かれた火の一例として残す。集落に最初からある焚き火にでき、プレイヤーが熾す火と同じ仕組みで燃える。

### 火は残ターン数だけを持つ

火は燃料を貯め込まず、あと何ターン燃えるかの `Fire.Remaining` だけを持つ。燃料をくべるとは、その燃料の熱量を効率で割り引いた燃焼時間を残ターン数へ足し、燃料アイテムを消費することをいう。着火も給油も同じ `AddFuel` の一様な過程で、`Remaining += HeatContent * 効率 / 100` になる。

補充は給油メニューで行う。火に隣接して開き、持ち物の燃料を選ぶと即座に残ターン数へ加わる。くべた燃料は個々の薪として残らないので取り戻せない。投げる操作は要らない。

消火のアクションは持たない。燃料をくべなければ残ターン数が減って自然に燃え尽きる。能動的に消す手段が要るなら将来足せる。燃えている火は `Fire` を serde で保存し、save と load をまたいでも火が消えないようにする。火は残ターン数だけを持つので、燃料アイテムの並びを別途保存する必要はない。

```go
// FireSystem は火の残ターン数を毎ターン一定量減らし、0 以下になったら Fire を外して鎮火する。
// 火は燃料を貯めず残量だけを持つ。効率は燃料をくべるときに燃えている場所から引く。
// 光には関与しない。暖房が切れるのは Fire が外れた結果として heatSourceWarmthAt が数えなくなるため。
type FireSystem struct{}

const fireBurnPerTurn = 1 // 1ターンで燃える量。燃料アイテムの HeatContent はこの単位で釣り合わせる
```

`InitializeSystems` へ登録する。呼び出しリストへ足すだけでは毎フレーム黙ってスキップされるため、登録を必ず確認する。`fireBurnPerTurn` を1にすると、`HeatContent` が N の燃料は100%効率で N ターン燃える。薪1本の `HeatContent` は数十ターンを目安に raw で決め、遊びの手触りを見て調整する。

### 情報は給油メニューと観察メニューで見せる

給油メニューのタイトルに状態の一行を出す。燃焼中か、予想燃焼時間の残りターン数を見せる。残りは `Fire.Remaining` をそのまま出す。各行にはくべると増える燃焼ターン数を添え、どれだけ火が延びるかを見て選べるようにする。素早い確認は examine の面でも見られる。

### 体温の最大を適温にする

寒さ専用にするため高体温の方向を撤去する。オフセットの上限を適温にし、暑い環境ペナルティと高体温の発症を消す。

- `bodyTempMax` を `5.0` から `0.0` にする。体温は平熱を上限とし、これ以上は上がらない。
- `calcBodyTempRate` の正のレートを撤去する。適温より暑い環境は害でなく、レート0の中立にする。
- `updateTemperatureConditions` から高体温の分岐を外す。
- `ConditionHyperthermia` と、それに紐づく `CharModifiers.HeatProgress` を撤去する。未リリースのため後方互換は考えない。
- 熱源が `offset < 0` のときだけ効くゲートは、上限が適温になったことで温めても適温で頭打ちを自然に満たす。ゲート自体は変えない。

### 将来の拡張

同じ機構の上に、今回は実装しない拡張を載せられるようにしておく。

- **かまど**: 火を宿す据え付けの構造物。`Hearth{Efficiency}` を持ち、着火時の効率へ `groundBurnEfficiency` の代わりに使う。地面直より効率が良く、薪が長持ちする。グレードの違いは効率の違いで、raw の別 prop として定義し enum を持たない。かまどは再利用でき、燃え尽きたら未着火に戻る。
- **建設機構**: 素材アイテムを消費してタイルへ prop を据える汎用の仕組み。かまどはその最初の利用者。分解して産出する `InteractionDisassemble` のちょうど逆になる。
- **投げる**: 燃えている火へ遠くから燃焼物を届ける手段。補充は隣接して給油メニューで足りるので、投げるは離れた火へ燃料を放り込みたいときだけの役目になる。

いずれも `Fuel`・`Fire`・効率の上に足し算で載り、本設計の核を変えない。

## 採用しなかった方法

- **延焼を入れる**: タイルからタイルへ火が広がる伝播はゲームの主眼でなく、暴走する野火は生存の焦点をぼかす。直交性はデータで満たせるので伝播は入れない。将来必要になれば `Fuel` と `Fire` の上に独立して足せる。
- **火を必ずかまどに宿す**: 据え付けの構造物だけで火を許すと、火の前に必ず建設の一手が要り、今いる場所で暖を取れない。地面直の火を効率の悪い形として許し、かまどは効率を上げる将来の選択肢にする。
- **携帯できる火を持つ**: 松明のように火を持ち歩く形は、持ち物が燃える状態の扱いを増やしてややこしい。火は地面のタイルだけが宿すと割り切る。
- **火に光を持たせる**: 照明はライトと電力の別系統が担うため、火を光へ結ばない。暖房だけに絞ると設計が小さく収まる。
- **燃料を収納として個々に抱える**: 火が燃料アイテムを収納として持ち、上から順に燃やす形も検討した。個々の薪が見え収納メニューを流用できる利点はあるが、火から燃料を取り戻せてしまう不自然さ、容量制限、収納の並び保存の重さが要る。火は残ターン数だけを持つプールにし、くべた瞬間に燃焼時間へ畳み込む。個々の薪は見えなくなるが、取り戻せない火の手触りに合い、実装も軽い。総燃焼時間はどちらも同じになる。
- **投げて燃料を補充する**: 火のタイルへ燃焼物を投げてくべる形は操作が面倒になる。補充は隣接して給油メニューで足りる。投げるは離れた火へ放り込みたいときの将来の手段に留める。
- **熱を効率でスケールさせる**: 良い火ほど強く広く温める形は、profile が可変になり調整と読みが増える。熱は固定にし、効率は燃焼時間だけを変える単純な緊張にする。良い火の見返りは薪の節約にする。
- **消火の手段を持つ**: 水をかけて消すような能動的な消火は今回入れない。燃料をくべなければ残ターン数が尽きて自然に燃え尽きるので、消火は無くても火は必ず終わる。能動消火が要る場面が出たら将来足せる。
- **高体温を残す**: 寒さ専用の主題に暑さの罰は不要で、体温ゲージに上と下の二方向を持たせると読みも実装も重くなる。上限を適温にして片方向へ倒す。

## コメント

設計の骨は「燃える性質 `Fuel`」と「今燃えている状態 `Fire`」を分けたことにある。`Fuel` を多くのものへ広げて火を直交的にし、`Fire` を地面のタイルの状態にすると携帯火の複雑さを避けられる。暖房は既に完成しているので、`heatSourceWarmthAt` に Fire の条件を一つ足すだけで火がついている間だけ暖かいが成り立つ。

効率を「地面直は定数、かまどはかまどの値」と着火時に場所から引く形にしたので、かまどが未実装でも成立し、後から効率を上げる据え付けだけを足せる。熱は固定で効率は持ちに効くという分け方が、良い火の見返りを暖かさでなく薪の節約に定め、寒冷生存の緊張を素直にする。

寒さ専用への割り切りが設計を軽くした。体温の上限を適温にすると、熱源の安全ゲートと相まって温めても頭打ちが自動で満たされ、高体温の分岐一式を丸ごと落とせる。

かまど、建設、投げるは、いずれも本設計の核の上に足し算で載る将来の拡張として置いた。核を小さく保ち、遊びの手触りを見ながら継ぎ足せる形にする。

### 実装メモ

- 火の状態は設計名 `Fire` でなく `Burning`。`Fire` は近接攻撃の予約語のため。
- 火は残ターン数だけを持つプールモデル。当初は燃料を収納として個々に抱える案だったが、火から取り戻せる不自然さ・容量制限・並び保存の重さを避け、くべた瞬間に残ターン数へ畳む形にした。retrieve は無い。
- 燃料を残ターン数へ畳む副作用は `lifecycle.AddFuel`、効率と見積もりの読み取りは `query.BurnEfficiency`・`EstimateBurnTurns`・`FuelBurnTurns`。`systems`→`activity`→`lifecycle`→`query` の一方向依存で着火と給油が同じ `AddFuel` を共有する。
- bonfire は `Burning.Remaining` の初期チャージ 999 で置かれた火にする。プレイヤーの campfire は地面の燃料から着火し残ターン数を得る。どちらも隣接して給油で継ぎ足せる。
