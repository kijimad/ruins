# 焚き火と直交的な火: 寒さを生き延びる熱源

## 背景

本作は寒さを主題にするゲームで、プレイヤーは体温を保って生き延びる。体温は `HealthStatus.BodyTempOffset` が平熱からのずれを持ち、`TemperatureSystem` が環境有効温度から毎ターン更新する。環境より体が冷えれば低体温が進み、放置すると発症する。

暖房の土台は既にある。`HeatSource{Radius, Warmth}` を持つエンティティは `heatSourceWarmthAt` が半径内をチェビシェフ距離で線形減衰して集約し、`bodyTempRate` を通して体温を平熱へ押し戻す。熱源は平熱未満のときだけ効く。焚き火に相当する `bonfire` prop も既にあり `HeatSource` を持つ。

しかし今の焚き火は静的で、置いた瞬間から永久に暖かい。着火も消火もなく、燃料も減らない。これでは「火を絶やさぬよう燃料をくべ続ける」という寒冷生存の核が生まれない。

方針は3つ。第一に、火を焚き火専用のハードコードにせず、燃えるという性質を多くのものへ広げた直交的な要素にする。燃焼を一様な過程にすれば、現実らしさと拡張性が同時に得られる。専用の焚き火オブジェクトも専用UIも持たず、火はどこでも熾せる汎用のエンティティにする。第二に、タイルからタイルへ火が広がる延焼はゲームの主眼でないため入れない。直交性はデータに宿し、伝播には宿さない。第三に、本作は寒さ専用なので高体温の方向を撤去し、体温ゲージの最大を適温にする。

## 要件

- 燃えている焚き火は半径内のプレイヤーを強く温める。体温は適温を超えないので、近づきすぎても高体温にならず安全である。
- 未着火の焚き火に火種で着火できる。
- 燃えるものをくべて燃料を補充できる。もの毎に熱量が違い、熱量ぶん燃焼が延びる。燃料が尽きると鎮火する。
- 温める範囲は熱源の半径で決まり、距離で減衰する。既存機構を踏襲する。
- 火はどこでも熾せる。専用の焚き火オブジェクトも専用UIも持たない。着火が燃料から火エンティティを生む。
- 熱の強さと広さは火ごとに固定にする。燃料を多く入れるほど長く燃えるだけで、温めの profile は変えない。
- 火は焚き火専用でなく直交的な性質にする。燃焼は「燃料の熱量を火へ移し、火が熱を出す」一様な過程で表す。
- 携帯できる火は持たない。火は地面に置かれた prop だけが宿す。燃料アイテムは持ち運べ、焚き火にくべると消費される。
- 光は火の責務にしない。照明はライトと電力の別系統が担う。本設計は暖房だけを扱う。
- 体温の最大を適温にする。高体温と暑い環境ペナルティを撤去する。

## 調査結果

新設と流用の境目を実測で確認した。

- 体温は `HealthStatus.BodyTempOffset`、更新は `internal/systems/temperature.go` の `TemperatureSystem`。低体温 `ConditionHypothermia` と高体温 `ConditionHyperthermia` の両方が実装済み。オフセットは `bodyTempMin=-5.0` から `bodyTempMax=5.0` にクランプする。
- 熱源は `internal/components/heat_source.go` の `HeatSource{Radius, Warmth}`。集約は `temperature.go` の `heatSourceWarmthAt` で距離線形減衰。熱源は `offset < 0` のときだけ効く安全設計。
- 火・燃焼・延焼・燃料の機構は component も system も存在しない。焚き火の暖房は延焼機構と無関係にゼロから設計できる。
- 位置は `GridElement`、prop 生成は `SpawnProp`、相互作用は `Interactable` と `InteractionKind` と `ExecuteInteraction` の三点。着火や燃料補充の相互作用種別は未定義。`ExecuteInteraction` は default を置かない網羅分岐なので、種別追加時は case を足す。
- アイテム消費は `Consumable`。対象と持ち物を消費して状態を変える雛形は `InteractionDisassemble` が最も近い。
- 距離クエリは `internal/geometry` の `ChebyshevDistance` などが揃う。

## 設計

### データの形

燃えるという性質を持つものと、今まさに燃えているものを分ける。前者は多くのアイテムや prop が持ち、後者は火がついた焚き火だけが持つ。

```go
// Fuel は燃やせるものが持つ性質。多くのアイテムや prop に付き、燃やしたときの熱量を表す。
// 木・紙・油で値が違う。火を焚き火専用にしないための核で、燃焼はこの熱量を火へ移す一様な過程になる。
type Fuel struct {
	HeatContent float64 // 燃やしたとき Fire の残量へ足す熱量
}

// Fire は今まさに燃えているエンティティに付く。地面に置かれた prop だけが持ち、持ち物には付かない。
// 毎ターン残量が減り、尽きると外れる。Fire がある間だけ同じエンティティの HeatSource が暖房として効く。
type Fire struct {
	Remaining float64 // 残りの燃焼量。FireSystem が毎ターン減らす。0 以下で鎮火し Fire を外す
}
```

`HeatSource{Radius, Warmth}` は熱の profile として今のまま残す。`Fire` が暖房の on と off を、`HeatSource` が半径と強さを持つ。この2部品に分けると、大きな焚き火も将来の小さな火も同じ組み合わせで表せ、焚き火のための特別なコードパスが要らない。

### 暖房は火がついている間だけ効く

`heatSourceWarmthAt` を、`Fire` を持つエンティティの `HeatSource` だけ集約するよう変える。消えた焚き火は `HeatSource` を持つが `Fire` を持たないので、暖房として数えない。

```go
// 変更前: HeatSource と GridElement を持つものを集約する
// 変更後: さらに Fire を持つ、すなわち燃えているものだけを集約する
```

体温への効き方、距離線形減衰、平熱未満だけ効く安全ゲートは変えない。半径と減衰の実測が既に決定論なので、ここは条件を一つ足すだけで載る。

### 熱は固定、燃料は燃焼時間だけを延ばす

温めの強さと広さは `HeatSource{Radius, Warmth}` が決め、火ごとに固定にする。燃料を多くくべても延びるのは `Fire.Remaining` すなわち燃える長さだけで、profile は変わらない。大きく育てて広く温めるのでなく、火を絶やさぬよう燃料を継ぐ、という単純な緊張にする。`HeatSource` を profile、`Fire` を on と残り時間に分けた形が、この「熱は一定・燃料は時間」をそのまま表す。

### 燃料を毎ターン燃やす

`Fire` の残量を毎ターン減らし、尽きたら鎮火する専用システムを足す。

```go
// FireSystem は燃えているエンティティの残量を毎ターン一定量減らし、尽きたら Fire を外す。
// 光には関与しない。暖房が切れるのは Fire が外れた結果として heatSourceWarmthAt が数えなくなるため。
type FireSystem struct{}

const fireBurnPerTurn = 1.0 // 1ターンで燃える量。燃料アイテムの HeatContent はこの単位で釣り合わせる
```

`InitializeSystems` へ登録する。呼び出しリストへ足すだけでは毎フレーム黙ってスキップされるため、登録を必ず確認する。

### 火を熾す

火はどこでも熾せる。焚き火という専用オブジェクトを置くのでなく、着火が燃料から火エンティティを生む。プレイヤーは火種の道具と燃料を持ち、足元に火を作る。

熾す過程は、火種を持つとき燃料アイテムを1つ消費し、足元のタイルへ `GridElement`・固定の `HeatSource`・`Fire{Remaining: その燃料の HeatContent}` を持つエンティティを生成する。これが焚き火であり、以後は燃料をくべて延命する。生成する `HeatSource` の半径と強さは全ての火で共通の固定値にする。

火種は再利用できる道具にし、着火は確実に成功する最小形から始める。成功率や火種の消費は将来の調整余地として残す。

既存の `bonfire` prop は、あらかじめ置かれた火の一例として残す。集落に最初からある焚き火にでき、プレイヤーが自分で熾す火と同じ仕組みで燃える。

### 燃料を補充する

燃えるものをくべて燃焼を延ばす。持ち物から `Fuel` を持つアイテムを選び、消費して残量へ熱量を足す。

```go
// InteractionKind へ追加
InteractionRefuel // 燃えている焚き火へ、持ち物の Fuel アイテムをくべる。アイテムを消費し Remaining += HeatContent
```

対象と持ち物を消費して状態を変える流れは `InteractionDisassemble` が雛形になる。くべる相手のアイテム選択は既存のアイテム選択メニューに載せる。もの毎の熱量差は各アイテムの `Fuel.HeatContent` で表し、木は小さく、油は大きい、といった調整を raw で行う。

### 専用オブジェクトも専用UIも持たない

焚き火は専用の型を持たない。火は着火で生まれる汎用のエンティティで、`HeatSource` と `Fire` の組み合わせにすぎない。管理の専用画面も作らない。くべる・消火は既存の相互作用メニューとアクションに載せ、燃料の残量は火に近づいたときの表示や examine で見せる。専用UIを作るとその瞬間に火が特別な設備へ戻るため、汎用の面だけで扱う。

### 体温の最大を適温にする

寒さ専用にするため高体温の方向を撤去する。オフセットの上限を適温にし、暑い環境ペナルティと高体温の発症を消す。

- `bodyTempMax` を `5.0` から `0.0` にする。体温は平熱を上限とし、これ以上は上がらない。
- `calcBodyTempRate` の正のレートを撤去する。適温より暑い環境は害でなく、レート0の中立にする。
- `updateTemperatureConditions` から高体温の分岐を外す。
- `ConditionHyperthermia` と、それに紐づく `CharModifiers.HeatProgress` を撤去する。未リリースのため後方互換は考えない。
- 熱源が `offset < 0` のときだけ効くゲートは、上限が適温になったことで「温めても適温で頭打ち」を自然に満たす。ゲート自体は変えない。

## 採用しなかった方法

- **延焼を入れる**: タイルからタイルへ火が広がる伝播はゲームの主眼でなく、暴走する野火は生存の焦点をぼかす。直交性はデータで満たせるので伝播は入れない。将来必要になれば Fuel と Fire の上に独立して足せる。
- **携帯できる火を持つ**: 松明のように火を持ち歩く形は、持ち物が燃える状態の扱いを増やしてややこしい。火は地面の prop だけが宿すと割り切る。
- **火に光を持たせる**: 照明はライトと電力の別系統が担うため、火を光へ結ばない。暖房だけに絞ると設計が小さく収まる。
- **火を1種類に統一し不燃の炉タイルや囲いフラグで広がりを止める**: 延焼を入れないので囲いで止める必要がそもそも無い。`Fire` の有無だけで暖房の on と off を表すほうが単純。
- **専用の焚き火オブジェクトと専用UIを持つ**: 設置して管理画面で燃料を継ぐ形は分かりやすいが、火を特別な設備に戻し、直交性と逆行する。着火で生まれる汎用の火に倒し、UIは既存の面で足りる。どこでも熾せるほうが、今いる場所で暖を取れて寒冷生存にも合う。
- **熱を燃料量でスケールさせる**: 火が育つほど強く広く温める形は現実らしいが、profile が可変になり調整と読みが増える。熱は固定にし、燃料は燃焼時間だけを延ばす単純な緊張にする。
- **高体温を残す**: 寒さ専用の主題に暑さの罰は不要で、体温ゲージに上と下の二方向を持たせると読みも実装も重くなる。上限を適温にして片方向へ倒す。
- **`HeatSource` の値を上げて静的なまま強く温める**: 着火も燃料もない静的な暖房では、火を絶やさぬ緊張という寒冷生存の核が生まれない。

## コメント

設計の骨は「燃える性質」と「今燃えている状態」を分けたことにある。`Fuel` を多くのものへ広げると火が直交的になり、`Fire` を prop だけの状態にすると携帯火の複雑さを避けられる。暖房は既に完成しているので、`heatSourceWarmthAt` に Fire の条件を一つ足すだけで「火がついている間だけ暖かい」が成り立つ。既存資産を壊さず、着火・燃料・鎮火という新しい緊張だけを足せる。

寒さ専用への割り切りが設計を軽くした。体温の上限を適温にすると、熱源の安全ゲートと相まって「温めても頭打ち」が自動で満たされ、高体温の分岐一式を丸ごと落とせる。

火種の消費や着火成功率、燃料アイテム毎の熱量の釣り合いは、遊びの手触りを見ながら raw と定数で調整する余地として残す。
