# 終端: run を死で締め、統計を記録して見せる

## 背景

run の締めが、全遺跡ボス撃破の `EventAllCleared` と汎用のゲームオーバーだけで、サバイバルの decision に対応する終端が無い。死んでも戦果が残らず、遊びが締まらない。この doc は run に**死という終端と結果画面**を与える。

生還はいまのところ設けない。冷気に呑まれる世界からは逃げ切れず、run は必ず死で終わる。競うのは、死ぬまでにどこまで進み何日もったか。生還の勝利条件は将来の検討に残し、まず死で締まる一周を成立させる。逃げ切れない設定は一方向逃避のテーマとも噛み合う。

## 要件

**Hard**

- run は必ず死で終わり、結果画面が出る。
- 死因を問わず生存日数と経過ターンが記録される。倒れるまで生き延びた長さが誇りとして残る。
- 死因は身体モデル `260821232324` が確定する文字列で区別して表示する。凍死・失血死・病死・餓死など。
- 旧 `EventAllCleared`・全遺跡クリア勝利を退役させる。
- 決着の判定に新しい乱数を持ち込まない。

**Soft**

- 結果画面が次の run への動機になる。経過ターン・日数・死因・倒した敵の数・売上などの統計の一望。
- 統計を道中でも見られる。倒した数や漁った数が、いまの run の手応えになる。
- 倒れるまでの戦果が「次はもっと」を誘う。

**Anti**

- 決着の種類を増やさない。死因の違いは文字列のデータで表す。
- 途中セーブからのやり直しで決着を無かったことにさせない。決着は run に1度きり。
- 生還を今むやみに足さない。まず死で締まる一周を検証する。

## 設計

### データ: run 記録は RunStats 1つ

run の記録は `RunStats` シングルトン1つに集約する。`RunStats` は run 中ずっと存在し serde 保存されるので、決着のスナップショットを別コンポーネントに持つ必要がない。生存日数と経過ターンは `GameTime` から引ける。決着に固有なのは死因だけなので、`Cause` を `RunStats` に足す。決着の種別 enum は今は要らず、将来 生還 を足すときに導入する。

到達度は経過ターンで示す。前進距離はチャンク単位で、プレイヤーはチャンクを意識しないので指標に向かない。ターンは誰にでも読める単位で、遠くへ行くほど増えるので到達度の代理になる。距離統計は持たない。

```go
// RunStats は run を通じて積み上げる統計と死因を保持するシングルトン。
// run 中ずっと存在し serde 保存する。決着時に死因を記録する
type RunStats struct {
	EnemiesKilled  int             // 倒した敵の数
	ItemsScavenged int             // 漁ったアイテム数
	SalesTotal     consts.Currency // 売上累計
	Cause          string          // 死因。決着時に記録する。区別する値の集合が要るまで素の文字列
}
```

各カウンタは対応する出来事の1点で加算する。撃破は `dead_cleanup` の死亡処理、漁りは取得経路、売上は通販の集金。加算点を1箇所に閉じ、二重計上を避ける。生存日数と経過ターンは `GameTime` から読めるので溜めない。細目、たとえば敵種ごとの撃破数は、実プレイで見たくなったものを足す。

### 死の接続

死は身体モデル `260821232324` の経路で確定する。HP が0になると、その処理が `RecordDeath` で `RunStats.Cause` に死因を記録し、終端 State へ遷移させる。決着のスナップショットは `RunStats` と `GameTime` が既に保持しているので、決着時に確定するのは死因だけで済む。失血・凍死・餓死・病死は死因が違うだけで、終端は1つの結果画面に集約する。既存の汎用ゲームオーバーはこの経路へ置き換える。

### 結果画面

終端 State は `RunStats` と `GameTime` を読み、死の結果を出す。表示は character・inventory と同じ
メニュー画面枠で、統計を Label と Value の2列テーブルに並べる。区切り文字で連ねた本文にはしない。

- 題字: 死因つきの最期。当面は「You died.」。死因は身体モデル接続後に添える
- 本文: 生存日数・経過ターン・倒した敵の数・漁ったアイテム数・売上累計のテーブル
- 操作: 任意キーでタイトルへ戻り、次の run を始める

道中でも同じ統計を、常時メニューのステータス画面から同じテーブルで覗ける。結果画面と道中画面は
1つの読み取り専用 State を、見出しと閉じ方だけ変えて共用する。行の組み立ては1箇所に閉じる。

### 退役

`EventAllCleared`・全遺跡クリア勝利・ボス撃破のクリアフラグ処理を撤去する。`dead_cleanup.go` のボス撃破クリアフラグと、それを受ける遷移が対象。逓増 doc `260822014350` の `GameClearDepth` 退役と対になる。

## 採用しなかった方法

- **生還の勝利条件を今入れる**。日数 N 生存や敵 K 体撃破で生還にする。却下。いまは死で締まる一周が成立するかを先に検証する。生還は面白さの核が出てから足す。冷気から逃げ切れない設定とも噛み合う。
- **死因ごとに決着種別の定数を増やす**。却下。死因は素の文字列で持つ。定数の膨張と doc 横断の管理を避ける。区別する値の集合が要るとき、身体モデルが死因を定義するときに、名前付き型へ格上げする。
- **決着専用の `RunOutcome` コンポーネントを別に持つ**。却下。`RunStats` は run 中ずっと存在し serde 保存されるので、決着スナップショットを別に持つのは重複になる。生存日数と経過ターンは `GameTime` から引け、決着固有の値は死因だけ。死因を `RunStats.Cause` に足せば `RunStats` 1つが run の記録になる。決着専用コンポーネントは決着の瞬間だけ現れセーブ時に居ないので保存に意味が薄く、二重管理を招く。
- **クリア後の周回要素を今作る**。却下。まず一周が成立してから。結果画面の「次の run」で足りる。

## コメント

生還はいまのところ設けない。冷気からは逃げ切れず、死ぬまでどれだけ生き延び戦えたかを競う。生還を将来足すなら決着種別の enum を導入し `RunStats` へ種別を加える。

`RunStats` は新コンポーネントなので `add-component` の手順に従う。serde 除外はしない。積み上げる統計でセーブをまたいで保たれる必要があるからだ。死因 `Cause` も同じ `RunStats` に載るので、run の記録は1コンポーネントに閉じる。結果画面に出す統計の項目は実プレイで誇りたくなるものを見てから増やす。最小は日数・経過ターン・死因・撃破数。
