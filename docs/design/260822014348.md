# 終端: run を死で締め、統計を記録して見せる

## 背景

run の締めが、全遺跡ボス撃破の `EventAllCleared` と汎用のゲームオーバーだけで、サバイバルの decision に対応する終端が無い。死んでも到達距離が残らず、遊びが締まらない。この doc は run に**死という終端と結果画面**を与える。

生還はいまのところ設けない。冷気に呑まれる世界からは逃げ切れず、run は必ず死で終わる。競うのは、死ぬまでにどこまで進み何日もったか。生還の勝利条件は将来の検討に残し、まず死で締まる一周を成立させる。逃げ切れない設定は一方向逃避のテーマとも噛み合う。

## 要件

**Hard**

- run は必ず死で終わり、結果画面が出る。
- 死因を問わず到達距離と生存日数が記録される。倒れるまでに進んだ距離が誇りとして残る。
- 死因は身体モデル `260821232324` の `DeathCause` で区別して表示する。凍死・失血死・病死・餓死など。
- 旧 `EventAllCleared`・全遺跡クリア勝利を退役させる。
- 決着の判定に新しい乱数を持ち込まない。

**Soft**

- 結果画面が次の run への動機になる。到達距離・日数・死因・倒した敵の数・売上などの統計の一望。
- 統計を道中でも見られる。倒した数や漁った数が、いまの run の手応えになる。
- 倒れるまでの距離と戦果が「次はもっと」を誘う。

**Anti**

- 決着の種類を増やさない。死因の違いは `DeathCause` のデータで表す。
- 途中セーブからのやり直しで決着を無かったことにさせない。決着は run に1度きり。
- 生還を今むやみに足さない。まず死で締まる一周を検証する。

## 設計

### データ: 決着は死のみ

生還が無いので決着は死の1種。`RunOutcome` は死因とスコアを持つ。決着の種別 enum は今は要らず、将来 生還 を足すときに導入する。

```go
// DeathCause は死因。結果画面の表示に使う。身体モデル 260821232324 が確定して渡す
type DeathCause string

// RunOutcome は run の決着。いまは死のみ。決着時に生成し終端 State が消費する。
// 決着時のみ存在し、セーブ時には居ないので保存の心配は無い
type RunOutcome struct {
	Cause       DeathCause // 死因
	ReachedDist int        // 到達した前進距離。スコアの主軸
	Days        int        // 生存日数
	Turns       int        // 経過ターン数
}
```

`RunOutcome` は決着の瞬間に生成し、結果画面が消費する。セーブが起きるのは生存中で、そのとき `RunOutcome` は存在しない。結果画面はセーブ操作を持たないので、`RunOutcome` が居るあいだにセーブは起きない。加えて `RunOutcome` は素の struct で serde 互換であり、毎フレーム再生成される一時状態でもない。serde 除外の方針はこの2種に限るので、`RunOutcome` は除外せず既定の丸ごと保存に任せる。実際にはセーブ時に居ないので何も保存されず、決着前の世界に戻っても決着済みの状態が復元されることは構造的に起きない。生還を将来足すときは決着種別の enum を導入し、この型へ種別を1つ加えるだけで済む。

### 死の接続

死は身体モデル `260821232324` の経路で確定する。HP が0になると、その処理が `RunOutcome` を `DeathCause` つきで生成し、終端 State へ遷移させる。失血・凍死・餓死・病死は死因が違うだけで、終端は1つの結果画面に集約する。既存の汎用ゲームオーバーはこの経路へ置き換える。

### 統計: run 中に貯めて結果へ出す

倒した敵の数などの統計を run 中に貯め、結果画面と道中で見せる。統計は `RunStats` シングルトンに溜める。run を通じて積み上がるので保存され、ロードした run も履歴を保つ。決着時のみ現れる `RunOutcome` と違い、`RunStats` は run 中ずっと存在するので保存に意味がある。

```go
// RunStats は run 中に貯める統計。セーブ対象。ロードした run も履歴を保つ
type RunStats struct {
	EnemiesKilled  int             // 倒した敵の数
	MaxDist        int             // 到達した最大前進距離。スコアの主軸
	ItemsScavenged int             // 漁ったアイテム数
	RuinsLooted    int             // 漁った遺跡数
	SalesTotal     consts.Currency // 売上累計
	WoundsTaken    int             // 負った傷の数
}
```

各カウンタは対応する出来事の1点で加算する。撃破は `dead_cleanup` の死亡処理、漁りは取得経路、売上は通販の集金、負傷は傷付与。加算点を1箇所に閉じ、二重計上を避ける。生存日数は `GameTime` から読めるので溜めない。細目、たとえば敵種ごとの撃破数は、実プレイで見たくなったものを足す。

### 結果画面

終端 State は `RunOutcome` と `RunStats` を読み、死の結果を出す。

- 題字: 死因つきの最期。例として「凍死 - 前線に呑まれて」
- 本文: 到達距離・生存日数・経過ターン・倒した敵の数・漁った遺跡数・売上累計・負った傷の数
- 操作: タイトルへ戻る。次の run を始める

道中でも同じ `RunStats` をステータス画面から覗ける。

### 退役

`EventAllCleared`・全遺跡クリア勝利・ボス撃破のクリアフラグ処理を撤去する。`dead_cleanup.go` のボス撃破クリアフラグと、それを受ける遷移が対象。逓増 doc `260822014350` の `GameClearDepth` 退役と対になる。

## 採用しなかった方法

- **生還の勝利条件を今入れる**。距離 D 到達や日数 N 生存で生還にする。却下。いまは死で締まる一周が成立するかを先に検証する。生還は面白さの核が出てから足す。冷気から逃げ切れない設定とも噛み合う。
- **死因ごとに決着種別の定数を増やす**。却下。死因はデータ `DeathCause` で持つ。定数の膨張と doc 横断の管理を避ける。
- **`RunOutcome` を skipComponents で serde 除外する**。却下。serde 除外の方針は serde 非互換か毎フレーム再生成の一時状態に限る。`RunOutcome` はどちらでもなく、しかもセーブは生存中にしか起きず保存時には存在しない。除外は方針違反かつ無意味なので、既定の丸ごと保存に任せる。決着時生成・即消費なので、保存しても実害は無い。
- **クリア後の周回要素を今作る**。却下。まず一周が成立してから。結果画面の「次の run」で足りる。

## コメント

生還はいまのところ設けない。冷気からは逃げ切れず、死ぬまでの到達距離を競う。生還を将来足すなら決着種別の enum を導入し `RunOutcome` へ種別を加える。

`RunOutcome`・`RunStats` は新コンポーネントなので `add-component` の手順に従う。どちらも serde 除外はしない。`RunStats` は積み上げる統計でセーブをまたいで保たれる必要がある。`RunOutcome` は決着時のみ存在しセーブ時には居ないので、保存しても実害が無く、serde 除外の方針にも当たらない。結果画面に出す統計の項目は実プレイで誇りたくなるものを見てから増やす。最小は到達距離・日数・死因・撃破数。
