# 終端: 生還と死で run を締め、到達距離を記録する

## 背景

マクロループ設計 `260821223229` の②終端を詳細化する。現状、run の締めは全遺跡ボス撃破の `EventAllCleared` と汎用のゲームオーバーだけで、一方向逃避の decision に対応する終端が無い。逃げ切っても何も起きず、死んでも到達距離が残らない。

前提が1つ変わった。駆動 doc `260822014347` で、前線の追いつきを即敗北にしない方針を確定した。前線での死は低体温から身体モデル `260821232324` の血経路を通る凍死であり、他の死因と同じ経路で訪れる。したがって決着は**生還か死かの2種だけ**になり、呑まれ専用の決着は要らない。

## 要件

**Hard**

- run は必ず終わる。生還か死のどちらかで締まり、結果画面が出る。
- 死因を問わず到達距離と生存日数が記録される。呑まれるまでに進んだ距離が誇りとして残る。
- 死因は身体モデルの `DeathCause` で区別して表示する。凍死・失血死・病死・餓死。
- 旧 `EventAllCleared`・全遺跡クリア勝利を退役させる。
- 決着の判定に新しい乱数を持ち込まない。

**Soft**

- 結果画面が次の run への動機になる。到達距離・日数・死因・売上などの一望。
- 生還と死が対称の余韻を持つ。逃げ切りの安堵と、倒れるまでの距離の誇り。

**Anti**

- 決着の種類を増やさない。死因の違いは `DeathCause` のデータで表す。
- 途中セーブからのやり直しで決着を無かったことにさせない。決着は run に1度きり。

## 設計

### データ: 決着は2種

前線即敗北が消えたので `OutcomeKind` は2種に落ちる。親 doc の3種からさらに単純になる。

```go
// OutcomeKind は run の決着の種類。2種に固定し、死因の詳細は Cause で記録する
type OutcomeKind int

const (
	OutcomeEscaped OutcomeKind = iota // 終端条件を満たして生還。主軸が距離でも日数でも定義は変わらない
	OutcomeDied                       // 力尽きた。凍死・失血死・病死・餓死などの死因は Cause に持つ
)

// DeathCause は OutcomeDied の死因。結果画面の表示に使う。
// 身体モデル 260821232324 の血経路が死因を確定して渡す
type DeathCause string

// RunOutcome は run の決着。決着時に生成し、終端 State が消費する。
// run 中は存在しないので保存対象にしない
type RunOutcome struct {
	Kind        OutcomeKind
	Cause       DeathCause // OutcomeDied のときのみ
	ReachedDist int        // 到達した前進距離。スコアの主軸
	Days        int        // 生存日数
}
```

`RunOutcome` は決着の瞬間に生成する。run 中に存在しないため serde の保存対象にせず、`skipComponents` へ入れる。途中セーブから戻っても決着前の世界に戻るだけで、決着の取り消しは構造的に起きない。

### 生還条件

主軸は要決定のまま2案を保持する。`OutcomeEscaped` は「終端条件を満たして生還」と抽象化してあるので、どちらでも型は変わらない。

- **距離案**: 前進距離が閾値 D に達したら生還。目的地に着く物語。第一候補。
- **日数案**: 日数 N を生き延びたら生還。救援が来る物語。

判定は毎ターンの純関数で、プレイヤー絶対 X または `GameTime` を読むだけ。専用 system を立てず、既存のターン処理へ1判定を足す。

### 死の接続

死は身体モデル `260821232324` の2系統で確定する。血が0になる失血死と、低体温・飢餓・致死性の病が進行しきる臓器不全死。どちらの確定処理も `RunOutcome` を `OutcomeDied` と `DeathCause` で生成し、終端 State へ遷移させる。失血死・凍死・餓死・病死は死因が違うだけで、終端は1つの結果画面に集約する。既存の汎用ゲームオーバーはこの経路へ置き換える。

### 結果画面

終端 State は `RunOutcome` を読み、生還と死で同じ画面骨格に違う題字を出す。

- 題字: 生還 または 死因つきの最期。例として「凍死 - 前線に呑まれて」
- 本文: 到達距離・生存日数・売上累計・漁った遺跡数
- 操作: タイトルへ戻る。次の run を始める

### 退役

`EventAllCleared`・全遺跡クリア勝利・ボス撃破のクリアフラグ処理を撤去する。`dead_cleanup.go` のボス撃破クリアフラグと、それを受ける遷移が対象。逓増 doc `260822014350` の `GameClearDepth` 退役と対になる。

## 採用しなかった方法

- **呑まれ専用の決着 `OutcomeConsumed` を残す**。却下。駆動 doc で前線即敗北を廃したため、前線での死は凍死の `DeathCause` で表せる。決着の種類は増やさない。
- **死因ごとに `OutcomeKind` を増やす**。却下。親 doc から継承。定数の膨張と doc 横断の管理を避け、死因はデータで持つ。
- **`RunOutcome` を保存対象にする**。却下。run 中に存在しない一瞬のデータで、保存すると途中セーブとの整合問題を生む。決着時生成・即消費に閉じる。
- **クリア後の周回要素を今作る**。却下。まず一周が成立してから。結果画面の「次の run」で足りる。

## コメント

生還条件の主軸は距離案を第一候補として実プレイで決める。結果画面に出す統計の項目は、実プレイで「誇りたくなるもの」を見てから足す。最小は距離・日数・死因の3つ。
