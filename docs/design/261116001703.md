# コード監査: セーブロードがフォグを毎回消す 2026-11-16

## 背景

自律コード監査エージェントが internal 配下を横断的に調査した。golangci-lint が機械的に捕まえる forcetypeassert・errcheck・nilerr・exhaustive 等のパターンは対象外とし、意味を理解しないと分からない誤りだけを狙った。

Ark ECS の strict semantics、worldgen の座標・境界計算、戦闘・成長の数式、serde・保存復元の整合、states/input/aiinput の状態遷移の5観点で並行調査し、各候補を敵対的に自己検証した。確度が残ったのは次の1件のみ。

## 問題: ロードすると現在ステージの探索済みフォグが毎回消える

- 箇所: `internal/save/serde.go:111-123` の `reestablishSingleton`
- 症状: セーブをロードすると、ロード直後に全 `StageField` の `ExploredTiles` が無条件で空 map に入れ替わる。俯瞰図・ミニマップのフォグが「同じフロアに居続けているのに、見た範囲を忘れた」状態に戻る。
- 根拠・失敗シナリオ:
  - `gc.StageField.ExploredTiles` は `internal/components/stage_field.go:20` で `json:"-"`。serde 対象外のため、ロード直後は常に zero 値の `nil` になる。
  - `reestablishSingleton` は `if field.ExploredTiles == nil { field.ExploredTiles = make(...) }` という条件を書いているが、json:"-" のフィールドはロード直後必ず `nil` なので、この条件は実質無条件に働く。保存前の内容を復元する経路が無い。
  - 一方 `internal/states/dungeon.go:145-157` は、フロアを新規生成する経路でだけ `stage.ResetExploredTiles` を呼び、`if !st.Resume { ... }` のブロックで囲んでいる。つまりコードベース自身が「ステージへ新規入場したときはフォグをリセットする」「セーブロードの復帰 `Resume` ではリセットしない」という意図を明示している。
  - `internal/worldstream/band.go:98-99,112` も `ExploredTiles` を「永続の」データと呼び、帯シフト時はキー付け替えで内容を保持する。別の場所でも「このフィールドは保つべきもの」という前提で書かれている。
  - しかし `save/serde.go` のコメントは「入場時リセット方針なので空でよい」と書いており、`dungeon.go` が区別している「新規入場」と「ロード復帰」を混同している。結果として、ダンジョン内で `internal/states/dungeon_input.go:416` の入眠オートセーブや他の自動保存を経てロードし直すと、同じフロアの同じ場所に戻るにもかかわらずフォグだけ消える。
  - `internal/save/serde_test.go:114-117` は `ExploredTiles` が非nilであることしか確認しておらず、「保存前の内容が保たれる」契約はテストで守られていない。
- 修正方針案: `ExploredTiles` を save 対象に含めて往復させる。`GridElement` はキーが struct なので、他の struct キー map と同様に `json:"-"` + ロード時再構築ではなく、スライス等へ変換して保存し復元時に map へ戻す。あるいは「ロード復帰時はフォグをリセットする」という仕様に倒すなら、`save/serde.go` のコメントと `dungeon.go` の `!st.Resume` ガードの意図を揃えて明文化する。どちらを採るかは設計判断。
