# prop と item を層と正のマーカーで分ける

## 背景

フィールドに置かれる物のうち、拾える物すなわちアイテムと、置き物 prop の区別が分かりづらい。原因は同定が**否定**で組まれていることにある。

- `IsPickable` は「フィールド上にいて `Fixed` でない」を拾える条件にする。`internal/world/query/query.go:56`。アイテムを指す正のマーカーは無い。
- FieldLook のカテゴリ表も `Player / Enemy / NPC / Fixed / Tile` で、アイテムのカテゴリが無い。`internal/components/invariant.go:143`。
- prop は `NewPropSpec` が無条件に `Fixed` を付けて作る。`internal/raw/raw.go:695`。分解は `Fixed && GridElement` かどうかで産出先を振り分ける。`internal/activity/disassemble.go:165`。

否定定義は、フィールドに新種の実体が増えるたびに漏れる。実害が #847 で顕在化した。展開キューブが周囲へ出す投影タイル `DeployedTile` は `LocationOnField` を持ち `Fixed` を持たないため、現状の `IsPickable` が **true を返す**。投影タイルを拾えてしまう。`internal/world/lifecycle/cube_deploy.go` の `spawnDeployedTiles`。

混乱の根は「prop」という語ではなく、否定定義とアイテムマーカー不在にある。正の `Item` を足し、prop マーカーを正にすれば、語に関係なく区別が立つ。

## 要件

- アイテムか prop かを**正のマーカー**で同定する。新種の実体が増えても既定で「拾えない」に倒れる。
- prop は設置物の総称とする。家具・構造物・自然物・場の効果を含む。無理に furniture へ狭めない。
- 分解の産出先の振り分けを、`Fixed` の有無でなく層で決める。
- #847 の投影タイルが誤って拾える潜在バグを、同じ設計で塞ぐ。
- プレイヤーがアイテムと prop を遊びの中で区別できる表示を保つ。
- 将来: アイテムをフィールドへ置いて prop 化する item-deploy と、prop の下位分類すなわち家具・構造物への細分を、余地として残す。今回は実装しない。

## 設計

### 2軸で捉える。役割層と保存性

フィールドに現れる物を2つの軸で分ける。混同の元は、この2軸を1つの否定フラグに畳んでいたことにある。

- **役割層。何であるか**: `item`（可搬）/ `prop`（設置物の総称）/ `terrain`（壁・床のタイル地形）。
- **保存性。真実か投影か**: 置かれて**保存される**実体か、source から毎フレーム**導出される一時投影**か。`DeployedTile` は後者で、`Deployed` から再導出し serde しない。#847 の `skipComponents` とロード時 despawn がその型。

役割層は存在論、保存性はライフサイクルで、直交する。投影は役割層の存在論には入れない。相互作用も拾得も対象外にする。

`prop` は家具・構造物・自然物・場の効果を含む雑多な総称で、演劇やゲームの「場に置かれた物」の語義そのままにする。`Door` や `Fire` や `Grass` を家具と呼ぶのは不正確なため、層マーカーの名前は狭い `Furniture` にせず総称の `Prop` にする。家具と構造物を分けたくなったら、将来 `Prop` の下位分類として細分する。

### 正のマーカーへ置き換える

`Fixed`（否定の置き物マーカー）を、正のマーカー2つに置き換える。

```go
// 変更前: 置き物を否定で同定する
type Fixed struct{}

// 変更後: 役割層を正のマーカーで同定する
// Item は可搬アイテム。拾える。バックパックへ入る
type Item struct{}

// Prop は設置物。1タイルに1つ。分解でアイテムを産む。既定で拾えない
// 家具・構造物・自然物・場の効果の総称。個別の種別は将来 sub-role で細分しうる
type Prop struct{}
```

- アイテムは `Item` を持つ。`NewItemSpec` が付ける。
- prop は `Prop` を持つ。`NewPropSpec` が付ける。`Fixed` は廃止する。
- 壁は `terrain` すなわち既存のタイル地形のまま。エンティティにしない。
- ドアは開閉状態を持つので `Prop` の構造物として entity のまま残す。壁と違い状態があるため terrain 化しない。

### 拾得判定を正へ

```go
// 変更前: フィールド上かつ Fixed でない。投影タイルも誤って true
func IsPickable(entity ecs.Entity, world w.World) bool {
	if !world.Components.LocationOnField.Has(entity) {
		return false
	}
	if world.Components.Fixed.Has(entity) {
		return false
	}
	return true
}

// 変更後: フィールド上かつ Item。Item を持たない投影タイル・ドア・設置物は自然に除外
func IsPickable(entity ecs.Entity, world w.World) bool {
	return world.Components.LocationOnField.Has(entity) &&
		world.Components.Item.Has(entity)
}
```

`DeployedTile` は `Item` を持たないので false に倒れる。#847 の潜在バグをこの一手で塞ぐ。

### FieldLook に正のカテゴリを足す

```go
// 変更前
FieldLookCategoryKey: {
	{Name: CategoryPlayer, Pred: c.has(c.Player)},
	{Name: CategoryEnemy, Pred: c.has(c.FactionEnemy)},
	{Name: CategoryNPC, Pred: Or{c.has(c.FactionAlly), c.has(c.FactionNeutral)}},
	{Name: CategoryFixed, Pred: c.has(c.Fixed)},
	{Name: CategoryTile, Pred: c.has(c.Tile)},
},

// 変更後: Item と Prop の正カテゴリ。Fixed カテゴリは廃止
FieldLookCategoryKey: {
	{Name: CategoryPlayer, Pred: c.has(c.Player)},
	{Name: CategoryEnemy, Pred: c.has(c.FactionEnemy)},
	{Name: CategoryNPC, Pred: Or{c.has(c.FactionAlly), c.has(c.FactionNeutral)}},
	{Name: CategoryItem, Pred: c.has(c.Item)},
	{Name: CategoryProp, Pred: c.has(c.Prop)},
	{Name: CategoryTile, Pred: c.has(c.Tile)},
},
```

表示名 msgid は `CategoryItem = "Item"`・`CategoryProp = "Prop"` とし、内部マーカー名に揃える。他のカテゴリ `Self`・`Enemy`・`NPC`・`Tile` も素の語なので `Prop` も同じ register で収まる。msgid とコンポーネント名が一致し、翻訳ルックアップの対応も追いやすい。

### 表示。プレイヤーの区別

内部の層分けを、既存の3チャンネルへそのまま乗せる。表示のためだけの追加フラグは要らない。

- **常時・受動。描画深度**: `internal/components/sprite.go:89` の深度規約が既にアイテムと prop を分ける。アイテムは `DepthNumRug`「床に置くもの」で床に寝た見た目、prop は `DepthNumTaller`「高さのあるもの」で立体。`raw.go:264` と `spawn_prop.go:144` が既にこの割り当て。操作不要で一目で分かる。
- **明示・要求時。見回しのカテゴリ**: `look_around.go:206` が対象の名前とカテゴリを併記する。上の正カテゴリで `木の棒 [Item]` / `テーブル [Prop]` になる。確定情報の channel。
- **相互作用の可否。動詞**: `PickablesAt` は `IsPickable` を呼ぶだけで変更不要で、判定を正へ替えた結果 `Item` のみを返す。アイテムには拾う、prop には調べる・分解、と出せる動詞が層で変わる。スプライトが紛らわしくても動作で発見できる。

3チャンネルが受動・明示・動作と粒度を分けて冗長に伝える。まず追加投資なしで出し、実プレイで紛らわしさが残った箇所だけ、床アイテムへの受動マーカーや見回しの色分けを足す。

### 分解の振り分けを層で決める

```go
// 変更前: Fixed && GridElement で prop 判定
if world.Components.Fixed.Has(target) && world.Components.GridElement.Has(target) {
	// フィールドへ産出し、対象を RemoveEntity
}

// 変更後: Prop と Item を両方とも正で分岐する。どちらでもなければ分解対象でない
switch {
case world.Components.Prop.Has(target):
	// フィールドへ産出し、対象を RemoveEntity
case world.Components.Item.Has(target):
	// ChangeItemCount(-1)、バックパックへ産出
default:
	// Player・Enemy 等は分解対象でない。呼び出し元が保証するがここでも弾く
}
```

`else` を Item と決めつけない。否定フォールバックは廃止する `Fixed` と同じ罠で、`Prop` でない物を Item と誤認しうる。`Prop` と `Item` の双方を正で判定し、どちらでもない target は `default` でガードする。分解の呼び出し元が対象を保証するが、二重に弾いて安全側へ倒す。

### 1タイル1prop の不変条件

`Prop` は1タイルに1つに保つ。prop spawn と将来の item-deploy の直前に、`SpatialIndex` で「そのタイルに `Prop` を持つ entity がいるか」だけを見て、いれば弾く。#847 の `deploySpaceFree` は展開に要する全タイルが空かを見るが、こちらは対象タイル1つの `Prop` 在を見る別条件で、`SpatialIndex` を使う点だけ揃える。この確認はアイテム spawn やキャラ spawn には課さず、prop を新設する経路にのみ課す。`internal/world/lifecycle/cube_deploy.go`。

### #847 との整合。deploy は2種類

- **cube-deploy**（#847）: `Deployed` から `DeployedTile` を撒く投影。保存しない。役割層に属さない。相互作用・拾得の対象外。今回のマーカーを付けない。
- **item-deploy**（将来）: アイテムを1つフィールドへ置いて `Prop` 化する実体の配置。保存する。1タイル1prop を守る。

名前と挙動を分け、混同を避ける。今回は cube-deploy の投影が拾えない状態を保証するところまでを射程にし、item-deploy 本体は将来フェーズに置く。

## 採用しなかった方法

- **prop を furniture に統一する**: 層マーカーを `Furniture` にする案。しかし prop の実メンバーは家具だけでなく、`Door`・`Window`・`Fence` の構造物、`Fire`・`Candle` の効果、`Grass`・`Rubble`・`Rock` の自然物を含む。これらを「家具」と呼ぶのは不正確で、つぶそうとしている命名のねじれを再生産する。furniture は総称でなく下位分類なので、層マーカーは総称の `Prop` にする。
- **方向 A。prop を重いアイテムへ統一する**: prop を `Item` にして家具は非常に重く移動不能に倒す案。層が1つで済むが、ドアやワープのような構造物まで「重いアイテム」になり、拾得・重量・分解の分岐が結局 prop 専用の重さ判定で復活する。否定判定の入れ替えにしかならず、分かりづらさの根が残る。正の層で分ける方向を採る。
- **prop を実態で3層に再分配する**: `Grass`・`Rubble` を terrain、`Fire` を効果、残りを家具、と実態へ振り分ける案。最も正確だが、生成・分解・描画・raw を大改修する大工事で今回スコープを超える。まず総称 `Prop` を正マーカー化し、細分は将来 doc に委ねる。
- **家具をタイル属性にする**: CDDA 流に prop をタイルの属性で持つ案。1タイル1prop が型で保証されるが、ruins は prop を entity で持つ ECS で、entity から属性へ移すのは spawn・分解・描画・serde の全経路に波及して破壊が大きい。`Prop` マーカーを付けた entity のまま 1タイル1prop を `SpatialIndex` で守れば、最小の破壊で同じ不変条件に届く。#847 も entity-on-tile で機能している。
- **ドアを terrain タイルへ**: ドアを壁と同じ地形層へ畳む案。CDDA では地形だが、ruins のドアは開閉という状態を持つ。地形をステートフルにする必要が出て、地形は生成の純関数という現在の性質を崩す。ドアは `Prop` の構造物として entity に留める。
- **重い prop の押す/引く移動を今回入れる**: 可搬性を item・可搬 / 重prop・押引 / 不可搬の3段にする案。移動コストは既存の `PassCost` の発想を流用できるが、押引は新機構で今回の主眼ではない。MVP は「置く・分解してアイテムに戻す」に絞り、押引は将来フェーズへ。

## コメント

- `Fixed` の `.Fixed` フィールド参照・`gc.Fixed`・`CategoryFixed` の全参照を洗い出してから置換する。exhaustive linter が守る散在スイッチがあれば、カテゴリ変更で漏れが lint に出る。
- serde の後方互換は未リリースのため考慮しない。旧セーブに `Fixed` が残っても新コードが無視するだけ。
- #847 が未マージのため、`Item` による `IsPickable` 修正が投影タイルに効くことは #847 マージ後に結合して確認する。順序は #847 を先に入れ、本 doc の変更を後に重ねるのが安全。
