# セーブ・ロードは Steam 本番と開発・テストだけ有効にする

## 背景

ゲームを体験版とフル版で配る。体験版はセーブ・ロードを持たず、フル版だけが持つ。どの配布物を
体験版にしてどれをフル版にするかは、実行時の設定でなくビルド時と起動プロファイルで決まる。

- **既定配布とWASM**: 体験版。セーブ・ロードを出さない。
- **Steam版**: 本番のフル版。セーブ・ロードを出す。
- **開発とテスト**: セーブ・ロードを出す。開発中に保存を試せ、テストがフル版の挙動を覆える。

区別軸は既存の2つで足りる。Steam版は `build_steam.sh` が `-tags steam` を付ける。開発とテストは
development プロファイルで動く。`make run` は `RUINS_PROFILE=development` を渡し、テストの
`InitTestWorld` も development プロファイルを使う。既定配布とWASMは production かつ steam タグ
なしなので、この2軸のどちらにも該当せず体験版になる。

## 要件

- セーブ・ロードを出すのは Steam ビルド、または development プロファイルのときだけにする。
- 既定のデスクトップ配布と WASM では、メインメニューの「ロード」とダンジョンメニューの「セーブ」を
  出さない。
- 開発とテストの挙動は不変にする。既存のメニュー・テスト・VRT golden はそのまま通す。
- 新しい env や設定ファイル項目を増やさない。既存の steam タグと profile だけで表す。

## 設計

### 判定は Config.SaveLoadEnabled フィールドに集約する

出し分けの真偽を Config のフィールドにし、値は他の設定と同じく `ApplyProfileDefaults` の profile
既定で決める。env でなく profile と steam タグで決まる導出フィールドで、`RNG` と同じ扱い。呼び出し側
はフィールドを読むだけにする。

```go
// config.go: struct フィールド
SaveLoadEnabled bool

// ApplyProfileDefaults 内の profile 既定
// applyProductionDefaults:  c.SaveLoadEnabled = consts.IsSteamBuild
// applyDevelopmentDefaults: c.SaveLoadEnabled = true
```

steam タグは production 既定の一行だけに現れる。`consts.IsSteamBuild` は steam タグで切り替わる
ビルド時定数にする。config は consts だけに依存し、steamworks には依存しないので、テストや非 steam
ビルドに C 依存が漏れない。

```go
// consts/steambuild_off.go (//go:build !steam)
const IsSteamBuild = false
// consts/steambuild_on.go (//go:build steam)
const IsSteamBuild = true
```

### メニューは採否を問うだけにする

```go
// main_menu.go
if world.Resources.Config.SaveLoadEnabled {
    items = append(items, loadItem)
}
// factories.go の dungeonMenuChoices も同様にセーブ項目を条件追加する
```

## 変更箇所

| ファイル | 変更内容 |
|---|---|
| `internal/consts/steambuild_off.go` | 新設。`//go:build !steam` の `const IsSteamBuild = false` |
| `internal/consts/steambuild_on.go` | 新設。`//go:build steam` の `const IsSteamBuild = true` |
| `internal/config/config.go` | `SaveLoadEnabled` フィールドを追加。profile 既定で決め、production は steam タグで真 |
| `internal/states/main_menu.go` | ロード項目を `SaveLoadEnabled` で条件追加へ |
| `internal/states/factories.go` | ダンジョンメニューのセーブ項目を `SaveLoadEnabled` で条件追加へ |

## 採用しなかった方法

- **production プロファイルを体験版にする**: Steam リリースも production プロファイルで動くので、
  Steam 版まで体験版になってしまう。配布物の区別に profile 単独は使えない。
- **env `RUINS_DEMO` で切り替える**: 体験版かどうかは配布物ごとに固定で、実行時に変える必要がない。
  env にすると各配布の起動時に必ず設定する運用が要り、設定漏れで挙動がぶれる。ビルド時に固定する
  ほうが安全。
- **ビルドタグで save パッケージごとバイナリから外す**: WASM から `internal/save` の依存を断つ案。
  UI を出さない体験版では localStorage は使われないので実害がなく、seam を切る複雑さに見合わない。
  依存を断つのでなく採否で出し分ける。

## コメント

体験版かフル版かはビルド時と起動プロファイルで固定する。判定は `Config.SaveLoadEnabled()` の1箇所に
集約し、メニューは採否を問うだけにする。開発とテストは development プロファイルなので有効側に入り、
既存テストと golden は無変更で通る。Steam 版は steam タグで有効になる。既定配布と WASM は production
かつタグなしなので体験版になる。
