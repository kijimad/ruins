# セーブ・ロードの出し分け。WASM は機構ごと、体験版は実行時方針で外す

## 背景

セーブ・ロードを出すかどうかには直交する2つの軸がある。

- **能力**: このビルドが永続化できるか。ビルド時に決まる事実。WASM はブラウザの localStorage が
  quota も小さく永続性も保証しづらいので不採用とし、保存できない。
- **方針**: 保存できるビルドでもセーブ・ロードを提供するか。実行時に決まる配布方針。将来
  デスクトップ版を体験版として配布する場合、保存はできても出さないことがありうる。

能力軸はビルドタグで扱う。WASM は save パッケージへの依存を断ち、機構ごとバイナリから外す。
方針軸は実行時 env `RUINS_DEMO` で扱う。保存できるデスクトップでも体験版なら UI から落とす。
2軸を1本に相乗りさせると、デスクトップ体験版が能力軸では表現できなくなるので分ける。

## 要件

- WASM ビルドではメインメニューの「ロード」とダンジョンメニューの「セーブ」を出さない。
- WASM ビルドの依存グラフから `internal/save` を外す。dead branch でも参照を残さない。
- `RUINS_DEMO=true` のデスクトップビルドでも同じくロード・セーブを出さない。ただし保存機構は
  同一バイナリが通常版も兼ねるのでバイナリには残る。UI から落とすだけにする。
- デスクトップの通常挙動は不変。既存のメニュー・テスト・VRT golden はそのまま通す。
- 分割は既存の `internal/save` の `//go:build js && wasm` / `//go:build !js || !wasm` 慣習に合わせる。

## 設計

### save 結合コードをプラットフォーム別ファイルへ隔離する

`const bool` フラグで `if enabled { NewSaveMenuState }` と書くと、WASM の dead branch でも
`NewSaveMenuState` → `save` を参照し、機構がバイナリに残る。そこで save を参照するコードを
デスクトップ限定ファイルへ移し、WASM 側では symbol ごと存在させない。

```go
// saveload_desktop.go (//go:build !js || !wasm)
func loadMainMenuItem(world w.World) (mainMenuItem, bool) // ロード項目を返す。体験版なら ok=false
func dungeonSaveMenuChoice(world w.World) (Choice, bool)  // セーブ項目を返す。体験版なら ok=false
// NewSaveMenuState / NewLoadMenuState / loadSlotChoice / formatSaveSlotLabel /
// newResumeStateFactory / backChoice も全てここへ移す

// saveload_wasm.go (//go:build js && wasm)
func loadMainMenuItem(_ w.World) (mainMenuItem, bool) { return mainMenuItem{}, false }
func dungeonSaveMenuChoice(_ w.World) (Choice, bool)  { return Choice{}, false }
// save は import しない
```

メニュー構築側は採否を問うだけにする。

```go
if item, ok := loadMainMenuItem(world); ok { items = append(items, item) }        // main_menu.go
if c, ok := dungeonSaveMenuChoice(world); ok { choices = append(choices, c) }      // factories.go
```

### 配布方針は実行時 env で分ける

能力軸を満たすデスクトップでも、体験版のときはセーブ・ロードを出さない。これはビルド時でなく
実行時の方針なので、`Config.Demo`(env `RUINS_DEMO`)で表す。採否関数は能力軸のうえに方針軸を
重ねて判定する。デスクトップ実装は `Config.Demo` が真なら ok=false を返す。WASM 実装は能力を
持たないので、このフラグに依らず常に ok=false を返す。

```go
// saveload_desktop.go
func loadMainMenuItem(world w.World) (mainMenuItem, bool) {
    if world.Resources.Config.Demo {
        return mainMenuItem{}, false
    }
    return mainMenuItem{...}, true
}
```

デスクトップ体験版は保存機構自体はバイナリに残す。同一バイナリが env 切り替えで通常版も兼ねる
以上、save コードは必ず含まれる。機構ごとの除去は能力軸=ビルド時にしか成立しない。デスクトップ
体験版専用バイナリで機構ごと外したくなったら、その時点で `demo` 専用ビルドタグを切る。今は不要。

### save パッケージの WASM 実体を無保存スタブにする

ゲーム本体は WASM で save を参照しないが、`go build ./...` はパッケージ単体をビルドするので、
`save/wasm.go` のプラットフォーム別メソッドは残す。ただし localStorage 保存は載せず、呼ばれても
永続化しないスタブにする。体験版=保存無効の意図をパッケージ層でも明示する。

## 変更箇所

| ファイル | 変更内容 |
|---|---|
| `internal/config/config.go` | 方針軸の `Demo bool`(env `RUINS_DEMO`)を追加。既定は無効 |
| `internal/states/saveload_desktop.go` | 新設。save 結合の UI・ファクトリを集約。採否関数は体験版なら false を返す |
| `internal/states/saveload_wasm.go` | 新設。採否関数が常に false を返す空実装。save を import しない |
| `internal/states/factories.go` | save/load 群を移設。`save`・`logger` import 除去。ダンジョンメニューを採否関数経由へ |
| `internal/states/main_menu.go` | ロード項目を採否関数経由の条件追加へ |
| `internal/save/wasm.go` | localStorage 保存を無保存スタブへ置換 |
| `internal/save/doc.go` | wasm.go の責務記述を更新 |

## 採用しなかった方法

- **const bool フラグで UI だけ隠す**: dead branch が save を参照し続け、WASM バイナリに機構が残る。
  「機構ごと消す」を満たさないので不採用。
- **save パッケージ全体をデスクトップ限定にする**: WASM で全ファイルがビルド制約で除外され、
  `go build ./...` が「build constraints exclude all Go files」で落ちる。スタブを残して回避する。
- **テストファイルにビルドタグを付ける**: デスクトップでしか走らないテストが desktop 限定 symbol を
  参照するのは既存の `save_integration_test.go` と同じ許容範囲。WASM でテストはビルドしないため不要。
- **能力軸も env で表す**: env なら WASM でも save コードがバイナリに残り、機構ごと除去できない。
  能力軸はビルド時の事実なのでビルドタグで扱い、実行時に変わる方針軸だけを env にする。

## コメント

能力軸の除去は、UI を隠すのでなく依存を断つことで表す。WASM ビルドの `internal/states` は
`internal/save` に依存しなくなり、機構ごとバイナリから外れる。検証は
`GOOS=js GOARCH=wasm go list -deps .` に save が出ないことで行う。方針軸の体験版は `RUINS_DEMO`
で UI から落とすだけで、機構はバイナリに残す。デスクトップの通常挙動は無変更で、既存テストと
golden はそのまま通る。
