# 隊マネジメントシステムへの転換

## 背景

従来の設計は1人のキャラクターを直接操作するローグライクだった。しかし既存のローグライクとの差別化が不足しており、ゲームを特徴づけるコアメカニクスがなかった。

RimWorldの間接操作とDarkest Dungeonの隊員育成・喪失サイクルを参考に、隊マネジメント構造に転換する。リーダーが未知の領域を先頭で切り開き、隊員がポリシーに基づいて探索済みエリアで自律行動する。1人称視点 × 隊マネジメント × ポリシー自動化の組み合わせは既存のローグライクにない。

## 設計

### 概要

プレイヤーはリーダーとして先頭で未知の領域を切り開き、隊員はポリシーに基づいて探索済みエリアで戦闘・回収・運搬を自律的にこなす。

### 変更点

| 項目 | 旧設計 | 新設計 |
|------|--------|--------|
| 操作 | 1人のキャラクターを直接操作 | リーダーを直接操作し、隊員はポリシーに基づいて自律行動する |
| 戦闘 | プレイヤーが直接戦う | リーダーは弱い戦闘能力で前線を切り開く。隊員が探索済みエリアで主戦力として戦う |
| 隊員の行動範囲 | （該当なし） | 探索済みエリアのみ。リーダーが通過して視界に入れたマスだけ行動可能 |
| 隊員の自律行動 | （該当なし） | ポリシーシステムで制御。アイテム回収・分解・分配・戦闘行動をポリシーで自動化する |
| スキル永続性 | 毎ランリセット | 隊員に紐づいて永続。隊員の死亡で全喪失 |
| 職業 | ゲーム開始時に選択 | 廃止。隊員のランダム初期属性に置き換え |
| 本の入手 | ダンジョン発見 + 店で購入 | ダンジョン内発見のみ。店では購入不可 |
| リーダー死亡 | （単一キャラのため該当なし） | ラン失敗。通貨なし、バックパック消滅。ストレージと生存隊員は保持 |
| 隊員の死 | （該当なし） | 永久喪失。サイボーグ投資・スキル蓄積ごと失われる |
| 参考作品 | Elona, CDDA, Slay the Spire | RimWorld, Elona, Darkest Dungeon |

### 隊編成

- 2〜10人の隊員を雇用できる
- 軽量NPC（低コスト・使い捨て偵察）と重量NPC（高投資・精鋭）を組み合わせる
- 維持コスト（食料・凍晶バッテリー）が人数に比例するため、多ければ良いわけではない
- 隊員は商人の店で他の商品と同列に並ぶ雇用候補、人身売買、から選んで雇用する。専用の酒場画面は持たない

### 隊員の個性

- 名前・外見・初期属性がランダム生成される
- 性格や人間関係のシステムはない
- 能力面の差異と育成の歴史で愛着が生まれる設計

### 雇用を店の在庫へ統合する（人身売買）

雇用の専用画面だった酒場をやめ、商人の店の売買に統合する。隊員候補を他の商品と同列に並べ、購入で雇用する。店の在庫は既存の収納機構を再利用し、新コンポーネントは足さない。

商人の品揃えは、商人を所有者とする `LocationInStorage` を持つ実体で表す。既存の収納システムと同じ機構をそのまま使う。

```go
// 商品も隊員候補も「商人の在庫にある実体」。新コンポーネントは不要。
// item:    既存のアイテム実体。LocationInStorage で商人が保持する
// 隊員候補: GridElement を持たない member 実体。フィールドに出ないので描画も戦闘もしない inert 状態
world.Components.LocationInStorage.Add(stock, &gc.LocationInStorage{Owner: merchant})
```

- 在庫は商人生成時に決める。`SpawnStorageItem(itemID, count, merchant)` でアイテムを積み、隊員候補は member spec を GridElement なしで生成して商人へ入れる。
- 買う = `MoveToBackpack(item, player)` で商人→プレイヤーへ実体を移す。在庫が実体ごと減る。通貨を消費する。
- 売る = `MoveToStorage(item, merchant)` でプレイヤー→商人へ移す。売った品が店頭に並ぶ。通貨を得る。
- 雇う = 商人在庫の隊員候補実体に GridElement と squad 化、FactionAlly・SquadMember・SquadAI、を付けてプレイヤー隣へ出す。候補は生成済みなので新規 spawn でなく活性化。通貨を消費する。

#### クリーンアップ

隊員候補もアイテムも商人の在庫実体として持つため、買われなかった在庫が孤児化しないようにする。

- 商人が despawn するとき、その `LocationInStorage{Owner: merchant}` を持つ実体、アイテムと未購入の隊員候補、を全て despawn する。死んだ商人を指す実体を残さない。
- 隊員候補は GridElement を持たないのでフィールドに現れず、戦闘・AI・描画の対象にならない。inert 状態は「フィールド不在」で自然に満たす。
- save/load は実体参照を既存の id 空間 serde に委ねる。商人と在庫の所有関係はエンティティ参照として保存・復元される。

### ポリシーシステム

隊員の自律行動はポリシーで制御する。位置ポリシー（護衛・前衛・巡回・待機・撤退）、戦闘ポリシー（攻撃・回避）、アイテムポリシー（回収・無視）、アイテム処理ポリシー（保持・分配・分解）を組み合わせて隊員の役割を定義する。ポリシーに加えて直接命令も出せる。行動はシンプルで予測可能にし、隊員の動きを見て「なぜそう動いたか」が常にわかる状態を目指す。

### HUD

- ミニマップで隊員・敵の位置を表示する
- 隊員HP一覧で状態を常時把握する
- 1人称視点で散開した隊員の状況をこの2要素で補う

### スキル永続化

`260320172850.md` のスキル体系（36スキル・7カテゴリ・使用ベース成長・減衰曲線）はそのまま維持する。変更点は永続性モデルのみ:

- スキルは隊員に紐づいて永続する（旧: 毎ランリセット）
- 隊員が死亡するとその隊員のスキル蓄積は全て失われる
- 長く生き延びた隊員ほどスキルが高く、失ったときの損害が大きい

### 本の入手制限

スキルが永続になったため、本を店で購入可能にすると通貨で無限にスキルを伸ばせてしまう。本はダンジョン内でのみ発見できる形にしてバランスを保つ。

## コメント

### 採用しなかった案

| 案 | 不採用理由 |
|----|----------|
| 完全自動（RimWorld型） | 1人称視点と矛盾する。プレイヤーが暇になるリスクが高い |
| リーダー戦闘能力なし | 隊員の自律行動を見ているだけになり、ダンジョン探索で暇になるリスクが高い。弱くても戦えることでリーダーの位置取りに緊張感が生まれる |
| 隊員がマップ全域で自由行動 | 未探索エリアにNPCが先行すると1人称視点の探索感が薄れる。リーダーが前線を切り開く役割がなくなる |
| 命令のみでポリシーなし | アイテム回収・分配・分解を毎回手動で指示するのは煩雑。ポリシーで自動化することで面倒な作業をNPCに委任する楽しさが生まれる |
| リーダー直接操作 + 仲間AI（従来RPG型） | 既にやっているゲームが多く差別化にならない |
| 隊員に性格・人間関係を持たせる | 実装コストが高く、「単なる駒」としての割り切りで十分な深さがある |
| スキル毎ランリセットの維持 | 隊員が永続するのにスキルがリセットされると、隊員の価値がサイボーグパーツだけになる |
| リーダー死亡でセーブ消滅 | 隊員の長期育成投資が一瞬で消えるのは罰が重すぎる |
| リーダー死亡でも隊員保持のみ | ラン失敗のペナルティが軽すぎてリーダーの位置取りが緊張感を欠く |
| 本を店でも購入可能 | スキル永続下では通貨→スキルの無限変換になりバランスが崩壊する |

### 設計の正典

この設計変更により `docs/plan/design.md` を全面改訂した。design.md が現在のゲーム設計の正典である。`260320172850.md` のスキル体系（スキル一覧・効果式・成長曲線・成長速度）は引き続き有効だが、永続性モデルと本の入手方法は本ドキュメントの設計が優先する。
