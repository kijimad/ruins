# 体の攻撃をアイテムの表から分ける

## 背景

素手 `bare_hands` や、敵の噛みつき `bite`・体当たり `tackle`・火を吐く `breathe_fire` のような体に備わった攻撃は、アイテムの表 `items` の行として書かれている。敵の攻撃表 `commandTables` が引く 24 行のうち 17 行は、戦利品・レシピ・初期装備・物の組 `itemGroups` のどこからも参照されない、拾えない攻撃だけの行である。重さ `0 g`・値段 `0`・地面に落ちたときの絵 `field_item` を、使われないのに持っている。

| 種類 | 行 |
|---|---|
| 攻撃だけの行。17 | `bare_hands`・`bite`・`bombard`・`breathe_fire`・`cold_attack`・`flame_attack`・`frost_maw`・`light_shot`・`photon_flash`・`rend`・`roar`・`shock`・`shock_bite`・`smash`・`strafe`・`tackle`・`venom_fang` |
| 敵が使い、物の組から拾える物でもある行。7 | `bleed_claw`・`blind_powder`・`cleaver`・`curse_dagger`・`drowsy_pipe`・`paralyze_rod`・`toxin_barb` |

灯りと武器と道具に残量を持たせる設計 `261119224218` は、「近接攻撃を持つアイテムは残量を必ず持つ」という規則を置く。拾えない攻撃がアイテムに混ざっていると、この規則に例外が要る。例外をアイテムの印で表すと、拾えないという性質をアイテムに持たせることになり、意味が合わない。

## 要件

- アイテムの表の行は、拾える物だけにする
- 敵の攻撃表は、体の攻撃とアイテムのどちらも引ける
- 攻撃の振る舞い、すなわち命中・ダメージ・攻撃の分類・ログに出る名前は変えない

## 設計

### 体の攻撃の表

raw に体の攻撃の表 `bodyAttacks` を足す。行は名前と近接攻撃だけを持つ。近接攻撃の型はアイテムと同じ `#Melee` を使う。

```cue
// 体の攻撃。体に備わり、拾えない攻撃
#BodyAttack: {
	id!:    #EntityID
	name!:  #EntityName
	melee!: #Melee
}

#Raws: {
	// ...今の欄
	bodyAttacks?: [...#BodyAttack]
}
```

攻撃だけの 17 行を `items` から `bodyAttacks` へ移す。移すときに `description`・`spriteKey`・`spriteSheetName`・`value`・`weight` を落とす。どれも攻撃の処理では読まない。拾える 7 行はアイテムのまま残す。

### 敵の攻撃表が引く先

敵の攻撃表の行に、引く表を欄で書き分ける。どちらか1つだけを書く。

```cue
#CommandTableEntry: {
	// 体の攻撃の id
	bodyAttack?: #EntityID
	if bodyAttack != _|_ {
		bodyAttack_ref: _bodyAttackIDs[bodyAttack] @rawgen(-)
	}
	// 使う武器のアイテムの id
	item?: #EntityID
	if item != _|_ {
		item_ref: _itemIDs[item] @rawgen(-)
	}
	weight!: #EntryWeight
}
```

```toml
[[commandTables]]
id = "bat"
name = "コウモリ"
entries = [
  { bodyAttack = "bite", weight = 2 },
  { bodyAttack = "tackle", weight = 1 },
]
```

「どちらか1つだけ」は `raw.validateRules` に置く。CUE の選言で書くと実データで遅くなるため、ruins-cue の規約に従い Go の規則にする。

### 攻撃を取り出す処理

近接攻撃と名前を取り出す処理を `raw` に1つ置き、敵の攻撃と素手の両方から呼ぶ。

```go
// BodyAttackMelee は体の攻撃の近接攻撃と名前を返す
func BodyAttackMelee(raws rawschema.Raws, id string) (*gc.Melee, i18n.Msgid, error)

// CommandEntryMelee は敵の攻撃表の行が引く近接攻撃と名前を返す。体の攻撃かアイテムかは行の欄で決まる
func CommandEntryMelee(raws rawschema.Raws, entry rawschema.CommandTableEntry) (*gc.Melee, i18n.Msgid, error)
```

- `raw.SelectCommandByWeight` は id の文字列でなく、選んだ行 `rawschema.CommandTableEntry` を返す
- `query.GetAttackFromCommandTable` は選んだ行を `CommandEntryMelee` に渡す。今は `NewWeaponSpec` でエンティティの仕様を丸ごと組んで `Melee` と `Name` だけを使っているので、組む量も減る
- `activity.getBareHandsAttack` は `BodyAttackMelee(raws, "bare_hands")` を呼ぶ
- バランスの計算 `internal/balance` は、武器を名前でなく数値 `WeaponStats` で受け取る。呼ぶ側が `LoadWeaponFromBodyAttack` か `LoadWeaponFromItem` で、どちらの表から読むかを決める。ダメージの倍率を変える `withScaledMeleeDamages` は両方の表の近接攻撃を動かす

## 採用しなかった方法

- **敵の攻撃表の行は `id` のまま、体の攻撃の表とアイテムの表の両方から探す**: raw の行を書き換えずに済む。ただ、どちらの表の行かが読み手から見えず、2つの表の id が重ならない検査も別に要る
- **拾える 7 行も体の攻撃の表へ移し、アイテムには別の行を置く**: 同じ近接攻撃を2か所に書くことになり、値がずれる
- **アイテムの行に拾えないという印を足す**: 拾えないという性質をアイテムに持たせることになる。残量の規則にも例外が残る
