# 一時ポインタ変数を Go 1.26 の new(式) に置き換える

## 背景

値のポインタが欲しいだけのために一時変数を宣言する箇所が散在している。生成コード oapi のオプショナル・フィールドがポインタ型で、変換結果や関数戻り値のアドレスを直接は取れないことが主な発生源になる。

```go
zero := 0
e, err := lifecycle.SpawnTile(world, tileName, x, y, &zero) // zero は &zero のためだけ
```

Go 1.26 で組み込みの `new` が式を取れるようになった。`new(v)` は値のコピーへのポインタを返し、`&v` と等価で、アドレスを取れない変換結果にもそのまま使える。実機で確認した。

```go
p := new(oapi.ItemCount(3)) // *oapi.ItemCount。&oapi.ItemCount(3) は書けないが new なら書ける
```

AST で「宣言直後にアドレスを1度だけ取り、他では使わない」一時変数を数えると83箇所ある。加えて `disassembly_test.go` に自前の `ptr[T any](v T) *T { return new(v) }` があり、8箇所で使われる。これは Go 1.26 の `new` の薄いラッパにすぎない。

## 要件

- 「ポインタを取るためだけの一時変数」を畳み、意図を1行で表す
- 言語の組み込みで足りるものは自前ヘルパを増やさない。YAGNI と公開 API 最小化に従う
- 挙動と評価順を変えない

## 設計

一時変数を、その値を生む式へインライン化する。式の種類で置換先を選ぶ。

- 複合リテラル `T{...}` や `[]T{...}` は `&T{...}` にする。Go は元々これを直接書けるので `new` は使わない
- それ以外の式、変換・関数戻り値・デリファレンス・スカラーリテラル・識別子は `new(式)` にする

```go
// 変換・スカラー
-zero := 0
-... SpawnTile(..., &zero)
+... SpawnTile(..., new(0))

// デリファレンスの防御コピー。new(*p) も独立したコピーを確保するので意味は同じ
-dest := *ctx.Grid
-return &activity.PickupActivity{Destination: &dest}
+return &activity.PickupActivity{Destination: new(*ctx.Grid)}

// 複合リテラルは &T{...}
-destination := gc.GridElement{Coord: c}
-... &destination
+... &gc.GridElement{Coord: c}
```

安全のため、置換は「宣言の直後の文でアドレスを取る」隣接ケースだけに絞る。宣言と使用の間に文が挟まると式の評価タイミングが動きうるため、その15箇所は今回対象外にする。対象は隣接する68箇所と `ptr` ヘルパ経由の8箇所になる。`ptr` ヘルパ自体は削除する。

置換は go/packages の型情報で定義-使用を解いて対象を特定した。名前一致では同名の別変数や入れ子スコープを取り違えるため、型オブジェクト単位で「使用がちょうど1回、それが `&` の直接オペランド」を厳密に判定する。処理の大半は機械置換で行い、入れ子の複合リテラルが絡む数箇所だけ手で整えた。名前がテストデータの説明として効く複合リテラルの一時変数は、読みやすさを優先して残した。

ループ変数を写して独立ポインタを作る `e := entity; &e` のような箇所は、`new(entity)` にするとエイリアスの余地が消えてむしろ安全になる。

## 変更箇所

| 対象 | 変更 |
|---|---|
| 一時ポインタ変数 68箇所 | 宣言を削り、使用箇所を `new(式)` または `&T{...}` に置き換える |
| `internal/world/lifecycle/disassembly_test.go` | ローカル `ptr` を削除し、8箇所の `ptr(...)` を `new(...)` に置き換える |

## 採用しなかった方法

- **共通の `ptr` ヘルパを新設する** — `ptr(v)` は `new(v)` より意図が読めるという利点はあるが、組み込みの薄いラッパを保守する負担に見合わない。Go 1.26 の `new` を使う方が筋が通る
- **間に文が挟まる15箇所も置換する** — 式の評価タイミングが動きうる。得られる一貫性より回帰リスクが勝るので今回は見送る
- **PtrSlice を別パッケージへ移す** — raw の `PtrSlice` を汎用 leaf へ出す層破り解消は有用だが、これはポインタ生成でなくデリファレンスの整理で別軸になる。今回のスコープから外す
- **複合リテラルも `new` にする** — `new(T{...})` も合法だが、`&T{...}` が既存の慣用形なのでそちらに揃える

## コメント

- 主眼は「共通化」ではなく、組み込みで足りる処理から一時変数と自前ヘルパを取り除くことにある
