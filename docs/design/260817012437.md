# メニュー選択カーソルをゆるやかに点滅させる

## 背景

メニューの選択中の行は、選択バー画像 `res.Panel.SelectionBar` を行コンテナの背景に敷いて表す。実体は `styled.NewListItem` と、タブメニューの `messagewindow` 側フォーカス更新でこの背景画像を差し替えるだけの静的表現になっている。カーソルが移動した瞬間にバーが現れて消えるだけで、アクティブであることの手がかりが弱い。

一方、ダンジョン内の調査カーソル `LookAroundState` と射撃カーソル `ShootingState` は、各 state の `Draw` 内で自前に `blinkCounter` を持ち `math.Sin` でアルファを揺らして点滅させている。これらは state ごとに手描きの実装で、メニュー UI とは描画機構が別物になっている。メニュー選択の点滅にこの方式は流用できない。理由は下記のとおり ebitenui の retained ツリーと相性が悪いため。

やりたいことは、選択中の行をゆるやかに明滅させ、いまどこが選ばれているかを一目でわかるようにすること。よくあるゲームメニューのアクティブ表現に寄せる。

### 現状の描画機構と制約

- メニュー UI は ebitenui の retained ツリー。`menuloop.Screen` は入力や props に変化があったフレーム、つまり dirty なフレームだけツリーを組み直し、変化が無ければ前フレームのツリーを再利用する。よってツリー再構築を毎フレーム回して点滅させる方式は、retained 最適化と hooks の再発火を壊すので取れない。
- ただし描画 `s.widget.Draw(screen)` は dirty に関係なく毎フレーム走る。ebitenui はこの中で各ウィジェットの `Render` を毎フレーム呼ぶ。既存の `styled.GradientLine` はこの `Render` の中で `op.ColorScale.ScaleWithColor` を掛けて描いており、カスタムウィジェットの `Render` が「ツリーを組み直さずに毎フレーム描画へ介入できる差し込み口」になることを示している。
- 選択バーは現状コンテナの背景画像 `BackgroundImage` として敷かれる。背景画像は ebitenui がコンテナ内部で描くため、こちらからフレームごとのアルファを掛ける隙間が無い。アルファを揺らすには自前で描く層に置き換える必要がある。
- `world.Config.DisableAnimation` が真のときはアニメーションを止める約束がある。VRT は `internal/vrt/state.go` でこれを真にする。styled と messagewindow のゴールデンテストはこのフラグを触らず `world` も渡さず、単フレームで `NewListItem` を直接描く。ゴールデン画像を揺らさない配慮が要る。

## 要件

- 選択中の行が、ゆるやかな正弦のアルファ揺れで明滅する。ハードな点灯消灯ではなく滑らかに脈動させる。
- 明滅の谷でも完全には消えない。選択が一瞬消えたように見えるとかえって迷うため、下限アルファを残す。
- `world.Config.DisableAnimation` が真なら点滅せず、従来どおりの静止表示にする。
- 既存のゴールデン画像を作り直さずに済ませる。つまり静止状態の見た目は現状の選択バー、フルアルファと一致させる。
- 影響範囲はメニューのリスト選択。`styled.NewListItem` を通る画面を主対象とする。HUD の武器スロット枠、調査・射撃カーソルは対象外。後者は描画機構が別で、別途に自前実装されているため本件では触らない。

## 設計

### 方針

選択バーを「背景画像の差し替え」から「毎フレーム自分でアルファを掛けて描くカスタムウィジェット」へ置き換える。点滅の位相は正弦で、位相0をフルアルファのピークに取る。これで次が同時に満たせる。

- 単フレームで描かれるゴールデンはカウンタ0、位相0、フルアルファになり現状と一致する。ゴールデン作り直し不要。
- `DisableAnimation` 時はアルファをピーク固定にすれば静止表示になり、同じく現状と一致する。
- アイドル時はカウンタが進みゆるやかに脈動する。

時間源はウィジェット自身が持つ。ebitenui は retained ツリーでも毎フレーム `Update` を各ウィジェットへ配る。`menuloop.Screen.Update` は毎フレーム `s.widget.Update()` を呼ぶため、カスタムウィジェットの `Update` でフレームカウンタを進めれば、ツリーを組み直さなくても時間が進む。カーソル移動でツリーが再構築されるとカウンタは0に戻り、選択が動くたびにピークから明滅し直す。これはアクティブな行が動いた瞬間に強調される望ましい挙動になる。

### アルファの式

位相0をピークに取るため余弦を使う。

```go
// selectionBlinkAlpha はフレームカウンタから選択バーのアルファ倍率を返す。
// 位相0はピーク。ゆるやかに selectionBlinkFloor まで沈んで戻る。
// animate が偽なら常にピーク、静止表示になる。
func selectionBlinkAlpha(tick int, animate bool) float32 {
	if !animate {
		return 1.0
	}
	// (1-cos)/2 は tick=0 で 0、半周で 1。振幅 (1-floor) だけピークから沈める
	dip := (1 - math.Cos(float64(tick)*selectionBlinkSpeed)) / 2
	return float32(1.0 - (1.0-selectionBlinkFloor)*dip)
}
```

パラメータは `theme` に定数で置く。数値は初期値で、実機で微調整する。

```go
const (
	// selectionBlinkFloor は明滅の谷のアルファ下限。完全には消さない
	selectionBlinkFloor = 0.55
	// selectionBlinkSpeed は1フレームあたりの位相進み(rad)。60fps で 2π/0.1 ≈ 63フレーム、約1.0秒周期
	selectionBlinkSpeed = 0.1
)
```

### カスタムウィジェット

`styled.NewListItem` が背景に敷いている選択バーを、次のウィジェットで置き換える。`GradientLine` と同じく `widget.PreferredSizeLocateableWidget` を満たし、`Render` でナインスライスを幅に合わせて描きつつアルファを掛ける。

```go
// selectionBar は選択中の行に敷くナインスライスのバー。Render でアルファを揺らして明滅させる。
// selected が偽なら描かない。時間源は自前のフレームカウンタ。
type selectionBar struct {
	widget  *widget.Widget
	src     *image.NineSlice // res.Panel.SelectionBar と同じ画像
	selected bool
	animate  bool // DisableAnimation の否定。偽なら静止
	tick     int
}

func (b *selectionBar) Update(o *widget.UpdateObject) {
	b.widget.Update(o)
	b.tick++ // 毎フレーム進む。ツリー再構築時は新規生成され0から
}

func (b *selectionBar) Render(screen *ebiten.Image) {
	b.widget.Render(screen)
	if !b.selected {
		return
	}
	alpha := selectionBlinkAlpha(b.tick, b.animate)
	// b.widget.Rect にナインスライスを描き、op.ColorScale.ScaleAlpha(alpha) を掛ける
}

// SetSelected はフォーカス更新から選択状態を切り替える
func (b *selectionBar) SetSelected(v bool) { b.selected = v }
```

行の重なり順は、バーを背面、コンテンツ行を前面に置く。現状 `NewListItem` は縦の `RowLayout` で「コンテンツ行 + 区切り線」を積む。ここを、コンテンツ行の背面に `selectionBar` を重ねる構成へ変える。ebitenui は追加順に描くため、バーを先に、コンテンツを後に足せば前面に文字が来る。具体的なレイアウト種別は実装時に `AnchorLayout` か重ね合わせで確定する。

### アニメ有効フラグの引き回し

`selectionBar` は `animate bool` を要る。`NewListItem` は現状 `world` も `config` も受け取らず `res resources.UIResources` だけを取る。ゴールデンテストも `world` 無しで `NewListItem` を直接呼ぶ。ここで下記を選ぶ。

- 位相0ピーク設計により、単フレーム描画のゴールデンは `animate` の真偽に関わらずピークになり現状と一致する。よってゴールデン安定のために `animate` を渡す必要は無い。
- 実プレイで `DisableAnimation` を効かせたい経路、つまり `world` を持つ描画経路だけが `animate` を必要とする。`NewListItem` に `animate` を可変長オプションかデフォルト真の引数で足し、`world` を持つ呼び出し側が `!world.Config.DisableAnimation` を渡す。`world` を持たない既存呼び出しはデフォルト真のままで、単フレームゴールデンはピーク一致で問題ない。

グローバルな可変状態は増やさない。時間源はウィジェット内、有効フラグは引数で明示的に渡す。

### タブメニューのフォーカス更新

`messagewindow` のタブメニューは `createMenuButton` 経由で `styled.NewListItem` を使い、`UpdateFocus` で選択行の背景画像を直接差し替えている。バーをウィジェット化するとこの差し替えは効かなくなる。`UpdateFocus` は背景画像の付け外しをやめ、行内の `selectionBar` を辿って `SetSelected(true/false)` を呼ぶ形へ変える。テキスト色の切り替えは現状どおり残す。

### 影響範囲まとめ

- 主対象は `styled.NewListItem` を通るメニュー。`messagewindow` タブメニューを含む。
- `styled` のテーブル選択行 `NewTableRow` も同じ選択バー画像を使う。今回と同じ差し替えで揃えられるが、まず `NewListItem` とタブメニューを対象にし、テーブルは追随課題とする。
- 対象外は HUD 武器スロット枠、調査・射撃カーソル。

## 採用しなかった方法

- **毎フレームツリーを dirty 扱いにして組み直す**。`Screen` を毎フレーム dirty にすれば背景画像を差し替え続けられるが、retained 最適化を殺し hooks を毎フレーム再発火させる。点滅のためにメニュー全体の再構築コストを払うのは釣り合わない。
- **背景画像のナインスライスを毎フレーム作り直す**。`NewNineSliceColor` をアルファ違いで毎フレーム生成して差し替える案。生成コストが無駄で、かつ差し替えを毎フレーム走らせるため上と同じく dirty 前提になる。
- **`Screen.Draw` で ebitenui 描画後にオーバーレイを重ねる**。選択行の矩形 `GetWidget().Rect` を取り、その上に明滅する矩形を後描きする案。`Screen` が選択の座標を知る必要があり、View に選択ウィジェットを露出させる結合が増える。しかも `menuloop.Screen` を通る画面しか救えず、overlay やテーブルなど他のリスト表現に広がらない。カスタムウィジェット方式なら選択表現の一箇所に閉じる。
- **調査・射撃カーソルの `blinkCounter` 方式を流用する**。あれは state の `Draw` で手描きする前提で、ebitenui の retained ツリーには乗らない。メニューへ持ち込むと state ごとの重複実装が増える。選択表現は widget 側に一元化するのが筋。
- **共有のフレームクロックを中央で1回進める**。`MainGame.Update` でグローバルカウンタを進め全ウィジェットが参照する案。カーソル移動をまたいで位相が連続する利点はあるが、グローバル可変状態が増える。選択は常に1件で、移動時にピークから振り直す挙動はむしろ好ましいため、ウィジェット自前カウンタを採る。連続位相が要ると分かった時点で共有クロックへ移せる。

## コメント

- 数値 `selectionBlinkFloor` `selectionBlinkSpeed` は実機で「ゆるやか」の体感に合わせて調整する。周期は約1秒前後を初期値にする。
- 重ね合わせのレイアウト種別は実装時に確定する。`AnchorLayout` で背面ストレッチが素直か、専用の重ね合わせが要るかを実装で見極める。
