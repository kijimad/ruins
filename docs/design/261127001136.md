# 地上の帯を15×15に広げ、描画は画面に映りうる範囲のタイルだけを投影する

## 背景

錨を下ろしたエリアは帯の範囲で決まる。今の帯は9×9チャンクで、拠点から端まで約100タイルしかなく、遠征の道のりが短い。帯を15×15に広げ、エリアを横にも縦にも広げる。

帯の列の数は地形の生成に効く。区域の位置 `districtAt` と道の計画 `planAt` が列の数を引数に取るので、展開中だけ広げると、すでに生成した列と前提が食い違う。帯はいつも同じ大きさで広げる。

広げると重くなる。地上の描画と北へのずれを、帯の大きさごとに別のプロセスで測った。

| 帯 | タイル数 | 描画 1フレーム | 北へ1行ずれる |
|---|---|---|---|
| 9×9 | 52,690 | 9.7ms | 約67ms |
| 13×13 | 111,002 | 16.3ms | 約126ms |
| 15×15 | 148,240 | 20.7ms | 約180ms |

13×13の描画を CPU プロファイルで見ると、描画の約83%が `Projector.TileOnScreen` だった。全タイルについて、底と天面の8隅を毎フレーム投影し、画面に掛かるかを確かめている。画面に映るのは帯の一部なので、ほとんどの投影は落とすためだけに使われている。

## 設計

### 画面に映りうる範囲を毎フレーム一度だけ矩形で求める

`NewProjector` で、視錐台と、高さ0から立つ物の天面までの層が重なる所を、XZ 平面の整数の矩形で求めて持つ。`TileOnScreen` は、まず矩形の外かを整数で比べて落とし、中のタイルだけ8隅を投影する。呼ぶ側は変えない。

```go
type Projector struct {
	vp     mat
	view   mat
	eye    Vec
	target Vec
	sw, sh int
	// visMin, visMax は層 0〜maxStandHeight が視錐台に入りうるタイルを包む矩形。両端を含む
	visMin, visMax consts.Coord[consts.Tile]
}

// maxStandHeight は TileOnScreen に渡す天面の高さの上限。矩形はこの高さまでの層で求める
const maxStandHeight = max(WallHeight, BillboardHeight)
```

矩形の求め方。

- カメラの向きと画面の縦横比から、近平面と遠平面の4隅ずつ、視錐台の8隅をワールド座標で作る
- 視錐台の12本の辺それぞれについて、高さ0と `maxStandHeight` の平面と交わる点を求める。層の中にある隅もそのまま点に入れる
- 点の X と Z の最小と最大を取り、外へ1タイル広げて整数にする。点が無ければ空の矩形にする

視錐台と層の重なりは凸なので、その頂点は「層の中にある視錐台の隅」と「視錐台の辺と層の面の交点」のどちらかになる。点の範囲で重なり全体を包める。タイルの箱が視錐台と重なれば、その重なりの点は矩形に入るので、映るタイルを落とすことはない。描画の結果は変わらない。

`TileOnScreen` に `maxStandHeight` より高い天面を渡したときは、矩形で落とさず、今までどおり8隅を投影する。

### 帯を15×15にする

```go
// internal/dungeon/registry.go
DungeonOverworld = NewOverworldDefinition("Overworld", 0, 24, 24, 15, 15)
```

地上の生成が変わるので、地上の golden を撮り直す。

列の数が変わると区域の置かれ方も変わる。開始から最初の通信施設までの距離を seed 100個で測ると、9列で中央値22、上位10%で34、最大64チャンク、15列で中央値25、上位10%で35、最大86チャンクだった。確かめる範囲は、9列のときと同じく測った分布に合わせ、seed 100個の全てで90チャンク以内にする。

### 北へのずれの重さは受け入れる

北へ1行ずれるたびに、列の数ぶんのチャンクを一度に生成する。15列では今の倍ほど引っかかる。遊んで気になれば、生成を何フレームかに分ける手当てを別に考える。

## 採用しなかった方法

| 案 | 採らなかった理由 |
|---|---|
| タイルを座標の格子に持ち、画面の範囲だけを回す | 回す数は減るが、タイルを格子に持つ索引を足し、生成とずれのたびに保つ仕組みが要る。矩形で落とせば、回す数は残っても1枚あたりは整数の比較だけで済む |
| 画面の4隅を地面へ逆に投影して範囲を求める | 見下ろし角を寝かせると、画面の上端の視線が地平線より上を向き、地面と交わらない。視錐台の辺と層の交わりで求めれば、遠平面で自然に閉じる |
| 展開中だけ帯を広げる | 列の数が地形の生成に効くので、すでに生成した列と前提が食い違う |
| 北へのずれの生成を何フレームかに分ける | 生成の作りを変える大きな変更になる。今回は帯を広げることを先にする |

## コメント

- 描画の時間は、帯の大きさごとに別のプロセスで測る。1つのプロセスで大きさを変えながら測ると、前の世界がメモリに残り、後の数字が重く出る
- 見下ろし角を最小まで寝かせると、映りうる範囲は遠平面まで伸び、帯のほとんどが矩形に入る。そのときの重さは絞り込む前と同じで、15×15では約20.7msになる。最小の角度は一時的な視点として割り切る
- 最小の距離と見下ろし角で、絞り込みの有無の絵を画素で比べると、斜めの向きで1枚あたり1〜4画素だけ違った。どれも周りから浮いた1画素で、絞り込む前の描き方が出していたものだった。カメラの面をまたぐタイルを残すと、カメラのごく近くの頂点が画面のはるか外へ投影され、三角形を塗るときの丸めで画面に点が出る。既定の視点では golden は変わらない
- 帯を広げた後の1ターンは、9×9の4.6msから15×15で5.8ms、組み立て後のヒープは229MBから260MBになった
