# ダンジョンの間取りの段の並びを raw で組む

## 背景

doc 261115150337 で、間取りの数値とタイルを作り方ごとの表 `roomLayouts`・`caveLayouts` などへ移した。段の並びはまだ作り方ごとの Go の関数 `NewCavePlanner` などが持つ。参考 codebase: `internal/mapplanner/lib.go` の `NewSmallRoomPlanner`、`cave_planner.go` の `NewCavePlanner`。

今の段の並びは次のとおりである。`BuildChain` が最後に敵・アイテム・ポータルの段を足す。

| 間取り | 最初の段 | 中の段 |
|---|---|---|
| small_room | RectRoomPlanner | FillAll → RoomDraw → LineCorridorPlanner → DoorPlanner → ConvertIsolatedWalls → EnvironmentPlanner |
| big_room | BigRoomPlanner | FillAll → BigRoomDraw → ConvertIsolatedWalls → EnvironmentPlanner |
| cave | CavePlanner | CaveCellularAutomata → CavePathWidener → CaveConnector → CaveStalactites → ConvertIsolatedWalls → EnvironmentPlanner |
| ruins | RuinsPlanner | FillAll → RuinsDraw → RuinsDebris → RuinsCorridors → ConvertIsolatedWalls → EnvironmentPlanner |
| forest | ForestPlanner | ForestTerrain → ForestTrees → ForestPaths → ForestWildlife → ConvertIsolatedWalls → EnvironmentPlanner |
| 絵 | TemplatePlanner | TemplatePlanner → EnvironmentPlanner |

設計の指針は、生成の内容を TOML で表現でき、組み合わせやすいことである。段の並びを raw に書けば、既存の段を組み替えた間取りを Go を書かずに足せる。たとえば扉のある廃墟、鍾乳石の撒かれた大部屋である。

## 要件

1. 間取りの行は、最初の段と中の段を段の行の id の並びで持つ。
2. 段の種類ごとに型付きの表を分け、条件付きのフィールドを使わない。
3. 今の5つの間取りと4つの絵の間取りを raw の並びで組み直し、地図の生成結果を変えない。

## 設計

### 間取りの行

作り方ごとの6つの表を1つの `layouts` にまとめる。タイルは間取りの行に1回だけ書き、段は作るときに間取りのタイルを受け取る。

```cue
#Layout: {
	id!:    #EntityID
	tiles!: #LayoutTiles
	// 最初の段の行の id
	start!:    #EntityID
	start_ref: _startIDs[start] @rawgen(-)
	// 中の段の行の id。並びの順に走る
	steps!: [...#EntityID]
	steps_ref: [for x in steps {_stepIDs[x]}] @rawgen(-)
}
```

- 絵の間取りは `start` に絵の最初の段を指し、`steps` を空にする。絵の間取りは `tiles` を使わないが、型を分けないために書く。
- 間取りのタイルに `ground` と書けば、ダンジョンの行の下地 `ground` を置く。施設の絵のパレットの `ground` と同じ予約語である。森の間取りは床と孤立した壁の置き換え先を `ground` にし、ダンジョンごとの土の色で描く。`ground` を使う間取りを持つダンジョンは下地が必須で、計画に下地が無ければ `ErrGroundNotSet` になる。
- `EnvironmentPlanner` は全ての間取りの最後に要るので、`newLayoutChain` が最後に足す。地上のチェーンは環境の段を持たないので、`BuildChain` では足さない。
- ランダムに選ぶ候補は、最初の段が絵でない間取りの行から行の順に作る。今の候補の順に行を並べ、乱数の消費を変えない。

### 最初の段の表

最初の段は部屋の矩形 `MetaPlan.Rooms` を決める。

| 表 | 今の型 | 欄 |
|---|---|---|
| `rectRoomStarts` | RectRoomPlanner | `rooms`・`roomSize` |
| `noiseStarts` | CavePlanner | `wallChance` |
| `buildingStarts` | RuinsPlanner | `buildings`・`buildingWidth`・`buildingHeight` |
| `clearingStarts` | ForestPlanner | `clearings`・`clearingSize` |
| `templateStarts` | TemplatePlanner | `template` |
| `simpleStarts` | 欄を持たない最初の段 | `kind`。値は `full_room` で BigRoomPlanner |

### 中の段の表

| 表 | 今の型 | 欄 |
|---|---|---|
| `corridorSteps` | LineCorridorPlanner | `width` |
| `doorSteps` | DoorPlanner | `chance` |
| `bigRoomSteps` | BigRoomDraw | `pillarSpacing`・`obstacleArea`・`mazeGapChance`・`platformRadius` |
| `automataSteps` | CaveCellularAutomata | `iterations`・`wallNeighbors`・`minRoomTiles` |
| `widenSteps` | CavePathWidener | `chance` |
| `scatterWallSteps` | CaveStalactites | `chance` |
| `ruinedWallSteps` | RuinsDraw | `wallGapChance`・`partitionGapChance` |
| `ruinedPathSteps` | RuinsCorridors | `chance` |
| `treeSteps` | ForestTrees | `density`・`largeTreeChance` |
| `trailSteps` | ForestPaths | `tile` |
| `gladeSteps` | ForestWildlife | `spots` |
| `simpleSteps` | 欄を持たない中の段 | `kind` |

`simpleSteps` の `kind` は次の列挙である。

| 値 | 今の型 |
|---|---|
| `fill_wall` | FillAll。間取りの壁で埋める |
| `draw_rooms` | RoomDraw |
| `connect_rooms` | CaveConnector |
| `debris` | RuinsDebris |
| `forest_floor` | ForestTerrain |
| `isolated_walls` | ConvertIsolatedWalls |

```cue
#SimpleStep: {
	id!:   #EntityID
	kind!: #SimpleStepKind
}

#SimpleStepKind: "fill_wall" | "draw_rooms" | "connect_rooms" | "debris" | "forest_floor" | "isolated_walls"
```

- 段の id は、最初の段の表どうし、中の段の表どうしで一意にする。
- 欄を持たない段を1つの表にまとめ、行が id だけの表を作らない。`kind` は Go の exhaustive な switch で段に写す。
- 汎用に使える段は Go の型を汎用の名前に変える。CavePathWidener を Widen、CaveConnector を ConnectRooms、CaveStalactites を ScatterWalls にする。地図のスナップショットの段の名前が変わるので、golden のファイル名が変わる。中身は変わらない。

### Go

```go
// newLayoutChain は間取りの行から最初の段と中の段を引いてチェーンを作る
func newLayoutChain(raws rawschema.Raws, id string, width, height consts.Tile, seed uint64) (*PlannerChain, error)

// newStart は絵でない最初の段の行 id を表から引いて段を作る。絵の最初の段は大きさを絵から決めるので newLayoutChain が別に作る
func newStart(raws rawschema.Raws, id string, tiles rawschema.LayoutTiles) (InitialMapPlanner, error)

// newStep は中の段の行 id を表から引いて段を作る
func newStep(raws rawschema.Raws, id string, tiles rawschema.LayoutTiles) (MetaMapPlanner, error)
```

- 段の型は行の値とタイルを持つ。`CavePlanner{Layout: l}` のような間取りの行を丸ごと持つ形をやめる。
- `NewCavePlanner` などの作り方ごとの関数を消す。テストは `newLayoutChain` か、段の型を直接組む。

## 採用しなかった方法

- **段を間取りの行の中に書く。** `steps = [{ widen = { chance = 0.3 } }]` は読みやすいが、要素が任意のフィールドのうち1つだけを持つ排他の型になり、条件付きのフィールドと同じ弱さを持つ。
- **段の並びを Go に残す。** 新しい組み合わせのたびに Go の関数が要る。
- **欄を持たない段も種類ごとに表を作る。** id だけの行の表が6つ増え、読みにくい。
- **最初の段を中の段と同じ並びに入れる。** 最初の段は部屋を決める別のインタフェースで、並びの先頭だけ型が違う並びになる。

## コメント

- 組み替えで意味の合わない並びも書ける。とくに `MetaPlan.Rooms` の意味は最初の段で違い、廃墟では建物、森では空き地である。`debris` や `treeSteps` はその意味を前提にする。全ての間取りの行を複数の seed で計画し、つながった地図になることをテストで確かめる。
- 段の順と式を今のままにするので、乱数の消費は変わらない。地図のスナップショットで確かめる。
