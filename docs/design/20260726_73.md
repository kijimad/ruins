# 分解システム —— 配置物とアイテムを工具で解体して素材を得る

## 背景

スカベンジングの中核要素として、配置物 prop とアイテムを分解して複数の素材アイテムを得る仕組みを
入れる。design.md は兵站運用の第二軸に「重量・運搬・取捨・**分解**」を挙げており、doc 72 は物づくりを
「リーダー自身が行う合成・調合」に限ると定めた。分解はその隣に立つ**リーダーの野外の動詞**であり、
重い配置物を持ち帰れない代わりにその場で素材へ崩す、という兵站判断を作る。

## 要件

- 配置物とアイテムを分解して、複数のアイテムを手に入れる
- 分解は複数ターンかかる継続行為である
- スキルが上がるほど必要なターンコストが減り、入手アイテムが増える
- 分解には対応する工具アイテムが必要で、工具によって分解できる対象が異なる
- 工具のグレードが高いほど必要なターンコストが減り、入手アイテムが増える
- NPC 接触面: **隊員は分解に触れない**。リーダー専用の動詞とする。doc 72 の宣言規約に従う
- 帯リベース接触面: 分解 activity は対象をエンティティ参照で持ち、座標を持たない。対象が帯の
  シフトで破棄された場合は activity を中断終了する

## 設計

### 複数ターン経過の実装 —— 既存 activity 基盤に載せる

新しい時間機構は作らない。`internal/activity` の継続実行の枠組みが、必要なものを全て持っている。

- `Info.TotalRequiredAP` に分解の総工数を入れ、毎ターン `ActionPointCost` ずつ積む。100AP が
  標準1ターンなので、総工数 300AP は約3ターンの作業になる
- `Interruptible: true / Resumable: true`。敵の出現や割り込みで中断しても進捗は保持され、再開できる。
  安全確認は継続 activity 共通の既存機構が担う
- 進捗表示は `GetProgressPercent` の既存機能をそのまま使う
- 先例は読書 `ReadActivity`。総工数を消化して完了時に効果とスキル成長を発火する構造をそのまま踏襲する

```go
// DisassembleActivity は対象を工具で解体する継続 activity。
type DisassembleActivity struct {
	Target ecs.Entity // 分解対象。prop またはインベントリ内アイテム
	Tool   ecs.Entity // 使用する工具
}
```

### データ定義 —— raw で宣言する

分解できるかどうか・何が出るかは raw の宣言で決まる。コードは解釈するだけにする。

```toml
# 分解される側。prop と item の両方に同じ形で持たせる
[[props]]
name = "スチール棚"
# ...既存フィールド...

[props.disassembly]
toolCategory = "prying"  # 必要な工具分類。この分類の工具を所持していないと分解できない
baseAP = 300             # 基礎工数。100AP が標準1ターン

[[props.disassembly.yields]]      # 確定枠。必ず出る
name = "鉄くず"
amount = "1d2+1"

[[props.disassembly.yields]]      # 確率枠。chance は百分率
name = "ネジ"
amount = "1d3"
chance = 60

[[props.disassembly.bonus]]       # ボーナス枠。条件を満たすと産出に加わる
name = "鉄板"
amount = "1"
minSkill = 10                     # 機械スキルがこの値以上
```

```toml
# 分解する側の工具。カテゴリの対応とグレードを持つ
[[items]]
name = "バール"
# ...既存フィールド...

[items.disassemblyTool]
categories = ["prying"]  # 対応する工具分類。複数可
grade = 1                # 1..3。高いほど速く、多く得る
```

工具分類の初期語彙は3つに絞る。こじ開け prying、精密 precision、切断 cutting。木製家具・棚は
prying、電子機器・機械は precision、金属大物は cutting。対象と工具の対応は raw の宣言だけで
拡張できる。

### 工数と産出の式

スキルは既存の**機械 SkillMechanic** を分解の統括スキルとする。数値は初期値で、調整を前提とする。

```
必要工数 requiredAP = ceil(baseAP × skillFactor × gradeFactor)
  skillFactor = max(0.5, 1 - 機械スキル値 × 0.01)   # スキル50で下限の半減
  gradeFactor = {1: 1.0, 2: 0.8, 3: 0.6}

産出:
  確定枠  そのまま出す
  確率枠  chance' = min(100, chance + 機械スキル値 + (grade - 1) × 10)
  ボーナス枠 minSkill / minGrade の条件を満たしたものを確定で出す
```

- 完了時に `skill.GainExp` で機械スキルへ経験値を入れる。武器攻撃・読書に続く3例目で、同じ型の
  横展開になる。機械スキルの説明文の獲得条件も更新する
- 産出個数は既存の `Dice` 表記を使い、抽選は他の戦闘・生成と同じくラン中の乱数でよい

### 対象と入口

**prop の分解**。隣接した prop への相互作用に `InteractionDisassemble` を追加する。既存の
`InteractionKind` は文字列 enum で、`ExecuteInteraction` の分岐に1ケース足すだけでよい。

- 開始条件: 対応分類の工具を所持していること。無ければ「工具が無い」と名前のある失敗をログに出す
- 完了時: prop エンティティを消し、産出を**足元にドロップ**する。拾うかどうかは既存の Pickup と
  重量制約に任せ、拾捨の判断を兵站に残す
- 対象 prop が activity 中に消えた場合、帯シフトによる破棄を含め、activity を中断終了する

**アイテムの分解**。インベントリ画面から対象を選んで開始する。産出はインベントリへ加算し、
重量超過は既存の移動ペナルティに任せる。

### 攻撃破壊との関係

序盤は工具を持っていないため、破壊が唯一の入手手段になる時期がある。破壊にも**少量の産出**を
持たせ、対比を「速いが少ない」対「工具と時間を要するが多い」にする。

- 破壊で prop が壊れたとき、分解定義の**確定枠だけ**を破壊回収率で抽選して足元に落とす。
  初期値 30%。確率枠・ボーナス枠は出さない
- 新しい authoring は不要で、分解定義を持つ prop がそのまま破壊でも少量を落とす。分解定義の
  無い prop は従来どおり何も出さない
- 工具の入手は「同じ棚から数倍取れるようになる」成長として体感され、破壊は工具を手に入れる
  までのブートストラップになる

### 提示

- 開始・完了・ボーナス産出・スキル上昇をそれぞれログ1行で出す。「バールで棚をこじ開け始めた」
  「鉄板を回収した。機械が伸びた」
- 進捗はアクティビティ共通の進捗率表示を使う

## 採用しなかった方法

- **即時実行の gameaction にする** —— 合成と同じ型で最小工数だが、複数ターンかかる緊張が要件の核。
  継続 activity の基盤は完備しており、載せるだけで中断・再開・進捗表示まで揃う
- **実時間・tick ベースの進行** —— ターン制の外に時間機構を作らない。工数は AP で表す
- **工具の耐久消耗** —— 将来の拡張余地として残す。まずは所持判定のみで始める
- **カテゴリ別の分解スキル** —— 木工・電子・金属と分けるとスキル語彙が増える。機械1本に統括し、
  対象差は工具分類と産出テーブルで表す
- **隊員による分解** —— doc 72 のとおり隊員は戦闘の仲間であり、労働の語彙を持たせない
- **破壊で分解と同等の産出を出す** —— 工具と時間の意味が消える。破壊は確定枠の少量回収に留め、
  分解との差を保つ

## コメント

- 分解は doc 72 が確定した「リーダー自身が行う物づくり」の入口側にあたる。合成が素材→完成品なら、
  分解は配置物→素材で、既存の合成レシピの材料供給源になる
- 産出テーブルの authoring は raw 宣言のみで拡張できる。初期実装では分解可能な prop を数種に絞り、
  手応えを見てから広げる
