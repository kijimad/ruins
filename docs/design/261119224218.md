# 灯りに残量、武器と道具に摩耗を持たせて有限にする

## 背景

灯りと武器と道具は、一度手に入れると無限に使える。

- 灯りは松明 `torch` と、キューブに置くランタン `deployable_lamp` の2つだけで、どちらも消えない。装備した光源は `StatsChanged` のたびにプレイヤーの `LightSource` へ写すだけで、減るものが無い。`internal/systems/stats_changed.go:86`
- 道具は武器の行に `tool` の分類とグレードを持つ。合う道具を構えて置物を殴るとダメージが `1+グレード` 倍になり、壊すと産出が増える。`internal/activity/salvage.go:38`。使っても減らない。

寒く暗い惑星で廃墟を漁るゲームなので、灯りと道具が尽きることを、拾い集める理由と判断の材料にしたい。灯りは種類ごとに性能を変え、選ぶ意味を持たせる。

## 要件

- 灯りは使うと残量が減り、尽きると消える。
  - 使い切りの灯りは、尽きると無くなる。松明が例。
  - 補充できる灯りは、尽きても物は残り、燃料を足すとまた点く。ランタンが例。
- 灯りは種類ごとに性能が違う。照らす半径、色、残量の上限、1ターンに減る量。
- 武器と道具は使うと摩耗が進み、限度に達すると壊れて無くなる。敵を殴っても、撃っても、道具として置物を殴っても進む。
- 残量と摩耗は、一覧では段階、アイテムの詳細では数字で見える。
- 値はすべて raw の行で決め、新しい灯りや道具は行を足すだけで作れる。

## 設計

### 用語

| 用語 | Go | 意味 |
|---|---|---|
| 残量 | `Charge` | 灯りがあと何ターン点くか。燃料の油も電池も同じ語で扱う。英語の表示は Charge |
| 摩耗 | `Attrition` | 武器と道具を使い手として使うほど進む。限度に達すると壊れる。英語の表示は Attrition。装備の `Wearable` と読み違えないよう、Wear は使わない |
| 耐久 | `HP` 既存 | フィールドにある物が攻撃されると減る。置物の `HP` で、調べる画面の表示は Durability。この設計では変えない |

摩耗と耐久は、減るきっかけが逆なので別のデータにする。耐久は攻撃「される」側の値で、摩耗は使う「主体」として使う側の値である。語も、使うほど進む「摩耗」と、攻撃に耐える「耐久」で分ける。同じ実体が両方を持つことになっても、互いに影響しない。

「燃料値」は、油と電池の両方に当てはまる「残量」にする。キューブの `FuelTank` は熱量 `consts.Heat` を単位に持ち、可燃物をくべて満たす別の仕組みなので、名前を分ける。

### データ

raw に2つの欄を足す。`#LightSource` はアイテムのほか、キューブに置く設備 `#Deployable` と、光る敵 `#Member` も使う。敵の内蔵光源は減らさないので、残量は省ける欄にして、持つ灯りだけが消耗する。

```cue
// 光源設定。charge を省いた光源は減らない
#LightSource: {
	radius!:  #LightRadius
	color!:   #RGBAColor
	enabled!: #LightEnabled
	charge?:  #LightCharge
}

// 灯りの残量。refill を省くと使い切りで、尽きると無くなる
#LightCharge: {
	max!:    #ChargeTurns   // 残量の上限。ターン数
	drain!:  #ChargeTurns   // 点いている1ターンに減る残量
	refill?: #EntityID      // 残量を満たす燃料のアイテム
}

// アイテムの摩耗の限度。近接武器・遠隔武器・道具は必ず持つ。使うたびに摩耗が1進み、限度で壊れて無くなる
#Item: {
	// 既存の欄は省略
	attritionLimit?: #AttritionLimit
	if melee != _|_ {attritionLimit!: #AttritionLimit}
	if fire != _|_ {attritionLimit!: #AttritionLimit}
	if tool != _|_ {attritionLimit!: #AttritionLimit}
}
```

Go のコンポーネントは2つ足す。どちらもアイテム1個ごとに持ち、セーブに載る。

```go
// Charge は灯りの残量。Current が0になると灯りは消える。Drain は点いている1ターンに減る量で、
// 生成時に raw から写す。減らすシステムが raw を引かずに済み、テストで値を直に組める
type Charge struct {
	Pool[consts.Turn]
	Drain consts.Turn
}

// Attrition は武器と道具の摩耗。Current は0から使うたびに増え、Max に達すると壊れる。
// 直す仕組みは Current を下げるだけで足せる。攻撃されて減る HP とは別のデータ
type Attrition Pool[int]
```

`LightSource` は今の形のまま、照らす半径と色と点灯を持つ。補充の燃料は補充するときだけ raw の行から引く。

```go
// 変えない
type LightSource struct {
	Radius  consts.Tile
	Color   color.RGBA
	Enabled bool
}
```

### 灯りの減り方

- 装備している灯りと、キューブの展開空間に置いた灯りが、点いている間だけ毎ターン `Drain` ずつ減る。背負っているだけの灯りは減らない。
- `charge` を持たない光源は減らない。敵の内蔵光源はこちら。
- プレイヤーの居ないステージの灯りは減らない。走査は `query.ActiveFilter` を使い、退避中のステージを外す。ダンジョンに潜っている間、キューブに置いたランタンは減らない。
- 減らすのは新しいシステム `LightChargeSystem` で、ターンの終わりに走る。`InitializeSystems` とターン終わりの実行の一覧の両方に登録する。一覧では `FireSystem` の後、`DeadCleanupSystem` の前に置き、同じターンのうちに灯りの写し直しと視界の再計算が反映されるようにする。
- 灯りが点いているかは、`LightSource.Enabled` が true で、`Charge` を持つなら残量が0より多いこと、で決める。この判定を `query.LightLit` の1か所に置き、視界の計算と装備の灯りを写す処理の両方がこれを通る。残量が尽きても `Enabled` は書き換えないので、点いているかの真実は残量の1つだけになる。
- 残量が0になったら:
  - `refill` を持たない灯りは、アイテムを消す。松明は燃え尽きる。
  - `refill` を持つ灯りは、物を残す。残量0なので `query.LightLit` が false になり消える。
  - どちらも、持ち主がプレイヤーならログを出し、`StatsChanged` を付けて灯りを写し直す。
- 補充は、灯りに「燃料を足す」動詞で行う。`refill` のアイテムを1つ消費して残量を上限まで戻す。

### 灯りの種類

性能を変えて、選ぶ意味を持たせる。1日は 1500 ターン。

| 灯り | 半径 | 色 | 残量 | 1ターンの減り | 補充 | 役割 |
|---|---|---|---|---|---|---|
| 松明 `torch` | 6 | 暖色 | 600 | 1 | 無し、使い切り | 安く広く照らす。火種も兼ねる |
| 手提げランタン `hand_lantern` 新規 | 5 | 暖色 | 1500 | 1 | 灯油 `lamp_oil` 新規 | 長持ちし、油で何度も使える |
| 懐中電灯 `flashlight` 新規 | 8 | 白 | 1000 | 1 | 電池 `battery` 新規 | 最も遠くまで照らすが、電池は貴重 |
| キャンプランタン `deployable_lamp` | 4 | 暖色 | 3000 | 1 | 灯油 `lamp_oil` | キューブに置く。半日以上もつ |

- 既存の `scrap_battery` は使い切った電池で、売るだけのガラクタとして残す。懐中電灯には新しく足す使える電池 `battery` を使う。
- 松明は `melee` を持つので、残量と摩耗の両方が付く。燃え尽きても、振り続けて壊れても無くなる。どちらか先に来た方で消えるのを仕様とする。
- 着火に使った火種が残量を持つなら、残量を固定で 30 減らす。火種は装備しているものを先に、無ければ背負っているものから、残量の多いものを選ぶ。`executeIgnite` が使った火種を選んで減らす。

### 武器と道具の摩耗

- 摩耗は、振った回数と撃った発数で進む。近接攻撃も射撃も、1回の行動で `AttackCount` 回の当てる試行を行うので、試行1回ごとに1進む。外れても進む。連撃の武器は速く擦り減るので、行の `attritionLimit` で釣り合わせる。
- 進める場所は `applyAttackDamage` の1か所にする。近接 `attack.go` と射撃 `shoot.go` の両方がここを通り、道具として置物を殴るときも同じ経路になる。素手や敵の内蔵攻撃は武器のアイテムを持たないので、使った武器がアイテムの実体で `Attrition` を持つときだけ進める。殴られた置物の側は、これまでどおり耐久 `HP` が減る。
- 遠隔武器は再装填では進まない。弾薬が尽きるのとは別に、銃そのものも擦り減る。
- 限度に達したら武器を消し、持ち主がプレイヤーならログを出す。構えていた武器が消えたら素手に戻る。
- 近接攻撃・遠隔攻撃・道具の行はすべて `attritionLimit` を持つ。CUE で必須にし、摩耗しない武器は作らない。
- 限度は武器ごとに行で決める。近接の目安は素材の弱い武器で 80、普通で 150、頑丈な武器や道具のグレード3で 250 回。遠隔は撃つ回数が弾薬で限られるので、近接より多めにし、目安は 300〜600 発。
- 壊れた武器や道具を直す仕組みは、この設計では作らない。将来、工作台で直す余地を残し、`Attrition` は限度と現在の摩耗を持つ形にしておく。

### 表示

一覧ではひと目で分かる段階を、詳細では正確な数を見せる。CDDA も、名前の横に傷みの段階を記号と色で出し、数は詳しい説明に回している。

| 場所 | 摩耗 | 残量 |
|---|---|---|
| 一覧の名前の横 | 5段階の短いバー。緑から黄、赤へ変わる | 同じ形のバー。点いている灯りには点灯の印を添える |
| アイテムの詳細 `entityspec` | `摩耗 37 / 150` | `残量 420 / 600 ターン` |
| ログ | 段階が変わったときだけ出す。例「つるはしが傷んできた」 | 残りが少なくなったときだけ出す。例「松明が燃え尽きかけている」 |

- バーは「長いほど良い」にそろえる。摩耗はデータとしては進む値だが、バーには限度までの残りを描く。残量はそのまま描く。どちらも長いほど良いと読め、向きを取り違えない。
- 割合の数字は一覧に出さない。摩耗は増えるほど悪く、残量は減るほど悪いので、数字のままだと良し悪しの向きを毎回考えることになる。
- バーの段階とログの段階は同じ境目を使う。限度までの残りが 80%・60%・40%・20% を割るたびに1段下がる。

## 採用しなかった方法

- **残量をコンポーネント `LightSource` に持たせる**: 灯りの性能と消耗が1つの型に混ざり、敵の内蔵光源にも消耗の欄が付く。raw では `#LightSource` の中に省ける欄として書き、Go では消耗する物だけが `Charge` を持つ形にする。
- **キューブの `FuelTank` を灯りにも使う**: 単位が熱量で、可燃物をくべて満たす仕組み。灯りは決まった燃料で満たすので、使い方が違う。
- **摩耗を耐久 `HP` で持つ**: `HP` は攻撃されて減る値で、攻撃の対象の判定にも使う。使う側の消耗と攻撃される側の消耗はきっかけが逆なので、別のデータにする。武器を殴れるものと誤って扱うことも防ぐ。
- **使う側の値も「耐久」と呼ぶ**: 置物の耐久と同じ語になり、どちらの話か取り違える。使うほど進む「摩耗」と呼び分ける。
- **英語の名前を Wear にする**: 装備の `Wearable` が多くの箇所で使われ、「着る」と読み違える。コードに使われていない Attrition にする。
- **道具として置物に使ったときだけ摩耗させる**: 範囲は小さいが、敵を殴る武器は無限に使えるままになる。作者の判断で、敵を殴っても摩耗させる。
- **遠隔武器には摩耗を持たせない**: 弾薬で既に有限なので省ける。作者の判断で、銃そのものも擦り減るようにする。
- **残量が尽きたら `LightSource.Enabled` を false にする**: 読む側を変えずに済むが、点いているかを `Enabled` と残量の2つで表すことになり、片方だけ書き換えるとずれる。判定を `query.LightLit` の1か所に置き、真実を残量の1つにする。
- **`Drain` を毎ターン raw から引く**: 灯りは数個で性能の問題は無いが、システムが raw に依存し、テストで値を直に組めない。生成時に `Charge` へ写す。
- **一覧に割合の数字を出す**: 摩耗と残量で良し悪しの向きが逆になり、読み違える。
- **CDDA と同じく `||` のような文字の記号で段階を出す**: 記号の意味を覚える必要がある。バーなら長さで読める。
- **言葉の段階を名前に添える**: 新品・傷んだ・壊れかけのような語で分かりやすいが、日本語の名前が長くなる。ログで同じ語を使う。
- **灯りを手で点け消しする**: 残量の節約にはなるが、操作が増える。まずは装備したら点き、外したら消える形にする。

## コメント

作者と決めたこと。

- 敵を殴っても武器の摩耗を進める。遠隔武器も撃つたびに摩耗する。
- 壊れた武器や道具を直す仕組みは、将来作る可能性がある。この設計では作らず、`Attrition` を限度と現在の摩耗で持って余地を残す。
- 灯りの燃料の値は「残量」と呼ぶ。
- 使う側の消耗は「摩耗 `Attrition`」、攻撃される側の消耗は既存の「耐久 `HP`」とし、データも語も分ける。
- 一覧は5段階のバー、詳細は正確な数で見せる。
