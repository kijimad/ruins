# 灯りと武器と道具に残量を持たせて有限にする

## 背景

灯りと武器と道具は、一度手に入れると無限に使える。

- 灯りは松明 `torch` と、キューブに置くランタン `deployable_lamp` の2つだけで、どちらも消えない。装備した光源は `StatsChanged` のたびにプレイヤーの `LightSource` へ写すだけで、減るものが無い。`internal/systems/stats_changed.go:86`
- 道具は武器の行に `tool` の分類とグレードを持つ。合う道具を構えて置物を殴るとダメージが `1+グレード` 倍になり、壊すと産出が増える。`internal/activity/salvage.go:38`。使っても減らない。

寒く暗い惑星で廃墟を漁るゲームなので、灯りと武器と道具が尽きることを、拾い集める理由と判断の材料にしたい。灯りは種類ごとに性能を変え、選ぶ意味を持たせる。

## 要件

- 灯りと武器と道具は、使うと残量が減り、0で尽きる。
  - 灯りは、点いている間に毎ターン減る。
  - 武器と道具は、振るか撃つたびに減る。敵を殴っても、撃っても、道具として置物を殴っても減る。
- 尽きたときの扱いは2つ。
  - 補充できない物は、尽きると無くなる。松明と武器と道具が例。
  - 補充できる物は、尽きても物は残り、燃料を足すとまた使える。ランタンが例。
- 灯りは種類ごとに性能が違う。照らす半径、色、残量の上限、1ターンに減る量。
- 残量は、一覧では段階、アイテムの詳細では数字で見える。
- 値はすべて raw の行で決め、新しい灯りや武器は行を足すだけで作れる。

## 設計

### 用語

| 用語 | Go | 意味 |
|---|---|---|
| 残量 | `Charge` | 灯りや武器や道具を、あとどれだけ使えるか。使うと減り、0で尽きる。英語の表示は Charge |
| 耐久 | `HP` 既存 | フィールドにある物が攻撃されると減る。置物の `HP` で、調べる画面の表示は Durability。この設計では変えない |

残量と耐久は、減るきっかけが逆なので別のデータにする。耐久は攻撃「される」側の値で、残量は使う「主体」として使う側の値である。

灯りの残量と武器の残量は、同じデータにする。違うのは減るきっかけと点け消しの有無だけで、値の形は「上限と現在値」で同じだからである。

| 物 | 減るきっかけ | 1回に減る量 | 点け消し |
|---|---|---|---|
| 灯り | 点いている1ターンごと | 行の `drain` | 有る。点いている間だけ減る |
| 武器と道具 | 攻撃の行動1回ごと | 行の `drain` | 無い |

### データ

raw のアイテムの行に、残量の欄を1つ足す。灯りの性能を表す `#LightSource` は変えない。`#LightSource` はキューブに置く設備 `#Deployable` と、光る敵 `#Member` も使うが、残量はアイテムの行に置くので、敵の内蔵光源は残量を持たず減らない。

```cue
// アイテムの残量。灯りは点いている間に、武器と道具は使うたびに drain ずつ減り、0で尽きる。
// refill を省くと使い切りで、尽きると無くなる
#Charge: {
	max!:    #ChargeAmount  // 残量の上限。灯りはターン数、武器と道具は回数
	drain!:  #ChargeAmount  // 1回に減る量
	refill?: #EntityID      // 残量を満たす燃料のアイテム
}

#Item: {
	// 既存の欄は省略
	charge?: #Charge
	// 生来の攻撃の印。素手や噛みつきのように、拾える物でなく体に備わった攻撃の行に付ける
	innate?: true
}
```

`lightSource`・`deployable.lightSource`・`melee`・`fire`・`tool` のどれかを持つアイテムの行は、`innate` を持たない限り `charge` を必ず持つ。素手 `bare_hands` や敵の噛みつきのような生来の攻撃も `melee` を持つアイテムの行なので、`innate` で外す。敵が使う攻撃の行には、包丁 `cleaver` のように拾える道具と同じ行もあるので、敵の攻撃表に載るかどうかでは見分けられない。`innate` の行は `charge` を持てない。キューブに置く設備の灯りは `deployable.lightSource` に光源を持つので、規則に含めないとランタンだけ検査を抜ける。複数の欄を見る条件なので、CUE でなく `raw.validateRules` に置く。

減るきっかけはアイテムの実体が持つコンポーネントから決まる。`gc.LightSource` を持てば点いている間に減り、持たなければ使うたびに減る。raw の `lightSource` と `deployable.lightSource` はどちらも `gc.LightSource` になるので、2つの欄の違いはここで吸収される。松明は `lightSource` と `melee` の両方を持つが、灯りとして点いている間に減り、振っても減らない。消耗の値を1つにして、何で尽きるかを迷わせない。

Go のコンポーネントは1つ足す。アイテム1個ごとに持ち、セーブに載る。

```go
// Charge はアイテムの残量。灯りは点いている間に、武器と道具は使うたびに Drain ずつ減り、
// Current が0で尽きる。Drain は生成時に raw から写し、減らす処理が raw を引かずに済むようにする。
// 直す仕組みは Current を戻すだけで足せる。攻撃されて減る HP とは別のデータ。
// Max と Drain は生成時に写すので、raw を調整しても生成済みの実体には効かない
type Charge struct {
	Pool[int]
	Drain int
}
```

`LightSource` は今の形のまま、照らす半径と色と点灯を持つ。補充の燃料は補充するときだけ raw の行から引く。

`Max` は、将来の修理で上限を変える余地として実体に持つ。`Drain` は、減らす処理が raw を引かずに済み、テストで値を直に組めるように写す。どちらも生成時の値で固まるので、raw を調整しても、生成済みやセーブ済みの物は古い値のままになる。未リリースなので受け入れる。

### 灯りの減り方

- **照らすなら減る。** `query.LightLit` は「照らしているか」の判定で、置き場所も含めて決める。照らしているのは、`GridElement` を持つ物と、プレイヤーの装備の欄 `LocationEquipped` にある物だけで、背負っている物は照らさない。装備の灯りをその場に写すのはプレイヤーだけなので、`StatsChangedSystem` と同じくプレイヤーの装備に絞る。敵が灯りを装備しても照らさず、減らない。`query.LightLit` が true で `Charge` を持つ物は、毎ターン `Drain` ずつ減る。装備している灯りも、キューブの展開空間に置いた灯りも、床に落とした灯りも同じ規則で減る。照らす物と減る物が必ず一致するので、落とした松明が減らずに照らし続ける抜け穴が無い。光る物を今後足すときも、この規則から漏れない。
- 背負っているだけの灯りは照らさないので減らない。
- 眠っている間も、装備の灯りは照らし続けて減る。点け消しの操作は作らないので、寝る前に外すかを選ぶ判断になる。眠り始めるときに点いている装備の灯りがあれば、ログで知らせる。
- プレイヤーの居ないステージの灯りは減らない。走査は `query.ActiveFilter` を使い、退避中のステージを外す。ダンジョンに潜っている間、キューブに置いたランタンは減らない。
- 減らすのは新しいシステム `LightChargeSystem` で、ターンの終わりに走る。`InitializeSystems` とターン終わりの実行の一覧の両方に登録する。一覧では `FireSystem` の後、`DeadCleanupSystem` の前に置き、同じターンのうちに灯りの写し直しと視界の再計算が反映されるようにする。
- `query.LightLit` は、置き場所が照らせる所で、`LightSource.Enabled` が true で、`Charge` を持つなら残量が0より多いこと、で true になる。この判定を1か所に置き、視界の計算と装備の灯りを写す処理と `LightChargeSystem` がすべてこれを通る。視界の計算と装備の灯りを写す処理は、今も自分で置き場所を絞っているので、置き場所の条件は重なるが、3つが同じ判定を通ることを優先する。残量が尽きても `Enabled` は書き換えないので、点いているかの真実は残量の1つだけになる。
- 装備の灯りを写したプレイヤー自身の `LightSource` と、光る敵の内蔵光源は `Charge` を持たないので、照らしても減らない。減るのは灯りのアイテムの実体だけである。
- 残量が0になったら:
  - `refill` を持たない灯りは、アイテムを消す。松明は燃え尽きる。消すときは既存の lifecycle の削除の経路を通し、装備の欄から外れることと、総重量の再計算と `StatsChanged` が漏れないようにする。
  - `refill` を持つ灯りは、物を残す。残量0なので `query.LightLit` が false になり消える。
  - どちらも、持ち主がプレイヤーならログを出し、`StatsChanged` を付けて灯りを写し直す。
- 補充は、灯りに「燃料を足す」動詞で行う。`refill` のアイテムを1つ消費して残量を上限まで戻す。

### 灯りの種類

性能を変えて、選ぶ意味を持たせる。1日は 1500 ターン。

| 灯り | 半径 | 色 | 残量 | 1ターンの減り | 補充 | 役割 |
|---|---|---|---|---|---|---|
| 松明 `torch` | 6 | 暖色 | 600 | 1 | 無し、使い切り | 安く広く照らす。火種も兼ねる |
| 手提げランタン `hand_lantern` 新規 | 5 | 暖色 | 1500 | 1 | 灯油 `lamp_oil` 新規 | 長持ちし、油で何度も使える |
| 懐中電灯 `flashlight` 新規 | 8 | 白 | 1000 | 1 | 電池 `battery` 新規 | 最も遠くまで照らすが、電池は貴重 |
| キャンプランタン `deployable_lamp` | 4 | 暖色 | 3000 | 1 | 灯油 `lamp_oil` | キューブに置く。半日以上もつ |

- 既存の `scrap_battery` は使い切った電池で、売るだけのガラクタとして残す。懐中電灯には新しく足す使える電池 `battery` を使う。
- 着火に使った火種が残量を持つなら、残量を固定で 30 減らす。火種は、残量を持たない物を先に、次に背負っている物、最後に装備している物から選ぶ。同じ順位なら残量の多い物を選ぶ。点いている装備の松明を削らずに済むよう、照らしていない物から使う。ライターのような残量を持たない火種を今後足せば、それが最初に選ばれる。`executeIgnite(target, world)` は着火する主体を受け取らないので、署名に actor を足す。火種を選ぶ処理は `query.HoldsFireStarter` の隣に、火種を返す関数として置き、所持の判定と選択を同じ所にそろえる。

### 武器と道具の減り方

- 近接攻撃も射撃も、攻撃の行動1回ごとに `Drain` ずつ減る。外れても減る。今のコードは1回の行動で `applyAttackDamage` を1回だけ呼び、`AttackCount` は表示にしか使っていないので、行動1回と当てる試行1回は同じになる。
- 本来の用途以外に使うと、倍の量が減る。倍率は固定の 2 で、`attack.go` の定数に置く。行ごとに変える理由が無いので raw には持たせない。置物を壊すか敵を攻撃するかは、攻撃の対象が `gc.Prop` を持つかで決める。キューブの展開空間に置いた設備も `Prop` を持つので、置物として扱う。

  | 使う物 | 敵を攻撃する | 置物を壊す |
  |---|---|---|
  | `tool` を持つ物。つるはし・斧など | 2 倍 | 1 倍 |
  | `tool` を持たない武器。剣・銃など | 1 倍 | 2 倍 |

  つるはしは置物を壊すため、剣は戦うため、という使い分けが生まれる。Minecraft も、斧やつるはしで敵を叩くと、剣でブロックを壊すと、それぞれ2回分減らしている。
- 減らす場所は `applyAttackDamage` の1か所にする。関数の先頭で `defer` に減らす処理を積み、`dropSalvage` が error で早く戻った場合も含めて、外れて早く戻る分岐でも、当たって `growWeaponSkill`・`dropSalvage`・`applyInjury` を終えた後でも、最後に1回走るようにする。最後の1回で武器を先に消すと、`dropSalvage` が道具のグレードの産出の上乗せを付けられず、消えた武器の `Melee`・`Fire` を読むことにもなるので、必ず最後に減らす。振った事実は変わらないので、途中の error でも減らす。`defer` の中の削除や弾の戻しの error は、名前付きの戻り値へ `errors.Join` で合わせて返し、握りつぶさない。近接 `attack.go` と射撃 `shoot.go` の両方がここを通り、道具として置物を殴るときも同じ経路になる。`applyAttackDamage` は今 `Melee` や `Fire` の値だけを受け取り、武器の実体を知らない。そこで `getAttackParams` と `getEquippedFire` が武器の実体も返し、`applyAttackDamage` の引数で渡す。素手や敵の内蔵攻撃は武器のアイテムを持たないので `gc.InvalidEntity` を渡し、何も減らさない。減らすのは、渡された武器が `gc.LightSource` を持たず `Charge` を持つときだけで、松明で殴っても減らない。殴られた置物の側は、これまでどおり耐久 `HP` が減る。
- 遠隔武器は再装填では減らない。弾薬が尽きるのとは別に、銃そのものも擦り減る。
- 銃が尽きて消えるとき、弾倉に残った弾は持ち主のバックパックへ弾薬のアイテムとして戻す。撃った弾は `shoot.go` が弾倉から先に減らしているので、残りの数をそのまま戻せばよい。
- 0になったら武器を消し、持ち主がプレイヤーならログを出す。構えていた武器が消えたら素手に戻る。消すときは、灯りと同じく既存の lifecycle の削除の経路を通す。
- 武器と道具は補充できない。`refill` を持つ武器の行は `raw.validateRules` で落とす。
- 上限は行で決める。`drain` は1。近接の目安は素材の弱い武器で 80、普通で 150、頑丈な武器や道具のグレード3で 250 回。遠隔は撃つ回数が弾薬で限られるので近接より多めにし、目安は 300〜600 発。
- 壊れた武器や道具を直す仕組みは、この設計では作らない。将来、工作台で直す余地を残し、`Charge` は上限と現在値を持つ形にしておく。

### 表示

一覧ではひと目で分かる段階を、詳細では正確な数を見せる。CDDA も、名前の横に傷みの段階を記号と色で出し、数は詳しい説明に回している。

| 場所 | 表示 |
|---|---|
| 一覧の名前の横 | 5段階の短いバー。緑から黄、赤へ変わる。点いている灯りには点灯の印を添える |
| アイテムの詳細 `entityspec` | 灯りは `残量 420 / 600 ターン`、武器と道具は `残量 120 / 150 回` |
| ログ | 段階が下がったときだけ出す。例「つるはしが傷んできた」「松明が燃え尽きかけている」 |

- 残量は減るほど悪い向きの1つの値なので、バーは長いほど良い。割合の数字は一覧に出さない。
- バーの段階とログの段階は同じ境目を使う。上限に対する残量が 80%・60%・40%・20% を割るたびに1段下がる。
- ログの文は、灯りか武器かで言い回しを変える。
- 段階は保存しない。減らす前と後の残量からそれぞれ段階を出し、違えばログを出す。状態を増やさずに済む。上限が小さい行では1回で2段下がることがあるが、ログは下がった後の段階で1行だけ出す。
- 床に落とした松明は1本ずつ毎ターン減るので、拾うとすべて別の行になる。一覧の行は増えるが、それぞれの残量が見えるので、仕様として受け入れる。
- 残量の違う同じ品は、別のスタックに分ける。`query.StackKeyOf` のキーに残量の現在値を足す。装備の指紋が生値で個体を分けているのと同じ考え方で、使いかけの物はそれぞれ別の行になり、バーが1つの値を正しく見せる。
- 売値は残量で下げない。値段の計算を増やさず、使いかけでも売れる。

## 採用しなかった方法

- **灯りの残量と武器の摩耗を別のデータにする**: 値の形はどちらも上限と現在値で同じで、違うのは減るきっかけと点け消しだけ。作者の判断で1つにまとめ、きっかけはアイテムが持つ欄から決める。
- **値の向きを「摩耗が進む」にする**: 灯りは残りが減る向きが自然で、2つの向きが混ざると表示で取り違える。残量の1つの向きにそろえる。
- **減るきっかけを raw の欄で指定する**: `lightSource` を持つかどうかで決まるので、欄を足すと矛盾した行を書ける余地が生まれる。
- **残量を `#LightSource` の中に置く**: 武器も残量を持つので、灯りの欄に置くと武器に置き場が無い。アイテムの行に置く。
- **キューブの `FuelTank` を灯りにも使う**: 単位が熱量で、可燃物をくべて満たす仕組み。灯りは決まった燃料で満たすので、使い方が違う。
- **残量を耐久 `HP` で持つ**: `HP` は攻撃されて減る値で、攻撃の対象の判定にも使う。使う側の消耗と攻撃される側の消耗はきっかけが逆なので、別のデータにする。武器を殴れるものと誤って扱うことも防ぐ。
- **道具として置物に使ったときだけ減らす**: 範囲は小さいが、敵を殴る武器は無限に使えるままになる。作者の判断で、敵を殴っても減らす。
- **遠隔武器には残量を持たせない**: 弾薬で既に有限なので省ける。作者の判断で、銃そのものも擦り減るようにする。
- **残量が尽きたら `LightSource.Enabled` を false にする**: 読む側を変えずに済むが、点いているかを `Enabled` と残量の2つで表すことになり、片方だけ書き換えるとずれる。判定を `query.LightLit` の1か所に置き、真実を残量の1つにする。
- **`Drain` を毎ターン raw から引く**: 灯りは数個で性能の問題は無いが、システムが raw に依存し、テストで値を直に組めない。生成時に `Charge` へ写す。
- **一覧に割合の数字を出す**: 段階のバーのほうがひと目で分かる。数は詳細で見せる。
- **CDDA と同じく `||` のような文字の記号で段階を出す**: 記号の意味を覚える必要がある。バーなら長さで読める。
- **言葉の段階を名前に添える**: 新品・傷んだ・壊れかけのような語で分かりやすいが、日本語の名前が長くなる。ログで同じ語を使う。
- **素材で減り方を変える**: 木の武器は速く減るなど。上限 `max` を行ごとに決めるので、素材の違いはそこで表せる。
- **CDDA のように確率で減らす**: 当てるたびに確率で傷みが進む。運で寿命がぶれて読みにくく、テストも乱数の固定が要る。減る量は決まった値にする。
- **減らす灯りを装備とキューブに置いた物に限る**: 床に落とした灯りも照らすので、落とせば減らない灯りになる。照らす物すべてを減らす。
- **床に落ちた灯りは消す**: 落とした松明が消えるのは不自然で、場合分けも増える。
- **連撃の武器を試行の回数だけ減らす**: 今のコードは1回の行動で1回しか当てないので、`AttackCount` 回の試行は無い。連撃を作るのは別の設計にする。
- **呼び出し側の `performAttack` と `ShootBehavior.DoTurn` で減らす**: `applyAttackDamage` の署名を変えずに済むが、減らす所が2か所になる。
- **スタックのキーで残量を5段階に量子化する**: 行は減るが、同じ段階の中で減った物とそうでない物が混ざり、使う順が決まらない。
- **使いかけの物の売値を下げる**: 値段の計算が増える。
- **`query.LightLit` は置き場所を見ず、`LightChargeSystem` の走査だけを置き場所で絞る**: 判定の重なりは無くなるが、照らす物と減る物を決める条件が2か所に分かれ、ずれうる。
- **敵の攻撃表に載る行を `charge` の必須から外す**: 包丁のように、敵も使い拾える道具でもある行があり、見分けられない。
- **`charge` の必須を、生成表に載るなど拾える行に絞る**: 拾えるかは複数の表を辿らないと決まらず、検査が重くなる。行に印を書くほうが読める。
- **銃が壊れたら弾倉の弾も失う**: 単純だが、銃の寿命の終わりに弾まで失うのは罰が重い。
- **眠っている間は装備の灯りを照らさない**: 寝ても減らずに済むが、照らすかの判定が置き場所以外の状態に広がる。ログで知らせ、外すかをプレイヤーに任せる。
- **火種は装備している物を先に選ぶ**: 点いている松明が着火のたびに削れる。照らしていない物から使う。
- **灯りを手で点け消しする**: 残量の節約にはなるが、操作が増える。まずは装備したら点き、外したら消える形にする。

## コメント

作者と決めたこと。

- 敵を殴っても武器の残量を減らす。遠隔武器も撃つたびに減る。
- 壊れた武器や道具を直す仕組みは、将来作る可能性がある。この設計では作らず、`Charge` を上限と現在値で持って余地を残す。
- 灯りの残量と武器の摩耗は、データとしては同じ「残量 `Charge`」にする。違いは減るきっかけと点け消しの有無だけ。
- 使う側の消耗は「残量 `Charge`」、攻撃される側の消耗は既存の「耐久 `HP`」とし、データも語も分ける。
- 松明は灯りとして点いている間に減り、振っても減らない。
- 一覧は5段階のバー、詳細は正確な数で見せる。
- 本来の用途以外に使うと、倍の量が減る。
