# HPで気軽に戦い、部位の不調で緊張を足す: 怪我・病気・低体温ダメージと治療

## 背景

日常のささいな戦闘は HP が担う。通常のやり取りはすべて HP で行い、気軽に戦い、ゲームのテンポを保つ。HP はターン経過でゆっくり自然回復し、回復アイテムで即時に戻る。並の damage は時間が癒すか、急ぐなら回復アイテムで戻す。この生命ゲージはそのまま使う。

不調はその上に薄く載る例外だ。あくまで、たまに起きる状態異常として扱う。戦闘のたびに起きるものではなく、ときおり骨折や切り傷を負い、生活のなかで栄養不足や特定の行動から病気になり、寒さが続けば低体温で HP を削られる。手間にならない範囲でリアリティと緊張感を足すのが狙いで、日常戦闘の主役は HP、不調は稀に差し込まれる脇役という役割分担を保つ。不調は HP と違って勝手には戻らず、治療する必要があり、治療したうえでターン経過することで回復する。回復の速さは症状ごとにまちまちにする。

現状の土台:

- HP は単一プール `type HP Pool[int]`。ダメージは `gameaction.ApplyDamage` の1経路で削り、0 で `Dead` が付いて死亡する。
- HP の毎ターン自然回復は未実装。回復は休息アクティビティと回復アイテムの能動2経路だけ。
- 部位ごとの不調の枠は既にある。`HealthStatus.Parts[BodyPart].Conditions[]HealthCondition{Type, Severity, Timer, Effects}` という「部位ごとに複数の不調を持つ」構造と、付与・回復・タイマー・重症度導出の API 一式、`StatEffect` を6能力へ配線する `StatsChangedSystem` までが揃う。ただし実際に使われているのは全身の低体温だけだ。
- 低体温はデバフのみで、HP ダメージは無い。能力デバフと移動コストペナルティに効くだけで HP を削らない。

先行設計として、棚上げの doc `260821232324`「身体の不調」がこの機能に近い設計を持つ。ただしそれはバックログ整理で dropped にされただけで、設計が却下されたわけではない。本 doc はそれを土台にしつつ、2点で方針を変える。ひとつは怪我を専用の Wound 型でなく既存 HealthCondition に統一すること。もうひとつは治療を即時治癒でなく「治療してターン経過で回復」にすること。死の終端 `RunOutcome` を定める doc `260822014348` は既に done で、死因の受け皿は存在する。

## 要件

Hard は満たさねばならない、Soft は最大化したい、Anti は踏んではいけない罠。

**Hard**

- 日常のささいな戦闘は HP が担う。通常のやり取りは HP で行い、HP はターン経過でゆっくり自然回復し、回復アイテムで即時回復する。死は HP が0で訪れる。
- 不調はたまに起きる状態異常として扱う。戦闘のたびには起きず、稀に差し込まれる。日常戦闘の主役は HP で、不調はその上に薄く載る例外に留める。
- 不調は既存の HealthCondition に統一する。骨折・切り傷・病気・低体温を、部位に付く1つの condition として同じ枠で持つ。専用の Wound 型・出血・傷跡の層は持たない。
- 戦闘でたまに、命中した部位に怪我が付き、能力デバフになる。骨折・切り傷など。
- 低体温はデバフに加え、重症で毎ターン HP ダメージを与える。
- 生活のなかで栄養不足や特定の行動を契機に、たまに病気になり、部位に不調が付く。肝臓が悪くなるなど。
- 不調は治療を要し、治療したうえでターン経過で回復する。回復の速さは症状ごとに違う。
- 治療は手間にならない範囲にする。掠り傷まで治療を強いず、戦闘のたびの治療を routine にしない。

**Soft**

- 負った場所が読める。腕を負えば狙いが乱れ、脚を負えば動きが鈍る、が体感できる。
- 治療の判断が危機の局面で生まれる。死にかけたときに薬を切るか温存するかの決断になる。
- よく食べ休むほど HP と不調の回復が速い。食料が回復の動機になる。

**Anti**

- 部位ごとの耐久プールや機能算出の中間層を作らない。負傷は能力へ直接効かせる。
- 治療を療養ミニゲームにしない。全快の安全地帯を作らず、前進の合間に手当てする。
- 掠り傷まで治療を強いない。軽い不調は代謝で自然に癒えるようにし、手間を減らす。
- 不調を頻発させない。戦闘のたびに怪我を起こさず、発生確率を低く保つ。日常戦闘を状態異常の連続にしない。
- 病気を必ず出血させない。機能低下を主にする。

## 設計

### 全体方針: HP は据え置き、不調は既存の枠へ、治療は回復軌道への点火

生命ゲージの HP はそのまま残す。毎ターン HP を代謝ぶん自然回復させる新システムを足す。低体温の重症・致死性の病はこの HP を削る。

不調は既存の HealthCondition に種類を足して部位に付ける。骨折・切り傷・病気・低体温を同じ形で持ち、種類で振り分ける。種類ごとに「どう治るか」「毎ターンの HP ダメージ」「効果先の能力」を固定パラメータのカタログで定める。

治療は不調を即座には治さない。治療済みの印を立てて回復軌道へ乗せるだけで、実際の回復はターン経過で不調のタイマーが減って進む。回復の速さは症状ごとに違う。治療は身体まとめて1アクションで、重い不調から順に自動で配り、部位を選ばせない。

### ① HP リジェネ: 代謝で毎ターン自然回復

HP を毎ターン代謝ぶん回復させる。代謝は VIT と満腹度から出す派生値で、よく食べ休めば速く、飢えれば遅い。細かい内臓機能へは分解せず、1つの派生値に留める。

```go
// Metabolism は回復速度の係数。VIT と満腹度から出す派生値。
// HP の毎ターン自然回復量と、病気の免疫獲得速度を左右する
func Metabolism(world w.World, entity ecs.Entity) consts.Percent

// HealthRegenSystem は毎ターン HP を代謝ぶん自然回復させる。turn-end に登録する
type HealthRegenSystem struct{}
```

### ② 不調の種類とカタログ

既存の HealthCondition をそのまま使い、種類を足す。部位は `HealthStatus.Parts[BodyPart]` の添字で表し、condition に部位フィールドは足さない。回復のしかた・HP ダメージ・効果は、条件のインスタンスに持たせず種類ごとの固定パラメータとしてカタログで持つ。導出可能な固定値をインスタンスへ散らさないためだ。

```go
// 状態種類を足す。低体温は既存
const (
	ConditionHypothermia ConditionType = "Hypothermia"
	ConditionFracture    ConditionType = "Fracture"    // 骨折
	ConditionLaceration  ConditionType = "Laceration"  // 切り傷
	ConditionLiverIllness ConditionType = "LiverIllness" // 肝疾患。病気の一種
	// 病気を数種、カタログで足す
)

// RecoveryMode は不調が未治療のときどう振る舞い、治療でどう治るか。
// 低体温は TemperatureSystem が体温から進めるのでこの区分には入らない
type RecoveryMode int

const (
	// 治療して初めて回復する。未治療は保持し悪化しない。骨折・切り傷。
	// ただし掠り傷相当の軽い怪我は代謝で僅かに癒える
	RecoverAfterTend RecoveryMode = iota
	// 未治療なら悪化し続け、治療して初めて回復軌道へ乗る。病気。
	// 早く気づいて質のよい治療をすれば重症になる前に治り、無視すればより重症・悪化する
	ProgressUntilTend
)

// conditionSpec は種類ごとの固定パラメータ。ConditionSystem が扱う怪我と病気を定める。
// 低体温は TemperatureSystem が担うのでこのカタログには載せない
type conditionSpec struct {
	Recovery   RecoveryMode                    // 未治療の振る舞いと治し方
	WorsenPer  float64                         // ProgressUntilTend で未治療のとき1ターン Timer を増やす量。病気の進行速度
	RecoverPer float64                         // 治療済みで1ターン Timer を減らす量。症状ごとに違い、良い薬で速まる
	HPDamage   int                             // 重症で毎ターン与える HP ダメージ。0 なら無害
	Effect     func(sev Severity) []StatEffect // 重症度から能力デバフを出す
}
```

HealthCondition に治療の質を1つ足す。骨折・切り傷は治療して初めて回復軌道へ乗り、病気は治療して初めて悪化が止まって回復に転じるためだ。値は治療に使ったアイテムの Potency が入り、回復速度を左右する。

```go
// 変更前
type HealthCondition struct {
	Type     ConditionType
	Severity Severity
	Timer    float64
	Effects  []StatEffect
}

// 変更後: 治療の質を持つ
type HealthCondition struct {
	Type        ConditionType
	Severity    Severity
	Timer       float64
	Effects     []StatEffect
	TendQuality float64 // 0 なら未治療。正なら治療済みで、値が回復速度を左右する。適した薬の Potency が入る
}
```

不調は HealthStatus を持つ生き物に適用する。什器やロボットなど不調を持たない対象は、従来どおり HP と単純な耐久で壊す。

### ③ 不調を進めるシステム

毎ターン、全不調をカタログに従って進める。低体温は既存の TemperatureSystem が体温から進めるので、ここでは怪我と病気の回復軌道と、重症の HP ダメージを進める。

```go
// ConditionSystem は毎ターン怪我と病気の不調を進める。turn-end に登録する。
// 低体温の進行と回復は TemperatureSystem が担うので、ここでは扱わない
type ConditionSystem struct{}
```

1ターンの処理:

- RecoverAfterTend の不調、すなわち骨折・切り傷は、`TendQuality` が正なら Timer を `RecoverPer` に質を掛けたぶん減らす。未治療なら保持する。掠り傷相当の軽い怪我は代謝で自然に癒えるよう、Minor 未満は治療なしでも僅かに減らす。
- ProgressUntilTend の不調、すなわち病気は、`TendQuality` が0のあいだ毎ターン Timer を `WorsenPer` 増やして悪化させる。治療して `TendQuality` が正になると Timer を `RecoverPer` に質と代謝を掛けたぶん減らして回復させる。だから放置すれば重症・致死へ進み、早く気づいて質のよい治療をすれば重症になる前に治せる。治療の質が高いほど回復が速く、進行に打ち勝てる。
- 重症で `HPDamage` を持つ不調は、`gameaction.ApplyDamage` を死因ラベル付きで呼び HP を削る。
- Timer が 0 になった不調は消す。既存の UpdateTimer が Severity を再計算し、0 で SeverityNone になる。能力効果が変わったら `StatsChanged` を Add して再計算を起こす。TemperatureSystem の既存実装が手本になる。

### ④ 戦闘での怪我

攻撃が命中したとき、低い確率で命中部位に怪我を1つ付ける。怪我はたまに起きる状態異常なので、命中のたびには付けず、ときおり差し込む。命中部位は部位サイズの重みで抽選し、怪我の種類は武器の性質から導く。斬撃は切り傷、打撃は骨折、のように。

```go
// applyInjury は攻撃命中時に、確率で命中部位へ怪我を1つ付ける。
// 怪我の種類は武器種から導き、命中部位は部位サイズの重みで抽選する
func applyInjury(world w.World, target ecs.Entity, weapon ecs.Entity)
```

`gameaction.ApplyDamage` が HP を削った後、HealthStatus を持つ対象にだけ怪我を付ける。HP を削る処理は共通で、怪我は HealthStatus 持ちへの追加になる。命中時にログを出し、`左腕を骨折した` のように負った場所を伝える。

### ⑤ 病気

栄養不足や特定の行動を契機に、低い確率で病気を付ける。契機は既存の曝露へ紐づける。Hunger が Starving のとき衰弱の病、Perishable の rotten 段階の摂取で疫病、のように。

```go
// maybeContractIllness は栄養不足や特定行動を契機に、低い確率で病気を付ける
func maybeContractIllness(world w.World, entity ecs.Entity, trigger IllnessTrigger)
```

病気は ProgressUntilTend で、治療するまで放置すると悪化し続ける。発症後は毎ターン進行して重症へ向かい、無視し続ければ致死性の病は死なせ、非致死の病は重い機能低下を残す。治療して初めて回復軌道へ乗り、良い薬ほど速く治る。だから早く気づいて質のよい治療をすれば重症になる前に快方へ向かい、進行が浅いうちに小さな治療で足りる。放置して重くなるほど、治すのに強い治療と時間が要る。早期発見と治療の質が効くようにして、病気を「気づいたら手を打つ」判断にする。

まずは潜伏期を持たない即発症で最小に始める。感染から自覚まで時間差を付けたくなったら、カタログに発症閾値 Onset を足し、Timer が Onset 未満の潜伏中は Effects と表示を抑えて背後で進行だけ進める形に広げる。

### ⑥ 治療: 使うタブで症状に合うアイテムを選び、部位は自動選択

治療は「使う」タブから、症状に合う性質のアイテムを選んで行う。症状ごとに治療アイテムがあり、骨折には添え木、切り傷には包帯、のように分かれる。アイテムは治療できる不調の種類を持つ。

```go
// Remedy はこのアイテムが治療できる不調の種類を表す。使うと、治療できる種類の不調のうち
// 最も重いものを1つ治療済みにする。骨折→添え木、切り傷→包帯 のように症状ごとに用意する。
// Potency は治療の質。回復軌道に乗せた不調の回復速度を左右し、良い薬ほど大きい
type Remedy struct {
	Treats  []ConditionType
	Potency float64
}
```

アイテムを使うと、治療できる種類の不調のうち最も重いものを1つ自動で選び、治療済みにする。プレイヤーは部位を選ばない。適した対象部位は重大順で自動選択される。

```go
// applyRemedy は治療アイテムを使ったとき、Treats に一致する不調を全部位から集め、
// 最も重いものを1つ治療済みにする。部位は重大順で自動選択する。一致する不調が無ければ何もしない
func applyRemedy(world w.World, user ecs.Entity, remedy ecs.Entity)
```

- Treats に一致する不調を全部位から集め、最も重い1つを重大順で選ぶ。
- その不調を治療済みにして回復軌道へ乗せる。Remedy の Potency がその回復速度を左右する。良い薬ほど速く治る。
- **アイテム1つで部位1つ**を治療する。複数の部位を負っていれば、足りないぶんさらにアイテムを使う。
- 一致する不調が無ければアイテムは消費しない。誤って使っても無駄にしない。

治療は即座には治さない。治療済みの印を立てるだけで、Timer は ConditionSystem がターン経過で減らす。だから治療しても即全快せず、回復を待つ緊張が残る。回復の速さは症状と薬の質で違う。

**健康タブに治し方を載せる**。プレイヤーに症状の治し方を完全には探させない。健康タブは今ある不調を部位ごとに並べ、各不調に、どの種類のアイテムで治療できるかを表示する。だから使うべきアイテムが分かり、当てずっぽうにならない。

回復アイテムは HP の即時回復を担い、Remedy を持つアイテムは不調の治療を担う。両方を持つ救急道具もあり得る。傷ついたら適した薬を使い、ターン経過で治る、というループが、テンポを止めず、良い薬を使うか温存するかの判断とともに回る。全快の安全地帯は作らず、前進の合間に治療する。

### ⑦ 死

死は HP が0で訪れる。致死ダメージが一気に削り、低体温の重症と致死性の病は終端で HP を尽きさせる。死因は失血・凍死・餓死・病死などのラベルで区別し、run の終端 State へ渡す。決着の型 `RunOutcome` は done の doc `260822014348` に定義済みで、そこへ接続する。

## 採用しなかった方法

- **怪我を専用の Wound 型で持つ**。棚上げ doc `260821232324` のように `Wound{Part, Type, Bleeding, Deep, float Severity}` を病気と分けて持つ。出血で HP を削り傷跡を残すリアリティは出るが、HealthStatus の平坦化・float 化・serde 変更を伴い複雑になる。既存の HealthCondition 枠に統一すれば7〜8割を再利用でき、要件の「手間にならない範囲」に合う。棚上げ doc は着想の資産として残し、出血や傷跡が欲しくなったら参照する。
- **治療で即座に治す**。棚上げ doc の最終案はテンポとアイテムの手応えを優先して即時治癒にした。だが今回の要件は治療してターン経過で回復すること。治療を回復軌道への点火にし、ターンが治す形にする。治療しても即全快しない緊張を残し、症状ごとに回復速度を変えて手応えを出す。
- **1アクションで治療量をまとめて配る**。1回の治療で budget を持ち、負傷度の重い順に複数の不調へ自動で配る。治療の手数は減るが、どの薬がどの症状に効くかの手応えが薄れ、アイテムの区別が消える。症状ごとに治療アイテムを分け、使うと最も重い1つを治す形にする。アイテム1つで部位1つなので、足りなければさらに使う判断になる。
- **治療する部位をプレイヤーに手で選ばせる**。どの部位を治すか毎回選択する。煩雑で、負傷度を読む手間になる。適した対象部位は重大順で自動選択し、選ばせない。
- **症状の治し方をプレイヤーに完全に探させる**。どのアイテムが効くかを試行錯誤で見つけさせる。詰まりの元になる。健康タブに各不調の治し方を載せ、使うべきアイテムが分かるようにする。
- **部位ごとの耐久プールや機能算出の中間層を持つ**。1体への微管理になり、抽象値は体感しにくい。負傷は部位から能力へ直接効かせれば足りる。
- **病気を放置で自然治癒させる**。発症後は免疫でターン経過とともに勝手に治る。却下。放置で治るなら緊張が生まれず、治療の動機も薄い。放置すると悪化する進行にして、早く気づいて質のよい治療をすれば重症前に治り、無視すれば重症・致死へ向かう形にする。早期発見と治療の質が効くようにする。
- **病気に長い潜伏を必須化する**。まず即発症で最小に始め、感染から自覚の時間差が欲しくなったらカタログに Onset を足す。最初から潜伏の管理を背負わない。
- **HP の自然回復を作らず休息と回復アイテムだけに留める**。だが要件が HP のゆっくりした自然回復を求める。代謝という1つの派生値で回復速度を決め、食料と休息が回復の動機になる形にする。

## コメント

数値は着手後に実プレイで測る。代謝率・怪我の発生確率・症状ごとの回復速度・低体温の HP ダメージ量・病気の機能低下量と致死速度・治療の budget と1不調あたりの消費、いずれも実プレイで釣り合わせる。

serde は `HealthCondition` に `TendQuality` を足し、`Remedy` を新設するので変わる。`ruins-review` の serde 観点で点検し、旧セーブとの互換は維持せず、バージョン記録と不一致警告で扱う。

実装は進捗の上から順に進める。HP リジェネと低体温ダメージという HP まわりを先に入れ、次に不調カタログと ConditionSystem の土台、その上に戦闘の怪我・治療・病気を載せる。各段で `make check` を通し、最小の一周を実プレイしてから数値を詰める。
