# 季節と日の出入りをゲームログで知らせる

## 背景

季節と時間帯はすでにゲームの挙動へ効いている。世界温度は季節の正弦波と時間帯補正で決まり、地上の明るさと視界は時間帯で変わる。しかしプレイヤーには変化した瞬間を知らせる手立てがなく、寒さや暗さが進んでも気付きにくい。

変化を知らせて、備え、たとえば火を焚く、退避する、の判断につなげたい。温度モデルは [[260822220253]]、熱源は [[260824095722]]、火は [[260829215021]] に連なる。

## 要件

- 季節が変わったらゲームログに出す。年に数回しか起きないので見逃すと痛い。
- 日の出と日の入りをゲームログに出す。時間帯は6区分あるが、知らせるのは日の出入りの2つだけにする。毎区分出すと戦闘や採取のログに紛れる。
- 変化の事実だけを出す。気温がどう動くかは既存システムが担うので重複させない。
- 変化の検出のために状態を増やさない。季節も時間帯も `GameTime.TotalTurns` から導出しているので、現在と直前の導出値の差で判定できる。

## 設計

季節と時間帯は `GameTime` が `TotalTurns` から純関数で導く。変化検出も同じ土台に乗せ、直前ターンの値を保持する component は持たない。判定は「現在ターンの導出値」と「1つ前のターンの導出値」の比較で行う。

```go
// 直前のターンから季節が変わったか。Advance の直後に呼ぶ想定。
func (gt *GameTime) SeasonJustChanged() bool

// 現在の時間帯と、直前のターンから時間帯が変わったか。
// どの時間帯へ入ったかで日の出入りを見分けられるよう、変わった先も返す。
func (gt *GameTime) TimeOfDayJustChanged() (TimeOfDay, bool)
```

いずれも内部で `prev := GameTime{TotalTurns: gt.TotalTurns - 1}` を作り、既存の `GetSeason` / `GetTimeOfDay` に委譲する。導出の計算式を複製しない。

ログ出力は `turn_system.go` の関数 `logEnvironmentChange(world)` に置き、ターン確定時に1度だけ呼ぶ。呼び出し元の `runEndPhase` と同じファイルにまとめ、ターン終了処理の流れを1箇所で追えるようにする。日の出入りの割り当ては presentation の方針なので、`GameTime` でなくこの関数が持つ。夜明けへ入るのが日の出、夜へ入るのが日の入りとし、ほかの区分への変化は出さない。夕は太陽がまだ空にある薄暮なので、沈み切って夜になった瞬間を日の入りとする。

```go
if tod, changed := gt.TimeOfDayJustChanged(); changed {
    switch tod {
    case gc.TimeDawn:  // 日の出
    case gc.TimeNight: // 日の入り。夕は薄暮なので夜入りで出す
    default:             // ほかの区分へは知らせない
    }
}
```

呼び出しは `turn_system.go` の `runEndPhase` で `GameTime.Advance()` の直後に置く。変化は直前ターンとの差で見るので、時間を進めた後でなければならない。毎フレーム走る System にはしない。`progressTurnHunger` と同じ「ターン終了時に直接呼ぶ関数」に揃え、`InitializeSystems` 登録漏れで黙ってスキップされる形を避ける。

日の始まりは暦の夜明けなので、季節が変わるターンは必ず日の出のターンと重なる。そのターンは季節ログと日の出ログの両方を出す。暦の自然な挙動で、抑制しない。

## 採用しなかった方法

| 方法 | 不採用の理由 |
|---|---|
| 前回の季節・時間帯を component に保持して比較 | 導出可能な状態を保存すると serde 対象が増え、`TotalTurns` と二重の真実になる。差分は導出で取れるので不要。 |
| 6区分すべての切り替わりをログに出す | 1日6回は頻度が高く、戦闘や採取のログに紛れて逆に気付けない。日の出入りの2つに絞る。 |
| 変化の影響、たとえば「冷えが厳しくなる」も添える | 実際の気温変化は既存システムが決めるので、文言に固定値を書くと乖離する。事実だけ出す。 |
| 毎フレーム走る System として登録 | 変化検出はターンに1回で足りる。フレーム単位だと同じ変化を何度も出しかねない。 |
| 時刻・季節を常設 UI に表示 | 見逃さないという点では有効だが UI の作り込みが要る。まずログで最小に入れ、埋もれるようなら別途検討する。 |

## コメント

- 日の出=夜明け入り、日の入り=夜入り、の割り当ては presentation の方針。`GameTime` は中立に保ち、systems 側が決める。後で全区分に広げたくなっても systems の switch だけで済む。夕は太陽がまだ空にある薄暮なので日の入りにしない。沈み切って夜になった瞬間を日の入りとする。
- 季節ログと日の出ログが同時に出るのは、暦の1日が夜明けで始まる仕様の自然な帰結。
