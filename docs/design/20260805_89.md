# 天気システムを設計する

## 背景

ruins にはオーバーワールドの一般天気、晴・曇・雨・雪・霧などが無い。既にある関連要素は次のとおり。

- `GameTime{TotalTurns}` シングルトン。`GetTimeOfDay` で時間帯6区分、`GetTemperatureModifier` で時間帯ごとの気温修正を持つ。`turnsPerDay=1500`、時間帯あたり250ターン。季節は未実装。
- `TileTemperature{Shelter, Water, Foliage}` コンポーネント。タイル環境ごとの気温修正。
- `CalculateEnvTemperature = ステージ基本気温 + タイル修正 + 時間帯修正`。摂氏で算出する。
- `TemperatureSystem` が快適温度域と断熱値から寒暑ダメージを与える。
- 寒波前線 `FrostRenderSystem` と temperature 系。空間的に西へ動く極低温ハザード。特定の演出であり一般天気ではない。
- `IsOnOverworld` が霜・寒波前線などオーバーワールド固有の効果を gate する。現ステージが帯データ `SeamlessBand` を持つかで判定する。
- 視界は `VisionSystem`、視界半径 `VisionRadiusTiles=24`、暗さ `DarknessVisible=0.15`。

目的は、オーバーワールドに一般天気を足し、視界・環境気温・光・降水演出へ効かせること。既存の気温・寒波前線・帯という抽象に天気を重ねる。

## CDDA 天気の調査まとめ

`./Cataclysm-DDA` の天気実装を精読した。3層に分かれる。

### 1. 生成層 weather_gen

天気は `(位置, 時刻, seed)` の純関数。4次元 simplex ノイズで気温・湿度・気圧を算出し、保存状態を持たない。任意の過去・未来時点を再計算でき、予報や未装填領域の降雨積算に使える。seed はノイズの第4座標として入り、量ごとにオフセットして相関を切る。

- 気温 = `基本気温 + 季節modifier + 日周cos(最低は05:00) + 季節sin(±12K) + ノイズ(±6K)`。日較差とノイズ振幅は冬ほど大きい。
- 湿度・気圧もノイズ + 季節項。
- **風だけは大域 RNG と static 変数で非決定論的**。風に依存する天気、嵐や霧は再計算で揺れる。これは CDDA の設計上の弱点。

連続量 `w_point{temperature, humidity, pressure, windpower, winddirection, ...}` を出し、次層へ渡す。

### 2. 型定義層 weather_type

データ駆動の天気カテゴリ。主なフィールド:

| フィールド | 意味 |
|---|---|
| id, name, color, symbol | 識別・表示 |
| priority | 選択の優先度。高いほど優先 |
| required_weathers | 前提天気チェーン。escalation ラダーを作る |
| condition | 発生条件。`weather('temperature'\|'humidity'\|'pressure'\|'windpower')` の閾値式 |
| sight_penalty | 視界の不透明度倍率。1.0で無影響、大きいほど視界が縮む |
| light_modifier, light_multiplier | 環境光への加算・乗算 |
| temperature_modifier | 気温オフセット |
| sound_attn | 音の減衰量 |
| precip, rains | 降水の強さ none/very_light/light/heavy と、液体か雪か |
| duration_min/max | 再ロールまでの時間。既定5分 |
| weather_animation, tiles_animation | 降水アニメ |

**選択アルゴリズム**: `w_point` を priority 昇順に走査し、`required_weathers` が現在の選択天気を含むか空、かつ `condition` が真なら上書き採用する。break せず走査し切るので最高優先度の合致型が勝つ。既定は clear。雨のラダーは湿度・気圧が駆動し、気温33°Fで雨↔雪が切り替わり、風で嵐系が分岐する。

カタログ: clear, sunny, cloudy, light_drizzle, drizzle, rain, rainstorm, thunder, lightning, flurries, snowing, snowstorm, fog, mist, portal storms。acid rain は独立の天気型では無く場・EOC 側。

### 3. 効果層 weather.cpp

毎ターン `update_weather` が、期限が来たら天気を再計算し、`nextweather = turn + rng(duration_min,max)` を置く。効果の配線は次のとおり。

- **視界**: `sight_penalty` は屋外タイルの透明度に乗じる。倍率>1で不透明になり視界が縮む。`sight_penalty` が変わったときだけ LOS キャッシュを再構築する。
- **光**: `環境光 = 空の光 * light_multiplier + light_modifier`。雨 -30、雷 -45 など。
- **気温**: 局所タイル気温 = `環境気温 + 近隣の熱源 + temperature_modifier`。体温モデルへ入り、凍傷・熱中症・速度低下・士気へ効く。
- **降水**: `rains && precip!=none` かつ屋根が無ければ、プレイヤーを濡らし、容器に雨を溜め、場と匂いの減衰を早め、火を消す。雪は積雪モデルで深さを持つ。
- **音**: 出力音量から `sound_attn` を引く。
- **雷・ハザード**: 周期スクリプト EOC で表現。雷は 1/600 で閃光と一時的な光量、雷鳴は 1/50。
- **風**: 遮蔽・地形で補正した風速が風冷えと延焼方向へ効く。

照会 API は `get_weather().weather_id->...` と `get_temperature(pos)`、任意時点の `current_weather(pos,t)`。UI はサイドバーの天気名・風・気温、降水アニメ overlay、予報。

## 要件

- オーバーワールドに一般天気を出す。初期は晴・曇・雨・雷雨・雪・霧。
- 決定論的。`(時刻, seed)` から再現でき、保存状態を増やさない。CDDA の風のような非決定論は持ち込まない。
- 天気は視界・環境気温・光・降水演出へ効く。
- 屋内・ダンジョン・遺跡は天気の影響外。`IsOnOverworld` で gate する。
- 既存の寒波前線・気温と共存する。天気は前線を置き換えない。

## 設計

### 全体方針: CDDA の3層を縮約する

CDDA の生成→型→効果の3層を踏襲しつつ、2D の単一オーバーワールド向けに縮約する。

- **決定論を全面採用する**。天気を「天気ピリオド」に区切り、`periodIndex = TotalTurns / turnsPerWeatherPeriod` ごとに1つ固定する。現在天気や次変化時刻をシングルトンへ保存せず、`GameTime.TotalTurns` と `Seed` から都度算出する純関数にする。セーブ不要で再現でき、CDDA の風の非決定論を避けられる。
- **連続量を2つに絞る**。CDDA の温度・湿度・気圧・風のうち、ruins は気温を既に持つ。天気選択の連続量は「気温」と「降水ポテンシャル」の2つにする。降水ポテンシャルは雲・湿りの代理で 0..1、決定論ハッシュから出す。雨か雪かは気温閾値で分ける。湿度・気圧・風は他所で使わないため導入しない。
- **空間変化はしない**。現オーバーワールドで単一の天気にする。時刻に依存し位置に依存しない。空間的な寒暖差は既存の寒波前線が担う。

### データ定義

```go
// PrecipClass は降水の強さ
type PrecipClass int

const (
	PrecipNone PrecipClass = iota
	PrecipLight
	PrecipHeavy
)

// WeatherPoint は決定論的に算出する連続気象量。CDDA の w_point を気温と降水ポテンシャルへ縮約する。
type WeatherPoint struct {
	Temperature     int     // ℃。天気オフセット前の環境気温
	PrecipPotential float64 // 0..1。雲・湿りの代理。決定論ハッシュから
}

// WeatherType は天気1種。データ駆動。CDDA weather_type を必要分へ縮約する。
type WeatherType struct {
	ID           WeatherID
	Name         string                  // 表示名
	Priority     int                     // 高いほど優先
	RequiredPrev []WeatherID             // 前提天気チェーン。空なら無条件
	Condition    func(WeatherPoint) bool // 発生条件。気温と降水ポテンシャルの閾値

	// 効果
	VisionScale  float64     // 視界半径の倍率。1.0で無影響、1未満で狭まる
	Darkness     float64     // 追加の暗さ 0..1。曇・雨で薄暗く
	TempModifier int         // 環境気温オフセット ℃
	Precip       PrecipClass // 降水の強さ
	Snow         bool        // 降水が雪か。見た目と将来の積雪用
}
```

### 天気の決定 : 決定論・状態レス

```go
// CurrentWeather は現在の天気型を返す。状態を保存せず、時刻と seed から都度算出する。
func CurrentWeather(world w.World) *WeatherType {
	if !IsOnOverworld(world) {
		return weatherClear // 屋内・ダンジョンは常に無天気
	}
	period := int(GetGameTime(world).TotalTurns) / turnsPerWeatherPeriod
	p := computeWeatherPoint(world, period)
	prev := selectWeather(computeWeatherPoint(world, period-1)) // 前ピリオドの天気
	return selectWeather(p, prev)
}
```

- `computeWeatherPoint(world, period)`: 気温は代表点の環境気温、天気オフセット前の値を使う。降水ポテンシャルは `smoothHash(seed, period)` で、隣接ピリオドを補間して境界での急変を避ける。
- `selectWeather`: WeatherType 一覧を Priority 昇順に走査し、`RequiredPrev` が前ピリオド天気を含むか空、かつ `Condition` が真の最高優先度を採用する。既定は clear。CDDA と同じラダー。
- 予報は同じ関数へ未来の period を渡すだけで出せる。
- 1ターン内の多重呼び出しは、SpatialIndex と同じくメモ化で再計算チャーンを避ける。

### カタログ 初期案

数値は初期値で調整前提。気温は天気オフセット前の値で判定する。

| ID | 優先 | 前提 | 条件 | VisionScale | Darkness | Temp | Precip | Snow |
|---|---|---|---|---|---|---|---|---|
| clear | 0 | - | 既定 | 1.0 | 0 | 0 | none | - |
| fog | 15 | clear | precip 0.3..0.5 | 0.55 | 0.10 | 0 | none | - |
| cloudy | 20 | - | precip≥0.4 | 1.0 | 0.10 | -1 | none | - |
| rain | 50 | cloudy | precip≥0.7 かつ temp≥1 | 0.80 | 0.20 | -2 | heavy | 否 |
| storm | 60 | rain | precip≥0.85 かつ temp≥1 | 0.65 | 0.30 | -3 | heavy | 否 |
| snow | 100 | cloudy,rain | precip≥0.7 かつ temp<1 | 0.75 | 0.15 | -2 | heavy | 是 |

### 効果の配線

1. **気温**: `CalculateEnvTemperature` に天気の `TempModifier` を1項加える。`base + tile + time + weather`。`TemperatureSystem` の寒暑ダメージへ自動反映される。判定用の気温は天気オフセット前を使い、循環を避ける。
2. **視界**: `VisionSystem` の `visionRadius` に `VisionScale` を掛ける。屋外のときのみ。CDDA の屋外不透明度倍率を、ruins のタイル半径ベースに合わせて視界半径の縮小へ翻訳する。天気が変わった period では `vs.RequestUpdate()` で視界を再計算する。
3. **光・暗さ**: `computeTileRenderMap` の可視タイル `Darkness` に `WeatherType.Darkness` を加える。上限をクランプする。曇・雨で薄暗くなる。
4. **降水演出**: `RainRenderSystem` を `FrostRenderSystem` と同じ雛形で新設する。`IsOnOverworld` で gate し、可視かつ屋外のタイルへ雨・雪の粒を描く。`helper.go` の Renderers へ登録する。
5. **gate**: すべて `IsOnOverworld` で屋外限定にする。帯データを持たないダンジョン・屋内・遺跡は自動的に影響外になる。

### 状態の持ち方

`WeatherState` シングルトンは持たないことを推奨する。`GameTime.TotalTurns` と `Seed` から算出する純関数へ寄せ、キャッシュは1ターン内のメモ化のみにする。SpatialIndex と同じ再構築パターン。

### 寒波前線との関係

別機構として共存する。天気は時刻依存で一様な環境状態、寒波前線は空間的に動く極低温ハザード。両者とも気温と視界へ加算合成する。天気は前線を置き換えない。

## 採用しなかった方法

- **完全な simplex noise と湿度・気圧・風を CDDA 準拠で持つ**: 2D 単一オーバーワールドには過剰。気温と降水ポテンシャルの2量で足りる。風の非決定論も持ち込みたくない。
- **現在天気をシングルトンへ保存し duration で切り替える**: 状態とセーブが増え、再現性の管理コストがかかる。決定論なら不要。
- **空間的に変化する天気**: 初期は不要。空間差は寒波前線が担う。導入は将来の判断。
- **雷・濡れ・積雪・音・風冷え**: 初期スコープ外。将来フェーズで分割する。

## コメント

- 決定論の要は、ピリオド境界での急変を避けるため降水ポテンシャルを隣接ピリオド補間すること。天気変化は視界再計算を要求するので、ピリオド長で頻度を抑える。
- 視界効果の翻訳に注意する。CDDA は屋外タイルの不透明度、ruins は視界半径。半径縮小は屋内へ効かせない。`IsOnOverworld` gate で担保する。
- 雨か雪かは気温閾値で分ける。天気の `TempModifier` が雨雪判定へ再帰しないよう、判定には天気オフセット前の気温を使う。適用順に注意する。
- 予報 UI・積雪・アイテム濡れ・音・風は、本 doc の初期スコープ外とし将来の設計 doc で分割する。
