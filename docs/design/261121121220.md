# 物を投げて敵に当てる

## 背景

物の使い道に特化する方針では、物を増やすことと同じくらい、操作を増やすことが効く。同じ物でも操作ごとに別の使い道が生まれ、試せることが物の数と操作の数の掛け算で増える。今の操作は、調べる・置く・食べる・読む・使う・分解するの6つで、投げるが無い。

投げるが無いことで、次のことが起きている。

- 石と尖った石は、説明文で「投げると武器になる」と約束しているのに、使い道が無い
- 手榴弾・毒手榴弾・火炎手榴弾は `inflictsDamage` を持ち、「使う」と使った本人が傷つく。投げるはずの物が、使うと自分に効く
- 持ち物画面の動詞の表には「投げるは後で足す」と書かれたままになっている

投げられることの意義は次のとおり。入口は戦闘の選択肢だが、本命は、拾った物で体を傷つけずに状況を動かす手が増えることにある。

- 傷を負わずに戦える。近接は反撃で切り傷や骨折を負い、止血と手当ての手間につながる。離れて削る手は、体の仕組みが重いほど価値が大きい
- 弾や銃が無くても遠くに届く。拾った物がそのまま遠距離の手段になり、弾の節約にもなる
- ガラクタに出口ができる。使い道の無い物や重くて持て余す物も、投げれば重さを減らしつつ敵を削れる
- 何が投げ向きかを知る遊びになる。尖った石は石より効き、手榴弾は壊れて爆ぜる、と試して覚える
- 音で敵を引く、遠くの火に燃料をくべる、氷を割る、などの戦闘以外の手につながる。マスを狙う操作が要るので、この doc では扱わない

## 要件

- どの物も投げられる。威力は重さから導き、重すぎる物は投げられない
- 投げ向きの物は、物の行の投げの欄で威力を上書きし、投げると壊れるかを決める
- 狙いは、射撃と同じく見えている敵から選ぶ。射程・射線・命中・ダメージは射撃の仕組みを使う
- 投げるほど上達する投擲のスキルを足す
- 壊れる物は、当たっても外れても投げると無くなる。外れた手榴弾は効果無く無くなる。外れる危険が投げる前の判断の重さになる。壊れない物は、当たっても外れても、狙った敵の足元に落ち、拾い直せる。外れた物を射線の先へ飛ばすのはマスを狙う操作と同じ扱いが要るので、この doc では足元に落とす形に単純にする
- 投げられるのは背負い袋の物だけ。装備中の物は持ち物画面の投げるに出ず、外してから投げる
- 手榴弾は狙った敵1体に当て、投げると壊れる。使った本人が傷つく効果は消す
- 持ち物画面に「投げる」の動詞を足し、ダンジョンからも直接呼べる

## 設計

### 投げの値

どの物も投げられる。投げの値は、物の行に投げの欄があればその値を使い、無ければ重さから導く。重さが 5 kg を超える物は投げられない。

重さから導く値は次のとおり。

| 値 | 決め方 |
|---|---|
| damage | 重さ 1 kg あたり 1 を四捨五入。最小 1、最大 5 |
| accuracy | 70 から、重さ 1 kg あたり 5 を引いて四捨五入 |
| 壊れるか | 壊れない |

重い物ほど当たれば痛いが当てにくい。5 kg まで威力が上がり続けるので、重いガラクタも、当てにくさと引き換えに投げる理由が残る。重さから導く damage は最大 5 なので、投げ向きの物は欄で 6 以上の値を書いて上回らせる。重さを持たない物は 0 g として扱い、威力 1・命中 70 で投げられる。

重さはミリグラムの整数で持つので、四捨五入も整数で計算する。

```go
damage := (mg + consts.MilligramPerKg/2) / consts.MilligramPerKg      // 1 kg あたり 1
accuracy := 70 - (mg*5+consts.MilligramPerKg/2)/consts.MilligramPerKg // 1 kg あたり 5
```

| 物 | 重さ | damage | accuracy |
|---|---|---|---|
| 布切れ | 100 g | 1 | 69 |
| 1 kg の物 | 1 kg | 1 | 65 |
| 皿の山 | 3 kg | 3 | 55 |
| 4.5 kg の物 | 4.5 kg | 5 | 47 |
| 5 kg の物 | 5 kg | 5 | 45 |

100 g の布は威力 1 で、投げられても武器としては役に立たない。

投げ向きの物だけ、行に投げの欄を書いて上書きする。

```cue
// 投げたときの値。書かない物は重さから導く
#Throw: {
	damage!:   #BaseDamage
	accuracy!: #Accuracy

	// 投げると壊れて無くなる。省くと壊れず、狙った敵の足元に落ちる
	breaks?: bool
}

#Item: {
	// ...今の欄
	throw?: #Throw
}
```

投げの値はコンポーネントとして保存せず、投げるときに導く。値は raw の欄と重さだけで決まるので、保存すると重さと二重に持つことになる。投げの欄は、道具の性質を引く `raw.FindTool` と同じく `query.GetEntityID` で id を取り、`RawMaster` の物の行から引く。重さは、生成のときに解析済みの `gc.Weight` コンポーネントから取る。`Weight` を持たない物は 0 g として扱う。

```go
// ThrowAttack は物を投げたときの攻撃の値。攻撃の種類は投擲に固定する。コンポーネントでなく、投げるときに導く値
type ThrowAttack struct {
	Damage   int
	Accuracy int
	Breaks   bool // 投げると壊れて無くなる
}

// ThrowAttackOf は物の投げの値を返す。raw の行に投げの欄があればその値、無ければ重さから導く。
// 5 kg を超える物は投げられないので ok=false を返す
func ThrowAttackOf(world w.World, item ecs.Entity) (ThrowAttack, bool)
```

`ThrowAttack` は攻撃の値の型 `gc.Attacker` を満たす。欄に無い値は次のように固定する。

| メソッド | 値 |
|---|---|
| `GetAttackCategory` | `throw` |
| `GetElement` | 無し `NONE` |
| `GetAttackCount` | 1 |
| `GetCost` | 1。物を手放す代わりに、射撃の 2 より安くする |
| `GetTargetType` | 敵1体。`ENEMY`・`SINGLE` |

投げる行動は、射撃と同じ命中とダメージの計算 `applyAttackDamage` にこの値を渡す。

投げの欄を書く物は次の案にする。

| 物 | 重さ | damage | accuracy | 壊れる |
|---|---|---|---|---|
| 石 `stone` | 1 kg | 6 | 70 | いいえ |
| 尖った石 `sharp_stone` | 300 g | 7 | 80 | いいえ |
| 手榴弾 `grenade` | 400 g | 20 | 75 | はい |
| 毒手榴弾 `poison_grenade` | 400 g | 15 | 75 | はい |
| 火炎手榴弾 `flame_grenade` | 400 g | 25 | 75 | はい |

石と尖った石は、重さだけならどちらも威力 1 だが、投げ向きなので欄で上書きする。尖った石は石より威力も命中も上にする。

手榴弾3種の damage は、今の `inflictsDamage` の値をそのまま移す。これまでの自傷は固定の値をそのまま与えていたが、投げると `formula.Damage` で感覚の値・スキルの倍率・防御が掛かる。遠距離武器の damage は 4〜34 に分布し、火炎手榴弾の 25 は上のほうになる。投げると無くなるので高めにしているが、実装後に手触りで調整する。命中は基準の 80 からの差が補正になるので、石の 70 は -10、尖った石の 80 は ±0 になる。

### 攻撃の種類と投擲のスキル

攻撃の種類の列挙に `throw` を足し、`attackTypes` に行を1つ足す。遠距離の攻撃として、射程と命中の落ち方を持つ。

```toml
[[attackTypes]]
  accuracy = "throw_accuracy"
  damage = "throw_damage"
  id = "throw"
  injury = "fracture"
  maxRange = 6
  name = "Throwing"
  optimalRange = 3
  penaltyPerTile = 10
  range = "ranged"
  skill = "throw"
```

射程は弓より短くする。弓は最適射程が4、最大射程が10。

怪我は攻撃の種類ごとに1つに決まるので、投擲で負わせる怪我は骨折になる。尖った石や手裏剣のような刃物も骨折になり、手裏剣はこれまでの弓の切り傷から変わる。物ごとに怪我を変えるのは、この doc では扱わない。

ブーメランと手裏剣は、今は弓の攻撃の種類 `bow` を持つ、装備して撃つ武器になっている。どちらも投げる武器なので、攻撃の種類を `throw` に移し、投擲のスキルで上達するようにする。装備して撃つ形と、ブーメランが手元に戻る挙動はそのまま保つ。物を手放す投げる行動とは別に、射撃の経路で使う。射程は弓より短くなる。

スキルの列挙に `throw`、熟練の列挙に `throw_damage` と `throw_accuracy` を足し、`skills` に行を足す。伸び方は弓にそろえる。スキルの id は、ほかの攻撃と同じく攻撃の種類の id にそろえて `throw` にする。

```toml
[[skills]]
  ability = "sen"
  category = "ranged"
  effect = "Increases throwing damage and accuracy"
  gainedBy = "Raised by throwing items at enemies"
  id = "throw"
  name = "Throwing"
  summary = "Technique for throwing items"
  [[skills.proficiencies]]
    id = "throw_damage"
    perLevel = 5
  [[skills.proficiencies]]
    id = "throw_accuracy"
    perLevel = 3
```

### 投げる行動

```go
// ThrowParams は投げる行動のパラメータ
type ThrowParams struct {
	Item   ecs.Entity // 投げる物
	Target ecs.Entity // 狙う敵
}
```

- 行動の種類に `BehaviorThrow` を足し、`internal/activity/throw.go` に `ThrowBehavior` を置く
- Validate は、物が actor の背負い袋にあり `ThrowAttackOf` で投げられること、狙う敵が生きていること、射程と射線を射撃と同じ関数で確かめる
- DoTurn は、狙った敵の座標を先に取ってから、射撃と同じ命中の補正と `applyAttackDamage` で当てる。そのあと、壊れる物なら `lifecycle.ChangeItemCount(world, item, -1)` で1つ消し、壊れない物なら `lifecycle.MoveMembersToField(world, []ecs.Entity{item}, coord, actor)` で1つを先に取った座標へ移す。どちらも持ち主に `WeightDirty` を付けるので、重さの再計算が走る。座標を先に取るので、倒した敵の死亡の処理に頼らない
- 持ち物画面はスタックの代表を表示する。狙いを選ぶ画面にはその代表の entity を渡し、Validate で背負い袋にあることを確かめ直す。画面を重ねている間に物が消えていれば拒む
- 狙える敵の判定は、射撃の `CanShootTarget` にならい `CanThrowTarget` を置く

### 狙いを選ぶ画面

射撃の画面は、見えている敵を絞り、Tab で切り替え、Enter で撃つ。投げるも同じ流れなので、画面を `TargetingState` として共有し、射撃と投げるで違う部分をインターフェースに切り出す。

```go
// targetMode は敵を狙う画面で、射撃と投げるで違う部分
type targetMode interface {
	bindings() []keybind.Binding
	canTarget(world w.World, player, target ecs.Entity) bool
	hitRate(world w.World, player, target ecs.Entity) int
	execute(world w.World, player, target ecs.Entity) error
	// handle は狙い方に固有のアクションを処理する。射撃のリロードがこれに当たる
	handle(world w.World, player ecs.Entity, action inputmapper.ActionID) (handled bool, err error)
	title(world w.World) string
	// drawSource は情報パネルに、使う武器や物の行を描く
	drawSource(world w.World, player ecs.Entity, drawText func(string))
	unavailable(world w.World, player ecs.Entity) string
	noTarget(world w.World) string
	help(world w.World) string
}
```

射撃の `ShootMode` は装備中の武器を使い、R でリロードする。投げるの `throwMode` は投げる物の entity を持つ。持ち物画面の投げるは、持ち物画面を狙う画面に切り替えるので、投げても取り消してもダンジョンへ戻る。

### 持ち物画面の動詞

動詞の表に「投げる」を足す。キーは Shift+t。対象は `ThrowAttackOf` で投げられる物、つまり 5 kg 以下の物で、実行すると狙いを選ぶ画面を重ねる。

持ち物の詳細には、投げの欄を書いた投げ向きの物だけ、投げの威力と命中の行を出す。どの物も投げられるので、全部に出すと詳細が同じ行で埋まる。

「使う」の t は今は Shift の指定が無く、Shift+t でも反応する。置く d と分解する D の組と同じく、「使う」を Shift 無しに限り、投げるを Shift 付きにする。持ち物画面の動詞の表と、ダンジョンのキーの束縛の両方を直す。ダンジョンのキーの束縛は、全行の条件が互いに重ならないことを前提にしている。

アクション `ActionVerbThrow` と、ダンジョンから動詞画面への受け渡しは、すでにある。足すのはキーの束縛だけになる。

### 自傷の効果を消す

`inflictsDamage` の欄、`InflictsDamage` コンポーネント、使うの効果の組の `damageEffect` を消す。手榴弾3種は投げの欄を持ち、投げると壊れる。

手榴弾3種の消費物の欄は、使う効果が無くなるので消す。投げると無くなるかは、投げの欄の `breaks` で決まる。

`schema.cue` の「食べる・使うの効果を持つ物は消費物」の一覧から `inflictsDamage` を外す。

### 使い道の統計

`internal/raw/item_uses_test.go` の「投げる」の列は、行に投げの欄を書いた投げ向きの物を数える。どの物も投げられるので、全部を数えると使い道の数が一律に1増えるだけになる。石と尖った石が加わり、3から5になる。

## 採用しなかった方法

- **投げの欄を書いた物だけを投げられる**: 物ごとに投げの値を書く手間が増え、試せることも狭まる。どの物も投げられれば、何が投げ向きかを試して知る遊びになる。布や紙は重さから導くと威力 1 になり、武器として役に立たないので、全部投げられても困らない
- **消費物は投げると無くなる**: パンのような食べ物まで投げると消える。壊れるかは投げの欄で決める
- **壊れる物は当たったときだけ無くなる**: 外れた手榴弾が爆ぜずに床に残り、損無く何度でも投げ直せてしまう
- **投げの値をコンポーネントで持つ**: 値は raw の欄と重さで決まり、保存すると重さと二重に持つことになる。投げるときに導けば出典が1つで済む
- **重さから導く威力の上限を高くする**: 重いガラクタが投げ向きの物より強くなり、何が投げ向きかを試して覚える遊びが逆転する
- **重さから導く威力の傾きを急にする**: 1 kg あたり 4 だと約 1.1 kg で上限に届き、そこから重いほど命中が下がるだけになる。重いガラクタを投げる理由が無くなる
- **既存のスキルに相乗りする**: 格闘や弓の熟練で投げると、何で上達したかの意味がずれる
- **手榴弾の爆風の範囲まで入れる**: 範囲の決め方と味方への巻き込みを決める必要があり、最初の段が大きくなる。単体に当てる形で投げるの仕組みを先に通す
- **マスを自由に狙う**: カーソルでマスを選ぶ画面を一から作ることになる。音で敵を引く、火にくべる、などマスを狙う理由ができたときに足す
- **マーカー `Throwable` を付ける**: 投げの欄に値が要るので、値を持つ欄そのものを性質にする
- **ブーメランと手裏剣を投げの欄で投げる物にする**: 投げると手放すので、手元に戻るブーメランの挙動と食い違う。装備して撃つ武器のまま、攻撃の種類だけを投擲に移す
- **ブーメランと手裏剣を弓のまま残す**: 投げる武器なのに弓の熟練で上達し、何で上達したかの意味がずれる
