# 燃料に残量を持たせ、灯りとの間で移す

## 背景

灯りの残量の設計 261119224218 で、手提げランタンと懐中電灯を、灯油と電池で補充できるようにした。今の補充は、燃料を1つ使うと灯りが満タンに戻る。燃料はそれ自体の量を持たない。

この形では、燃料を拾うことが「満タン1回分」を拾うことと同じになり、選ぶことが無い。拾った懐中電灯も満タンで生まれるので、補充メニューに出ず、補充できないように見える。

燃料にも残量を持たせ、灯りとの間で量を移す形にする。電池は 1000 のように量を持ち、0になるまで何度でも灯りへ移せる。見つかる電池や懐中電灯の残量はまちまちで、ほかの灯りから抜いて別の灯りへ入れる、という使い回しが生まれる。廃墟で物を漁って組み合わせる遊びに合う。

## 要件

- 燃料の行は残量を持つ。補充は、灯りの不足分と燃料の残りの少ない方を移す。燃料は残りが0になるまで使える。
- 燃料の残量が0になったら、使い切った物に変わる。電池は使い切った電池 `empty_battery`、灯油は空の缶 `empty_oil_can` になる。
- 灯りから燃料を抜ける。抜くには、空になった物を入れ物として1つ使う。使い切った電池は電池に、空の缶は灯油に戻り、灯りの残量がそこへ移る。満たすと抜くは対称で、物の数は増えも減りもしない。
- 見つかる燃料と灯りは、上限までのランダムな残量で生まれる。作った物、初期装備、商人の品、デバッグの木箱は満タンで生まれる。
- 燃料を燃やすときの熱は、残量の割合で決める。残量の少ない灯油は、少しの熱にしかならない。
- 売値は残量を見ない。灯りの残量の設計 261119224218 の「売値は残量で下げない」にそろえる。
- 補充メニューで、満たすか抜くかを選べる。満タンの灯りも並び、補充できる物を持っているのに何も出ない、ということが無い。

## 設計

### データ

```cue
#Charge: {
	max!:          #ChargeAmount
	acceptedFuel?: #FuelKindId

	// 見つかったとき、上限までのランダムな残量で生まれる。作った物と初期装備は満タンで生まれる
	randomOnLoot?: true
}

// 燃料。受ける種別が同じ灯りへ残量を移す
#Refill: {
	kind!:     #FuelKindId
	kind_ref:  _fuelKindIDs[kind] @rawgen(-)

	// 残量が0になったときに置き換わる物。抜くときの入れ物にもなる
	emptiesTo!: #EntityID
	emptiesTo_ref: _itemIDs[emptiesTo] @rawgen(-)
}

// 燃料の種別。抜いたときに作る燃料の物を持つ
#FuelKind: {
	id!:   #FuelKindId
	item!: #EntityID
	item_ref: _itemIDs[item] @rawgen(-)
}

#Item: {
	// 燃料の行は残量を持つ
	if refill != _|_ {
		charge!: _ @rawgen(-)
	}
}
```

```toml
[[fuelKinds]]
  id = "battery"
  item = "battery"

[[fuelKinds]]
  id = "oil"
  item = "lamp_oil"

[[items]]
  id = "battery"

[[items]]
  id = "lamp_oil"
  [items.charge]
    max = 1500
    randomOnLoot = true
  [items.refill]
    kind = "oil"
    emptiesTo = "empty_oil_can"
```

- 燃料の残量も、灯りや武器と同じ `gc.Charge` で持つ。新しいコンポーネントは足さない。
- 燃料の残量は、`ChargeTriggerOf` では使うたびに減る物になる。燃料は殴る物でも照らす物でもないので、攻撃や照らす処理の対象に入らない。ゲージは一覧のアイコンにそのまま出る。
- 使い切った電池 `empty_battery` と空の缶 `empty_oil_can` を新しく足す。どちらも売値を燃料より低くする。既存の `scrap_battery` は重さ 700 g・売値 45 で、電池 50 g・売値 30 と釣り合わないので、電池の空の物には使わず、別のガラクタのまま残す。
- `emptiesTo` の物は燃料にしない。燃料にすると、0 になって燃料に変わり続ける。
- `randomOnLoot` は手提げランタン、懐中電灯、電池、灯油に付ける。松明と武器と道具には付けない。

### 移す

```go
// TransferCharge は from の残量を to へ、to の不足分と from の残りの少ない方だけ移す。移した量を返す
func TransferCharge(world w.World, from, to ecs.Entity) (int, error)
```

- 満たすは、燃料から灯りへ移す。今の `RefillCharge` を置き換える。種別が合わなければ `ErrRefillMismatch`、灯りが満タンなら `ErrChargeFull` を返し、何も移さない。
- 抜くは、灯りの `acceptedFuel` から種別の表の `item` の燃料を引き、その燃料の `refill.emptiesTo` を入れ物にする。持っている入れ物を1つ、`item` の燃料の物に置き換え、残量0のそこへ灯りから移す。入れ物を持っていなければ抜けない。入れ物の上限を超える分は灯りに残る。灯りの残量が0なら抜けない。
- 燃料が0になったら、同じ置き場所で `emptiesTo` の物に置き換える。置き換えは `lifecycle.ReplaceItem(world, item, rawID)` に置く。同じ置き場所に新しい物を作り、元の物を `lifecycle.RemoveItem` で消し、持ち主に重さと灯りを計算し直させる。`ChangeItemCount` は同じ物の数を変えるだけなので使えない。移す処理と `ConsumeCharge` の両方がこれを通す。燃料の残量は今は移す処理でしか減らないが、後で燃料に別の使い道を足しても、`emptiesTo` を通らずに消えることが無い。消すのは `lifecycle.RemoveItem` を通し、持ち主に重さと灯りを計算し直させる。
- 満たすと抜くを繰り返しても、燃料の物と空の物の数の合計は変わらない。テストで固定する。
- 売値は残量を見ないので、灯りを通して燃料を小分けにすると売値の合計は増える。増える分は、使い切った燃料から出た空の物の数で頭打ちになる。受け入れる。
- 2つの燃料が同じ `emptiesTo` を持つと、空の物からどの燃料に戻すかは `fuelKinds.item` で決まるので一意だが、まぎらわしい。CUE で `emptiesTo` の重複を禁じる。
- 補充メニューの燃料は、今の給油メニューと同じく持ち物から並べる。床の燃料では満たせない。
- 灯りが0から戻ったときと、0になったときは、持ち主に `StatsChanged` を付け、視界を計算し直させる。今の補充と同じ。

### 燃やすときの熱

- 灯油は材質が油なので、焚き火やキューブにくべられる。今の熱量 `query.HeatContent` は材質と重さで決まり、残量を見ない。
- 燃料の行の物の熱は、材質と重さの熱に残量の割合を掛ける。松明や武器など、燃料でない残量を持つ物の熱は今のまま変えない。残量の少ない灯油は少しの熱にしかならず、灯りの残量から熱を生み出す抜け道も無くなる。
- 重さを残量に比例させる案は、持ち物の重さの計算全体に波及するので採らない。

### 見つかったときの残量

- 生成の関数 `lifecycle.SpawnFieldItem`・`SpawnStorageItem` は今のまま満タンで作る。見つかる物を置く呼び出し側が、生成した後に `randomOnLoot` を持つ物の残量を 1 から上限までのランダムに書き換える。
- 生成の関数は count 個を作っても代表の1個しか返さない。生成の直後は作った物がすべて同じスタックなので、代表と同じスタックの物をすべて、1個ずつランダムにする。`lifecycle.RandomizeLootCharge(world, rep, rng)` にまとめる。
- 見つかる物を置く呼び出し側は、`internal/mapspawner/spawner.go` の床と収納、`internal/overworld/loot_scatter.go`、`internal/overworld/facility_loot.go` の床と収納。乱数は、その場で物を選ぶのに使っている乱数をそのまま使い、同じシードなら同じ残量になる。
- 満タンのままにするのは、作る、初期装備、商人の品 `lifecycle/merchant.go`、分解で出る物、燃えかすと死体の素材、デバッグの木箱。商人の品は満タンにして、買う意味を持たせる。分解と燃えかすと死体からは燃料も灯りも出ない。

### 補充メニュー

1. 1段目は、持っている、燃料を受ける灯りを満タンの物も含めて並べる。各行に一覧と同じアイコンとゲージを出す。
2. 灯りを選ぶと、「満たす」と「抜く」を選ぶ。満タンなら「満たす」を、残量0なら「抜く」を、選べない行にする。
3. 「満たす」は、今の給油メニューを灯りのくべ先で開く。燃料の行に、移せる量 `min(灯りの不足分, 燃料の残量)` を出し、選ぶと移す。灯りが満タンになったら閉じる。満タンのとき、合う種別の燃料を1つも持たないときは、選べない行にする。
4. 「抜く」は、入れ物を1つ使ってすぐに移し、ログに出す。残量0のとき、入れ物を持たないときは、選べない行にする。

- 補充できる灯りを1つも持たないときだけ「補充できる物が無い」を出す。

### スタック

残量の違う燃料は別のスタックになる。拾い集めた電池は残量ごとに別の行に並ぶ。今の松明や武器と同じ扱いで、それぞれのゲージで残りが見える。

## 採用しなかった方法

- **燃料は今のまま、1つで満タンにする**: 拾う燃料に差が無く、使い回しの判断が生まれない。拾った満タンの懐中電灯が補充メニューに出ず、補充できないように見える。
- **使い切った燃料を消す**: 単純だが、使い切った電池が売れるガラクタとして既にある。空の物が残ると、拾い集めの遊びにつながる。
- **使い切った燃料を残量0のまま残す**: 充電の仕組みを後で足す余地は残るが、今は使い道が無く、空の電池が持ち物に溜まる。
- **抜くを持ち物の動詞にする**: 持ち物の動詞のタブは7つで横幅が足りない。燃料の出し入れを補充メニューにまとめる。
- **抜くと、入れ物なしで燃料の物ができる**: 初めの案。満たすと燃料が空の物に変わり、抜くと燃料の物が無から作られるので、繰り返すと空の物が無限に増え、売れば金も湧く。入れ物を使う形にして、物の数を保存する。
- **抜く先を、持っている同じ種類の満タンでない燃料に限る**: 新しい物を作らないので増えないが、使い切った後に抜けない。
- **売値と熱を残量の割合で比例させるだけにする**: 増える物の価値は抑えられるが、空の物が増え続けることは変わらない。熱は割合で比例させるが、それだけでは足りない。
- **電池の空の物に既存の `scrap_battery` を使う**: 重さと売値が電池と釣り合わない。
- **燃料だけランダムにし、灯りは満タンで生む**: 拾った懐中電灯が満タンだと、抜いて使い回す判断が生まれにくい。
