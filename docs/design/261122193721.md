# 燃料に残量を持たせ、灯りとの間で移す

## 背景

灯りの残量の設計 261119224218 で、手提げランタンと懐中電灯を、灯油と電池で補充できるようにした。今の補充は、燃料を1つ使うと灯りが満タンに戻る。燃料はそれ自体の量を持たない。

この形では、燃料を拾うことが「満タン1回分」を拾うことと同じになり、選ぶことが無い。拾った懐中電灯も満タンで生まれるので、補充メニューに出ず、補充できないように見える。

燃料にも残量を持たせ、灯りとの間で量を移す形にする。電池は 1000 のように量を持ち、0になるまで何度でも灯りへ移せる。見つかる電池や懐中電灯の残量はまちまちで、ほかの灯りから抜いて別の灯りへ入れる、という使い回しが生まれる。廃墟で物を漁って組み合わせる遊びに合う。

## 要件

- 燃料の行は残量を持つ。補充は、灯りの不足分と燃料の残りの少ない方を移す。燃料は残りが0になるまで使える。
- 燃料は入れ物として扱う。残量が0になっても別の物に変わらず、残量0の電池や灯油缶として残る。
- 灯りから燃料を抜ける。抜く先は、同じ種別の満タンでない燃料。残量0の燃料にも、使いかけの燃料にも抜ける。満たすと抜くは同じ「2つの入れ物の間で残量を移す」処理で、物の数は変わらない。
- 見つかる燃料と灯りは、上限までのランダムな残量で生まれる。作った物、初期装備、商人の品、デバッグメニューの木箱は満タンで生まれる。
- 燃料を燃やすときの熱は、残量の割合で決める。残量の少ない灯油は、少しの熱にしかならない。
- 燃料の売値は残量の割合で決まり、残量0の燃料は価値0になる。灯りの売値は灯りの残量の設計 261119224218 の「売値は残量で下げない」のまま変えない。
- 補充メニューで、満たすか抜くかを選べる。満タンの灯りも並び、補充できる物を持っているのに何も出ない、ということが無い。

## 設計

### データ

```cue
#Charge: {
	// 残量の上限。灯りはターン数、武器と道具は回数、燃料は灯りへ移せるターン数
	max!:          #ChargeAmount
	acceptedFuel?: #FuelKindId
}

// 燃料。受ける種別が同じ灯りとの間で残量を移す。残量0でも残り、抜くときの入れ物になる
#Refill: {
	kind!:    #FuelKindId
	kind_ref: _fuelKindIDs[kind] @rawgen(-)
}

#Item: {
	// 燃料は残量を持ち、燃料を受けない。空文字は燃料の種別の id にならないので、受ける種別を書くと落ちる
	if refill != _|_ {
		charge!: _ @rawgen(-)
		charge: {acceptedFuel?: ""} @rawgen(-)
	}
}
```

```toml
[[items]]
  id = "battery"
  [items.charge]
    max = 1000
  [items.refill]
    kind = "battery"

[[items]]
  id = "lamp_oil"
  [items.charge]
    max = 1500
  [items.refill]
    kind = "oil"
```

- 燃料の残量も、灯りや武器と同じ `gc.Charge` で持つ。新しいコンポーネントは足さない。
- 燃料の残量は、`ChargeTriggerOf` では使うたびに減る物になる。燃料は殴る物でも照らす物でもないので、攻撃や照らす処理の対象に入らない。分類の意味とは少しずれるが、今これを見るのは攻撃だけなので、分類は足さない。`ChargeTriggerOf` の doc に、燃料は灯りへ移すときだけ減ると書く。ゲージは一覧のアイコンにそのまま出る。残量0の燃料もゲージで空と見せ、名前は変えない。灯りも0のとき名前を変えない。
- 残量を移し合う物は、燃料と燃料を受ける灯り。`query.ChargeKindOf(world, item)` が、灯りなら受ける種別を、燃料なら自分の種別を返す。移す処理、0になっても残す判定、見つかったときのランダムがこれを使う。手提げランタン、懐中電灯、電池、灯油が当たり、松明と武器と道具は当たらない。

### 移す

```go
// TransferCharge は from から to へ、to の空きと from の残りの少ない方を移し、移した量を返す。
// 燃料から灯りへ満たすのも、灯りから燃料へ抜くのもこれを通す
func TransferCharge(world w.World, from, to ecs.Entity) (int, error)
```

- 満たすは `TransferCharge(燃料, 灯り)`、抜くは `TransferCharge(灯り, 燃料)`。種別が合わなければ `ErrRefillMismatch`、受け側が満タンなら `ErrChargeFull`、出し側が0なら `ErrChargeEmpty` を返し、何も移さない。
- 抜く先の燃料の上限を超える分は灯りに残る。今の raw は、手提げランタンと灯油、懐中電灯と電池の上限をそろえているので、空の燃料へ抜けば実データでは超えない。上限をそろえるのは、満タンの燃料1つで灯りが満タンになる今の手触りを保つため。超える分の分岐はテストで灯りの上限を上げて確かめる。
- 使いかけの燃料にも抜けるので、灯りを通して残量の違う燃料をまとめ直せる。拾った燃料が残量ごとに細かい束に分かれても、寄せて束を減らせる。
- 抜いて灯りが0になったときは「切れた」のログを出さない。抜いたときのログと重なる。灯りが0になれば照らさなくなるので、持ち主に `StatsChanged` を付け、視界を計算し直させる。
- 燃料が0になっても物は残る。`ConsumeCharge` は、`ChargeKindOf` が種別を返す物を0で残し、それ以外を消す。燃料の残量は今は移す処理でしか減らないが、後で燃料に別の使い道を足しても、0で入れ物として残る。
- 移しても物は作らず消さないので、物の数は変わらない。満たして抜くを繰り返しても残量の合計は変わらない。テストで固定する。
- 補充メニューの燃料も、抜く先の燃料も、今の給油メニューと同じく持ち物から並べる。床の燃料は使えない。
- 灯りが0から戻ったときと、0になったときは、持ち主に `StatsChanged` を付け、視界を計算し直させる。今の補充と同じ。`TransferCharge` と `ConsumeCharge` のどちらも、この扱いを `gameaction` の1つの関数 `syncCarrierLight(world, light, before)` で行う。灯りの残量が0の境目をまたいだかを `before` と今の残量で見て、またいでいれば持ち主に写し直させる。灯りでない物には何もしない。

### 売値

- 燃料の売値は、価値に残量の割合を掛ける。`query.GetItemValue` で掛けるので、売値と買値と表示がそろう。残量0の燃料は価値0。
- 燃料を小分けにしても、残量の合計が変わらないので売値の合計も増えない。割合の切り捨ての分だけ、小分けにすると合計がわずかに下がる。
- 灯りの売値は残量で変えない。灯りの残量の設計 261119224218 の決めごとのまま。

### 燃やすときの熱

- 灯油は材質が油なので、焚き火やキューブにくべられる。今の熱量 `query.HeatContent` は材質と重さで決まり、残量を見ない。
- 燃料の行の物の熱は、材質と重さの熱に残量の割合を掛ける。松明や武器など、燃料でない残量を持つ物の熱は今のまま変えない。残量の少ない灯油は少しの熱にしかならず、灯りの残量から熱を生み出す抜け道も無くなる。
- 燃料を焚き火やキューブにくべると、中身だけが燃え、入れ物が残量0で同じ置き場所に残る。今の `lifecycle.AddFuel`・`AddCubeFuel` はくべた物を消すが、燃料の行だけは残量を0にして残す。熱は残量を0にする前に測る。残量0の燃料は熱が0なので、もう燃やせる物の一覧に出ない。
- 床に置いた灯油に火をつけると、`executeIgnite` もタイルの燃える物を `AddFuel` に渡すので、火のタイルに残量0の灯油缶が残る。
- キューブのタンクが満タンに近くても、`AddCubeFuel` は入る分で切り捨てて燃料を丸ごと使い、灯油は残量0になる。今もくべた物は丸ごと消える形で、それを受け入れる。入る分だけ残量を減らすには熱と残量の換算が要るので、別の設計に回す。
- 割合を掛けた熱は、残量が1以上なら最低1にする。燃やせる物かの判定 `query.IsCombustible` は熱が0より大きいかなので、丸めで0になると、焚き火とキューブの一覧から消えてしまう。
- 重さを残量に比例させる案は、持ち物の重さの計算全体に波及するので採らない。残量0の灯油缶も 500 g のまま。重さは残量で変えない、の決めごとの帰結として受け入れる。

### 見つかったときの残量

- 生成の関数 `lifecycle.SpawnFieldItem`・`SpawnStorageItem` は今のまま満タンで作る。見つかる物を置く呼び出し側が、生成した後に `query.ChargeKindOf` が種別を返す物の残量を書き換える。残量は上限の 1/4・2/4・3/4・4/4 の4段階からランダムに選ぶ。各段階は `max(1, 上限 × k / 4)` で、上限が小さくても残量0の燃料を作らない。1 から上限までの一様にすると、残量の違う物は別のスタックになるので、拾った燃料がほぼ1個ずつ別の行に並ぶ。4段階なら遊びの差は残り、同じ段階の物は束になる。
- 生成の関数は count 個を作っても代表の1個しか返さない。代表と同じスタックの物をまとめて書き換えると、同じ場所に先に置いた同じ物まで巻き込む。そこで、生成の関数の中に、作った物をすべて返す内部の関数を足し、作った物だけを1個ずつランダムにする。見つかる物を置く経路は `lifecycle.SpawnFieldLoot`・`SpawnStorageLoot` を呼ぶ。生成とランダムを1つの関数にまとめ、呼び出し側がランダムにし忘れる余地を無くす。
- 残量の乱数は、その物を選んだ乱数からそのまま引く。地図は `MetaPlan.RNG`、施設は `spawnFacility` の物の乱数、散布は物の抽選の乱数。生成の関数 `SpawnFieldLoot`・`SpawnStorageLoot` は、呼び出し側から乱数を受け取る。
  - 燃料と灯りの数で乱数の消費が変わり、物の定義を変えると後の抽選がずれる。戦利品の表の行や重みを変えても同じことは起きるので、今の生成がもとから受け入れている性質として受け入れる。
- 満タンのままにするのは、作る、初期装備、商人の品 `lifecycle/merchant.go`、分解で出る物、燃えかすと死体の素材、デバッグメニューの木箱、イベントなどが持ち物へ物を足す `lifecycle.ChangeStackCount`。`ChangeStackCount` は、残量が半分の電池のスタックを増やしても満タンの電池が別の行にでき、元のスタックの個数は増えない。デバッグメニューの木箱 `states/debug_menu.go` には燃料も灯りも入っていない。地図に置く prop の `debug_crate` は `mapspawner` の収納の経路を通るので、ほかの見つかる物と同じくランダムになる。デバッグでランダムな残量を確かめられるので、除外しない。商人の品は満タンにして、買う意味を持たせる。分解と燃えかすと死体からは燃料も灯りも出ない。

### 補充メニュー

1. 「満たす」と「抜く」の2つのタブを持つ。どちらのタブにも、持っている燃料を受ける灯りを満タンの物も含めて並べ、各行に一覧と同じアイコンとゲージを出す。
2. 選べる行の右には移せる量の上限を出す。満たすタブは灯りの空き、抜くタブは灯りの残量。
3. 選べない行はカーソルを止めず、右に理由を出す。文字色はほかの物の一覧と同じにし、選択肢メニューの淡色は使わない。満たすタブは、灯りが満タンなら「満タン」、残量のある合う燃料を持たなければ「燃料が無い」。抜くタブは、灯りが0なら「空」、満タンでない合う燃料を持たなければ「入れ物が無い」。
4. 満たすタブで灯りを選ぶと、給油メニューを灯りのくべ先 `LightFuelSink` で開く。残量のある同じ種別の燃料を並べ、各行に移せる量 `min(灯りの不足分, 燃料の残量)` を出し、選ぶと移す。灯りが満タンになったら閉じる。
5. 抜くタブで灯りを選ぶと、給油メニューを抜く先 `LightDrainSink` で開く。同じ種別の満タンでない燃料を並べ、各行に移せる量 `min(燃料の空き, 灯りの残量)` を出し、選ぶと移してログに出す。灯りが0になるか、抜く先が無くなったら閉じる。

- 補充できる灯りを1つも持たないときは、どちらのタブにも「補充できる物が無い」を出す。

### スタック

残量の違う燃料は別のスタックになる。拾い集めた電池は残量ごとに別の行に並ぶ。今の松明や武器と同じ扱いで、それぞれのゲージで残りが見える。

## 採用しなかった方法

- **見つかったときにランダムにするかを、残量の欄 `randomOnLoot` で行ごとに選ぶ**: ランダムにする物は残量を移し合う物とちょうど一致し、`refill` と `acceptedFuel` から導ける。欄にすると、燃料や補充できる灯りを足したときに書き忘れて満タンで見つかる。移し合わない物をランダムにしたくなったら、そのとき欄を足す。

- **燃料は今のまま、1つで満タンにする**: 拾う燃料に差が無く、使い回しの判断が生まれない。拾った満タンの懐中電灯が補充メニューに出ず、補充できないように見える。
- **使い切った燃料を消す**: 単純だが、抜く入れ物が無くなり、灯りの残量を燃料に戻せない。
- **使い切った燃料を、空の電池や空の缶のような別の物に置き換える**: PR #1061 の初めの実装。空の物を抜く入れ物にし、抜くと燃料の物に戻す。置き換えのために、空の物の行、燃料の行から空の物を指す欄、種別の表から燃料を指す欄、置き場所を保って置き換える処理、表をまたぐ CUE の検査4つが要った。燃料を入れ物として残量0で残せば、どれも要らず、使いかけの燃料にも抜けてまとめ直せる。
- **抜くを持ち物の動詞にする**: 持ち物の動詞のタブは7つで横幅が足りない。燃料の出し入れを補充メニューにまとめる。
- **抜くと、入れ物なしで燃料の物ができる**: 初めの案。満たすと燃料が空の物に変わり、抜くと燃料の物が無から作られるので、繰り返すと空の物が無限に増え、売れば金も湧く。入れ物を使う形にして、物の数を保存する。
- **燃料の売値は残量を見ない**: 灯りとそろうが、残量0の燃料が満タンと同じ値で売れる。
- **燃料だけランダムにし、灯りは満タンで生む**: 拾った懐中電灯が満タンだと、抜いて使い回す判断が生まれにくい。
