# スキル成長の決定論的メトリクスと調整基盤

## 背景

バランス導出は固定プレイヤーの静的な保守下限で、スキル成長を意図的に含めない。詳細は `docs/balance/approach.md` の「導出の前提。静的な保守下限」。そのためスキルの成長パラメータ、すなわち `internal/skill/growth.go` の `growthConfig`(BaseExp・AbilBonus・DecayPerLevel・MaxLevel)を触っても baseline.md は動かず、調整の目安が無い。

武器は戦闘メトリクスの入力そのものなので既存ワークフローで調整できるが、スキル成長には対応する導出メトリクスが未実装。ここを埋めて、戦闘と同じ「目標×導出×凍結ゲート」の枠でスキルを調整できるようにする。

## 要件

- 決定論的。乱数を使わず、能力値を与えれば一意に定まる。
- 単一出典。成長式を `balance` 内に再実装しない。実物の `skill.GainExp` をそのまま使う。式が変われば自動追従する。
- 行動非依存。主メトリクスは「Lv N 到達に要する攻撃回数」。経過日への写像は攻撃頻度という行動依存量が要るので主メトリクスに含めない。静的下限の思想に合わせる。

## 設計

成長は1攻撃ごとに `exp = max(growthSpeed.ApplyInt(BaseExp)*100/decay, 1)` を加算し、`Exp.Current` が `LevelUpExp(=100)` に達すると `Value++`。`growthSpeed = 100 + 能力値*AbilBonus`、`decay = 100 + スキル値*DecayPerLevel`。スキル値が上がるほど減衰で1攻撃の exp が減る。

再実装せず、実物 `skill.GainExp` を決定論的に反復して攻撃回数を数える。

```go
// internal/balance/growth.go
// AttacksToSkillLevel は能力値 abilityValue で、スキルを Lv0 から targetLevel へ上げるのに要する
// 攻撃回数を返す。実物の skill.GainExp を反復適用して数えるので式を再実装しない。
func AttacksToSkillLevel(abilityValue, targetLevel int) int {
    if targetLevel <= 0 || targetLevel > skill.MaxLevel() {
        return 0
    }
    s := &gc.Skill{Exp: gc.IntPool{Max: gc.LevelUpExp}}
    attacks := 0
    for s.Value < targetLevel {
        skill.GainExp(s, abilityValue)
        attacks++
    }
    return attacks
}
```

`skill.MaxLevel()` は `growthConfig.MaxLevel` を world 抜きで参照する公開窓。上限超過の targetLevel は無限ループになるので弾く。exp は常に 1 以上なので MaxLevel 未満なら必ず有限回で到達する。

基準の能力値は静的下限の思想で最も遅い `abilityValue = 0`(成長ボーナスなし)を既定にする。能力が高いほど速いのは高位ケースとして別途見る。

## 採用しなかった方法

- **成長式を balance に再実装**。単一出典が崩れ、`growthConfig` 変更に追従しない。実物 `GainExp` の反復で代替。
- **経過日 d での到達スキル値を主メトリクスにする**。攻撃頻度という行動依存量が要り、静的下限に載らない。攻撃回数を主にし、日への写像は将来の C 層に残す。

## コメント

戦闘・生存・物流・経済に続く5つ目の導出ドメイン。目標は人が決める。例として「主要武器スキルが実プレイの想定攻撃回数で程よく上がる」を攻撃回数で表現できるようになる。
