# ゲーム段階ごとの想定ビルドで後半のブレを抑える

## 背景

バランス導出は強化なし固定プレイヤーの静的な下限で評価している。詳細は `docs/balance/approach.md` の「導出の前提。静的な保守下限」。この下限は「最弱でもこれだけは成立する」を保証するが、実プレイの後半で起きる**ブレ**を見せない。

後半はスキル成長・装備・バフで戦力が大きく振れる。強ビルドは後半を無双し、噛み合わないビルドは詰む。下限カーブだけを見ていると、この後半のブレが設計の視界に入らない。

## 要件

- ゲーム段階、例えば序盤・中盤・終盤ごとに目標を決める。
- 各段階で数種類の**想定ビルドパターン**、例えば近接特化・遠隔特化・耐久型のスキルと装備を用意する。
- 各パターンで戦力比カーブを評価し、後半の目標帯を「下限」だけでなく「想定ビルドの帯」で見る。最強ビルドと最弱ビルドの戦力比差、すなわちブレ幅を設計内に収める。

## 設計（スケッチ）

- `balance/metrics.go` の `DifficultyCurve` にビルドプロファイル、すなわち能力値・武器・スキル値の組を渡せるようにする。現在の固定プレイヤーは「下限プロファイル」の1つとして扱う。
- 代表ビルドを2〜4種プロファイル化し、各カーブを出す。段階別目標帯と付き合わせ、ブレ幅を1指標にする。
- スキル値はビルドの入力になるので、`balance/growth.go` の成長メトリクスと繋ぎ、想定プレイ時間での到達スキルをプロファイルへ反映できる。

## 採用しなかった方法（現時点）

- モンテカルロで実ビルド分布を測る。行動依存で重く、まずは代表プロファイルの決定論評価で十分。必要なら後段で足す。

## コメント

`approach.md` の静的下限の思想は保ったまま、その上に「想定ビルドの帯」を重ねる位置づけ。着手時は段階の切り方と代表ビルドの定義を先に決める。目標帯ダッシュボード(`balance/targets.go`)の段階別・ビルド別への拡張とも繋がる。
