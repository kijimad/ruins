# 施設の多様化

## 背景

オーバーワールドの施設は house・store・office・depot・antique・clinic・lab の7種が定義されているが、プレイヤーには家しか無いように見え、家には不自然な物が出る。施設ごとのリスクとメリットに差が無く、探索の選択が単調になっている。原因は3つある。

**戦利品が施設でなく家具で決まる。** 収納家具の中身は prop の `storage.lootTableId` だけで決まり、施設の種別を見ない。家のタンス・本棚・樽は共通の表 `storage_box` を引き、その中身は何でも入りの `materials` と `junk`、`early_armor`・`midgame_armor` になる。家のタンスから鎧や原子核が出る。店の商品棚 `store_shelf` は銃の組を含むので、コンビニや骨董品店の棚から銃が出る。目玉の置物 hero も施設を問わず家に置かれる。

**種別が違っても中身がほぼ同じ。** antique は store と、lab は clinic と、敵の表以外が同一になっている。office と depot は奥の部屋が全部「樽と菓子」になる。

**珍しい施設に出会えない。** 市街地は6行に1つで幅は2〜3列なので、北へ進むと素通りしやすい。住宅地では house が多数派になる。antique と lab は都心、すなわち 3×3 の市街地の中心1マスにしか出ず、市街地あたり約0.05棟しか無い。原野のランドマークも家に見える物が多い。

## 要件

- 同じ家具でも、置かれた施設に合った戦利品が出る。家のタンスから鎧や銃は出ない
- 施設ごとにリスクとメリットが違う。危険な施設ほど見返りが大きい
- 新しい施設として銃砲店・軍基地・倉庫・発電施設を足す
- antique と lab に、store と clinic とは違う間取りと家具を与える
- 北へ進む道中で、特殊な施設に実際に出会える

## 設計

3段に分けて進める。各段は単独で遊びが良くなり、後段の土台になる。

### 1段目: 施設ごとの戦利品

部屋の定義の家具の行に、その家具の中身を引く戦利品表を直接書く。どの部屋のどの家具から何が出るかを、部屋の定義の1行で読めるようにする。冗長でも、既定と差し替えを頭で合成しなくて済む明示的な定義を選ぶ。

```tsp
/** 内装レシピの1配置指示 */
model ContentStuff {
  kind: StuffKind;
  ref: EntityID;
  weight?: EntryWeight;
  amount: Dice;
  placement?: Placement;
  satellites?: ContentSatellite[];
  /** 収納家具の中身を引く itemTables の id。収納家具では必須 */
  lootTable?: EntityID;
}

/** 衛星にも収納家具があるので同じく書く */
model ContentSatellite {
  kind: StuffKind;
  ref: EntityID;
  offsets: ContentVec[];
  lootTable?: EntityID;
}

model Facility {
  id: EntityID;
  isShop: boolean;
  planner: PlannerKey;
  enemyTable: EntityID;
  zones: FacilityZone[];
  /** 収納家具が荒らされて空になっている確率。0から100の百分率で、省略は0 */
  @minValue(0) @maxValue(100) lootedChance?: int32;
}
```

```go
// interior の配置に表を運ぶ
type Placed struct {
	Kind      StuffKind
	Ref       string
	Pos       Vec
	LootTable string // 収納家具の中身を引く itemTables の id。収納でなければ空
}

// 変更前。prop の storage.lootTableId から引く
func populateStorageLoot(world w.World, entity ecs.Entity, propName string, rng *rand.Rand) error

// 変更後。部屋の定義が書いた表から引き、施設 fac の荒らされ率で空のまま残す
func populateStorageLoot(world w.World, entity ecs.Entity, propName, tableID, fac string, rng *rand.Rand) error
```

- 収納家具の行には `lootTable` を必須にする。部屋の定義を全て舐めるテストで書き漏れを落とし、実行時も表の無い収納家具は error にする。書き漏れが黙って別の表になることを防ぐ
- raw の検証で `lootTable` が実在する itemTables であることを確かめる
- 複数の施設で共有する部屋の定義は、施設ごとに中身が違えば分ける。骨董品店はコンビニの定義を使っていたので `antique_store` を、倉庫は奥室の `storage` を使っていたので `depot_backroom` を作る
- 家具 prop の `storage.lootTableId` は、ダンジョンのように部屋の定義を通らずに家具を置く経路のために残す
- house には衣類・日用品・食料・紙片の表を用意する。不自然な物は家から消える
- 既存の他施設にも施設らしい表を与える。store の棚から銃を外し、銃は2段目の銃砲店へ寄せる
- 施設ごとの荒らされ率 `lootedChance` で、収納家具を確率で空のまま残す。店は棚が多く1棟で家の約5倍が出ていたので、安全な店ほど先に荒らされているとして量を抑える。危険な施設ほど荒らされていない、という差でリスクとメリットを付ける
- 店にしか無い商品棚 `goods_shelf` の中身を `2d4+1` から `1d3` へ減らす

### 2段目: 施設を足し、作り分ける

| 施設 | 危険 | 主な見返り | 中身の作り分け |
|---|---|---|---|
| 倉庫 warehouse | 低 | 素材がまとまって出る | 棚と木箱が並ぶ広い主室。既存の depot を作り直す |
| 銃砲店 gunshop | 中 | 銃と弾薬 | 店の間取りに銃架とカウンター。武装した敵 |
| 発電施設 powerplant | 中 | 電子部品と燃料 | 機械室と制御室。罠や危険物がある |
| 軍基地 military | 高 | 軍用の武器と防具 | 兵舎と武器庫。強い敵 |
| 骨董品店 antique | 中 | 骨董品と希少品 | store と別の陳列。亡霊系の敵は今のまま |
| 研究所 lab | 高 | 研究資料と化学素材 | clinic と別の実験室 |

- 新しい施設は、`[[facilities]]`・`[[enemyTables]]`・`[[facilityContents]]`・`[[interiorContents]]`・`[[facilityRooms]]`・`[[mapGlyphs]]` の各行と、地図の凡例名の訳で足す
- 施設らしい見た目が要る家具だけを新しい prop として足す。例: 銃架、軍用ロッカー、制御盤。中身は部屋の定義の `lootTable` で決める
- hero も施設ごとに候補を持たせ、家に鳥居や毒樽が出ないようにする
- 敵も戦利品と同じく部屋の定義で置く。部屋の定義の種別 `being` は型だけあって生成が捨てていたので、`furnishBuilding` で拾い、危険度に応じて施設の敵の表から1体を引いて置く。Ref は戦利品の対応表と同じく抽象名にし、今は施設の `enemyTable` から引く `occupant` だけを持つ。軍基地の兵士や研究所の検体のように部屋で顔ぶれを変える Ref は、その施設を足すときに個別の敵の表と対応させる。街路の敵は今のまま残す
- 間取りは既存の planner で足りる施設から作る。新しい planner は、既存の部屋の役割で表せない施設だけに足す

### 3段目: 出会いやすくする

- 軍基地と発電施設は、市街地の外に単独の大きな施設として置く。ランドマークと同じく原野へ点在させ、北へ進む道中で目に入るようにする
- 都心以外の地区にも特殊な施設の重みを配り、市街地あたりの珍しい施設を増やす
- 危険度の高い施設を日数で出やすくする案は、地図の表示と生成で施設の種別を一致させる機構が要る。設計 doc 260822014350 が後続作業として切り出しており、この段で扱うか別 doc に分けるかを着手時に決める

## 採用しなかった方法

- **施設の定義で家具の戦利品表を差し替える。** 実際の中身を知るには、家具の既定の表と施設の差し替えの2か所を合成する必要があり、わかりにくい
- **施設ごとに家具の prop を作り分ける。** 銃砲店のタンス、軍基地のタンスのように同じ家具の複製が施設の数だけ増える。見た目が要る家具だけを新しい prop にし、中身の違いは部屋の定義の `lootTable` で表す
- **共通の表から不自然な物を抜くだけにする。** 家は直るが施設ごとの違いが出ず、新しい施設の中身も作り分けられない
- **先に施設の数だけ増やす。** 戦利品が家具で決まるままだと、新しい施設も既存と同じ中身になり、多様性が出ない
