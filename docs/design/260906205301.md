# 疲労・空腹を不調保存でなく読み取り時の導出へ戻す

## 背景

疲労・空腹を Exhaustion・Malnutrition の不調として `HealthStatus` に保存し、量から毎ターン同期していた。だが
この不調は「今の量の純関数」で導出でき、保存する必要がない。保存するから同期が要り、量を直接変える箇所、
例えば debug やアイテム、が同期を忘れると量と不調がずれて効果が反映されない。実際に debug で疲労を最大にしても
Effects に出ないバグが起きた。

Ark には値変更の自動検知が無く、`Fatigue.Current += 1` はイベントを発火しない。だから「保存＋変更検知」は
成立せず、保存する限り同期漏れの余地が残る。ruins の原則 `derivable-state-not-component`、導出できる状態は
component に保存せず読み取り時に導出する、に従い、疲労・空腹の効果を保存せず読み取り時に導出へ戻す。

低体温は Timer で進行する本当に状態を持つ不調なので保存が正しく、対象外。疲労・空腹だけを導出へ戻す。

## 要件

- 疲労・空腹の不調 `Exhaustion`・`Malnutrition` と保存・同期を撤去する。効果は量から読み取り時に導出する。
- 意識 master 乗数と funnel は維持する。疲労・空腹は意識を下げ、意識が局所機能へ乗算される。
- 量を直接変える箇所が同期を呼ぶ必要をなくす。保存が無いのでズレようがない。
- 回復も従来どおり実効意識ベース。挙動は据え置きを狙い、差分が出れば golden 再生成。

## 設計

### 導出は query 層の EffectiveBodyFuncs に集約

`HealthStatus.BodyFuncs` に全身性の追加ペナルティを渡せる口を足す。意識は `100 - 全身性 - 追加ペナルティ`
となり、局所機能はその意識で一度だけ乗算される。再スケールは不要。

```go
// components: 追加の全身性ペナルティを受ける口。既存の BodyFuncs() は 0 を渡す薄いラッパ
func (hs *HealthStatus) BodyFuncs() BodyFuncs            { return hs.bodyFuncs(0) }
func (hs *HealthStatus) BodyFuncsWith(extra int) BodyFuncs { return hs.bodyFuncs(extra) }
func (hs *HealthStatus) bodyFuncs(extraSystemic int) BodyFuncs {
	// systemic += extraSystemic して意識を出し、局所機能へ master 乗算する
}
```

```go
// query: 疲労・空腹の意識低下を量から都度導出して渡す。保存された不調は無い
func EffectiveBodyFuncs(world, entity) gc.BodyFuncs {
	hs := &gc.HealthStatus{}
	if world.Components.HealthStatus.Has(entity) { hs = world.Components.HealthStatus.Get(entity) }
	return hs.BodyFuncsWith(consciousnessPenalty(world, entity))
}

// 疲労・空腹の段階から意識低下量を都度計算する
func consciousnessPenalty(world, entity) int {
	p := 0
	if Fatigue: p += Fatigue.ConsciousnessPenalty()   // Tired 10 / Exhausted 25
	if Hunger:  p += HungerConsciousnessPenalty(level) // Hungry 10 / Starving 20
	return p
}
```

### 撤去するもの

- `ConditionExhaustion`・`ConditionMalnutrition` と conditionDefs の両エントリ。
- `Fatigue.ConditionSeverity`・`HungerConditionSeverity` を `ConsciousnessPenalty`・`HungerConsciousnessPenalty` へ戻す。
- `SetGaugeCondition`・`severityTimer`。低体温は Timer 進行なので使っておらず、これで未使用になる。
- systems の `SyncFatigueCondition`・`SyncHungerCondition`・`syncGaugeCondition` と progressTurn・debug の同期呼び出し。

### 影響しないもの

- 回復 `Metabolism` は `EffectiveBodyFuncs().Consciousness` を読むだけ。意識に疲労・空腹が畳まれるので効果は同じ。
- 不調の float 治癒 `metabScale` は怪我・病気の自己参照停止対策として残す。
- Basic タブは疲労・空腹の段階を表示。Health タブには疲労・空腹は「不調」としては並ばなくなる。

## 採用しなかった方法

- **保存＋機械検知で忘れを防ぐ**: 量の変更を choke point 関数に集約し lint で直接書き込みを禁止する。だが保存＋同期の
  二重管理は残る。Ark に値検知が無い以上、保存をやめるほうが根治。
- **保存のまま同期を毎フレーム走らせる**: 検知の代わりに常時和解する。だが導出できる状態をあえて保存し続ける点は
  derivable-state-not-component に反する。
- **低体温も導出へ**: 低体温は Timer 進行で状態を持つので純関数でなく、保存が正しい。対象は疲労・空腹だけ。

## コメント

保存をやめると「量を変えたら同期」という規律が不要になり、debug やアイテムが忘れても壊れない。意識 master 乗数と
funnel は保ったまま、疲労・空腹だけを純導出へ戻す。意識低下量 Tired/Exhausted=10/25、Hungry/Starving=10/20 は
初期値で実プレイ調整する。
