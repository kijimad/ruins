# 移動拠点キューブを展開式の携行基地へ拡張する

## 背景

キューブの展開/圧縮の土台は完成している。展開で既存機能をフィールドへ出し、圧縮で1タイルへ畳んで運転する。貨物往復と燃料経済も入っている。設計 doc 260920004814 参照。

しかし展開しても露天で、設備も安全も強化も無い。プレイヤーが素材や通貨を投じて能動的にできることが乏しく、フィールドで拠点を強化したり設備を配置したりできない。結果としてプレイヤーの選択肢が薄い。ここを転換する。

過去の方針は「安全を希少に保つ」ため、携行できる安全地帯・歩ける内部・設備を排していた。memory `no-portable-safe-zone-survival` と `cube-visible-upgrades-not-interior`。この2つを本 doc で意図的に転換する。ただし北進の一方通行エスケープというマクロループは維持する。静的なフィールド建築はこのループと衝突するため採らず、**キューブ中心の携行基地**で拠点建築を実現する。展開フットプリントの中に建て、畳めば北へ運べる。建築の楽しさと mobility を両立させる。

## 要件

- プレイヤーが素材/通貨を投じて能動的にできることを増やす。素材の sink とプレイヤーの選択肢を同時に作る。
- 拠点強化はフィールドにタイルとして見える。
- 北進を妨げない。すべて畳んで運べる。静的拠点を作らない。
- survival の緊張は「静的な絶対安全」でなく「コスト付き・展開状態限定の安全」で残す。畳めば安全は消える。

## 設計

強化を2つの軸に分ける。呼び出し側の性質が違う。

- **軸A 論理設備スロット**。空間を消費しない。装備と同様に、工作台で作ったモジュールアイテムをキューブのスロットへ付け替える。装着したアイテムが stat を与える。エンジン・耐久力・展開範囲(共通モジュールで縦横一律に拡張)。
- **軸B 展開グリッドの設備 prop**。展開フットプリントのマスを消費して設備を据える。据付用アイテムを工作台で作り、マスへ据えて prop 化する。ストレージ・工作台・料理・ベッド・ライト・暖房。畳むと既存の貨物往復で畳まれ、拾えばアイテムへ戻る。ライトは照らす位置を選ぶ意味があるのでマスを消費する prop にする。暖房もマスを消費する prop だが、効果は位置に依らず閉鎖した展開空間全体を一律に暖める。位置ごとの計算が要らずシンプル。既存の `HeatSource` を、閉鎖空間全体を暖める形へ簡略化して使う。詳細は下記。

どちらの軸もアイテムを工作台で作って付け替える。工作台自体が軸Bの設備 prop で、将来は工作台の種類で作れるアイテムが変わる。基本工作台で基本モジュール・据付材、上位工作台(溶接機等)で上位、というブートストラップになる。

2軸は結び付く。展開範囲を広げるほど軸Bの設備を置けるマスが増える。範囲拡張が建築キャンバスの拡大になる。展開範囲は共通の拡張モジュールで縦横一律に広げる。当初は縦横を別モジュールで分けて地形に合わせる案だったが、モジュールが2種に増えて煩雑なので、共通1種で一律に伸ばす形に簡略化した。

### データ定義

軸Aは専用の Tier 型を作らず、装着関係の保存 + 読み取り時導出という装備機構のパターンを流用する。ただし具体型 `LocationEquipped` はキャラの `Abilities`・スロット enum・`UnequipAll` とキャラ前提で密結合しているので流用せず、キューブ専用の `LocationCubeModule` を足す。`LocationStowed`（貨物）が同じ `clearLocation` 排他系にキューブ専用で足された前例に倣う。モジュールの性能はアイテム固有なので `CubeModule` コンポーネントに持たせ spawn 時に raw から設定する。装着関係 `LocationCubeModule` と性能 `CubeModule` はどちらも保存し、実効 stat は保存せず読み取り時に導く。導出可能な状態は component にしない方針に沿う。範囲の実効半径は縦横別の `consts.Coord[consts.Tile]` だが、共通モジュールは1つのスカラー `RangeBonus` を持ち、装着でその値を縦横とも一律に加算する。ジオメトリは矩形対応のまま、モジュールは一律拡張に閉じる。

```go
// CubeModule はキューブへ装着するモジュールの性能。展開範囲を X/Y それぞれ何タイル広げるか。
// エンジン燃費・耐久 HP は将来ここへフィールドを足す。値はアイテム固有なので保持する。
type CubeModule struct {
	RangeBonus consts.Coord[consts.Tile]
}

// LocationCubeModule はキューブに装着したモジュールであることを示すロケーション。Owner は装着先のキューブ。
// 他ロケーションと排他。装着関係を保存し、実効 stat は導出する。
type LocationCubeModule struct {
	Owner ecs.Entity
}
```

まず共通の展開範囲モジュールを実装する。エンジン燃費・耐久 HP は同じ `CubeModule` にフィールドを足し `CubeDeployRange` と同型の導出を書く将来の別スライス。

軸Bは新しい型を足さず、据付用アイテムと prop の往復に乗せる。据付用アイテムは deployable として持ち、展開フットプリントのマスへ据えると `Prop` + `Interactable`（設備ごとの `InteractionKind`）の通常の prop になる。圧縮時は既存の `LocationStowed`（相対オフセット保持）で畳まれ、拾えばアイテムへ戻る。設置アイテムとフィールド設置物の往復は deployable-item の方針に沿う。往復機構は実装済みなので、新規は「据付用アイテムを工作台で作る」ことと「各設備の効果」だけ。ただしライトだけは Interactable を持たず既存 `LightSource` を出す受動 prop なので、`InteractionKind` には加えず exhaustive スイッチの対象外にする。

### 展開範囲を建築キャンバスにする

`consts.CubeDeployCampRadius = 2`（正方の一律半径）を、装着した展開範囲モジュールから導く `consts.Coord[consts.Tile]` の縦横別半径へ置き換える。共通モジュールは縦横を一律に伸ばすので実効範囲は正方のままだが、ジオメトリは矩形対応にしておく。展開フットプリントは正方でなく W×H の矩形になる。展開判定 `deploySpaceFree`、畳み込み `stowNearbyItems`、レーザー壁描画が縦横それぞれの半径を参照する。判定は現行の chebyshev 距離から `dx <= rangeX && dy <= rangeY` の直積へ変える。chebyshev は矩形では使えないので置き換える。モジュール未装着の初期範囲は現行の 2 を縦横とも引き継ぎ、バランスの起点にする。

野営フットプリントは展開した時点の範囲を `Deployed.Range` に凍結する。展開は「その広さが空いているか」を判定してから開き、畳むときは同じ広さを巻き取ることで「畳むのは自分で置いた物だけ」を保証する。範囲を毎回 `CubeDeployRange` で導出すると、展開中に装備で範囲が伸びたぶん、展開時に空だと検証していない外周まで圧縮で巻き込む。凍結すれば展開中の装備は野営を広げず、拡張は畳んで開き直したとき、その広さの空きを再検証してから反映する。畳み込み `stowNearbyItems` とレーザー壁描画は凍結値を参照し、展開判定 `deploySpaceFree` だけが展開時のライブ範囲を使う。

トレードオフを効かせる。

- 範囲が広いほど設備を多く置けるが、全か無かの展開なので、より開けた場所でしか全開できない。広げるほど四方に開けた場所が要る。狭所では畳んだままか、モジュールを外して小さく開ける。
- 軸Aの強化と軸Bの設備は重量を持ち、`CubeWeight` → `DriveFuelCost` に効く。強くするほど燃費が悪化する。既存の重量→燃費経済をそのまま使う。

### 耐久力の導入

専用型は作らず、キャラクターと同じ既存の `HP` コンポーネント(`Pool[int]`、Current/Max)をキューブにも付ける。`HP.Max` は装着した耐久モジュール由来で加算する。ダメージと回復の算術を流用する。無敵にしないことで「携行拠点でも緊張が残る」を担保する。ただしキャラの死亡経路(`HP.Current == 0` → `Dead` 付与でエンティティ処理)は使わず、キューブは 0 で運転・展開を止め、素材で修理して復帰する。大破の破壊的挙動は将来。

### 安全の扱い（方針転換）

暖房とベッドは安全を与える。ただし静的な絶対安全にはしない。

- **暖房**（軸B）: 閉鎖した展開空間全体を一律に暖める。既存の `HeatSource`（現在はチェビシェフ半径で距離減衰する）を、閉鎖空間の内外だけで効く形へ簡略化して使う。展開したキューブの野営はレーザー壁で閉じた空間なので、内部に熱源があれば野営全体が一律に暖かい。燃料を消費し、畳むと消える。開けた場所の火は暖房効果を持たない。暖は閉鎖空間の内側でのみ得られる。
- **ベッド**（軸B）: 安全な睡眠を与える。展開中のみ。畳むと使えない。

安全は「展開状態限定・コスト付き・畳めば消える」に閉じる。北へ動くには畳むので、移動中は安全を持ち運べない。これで携行基地を許しつつ survival の緊張を残す。暖も同じで、開けた場所の火では暖まれず、閉鎖空間を建てて初めて得られる。暖を拠点建築の報酬に閉じ、野外の緊張を保つ。

## なぜこの形か

- **携行基地は北進ループと建築の両立点**。静的拠点は「北へ逃げ続ける」一方通行と衝突する。キューブに閉じれば、建てて畳んで運ぶことで mobility を保ったまま拠点強化の agency を出せる。CDDA の deathmobile、RimWorld のキャラバンと同じ発想。
- **2軸に分けるのは消費するものが違うから**。軸A は stat で空間を食わない論理強化、軸B はフィールドのマスを食う物理設備。混ぜると「範囲を広げると設備が置ける」というトレードオフが表現できない。
- **既存機構に最大限乗せる**。展開/圧縮・貨物往復・重量→燃費は完成済み。軸B は新型を足さず prop + LocationStowed の往復に乗せ、可変半径は `CubeDeployCampRadius` の一点置換で通す。
- **安全はコスト付き・展開限定に閉じる**。方針転換で安全を許すが、畳めば消える設計にすることで survival の希少性を残す。絶対安全を与えない。

## 採用しなかった代替

- **静的フィールド建築**: フィールドの任意地点に恒久設備を建てる型。自由度は最大だが、北進の一方通行マクロループを再設計する必要があり、ゲームの背骨と衝突する。携行基地なら背骨を保てる。
- **歩ける内部ステージ**: memory `cube-visible-upgrades-not-interior` で撤去済み。別ステージ/深さ層は overworld 主軸方針とも擦れる。フィールドに見える建築で agency を出す方が一貫する。
- **安全を一切与えない（現状維持）**: 緊張は最大だがプレイヤーの選択肢が薄いまま。今回の転換の動機そのものに反する。

## コメント

北進マクロループとの整合が本 doc の肝。静的拠点でなく携行基地に閉じることで、過去方針の転換を局所化する。

転換する過去方針は2つ。`no-portable-safe-zone-survival`（安全を希少に保つ）は暖房・ベッドで覆し、`cube-visible-upgrades-not-interior`（内部・設備を撤去）は軸Bの設備 prop で覆す。いずれも展開状態限定・畳めば消えるに閉じ、北進中は安全も設備も運べない。
