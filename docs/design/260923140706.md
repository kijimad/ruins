# 移動拠点キューブを CDDA/RimWorld 式の携行基地へ拡張する

## 背景

キューブの展開/圧縮の土台は完成している。展開で既存機能をフィールドへ出し、圧縮で1タイルへ畳んで運転する。貨物往復と燃料経済も入っている。設計 doc 260920004814 参照。

しかし展開しても露天で、設備も安全も強化も無い。プレイヤーが素材や通貨を投じて能動的にできることが乏しく、CDDA や RimWorld のような拠点強化・設備配置ができない。結果としてプレイヤーの選択肢が薄い。ここを転換する。

過去の方針は「安全を希少に保つ」ため、携行できる安全地帯・歩ける内部・設備を排していた。memory `no-portable-safe-zone-survival` と `cube-visible-upgrades-not-interior`。この2つを本 doc で意図的に転換する。ただし北進の一方通行エスケープというマクロループは維持する。静的なフィールド建築はこのループと衝突するため採らず、**キューブ中心の携行基地**で拠点建築を実現する。展開フットプリントの中に建て、畳めば北へ運べる。建築の楽しさと mobility を両立させる。

## 要件

- プレイヤーが素材/通貨を投じて能動的にできることを増やす。素材の sink とプレイヤーの選択肢を同時に作る。
- 拠点強化はフィールドにタイルとして見える。
- 北進を妨げない。すべて畳んで運べる。静的拠点を作らない。
- survival の緊張は「静的な絶対安全」でなく「コスト付き・展開状態限定の安全」で残す。畳めば安全は消える。

## 設計

強化を2つの軸に分ける。呼び出し側の性質が違う。

- **軸A 論理設備スロット**。空間を消費しない。キューブの stat を Tier で上げる。エンジン・耐久力・展開範囲・暖房。
- **軸B 展開グリッドの設備 prop**。展開フットプリントのマスを消費して設備を建てる。ストレージ・工作台・料理・ベッド・ライト。プレイヤーの行動を増やす。畳むと既存の貨物往復で一緒に畳まれる。ライトは照らす位置を選ぶ意味があるので、cube 全体の stat でなくマスを消費する prop にする。

2軸は結び付く。軸Aの展開範囲を広げるほど、軸Bの設備を置けるマスが増える。範囲拡張が建築キャンバスの拡大になる。

### データ定義

軸Aは保存 component で持つ。空間を持たない stat の集合。

```go
// CubeUpgrades はキューブの論理設備。スロットごとに Tier を持ち、素材で強化する。空間は消費しない。
// 保存する。Tier 0 は未強化。
type CubeUpgrades struct {
	Engine     int // 燃費。Tier で DriveFuelCost を下げる
	Durability int // 耐久。Tier で既存 HP コンポーネントの Max を上げる
	Range      int // 展開範囲。Tier で展開半径を広げ、建築マスを増やす
	Heating    int // 展開範囲の保温。燃料を消費して暖を供給する。安全に関わる
}
```

軸Bは新しい型を足さず、既存の prop と貨物往復の仕組みに乗せる。設備 prop は `Prop` + `Interactable`（設備ごとの `InteractionKind`）を持つ通常のフィールド prop として展開フットプリント内に建てる。圧縮時は既存の `LocationStowed`（相対オフセット保持）で畳まれ、展開で同配置へ戻る。往復の機構は実装済みなので、新規なのは「設備 prop を素材から作って置く」ことと「各設備の効果」だけ。

### 展開範囲を建築キャンバスにする

`consts.CubeDeployCampRadius = 2` の固定値を、`CubeUpgrades.Range` 由来の可変半径へ置き換える。展開判定 `deploySpaceFree`、畳み込み `stowNearbyItems`、レーザー壁描画がこの半径を参照する。

トレードオフを効かせる。

- 範囲が広いほど設備を多く置けるが、全か無かの展開なので、より開けた場所でしか全開できない。狭所では畳んだままか小さくしか開けない。
- 軸Aの強化と軸Bの設備は重量を持ち、`CubeWeight` → `DriveFuelCost` に効く。強くするほど燃費が悪化する。既存の重量→燃費経済をそのまま使う。

### 耐久力の導入

専用型は作らず、キャラクターと同じ既存の `HP` コンポーネント(`Pool[int]`、Current/Max)をキューブにも付ける。ダメージと回復の算術を流用する。無敵にしないことで「携行拠点でも緊張が残る」を担保する。ただしキャラの死亡経路(`HP.Current == 0` → `Dead` 付与でエンティティ処理)は使わず、キューブは 0 で運転・展開を止め、素材で修理して復帰する。大破の破壊的挙動は将来。

### 安全の扱い（方針転換）

暖房とベッドは安全を与える。ただし静的な絶対安全にはしない。

- **暖房**（軸A）: 展開範囲を暖める。燃料を継続消費する。畳むと消える。
- **ベッド**（軸B）: 安全な睡眠を与える。展開中のみ。畳むと使えない。

安全は「展開状態限定・コスト付き・畳めば消える」に閉じる。北へ動くには畳むので、移動中は安全を持ち運べない。これで携行基地を許しつつ survival の緊張を残す。

## なぜこの形か

- **携行基地は北進ループと建築の両立点**。静的拠点は「北へ逃げ続ける」一方通行と衝突する。キューブに閉じれば、建てて畳んで運ぶことで mobility を保ったまま拠点強化の agency を出せる。CDDA の deathmobile、RimWorld のキャラバンと同じ発想。
- **2軸に分けるのは消費するものが違うから**。軸A は stat で空間を食わない論理強化、軸B はフィールドのマスを食う物理設備。混ぜると「範囲を広げると設備が置ける」というトレードオフが表現できない。
- **既存機構に最大限乗せる**。展開/圧縮・貨物往復・重量→燃費は完成済み。軸B は新型を足さず prop + LocationStowed の往復に乗せ、可変半径は `CubeDeployCampRadius` の一点置換で通す。
- **安全はコスト付き・展開限定に閉じる**。方針転換で安全を許すが、畳めば消える設計にすることで survival の希少性を残す。絶対安全を与えない。

## 採用しなかった代替

- **静的フィールド建築（RimWorld コロニー型）**: 自由度は最大だが、北進の一方通行マクロループを再設計する必要があり、ゲームの背骨と衝突する。携行基地なら背骨を保てる。
- **歩ける内部ステージ**: memory `cube-visible-upgrades-not-interior` で撤去済み。別ステージ/深さ層は overworld 主軸方針とも擦れる。フィールドに見える建築で agency を出す方が一貫する。
- **安全を一切与えない（現状維持）**: 緊張は最大だがプレイヤーの選択肢が薄いまま。今回の転換の動機そのものに反する。

## コメント

北進マクロループとの整合が本 doc の肝。静的拠点でなく携行基地に閉じることで、過去方針の転換を局所化する。
