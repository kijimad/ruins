# 施設を手で描いた絵と部品の組み合わせで作る

## 背景

オーバーワールドの施設は、`internal/mapplanner/interior` が手続きで作っている。planner が区画を部屋に分けて役割を付け、部屋ごとのレシピで家具を置き、荒れ方・小物・外装・外構・目玉の工程を重ねる。参考 codebase: `internal/mapplanner/interior/furnish.go`、`internal/overworld/interior_furnish.go`。

この形では、家や店に見せる調整が収束しない。

- **部屋どうしのつながりを規則で表しにくい。** 玄関から居間、居間から台所のような関係や、店の売り場と倉庫の位置関係を、部屋の分け方と役割の付け方だけで決めている。
- **広い通路を作れない。** 部屋の間は幅1の戸口でしかつながらず、店の通路や廊下の広がりを表せない。
- **家具の並びが規則の積み重ねになる。** 壁沿い・扉から遠く・中央のような置き方の規則を足しても、人が見て自然な並びに近づかない。

一方、手で描いた ASCII の絵を部品として組み合わせる仕組み `internal/maptemplate` がすでにある。地図の文字の意味をパレットで決め、入れ子の部品を重み付きで選んではめる。今はダンジョンとデバッグ用の5枚にしか使っていない。参考 codebase: `internal/maptemplate/template.go`、`assets/levels/`。

## 要件

1. 施設の建物は、間取りから家具の並びまで人が描いた絵で作る。
2. 1つの施設でも見た目が毎回変わる。同じ間取りでも家具・中身・荒れ方が変わる。
3. 収納の中身の表、荒らされ率、建物の中の敵、扉、屋内の判定は、今の施設と同じく働く。
4. 生成は今と同じく、run の seed とチャンクの座標から決まる。
5. 手続きで部屋を分ける仕組みは、全施設を移したあとに消す。

## 設計

変化は次の段を重ねて出す。着想は既存のローグライクのマップ生成の作り方で、絵の枚数と、同じ絵を描き分ける仕組みの両方から変化を作る。

| 段 | 出し方 |
|---|---|
| 間取り | 施設ごとに複数の絵を描き、重みで選ぶ |
| 生活ぶり | 同じ絵を別のパレットで描き分ける。普通・荒らされた・散らかった、のように建物ごとにパレットを選ぶ |
| 家具 | パレットの1文字が、家具の候補を重み付きで持つ |
| 部品 | パレットの1文字の位置に、小さな部品を重み付きで置く。何も置かない候補も持てる |
| 向き | 入口の向きに合わせて絵を回し、左右も反転する |
| 中身 | 収納の中身の表と床の戦利品を、文字に結び付けて引く |

### 区画と向き

区画は 20×20 に固定する。チャンクは 24×24 で、北と西に幅4の街路を敷くので、残りがちょうど 20×20 になる。今は区画の大きさを 17〜20 で揺らしているが、揺らぎは絵の中の前庭で表す。

施設の絵は 20×20 で、入口を北の辺に向けて描く。入口を西の街路へ向ける区画では、絵を左へ90度回して置く。どちらの向きでも、左右の反転を半々で選ぶ。

### テンプレートの形式

`maptemplate` の `[[chunk]]` に、施設と重みを書く欄を足す。

```toml
[[chunk]]
name = "20x20_house_bungalow"
facility = "house"       # この絵を使う施設。施設の絵でなければ省く
weight = 100
palettes = ["house"]     # 候補が複数あれば建物ごとに1つ選ぶ
map = """
....................
.~~~~~~~~~~~~~~~~~~.
.~######+#######~~~.
...
"""
```

パレットは、文字ごとに候補を重み付きで持てるようにする。

```toml
[palette]
id = "house"
weight = 100             # 同じ施設の候補パレットの中での重み

[palette.terrain]
"#" = "wall"
"." = "dirt"             # 屋外の地面。屋外として扱う
"~" = "floor"            # 屋内の床。屋内として扱う

[palette.props.d]
tile = "floor"
candidates = [{ id = "dresser", weight = 2 }, { id = "bookshelf", weight = 1 }]
lootTable = "house_closet"   # 収納の中身を引く itemTables の id。収納でなければ省く

[palette.nested.T]
# この文字の位置を左上に、部品を1つ置く。null は何も置かない
chunks = [{ name = "2x2_table_set", weight = 3 }, { name = "null", weight = 1 }]

[palette.items.f]
tile = "floor"
itemGroup = "food"       # 床に落ちる戦利品

[palette.beings.Z]
tile = "floor"           # 施設の敵の表から危険度に応じて1体置く

[palette.doors.+]
tile = "floor"           # 扉。向きは左右か上下の壁から決める
```

```go
// internal/maptemplate の解決結果。今の MapCell を広げる
type MapCell struct {
	Terrain   string
	Prop      string // 候補から選んだ prop の id
	LootTable string // 収納の中身を引く itemTables の id
	ItemGroup string // 床に落ちる戦利品の itemGroup の id
	Being     bool   // 施設の敵を1体置く
	Door      bool
	NPC       string
}
```

- 部品の大きさは名前の先頭の `{W}x{H}_` で決め、今の入れ子と同じく描いた位置にはめる。部品の中にもパレットの文字を使える。
- 屋内かどうかは地形で決める。屋内の床の地形を置いたマスを屋内として扱う。
- seed は今の加算をやめ、`interior` で使っている撹拌つきの子 seed の作り方にそろえる。部品ごとの seed が互いに似通わないようにする。

### 消すもの

全施設を移したあとに消す。

- `internal/mapplanner/interior` のうち、間取り・部屋の中身・経年・小物・外装・外構・目玉。屋外の散布 `ScatterArea` と、その型 `Rect`・`Vec` は屋外で使うので、`overworld` へ移して残す
- raw の `facilityContents`、`facilityRooms`、`interiorContents`、`interiorRefs`、`interiorProfile`、`flavorContent` と、CUE のスキーマ
- `internal/balance/loot.go` の戦利品の試算は、施設の絵から収納と床の戦利品を数える形に直す
- 内装の golden と分布の golden

## 採用しなかった方法

- **間取りは手続きのまま、部屋の中だけ部品で埋める**: 部屋どうしのつながりと広い通路の問題が残る。
- **区画の大きさごとに絵を描き分ける**: 描く枚数が大きさの数だけ増える。揺らぎは前庭で表せる。
- **入口の向きごとに絵を描き分ける**: 回転で済む。
- **荒れ方を今の経年の工程で上から重ねる**: 経年は部屋の矩形と戸口を前提に作られていて、部屋の無い絵には掛けにくい。荒れ方はパレットの描き分けで表す。
- **施設の行に使う絵の名前を並べる**: 絵を足すたびに raw も直すことになる。絵の側に施設と重みを書けば、1か所で済む。
