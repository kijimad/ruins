# 訳す前の文字列 msgid に型を付ける

## 背景

画面に出す文字列は、英語の原文 msgid を `query.T` に通して現在の言語の訳を引く。参考 codebase: `internal/world/query/singleton.go:62`。raw の行の `name` も、エンティティの名前 `gc.Name.Name` も msgid を持ち、表示するときに訳す。参考 codebase: `internal/world/query/name.go:15`

msgid と訳した後の文字列はどちらも `string` で、区別はコメント `// 表示名 msgid` の約束だけで保っている。コンパイラは取り違えを止められず、実際に約束が破れている。

```go
// internal/world/lifecycle/spawn_prop.go:105, :154
entitySpec.Name = &gc.Name{Name: query.T(world, "Ruins Entrance")}
Name: &gc.Name{Name: query.T(world, "Cube")},
```

訳した後の文字列を名前に入れているので、表示のときにもう1度 `T` を通る。日本語では訳文を msgid として引いても見つからずそのまま返るので、たまたま正しく見えている。セーブには訳文が残り、言語を切り替えても名前が変わらない。

未翻訳の文字列リテラルは lint が検査するが、参考 codebase: `internal/lintrule/untranslated_literal_test.go`、変数に入った msgid の受け渡しは追えない。

## 要件

1. msgid と訳した後の文字列を型で分け、取り違えをコンパイルで止める。
2. `T` に文字列リテラルを渡す今の書き方は変えない。
3. raw の値が msgid として入ってくる箇所がコードに表れる。
4. 挙動を変えない。上の2か所の二重の訳だけを直す。

## 設計

```go
// internal/i18n
// Msgid は訳す前の英語の原文。query.T に通して現在の言語の訳を引く
type Msgid string

// query
func T(world w.World, msgid i18n.Msgid, args ...any) string

// components
type Name struct {
	Name i18n.Msgid
}

type ConditionDef struct {
	Name        i18n.Msgid
	Description i18n.Msgid
}
```

- `T` は `i18n.Msgid` を受け取り `string` を返す。訳した後の文字列を msgid のフィールドへ入れると型が合わずコンパイルで止まる。msgid を訳さずに `string` を受け取る描画へ渡すことも、変換を書かない限り通らない。
- 型の付いていない文字列定数は名前付きの型へ自動で変換されるので、`T(world, "Fracture")` はそのまま通る。`T` の呼び出し 466 か所のうち 392 か所がリテラルで、書き換えは要らない。
- 変数を渡す 74 か所を、msgid を持つ値の型を `i18n.Msgid` にして直す。多いのは `internal/states/character_info.go`、`character_state.go`、`internal/systems/hud_extractor.go`、`internal/widgets/entityspec/spec.go`。
- raw の行の `name` と `description` は生成コードでは `string` なので、組み立てる箇所で `i18n.Msgid(row.Name)` と変換する。msgid が入ってくる箇所はこの変換で読める。
- enum の表示名を返すメソッドは `i18n.Msgid` を返す。`String()` は `fmt.Stringer` として `string` を返す約束なので、表示名とは別のメソッドに分ける。
- `i18n.Msgid` を名前付きの文字列型にしても、セーブの JSON は今と同じ文字列になる。

msgid を持つフィールドは次のとおり。

| フィールド | 参考 codebase |
|---|---|
| `gc.Name.Name` | `internal/components/` |
| 不調、部位、スキルの値の表の `Name`、`Description`、`Summary`、`GainedBy`、`Effect` | `internal/components/condition_defs.go`、`skill_defs.go` |
| キー割り当てのヒント `Label` | `internal/keybind/keybind.go:47` |
| 言語の表示名 `Label` | `internal/i18n/i18n.go:20` |
| 中断の理由 `CancelReason` | `internal/components/activity.go` |
| 統計の見出し `headerMsgid` | `internal/states/run_stats_state.go:29` |

## 変更箇所

| ファイル | 変更内容 |

| `internal/i18n/` | `Msgid` 型 |
| `internal/world/query/singleton.go` | `T` が `i18n.Msgid` を受け取る |
| `internal/components/` | msgid を持つフィールドと、表示名を返すメソッドの型 |
| `internal/raw/raw.go` | 行の `name` と `description` を `i18n.Msgid` に変換して入れる |
| `internal/world/lifecycle/spawn_prop.go` | ダンジョン入口とキューブの名前に msgid を入れる |
| `internal/states/`、`internal/systems/hud_extractor.go`、`internal/widgets/` | 変数で msgid を渡す箇所 |
| `internal/keybind/`、`internal/i18n/i18n.go` | `Label` の型 |

## 採用しなかった方法

- **コメントで約束するだけの今のまま**: 2か所で破れている。
- **lint で検査する**: 変数に入った値が msgid か訳文かは構文から分からない。型ならコンパイラが代入と引数を追う。
- **生成コードの `name` を型付けする**: tsp の拡張で生成される型を `i18n.Msgid` にできるが、生成の設定が込み入る。境目での変換で、msgid が入る箇所は十分に読める。
- **訳した後の文字列にも型を付ける**: 描画の関数はすべて `string` を受け取る。msgid 側だけを型にすれば、訳さずに描画へ渡す取り違えは止まる。
