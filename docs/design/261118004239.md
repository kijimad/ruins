# 壊した後に破片・血痕を残す

## 背景

敵を倒しても物を壊しても、跡が何も残らない。HP が尽きると `Dead` が付き、`DeadCleanupSystem` が実体を消す。参考 codebase: `internal/world/gameaction/damage.go` の `dealHP`、`internal/systems/dead_cleanup.go`。

消すまでに起きることは次のとおりである。

| 場面 | 起きること |
|---|---|
| 敵が死ぬ | ドロップ表から抽選したアイテムと持ち物を足元へ出し、撃破数を数え、絵をフェードアウトさせて消す |
| 物が壊れる | 同じ経路で消える。収納の中身は足元へ出すが、物そのものの素材は何も残らない |
| 物を道具で解体する | 壊すのとは別の操作で、raw の `disassembly` の素材が取れる |
| 火が燃え尽きる | 行の `burnoutItem` のアイテムを足元へ落とす。参考 codebase: `internal/systems/fire.go` の `spawnBurnoutItem` |

当てたときの手応えはダメージの数字だけで、音を鳴らす仕組みは無い。

爽快感を3つの層に分けて考える。

| 層 | 中身 | 今 |
|---|---|---|
| 当てた瞬間の手応え | 揺れや光、音、ノックバック | 数字だけ。音は無い |
| 結果が残る | 壊した・倒した跡が床に残る | 何も残らない |
| 報酬 | 落とし物や素材 | 敵はドロップ表、物は壊すと何も無い |

ターン制のローグライクでは、1つ目の層が弱くても成り立つ。この doc は2つ目の層だけを扱い、壊した・倒した跡を見た目だけの装飾として世界に残す。1つ目の層と3つ目の層は別に扱う。解体して素材や肉を取れる死体や残骸は、3つ目の層の別の機能として後で設計する。

## 要件

- 敵や物が死んだ・壊れたマスに、その種類に応じた跡を残す。
- 跡は見た目だけの装飾にする。通るのを遅くせず、殴れず、解体できず、拾えない。
- 跡を残すか、何を残すかは raw の行で決める。新しい種類は raw の行と絵で足し、コードは変えない。
- 跡を置く場所は死んだマスに決め、乱数を使わない。
- 霊のように、何も残さない敵も作れる。

## 設計

### 跡を残す欄を敵と物の行に足す

敵も物も、`Dead` が付いてから `DeadCleanupSystem` で消える同じ経路を通る。そこで、敵の行と物の行の両方に、跡として置く置物の id を持つ任意の欄 `remains` を足す。燃え尽きたときの `burnoutItem` と同じ形にする。

```cue
#Member: {
	// ...
	// 死んだときに足元へ置く置物。省くと何も残さない
	remains?: #EntityID
	if remains != _|_ {
		remains_ref: _propIDs[remains] @rawgen(-)
	}
}

#Prop: {
	// ...
	// 壊れたときに足元へ置く置物。省くと何も残さない
	remains?: #EntityID
	if remains != _|_ {
		remains_ref: _propIDs[remains] @rawgen(-)
	}
}
```

`remains` は置物の行を参照する。無い id は CUE の参照の検査で落ちる。

### 消すときに跡を置く

`DeadCleanupSystem` で実体を消す直前に、実体の raw の行が `remains` を持てば、その座標にその置物を置く。実体の行は `RawID` から引く。

```go
// spawnRemains は死んだ実体 e の行が持つ跡の置物を、e の座標へ置く
func spawnRemains(world w.World, e ecs.Entity, dying map[ecs.Entity]bool) error {
	// RawID から敵か物の行を引き、remains があり、e の座標に dying 以外の置物が無ければ
	// lifecycle.SpawnProp で座標へ置き、今のステージへ束縛する
}
```

- **置く順**: ドロップと持ち物を足元へ出した後、実体を消す前にする。ドロップの loop は `DropTable` が無い実体や何も出なかった実体を `continue` で飛ばすので、跡を置く処理はその loop に入れず、独立した loop にする。
- **重ねない**: 跡に限らず、そのマスに置物があれば置かない。扉やワープや焚き火の上で敵が死んでも、1マスに置物が2つ並ばない。同じマスに置物は1つという施設の置き方にそろえる。
- **判定から死ぬ実体を除く**: 壊れた物は、跡を置く時点ではまだ同じマスに置物として残っている。そのため、判定ではその tick で消す実体の集合 `dying` を除く。除かないと、物の跡が一度も置かれない。
- **置物を引く関数**: 実行中に座標から置物を引く関数はまだ無い。`query.GetEntitiesAt` から `Prop` を持つものを選ぶ小さな関数を足す。
- **ステージへの束縛**: `lifecycle.SpawnProp` は `StageBound` を付けない。`MoveToField` と同じく、置いた直後に `StageBound{CurrentStage}` を付け、今のステージのクエリにすぐ乗るようにする。

### 跡は床に寝かせた装飾の置物にする

跡は全て、描画順 `depth = 1` の置物にする。3D では立て板にせず地面に寝かせて描く。参考 codebase: `internal/components/sprite.go` の `DepthNumDecal`。通れて、`hp` を持たないので殴れず、`disassembly` を持たないので解体できない。

| 跡 | 例 |
|---|---|
| 体から出る跡 | 血痕、油の染み、粘液、焦げ跡 |
| 物の破片 | 木片、ガラス片、屑鉄の散らばり、瓦礫 |

物の破片の行の例を示す。

```toml
[[props]]
  blockPass = false
  blockView = false
  description = "壊れた木の家具の破片が床に散らばっている"
  id = "wood_splinters"
  name = "Wood Splinters"
  [props.spriteRender]
    depth = 1
    spriteKey = "debris"
    spriteSheetName = "field"
```

壊した家具の行には `remains = "wood_splinters"` を足す。

### 敵の跡

敵は79種いて、raw に体の種類の欄は無い。行ごとに `remains` を書く。

| 敵の種類 | 跡 |
|---|---|
| 生き物 | 血痕 |
| 戦車や機械 | 油の染み |
| スライム | 粘液 |
| 火の玉 | 焦げ跡 |
| 霊 | 何も残さない |

### 絵

| 跡 | 絵 |
|---|---|
| 散らかり・瓦礫・屑鉄 | 既存の `debris`、`rubble`、`scrap_metal` を使える。床に寝かせたときの見え方を目で確かめる |
| 血痕・油の染み・粘液・焦げ跡 | 無い。`blood_.png` は血の入った瓶のアイテムである。新しく用意する |

絵の用意がいちばんの関門である。そこで、既存の絵で作れる物の破片を先にし、敵の跡は絵が用意できてからにする。

### 消えない作りにする

跡は消えずに残す。地上は北へ進むと帯の南端のチャンクごと実体が消えるので、自然に片付く。参考 codebase: `internal/worldstream/worldstream.go` の `RemoveEntitiesInYRange`。ダンジョンの階は有限である。増えすぎたら、時間で消す仕組みを別に足す。

## 採用しなかった方法

- **残骸に通りにくさと解体の素材を持たせる**: 壊すのは速いが取れる量は少なく、解体は遅いが多く取れる、という選択が生まれる。ただ、戦った通路が残骸で埋まって経路が遅くなるなど、遊びへの影響を調整することになる。跡はまず見た目だけにし、素材を取れるものは解体できる死体と合わせて別の機能として扱う。
- **死体のアイテムを残し、解体で肉を取る**: 食料という生存の資源と結び付いて面白いが、腐敗や重さや解体の手間まで決めることになり重い。跡の装飾とは別の機能として、後で設計する。
- **跡の種類を敵の体の種類から導く**: raw に体の種類の欄が無く、足すと敵の分類の設計から始めることになる。行ごとに `remains` を書くほうが、何も残さない敵のような例外も素直に書ける。
- **跡を1つの絵にし、色だけを行で変える**: 絵は1枚で済むが、血と油と粘液で形が同じになり、見分けにくい。色を持たせる欄も別に要る。
- **跡を時間で消す**: 片付けの仕組みが要る。地上は帯の南端で自然に消えるので、まず消えない作りで始める。
- **壊したときに素材をそのままアイテムで落とす**: 跡が床に残らない。素材の報酬は別の機能で扱う。

## コメント

- 当てた瞬間の手応え、たとえば揺れや光、音は、この doc とは別に扱う。音を鳴らす仕組みはまだ無い。
- 解体できる死体や残骸は、この装飾とは別の置物か別の仕組みとして後で設計する。装飾の跡はそのとき置き換えず、両方を残せる。
- 出血の状態の敵が歩いた跡に血を落とすと、手負いの敵を追える。跡の置物ができた後に検討する。
- 79種の敵に `remains` を書く作業は漏れやすい。`remains` を持たない敵を一覧で固定するテストで、意図して省いた敵だけが残ることを確かめる案がある。
