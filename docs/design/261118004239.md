# 壊した後に破片・血痕を残す

## 背景

敵を倒しても物を壊しても、跡が何も残らない。HP が尽きると `Dead` が付き、`DeadCleanupSystem` が実体を消す。参考 codebase: `internal/world/gameaction/damage.go` の `dealHP`、`internal/systems/dead_cleanup.go`。

消すまでに起きることは次のとおりである。

| 場面 | 起きること |
|---|---|
| 敵が死ぬ | ドロップ表から抽選したアイテムと持ち物を足元へ出し、撃破数を数え、絵をフェードアウトさせて消す |
| 物が壊れる | 同じ経路で消える。収納の中身は足元へ出すが、物そのものの素材は何も残らない |
| 物を道具で解体する | 壊すのとは別の操作で、raw の `disassembly` の素材が取れる |
| 火が燃え尽きる | 行の `burnoutItem` のアイテムを足元へ落とす。参考 codebase: `internal/systems/fire.go` の `spawnBurnoutItem` |

当てたときの手応えはダメージの数字だけで、音を鳴らす仕組みは無い。

爽快感を3つの層に分けて考える。

| 層 | 中身 | 今 |
|---|---|---|
| 当てた瞬間の手応え | 揺れや光、音、ノックバック | 数字だけ。音は無い |
| 結果が残る | 壊した・倒した跡が床に残る | 何も残らない |
| 報酬 | 落とし物や素材 | 敵はドロップ表、物は壊すと何も無い |

ターン制のローグライクでは、1つ目の層が弱くても成り立つ。この doc は2つ目と3つ目の層を扱い、壊した・倒した跡を世界に残す。1つ目の層は別に扱う。

物の場合は、残骸に素材を持たせると「壊す」と「解体する」に違いが出る。壊すのは速いが取れる素材は少なく、解体は遅いが多く取れる、という選択になる。

## 要件

- 敵や物が死んだ・壊れたマスに、その種類に応じた跡を残す。
- 跡を残すか、何を残すかは raw の行で決める。新しい種類は raw の行と絵で足し、コードは変えない。
- 物の残骸は、通れるが遅く、こじ開けて解体すると素材の一部が取れる。道具で解体したときより取れる量を少なくする。
- 跡を置く場所は死んだマスに決め、乱数を使わない。
- 霊のように、何も残さない敵も作れる。

## 設計

### 跡を残す欄を敵と物の行に足す

敵も物も、`Dead` が付いてから `DeadCleanupSystem` で消える同じ経路を通る。そこで、敵の行と物の行の両方に、跡として置く置物の id を持つ任意の欄 `remains` を足す。燃え尽きたときの `burnoutItem` と同じ形にする。

```cue
#Member: {
	// ...
	// 死んだときに足元へ置く置物。省くと何も残さない
	remains?: #EntityID
	if remains != _|_ {
		remains_ref: _propIDs[remains] @rawgen(-)
	}
}

#Prop: {
	// ...
	// 壊れたときに足元へ置く置物。省くと何も残さない
	remains?: #EntityID
	if remains != _|_ {
		remains_ref: _propIDs[remains] @rawgen(-)
	}
}
```

`remains` は置物の行を参照する。無い id は CUE の参照の検査で落ちる。

### 消すときに跡を置く

`DeadCleanupSystem` で実体を消す直前に、実体の raw の行が `remains` を持てば、その座標にその置物を置く。実体の行は `RawID` から引く。

```go
// spawnRemains は死んだ実体 e の行が持つ跡の置物を、e の座標へ置く
func spawnRemains(world w.World, e ecs.Entity) error {
	// RawID から敵か物の行を引き、remains があれば lifecycle.SpawnProp で座標へ置く
}
```

置く順は、ドロップと持ち物を足元へ出した後、実体を消す前にする。跡の置物は通れるので、足元のアイテムを拾う邪魔にならない。

すでに跡の置物があるマスで、また何かが死んだときは、重ねて置かない。同じマスに置物は1つという施設の置き方にそろえる。

### 跡の種類は置物の行で作る

跡は2種類ある。どちらも既存の置物の欄だけで作れる。

| 種類 | 置物の行 | 例 |
|---|---|---|
| 床の模様 | 描画順 `depth = 1` にし、3D で地面に寝かせて描く。通れて、殴れない | 血痕、油の染み、粘液、焦げ跡 |
| 残骸 | `passCost` で通るのを遅くし、`disassembly` でこじ開けて素材を取らせる | 木片、屑鉄の山、瓦礫、ガラス片 |

残骸の行の例を示す。墜落現場の `wreck_debris` と同じ形である。

```toml
[[props]]
  blockPass = false
  blockView = false
  description = "壊れた木の家具の破片。通れるが遅い。こじ開けると薪が少し取れる"
  hp = 5
  id = "wood_splinters"
  name = "Wood Splinters"
  passCost = 30
  [props.disassembly]
    toolCategory = "prying"

    [[props.disassembly.yields]]
      count = "1d2"
      id = "firewood"
  [props.spriteRender]
    depth = 0
    spriteKey = "debris"
    spriteSheetName = "field"
```

壊した家具の行には `remains = "wood_splinters"` を足す。残骸から取れる量は、元の家具を道具で解体したときより少なくする。

### 敵の跡

敵は79種いて、raw に体の種類の欄は無い。行ごとに `remains` を書く。

| 敵の種類 | 跡 |
|---|---|
| 生き物 | 血痕 |
| 戦車や機械 | 油の染み。部品の残骸にもできる |
| スライム | 粘液 |
| 火の玉 | 焦げ跡 |
| 霊 | 何も残さない |

### 絵

| 跡 | 絵 |
|---|---|
| 散らかり・瓦礫・屑鉄 | 既存の `debris`、`rubble`、`scrap_metal` を使える |
| 血痕・油の染み・粘液・焦げ跡 | 無い。`blood_.png` は血の入った瓶のアイテムである。新しく用意する |

絵の用意がいちばんの関門である。そこで、既存の絵で作れる物の残骸を先にし、敵の跡は絵が用意できてからにする。

### 消えない作りにする

跡は消えずに残す。地上は北へ進むと帯の南端のチャンクごと実体が消えるので、自然に片付く。参考 codebase: `internal/worldstream/worldstream.go` の `RemoveEntitiesInYRange`。ダンジョンの階は有限である。増えすぎたら、時間で消す仕組みを別に足す。

| `assets/file/textures/single/` | 血痕・油の染み・粘液・焦げ跡の絵 |
| テスト | 死んだ敵と壊れた物の座標に跡が置かれること。`remains` を省くと何も置かれないこと。跡のあるマスに重ねて置かないこと。残骸を解体すると素材が取れること |

## 採用しなかった方法

- **死体のアイテムを残し、解体で肉を取る**: 食料という生存の資源と結び付いて面白いが、腐敗や重さや解体の手間まで決めることになり重い。跡の仕組みとは別に検討する。
- **跡の種類を敵の体の種類から導く**: raw に体の種類の欄が無く、足すと敵の分類の設計から始めることになる。行ごとに `remains` を書くほうが、何も残さない敵のような例外も素直に書ける。
- **跡を1つの絵にし、色だけを行で変える**: 絵は1枚で済むが、血と油と粘液で形が同じになり、見分けにくい。色を持たせる欄も別に要る。
- **跡を時間で消す**: 片付けの仕組みが要る。地上は帯の南端で自然に消えるので、まず消えない作りで始める。
- **壊したときに素材をそのままアイテムで落とす**: 跡が床に残らず、解体との違いも量だけになる。残骸の置物にすると、通るのが遅い・こじ開けるという手間で解体との違いが出る。

## コメント

- 当てた瞬間の手応え、たとえば揺れや光、音は、この doc とは別に扱う。音を鳴らす仕組みはまだ無い。
- 出血の状態の敵が歩いた跡に血を落とすと、手負いの敵を追える。跡の置物ができた後に検討する。
- 窓のガラス片は、踏むと痛いという遊びも考えられる。
