# 壊した後に破片・血痕を残す

## 背景

敵を倒しても物を壊しても、跡が何も残らない。HP が尽きると `Dead` が付き、`DeadCleanupSystem` が実体を消す。参考 codebase: `internal/world/gameaction/damage.go` の `dealHP`、`internal/systems/dead_cleanup.go`。

消すまでに起きることは次のとおりである。

| 場面 | 起きること |
|---|---|
| 敵が死ぬ | ドロップ表から抽選したアイテムと持ち物を足元へ出し、撃破数を数え、絵をフェードアウトさせて消す |
| 物が壊れる | 同じ経路で消える。収納の中身は足元へ出すが、物そのものの素材は何も残らない |
| 物を道具で解体する | 壊すのとは別の操作で、raw の `disassembly` の素材が取れる |
| 火が燃え尽きる | 行の `burnoutItem` のアイテムを足元へ落とす。参考 codebase: `internal/systems/fire.go` の `spawnBurnoutItem` |

当てたときの手応えはダメージの数字だけで、音を鳴らす仕組みは無い。

爽快感を3つの層に分けて考える。

| 層 | 中身 | 今 |
|---|---|---|
| 当てた瞬間の手応え | 揺れや光、音、ノックバック | 数字だけ。音は無い |
| 結果が残る | 壊した・倒した跡が床に残る | 何も残らない |
| 報酬 | 落とし物や素材 | 敵はドロップ表、物は壊すと何も無い |

ターン制のローグライクでは、1つ目の層が弱くても成り立つ。この doc は2つ目の層だけを扱い、壊した・倒した跡を見た目だけの装飾として世界に残す。1つ目の層と3つ目の層は別に扱う。解体して素材や肉を取れる死体や残骸は、3つ目の層の別の機能として後で設計する。

## 要件

- 敵や物が死んだ・壊れたマスに、その種類に応じた跡を残す。
- 跡は見た目だけの装飾にする。通るのを遅くせず、殴れず、解体できず、拾えない。草など、すでにマスにある置物と並んで置ける。
- 跡は置物と違う種類の実体にし、置物やアイテムを数える処理に巻き込ませない。
- 跡を残すか、何を残すかは raw の行で決める。新しい種類は raw の行と絵で足し、コードは変えない。
- 跡を置く場所は死んだマスに決め、乱数を使わない。
- 霊のように、何も残さない敵も作れる。

## 設計

### 跡は置物でない専用の種類にする

地上の草・雑草・土の散らかりは、描画順 0 の置物である。参考 codebase: raw.toml の `grass`・`weeds`。跡を置物にして「置物があるマスには置かない」とすると、草のマスに跡が出ない。また、実行中に `Prop` の有無を数える処理が2つある。

| 箇所 | 跡が置物だと起きること |
|---|---|
| `internal/world/lifecycle/facility.go` の設備を置けるかの判定 | 野営の中で敵を倒すと、跡のマスに設備を置けなくなる |
| `internal/world/lifecycle/cube_deploy.go` の `stowNearbyItems` | キューブを畳むと、範囲内の血痕も積み荷として畳まれ、展開のたびに出し直される |

そこで、跡は raw の専用の表 `decals` の行から作り、実体には印 `Decal` を付ける。`Prop` も `Item` も付けないので、上の2つの処理は跡を見ない。

```cue
// 敵や物が消えた跡に床へ残す装飾
#Decal: {
	id!:          #EntityID
	name!:        #EntityName
	description!: string
	spriteSheetName!: #EntityID
	spriteKey!:       #SpriteKey
}

#Raws: {
	// ...
	decals?: [...#Decal]
}
```

```go
// Decal は敵や物が消えた跡に床へ残す装飾であることを示すマーカーコンポーネント。
// 置物でもアイテムでもなく、通行・操作・拾得・積み込みのどれにも関わらない
type Decal struct{}
```

跡の実体は `GridElement`・`LocationOnField`・`SpriteRender`・`Name`・`Description`・`Decal` を持つ。`SpriteRender` の描画順は常に `DepthNumDecal` にし、3D で地面に寝かせて描く。参考 codebase: `internal/components/sprite.go`。描画順は行に持たせず、跡を組む関数で決める。`Name` を持つので、見回しで「血痕」と分かる。

### 跡を残す欄を敵と物の行に足す

敵も物も、`Dead` が付いてから `DeadCleanupSystem` で消える同じ経路を通る。そこで、敵の行と物の行の両方に、跡の行の id を持つ任意の欄 `remains` を足す。燃え尽きたときの `burnoutItem` と同じ形にする。

```cue
#Member: {
	// ...
	// 死んだときに足元へ残す跡。省くと何も残さない
	remains?: #EntityID
	if remains != _|_ {
		remains_ref: _decalIDs[remains] @rawgen(-)
	}
}

#Prop: {
	// ...
	// 壊れたときに足元へ残す跡。省くと何も残さない
	remains?: #EntityID
	if remains != _|_ {
		remains_ref: _decalIDs[remains] @rawgen(-)
	}
}
```

`remains` は跡の行を参照する。無い id は CUE の参照の検査で落ちる。

燃え尽きた火も、`internal/systems/fire.go` で `Dead` が付いて同じ経路で消える。火の置物の行に `remains` を書けば、焦げ跡を残せる。燃え残りの `burnoutItem` とも並べて持てる。

### 消すときに跡を置く

`DeadCleanupSystem` で実体を消す直前に、実体の raw の行が `remains` を持てば、その座標に跡を置く。行は `RawID` から引く。`RawID` は敵・置物・アイテム・タイルで同じ文字列の形を持つので、引く表は実体の種類で決める。`Prop` を持てば置物の行、持たなければ敵の行を引く。こうすると、敵と置物の id が重なっても誤らない。

```go
// spawnRemains は死んだ実体 e の行が持つ跡を、e の座標へ置く
func spawnRemains(world w.World, e ecs.Entity) error {
	// e が Prop を持てば置物の行、持たなければ敵の行を RawID で引く。
	// remains があり、その座標にまだ跡が無ければ lifecycle.SpawnDecal で置き、今のステージへ束縛する
}
```

- **置く順**: ドロップと持ち物を足元へ出した後、実体を消す前にする。ドロップの loop は `DropTable` が無い実体や何も出なかった実体を `continue` で飛ばすので、跡を置く処理はその loop に入れず、独立した loop にする。
- **重ねない**: そのマスにすでに跡があれば置かない。置物やアイテムがあっても置く。跡は床に寝かせて描くので、草や扉の下に見える。
- **跡を引く関数**: 座標の跡を引く関数を `query` に足す。`Decal` を持つ実体だけを見る。
- **ステージへの束縛**: 跡を組む関数は、置いた直後に `StageBound{CurrentStage}` を付け、今のステージのクエリにすぐ乗るようにする。帯の南端で実体を消す `RemoveEntitiesInYRange` と、ステージへ束縛する `stage.Bind` は、どちらも `GridElement` を持つ実体全てを見るので、跡も漏れなく扱われる。

### 跡の種類

| 跡 | 例 |
|---|---|
| 体から出る跡 | 血痕、油の染み、粘液、焦げ跡 |
| 物の破片 | 木片、ガラス片、屑鉄の散らばり、瓦礫 |

物の破片の行の例を示す。

```toml
[[decals]]
  description = "壊れた木の家具の破片が床に散らばっている"
  id = "wood_splinters"
  name = "Wood Splinters"
  spriteKey = "debris"
  spriteSheetName = "field"
```

壊した家具の行には `remains = "wood_splinters"` を足す。

### 敵の跡

`[[members]]` の行には、プレイヤーの行と中立の行も入っている。`DeadCleanupSystem` はプレイヤーを消さないので、プレイヤーの行の `remains` は使われない。敵対する行ごとに `remains` を書く。raw に体の種類の欄は無い。

| 敵の種類 | 跡 |
|---|---|
| 生き物 | 血痕 |
| 戦車や機械 | 油の染み |
| スライム | 粘液 |
| 火の玉 | 焦げ跡 |
| 霊 | 何も残さない |

### 絵

| 跡 | 絵 |
|---|---|
| 散らかり・瓦礫・屑鉄 | 既存の `debris`、`rubble`、`scrap_metal` を使える。ただ、これらは今は立てて描く置物の絵で、床に寝かせると見えにくい恐れがある。寝かせたときの見え方を目で確かめ、見えにくければ描き直す |
| 血痕・油の染み・粘液・焦げ跡 | 無い。`blood_.png` は血の入った瓶のアイテムである。新しく用意する |

絵の用意がいちばんの関門である。そこで、既存の絵で作れる物の破片を先にし、敵の跡は絵が用意できてからにする。

### 消えない作りにする

跡は消えずに残す。地上は北へ進むと帯の南端のチャンクごと実体が消えるので、自然に片付く。ダンジョンの階は有限である。増えすぎたら、時間で消す仕組みを別に足す。

テストで確かめること。

- 死んだ敵と壊れた物の座標に跡が置かれる。物は `Prop` で、敵はそうでないので、両方の表の引き方を通す
- ドロップの無い実体にも置かれる
- `remains` を省くと何も置かれない
- 跡のあるマスには重ねて置かない。草のある地上のマスには置かれる
- 跡のマスに、野営の設備を置ける
- キューブを畳むと、跡は積み荷にならずその場に残る
- 燃え尽きた火の行が `burnoutItem` と `remains` の両方を持つと、燃え残りと跡の両方が出る

## 採用しなかった方法

- **跡を置物にし、遮る置物だけを重ね置きの判定に使う**: 草のマスにも置けるようになる。ただ、置物の印の doc は「1タイルに1つ置かれる」としていて、その前提を緩めることになる。設備の判定やキューブを畳む処理も、跡を除く分岐を個別に足すことになる。
- **草などの下地の置物を消して跡に置き換える**: 戦ったマスから草が消え、跡が残る代わりに地面の見た目が崩れる。
- **残骸に通りにくさと解体の素材を持たせる**: 壊すのは速いが取れる量は少なく、解体は遅いが多く取れる、という選択が生まれる。ただ、戦った通路が残骸で埋まって経路が遅くなるなど、遊びへの影響を調整することになる。跡はまず見た目だけにし、素材を取れるものは解体できる死体と合わせて別の機能として扱う。
- **死体のアイテムを残し、解体で肉を取る**: 食料という生存の資源と結び付いて面白いが、腐敗や重さや解体の手間まで決めることになり重い。跡の装飾とは別の機能として、後で設計する。
- **跡の種類を敵の体の種類から導く**: raw に体の種類の欄が無く、足すと敵の分類の設計から始めることになる。行ごとに `remains` を書くほうが、何も残さない敵のような例外も素直に書ける。
- **跡を1つの絵にし、色だけを行で変える**: 絵は1枚で済むが、血と油と粘液で形が同じになり、見分けにくい。色を持たせる欄も別に要る。
- **跡を時間で消す**: 片付けの仕組みが要る。地上は帯の南端で自然に消えるので、まず消えない作りで始める。
- **壊したときに素材をそのままアイテムで落とす**: 跡が床に残らない。素材の報酬は別の機能で扱う。

## コメント

- 当てた瞬間の手応え、たとえば揺れや光、音は、この doc とは別に扱う。音を鳴らす仕組みはまだ無い。
- 解体できる死体や残骸は、この装飾とは別の置物か別の仕組みとして後で設計する。装飾の跡はそのとき置き換えず、両方を残せる。
- 出血の状態の敵が歩いた跡に血を落とすと、手負いの敵を追える。跡ができた後に検討する。
- 敵の行に `remains` を書く作業は漏れやすい。敵対する行のうち `remains` を持たない行を一覧で固定するテストで、意図して省いた敵だけが残ることを確かめる案がある。
- 跡を置く頻度は1ターンに数体の死に限られるので、座標の跡を引く関数は全走査でよい。
