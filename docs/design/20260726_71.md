# 隊の活動システムの企画 —— 生存の要求から加工・生産・協力を立ち上げる

## 背景

隊はこのゲームの核心である。しかし現状プレイヤーが隊に出せる指示は、戦闘・位置・回収・処理の
4ポリシーを巡回ボタンで切り替えるだけで、ざっくりとした命令しかできない。「働く」語彙、すなわち
採掘・加工・生産・治療・訓練は存在しない。

一方 `docs/plan/design.md` は既に方向を示している。生産・交易・整備は「人々を世代を越えて生かす
ための基盤」であり愛着×死×継承の核に奉仕する。逗留ゾーンでは腰を据えて採掘・加工・生産・訓練・
団欒する。`docs/plan/mock/dwell_production.html` はそのタイル上の手触りを検証済みである。

本 doc は Elona・RimWorld・CDDA を参考に、**次に何の機能を実装するか**を企画検討する。実装仕様
ではない。方針が決まった項目は個別の実装 doc へ切り出す。

## 検討の原則 —— 要求が先、活動は答え

「ゲーム内でやるべきこと」すなわち**生存への対立軸から始める**。加工・生産・協力を機能リストとして
先に設計せず、まず要求を定義し、活動はその答えとして立ち上げる。

- 要求のない生産は busywork になる。design.md が警戒する「効率スコア化」「無限グラインド」は、
  需要と切り離された生産機能から生まれる
- やることが決まれば、自ずと隊員にやらせたくなる。やらせれば使用ベースでスキルが育ち、育った
  隊員を失いたくなくなる。**需要 → 活動 → 成長 → 愛着**の連鎖が、機能を感情の核へ接続する
- design.md の漏れバケツ禁止と同型である。活動の成果は選択肢を買う。射程を延ばす食料、死亡曲線を
  下げる防寒具、世代を繋ぐ訓練

## 現状の棚卸し

実装調査の要点。詳細は各参照先にある。

| 領域 | 状況 |
|---|---|
| 対立軸: 体温・寒波前線 | 実装済み。TemperatureSystem・Front |
| 対立軸: 空腹 | **プレイヤー専用**。隊員は空腹にならない |
| 活動の器 activity | 実装済み。中断・再開・継続の枠組みが完備 |
| 活動の型 | move/attack/read/talk/transfer 等。**採取・採掘・加工・生産は無い** |
| クラフト | 実装済みだが activity 外の即時実行。**スキル未連動** |
| スキル | 25種定義済み・成長ロジックあり。**成長トリガーは武器攻撃と読書の2箇所のみ** |
| 命令 | 4ポリシーの巡回設定のみ。作業指示なし |
| 協力 | アイテム分配のみ |

ギャップは明確である。**対立軸はあるのに答える活動が無く、スキルは器だけがある**。activity と
スキルの基盤は完成しているので、企画の主題は「何を足すか」でなく「どの順で繋ぐか」になる。

## 参考作品の分解

| 作品 | 借りるもの | 借りないもの |
|---|---|---|
| RimWorld | **作業優先度の間接制御**。作業種別×優先度の表で、個別 micro なしに分業が決まる。zone 指定。bill すなわち在庫維持目標 | 拠点定住の前提。ruins は移動する隊 |
| CDDA | zone 指定による作業対象の指示。activity actor の継続・中断は導入済み | basecamp の実時間外注。ruins の隊は同じ地図上で目の前で働く |
| Elona | **大量パラメータが上がる楽しさ**。行動すれば対応スキルが上がる即物的な快感。生活スキルの幅 | 無限グラインドの許容。逗留の有限性で防ぐ |

## 企画の骨子

### 対立軸 → 活動 → スキルの対応表

| 対立軸 demand | 答える活動 answer | 育つスキル | 現状 |
|---|---|---|---|
| 食料が減る | 採取 → 調理 → 保存食の生産 | 探索・調合 | 空腹が隊に無い。活動なし |
| 体温が下がる | 薪集め → 焚き火・防寒具の生産 | 合成・耐寒 | 体温はある。活動なし |
| 電力・凍晶が要る | 採掘 → 精製 → バッテリー | 機械・荷重 | 凍晶は拾うのみ |
| 負傷・デススパイラル | 治療 → 療養 | 治療 | 医療品使用のみ |
| ベテランの老い | 訓練 → 伝承 | 全般＋指南 | 未着手。感情の核の入口 |

この表が企画の背骨である。各行は「需要が先に存在し、活動がそれに答え、スキルが副産物として育つ」
という向きで読む。逆向き、活動が先で需要を後付けする行は作らない。

### 活動の語彙

既存の activity Behavior として実装できる粒度に揃える。継続・中断・再開の枠組みは実装済みなので、
新しい仕組みは不要で型を足すだけでよい。

- **採取・採掘 gather/mine**。資源タイルから素材を得る。逗留ゾーンの資源が対象
- **加工 process**。解体・精製・調理。素材を中間財へ
- **生産 produce**。裁縫・工作・調合。中間財を消耗品・装備へ。既存クラフトの activity 化
- **ケア care**。治療・見張り。人を対象にする活動
- **訓練・伝承 train/mentor**。スキルの移転。design.md の Mentorship の一般形へ将来接続する

### 指示の器 —— 作業ポリシー＋リーダーの指定

3案を比較した。

- **A. RimWorld 型の作業優先度**。隊員ごとに作業種別×優先度を持たせ、隊員が自律的に仕事を選ぶ
- **B. リーダーの対象指定**。採取指定・集積点・立入禁止をリーダーが地図上で指定する
- **C. 直接命令の拡張**。個別のターン単位 micro

採用は **A＋B のハイブリッド**。作業ポリシーを既存4ポリシーに並ぶ第5層として足し、リーダーの
指定が作業の対象と場所を与える。design.md はリーダーの毎ターンの主軸を「環境操作と、採取／集積点／
優先目標／立入禁止の指定」と既に定義しており、**B は新機軸でなく既定方針の実装**である。C は
design.md が「直接 micro はしない」と明言しているため不採用。

戦闘4ポリシーとの関係は場所で切り替わる。危険区画では戦闘ポリシーが主、逗留ゾーンでは作業
ポリシーが主。design.md の「滞在の2つの場所」の区分がそのまま指示語彙の切替になる。

### 成長 —— 未接続のスキルを繋ぐ

各活動 Behavior の完了時に skill.GainExp を呼ぶ。武器攻撃と読書で実装済みのパターンの横展開で
あり、器は既にある。Elona 的な「上がる楽しさ」は提示が要で、上がった瞬間をログ1行で見せる。
これは design.md の愛着の3条件のうち提示に相当する。

### 協力 —— 明示コマンドにせず創発させる

- **段階1: 分業の創発**。採掘役が掘り、運搬役が集積点へ運び、加工役が作る。個別の協調 AI は
  作らず、作業ポリシーと集積点の重なりだけで物流が回る。既存の分配ポリシーの一般形
- **段階2: 共同作業**。師弟の訓練、2人がかりの重量物。伝承リンクへの入口
- 「協力せよ」という明示コマンドは作らない。ポリシーの重なりから協力が創発する方が、隊員の動きが
  読めて予測可能という既定原則に合う

### 逗留の有限性との結合

作業システムは design.md の逗留ゾーンの上で回る。資源の枯渇・前線の接近・ゾーンの天井という
3つの有限性が既に定義されており、無限グラインドは構造的に防がれる。作業システム側で改めて
制限を発明する必要はない。

## 次に実装する候補の優先順位

企画の出力。上から順に実装 doc へ切り出す。

1. **隊全体の食料需要**。空腹を隊員へ拡張する。対立軸が隊に接続されないかぎり、どの活動にも
   需要が生まれない。design.md は「隊員が多いほど食料消費が増える。維持コストの主要因」と既に
   宣言しており、拡張は既定路線。圧の強さはスラック原則に従い緩く始める
2. **採取＋調理の activity と作業ポリシーの最小形**。最初の需要→活動ループを1本閉じる。
   「食料が減る → 採って調理する → 探索と調合が育つ」
3. **クラフトの activity 化とスキル接続**。既存機能の格上げで最小工数。合成・調合スキルの
   成長トリガーが繋がる
4. **リーダーの採取指定・集積点**。zone の最小形。design.md の既定方針の実装
5. **訓練・伝承**。感情の核への入口。1〜4 が回ってから

1→2 の順序が肝である。需要より先に活動を作ると、誰も使わない生産メニューになる。

## 採用しなかった方法

- **直接 micro 命令の拡張** —— design.md が明言して排除している。事前ポリシー中心の設計思想と
  矛盾し、10人の micro は操作負荷で破綻する
- **生産を別画面のメニュー操作で完結させる** —— 「場所であってメニューでない」に反する。作業は
  タイル上で隊員が体を動かして起きる。camp_layout・dwell_production の mock で検証した方向を守る
- **RimWorld の bill を最初から作る** —— 在庫N維持の自動生産は器が大きい。まず単発の作業指示から
  始め、bill は将来の拡張余地として残す
- **CDDA basecamp 型の実時間外注** —— ruins の隊は同じ地図上に同座する。外注でなく目の前で
  働く姿が見えることが、愛着の提示に効く
- **需要の効率スコア化** —— 空腹・寒さを数値最適化の対象にしない。緩さ4原則のとおり身体で分かる
  圧のままにする
