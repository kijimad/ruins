# Prop を廃し設置を item の状態にする —— Minecraft 型の item↔設置モデル

## 背景

`Prop` コンポーネント、`internal/components/components.go:322` の `type Prop struct{}`、は空の種別タグである。だが実際に
担っているのは「フィールド上の物体が拾える loot か、破壊・収納で扱う恒久設置物 fixture か」の1ビットで、しかも
`IsPickable = LocationOnField && !Prop`、`internal/world/query/query.go:50-58`、と**陰性**で表現されている。

`Item` タグは既に撤去済みである。`bf30966ff`「冗長なカテゴリタグComponentを削除した」で `Item` と `Weapon` の
マーカーを消し、「アイテムか」を単一タグでなく、状態 `LocationOnField` と能力コンポーネント、Melee・Fire・
Consumable・Ammo・Book・Material・Wearable、へ分解した。Prop はこの整理から取り残された恣意的な種別タグである。

Item と Prop の境界は曖昧である。フィールドの item も設置された prop も `GridElement` と `LocationOnField` を持ち、
位置では区別できない。両者を分けている実体は `Prop` タグ1つに集約される。`20260731_80`、移動キューブ、は prop に
`gc.Weight` を item と対称に持たせ、拾って持ち運べる家具を志向する。

そこで方針を **Minecraft 型のモデル**に定める。

- **すべての物は item である**。基底は item で、インベントリに入る item 状態を持つ。
- **設置可能な item は設置できる**。設置は種別でなく**状態**。設置可能かは `Placeable` 能力で表す。
- **設置物は耐久を持つ**。破壊・分解すると**材料になる**。一部の設置物は**固定を外して元の item に戻せる**。
  設置状態の実体は `HP` を持ち、壊すと材料を落とす。取り外せるかは能力で表す。

このモデルでは「Prop」は「設置状態にある item」に解消され、種別タグ `Prop` は不要になる。ただし **item 状態と設置状態は
明示的に区別できる必要がある**。区別は種別タグでなく `LocationPlaced` 状態マーカーで表し、拾得・破壊・取り外しの入口を分ける。
Item・Weapon タグを状態と能力へ分解した `bf30966ff` の路線の完成形である。

## 要件

- **基底を item に一本化する**。現在の prop を「設置状態の item」として扱い、`Prop` 種別タグを廃する。
- **item 状態と設置状態を区別できる**。同じ item が所持・落下の item 状態と、設置状態を取りうる。設置状態は既存の
  Location 家族、`InBackpack`/`Equipped`/`InStorage`/`OnField`、と排他の第5状態 `LocationPlaced` として表し、`clearLocation`
  の排他機構にそのまま載せる。独立マーカーにすると `clearLocation` が知らず、拾った後も設置状態が残る不整合が出る。
- **設置は状態、Placeable は能力**。設置できる item に `Placeable` を付ける。設置状態は `GridElement` と `HP` と、
  設置時に付く機能コンポーネント、`BlockPass`・`Storage`・`Door`・`LightSource` など、で表す。
- **除去の動詞は2系統**。破壊・分解は設置物を壊して**材料**にする、実体消滅。取り外しは設置状態を item 状態へ**戻す**、
  実体保存。取り外せるのは一部の設置物だけで、能力 `Retrievable` で表す。既存の Location 状態遷移、`MoveToBackpack`
  などの排他切替、と同じ枠に載せる。
- **load-bearing な経路を先に移行する**。拾得判定・分解・破壊回収が `!Prop` に陰性依存している。設置状態の陽性判定へ
  反転してから `Prop` を除去する。反転前に消すとフィールドの家具・樽・扉が拾得やスタック消費の対象になり静かに壊れる。
- **段階的で各段が make check green**。追加 → 遷移導入 → 反転 → 削除の段に割る。
- **serde 互換**。ark-serde は skipComponents 除外の自動登録、`internal/save/serde.go:31-45`。旧セーブの `Prop` 参照を
  壊さない移行を設ける。
- **Ark strict semantics 遵守**。空タグの `Has`/`Get`、生成登録、serde を規約どおりにする。

## 設計

### 状態モデル

item は3つの排他的な「在り方」を持つ。所持、Location 系、はすでにある。ここへ**設置**を足す。

設置を既存 Location 家族の第5状態として足す。5状態は排他で、`clearLocation` が担保する。

```text
Location 家族(排他)                                  GridElement
 ├ LocationInBackpack{Owner}   所持              … 既存   無し
 ├ LocationEquipped{Owner,Slot} 装備             … 既存   無し
 ├ LocationInStorage{Owner}    収納              … 既存   無し
 ├ LocationOnField             落下(拾える)      … 既存   有り
 └ LocationPlaced              設置(HP+機能set)  … 新設   有り
```

- 落下と設置はどちらも `GridElement` を持つが、`LocationOnField` は拾え、`LocationPlaced` は耐久を持ち破壊・分解で材料に
  なり、取り外しで item 状態へ戻る、`Retrievable` の場合。区別は `Prop` タグでなく **どの Location コンポーネントを持つか**
  で表れる。現状 prop が持つ `LocationOnField` を `LocationPlaced` へ移すので、`IsPickable = LocationOnField` だけで済む。
- 設置物は同一 item エンティティのまま。設置で `LocationPlaced` と機能コンポーネントを付け、取り外しで外して所持へ戻す。
  別エンティティを立てない。`clearLocation` に `LocationPlaced` の除去を足し、排他を既存4状態と同じく担保する。

### コンポーネント

```go
// Placeable は「設置できる」を表す item 側の能力。設置時に付ける機能コンポーネント一式を PlacedForm で持つ。
// 全 item が持つわけではない。ポーションのように設置しない item は持たない。
type Placeable struct {
	PlacedForm PlacedForm // 設置状態で付与する機能コンポーネントの定義。raw の prop 属性から生成する
}

// PlacedForm は設置状態で付与する機能コンポーネントの束。既存の NewPropSpec が raw から optional に組む属性を
// そのまま畳んだもので、ゼロ値のフィールドは付与しない。輪郭は最小で、詳細は実装時に既存 spec から詰める。
// 耐久 HP はここにあり、item 状態では持たず設置時にだけ付く。
type PlacedForm struct {
	HP        int             // 設置物の耐久。0 なら不壊
	BlockPass bool            // 通行を塞ぐ
	BlockView bool            // 視界を塞ぐ
	PassCost  int             // 進入コスト。BlockPass と相互排他
	Storage   *WeightCapacity // 収納。nil なら非収納
	Door      bool            // 扉
	Light     *LightSource    // 光源
}

// LocationPlaced は item が世界へ設置されている Location 状態。既存の LocationInBackpack/Equipped/OnField/InStorage
// と排他の第5状態で、clearLocation が排他を担保する。GridElement を伴い、耐久 HP は PlacedForm から付く。Prop 種別
// タグの後継で、種別でなく位置状態を表す。破壊・分解では材料になり、取り外しでのみ item 状態へ戻る。
type LocationPlaced struct{}

// Retrievable は「設置状態から取り外して item 状態へ戻せる」を表す item 固有の能力。Placeable と同じく raw で決まり、
// item に全状態で付く。設置中だけ意味を持ち取り外しの可否を分ける。PlacedForm には含めない。これを持たない設置物は
// 取り外せず、破壊・分解で材料にするしかない。
type Retrievable struct{}
```

- `PlacedForm` は現在 `NewPropSpec` が raw から組む機能属性を「設置時に付ける集合」として畳んだもの。item の raw 定義が
  その設置形を持つ。`HP` は `PlacedForm` にあり、item 状態の Placeable item は耐久を持たない。設置で `HP` が付き、
  取り外し・破壊で外れる。よって耐久は設置状態だけの性質になる。
- `Retrievable` と `Placeable` は raw で決まる item 固有の能力で、所持中も設置中も item に付く。`PlacedForm` には含めず、
  設置状態でのみ取り外しの可否として作用する。
- 設置していない Placeable item は所持・落下でき、設置すると `PlacedForm` を展開して fixture になる。

### 遷移

```text
設置     PlaceItem   : 所持/落下 item → MoveToPlaced(clearLocation + LocationPlaced) + GridElement + HP + PlacedForm 展開
取り外し UnfixPlaced : Retrievable な LocationPlaced item → PlacedForm と HP を畳み MoveToBackpack。エンティティ保存
破壊     BreakPlaced : LocationPlaced item の HP が 0 → 実体を消滅させ材料を落とす。エンティティ消滅
分解     Disassemble : LocationPlaced item を工具で分解 → 実体を消滅させ材料を得る。エンティティ消滅
```

- 設置と取り外しは既存の `MoveToXxx` と同じ枠に載る。新設は `MoveToPlaced`、`clearLocation` の後に `LocationPlaced` を
  付け `GridElement` を残す、`MoveToField` が GridElement を残すのと同じ流儀、だけ。
- **設置は1個単位**。`Stackable` な item を設置するときは、既存の `TransferUnits` と同じく1個をスタックから分離して
  から `MoveToPlaced` する。設置物は `Stackable` を持たず、元スタックは1減る。
- **取り外しの処理順**。`UnfixPlaced` は先に `PlacedForm` と `HP` を外し、それから既存の `MoveToBackpack` を呼ぶ。
  `MoveToBackpack` が `GridElement` を外す。耐久は設置状態だけの性質なので、**取り外した item は耐久を引き継がず無傷で
  戻る**。設置中のダメージを所持 item へ持ち越さない。
- 除去は2系統に分かれる。**破壊・分解は材料にする**、実体消滅、既存の `dead_cleanup` の素材回収と `disassemble` を
  そのまま使う。**取り外しは元の item に戻す**、実体保存、Location 状態遷移。
- 取り外せるのは `Retrievable` を持つ設置物だけ。持たない設置物、例えば自然生成の樹木や固定された構造 prop、は
  破壊・分解で材料にするしかない。「固定を外すと item に戻るものもある」を能力で表す。
- 収納 prop、`Storage`、を破壊・取り外しするときは、中身を床へこぼしてから実体を処理する。既存の
  `SpillStorageItems` を使う。
- **自然生成の設置物**、doc 82 の屋外散布や POI の設置物、は item base を生成してから `MoveToPlaced` を流用して設置状態に
  する。専用の spawn 分岐を設けず、設置遷移を1本に保つ。

### load-bearing な3経路の反転

`Prop` を消す前に、`!Prop` 依存を Location 状態へ反転する。prop を `LocationOnField` から `LocationPlaced` へ移すので、
拾得判定は `!Prop` も `!Placed` も要らず `LocationOnField` だけになる。

| 経路 | 現状 | 反転後 |
|---|---|---|
| 拾得可否 `query.go:50-58` | `LocationOnField && !Prop` | `LocationOnField`、落下 item だけがこの状態を持つ |
| 分解 `disassemble.go:170` | `Prop && GridElement` → 実体除去＋収納こぼし / else スタック消費 | `LocationPlaced` → 実体除去＋収納こぼし / else スタック消費 |
| 破壊回収 `dead_cleanup.go:91` | `Prop && GridElement` の死骸を素材回収 | `LocationPlaced` の死骸を素材回収、材料になる |

### 従属する表示・分類の移行

- 影 `render_sprite.go:254`、`TurnBased || Prop` → `TurnBased || LocationPlaced`。
- 文言 `damage.go:57`・`look_around.go:296`、壊れた/耐久 の分岐を `LocationPlaced` 述語へ。
- カテゴリ `invariant.go` の `CategoryProp「置物」` を「設置状態」で再定義する。`Prop` は3つの CategoryGroup で参照され、
  `InventoryCategoryKey` の `CategoryGoods`、165行目、`ItemTypeCategoryKey`、173行目、`FieldLookCategoryKey`、185行目、の
  **3か所すべて**を `LocationPlaced` 述語へ移す。同じ item が所持中は「持ち物」、設置中は「置物」と、状態で分類が動く。

### 生成側

- item の raw に「設置形」を書けるようにし、`NewItemSpec` が Placeable な item へ `Placeable{PlacedForm}` を付ける。
- 現在の `[[props]]`、116件、は「設置形を持つ Placeable item」へ移す。`NewPropSpec` は item spec に統合し、`Prop{}`
  付与を廃す。取り外せる家具、樽・棚など、には `Retrievable` を付け、取り外せない構造物、壁・ドアや自然生成の樹木、は
  `Retrievable` を持たない LocationPlaced として破壊・分解専用にする。
- 自然生成、doc 82 の屋外散布や POI の設置物、は「item を設置状態で spawn する」経路になる。

## 採用しなかった方法

- **`Prop` をそのまま削除する** —— 3経路が `!Prop` に陰性依存し、削除するとフィールドの家具・樽・扉が拾得と
  スタック消費の対象になり静かに壊れる。設置状態の陽性判定へ反転してから消す。
- **`Carriable` 能力を1つ足して種別タグを反転するだけ** —— fixture/loot の区別を陽性へ反転する最小案。だが「設置は
  状態」「取り外しで item に戻る」という可逆遷移を表せない。doc 80 は家具を拾ってインベントリへ入れ内装へ設置する、
  item↔設置の往復を求めるが、`Carriable` だけでは prop を別の世界オブジェクトのまま残し所持状態への遷移を表せず半端に
  なる。状態モデルを採る。
- **設置物を別エンティティにして item と双方向リンクする** —— 設置のたびに fixture エンティティを立て item と結ぶ案。
  既存の Location 状態遷移が同一エンティティのコンポーネント差し替えで所持↔落下を解いており、設置も同じ枠に載せる
  ほうが一貫し、リンク管理の二重実装を避けられる。
- **破壊で元の item を丸ごと戻す、Minecraft 通りの挙動** —— 破壊・分解は材料にする既存挙動を保ち、元の item に戻すのは
  取り外しという別動詞に分ける。破壊で常に item が戻ると、壊す価値と作る価値の設計余地が消える。「固定を外すと item に
  戻るものもある」を `Retrievable` で限定表現する。
- **取り外しを設けず、Placeable なら常に item へ戻せるとする** —— 取り外せない構造物、壁・自然物、を表せない。
  取り外し可否を `Retrievable` で分け、能力の有無で「戻せるものもある」を表す。
- **設置を Location 家族と直交する独立マーカーにする** —— 設置を `LocationOnField` へ重ねる別タグにする案。だが
  `clearLocation` が独立マーカーを知らないため、設置物を拾って `MoveToBackpack` すると設置マーカーが残り、所持中の
  item が設置状態のままになる不整合が出る。設置を Location 家族の排他な第5状態 `LocationPlaced` にし、既存の排他機構に
  載せる。
- **壁・地形まで item 化する** —— 壁は現状 Tile で、prop 層と別。本 doc は prop 層の item↔設置統合に絞り、Tile の
  item 化には踏み込まない。

## コメント

- 本 doc の核は「Prop 削除」でなく「設置を種別タグから状態へ移す」ことである。Prop は「設置状態の item」に解消される。
  Item・Weapon タグを状態と能力へ分解した `bf30966ff` の路線の完成形になる。
- Minecraft 型の item↔設置は doc 80 の可搬家具、拾って内装へ設置、を素直に表す。設置状態と所持状態の遷移がそのまま
  家具の持ち運びになる。
- 除去は「破壊・分解で材料」と「取り外しで item に戻す」の2系統を並立させる。取り外しは `Retrievable` を持つ設置物に
  限る。どの設置物を取り外し可にするか、UI での動詞の出し分けはゲームデザインの論点として実装時に詰める。
- Ark strict semantics に留意する。状態遷移でのコンポーネント差し替え、空タグの `Has`、serde 登録の除外リストを
  規約どおりにする。
