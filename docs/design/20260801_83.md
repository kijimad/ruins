# Prop タグを廃し fixture を Location 状態にする —— ステーションは収納内 item で発動

## 背景

`Prop` コンポーネント、`internal/components/components.go:322` の `type Prop struct{}`、は空の種別タグである。だが実際に
担っているのは「フィールド上の物体が拾える loot か、漁って壊す恒久設置物 fixture か」の1ビットで、しかも
`IsPickable = LocationOnField && !Prop`、`internal/world/query/query.go:50-58`、と**陰性**で表現されている。曖昧さの元は
loose な loot も世界の fixture も両方 `LocationOnField` を持つ重なりで、そのため `!Prop` で分けている。

`Item` タグは既に撤去済みである。`bf30966ff`「冗長なカテゴリタグComponentを削除した」で `Item` と `Weapon` のマーカーを
消し、「アイテムか」を単一タグでなく、状態 `LocationOnField` と能力コンポーネント、Melee・Fire・Consumable・Ammo・Book・
Material・Wearable、へ分解した。Prop はこの整理から取り残された恣意的な種別タグである。

当初は Minecraft 型の item↔設置統合、item を置くと fixture になり壊すと item に戻る、を検討した。だがローグライクには
item と block の鋭い区別が無く、家具を運んで置き直す動機も無い。設置は「ステーションをキューブの収納に入れておくと発動」
に還元でき、可逆遷移の機構は over-engineering だった。検討の結論として却下し、採用しなかった方法に残す。

本 doc の方針は2点。**fixture の役割はタグでなく Location 状態で表す**。fixture か loot かは、漁る/壊すか運ぶ/使うかの
本物の役割で残すが、`Prop` タグを廃し `LocationFixture` 状態へ移す。Item を「タグ→状態」で消したのと同じ手である。もう1点、
**据え置きで利益を出すステーションは fixture でなく item にし、キューブの収納内での存在で効果を発動する**。設置サブシステムを
作らない。

## 要件

- **fixture の役割を `Prop` タグから Location 状態 `LocationFixture` へ移す**。役割は残し、タグを消す。
- **`LocationOnField` の重なりを解消する**。fixture を `LocationOnField` でなく `LocationFixture` で spawn し、
  `IsPickable = LocationOnField` だけに簡約する。
- **load-bearing な3経路を先に反転する**。拾得・分解・破壊回収の `!Prop` 依存を fixture 状態基準へ移してから `Prop` を
  削除する。反転前に消すと家具・樽・扉が拾得やスタック消費の対象になり静かに壊れる。
- **材料化の動詞は分解1本**。破壊、`HP`→0 のダメージ、は分解の発火条件に畳む。破壊と分解を別動詞にしない。
- **ステーションは収納内 item で発動**。溶接機・調理器などの効果は、item を持ち歩くのでなくキューブの収納内に在ることで
  与える。設置・取り外し・可逆遷移は作らない。
- **段階的で各段が make check green**。追加→反転→従属移行→削除→serde の段に割る。
- **serde 互換**。ark-serde の skipComponents 除外の自動登録、`internal/save/serde.go:31-45`、で `Prop` を移行する。
- **Ark strict semantics 遵守**。空タグの `Has`、生成登録、serde を規約どおりにする。

## 設計

### 弁別子: `Prop` タグ → `LocationFixture` 状態

```go
// LocationFixture は item が世界のタイルに fixture として在る Location 状態。既存の
// LocationInBackpack/Equipped/InStorage/OnField と排他の第5状態で、clearLocation が排他を担保する。
// GridElement を伴い、漁る・分解の対象になる。loose な loot は LocationOnField、fixture は LocationFixture、と
// 状態で分かれる。Prop 種別タグの後継で、種別でなく位置状態を表す。可逆遷移は持たず、生成時に付くだけ。
type LocationFixture struct{}
```

- 世界の fixture、家具・壁・棚・doc 82 の屋外散布、は `LocationFixture` で spawn する。プレイヤーは運ばず、漁って壊す。
- `clearLocation`、`internal/world/lifecycle/location.go:158-176`、に `LocationFixture` の除去を足し、排他を既存4状態と
  同じく担保する。fixture は破壊まで遷移しないので、実際に効くのは死亡・撤去の局面である。

### load-bearing な3経路の反転

`Prop` を消す前に `!Prop` 依存を fixture 状態へ移す。fixture が `LocationOnField` を明け渡すので拾得は簡約される。

| 経路 | 現状 | 反転後 |
|---|---|---|
| 拾得可否 `query.go:50-58` | `LocationOnField && !Prop` | `LocationOnField`、loose な loot だけがこの状態を持つ |
| 分解 `disassemble.go:170` | `Prop && GridElement` → 実体除去＋収納こぼし / else スタック消費 | `LocationFixture` → 実体除去＋収納こぼし / else スタック消費 |
| 破壊回収 `dead_cleanup.go:91` | `Prop && GridElement` の死骸を素材回収 | `LocationFixture` の死骸を素材回収 |

### 材料化は分解1本、破壊はその発火条件

- 材料を出す動詞は**分解**のみにする。工具での分解も、`HP`→0 のダメージによる破壊も、同じ「fixture を材料化する」経路へ
  畳む。破壊は分解の1カテゴリ、ダメージ起因の発火、として扱い、別動詞にしない。
- 収納 fixture、`Storage`、を材料化するときは、既存の `SpillStorageItems` で中身を床へこぼしてから実体を処理する。

### ステーションは収納内 item で発動

据え置きで利益を出す物、溶接機・調理器・ストーブ、は fixture でなく**通常の item** にする。効果は設置でなく、キューブの
収納内に在ることで発動する。

```text
効果の門: LocationInStorage(Owner = キューブの収納) かつ ステーション能力を持つ item → 効果を与える
```

- 棚に入れれば workshop が立ち上がり、持ち出せば止まる。設置・取り外しの行動も、fixture 化も要らない。既存の
  `LocationInStorage` 状態をそのまま門に使う。
- doc 80 の「presence 効果を持つ prop」と重量経済は、「presence 効果を持つ item、キューブ収納内で発動」に化ける。重量は
  運搬コストのブレーキとして残る。
- ステーション能力は capability コンポーネント、効果種別を持つ、で表す。具体は実装時に既存の効果系から詰める。

### 従属する表示・分類の移行

- 影 `render_sprite.go:254`、`TurnBased || Prop` → `TurnBased || LocationFixture`。
- 文言 `damage.go:57`・`look_around.go:296`、壊れた/耐久 の分岐を `LocationFixture` 述語へ。
- カテゴリ `invariant.go` の `CategoryProp「置物」` を `LocationFixture` 述語へ。`Prop` は `InventoryCategoryKey`、165行目、
  `ItemTypeCategoryKey`、173行目、`FieldLookCategoryKey`、185行目、の3か所で参照されるので全て移す。

### 生成側

- `NewPropSpec`、`raw.go:625-706`、は fixture の spawn 経路として残すが、`Prop{}` でなく `LocationFixture` を付ける。
  raw の `[[props]]`、116件、はそのまま fixture 定義として使える。
- ステーションは fixture でなく item として `NewItemSpec` にステーション能力を付けて定義する。

## 採用しなかった方法

- **Minecraft 型の item↔設置統合** —— item を置くと fixture になり、壊すと item に戻る可逆遷移。だがローグライクには
  item と block の鋭い表現差、ボクセル対スタック、が無く、棚 item と設置棚はどちらもスプライト付きエンティティで違いが
  薄い。家具を運んで置き直す動機も無い。設置は「ステーションを収納内 item で発動」に還元でき、`Placed`/`Placeable`/
  `Retrievable`/可逆遷移は薄い区別のための儀式になる。探索の結論として却下する。
- **`Prop` をそのまま削除する** —— 3経路が `!Prop` に陰性依存し、削除すると家具・樽・扉が拾得とスタック消費の対象になり
  静かに壊れる。fixture 状態の陽性判定へ反転してから消す。
- **fixture を種別タグのまま残す、現状維持** —— `Item`・`Weapon` を状態と能力へ分解した `bf30966ff` の路線と不一致。
  fixture を Location 状態にしてタグを消し、路線を揃える。
- **ステーションを設置物 fixture にする** —— 設置・取り外しのサブシステムが要る。収納内 item での発動で足り、既存の
  `LocationInStorage` 状態を門に使える。
- **破壊と分解を別動詞にする** —— 破壊は分解の1カテゴリ、ダメージ起因の発火、である。材料化の動詞を1本に畳む。

## コメント

- 本 doc の核は「fixture の役割はタグでなく Location 状態で表す」ことである。`Item`・`Weapon` を状態と能力へ分解した
  `bf30966ff` の路線の続きで、`Prop` タグを `LocationFixture` 状態へ移す。
- fixture の役割自体は消えない。漁る/壊す fixture か、運ぶ/使う item か、はローグライクの本物の役割区別で、能力に還元
  できない。消すのは恣意的なタグだけで、区別は Location 状態が担う。
- ステーションは doc 80 の presence 効果を、設置でなくキューブ収納内 item の存在で実現する。溶接機を持ち歩いても効かず、
  キューブの棚に据えて初めて workshop になる。
- Minecraft を検討して却下した経緯は採用しなかった方法に残す。看板にせず着想と対比に留める。
- Ark strict semantics に留意する。状態のコンポーネント差し替え、空タグの `Has`、serde 登録の除外リストを規約どおりにする。
