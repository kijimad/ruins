# 屋内外をタイルの種類で決め、部屋の形から推し量るのをやめる

## 背景

タイルの囲われ、つまり屋外・半屋外・屋内は、気温と地面の雪の両方に効く。今は部屋の形から3通りに推し量っている。

| 仕組み | 決め方 | 参考 codebase |
|---|---|---|
| `EnvironmentPlanner.floodFillOutdoor` | マップの外周から壁を越えずに届く領域を屋外にする | `internal/mapplanner/environment_planner.go:35` |
| `enclosedCells`、`roomIndoor` | 施設の絵の中で壁と扉に囲まれたマス、部屋の絵のマスを屋内にする | `internal/overworld/facility_template.go:106`、`internal/overworld/building.go:278` |
| `RecalcShelterAround` | 扉を開け閉めするたびに、周りの領域を塗り直す | `internal/world/lifecycle/shelter.go` |

推し量りは脆い。扉を開けると部屋が屋外になり、床に雪が積もった。壁に隙間がある部屋も屋外になる。市街地の外にある小屋は、どの仕組みも通らないので屋外のままである。

屋根は動かない性質で、床の種類とほぼ1対1に対応する。畳やリノリウムの床は屋内にしか無く、土や草は屋外にしか無い。

## 要件

1. 囲われはタイルの種類で決まる。同じ種類のタイルは、どこに置いても同じ囲われを持つ。
2. 扉の開閉で囲われを変えない。
3. 屋内と屋外の両方に使う種類のタイルを作らない。
4. 地図は位置から導く方針を保つ。

## 設計

### タイルの行が囲われを持つ

```cue
#Tile: {
	// ...
	// 囲われの度合い。省くと屋外
	shelter?: #Shelter
}
```

```go
// TileShelter はタイルの行の囲われを返す。行が省けば屋外
func TileShelter(t rawschema.Tile) rawschema.Shelter
```

- `raw.NewTileSpec` が `TileEnvironment.Shelter` を行から入れる。
- `EnvironmentPlanner` も同じ `TileShelter` で入れる。計画の環境は生成したタイルへ丸ごと写すので、両方で同じ値にする。
- 囲われの3段階と `shelterEffects` の行は残す。半屋外は、屋根付きの駐車場のような床を足すときに使う。

### 兼用していたタイルを分ける

施設の絵を全て調べると、兼用しているタイルは2つだった。

| タイル | 屋内 | 屋外 |
|---|---|---|
| `floor` | 遺跡・洞窟・小部屋の床、小屋の床 | 市街地の街路、道、森、町のレイアウトの道 |
| `floor_concrete` | 民家の玄関、コンビニの売り場、倉庫 | 駐車場、研究所の中庭 |

屋外の側に新しいタイルを足し、元のタイルは屋内にする。屋外で使うほうが多いが、`floor_` で始まる名前は屋内の床にそろえる。

| 新しいタイル | 絵 | 置き換える場所 |
|---|---|---|
| `road` | `floor` と同じ | `streetTerrain`、`road.go`、森の生成、町のパレットの道 |
| `pavement` | `floor_concrete` と同じ | 施設のパレットの `=`、研究所の中庭のパレットの `.`、屋外に置く家具の下のタイル |

- 民家とコンビニの屋内の `=` は、屋内のコンクリート床を指す別の文字に書き換える。

### 屋内にするタイル

`floor`、`floor_concrete`、`floor_wood`、`floor_tatami`、`floor_linoleum`、`floor_tile` を屋内にする。地図に置いていない板張り `plank_*` と滑らかな床 `smooth_*` も、床なので屋内にする。煉瓦 `brick_*` は外の舗装にも使える素材なので屋外のままにする。壁と虚空は通れないので囲われを使わず、屋外のままにする。

### 雪は囲われから導き、`snowable` を消す

囲われをタイルが持つと、`snowable` が区別するのは「屋根が無く通れる地面」だけになる。2つの欄に同じ事実を書くと、屋内なのに `snowable` という食い違う行を書けてしまう。欄を消し、雪の層は屋根が無く通れる地面に重ねる。

```go
// amount は地面 e に積もる雪の量を返す。通れて屋根の無い地面のときだけ正になる
func (l *snowLayer) amount(world w.World, e ecs.Entity, c consts.Coord[consts.Tile]) float64
```

- `#Tile` の `snowable` 欄、`Snowable` コンポーネントを消す。
- 水のタイルは今の raw に無いので、水を外す条件は足さない。通れるが雪が積もらない屋外のタイルを足すときは、その行の性質から雪を外す条件を足す。

### 推し量りの仕組みを消す

- `EnvironmentPlanner.floodFillOutdoor` と `geometry.EnclosedRegion`
- `enclosedCells`、`roomIndoor`、`spawnFacility` と `spawnFacilityTile` の屋内の引数
- `RecalcShelterAround` と、扉の開閉からの呼び出し

## 採用しなかった方法

- **屋根だけタイルで決め、熱の受け方は部屋の形から推し量る**: 扉を開けた部屋が冷える挙動は残るが、推し量りの仕組みが並び、ややこしさが減らない。
- **扉による塗り直しだけをやめる**: 変更は小さいが、屋根を形から推し量るのは変わらない。壁に隙間がある部屋や小屋は屋外のままで、雪が積もる。
- **屋外の側を元の名前に残し、屋内の側に新しいタイルを足す**: 屋外で使う箇所のほうが多いので書き換えは減るが、`floor_` で始まるのに屋外になるタイルが生まれ、名前から囲われが読めない。
- **`snowable` を残し、屋根のある囲われと一緒に書いた行を読み込みで弾く**: 食い違いは捕まえられるが、同じ事実を2か所に書く形は残る。欄を1つにすれば食い違いを書けなくなる。
- **タイルを分けず、置く側が囲われを指定する**: パレットや生成の呼び出しのたびに屋内外を書くことになり、書き忘れると今と同じ食い違いが起きる。

## コメント

- 扉を開けても部屋は冷えなくなる。外気が入る挙動を戻すなら、扉の近くのマスだけを温度で補正するなど、囲われと切り離した仕組みで足す。
- ダンジョンの `floor` は全て屋内になる。森は `road` にして屋外のままにする。
- 森は下地も空き地も `road` で埋まり、小道でない地面まで道と表示される。下地を土や草に分けるのは、golden が大きく動くので別に行う。
- 施設の絵の扉のマスは、パレットの `+` が指す屋内の床になる。外壁の扉の下も屋内なので、雪は積もらない。
- 施設の絵が置き場所に合うタイルを選んでいるかは、区画の縁から壁と扉を越えずにたどれる床が屋外のタイルを、たどれない床が屋内のタイルを指すかをテストで確かめる。
- 壁と虚空は行に `shelter` を持たないので屋外になる。立てず雪も積もらないので、見回しで壁を指したときの気温だけが変わる。
