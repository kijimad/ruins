# 拠点を据えて数日暮らし、尽きたら家ごと移る

## 背景

今のゲームには、ひとつの場所に留まって暮らす理由が無い。キューブを畳んで運ぶのは手番も燃料も使わず、どこで展開しても得るものは同じである。土地にも留まる理由が無い。拠点の周り 3×3 チャンクの食べ物と燃料で暮らせる日数を5つの seed で測ると、中央値で0日だった。敵は食べ物を落とさず、置物は壊しても燃料にならない。

そのため、拠点に愛着が生まれず、発つときに失うものも無い。ここでは、1つの土地で数日暮らし、乗り切って発つ一巡を、遊びの芯として組み立てるための要件を決める。

## 要件

要件が固まるまで、下の「設計の候補」は候補として扱う。

### 体験の狙い

遊び終えた後も覚えている情景を2つ決め、それを実現するのに要る仕組みを逆算する。

| 情景 | 見えているもの | 思ってほしい一言 |
|---|---|---|
| 吹雪の夜 | 外は吹雪と獣の気配。直した建物の中は暖かく、運んできた設備、蓄えた食べ物、積んだ燃料がある | ここは、自分で作った居場所だ |
| 発つ朝 | 襲撃を乗り切った朝、暮らしの道具をキューブに積んで雪原へ出る。振り返ると、世話になった建物は、襲撃の後の壊れた壁と、血の跡と瓦礫にまみれている | 乗り切った。世話になった。次へ行こう |

思い出は、場所の個性と数日の暮らしから自然に生まれればよく、記録する仕組みは要らない。遊びの手触りは、移りながら生き延びる緊張感にする。

### 一巡

1つのエリアでの一巡を、遊びの芯にする。

1. 新しいエリアに着き、手頃な建物に入り、壊れた所を直し、開いた所を塞いで拠点にする
2. 固定の周期で予告された襲撃の日を、拠点で乗り切る
3. 乗り切った後、周りで目標をこなし、報酬を得る
4. 世話になった拠点を離れ、より厳しく、より良い報酬のある次のエリアへ移る

主な時計は襲撃の周期で、乗り切ったら発つのが区切りになる。土地の食べ物と燃料が尽きることは、長居を防ぐ脇の圧にする。発つ理由は、尽きたから仕方なく移るよりも、次のエリアの方が良い物がある、という欲に置く。

### 守る条件

design.md の方針と、この議論で決めた条件。

- 恒久の拠点は持たない。拠点を強化しても、ずっと住めるようにはしない。強化は時間を買う物で、ずっとの安全は買えない
- 厳しさはプレイヤーの強さでなく、場所と時で決まる。襲撃の強さはエリアで決め、北ほど強い
- 圧は間欠的にする。普段は余裕を持たせ、長居のときだけ切迫させる
- 留まることを、ただ待つだけで得をする遊びにしない
- 運ぶか置いていくかに例外を作らない。全部を畳めるが、重い物は燃費が割に合わないので置いていく
- 建設はしない。何も無い地面に壁を建てない。手を入れられるのは、借りた建物の今ある壁、窓、扉のマスだけで、直す、塞ぐ、補強するに限る
- キューブは暮らしの道具を運ぶ物で、家ではない。勝手について来る。主役は人で、運転はしない
- 地下は作らない
- ソロのターン制で、群れと1手ずつ戦う重さを強いない

### 1つの土地での暮らしに要ること

- やることがある。加工、探索、狩り、建物の修理
- 発つ理由がある。次のエリアの方が良い報酬がある。その土地の食べ物と燃料もいずれ尽きる
- 備える理由がある。固定の周期で予告付きの襲撃が来る
- 残りが見える。土地の食べ物と燃料があとどれくらいか、次の襲撃が何日後かを、プレイヤーが知れる
- 詰まない。移る途中で燃料が尽きても、その場で立て直せる

### 拠点の整え方

家の中身は連れ歩き、殻は土地ごとに借りる。建物の形の種類は手で描く絵の数で決まり、多くは出せない。どの建物を借りるかは大きな判断にせず、着いたら手頃な建物に入る。判断の重みは、その建物をどう整えるかに置く。

| 整え方 | 選択 | 得と損 |
|---|---|---|
| 壊れた所を直す | どの壁、扉、窓を直して使うか | 直すほど暖かく守りやすいが、材料を食う |
| 開いた所を塞ぐ | どの窓と扉を塞ぎ、どこを開けておくか | 塞ぐほど守りやすいが、暗く、出入りが不便になる。開けておいた入口へ敵を集め、機銃を向けられる |
| 壁を補強する | どの面に材料を使うか | 材料は限られ、全部は固められない |
| 部屋を捨てる | 壊れた部屋を直すか、塞いで捨てて狭く暮らすか | 狭いほど暖かく守りやすいが、置ける物が減る |
| 設備を置く | 暖房、寝床、機銃を、どの部屋のどこに置くか | 暖かい奥に暮らしを、入口側に守りを置く |

- 誰がやっても同じ拠点にならない。限られた材料をどこに使うかで、拠点の形がプレイヤーごとに変わる
- 多様さは建物の形に頼らず、壊れ方、周り、巡ごとの状況の掛け合わせから出す。壊れ方は建物ごとに生成で変え、同じ形の建物でも直す所と塞ぐ所が変わる。巡ごとの状況の中心は、予告される襲撃の種類で、敵の来る方角と動き方で、塞ぐ所と固める面が変わる
- 暖まりやすさは室内の気温と体温へ、静かな所は眠りの質へ、広さは置ける設備の数へ流す。居心地値のような1つの数は作らない

### 報酬の法則

- 北の土地ほど寒く、拾える物も良い。報酬の差は、見て分かるようにする
- 報酬は、強くなること自体でなく、次のより寒い土地で暮らし、乗り切るための鍵にする。鍵を得ると次の土地へ踏み込め、その土地がまた次の鍵をくれる
- 鍵の形は3つで、互いを補う。どれかが足りなくても、他で補って進める
  - 運べる暮らしの道具。強い暖房や断熱で、より寒い土地の建物でも暖かく暮らせる
  - 人体改造。体が寒さに強くなり、外で動ける時間が延びる
  - 装備。防寒具で外の活動を、武器と機銃で襲撃を越える
- キューブは運ぶ器で、燃料という維持の手間を持つ

### 確かめる順番

作る前に確信までは持てない。置いている前提を分け、危うく、安く確かめられるものから順に確かめる。

| # | 前提 | 危うさ | 確かめ方 |
|---|---|---|---|
| 1 | 拠点の整え方が毎回違う判断になる | 高い | コードを書かずに確かめる。今ある建物の絵を紙に写し、壊れ方と襲撃の種類の札を引き、限られた材料でどこを直し、塞ぎ、固めるかを何度か試す |
| 2 | 報酬が次へ行こうと思わせる | 高い | コードを書かずに確かめる。北の土地ごとの報酬の差を表に並べ、行きたいと思えるほどの差かを見る |
| 3 | 外の寒さと中の暖かさの落差が、居心地として感じられる | 中 | 今の寒さと体温の仕組みのまま、手で作った建物に暖房を1つ置き、吹雪の夜を1晩過ごす |
| 4 | 直し、塞ぐことが、整える手応えになる | 中 | 壁と扉を直し、窓を塞げるだけの試作で、前後に暖かさと守りやすさが変わって見えるかを見る |
| 5 | 襲撃の準備が報われ、乗り切った手応えがある | 低め | 捨てる前提の試作で、手触りがよいことを確かめてある |
| 6 | 発つ朝に名残惜しさを感じる | 一番高い | 短い試作では出ない。1から5が通った後、作り込む前に、1つの拠点で数日を通しで遊ぶ |

6 を関門にする。数日の通しの遊びで名残惜しさが出なければ、作り込む前に方向を見直す。

### 数字の目安

| 項目 | 目安 | 状態 |
|---|---|---|
| 襲撃の間隔 | 固定。数日に1度 | 日数は未定。乗り切ったら発つので、1つのエリアに留まる日数もこれで決まる |
| 1日に要る食べ物 | 満腹1回の 500 | 今の仕組みの値 |
| 1日に要る燃料 | 地面の焚き火を1日もたせる熱量 3000、木で約15kg | 今の仕組みの値 |
| 1回の移動の距離と燃料 | 未定 | 燃料を締めるときに決める |

### 決めたこと

- 襲撃の周期を乗り切り、報酬を得て、次のエリアへ発つ一巡を、遊びの芯にする
- 襲撃の周期は、分かりやすく固定にする
- 報酬は、次のより寒い土地へ踏み込む鍵にする。鍵の形は、運べる暮らしの道具、人体改造、装備の3つで、互いを補う
- 家の中身は連れ歩き、殻は土地ごとに借りる。建設はせず、今ある壁、窓、扉のマスを直す、塞ぐ、補強するだけにする
- 建物選びは大きな判断にしない。判断の重みは、限られた材料での拠点の整え方に置く
- 前提を分け、危うく安く確かめられるものから順に確かめる。数日の通しの遊びを、作り込む前の関門にする

### 決める問い

設計に入る前に、次を決める。

1. 襲撃の周期の日数
2. 1日の過ごし方の例。朝から夜までに何をするか
3. エリアをどう区切るか。今の地上は北へなめらかに厳しくなるだけで、エリアの区切りが無い
4. 目標を誰が出すか。世界は無人で、依頼を出す人がいない。救難信号や古い記録など、物が目標を語る形が候補
5. 罠は待つだけで実るか。待つだけで得をしない条件とどう両立させるか
6. 襲撃を越えると何が得られるか。弾と修理の材料を減らすだけの税にしない
7. 土地の残りと、次の襲撃までの日数をどう見せるか
8. 拠点を置いたまま、プレイヤーが帯の外まで歩いたらどうするか
9. 移る途中で燃料が尽きたとき、どう立て直すか
10. 襲撃が暮らしの合間の試練にとどまり、拠点防衛の遊びに寄りすぎないか
11. 襲撃の種類を何にするか。種類ごとに、塞ぐ所と固める面が変わるようにする
12. 壊れ方をどう生成するか。今の施設の絵の上に、壊れた壁、扉、窓をどう散らすか
13. 直す、塞ぐ、補強するを、どの置物と材料で表すか。敵がそれをどう壊すか

## 設計の候補

この節は古い前提のまま残っている。キューブを家として襲撃が狙う、バリケードを建てる、という前提で書いてあり、今の要件とは合わない。要件が固まったら書き直す。襲撃と機銃は、捨てる前提の試作 `proto/base-raid` で、味方にした機銃とキューブへ押し寄せる12体の襲撃を遊び、手触りがよいことを確かめてある。留まって暮らす側は、まだ遊んで確かめていない。

### 拠点の一生

1. いい場所を選んでキューブを展開する。廃墟の壁や崖を使える場所は守りやすい
2. 予告で、次の襲撃までの日数が分かる
3. 残りの日数で、周りを漁り、狩り、罠を仕掛け、薪を集めに出る範囲を決める。遠いほど実りは多いが、戻るのが遅れる
4. 持ち帰った物を、食べ物・燃料・弾・機銃・バリケード・修理の材料のどれに回すかを決める
5. 囲いの中に機銃とバリケードを置く。どの面を厚くするかは土地の形で変わる
6. 襲撃をしのぐ。人は弾を足し、崩れた所を直し、最後の手段として自分も戦う
7. 襲撃を何度か越えるうちに、周りの食べ物と燃料が尽きる。キューブを圧縮して次の土地へ発つ。重いバリケードは置いていく

### 時計: 毎日の消費と、土地の限りある供給

留まれる日数は「その土地で手に入る量 ÷ 1日の消費」で決まる。生きるのに毎日要る食べ物と燃料が尽きると、留まれなくなり、移る。尽きても困らない物が尽きても圧にならないので、時計は食べ物と燃料で作る。

この時計の上で、加工は留まる日数を延ばし、探索は供給を見つけて延ばし、拠点の強化はその日数を安全に過ごす手段になる。いずれ尽きるので、強化してもずっと住めることにはならない。普通の土地が数日もつよう、量は測って合わせる。

### 土地の供給: 狩りと罠、薪

| 出どころ | 中身 | 尽き方 |
|---|---|---|
| 狩りと罠 | 土地の獣を狩る、または罠を仕掛けて待つと、肉が得られる | その土地の獣は数に限りがあり、狩るほど減る |
| 薪 | 木や家具を道具で壊して薪にする | 周りの木と家具の数に限りがある |

拾える物の量を増やすだけでは、拾って移るのが速くなるだけで、留まる手触りにならない。時間をかけて得る出どころを足す。

### 運ぶ物と置いていく物

区別のための印は作らない。全部が圧縮で畳まれ得る。運ぶかどうかは重さと値打ちの比で決まる。

- 畳んだ物の重さは `query.CubeWeight` に入り、1歩の燃料 `FollowFuelCost` を押し上げる。今の仕組みのままで、重い物ほど運ぶのが割に合わなくなる
- 機銃は作るのが大変で、比べて軽い。だから運ぶ
- バリケードはその土地の廃材で安く作れ、重い。だから普通は置いていく。次の土地に廃材が少ないと分かっていれば、燃料を払って積んでもよい

圧縮は置いた位置ごと畳み、展開で同じ並びに戻すので、運ぶ機銃を並べ直す手間は生まれない。手で置き直すのはバリケードだけで、その数は材料と囲いの広さで絞られる。置きまくる作業にしないため、バリケードは1つで数マスを塞ぐ大きめの物にし、数より置き場所を考えさせる。

### データ

```go
// Turret は据え置きの機銃。設備として囲いの中に置くと、手番ごとに射程内で射線の通る敵を撃つ。
// 弾は Charge に持ち、1発ごとに1減る。0なら撃たない。弾は補充メニューの充填で足す
type Turret struct {
	Range  consts.Tile
	Damage int
}

// Raider は襲撃で押し寄せる敵の印。展開したキューブを狙い、進路を塞ぐ物を殴って進む。
// 襲撃でない敵は今までどおり振る舞う
type Raider struct{}

// RaidForecast は次の襲撃の予告。ワールドに1つ持つ。予告の日になると襲撃を起こし、次の予告を引く
type RaidForecast struct {
	Day   int // ゲーム内の日。暦の日数と同じ数え方
	Kind  RaidKind
	Count int
}

// RaidKind は襲撃の種類。最初は1種だけで、天候の味付けを足すときに増やす
type RaidKind string
```

### 予告

- ゲームの開始時と襲撃の後に、次の襲撃の日を引く。間隔は数日で、拠点に何日いるのがちょうどよいかに合わせて決める
- 残りの日数を HUD に出し、近づくとログで知らせる
- 予告の日の夜に、展開しているキューブがあれば襲撃を起こす。展開していなければ、キューブのそばで起こす

### 襲撃

- キューブを中心とした輪の上に `Raider` を持つ敵を `Count` 体出す。出す位置は通れて誰もいないマスに限る。地上では床もエンティティなので、空きマスは `activity.CanMoveTo` で判定する
- 出した敵の手番は、普段の敵と同じ `aiinput` の処理で回す

### 敵の振る舞い

`Raider` を持つ敵の行動を `soloPlanner` に足す。

1. 3マス以内に敵対の相手がいれば、今までどおりそちらと戦う
2. キューブに隣接していればキューブを殴る
3. キューブへ寄る1歩を試し、進めればそちらへ動く
4. 進めず、寄る方向に通れない置物があれば、その置物を殴る

今の敵は道を探さず、寄る方向の候補を順に試すだけなので、4 が無いとバリケードの手前で止まる。

### 機銃

- 試作では固定の敵を味方に寝返らせたが、正式には設備にする。作った機銃を設備の配置画面で囲いの中に置くと、その場の置物になり、手番を持つ
- 置いた機銃は、射程内で射線の通るいちばん近い敵を撃つ。撃つ行動は試作で足した `TurretShoot` を元にし、弾を1減らす
- 射線はバリケードを通る。バリケードは通れないが見通せるものとして扱う
- 片付けると物に戻り、残りの弾も持ったままになる

### バリケード

- 作ったバリケードを設備の配置画面で囲いの中に置く。置くと通れない置物になり、HP を持つ
- 壊れると、置物の今の仕組みどおり残骸になる
- 修理は材料を使って HP を戻す

### 世界の形: 帯を家に合わせる

帯がずれるきっかけを、プレイヤーの位置でなく家の位置にする。家を置いている間は周りの土地が消えず、どの方向にも探索できる。家を北へ動かしたときだけ、帯が北へずれて南の土地が消える。あわせて帯の横幅を広げ、拠点の周りを数日かけて探索できるようにする。

```go
// 帯を北へずらすかを、プレイヤーでなく家の帯ローカルの行で判断する
if dr.band.ShouldShiftNorth(cubeLocalY) {
	if err := dr.band.ShiftNorth(world, dr.gen); err != nil {
		return err
	}
}
```

### 燃料を締める

土地の供給が整ったうえで、移る燃料を締め、移ることを重い決断にする。量は時計と合わせて測って決める。

### 負けたとき

キューブが壊れたら、今の仕組みどおり残骸になり、核から作り直す。襲撃のための特別な負け方は作らない。

## 採用しなかった方法

| 案 | 採らなかった理由 |
|---|---|
| 天候だけの災厄 | 備えが済めばこもって待つだけになり、うまく備えるほど退屈になる。天候は後で襲撃の性格を変える味付けに回す |
| 人が群れと1手ずつ戦う | ソロのターン制では手数が重く、同じ判断を何十回も繰り返す |
| 戦闘を数値で即決する | 準備の値打ちが見えにくい。試作で、押し寄せるのを見る緊張に手応えがあった |
| 機銃を置いていく物にする | 毎回の準備は重くなるが、家を育てる手応えが薄れる |
| 置いていく物に固定の印を付け、圧縮から外す | 例外が増えて分かりにくい。重さで割に合わないから置いていく方が、選ぶ自由も残る |
| 運転型のキューブ | 主役は人にしたい。運転は不自然で、作るのも重い |
| 地下の施設を守る | ruins では地下を作らない |
| 燃料だけを締める | 移るのが面倒になるだけで、留まる理由は生まれない |
| 畳む・広げるに手番をかける | 足止めの手間が増えるだけで、選ぶ所が生まれない |
| 家の温まり | 家が住むほど暖まるという理由が不自然だった |
| 土地勘や段取りで能率が上がる | 留まるほど楽になり、厳しさが削れる |
| 設備の能率を留まるほど上乗せする | 留まるほど楽になりすぎる。暖機運転は、上限を今の能率にする形でだけ後の候補に残す |
| 尽きることだけを圧にする | 漁り尽くした土地でも、固めた家に安全に居座れて、緊張にならない。毎日の消費と襲撃と組み合わせる |
| 拾える物を増やすだけ | 拾って移るのが速くなるだけ |
| 留まるほど敵が気づいて寄ってくる気配 | 予告付きの襲撃の方が、備える日数が見えて準備を楽しめる |
| 土地を区切り、間を俯瞰図の旅にする | 留まる・移るのリズムは一番はっきりするが、地続きの世界を作り直す大きな変更になる。帯を家に合わせて足りなければ考える |
| どの方向にも続く地続きの世界にする | 漁った跡を土地ごとに保存する仕組みが要る |
| 拠点を自由に建てる | 拠点防衛の建設は、壁や罠の種類、置き場の操作、敵の経路まで揃えないと満足させられず、作るのが沼になる |
| 建物選びを一巡の大きな判断にする | 建物の形の種類は手で描く絵の数で決まり、数巡で覚えてしまう。性質の得と損を付けても、形が少ないと毎回同じ選択になる |
| 直すのは壊れた所を元に戻すことだけに絞る | 誰がやっても同じ拠点になり、自分で整えた居場所と感じにくい |
| 殻に居心地値の1つの数を持たせ、バフをかける | 居心地値が一番高い建物を選べばよい、になり、最強の1つを選ぶ問題が残る。数を前に出すのは、身体の訴えで感じさせる方針とぶつかる |
| 報酬の中心を1つの種類に絞る | 1つが足りないと進めなくなり、自分なりの生き方の幅が狭まる。種類でなく、次の土地へ踏み込む鍵という役目で決める |
| 研究所は寒いので拠点にできない、のような決まりを足す | 決まりは理不尽に感じる。広く窓の割れた建物は暖まりにくい、という性質から寒さが出る形にする |

## コメント

- 着想は、血の月の夜に襲撃が来て拠点を固める遊びと、波の間に資源を掘って守る遊びである。どちらもソロで成り立っている
- 一巡と報酬の着想は、7 Days to Die と Cataclysm: Dark Days Ahead である。危険な場所ほど良い物があり、報酬が次のより危険な場所へ踏み込む力になる、という形が共通している
- 試作は `proto/base-raid` にある。機銃3基でもキューブの HP 200 を守り切れなかった。数値の釣り合いは正式に組んでから詰める
- 圧縮には重さの上限が効かない。重いバリケードを無理に積んだときに燃料が尽きる以外の歯止めが要るかは、遊んで決める
- 地上に置いた置物が、保存と読み込みをまたいで残るかは確かめていない。拠点に数日いる間は残らないと困る
- 後で足す候補は、天候の味付け、襲撃の種類、前触れを読む知識、灯りや罠などの守り、暖機運転である。暖機運転は、家を広げた直後は設備が冷えていて能率が低く、動かしているうちに今の能率まで戻る仕組みで、加工の設備ができてから考える
- 土地が何日もつかの数字は、開始の行の近くだけの値で、北の奥では違うかもしれない。測るのに使ったテストはコミットしていない。`internal/balance` の指標として残すのがよい
- 1つの土地に何日いてほしいかは数日とした。数字はまだ決めていない
