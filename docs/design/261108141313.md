# キューブの燃料タンクに上限を持たせ、モジュールで容量を伸ばす

## 背景

キューブの燃料は `FuelTank{Heat}` の燃料ポイントで、上限が無い。ゲージは表示上の基準 `FuelGaugeFullHeat = 3000` に対する比を 0..1 に丸めて描くだけになっている。参考 codebase: `internal/components/field.go`、`internal/consts/consts.go`。

上限を持たせると、満タンが実際の値になり、タンクを広げるモジュールという強化の要素を作れる。キューブの強化は見える形で与える方針とも合う。

上限の扱いは、個人の装備と同じ仕組みにそろえる。装備を付け外しすると持ち主に `StatsChanged` が付き、`StatsChangedSystem` が保存済みの上限、すなわち HP・AP・積載を計算し直す。現在値が新しい上限を超えれば切り詰める。参考 codebase: `internal/world/lifecycle/location.go:99`、`internal/systems/stats_changed.go`。

## 要件

1. 燃料タンクは上限と現在値を持つ。
2. 上限は、基準容量に装着中のモジュールの燃料容量ボーナスを足した値になる。
3. モジュールを付け外しすると、装備と同じく `StatsChanged` を経て上限を計算し直す。上限が下がって現在値を超えたら、上限まで切り詰める。
4. 給油は満タンでなければでき、あふれた分は捨てる。満タンのときはくべず、ログで知らせる。
5. 燃料タンクを広げるモジュールのアイテムを1つ足す。
6. 新規開始時は満タンで始める。ゲージは現在値を上限で割って描く。

## 設計

### データ

変更前は次のとおり。

```go
type FuelTank struct {
	Heat consts.Heat
}
```

変更後は次のとおり。HP・積載と同じく `Pool` を使う。

```go
// FuelTank はキューブの燃料ポイントの上限と現在値。上限は装着中のモジュールから StatsChangedSystem が計算する
type FuelTank Pool[consts.Heat]
```

モジュールの性能に燃料容量ボーナスを足す。

```go
type CubeModule struct {
	RangeBonus        consts.Tile
	FuelCapacityBonus consts.Heat
}
```

```tsp
model CubeModule {
  rangeBonus: RangeBonus;
  fuelCapacityBonus: FuelCapacityBonus;
}
```

どちらも必須にし、効果を持たないモジュールは 0 を書く。optional にすると Go 側がポインタになり、読む側に nil の分岐が増える。

### 上限の計算

- `FuelGaugeFullHeat` を `CubeFuelCapacityBase` に改める。表示上の基準でなく、実際の基準容量になる。
- `query.CubeFuelCapacity(world, cube)` が `CubeFuelCapacityBase` に装着中モジュールの `FuelCapacityBonus` を足して返す。展開範囲の `CubeDeployRange` と同じ形にする。
- `StatsChangedSystem` は `StatsChanged` を持つ実体を1回の走査で集め、実体ごとに印を1回だけ外してから、`Abilities` を持てば能力値を、`FuelTank` を持てば燃料タンクを計算し直す。燃料タンクは `Max` を `CubeFuelCapacity` で書き直し、`Current` が超えていれば切り詰める。走査を分けると毎フレームの確保が増え、片方が先に印を外すと他方の計算が飛ぶ。

### 印を付ける場所

- 装着の `MoveToInstalled` で、装着先のキューブに `StatsChanged` を付ける。
- 取り外しは、モジュールが別の場所へ移るときの `clearLocation` を通る。`LocationInstalled` を外すとき、元のキューブに `StatsChanged` を付ける。
- 装備も同じく、`clearLocation` で `LocationEquipped` を外すとき元の持ち主に `StatsChanged` を付ける。これまで装備は移動先の `MoveToBackpack` だけが印を付けており、収納や地面へ直接移すと能力値が戻らない穴があった。外す側で付ければ移動先に依らず漏れない。
- `StatsChanged` はセーブ対象なので、印を付けた直後にセーブしても再計算は失われない。

### 給油と消費

- `AddCubeFuel` は、満タンなら何もせず false を返し、アイテムも消さない。満タンでなければ熱量を足して `Max` で切り詰め、アイテムを消す。
- 給油メニューは、キューブのくべ先が false を受け取ったら「燃料タンクは満タンだ」とログを出す。
- `ConsumeCubeFuel` と `CubeFuelTotal` は `Current` を読み書きする。
- `FuelGaugeRatio` は `Current / Max` にする。

### モジュール

`cube_fuel_module` を raw に足す。燃料容量ボーナスは 1500、すなわち基準容量の半分にする。既存の範囲モジュールは燃料容量ボーナスを 0 にする。

## 採用しなかった方法

- **上限を保存せず毎回計算する**: 展開範囲と同じ形で、値がずれようがない。ただし個人の装備は上限を保存し、付け外しの印で計算し直している。キューブもそれにそろえ、上限を持つ量を同じ `Pool` で表す。
- **入りきらない燃料は選べない**: 無駄は出ないが、満タン近くでは石炭のような大きい燃料が一切くべられなくなる。
- **取り外しで上限を超えた分を残す**: 装備を外したときの AP と同じく切り詰める。仕組みをそろえる。
