# 拠点に機銃を置き、置き物で入口を塞いで襲撃を受ける

## 背景

襲撃は設計ドキュメント 261128105246 で入った。1晩の数は、機銃と置き物で塞ぐ守りがある前提の物量にしてあり、その2つは別の設計で足すとした。今はプレイヤーが殴り合って守るしかなく、数に対して厳しい。設計ドキュメント 261125003808 の一巡でも、入口を塞いで敵を集め、そこへ機銃を向ける、を拠点を整える判断の芯にしている。捨てる前提の試作で、機銃で群れを受ける手触りがよいことは確かめてある。

今の作りでは、どちらも成り立たない。

| 要るもの | 今の作り |
|---|---|
| 置いた物で塞ぐ | 置く設備 `Deployable` は、置くと通れて見通せる置物になる。`applyDeployable` が通り方と見通しを固定で付け、HP も持たない |
| 地上のどこにでも置く | 置けるのは設備の画面からだけで、キューブの野営の範囲に限られる。範囲は画面のカーソルが押さえ、`PlaceFacility` 自体は座標を確かめない。持ち物の「置く」は足元にアイテムのまま落とすだけ |
| 敵が塞ぐ物を壊しに来る | ある。襲撃の敵は距離の地図で、HP を持つ通れない置物を重く通れるマスとして数え、道の上にあれば殴って壊す |
| AI が撃つ | 無い。撃つ `ShootBehavior` は、武器をプレイヤーの手の選択 `SelectedHeld` から取るので、AI の実体には使えない。撃つ敵もいない |
| その場から動かず戦う | 無い。戦闘の方針が `attack` だと、動き方が `stationary` でも、敵が見えれば追いかけて殴る。`iron_sentinel` が実例 |
| 射線 | ある。`activity.CanShootTarget` が射程と射線を見る |
| 機銃と塞ぐ物を手に入れる | 無い。置く設備を作るレシピは無く、職業の初期所持品と落ちている物の表でだけ手に入る |

## 要件

- 置き物で塞ぐ。プレイヤーの隣の空いたマスに、地上のどこにでも置ける。塞ぐ物は通れず、HP を持ち、壊されると残骸になる。置いた物は隣から回収してバックパックへ戻せる
- 機銃を置く。置いた機銃は動かず、射程の中で射線の通る一番近い敵を自動で撃つ。最初は弾を撃ち尽くさない。弾を込める手間は後で足す
- 塞ぐ物は1種にし、見通せる柵にする。機銃は柵の向こうへ撃てる。種類は遊んでから足す
- 機銃と塞ぐ物は、襲撃の敵から見て壊す相手になる。塞ぐ物は時間を稼ぎ、機銃はそこへ集まった敵を撃つ
- 塞ぐ物はその土地の材料で安く重く、機銃は軽く高価にする。置きまくる作業にしない歯止めは、重さと材料と囲いの広さに置く
- 機銃はキューブと一緒に運べる。置いていく物にしない

## 設計

### 置いた形を raw の行で決める

置く設備の行に、置いた後の形を足す。無ければ今と同じく通れて見通せる置物になる。

```cue
// internal/rawschema/schema.cue

#Deployable: {
	storage?: #StorageRaw
	bedding?: #Bedding
	// blocking は置くと通れない置物になる設備の形。無ければ通れて見通せる
	blocking?: #DeployableBlocking
	// turret は置くと射程の中の敵を撃つ設備の性質
	turret?: #DeployableTurret
}

#DeployableBlocking: {
	hp!:         #HitPoints
	seeThrough!: bool
}

#DeployableTurret: {
	// 射撃の性質は手に持つ射撃武器と同じ fire の行で持つ
	fire!: #Fire
}
```

`applyDeployable` は、`blocking` があれば `Passage{Passable: false}`、`Visibility{SeeThrough}`、`HP` を付ける。`turret` があれば `Fire` を設備の実体そのものに付け、戦闘の方針 `hold` と動き方 `stationary` の `SoloAI`、味方の陣営、手番を付ける。バックパックの中では `GridElement` を持たないので、AI の手番に入らない。置くと地上の実体になり、手番に入る。

### 撃つ武器を、撃つ実体から引く

`ShootBehavior` は、撃つ武器を `query.ShooterFire` で引く。撃つ実体が自分で `Fire` を持てば自分を、持たなければ今どおり手に持つ武器を返す。プレイヤーの撃ち方は変わらない。

```go
// internal/world/query/equipment.go

// ShooterFire は shooter が撃つ射撃武器を返す。自分で Fire を持つ実体は自分を、持たなければ手に持つ射撃武器を返す
func ShooterFire(world w.World, shooter ecs.Entity) (ecs.Entity, bool)
```

### 戦闘の方針 hold

戦闘の方針に `hold` を足す。動かずにその場で戦う方針で、機銃に限らず、弓を持つ敵の見張りにも使える。

- 射程の中で `activity.CanShootTarget` が真の、一番近い敵対する相手を撃つ
- 撃てる相手がいなければ待つ。追わず、逃げない
- 殴られても方針は変わらない。`ReactToHostile` で `attack` へ移さない
- 弾が尽きれば待つ。プレイヤーが込めるまで撃たない

`Plan` の先頭で、`Converge`、`Passive` と並べて分ける。

### 弾は後で足す

最初は、raw の機銃の `fire` に、1晩では撃ち尽くさない大きな装弾数を持たせる。撃つ処理は手に持つ武器と同じく装弾数を減らすので、機銃だけの例外は作らない。弾を込める手間を足すときは、相互作用の「弾を込める」で、バックパックの機銃に合う口径の弾を込める。

### 置く、回収する

持ち物のアイテムの操作に「設置」を足す。`Deployable` を持つアイテムを、プレイヤーの隣の空いたマスへ置く。キューブの野営の外でも置ける。置いた物に隣接して相互作用の「回収」を選ぶと、バックパックへ戻す。収納に中身があれば戻さない。設備の画面から置く今の経路はそのまま残す。

```go
// internal/world/lifecycle/facility.go

// PlaceNextTo は装着アイテム item を、player の隣の coord へ置く。coord が隣でないか空いていなければ error を返す
func PlaceNextTo(world w.World, player, item ecs.Entity, coord consts.Coord[consts.Tile]) error
```

### 手に入れる

塞ぐ物と機銃をレシピで作れるようにする。材料は決める問いに残す。

## 採用しなかった方法

| 案 | 採らなかった理由 |
|---|---|
| 機銃を毎ターン撃たせる専用のシステムを作る | 撃つ判定、命中、弾の減り方を撃つ処理と二重に持つ。AI の手番と方針に乗せれば、弓を持つ敵にも使える |
| 機銃に `attack` の方針と `stationary` の動き方を付ける | `attack` は敵が見えると追いかけて殴る |
| 機銃に手で持つ射撃武器を持たせる | 手の選択はプレイヤーのものなので、AI の実体の武器を引けない。持ち物と装備の仕組みも機銃に要る |
| 塞ぐ物を野営の範囲の中にだけ置く | 野営は狭く、建物の窓や扉に届かない |
| 塞ぐ物を壁のタイルにする | 建物は建てない方針で、置けるのは向きの無い置き物だけ |
| 撃つ処理で機銃だけ弾を減らさない | 撃つ処理に例外が要る。装弾数を大きくすれば、データだけで同じことができる |
| 塞ぐ物を見通せる柵と見通せない板の2種にする | 種類の多さで遊ばせない方針で、まず1種で守りが成り立つかを見る |

## コメント

- 塞ぐ物を野営の外に置けるので、遠征先の建物を塞いで退路を作る使い方もできる。置いた物は帯が流れると消える
- 機銃の射撃は命中に距離と遮蔽の補正が付く。射線を見通せない物で切るので、塞ぐ物を見通せない物にすると、その向こうへは撃てない。窓を塞ぐなら、見通せる柵と見通せない板で守り方が変わる
- 試作では機銃3基でもキューブの HP 200 を守り切れなかった。数と射程と弾の量は、遊んで調整する

## 決める問い

1. 塞ぐ物と機銃のレシピの材料。塞ぐ物はその土地で拾える物、機銃は遠征で探す部品にする
2. 機銃の射程、弾の口径、装弾数、HP
