# キューブを運転する乗り物から、追従と待機を切り替える随伴者にする

## 背景

キューブは、プレイヤーが乗り込んで運転する乗り物になっている。この形は、遊んでいて自然なプレイ体験にならない。

- **乗っても何も変わらない**。運転は、プレイヤーが1マス歩くのと同じ1手でキューブを追随させるだけで、速さは徒歩と同じ。それなのに1タイルごとに `5 + 積載kg` の燃料を払う。参考 codebase: `internal/activity/player_actions.go:107`、`internal/world/query/cube.go:149`。
- **速さを足すと逃走手段になる**。キューブは通行可能な1マスの地物なので、扉も廊下も通れる。徒歩より速くすると、危険な場所でも戦わずに逃げ切れてしまう。
- **乗っている間の絵が曖昧**。乗車中のプレイヤーは描画から外れ、キューブだけが動く。参考 codebase: `internal/systems/render_sprite.go:202`。

そこで乗るのをやめる。キューブは、プレイヤーの後を自分で追う随伴者にする。追わせると燃料を食うので、節約したいときは「ここで待て」と命じて置いていく。待たせた場所へは、自分の足で戻る。

ついてこさせるか、待たせるかが燃料の判断になる。速さは持たないので、逃走手段にはならない。キューブは語らない。命令に従うだけの物として扱う。

## 要件

1. 乗車と運転をなくす。プレイヤーはキューブに乗らない。
2. キューブは追従と待機の2つのモードを持つ。モードはキューブメニューから切り替える。
3. 追従中のキューブは、プレイヤーに隣接するまで毎ターン1歩近づく。1歩ごとに燃料を払う。燃料の式は今の運転と同じにする。
4. 燃料が足りなければ、キューブはその場で待機に切り替わり、ログで知らせる。
5. 待機中のキューブは動かず、燃料も払わない。
6. 展開中のキューブは常に待機する。追従へ切り替えるには、先に圧縮する。
7. 遠隔の呼び戻しは持たない。待たせたキューブを動かすには、隣まで戻って命じる。
8. 帯のシフトで南端の行が破棄されるとき、そこに待機中のキューブがあれば失われる。その手前で警告を出す。
9. 燃料ゲージは、乗車中ではなく追従中に表示する。

## 設計

### データ

乗車を表す `Driving` と、乗れることを表す `Drivable` を廃止する。代わりに、随伴者であることとモードを持つ `Follower` を足す。

変更前は次のとおり。

```go
// Drivable は運転可能であることを示すマーカー。SpawnCube が付与する。
type Drivable struct{}

// Driving はプレイヤーが運転中であることと運転対象の乗り物を表す。一時状態なので保存しない。
type Driving struct {
	Vehicle ecs.Entity
}
```

変更後は次のとおり。

```go
// Follower はプレイヤーに随伴する NPC であることと、その移動モードを表す。モードは保存する。
type Follower struct {
	Mode FollowMode
}

// FollowMode は随伴者の移動モード。
type FollowMode int

const (
	// FollowModeStay はその場に留まる。燃料を使わない
	FollowModeStay FollowMode = iota
	// FollowModeFollow はプレイヤーに隣接するまで毎ターン1歩近づく。1歩ごとに燃料を払う
	FollowModeFollow
)
```

- **既定は待機**にする。ゼロ値を待機にしておくと、生成直後やロード直後に勝手に燃料を使わない。
- **`Follower` は保存する**。`Driving` は一時状態として保存から外していたが、モードはプレイヤーの命令なので、ロード後も保つ。
- `SpawnCube` は `Drivable` の代わりに `Follower{Mode: FollowModeStay}` と `TurnBased` を付ける。`TurnBased` は AP ループで行動するために要る。

### 追従の行動は aiinput に専用の planner を足す

敵と中立 NPC は、`aiinput` の `soloPlanner` が行動を決め、`runAPLoop` が AP を消費しながら実行している。参考 codebase: `internal/aiinput/processor.go:42`、`internal/aiinput/planner.go`。随伴者も同じ AP ループに乗せて、移動は既存の Move Activity を使う。

```go
// followerPlanner は随伴者の行動を決める。追従中でプレイヤーに隣接していなければ1歩近づき、
// それ以外は待つ。燃料が1歩分に足りなければ待機へ切り替えてログを出す
type followerPlanner struct{}

func (fp *followerPlanner) Plan(world w.World, entity ecs.Entity) *gc.Activity
```

- 1歩の選び方は、敵の追跡 `planChaseAction` と同じく、プレイヤーとの差から移動候補を並べて最初に通れるマスへ進む。参考 codebase: `internal/aiinput/planner_solo.go:177`。候補の計算は共有する。
- 燃料は、移動が成立したあとに払う。成立しなかった歩みでは燃料を使わない。今の運転と同じ順にする。参考 codebase: `internal/activity/player_actions.go:118`。
- **キューブは通行可能なので、廊下や扉を塞がない**。プレイヤーの後ろを歩いても、プレイヤーの通り道を邪魔しない。プレイヤーと位置を入れ替える処理は要らない。
- プレイヤーが1ターンに複数回行動できるときは、キューブが遅れる。重い荷を抱えた随伴者が遅れるのは自然なので、追いつかせる特例は作らない。

### 命令はキューブメニューから

キューブメニューの「運転」を、モードの切り替え項目に置き換える。参考 codebase: `internal/states/cube_menu.go:77`。

| 状態 | 項目 | 結果 |
|---|---|---|
| 待機・圧縮中 | ついてこい | `FollowModeFollow` へ |
| 追従中 | ここで待て | `FollowModeStay` へ |
| 展開中 | ついてこい は無効表示 | 圧縮が先 |

展開はモードを待機へ切り替えてから行う。展開と追従は同時に成り立たない。

### 帯のシフトで失われる

帯は 24×24 タイルのチャンクが7列×9行で、プレイヤーは中央の行にいる。参考 codebase: `internal/dungeon/registry.go:66`。シフトのたびに、南端の行はプレイヤー以外まとめて破棄される。参考 codebase: `internal/worldstream/band.go:76`。待たせたキューブは、プレイヤーが北へ約4チャンク、すなわち約100タイル離れると消える。

- **消えることを仕様にする**。北へ前進するだけの世界で、置いてきた物は戻らない。破棄から外して残しても、帯の外へ出るので二度と届かない。
- **警告を出す**。キューブが南端の行に入ったシフトで、「キューブが遠すぎる。次に北へ進むと置き去りになる」とログを出す。
- **積み荷も一緒に失われる**。圧縮中の積み荷 `LocationStowed` と燃料タンクの中身は GridElement を持たないはずで、行の破棄では消えずに孤立する。ここは未確認なので、キューブの削除時に所有物を連鎖して消す処理が要るかを実装時に確かめる。

### 表示

- 燃料ゲージは、乗車中フラグ `hud.Data.Driving` を `FollowerFollowing` に置き換えて、追従中に描く。参考 codebase: `internal/widgets/hud/data.go:37`。
- 乗車中のプレイヤーを描画から外す処理は、乗車がなくなるので消す。参考 codebase: `internal/systems/render_sprite.go:202`、`internal/systems/render3d.go:367`。
- マクロ地図のキューブマーカー `DriveCubeTiles` は `CubeTiles` に改め、`Follower` で集める。

## 採用しなかった方法

- **運転を残し、乗り物らしさを足す**: 慣性、道でだけ速い、建物に入れない、などを足す案。作る量が大きく、速さを持つと逃走手段になる。
- **視界に敵がいないときだけ速く運転する**: 移動用の速さが戦闘へ漏れない。ただ、乗るという体験の不自然さはそのまま残る。
- **ソリのように縄で牽く**: 身体の比喩は自然。ただ、牽いている間はプレイヤーが常に重くなり、戦う前に縄を外す操作が毎回挟まる。随伴者なら、待たせるかどうかを一度決めるだけで済む。
- **遠隔で呼び戻す**: 便利だが、待たせた場所との距離が意味を失う。長い距離を自動で戻る経路探索も要る。
- **待機中のキューブを帯の破棄から外す**: 帯の外へ平行移動されて、二度と届かない場所に残るだけになる。
- **キューブが語る**: 語り口は持たない。命令に従う物として扱い、物語はキューブに背負わせない。

## コメント

- 燃料の式は改名するだけで値は変えない。乗車から随伴に変わると燃料の使い方の感覚が変わるので、実際に遊んでから詰める。
- 敵はキューブを狙わない。敵は最寄りの敵対陣営を狙い、キューブは陣営を持たないため。キューブを連れて危険な場所へ入る代償を作るなら、別の判断にする。
- キューブは今後、戦闘や採取など他の命令を持てる形になる。ただ、今は追従と待機の2つだけにする。
