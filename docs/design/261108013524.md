# キューブを運転する乗り物から、追従と待機を切り替える随伴者にする

## 背景

キューブは、プレイヤーが乗り込んで運転する乗り物になっている。この形は、遊んでいて自然なプレイ体験にならない。

- **乗っても何も変わらない**。運転は、プレイヤーが1マス歩くのと同じ1手でキューブを追随させるだけで、速さは徒歩と同じ。それなのに1タイルごとに `5 + 積載kg` の燃料を払う。参考 codebase: `internal/activity/player_actions.go:107`、`internal/world/query/cube.go:149`。
- **速さを足すと逃走手段になる**。キューブは通行可能な1マスの地物なので、扉も廊下も通れる。徒歩より速くすると、危険な場所でも戦わずに逃げ切れてしまう。
- **乗っている間の絵が曖昧**。乗車中のプレイヤーは描画から外れ、キューブだけが動く。参考 codebase: `internal/systems/render_sprite.go:202`。

そこで乗るのをやめる。キューブは、プレイヤーの後を自分で追う随伴者にする。追わせると燃料を食うので、節約したいときは「ここで待て」と命じて置いていく。待たせた場所へは、自分の足で戻る。

ついてこさせるか、待たせるかが燃料の判断になる。速さは持たないので、逃走手段にはならない。キューブは語らない。命令に従うだけの物として扱う。

## 要件

1. 乗車と運転をなくす。プレイヤーはキューブに乗らない。
2. キューブは既存の NPC AI `SoloAI` で動く NPC になる。追従と待機の2つの移動方針を持ち、キューブメニューから切り替える。
3. 追従中のキューブは間合いを持ってついてくる。休んでいる間はプレイヤーとの距離が4マスに開くまで動かず、開いたら隣に追いつくまで毎ターン1歩近づいて休みに戻る。1歩ごとに燃料ポイントを払う。1歩の量の式は今の運転と同じにする。
4. 燃料ポイントが足りなければ、キューブはその場で待機に切り替わり、ログで知らせる。
5. 燃料はキューブに事前にくべて、燃料ポイントとして貯めておく。くべたアイテムはその場で消える。収納の中の物は燃料にならない。
6. 待機中のキューブは動かず、燃料も払わない。
7. 展開中のキューブは動かない。方針は展開で変わらず、圧縮するとその方針で動き出す。方針は展開中も切り替えられる。
8. 遠隔の呼び戻しは持たない。待たせたキューブを動かすには、隣まで戻って命じる。
9. キューブは他の NPC と同じく道を塞ぐ。プレイヤーが歩き込むと位置を入れ替える。
10. キューブメニューは、上に立つのでなく隣接して開く。
11. 帯のシフトで南端の行が破棄されるとき、そこに待機中のキューブがあれば失われる。その手前で警告を出す。
12. 燃料ゲージは右上の地図の下に、キューブの名前と並べて出す。キューブが同じステージにいる間は、待機中も含めて常に出す。
13. 新規開始時のキューブは、追従の方針で、燃料ゲージが満タンの状態で始まる。最初から追従させられ、燃料が減っていく様子で仕組みが分かる。

## 設計

### 既存の NPC AI に乗せる

敵と中立 NPC は `SoloAI` を持ち、`aiinput` の `soloPlanner` が行動を決め、`runAPLoop` が AP を消費しながら実行している。参考 codebase: `internal/aiinput/processor.go:42`。キューブもこの仕組みに乗せ、随伴者専用のコンポーネントや planner は作らない。

`soloPlanner.Plan` は、敵対する相手がいなければ状態遷移を通らず、移動方針 `Movement` だけで行動を決める。参考 codebase: `internal/aiinput/planner_solo.go:46`。キューブは陣営を持たないので、敵対する相手は常にいない。よって、移動方針を「待機」と「追従」で切り替えるだけで足りる。

- **待機は既存の `SoloStationary`** をそのまま使う。
- **追従は `SoloFollow` を足す**。

```go
const (
	// SoloFollow はプレイヤーに隣接するまで1歩ずつ近づく。キューブが燃料を払って随伴するのに使う
	SoloFollow SoloMovement = "follow"
)
```

`SoloFollow` は Go の定数だけに足し、raw のスキーマの列挙には足さない。キューブ専用の方針なので、データから敵へ割り当てられないようにする。

乗車を表す `Driving` は削除する。乗れることを表す `Drivable` は、キューブを見分けるマーカーとして残し、名前を `MobileBase` に改める。

```go
// MobileBase は移動拠点キューブであることを示すマーカー。SpawnCube が付与する。
type MobileBase struct{}
```

`SpawnCube` は、既存のマーカー・収納・HP に加えて、次の2つを付ける。

```go
SoloAI: &gc.SoloAI{
	CombatDefault: gc.CombatIgnore,
	CombatCurrent: gc.CombatIgnore,
	Movement:      gc.SoloStationary,
	SubState:      gc.AIStateWaiting,
},
TurnBased: ...,
```

- **初期の方針は追従**にする。開始直後から仕組みが目に見える。ロードではセーブした方針に戻るので、待たせたキューブが勝手に動き出すことはない。
- **AP は能力値なしで基準値にする**。毎ターンの AP 回復は `TurnBased` を持つ全員に `CalculateMaxActionPoints` を呼び、この関数は `Abilities` が無いとエラーを返す。参考 codebase: `internal/world/query/turn.go:73`、`:100`。キューブに `Abilities` を足すと、積載上限の 500kg が筋力の式で上書きされる。参考 codebase: `internal/world/query/weight.go:28`。速度の `CalculateSpeed` は `Abilities` が無ければ基準値で計算している。参考 codebase: `internal/world/query/turn.go:120`。AP もこれに揃え、`Abilities` が無ければ基準の 100 を返す。副次的に、キューブにも既存の過積載の減速が効き、重いと遅れる。エラーを返す経路が無くなるので、`CalculateMaxActionPoints` は `int` だけを返し、エラーを返す理由が無くなる `RestoreAllActionPoints` も戻り値を持たない。
- **戦闘方針は無視 `CombatIgnore`** にする。敵対する相手がいないので、実際には戦闘の状態遷移に入らない。
- `SoloAI` は既存の保存の仕組みで保存されるので、移動方針はロード後も保たれる。

### 追従の行動

`planDrivingAction` の移動方針の分岐に `SoloFollow` を足す。参考 codebase: `internal/aiinput/planner_solo.go:225`。

```go
// planFollowAction はプレイヤーに隣接していなければ1歩近づく。燃料が1歩分に足りなければ
// 待機へ切り替えてログを出し、その場で待つ
func (rp *soloPlanner) planFollowAction(world w.World, aiEntity ecs.Entity, solo *gc.SoloAI, grid *gc.GridElement) *gc.Activity
```

- **休む・追いつくの2状態で動く**。隣接するまで毎ターン寄ると、1マスに張り付いて機械的に見える。休んでいる間は距離が `followStartDistance = 4` に開くまで待ち、開いたら隣まで追いついて休みに戻る。追いかけ始める距離と止まる距離を分けるので、境目で動いたり止まったりを繰り返さない。状態は `SoloAI.SubState` の待機と移動で持つ。キューブは敵対する相手を持たず戦闘の状態遷移に入らないので、この欄は空いている。
- 1歩の選び方は、既存の BFS の経路探索 `FindNextStep` を使う。参考 codebase: `internal/activity/pathfind.go:42`。実装とテストはあるが、本番コードからはまだ呼ばれていない。群れる敵のような目標との差による貪欲な選び方だと、建物の壁の裏で詰まる。
- 燃料ポイントは planner で差し引く。`FindNextStep` は通行できるマスだけを返すので、払った歩みが失敗することはほぼない。planner が `SoloAI` の状態を書き換える前例は、巡回の向きの反転にある。参考 codebase: `internal/aiinput/planner_solo.go:331`。
- 払う前に1歩分の AP があるかを確かめ、足りなければ nil を返してそのターンの行動を終える。`runAPLoop` は計画を受け取ってから AP を確かめ、足りなければ計画を捨てるので、確かめずに払うと燃料だけ減る。参考 codebase: `internal/aiinput/planner.go:45`。
- 燃料ポイントが足りなければ `solo.Movement` を `SoloStationary` へ戻す。
- プレイヤーが1ターンに複数回行動できるときは、キューブが遅れる。重い荷を抱えた随伴者が遅れるのは自然なので、追いつかせる特例は作らない。
- **追従中は距離カリングから外す**。遠くの非交戦 AI は処理を飛ばされる。参考 codebase: `internal/aiinput/processor.go:68`。キューブが遅れて圏外へ出ると、そのまま凍結してしまうため、交戦中と同じく残す。

### キューブはキャラクターとして道を塞ぐ

`SoloAI` を持つものは、空間インデックスでキャラクターとして登録される。参考 codebase: `internal/world/query/singleton.go:244`。キャラクターのいるマスには移動できない。参考 codebase: `internal/activity/move.go:38`。そのため、キューブは今の「上に立てる地物」でなくなり、他の NPC と同じく道を塞ぐ。

**歩き込んだら位置を入れ替える**。狭い廊下で後ろについてきたキューブへ引き返すと、ぶつかって進めなくなる。そこで、歩き込みで発動する相互作用 `InteractionSwap` を足し、キューブに持たせる。

```go
// InteractionSwap は歩き込むと相手と位置を入れ替える相互作用。随伴者が道を塞がないようにする
InteractionSwap InteractionKind = "SWAP"
```

| 種類 | 発動範囲 | 発動方法 |
|---|---|---|
| `InteractionSwap` | 隣接 | 歩き込み |
| `InteractionOpenCubeMenu` | 同じマスから隣接へ変える | 手動のまま |

- 入れ替えは、扉・会話・攻撃と同じ「歩き込みで発動する相互作用」の枠に乗せる。参考 codebase: `internal/activity/player_actions.go:38`。暗黙の規則にせず、キューブが持つ相互作用として明示する。
- 入れ替えはプレイヤーの移動として扱い、AP は移動と同じだけ払う。キューブは燃料を払わない。待機中のキューブも、入れ替えでは1マスずれる。
- 展開中のキューブとは入れ替えない。野営の中心に据え付けてあるので、動かすと野営と位置がずれる。入れ替えの検証が `UserError` を返し、理由をログに出してターンを消費しない。
- キューブメニューは、収納や着火と同じく隣接で手動発動する。参考 codebase: `internal/components/interactable.go:61`。隣接の相互作用メニューは、発動範囲の設定から一覧を自動で作るので、設定を変えるだけで出る。参考 codebase: `internal/states/action_handlers.go:50`。足元にキューブがあると出していたログは消す。
- `InteractionSwap` は、攻撃と同じくアクションメニューに出さない種類として並べる。参考 codebase: `internal/states/action_handlers.go:308`。

### 命令はキューブメニューから

キューブメニューの「運転」を、移動方針の切り替え項目に置き換える。参考 codebase: `internal/states/cube_menu.go:77`。

| 状態 | 項目 | 結果 |
|---|---|---|
| 待機中 | ついてこい | `Movement` を `SoloFollow` へ |
| 追従中 | ここで待て | `Movement` を `SoloStationary` へ |

展開は方針を書き換えない。展開中のキューブは `planFollowAction` が休ませるので、追従の方針のままでも動かない。圧縮すると、展開前の方針でそのまま動き出す。

### 燃料は事前にくべて燃料ポイントで持つ

今の燃料は、キューブ収納にある可燃物の熱量の合計で、運転のたびにアイテムを消費している。参考 codebase: `internal/world/query/cube.go:156`。その消費はアイテム単位で、端数を繰り越さない。参考 codebase: `internal/world/lifecycle/cube.go:12`。1歩の燃料が 9 でも、石炭1個の 800 をまるごと消すので、燃料の種類に関係なく1マス1個を失っている。燃料がすぐ尽きる主な原因になっていた。

焚き火は、くべたアイテムを燃焼の残りターン `Burning.Remaining` へ即座に変換し、アイテムを消している。参考 codebase: `internal/world/lifecycle/fire.go:14`。キューブも同じ形にする。くべた時点で熱量を燃料ポイントへ変換し、歩くたびにポイントを減らす。

```go
// FuelTank はキューブに貯めた燃料ポイント。くべたアイテムの燃焼熱量がここへ畳み込まれ、随伴の1歩ごとに減る。保存する
type FuelTank struct {
	Heat consts.Heat
}
```

```go
// AddCubeFuel は fuel の燃焼熱量をキューブの燃料ポイントへ足し、fuel を消す。焚き火の AddFuel と対になる
func AddCubeFuel(world w.World, cube ecs.Entity, fuel ecs.Entity)

// ConsumeCubeFuel は燃料ポイントを amount 減らす。足りなければ減らさず false を返す
func ConsumeCubeFuel(world w.World, cube ecs.Entity, amount consts.Heat) bool
```

- **上限は持たない**。ゲージは今と同じく、表示上の基準 `FuelGaugeFullHeat = 3000` に対する比を 0..1 に丸めて描く。参考 codebase: `internal/world/query/cube.go:166`。くべすぎて捨てる、という罠を作らない。
- **収納の中の物は燃料にならない**。燃料と積み荷が分かれ、収納には燃料以外も自由に入れられる。
- **給油メニューは焚き火のものを共有する**。焚き火の給油メニュー `FeedFuelMenuState` は、持ち物の可燃物を一覧して、選ぶとくべる。参考 codebase: `internal/states/feed_fuel_menu.go`。焚き火に依存するのは、見出し・各行の増える量・くべる処理の3点だけになっている。この3点を呼ぶ側から注入する形にし、焚き火とキューブの両方で使う。今のキューブの「燃料」メニューは、収納画面を燃料で絞り込んだもので、これを置き換える。参考 codebase: `internal/states/cube_menu.go:39`。収納画面の絞り込み・追加列・タブ指定・見出しのオプションは、この燃料メニューだけが使っていたので、置き換えで使われなくなり削除する。

```go
// fuelSink は給油メニューのくべ先。見出し、各行で増える量の表示、くべる処理を呼ぶ側が決める
type fuelSink struct {
	title func(world w.World) string
	gain  func(world w.World, fuel ecs.Entity) string
	feed  func(world w.World, fuel ecs.Entity)
}
```

**新規開始時は満タンで始める**。`SpawnCube` で `FuelTank{Heat: consts.FuelGaugeFullHeat}` を付ける。アイテムを入れる必要はない。空のキューブなら1歩5で、約600歩ついてこられる。

### 帯のシフトで失われる

帯は 24×24 タイルのチャンクが7列×9行で、プレイヤーは中央の行にいる。参考 codebase: `internal/dungeon/registry.go:66`。シフトのたびに、南端の行はプレイヤー以外まとめて破棄される。参考 codebase: `internal/worldstream/band.go:76`。待たせたキューブは、プレイヤーが北へ約4チャンク、すなわち約100タイル離れると消える。

- **消えることを仕様にする**。北へ前進するだけの世界で、置いてきた物は戻らない。破棄から外して残しても、帯の外へ出るので二度と届かない。
- **警告を出す**。キューブが南端の行に入ったシフトで、「キューブが遠すぎる。次に北へ進むと置き去りになる」とログを出す。南端の行かどうかは帯の `InSouthRow` が答え、`ShiftNorth` が破棄する範囲と同じ式を使う。
- **積み荷も一緒に失われる**。帯の破棄は、消える実体が所有する収納・畳んだ積み荷・装着モジュールを `RemoveOwnedEntities` で既に道連れにしている。参考 codebase: `internal/worldstream/worldstream.go:50`、`internal/world/lifecycle/location.go:286`。新しい処理は要らない。

### 表示

- キューブは宙に浮いて上下に揺れる。元の絵を上へ1〜3ピクセルずらし、足元に半透明の影を描いた4コマ `cube_float_0..3` を `AnimKeys` に並べる。高く上がるほど影を細くする。描画のコードは変えず、golden ではアニメーションを止めて1コマ目で撮る。
- 燃料ゲージは、左上のプレイヤーのゲージ列から外し、右上の地図の下へ移す。地図と同じ幅で、名前の下に置く。仲間の状態を地図の下にまとめ、左上はプレイヤー自身の体の状態に絞る。描画データは `MacroMapData.Cube` に持ち、現ステージのキューブを `query.ActiveCube` で引く。
- 乗車中のプレイヤーを描画から外す処理は、乗車がなくなるので消す。参考 codebase: `internal/systems/render_sprite.go:202`、`internal/systems/render3d.go:367`。
- マクロ地図のキューブマーカー `DriveCubeTiles` は `CubeTiles` に改め、`MobileBase` で集める。
- ログの名前は、`SoloAI` を持つので NPC の色で出る。参考 codebase: `internal/world/query/name.go:34`。

### バランスの物流指標

バランスの物流指標は、収納を OIL で満たしたときの航続で、燃料自身の重さで頭打ちになる前提だった。燃料はくべるとポイントになり重さを持たないので、この指標は成り立たない。指標を「満タンの燃料ポイントで積荷0のキューブが随伴できる歩数」`FollowRangeFullTank` に置き換える。現状値は 600 歩で、目標帯は暫定で 400〜800 歩にする。

## 採用しなかった方法

- **運転を残し、乗り物らしさを足す**: 慣性、道でだけ速い、建物に入れない、などを足す案。作る量が大きく、速さを持つと逃走手段になる。
- **視界に敵がいないときだけ速く運転する**: 移動用の速さが戦闘へ漏れない。ただ、乗るという体験の不自然さはそのまま残る。
- **ソリのように縄で牽く**: 身体の比喩は自然。ただ、牽いている間はプレイヤーが常に重くなり、戦う前に縄を外す操作が毎回挟まる。随伴者なら、待たせるかどうかを一度決めるだけで済む。
- **随伴者専用の `Follower` コンポーネントと planner を作る**: キューブを上に立てる地物のまま保てるので、通路も塞がず変更も小さい。ただ、既存の NPC と別扱いの「上に立てる NPC」という独自の存在が残る。既存の `SoloAI` に乗せれば、新しい概念を増やさず、NPC として素直に振る舞う。
- **歩き込んだ非敵対キャラクターとは暗黙に入れ替える**: 規則として一般的だが、どの NPC に効くかがコードの分岐に埋もれる。相互作用として明示し、持たせた NPC にだけ効かせる。
- **収納の燃料をその場で必要量だけ燃やし、端数を繰り越す**: 収納に燃料と積み荷が混ざったままで、どれが燃えるかが分かりにくい。事前にくべて燃料ポイントで持つほうが、焚き火と同じ形で単純になる。
- **燃料ポイントに上限を設ける**: 満タンが実際の値になるが、上限を超える分の扱い、すなわち拒否するか捨てるかを決める必要が出る。ゲージを基準値で丸めれば、上限なしでも表示は成り立つ。
- **追従の1歩を目標との差で貪欲に選ぶ**: 群れる敵と同じ部品で済むが、壁の裏で詰まる。既存の `FindNextStep` で迂回できる。
- **キューブに `Abilities` を持たせて AP を計算する**: 積載上限が筋力の式で上書きされる。
- **遠隔で呼び戻す**: 便利だが、待たせた場所との距離が意味を失う。長い距離を自動で戻る経路探索も要る。
- **待機中のキューブを帯の破棄から外す**: 帯の外へ平行移動されて、二度と届かない場所に残るだけになる。
- **キューブが語る**: 語り口は持たない。命令に従う物として扱い、物語はキューブに背負わせない。

## コメント

- 燃料の式は改名するだけで値は変えない。乗車から随伴に変わると燃料の使い方の感覚が変わるので、実際に遊んでから詰める。
- 敵はキューブを狙わない。敵は最寄りの敵対陣営を狙い、キューブは陣営を持たないため。キューブを連れて危険な場所へ入る代償を作るなら、別の判断にする。
- 群れる移動方針の敵は、最寄りの `SoloAI` へ寄っていくので、キューブの周りにも集まる。参考 codebase: `internal/aiinput/planner_solo.go:302`。実害は小さいので許容する。
- キューブが被弾すると `ReactToHostile` で戦闘方針が攻撃へ変わる。参考 codebase: `internal/world/gameaction/damage.go:69`。敵対する相手がいないので行動は変わらない。
- キューブは今後、戦闘や採取など他の命令を持てる形になる。ただ、今は追従と待機の2つだけにする。
