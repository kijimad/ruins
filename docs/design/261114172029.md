# 地面の雪を気温と同じ式から導き、寒さを画面に出す

## 背景

北へ進むほど寒くなり、冬の底は -30℃ になるのに、オーバーワールドの地面は砂漠に見える。地面の基調が橙の `dirt` で、ムラも砂の橙・赤・桃で出しているためである。参考 codebase: `internal/overworld/scatter.go:82`。

地面の見た目と気温は別々に決まっていて、つながりが無い。寒い場所でも暖かい場所でも同じ絵になり、寒さが画面から伝わらない。

素材は足りている。DawnLike の `Floor.png` にある autotile の28組は、すべてタイルとして切り出し済みである。雪原に近い淡い白の `smooth_white`・`smooth_cream`、霜や氷に近い `smooth_bluegray`・`smooth_teal` がある。

気温は次の項の和で、判定に使う1つの式にまとまっている。参考 codebase: `internal/world/query/temperature.go:58`。

| 項 | 変わる単位 |
|---|---|
| ステージの基本気温 | ステージ |
| 季節 | 日。32日で1周 |
| 緯度 | 北へ1チャンクごとに -1℃、最大 -40℃ |
| 時間帯 | 1日に数回 |
| 天候 | 数時間 |
| 屋内外・タイルの補正 | 場所 |
| 熱源 | 焚き火の近く |

## 要件

1. 地面の雪は、判定に使う気温と同じ式から導く。寒い場所は白く、白い場所は寒い、が仕組みで保証される。
2. 雪は積もって残る。1日の中で時間帯や天候によって地面がちらつかない。
3. 屋内の床・道・壁は雪にしない。雪にするのは屋外の土の地面だけにする。
4. 地図は位置から導く方針を保ち、地面のエンティティを書き換えず、保存も要らない。
5. 雪になる気温の閾値は1か所に置く。

## 設計

### 気温の式を、その日の平均とその瞬間の揺れに分ける

```go
// ClimateTemperatureAt は屋外のその日の平均気温。ステージの基本気温+季節-緯度。
// 時間帯・天候・屋内外・熱源を含まないので、1日の中では変わらない。地面の雪はこの値から導く
func ClimateTemperatureAt(world w.World, y consts.Tile) int

// AmbientTemperatureAt はその瞬間の気温。ClimateTemperatureAt に時間帯と天候を足した世界温度を
// 屋内外で緩め、タイルの補正と熱源を足す。判定は今までどおりこちらを使う
func AmbientTemperatureAt(world w.World, x, y consts.Tile) (int, error)
```

- 季節と緯度は `AmbientTemperatureAt` の中で直接足していたのを、`ClimateTemperatureAt` を通して足す形に改める。判定の値は変わらない。
- 時間帯と天候を外すのは、夜だけ積もって朝に消える、といった1日の中のちらつきを避けるためである。

### 地面の覆い

```go
// GroundCover は屋外の土の地面を覆うもの
type GroundCover string

const (
	GroundCoverNone GroundCover = "none"
	GroundCoverSnow GroundCover = "snow"
)

// snowCoverTemperature はその日の平均気温がこれ以下なら地面が雪に覆われる℃
const snowCoverTemperature = 0

// GroundCoverAt はタイルの地面の覆いを ClimateTemperatureAt から導く
func GroundCoverAt(world w.World, y consts.Tile) GroundCover
```

- 霜のように 0〜5℃ の間を挟むかは、雪だけで試してから決める。

### 雪になるタイルを raw で示す

```cue
#Tile: {
	// ...
	// 雪に覆われたときに描くタイル。省くと雪にならない。屋外の土の地面だけに付ける
	snowCover?: #EntityID
}
```

```toml
[[tiles]]
  id = "snow"
  name = "Snow"
  # smooth_white の autotile を描く

[[tiles]]
  id = "dirt"
  snowCover = "snow"
```

- `dirt` と砂の `sand_orange`・`sand_red`・`sand_pink` に `snowCover = "snow"` を付ける。床・道・壁・草には付けない。
- どのタイルが雪になるかをデータで決めるので、地面の種類を足しても描く処理は変わらない。

### 描く瞬間に絵を差し替える

`Render3DSystem.collectTiles` が地面のタイルを描くとき、タイルが `snowCover` を持ち、`GroundCoverAt` が雪なら、雪のタイルの絵で描く。参考 codebase: `internal/systems/render3d.go:316`。

- autotile の添字はそのまま使う。土の地面どうしで計算した添字を雪の絵にも当てるので、土が続く範囲は雪も途切れずつながる。
- エンティティの `SpriteRender` は書き換えない。季節が進めば、次に描いた時点で地面が変わる。
- 気温は y ごとに1回求めれば足りる。緯度はチャンク単位で、季節は1日で変わらないため。

## 採用しなかった方法

- **地面を一面の雪の組に替える**: 変更は小さいが、気温とつながらない。北へ進む変化も季節の移ろいも見えない。
- **時間帯と天候も含めた瞬間の気温で雪を決める**: 夜だけ積もって朝に消える、と1日の中で地面がちらつく。雪は積もって残るものなので不自然。
- **熱源で雪を溶かす**: 焚き火の周りだけ土が見える演出は面白いが、まず基本の形を入れてから考える。
- **季節が変わったとき地面のエンティティを書き換える**: 地図を位置から導く方針を崩し、書き換えの時機と保存が要る。描く瞬間に差し替えれば状態を持たずに済む。
- **雪の模様の絵を新しく描く**: 見た目は最もよいが絵の作業が要る。まず既存の `smooth_white` で試し、無地が単調に見えるかを画像で確かめてから要否を決める。
- **雪かどうかを描く処理に直接書く**: 地面の種類が増えるたびに描く処理を直すことになる。raw の `snowCover` で示せばデータで足せる。

## コメント

- 緯度はチャンク単位なので、雪の境目はチャンクの行で横一直線になる。季節が進むと境目が南北に動く。
- 調べる画面のタイルの名前や、マクロ地図の色も雪に合わせるかは、地面の差し替えを入れてから決める。
- 雪の閾値と季節・緯度の値は仮。実プレイで振る。
