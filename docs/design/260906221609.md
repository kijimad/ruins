# 身体機能の依存階層を浅くし代謝を身体機能へ揃える

## 背景

身体機能の依存階層が深く、追いにくい。全身性の要因が意識を下げ、その意識を局所機能へ
もう一度掛ける再乗算があり、全身性が2段で効く。以前 `WithConsciousnessPenalty` を
「ややこしい」と却下したのと同じ「作って掛け直す」形が残っていた。

回復も奇妙だった。`Metabolism` が意識を読むため、痛みや注意散漫まで回復を鈍らせていた。
だが組織の修復速度が覚醒度で決まるのは生理的におかしい。痛くても傷は治る。これは回復を
意識 funnel に載せた過去の判断の行き過ぎで、真実を1つに保つ derive-on-read の要請と、
同じ中間ノードを通すという設計判断を混同していた。

さらに、代謝を素朴に `BodyFuncs` へ足すと型が歪む。ほかの身体機能は 100 から減るだけの
機能残量で上限 100 だが、代謝は VIT や睡眠で 100 を超え、土台が VIT という保存された基礎
能力値になる。減るだけの capacity の仲間に増えもする rate を混ぜることになる。分解すると、
代謝は積み上がる熟練軸 VIT・睡眠 と削れる身体機能軸 空腹・疲労 が加算で潰し込まれていた。

## 要件

- 全身性が意識へ効いたあと局所へ再乗算する段を廃し、依存階層を1段浅くする。局所機能は残す。
- 回復を意識から切り離す。代謝は空腹・疲労という生理的要因から導き、痛み・意識を経由しない。
- 代謝を `BodyFuncs` の一員にする。ただし削れる capacity 部分だけを入れ、VIT・睡眠は熟練軸へ移す。
- 命中・速度・回復を同一の `熟練 × 身体機能` パターンに揃える。挙動は据え置きを狙い差分は golden 再生成。
- 真実は量・不調のまま。行動と回復は経路が別でも同じ保存データから導き一貫させる。

## 設計

### 依存階層を浅くする。局所機能は意識からの減算にする

意識を出したあと局所へ再乗算するのをやめ、各局所機能を「意識 − 局所低下」の1段の減算にする。
機能は複数のまま残り、UI の操作・歩行・視覚も、腕の負傷=近接命中低下・脚の負傷=速度低下の
区別も温存する。消えるのは再乗算の1段だけ。

```go
func (hs *HealthStatus) bodyFuncs(extraSystemic int) BodyFuncs {
	// 全身性を1回だけ引いて意識を出す
	consciousness := clamp(100-systemic-extraSystemic-pain/painConsciousnessDivisor, 0, 100)
	// 各機能 = 意識 − その部位の局所低下。乗算せず1段の減算で積む
	limb := func(localDrop int) consts.Percent {
		return consts.Percent(clamp(consciousness-localDrop, 0, 100))
	}
	return BodyFuncs{
		Pain:          consts.Percent(pain),
		Blood:         consts.Percent(clamp(100-bloodDrop, 0, 100)),
		Consciousness: consts.Percent(consciousness),
		Manipulation:  limb(manip),
		Moving:        limb(moving),
		Sight:         limb(sight),
		Metabolism:    metabolismCapacity(extraSystemic), // 下記
	}
}
```

### 代謝を身体機能へ加える。削れる capacity だけ

`BodyFuncs.Metabolism` は他フィールドと同じ「減るだけの capacity、上限 100」にする。空腹・疲労で
下がる。VIT・睡眠の積み上がるボーナスは入れない。それは熟練軸の仕事。痛み・意識は入れない。

```go
type BodyFuncs struct {
	Pain          consts.Percent // 0 が無痛。意識を下げる要因
	Blood         consts.Percent // 100 が正常。失血で下がり危険域で HP が減る
	Consciousness consts.Percent // 100 が万全。不調・疲労・空腹・痛みで下がる。行動の系統
	Manipulation  consts.Percent // 意識 − 腕の局所低下。近接命中・製作
	Moving        consts.Percent // 意識 − 脚の局所低下。速度
	Sight         consts.Percent // 意識 − 頭の局所低下。遠隔命中
	Metabolism    consts.Percent // 100 が万全。空腹・疲労で下がる。回復の身体機能側
}
```

空腹・疲労は意識と代謝の両系統を下げるが、注意力の低下と栄養・休養の不足という別の理由で
効くので二重ではない。痛みは意識だけ、VIT・睡眠は代謝の熟練側だけ、と非対称なのが2フィールドを
分ける根拠になる。病気・失血は代謝の capacity には含めない。失血は別途 HP を削るので二重になる。

### 命中・速度・回復を同一パターンに揃える

回復も命中・速度と同じ `熟練（加算・100超可）× 身体機能（減算・100以下）` にする。

| 出力 | 熟練（加算） | × | 身体機能（減算） |
|---|---|---|---|
| 近接命中 | 100 + 剣技 + DEX | × | Manipulation |
| 速度 | 100 + AGI + DEX | × | Moving |
| 遠隔命中 | 100 + 射撃 + PER | × | Sight |
| 回復 | 100 + VIT + 睡眠 | × | Metabolism |

```go
// 回復率 = 熟練（VIT・睡眠の加算）× 身体機能（Metabolism capacity）
func Metabolism(world w.World, entity ecs.Entity) consts.Percent {
	prof := int(consts.PercentBase)
	for _, s := range recoveryProficiencySources(world, entity) { // VIT*3, 睡眠
		prof += s.Value
	}
	cap := EffectiveBodyFuncs(world, entity).Metabolism // 空腹・疲労で削れる
	return consts.Percent(max(prof, 0)).Mul(cap)
}
```

### 層の分担

`Metabolism` capacity のうち空腹・疲労は量なので `EffectiveBodyFuncs` が読み取り時に導出して
渡す。既存の意識ペナルティと同じ経路。VIT・睡眠は熟練軸として query が読む。純粋な `bodyFuncs()`
は conditions と extraSystemic から capacity を出すところまでを担う。

```
HealthStatus.bodyFuncs(extraSystemic)  ← 純粋。Pain/Blood/Consciousness/局所/Metabolism capacity
        ↓ 呼ぶ
EffectiveBodyFuncs(world, entity)       ← query。量から extraSystemic を導出して渡す
Metabolism(world, entity)               ← query。熟練（VIT・睡眠）× capacity で回復率
```

`ConsciousnessDrops` を `HealthStatus` に足し、意識の低下要因、怪我・病気・痛み、を内訳へ出せるようにした。
疲労・空腹は量から足す。意識・代謝の行を開くと、なぜ下がったかが 疲労 -25 のように読める。

`EffectiveBodyFuncs` は既に空腹・疲労の意識ペナルティを extraSystemic として渡していたので、代謝 capacity も
同じ extraSystemic から `bodyFuncs()` 内で導出でき、`capacity.go` は変更不要だった。回復の乗算合成は
命中と同じ加法差分の内訳で表せるので `Percent.Mul` も足していない。VRT golden は削除して強制再生成した結果、
Health/Effects の該当 golden は現在の描画とバイト一致で staleness は無かった。

## 採用しなかった方法

- **案A 体調1本に集約**: 局所機能を全廃し全出力=熟練×意識にする。鎖は最短だが `BodyFuncs` が
  意識を包むだけの器になり、身体機能という subsystem が死に機能になる。部位別の効き分けも失う。不採用。
- **代謝を BodyFuncs に入れず standalone のまま**: 型の歪みは避けられるが、回復だけ2軸パターンから
  外れ特別扱いが残る。命中・速度と揃える利点を捨てる。不採用。
- **代謝の capacity に病気・失血を含める**: 重傷で治りが遅い表現は出るが、失血は別途 HP を削るので
  二重。まず空腹・疲労だけの最小構成にし、必要なら後で足す。
- **回復を意識 funnel に載せ続ける**: 一貫性は出るが痛み・注意力まで回復に効く生理的な不自然さが
  残る。真実が1つなら経路は別でよいと判断し分離する。

## コメント

行動と回復は経路が別だが、量・不調という同じ保存データから読み取り時に導出するので一貫する。
削るのは意識の再乗算段1つ。機能も意識も UI も生きたまま鎖が1段浅くなる。代謝は熟練×身体機能の
4つ目の実例として型に収まり、VIT・睡眠は熟練軸へ移って capacity の土台が全フィールド一律 100 に
揃う。加算から乗算への合成変更でバランスは動くので実プレイで調整する。
