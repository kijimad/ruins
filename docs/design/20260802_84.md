# アイテム操作を動詞タブ化しショートカットで直達する

## 背景

現状のアイテム操作は導線が深く、よく使う操作ほど手数がかさむ。

- **アイテムを1つ使うまでに確定 Enter が3回、階層が3層**。`M`→ダンジョンメニュー→「所持」→アイテム選択→アクションウィンドウで動作選択、という流れになる。`internal/states/dungeon_input.go:34` の `M` から `NewDungeonMenuState` を push し、そこから `NewInventoryMenuState`、さらにアイテム選択後に `invSubStateWindow` のアクションウィンドウが必ず挟まる、`internal/states/inventory_menu.go:187`。
- **インベントリ直開きのホットキーが未配線**。`ActionOpenInventory` は `internal/inputmapper/action.go` に定義があり `DoAction` の分岐もあるが、`DungeonState.HandleInput` から生成されないため、必ず `M`→「所持」の中継を踏む。
- **アイテム選択後に必ずアクションウィンドウが挟まる**。消費アイテムでも「使う/捨てる/閉じる」から選び直す、`internal/states/inventory_menu.go:468` の `getActionItems`。
- **動詞ごとに導線とキーがバラバラ**。拾う=`G`、置く=`P`、使う/読むは `M` 経由、装備は別メニュー、と1つのアイテムに対する操作の一覧性が無い。
- **食べる/飲むは「使う」に吸収、投げる・アイテムの調べるは未実装**。`internal/activity/use_item.go` が栄養も回復もまとめて処理し、ログだけ「食べた。」に分かれる。`ThrowActivity` は存在しない。

先行事例の Elona は**動詞先行**、動詞キーを押すとその動詞に使えるアイテムだけの一覧が出る、で手数が短い。本 doc はこれを参考にしつつ、**動詞を上部タブにして戻らず切り替えられる**形へ拡張する。

## 要件

- ダンジョン・各メニューから、**動詞ショートカット1キーで対応タブへ直達**する。
- 上部タブ、調べる/置く/食べる/読む/飲む/使う/投げる、を**戻らずに切り替えられる**。
- 各タブは**その動詞に使えるアイテムだけ**を表示し、Enter で**即実行**する。中間のアクションウィンドウを廃す。
- 既存基盤を再利用する。タブは `hooks.UseTabMenu`、`internal/hooks/tabmenu.go`、と `styled` の行部品、実行は既存の `activity` 機構。車輪の再発明をしない。
- キー衝突を解消する。ダンジョンの移動 `WASD` や既存割当と競合しないこと。

## 設計

### 動詞タブ画面

動詞タブ画面を担う state を1つ足す。`StatusState`、`internal/states/status_state.go`、が5タブの雛形として最も近く、これに倣う。

- 上部に動詞タブ帯を置く。`styled.NewRowContainer` に各動詞を `styled.NewListItemText(label, color, isSelected, res)` で横並びにする。カーソル管理は `hooks.UseTabMenu(store, key, cfg)`。
- 各タブが1動詞に対応し、バックパックのアイテムを**その動詞の `accept` 述語で絞って**表示する。空なら「該当なし」を出す。
- アイテム選択の Enter で**選択アイテムへ動詞を即実行**する。従来の「使う/捨てる/閉じる」を選び直すアクションウィンドウは持たない。
- タブ切替は左右キーと `Tab`/`Shift+Tab`、`internal/states/window.go` の `HandleMenuInput` が既に `ActionMenuTabNext/Prev` を返す。ショートカットキーは画面を開くと同時に対応タブへジャンプし、開いている間も同じキーでタブを移せる。

### 動詞レジストリ —— 表駆動で拡張点を1つに

動詞を表駆動の登録リストにする。散布の feature 一覧やカタログと同じ発想で、動詞の追加を「エントリ1つ足す」ことに還元する。

```go
// itemVerb は動詞タブ1つ分の定義。Accept で対象アイテムを絞り、Exec で選択アイテムへ動詞を適用する。
// Exec は即時 activity か、ターゲット選択の別 state への遷移のどちらかを返す。
type itemVerb struct {
	ID     verbID        // "examine" / "place" / "eat" / "read" / "drink" / "use" / "throw"
	Label  string        // タブ見出し。調べる 等
	Key    verbKey       // 直達ショートカット。下記キーマップ参照
	Accept func(w.World, ecs.Entity) bool
	Exec   func(w.World, ecs.Entity) (es.Transition[w.World], error)
}

// verbs は表示順に並べた動詞タブの一覧。タブ順とショートカットの対応表を兼ねる。
func verbs() []itemVerb { ... }
```

`Accept` は既存のコンポーネント述語を流用する。

| 動詞 | 対象の絞り込み `Accept` | 実行 `Exec` | 実装状況 |
|---|---|---|---|
| 調べる | 全アイテム | 詳細ポップアップ表示 | 新規、軽量。`Description` は既存 |
| 置く | バックパック全アイテム | 既存 `PlaceState` のタイル選択へ | 既存流用、`internal/states/place_state.go` |
| 食べる | 食べ物の消費アイテム | `UseItemActivity` | 分類が要る、下記 |
| 読む | `Book` を持つ | 既存 `ReadActivity` | 既存 |
| 飲む | 飲み物の消費アイテム | `UseItemActivity` | 分類が要る、下記 |
| 使う | 道具の消費アイテム | 既存 `UseItemActivity` | 既存 |
| 投げる | `Throwable` を持つ | `ThrowActivity` + ターゲット選択 | 新規 |

捨てる、`DropActivity`、は動詞タブに出さない。足元へ落とす操作は「置く」がタイル選択で兼ねられるため、タブ数を絞る。装備は関心が別、`EquipMenu`、なのでこの画面には含めない。

### 消費アイテムの分類 —— 食べる/飲む/使う を分ける

現状 `Consumable` + 効果、`ProvidesNutrition`/`ProvidesHealing`/`InflictsDamage`、で、食・飲・使の区別が無い。タブを意味のあるものにするには分類が要る。

```go
// ConsumeKind は消費アイテムをどの動詞で使うかの分類。食べ物・飲み物・道具を明示する。
// 食べ物が回復も持つといった効果の重複でタブがぶれないよう、効果からの推論でなく明示値にする。
type ConsumeKind string

const (
	ConsumeFood  ConsumeKind = "food"  // 食べる
	ConsumeDrink ConsumeKind = "drink" // 飲む
	ConsumeTool  ConsumeKind = "tool"  // 使う
)

// Consumable に分類を1フィールド足す。raw で指定する。
type Consumable struct {
	// 既存フィールド
	Kind ConsumeKind
}
```

- `食べる` = `Consumable.Kind == ConsumeFood`、`飲む` = `ConsumeDrink`、`使う` = `ConsumeTool`。
- 既存の消費 raw に `Kind` を付ける移行が要る。指定漏れは既定を `ConsumeTool`、使う、に倒して安全側に寄せる。
- 効果適用の実体は `UseItemActivity` のままで、動詞は入口の分類だけで分ける。ログ文言も分類で選ぶ。

### 投げる —— 新規

- `Throwable` マーカーを足し、`Accept` で対象を絞る。
- `ThrowActivity` を `internal/activity/throw.go` に足し、`BehaviorName` へ登録する、`internal/components/activity.go` の一覧。
- 対象タイル・方向の選択は `PlaceState` のタイル選択フェーズと同型の UI を使う。命中時に `InflictsDamage` 等の効果を適用する。ポーションが割れて範囲効果、などは後続に回す。

### キー割り当てと衝突の解消

要望のキーは 調べる `X` / 置く `d` / 食べる `e` / 読む `r` / 飲む `q` / 使う `t` / 投げる `T`。物理キー判定なので調査で2つ衝突が判明した。**判断が要る**。

| 動詞 | 要望キー | 状態 | 提案 |
|---|---|---|---|
| 食べる | `e` | 空き | そのまま |
| 読む | `r` | 空き | そのまま |
| 飲む | `q` | 空き | そのまま |
| 使う | `t` | 空き | そのまま |
| 投げる | `T` | `t` と物理同一 | `KeyT` + `KeyShift` で区別。前例は `window.go:28` の `Tab`/`Shift+Tab` |
| 置く | `d` | **移動の東 `D` と衝突** | 既存の `P` を維持、または移動を矢印専用にする別改修 |
| 調べる | `X` | **`ActionOpenFieldInfo` に割当済** | フィールド情報を別キー、例 `l`、へ移し `X` を調べるに充てる |

- `t`/`T` は物理キーが同じなので、`IsKeyJustPressed(KeyT)` と `IsKeyPressed(KeyShift)` の併用で分ける。これはコードベース既存の唯一の流儀、`Tab`/`Shift+Tab`。
- `d` は `WASD` 移動の東と本質的に両立しない。置くは既存の `P` を維持するのを推奨する。要望どおり `d` にするなら移動を矢印専用にする必要があり、範囲が大きいので別 doc にする。
- `X` はフィールド情報に使われている。調べるへ充てるならフィールド情報を別キーへ移す。フィールド情報も「調べる」の一種なので、将来は調べるタブへ統合する余地もある。
- 実装は各 state の `HandleInput` に分岐を足し、`DoAction` で動詞タブ画面を対応タブで push する。`window.go` に共通ヘルパを1つ置き、ダンジョンからも各メニューからも同じキーで開けるようにする。

### 既存メニューとの関係

- この画面は**動詞先行の即操作**に特化する。隊員別にアイテムを閲覧する `InventoryMenu` や `EquipMenu` は関心が別なので当面残す。
- インベントリのアクションウィンドウ、使う/読む/分解/捨てる、は動詞タブ画面が主導線になった後に整理の余地がある。まず併存させ、移行を見てから縮小する。

## 採用しなかった方法

- **置くを `d` に割り当てる** —— ダンジョンの `WASD` 移動、東 = `D`、と衝突する。置くは既存の `P` を維持する。`d` を使うなら移動を矢印専用にする大改修が要り、本 doc の範囲外。
- **効果から食べ物/飲み物を推論する** —— `ProvidesNutrition`→食べ物、`ProvidesHealing`→飲み物、と推論すればデータ変更ゼロだが、食べ物が回復も持つ等の重複でタブがぶれる。明示分類 `ConsumeKind` を採る。
- **`InventoryMenu` を廃してすべてこの画面へ寄せる** —— 隊員別の閲覧と動詞先行の即操作は関心が別。まず併存させ、移行を見てから整理する。
- **アイテム選択後にアクションウィンドウを挟む現行方式を維持** —— 中間1階層が毎回入り、手数短縮の要件に反する。動詞先行で入口の1回に畳む。
- **1つの巨大メニューにタブとして装備・合成・収納も同居させる** —— それぞれ対象選択やモードが異なる。動詞タブは所持アイテムへの動詞に絞り、装備・合成は既存メニューに残す。

## コメント

- Elona の動詞先行を、タブ横断で戻らず切り替えられる形へ拡張する。手数は「動詞キー→アイテム→実行」の実質1階層になる。
- キー衝突、`d` と `X`、は要判断。移動体系に触れない範囲では 置く=`P` 維持・調べる=`X`(フィールド情報を移設) が現実的。
- 投げる・食べる/飲むの分離は新規実装を伴うので、タブ画面と既存動詞の配線を先に通し、段階的に足す。
