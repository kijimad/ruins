# 7日ごとの夜に襲撃が波で来て、錨のキューブを狙う

## 背景

要件は設計ドキュメント 261125003808 で決めた。襲撃は錨やエリアに関わらず挑戦全体の暦で7日ごとに来て、錨のキューブを狙う。強さは場所の北の深さで決める。襲撃はエリアの山場で、遠征の締め切りにもなる。

今の作りでは、敵はキューブを狙わない。

| 要るもの | 今の作り |
|---|---|
| 狙う相手 | `soloPlanner.Plan` は敵対する相手だけを探す。キューブは陣営を持たないので中立になり、選ばれない |
| キューブを殴る | 近接攻撃の判定に陣営の確かめは無い。置物は攻撃で壊れる。キューブは HP 200 を持ち、0で収納の中身を撒いて残骸になる。畳み込んだ貨物と装着したモジュールは撒かれず、持ち主の無い実体として残る |
| 道を探す | 敵は道を探さず、寄る方向の候補を順に試して、塞がれると待つ。道を探す `activity.FindNextStep` はキューブの追従だけが使う |
| 動く範囲 | `cullDistantSolo` は、交戦中でない敵をプレイヤーから42タイルより遠ければ止める |
| 敵を湧かせる | `lifecycle.SpawnEnemy`。種類は raw の敵の表から危険度で引く `raw.SelectEnemyByWeight` |
| 日付と夜 | 1日は1500ターン。夜は1000ターン目から。何日ごとに起きる仕組みは無い |
| 予告 | HUD に日数を出す欄は無い |

## 設計

### 襲撃の夜は経過ターンから導く

襲撃の夜は、7日目、14日目のように、7で割り切れる日の夜の始まりにする。日付 `day` は `GetDayNumber` で1から数えるので、`day % 7 == 0` の日の `(day-1) × 1500 + 1000` ターン目になる。7日目なら 10000 ターン目である。経過ターンから導けるので、次の襲撃の日を状態として持たない。

```go
// internal/world/query/raid.go

// raidEveryDays は襲撃の間隔の日数
const raidEveryDays = 7

// raidWaveTurns は襲撃の夜に波が来る、その日の中のターン。夜の始まりから小休止を挟んで3回来る
var raidWaveTurns = [...]consts.Turn{1000, 1150, 1300}

// RaidWaveAt は経過ターン turn がちょうど襲撃の波の来るターンなら、何番目の波かと true を返す
func RaidWaveAt(turn consts.Turn) (int, bool)

// RaidEndsAt は経過ターン turn がちょうど襲撃の夜が明けるターン、すなわち襲撃の日の翌日の0ターン目かを返す
func RaidEndsAt(turn consts.Turn) bool

// RaidWarnsAt は経過ターン turn がちょうど襲撃の日の夜明け、すなわちその日の0ターン目かを返す
func RaidWarnsAt(turn consts.Turn) bool

// DaysUntilRaid は今日を含めず、次の襲撃の夜まであと何日かを返す。今日が襲撃の日なら0
func DaysUntilRaid(turn consts.Turn) int
```

- ターンの終わりのシステムは、経過ターンを進める `GameTime.Advance` の前に回る。`RaidWaveAt` と `RaidEndsAt` には、その終わろうとしているターンの経過ターンを渡す。`AnchorFuelSystem` の `TotalTurns % n == 0` と同じ形になる
- 寝て時間を進めても、ターンの終わりは1ターンずつ回るので、ちょうどの経過ターンを踏み外さない。デバッグの時間帯の飛ばしは250の倍数へ飛ぶので、1150 と 1300 の波を踏み外しうる。季節の飛ばしは夜明けへ飛ぶので、予告と夜明けも踏み外しうる。どちらもデバッグ用なので扱わない。夜明けを踏み外すと印が外れず、距離で止まらない敵が残る
- `DaysUntilRaid` は、7日目の間ずっと0を返し、HUD は今夜と出す。8日目の夜明けに6へ変わる
- 前の襲撃の終わりは8日目の0ターン目、次の予告は14日目の0ターン目で、7日の周期では同じターンに重ならない

### 襲撃の敵に印を付ける

```go
// internal/components

// Raider は襲撃で湧いた敵に付く印。錨のキューブを狙い、プレイヤーから遠くても動く
type Raider struct{}
```

保存する。夜明けに印は外れ、普段の敵に戻る。

### 湧かせる

`RaidSystem` をターンの終わりに回す。`RaidWarnsAt` が真のターンにログで知らせ、`RaidWaveAt` が真のターンにその波を湧かせる。

- 襲撃は地上が現ステージのときだけ起こす。地上の生成は遺跡の入口を置かず、地下は作らない方針なので、遊びの中で地上の外にいることは無い。デバッグで遺跡にいる夜は起こさない
- 中心は現ステージの展開中のキューブにする。無ければプレイヤーにする。錨の無い夜は野ざらしで受ける
- 1晩の数は `raidBase + raidPerDanger × 危険度` と `raidMaxPerNight` の小さい方。危険度は中心の北の深さから `DangerLevelForDepth` で引く。危険度には上限が無く、北へ120チャンクでは式だけだと86体になるので、数に上限を置く。北の深さは、表 `raid` から強い種類を引く重みにも効くので、数を抑えても深さは強さで表れる。これを波の数で分けて、1つの波で湧かせる。割り切れない分は後の波に回す
- 前の波の敵は消えない。倒さずに放っておくと、次の波と重なって、一度に大勢を相手にすることになる
- 湧かせるマスは、中心からチェビシェフ距離 `raidSpawnMin` から `raidSpawnMax` の輪の上で、プレイヤーの視界の外にあり、下の距離の地図で中心まで道がつながり、`activity.CanMoveTo` で通れて誰もいないマスにする。道がつながるとは、置物と味方を壊したり待ったりして進めば着けることで、壁や地形で囲まれたマスだけを外す。足りなければ輪を外へ広げ、帯の端まで広げても足りなければ、湧かせる数を減らす
- 種類は raw の敵の表 `raid` から `raw.SelectEnemyByWeight` で引く。新しい敵は raw の行で足す
- ログに出す
- プレイヤーが寝ているなど中断できる活動の最中なら、`activity.InterruptActivity` で止める。眠りは近くに敵が見えると覚めるが、波は視界の外に湧くので、敵がキューブまで寄ってからでは迎える支度の時間が無い。波が来た時点で起こす

```go
// internal/systems/raid.go

const (
	raidSpawnMin  = 18
	raidSpawnMax  = 24
	raidBase      = 4
	raidPerDanger = 2
	// raidMaxPerNight は1晩の数の上限。仮の値
	raidMaxPerNight = 24
)
```

`runTurnEndSystems` の並びと `InitializeSystems` の登録の両方に足す。

### 印のある敵の振る舞い

#### 距離の地図

狙う的から各マスへの重み付きの距離の地図を作り、印のある敵はその値が小さくなる隣へ進む。敵ごとに道を探すと、群れの数だけ探索が走り、道が無い場合は帯の全体をたどるので重くなる。

地図を作る関数は、湧かせる `internal/systems` と、敵の手番を決める `internal/aiinput` の両方から使うので、道探しの `activity.FindNextStep` と同じ `internal/activity` に公開の形で置く。

```go
// internal/activity/raid_map.go

// RaidMap は狙う的から帯の各マスへの、重み付きの距離
type RaidMap struct {
	// dist は帯の範囲の各マスの距離。帯の幅 × 高さの長さ。届かないマスは負
	dist []int32
}

// raidObstacleCost は HP を持つ置物と味方の敵のマスを通る重み。仮の値
const raidObstacleCost = 5

// BuildRaidMap は的 targets から重み付きの距離の地図を作る。buf があればその配列を使い回す
func BuildRaidMap(world w.World, targets []consts.Coord[consts.Tile], buf *RaidMap) *RaidMap
```

- 的は、現ステージの展開中のキューブにする。無ければプレイヤーにする
- 通れるマスは重み1、HP を持つ置物と、味方の敵と、中立の生き物のマスは重み `raidObstacleCost` で通れるものとして数える。壁や地形のように HP を持たず通れないマスは数えない
- 斜めは、今の道探しの `canPassDiagonal` と同じ規則にする。縦横の隣の2マスがどちらも塞がっていれば斜めに抜けない。角の判定では、HP を持つ置物も塞ぐマスとして見る。広げるときと、敵が次の1歩を選ぶときの両方で同じ規則を使い、値の小さい隣が角の向こうで動けない、を起こさない
- 重みは小さい整数なので、優先度付きのキューでなく、距離ごとのバケツのキューで広げる。帯の全体まで広げ、距離の上限は置かない
- 使う順番。`RaidSystem` は波を湧かせる前に地図を作り、湧かせるマスを絞る。敵の手番では、現ステージに印のある敵がいるターンだけ、`soloPlanner` がそのターンの初めに1回作り、経過ターンが変わるまで使い回す。襲撃の無い普段のターンは作らない。AP で同じターンに何度も動く敵は、そのターンの初めの地図を下る。味方の敵と中立の生き物は重いマスなので、詰まっても待つだけで済む
- 地図は保存しない。ターンごとに作り直す
- 重さはベンチで測る。重ければ、的からの距離に上限を置くことを考える。上限を置くと、湧かせるマスも上限の内側に限られる

#### 振る舞い

`soloPlanner.Plan` に、印のある敵の枝を足す。

- 敵対する相手が見えている `canSee` なら、今と同じく追って殴る。見えなくなったら、状態にかかわらず、すぐに的へ戻る。`Chasing` が視界の外でも追い続ける今の振る舞いは、印のある敵では使わない
- 見えていなければ、距離の地図で値が一番小さい隣を選ぶ。そこが的なら殴る。HP を持つ置物なら殴る。扉が実例になる。味方の敵か中立の生き物なら待つ。空いたマスなら進む
- 道が帯の中に無く、距離の地図に自分の位置が無ければ待つ
- 逃げる種類の敵は表 `raid` に入れない

`cullDistantSolo` は、印のある敵を距離で止めない。遠征中に拠点へ寄る敵が止まると、襲撃の夜が締め切りにならない。

### 予告

- HUD のゲーム情報に、次の襲撃まであと何日かを出す。今日が襲撃の日なら今夜と出す
- 襲撃の日の夜明け、すなわちその日の0ターン目に、ログで知らせる

### キューブを殴り、壊れても続く

襲撃の敵は、普通の近接攻撃でキューブを殴る。キューブは raw の HP を持ち、0になると今の作りどおり壊れて残骸になる。

- 壊れると、錨が外れて帯がまた流れうる。燃料も失う。的はプレイヤーへ移り、群れは夜明けまでプレイヤーを狙う。遠征に出ていても寄ってくる。守りきれなかった夜は、プレイヤーが生き延びる夜になる。核があれば作り直せ、無ければ核を作る材料を探す。負けはプレイヤーの死だけで、キューブを失っても歩いて生き延びられる
- 壊れたキューブの残骸と、撒かれた暮らしの道具を前に朝を迎える。ボロボロになっても続く立て直しを、遊びの山場の1つにする
- 壊れたとき、収納の中身に加えて、畳み込んだ貨物と装着したモジュールも足元に撒く。今は撒かれず、持ち主の無い実体として見えないまま残る。`DeadCleanupSystem` で、`LocationStowed` と `LocationInstalled` の実体も足元へ出す
- 襲撃で壊れるのは展開中のキューブで、展開したときに畳んだ貨物はもう地面に出ているので、撒かれるのは収納の中身と装着したモジュールになる。畳んだ貨物が撒かれるのは、畳んだまま道の上で殴られて壊れたときである

### 波と小休止

襲撃の夜は、夜の始まりから小休止を挟んで3つの波で来る。小休止は150ターンで、その間に、壊れた所を直す、弾を込める、外へ出て数を減らす、休む、を選ぶ。どれも選ばずに放っておくと、残った敵に次の波が重なる。

### 夜明けに襲撃が終わる

`RaidEndsAt` が真のターンに、現ステージの印のある敵から印を外し、状態を待機に戻して、ログで知らせる。追跡の状態のまま残すと、距離で止まらない敵が残る。敵は消えず、普段の敵としてその土地に残る。

- 終わりが夜明けと決まっているので、あと何ターン持ちこたえればよいかが分かる
- 夜明けまでの間、敵はキューブを殴り続けるので、籠もって待つことは何もしないことでなく、守り切ることになる
- 倒しきれなかった敵は、拠点の周りに残る。乗り切った朝も、残った敵を片付けるか、避けて発つかの判断が要る
- 印が外れた敵は、普段の敵と同じく距離で止まり、キューブを目がけて押し寄せない。次の襲撃の数にも数えない

報酬は決める問いに残し、ここでは足さない。倒した敵は raw の行の落とし物をそのまま落とす。

## 採用しなかった方法

| 案 | 採らなかった理由 |
|---|---|
| 次の襲撃のターンを状態として持つ | 周期が固定なので経過ターンから導ける。状態を持つと保存と食い違う |
| 襲撃を錨のある時だけ起こす | 錨を下ろさない方が得になる |
| キューブに陣営を持たせて敵対させる | 普段の敵まで、近くを通るたびにキューブを狙うようになる。襲撃の敵だけが狙う方が、襲撃の山場がはっきりする |
| 倒されるまで狙い続ける | 終わりが見えず、籠もるとキューブが壊されるまで続く。倒しきれない敵が次の襲撃に持ち越される |
| 夜明けに残りの敵を消す | 吹雪の中へ引き上げさせると、倒さずに夜明けを待てば片付く。残った敵が土地の危険として残る方が、乗り切った朝にも判断が残る |
| キューブが壊れたらゲームオーバーにする | 遠征から戻るのが遅れただけで挑戦が終わり、理不尽に感じやすい。キューブは失っても核で作り直せる、という今の作りとも食い違う |
| 殴る代わりに、収納の中身を壊すか燃料を吸う | 攻撃に例外が要る。キューブが壊れないので、失う山場が無い |
| 夜明けの後も印を付けたままにする | 終わりの見えない襲撃になる。距離で止まらず道を探す敵がたまり続けて重くなる |
| 1晩の数を一度に湧かせる | 夜の中に山と谷が無く、直す、弾を込める、外へ出るの選択が生まれない |
| 普段の敵にも道を探させる | 敵の手番が重くなり、普段の手触りが変わる。印のある敵だけにする |
| 印のある敵ごとに `activity.FindNextStep` で道を探す | 群れの数だけ探索が走り、道が無い場合は帯の全体をたどる。距離の地図を1枚作って全員で下る |
| 道が無ければ、目標の方向の隣の置物を殴る別の枝を持つ | その方向が壁なら何もできず止まる。群れが詰まると後ろの敵も止まる。置物と味方を重いが通れるマスにすれば、壊す相手が道の上から決まる |
| 遺跡の中にいる夜も襲撃を起こす | 地上の生成は遺跡の入口を置かず、地下は作らない方針なので、遊びの中では起きない |

## コメント

- 数と輪の距離の値は仮で、遊んで調整する
- 前に捨てる前提の試作で、機銃3基でもキューブの HP 200 を守り切れなかった。機銃と置き物で塞ぐ仕組みは別の設計で足す。それまでは、プレイヤーが殴り合って守る

- 襲撃の種類は後で足す。顔ぶれで、特定の種族や、速さや硬さや遠くから撃つことに特化した群れにする。狙いで、略奪、キューブ、プレイヤーを分ける。天候も一緒に変え、吹雪で視界を狭め、寒波で外の体温を下げる。予告で、来る相手と狙いと天候を前もって見せ、整え方を毎回変える
- 種類は raw の行で足す。種類ごとに敵の表、狙い、天候、予告の文を持たせる。狙いの違いは、距離の地図を作る的をキューブ、プレイヤー、蓄えた物の置き場のどれにするかで表せる。今は1種類なので、`Raider` は空の印のままにし、種類や狙いの欄は使うときに足す
