# 7日ごとの夜に襲撃が波で来て、錨のキューブを狙う

## 背景

要件は設計ドキュメント 261125003808 で決めた。襲撃は錨やエリアに関わらず挑戦全体の暦で7日ごとに来て、錨のキューブを狙う。強さは場所の北の深さで決める。襲撃はエリアの山場で、遠征の締め切りにもなる。

今の作りでは、敵はキューブを狙わない。

| 要るもの | 今の作り |
|---|---|
| 狙う相手 | `soloPlanner.Plan` は敵対する相手だけを探す。キューブは陣営を持たないので中立になり、選ばれない |
| キューブを殴る | 近接攻撃の判定に陣営の確かめは無い。置物は攻撃で壊れる。キューブは HP 200 を持ち、0で収納の中身を撒いて残骸になる。畳み込んだ貨物と装着したモジュールは撒かれず、持ち主の無い実体として残る |
| 道を探す | 敵は道を探さず、寄る方向の候補を順に試して、塞がれると待つ。道を探す `activity.FindNextStep` はキューブの追従だけが使う |
| 動く範囲 | `cullDistantSolo` は、交戦中でない敵をプレイヤーから42タイルより遠ければ止める |
| 敵を湧かせる | `lifecycle.SpawnEnemy`。種類は raw の敵の表から危険度で引く `raw.SelectEnemyByWeight` |
| 日付と夜 | 1日は1500ターン。夜は1000ターン目から。何日ごとに起きる仕組みは無い |
| 予告 | HUD に日数を出す欄は無い |

## 設計

### 襲撃の夜は経過ターンから導く

襲撃の夜は、7日目、14日目のように、7で割り切れる日の夜の始まりにする。日付 `day` は `GetDayNumber` で1から数えるので、`day % 7 == 0` の日の `(day-1) × 1500 + 1000` ターン目になる。7日目なら 10000 ターン目である。経過ターンから導けるので、次の襲撃の日を状態として持たない。

```go
// internal/world/query/raid.go

// raidEveryDays は襲撃の間隔の日数
const raidEveryDays = 7

// raidWaveTurns は襲撃の夜に波が来る、その日の中のターン。夜の始まりから小休止を挟んで3回来る
var raidWaveTurns = [...]consts.Turn{1000, 1150, 1300}

// RaidWaveAt は経過ターン turn がちょうど襲撃の波の来るターンなら、何番目の波かと true を返す
func RaidWaveAt(turn consts.Turn) (int, bool)

// RaidWarnsAt は経過ターン turn がちょうど襲撃の日の夜明け、すなわちその日の0ターン目かを返す
func RaidWarnsAt(turn consts.Turn) bool

// NextRaidWaveTurn は経過ターン turn から数えて、次の襲撃の最初の波が来る経過ターンを返す
func NextRaidWaveTurn(turn consts.Turn) consts.Turn
```

- ターンの終わりのシステムは、経過ターンを進める `GameTime.Advance` の前に回る。`RaidWaveAt` と `RaidWarnsAt` には、その終わろうとしているターンの経過ターンを渡す。`AnchorFuelSystem` の `TotalTurns % n == 0` と同じ形になる
- 寝て時間を進めても、ターンの終わりは1ターンずつ回るので、ちょうどの経過ターンを踏み外さない。デバッグの時間帯の飛ばしは250の倍数へ飛ぶので、1150 と 1300 の波を踏み外しうる。季節の飛ばしは夜明けへ飛ぶので、予告も踏み外しうる。どちらもデバッグ用なので扱わない
- デバッグの項目 Advance to raid night は、`NextRaidWaveTurn` のターンへ進める。1手動けば、そのターンの終わりで最初の波が湧く

### 襲撃の敵の動き方

湧かせた敵の `SoloAI.Movement` を `raid` にする。動き方の値なので、キューブの `follow` と同じく AI の設定に収まり、`SoloAI` と一緒に保存される。誰が波で湧いたかは湧かせた時にしか分からず、種類や位置から導けないので、値として持つ。

```go
// internal/rawschema/schema.cue

#MovementPatternType: "random" | "patrol" | "wallHug" | "stationary" | "wander" | "territorial" | "swarm" | "follow" | "raid"
```

### 湧かせる

`RaidSystem` をターンの終わりに回す。`RaidWarnsAt` が真のターンにログで知らせ、`RaidWaveAt` が真のターンにその波を湧かせる。

- 波は地上が現ステージのときだけ湧かせる。予告はどのステージにいても出し、地上へ戻った夜に前触れなく波が来ないようにする。地上の生成は遺跡の入口を置かず、地下は作らない方針なので、遊びの中で地上の外にいることは無い。デバッグで遺跡にいる夜は起こさない
- 中心は `query.RaidTargets` の最初の的にする。現ステージのキューブで、展開しているかに関わらない。無ければプレイヤーである。湧かせる側と敵の手番は、同じ `query.RaidTargets` から的を引く。畳んだまま夜を越せばキューブを守らずに済む、という抜け道を作らない。キューブを失った夜は野ざらしで受ける
- 1晩の数は `raidBase + raidPerDanger × 危険度` と `raidMaxPerNight` の小さい方。危険度は中心の北の深さから `DangerLevelForDepth` で引く。危険度には上限が無く、北へ120チャンクでは式だけだと135体になるので、数に上限を置く。北の深さは、表 `raid` から強い種類を引く重みにも効くので、数を抑えても深さは強さで表れる。これを波の数で分けて、1つの波で湧かせる。割り切れない分は後の波に回す
- 前の波の敵は消えない。倒さずに放っておくと、次の波と重なって、一度に大勢を相手にすることになる
- 湧かせるマスは、中心からチェビシェフ距離 `raidSpawnMin` から `raidSpawnMax` の輪の上で、プレイヤーの視界の外にあり、下の距離の地図で中心まで道がつながり、`activity.CanMoveTo` で通れて誰もいないマスにする。道がつながるとは、置物と味方を壊したり待ったりして進めば着けることで、壁や地形で囲まれたマスだけを外す。足りなければ輪を外へ広げ、帯の端まで広げても足りなければ、湧かせる数を減らす
- プレイヤーからもチェビシェフ距離 `raidPlayerMin` 以上離す。キューブから離れた所で夜を過ごすと、輪がプレイヤーのそばを通る。視界の外というだけでは、暗がりや壁の裏でプレイヤーの隣に湧き、群れが寄ってくるのが見えない
- 最初の波の1000ターン目は夕と夜の境で、日照がまだ見える明るさに残る。開けた所では視界の半径40の中が見えていて、輪の多くが視界の中になる。そのときは足りなければ輪を広げる手順で視界の外まで広がって湧き、少し遅れて着く。2つ目と3つ目の波は暗く、この広がりは起きにくい
- 視界はプレイヤーが動いたときだけ作り直すので、立ち止まったまま暗くなると、明るい時の広い視界で判定する。より遠くに湧くだけなので許す
- 種類は raw の敵の表 `raid` から `raw.SelectEnemyByWeight` で引く。新しい敵は raw の行で足す
- ログに出す
- プレイヤーが眠っていれば、`activity.CancelActivity` で起こす。`InterruptActivity` は一時停止で、眠りの印を残したまま止めるので使わない。眠りは近くに敵が見えると覚めるが、波は視界の外に湧くので、敵がキューブまで寄ってからでは迎える支度の時間が無い。眠り以外の作業は止めない。進み具合を失わせないため

```go
// internal/systems/raid.go

const (
	raidSpawnMin  = 18
	raidSpawnMax  = 24
	raidPlayerMin = 18
	raidBase      = 12
	raidPerDanger = 3
	// raidMaxPerNight は1晩の数の上限。仮の値
	raidMaxPerNight = 60
)
```

`runTurnEndSystems` の並びと `InitializeSystems` の登録の両方に足す。

### 襲撃の敵の振る舞い

#### 距離の地図

狙う的から各マスへの重み付きの距離の地図を作り、襲撃の敵はその値が小さくなる隣へ進む。敵ごとに道を探すと、群れの数だけ探索が走り、道が無い場合は帯の全体をたどるので重くなる。

地図は、空間の索引と同じくシングルトンのコンポーネントにする。ステージに1枚で、世界から導き、群れの全員で読む値なので、planner や処理の欄には持たせない。型と、世界を見ない広げる処理と下る隣は `internal/components` に、世界から重みを書き出して作る処理は `internal/world/query` に置く。

```go
// internal/components/raid_map.go

// RaidObstacleCost は HP を持つ置物と、襲撃の敵が待つことになるキャラクターのマスを通る重み。仮の値
const RaidObstacleCost = 5

// RaidMap は狙う的から現ステージの各マスへの、重み付きの距離を保持するシングルトン
type RaidMap struct {
	Width, Height consts.Tile
	Cost          []int32
	Blocked       []bool
	Built         bool
	dist          []int32
}

// internal/world/query/raid_map.go

// GetRaidMap はシングルトンから、RaidTargets の的からの距離の地図を取得する。未構築なら作る
func GetRaidMap(world w.World) *gc.RaidMap

// InvalidateRaidMap は距離の地図を無効化する。次に引いたときに作り直す
func InvalidateRaidMap(world w.World)
```

空間の索引との違いは、作り直す時期にある。空間の索引は当たり判定に使うので、物が動くたびに無効化する。地図は帯の全体へ広げて重いので、敵の手番の初めと波を湧かせる前にだけ無効化し、手番の間は古いまま全員で下る。的も引数でなく `RaidTargets` が決める。狙いの違う襲撃を足すときは、的の組ごとに地図を持つ形に広げる。

- 的は、現ステージのキューブにする。展開しているかに関わらない。無ければプレイヤーにする
- 通れるマスは重み1にする。壊れたキューブの残骸のように、HP も通れなさも持たない物のマスも重み1で、殴らない
- HP を持つ置物と、味方の敵と、中立の生き物のマスは重み `raidObstacleCost` で通れるものとして数える。壁や地形のように HP を持たず通れないマスは数えない
- 敵対する相手、たとえばプレイヤーが道の上に立つマスは、重み1の通れるマスとして数える。次の1歩がそのマスなら殴る。隣にいればたいてい見えているので、見えている時の振る舞いと同じになる
- 斜めは、今の道探しの `canPassDiagonal` と同じ規則にする。縦横の隣の2マスがどちらも塞がっていれば斜めに抜けない。角の判定では、HP を持つ置物も塞ぐマスとして見る。広げるときと、敵が次の1歩を選ぶときの両方で同じ規則を使い、値の小さい隣が角の向こうで動けない、を起こさない
- 重みは小さい整数なので、優先度付きのキューでなく、距離ごとのバケツのキューで広げる。帯の全体まで広げ、距離の上限は置かない
- 使う順番。`RaidSystem` は波を湧かせる前に無効化して引き、湧かせるマスを絞る。敵の手番では、敵の手番をまとめて回す `aiinput` の処理の初めに無効化し、最初に引いた襲撃の敵が作る。襲撃の敵がいない手番は誰も引かないので作らない。毎回作り直すので、読み込みの後、キューブが壊れて的が変わった後、帯が流れた後も古い地図を下らない。配列はシングルトンが持って使い回す。AP で同じターンに何度も動く敵は、そのターンの初めの地図を下る。味方の敵と中立の生き物は重いマスなので、詰まっても待つだけで済む
- 地図は保存しない。読み込んだ後は未構築から始まる
- 大きさは、15×15チャンクの帯で360×360の約13万マス、`int32` で約520KB になる。襲撃の夜の約500ターンは、敵の手番ごとに帯の全体へ広げる。的がプレイヤーのときは、プレイヤーが動くたびに作り直すことになる
- 15×15チャンクの帯の全体を1回広げる時間は、`query.BenchmarkBuildRaidMap` で約2.1ms だった。各マスの重みを作るたびに配列へ一度だけ書き出し、バケツの配列も使い回す。隣を見るたびに空間の索引の map を引く形では約28ms で、確保も5万回を超えた
- 重さはベンチで測る。重ければ、的からの距離に上限を置くことを考える。上限を置くと、湧かせるマスも上限の内側に限られる

#### 振る舞い

`soloPlanner.Plan` に、襲撃の敵の枝を足す。

- 敵対する相手が見えていて、狙う的より近ければ、今と同じく追って殴る。的までの距離は、次の1歩のマスの距離の値に1を足して測る。自分の立つマスの値は、自分がいることで重く数えられているので使わない。見えなくなるか、的の方が近くなれば、状態にかかわらずすぐ的へ向かう。相手が的の上にいるなら追わない。地図が扉や置物を壊す道でそこへ導くので、追うと閉じた扉の前で止まる。`Chasing` が視界の外でも追い続ける今の振る舞いは、襲撃の敵では使わない
- それ以外は、距離の地図で値が一番小さい隣を全て、向きの順に試す。的か、仲間でないキャラクターなら殴る。中立の生き物も殴ってどかし、眠った獣が細い通路で群れを夜通し止めないようにする。HP を持つ置物なら殴る。扉が実例になる。空いたマスなら進む。仲間の敵に塞がれた隣は飛ばし、試す隣が残らなければ待つ。地図は敵の手番の初めに1回だけ作るので、先に動いた仲間の入ったマスは、後の敵から見るとまだ空いた値のままになる。次の候補へ移るので、開けた所では一番小さい隣が斜めを含めて並び、群れが横へ広がって前へ出る。細い通路では一番小さい隣が1つだけなので、塞がれていれば待つ。横へずれるだけのマスや真後ろのような遠ざかるマスへは動かず、行き来しない。自分のマスは重く数えられているので、自分が立っていなかったときの距離と比べて一番小さい隣を選ぶ。塊の横を回り込む道が本当に近ければ、斜め後ろへ出て回り込む
- 道が帯の中に無く、距離の地図に自分の位置が無ければ待つ
- 逃げる種類の敵は表 `raid` に入れない

`cullDistantSolo` は、襲撃の敵を距離で止めない。遠征中に拠点へ寄る敵が止まると、襲撃の夜が締め切りにならない。

### 予告

- 襲撃の日の夜明けに、どのステージにいても予告を、波が来るたびにも、ゲームログで知らせる。日数は HUD に常には出さない
- 襲撃の日の夜明け、すなわちその日の0ターン目に、ログで知らせる

### キューブを殴り、壊れても続く

襲撃の敵は、普通の近接攻撃でキューブを殴る。キューブは raw の HP を持ち、0になると今の作りどおり壊れて残骸になる。

- キューブは味方の陣営に属する。プレイヤーと同じ判定に乗るので、殴られたときと壊れたときのログが、味方と同じ形で出る。普段の敵も、見えたキューブを敵対の相手として狙う
- キューブの戦闘の方針は `passive` にする。敵がいても追わず逃げず、殴られても反撃せず、移動の方針だけで動く。`ignore` は殴られると `attack` へ移るので、殴られたキューブが敵を追いかけてしまう
- 壊れたときのログは、攻撃のログと同じく味方が関わるときに出す
- HUD の地図の下で、キューブの名前と燃料ゲージの間に HP ゲージを出す。左上のプレイヤーの欄と同じく HP を上に置く

- 壊れると、錨が外れて帯がまた流れうる。燃料も失う。的はプレイヤーへ移り、群れは倒されるまでプレイヤーを狙う。遠征に出ていても寄ってくる。守りきれなかった夜は、プレイヤーが生き延びる夜になる。核があれば作り直せ、無ければ核を作る材料を探す。負けはプレイヤーの死だけで、キューブを失っても歩いて生き延びられる
- 壊れたキューブの残骸と、撒かれた暮らしの道具を前に朝を迎える。ボロボロになっても続く立て直しを、遊びの山場の1つにする
- 壊れたとき、収納の中身に加えて、畳み込んだ貨物と装着したモジュールも足元に撒く。今は撒かれず、持ち主の無い実体として見えないまま残る。`DeadCleanupSystem` で、`LocationStowed` と `LocationInstalled` の実体も足元へ出す
- 展開中のキューブが壊れたときは、展開したときに畳んだ貨物はもう地面に出ているので、撒かれるのは収納の中身と装着したモジュールになる
- 畳んだまま壊れたときは、畳んだアイテムと装着したモジュールを、キューブのあったマスへ撒く。展開と同じ並びへは戻さない。キューブは囲まれて壊れるので、元の並びのマスは敵や壁で塞がれていることがある。畳んだ置き物はキューブと一緒に壊れて消え、置き物の収納の中身だけを撒く。守りを畳んで持ち歩けば、襲撃で失いうる

### 波と小休止

襲撃の夜は、夜の始まりから小休止を挟んで3つの波で来る。小休止は150ターンで、その間に、壊れた所を直す、弾を込める、外へ出て数を減らす、休む、を選ぶ。どれも選ばずに放っておくと、残った敵に次の波が重なる。

### 夜が明けても群れは止まらない

襲撃の時間は、群れが湧く時間帯である。夜が明けると新しい波は来なくなるが、湧いた敵は動き方が `raid` のまま、倒されるまで錨を狙い続ける。夜明けに襲撃を終わらせる処理とログは持たない。

- 夜明けを待って籠もるだけでは片付かない。倒しきれなかった敵は、朝も拠点を殴り続ける。乗り切るとは、群れを倒しきることになる
- 遠征に出ていても、残った群れは距離で止まらず拠点へ向かう。次の襲撃までに片付けておかないと、新しい波に重なる
- 残っている間は、敵の手番ごとに距離の地図を作る

報酬は決める問いに残し、ここでは足さない。倒した敵は raw の行の落とし物をそのまま落とす。

## 採用しなかった方法

| 案 | 採らなかった理由 |
|---|---|
| 次の襲撃のターンを状態として持つ | 周期が固定なので経過ターンから導ける。状態を持つと保存と食い違う |
| 襲撃を錨のある時だけ起こす | 錨を下ろさない方が得になる |
| キューブに陣営を持たせず、ログや狙いの判定でキューブだけを足す | 陣営で決まる判定ごとに特別扱いが増え、読みにくい。普段の敵もキューブを狙うようになるが、失えば戻らないキューブの重みと合う |
| キューブの戦闘の方針を `ignore` のまま陣営を付ける | 殴られると `attack` へ移り、キューブが敵を追いかける |
| 夜明けに残りの敵を消す | 吹雪の中へ引き上げさせると、倒さずに夜明けを待てば片付く。残った敵が土地の危険として残る方が、乗り切った朝にも判断が残る |
| キューブが壊れたらゲームオーバーにする | 遠征から戻るのが遅れただけで挑戦が終わり、理不尽に感じやすい。キューブは失っても核で作り直せる、という今の作りとも食い違う |
| 殴る代わりに、収納の中身を壊すか燃料を吸う | 攻撃に例外が要る。キューブが壊れないので、失う山場が無い |
| 夜明けに襲撃の敵を普段の動き方へ戻す | 夜明けを待って籠もれば群れが散り、倒さずに乗り切れる。襲撃の時間は群れが湧く時間帯で、湧いた群れの脅威まで時間で区切らない |
| 地図を planner の欄に持たせ、処理の作り方の引数で渡す | 地図は敵ごとの持ち物でなく、ステージに1枚の値。運ぶための欄と引数が planner、処理、ターンの処理、襲撃の処理の4か所に要る |
| 襲撃の敵をマーカーのコンポーネントで表す | 動き方の設定が `SoloAI` と別の場所に分かれる。キューブの `follow` と同じく動き方の値にする |
| 1晩の数を一度に湧かせる | 夜の中に山と谷が無く、直す、弾を込める、外へ出るの選択が生まれない |
| 普段の敵にも道を探させる | 敵の手番が重くなり、普段の手触りが変わる。襲撃の敵だけにする |
| 襲撃の敵ごとに `activity.FindNextStep` で道を探す | 群れの数だけ探索が走り、道が無い場合は帯の全体をたどる。距離の地図を1枚作って全員で下る |
| 道が無ければ、目標の方向の隣の置物を殴る別の枝を持つ | その方向が壁なら何もできず止まる。群れが詰まると後ろの敵も止まる。置物と味方を重いが通れるマスにすれば、壊す相手が道の上から決まる |
| 遺跡の中にいる夜も襲撃を起こす | 地上の生成は遺跡の入口を置かず、地下は作らない方針なので、遊びの中では起きない |

## コメント

- 数と輪の距離の値は仮で、遊んで調整する。数は、機銃と置き物で塞ぐ守りがある前提の物量にしてある。守る仕組みがそろうまでは、殴り合いだけでは厳しい
- 前に捨てる前提の試作で、機銃3基でもキューブの HP 200 を守り切れなかった。機銃と置き物で塞ぐ仕組みは別の設計で足す。それまでは、プレイヤーが殴り合って守る
- 襲撃の種類は後で足す。顔ぶれで、特定の種族や、速さや硬さや遠くから撃つことに特化した群れにする。狙いで、略奪、キューブ、プレイヤーを分ける。天候も一緒に変え、吹雪で視界を狭め、寒波で外の体温を下げる。予告で、来る相手と狙いと天候を前もって見せ、整え方を毎回変える
- 種類は raw の行で足す。種類ごとに敵の表、狙い、天候、予告の文を持たせる。狙いの違いは、距離の地図を作る的をキューブ、プレイヤー、蓄えた物の置き場のどれにするかで表せる。今は1種類なので、動き方の `raid` だけで表し、種類や狙いの欄は使うときに足す
- キューブだけを狙い見えた相手を追わない敵のような狙い方の違いは、敵の AI のコンポーネント `SoloAI` の値で持たせる
- 倒しきれない群れが残ると、距離で止まらず地図を下る敵がたまる。次の襲撃の数に重なって重くなるなら、残った群れの数で波を減らすか、地図を作り直す手番を絞る
- 波は、距離の地図でキューブまで道がつながるマスにしか湧かない。HP を持たない地形だけで閉じた場所にキューブがあると、予告のあと何も来ない。プレイヤーが置ける物は向きの無い置き物で、塞ぐ物は HP を持つので、今の地上では起きにくい。HP を持たない塞ぐ物や、地形で閉じた場所が生まれるようになったら、塞がれていても湧かせて殴らせる
- 波はちょうどのターンに地上にいるときだけ湧く。波のターンを地上の外で過ごすと、その波は来ず、1晩の数が減る。遊びの中で地上の外にいることは無いので、今は抜け道にならない。地上の外へ出られるようになったら、地上へ戻った時に来なかった波をまとめて湧かせる
- 襲撃の夜の1ターンの重さを、群れの数30、60で、寝て進める間の1フレームあたりの時間と、的がプレイヤーで毎ターン動く場合を、ベンチで数字にする。重さが気になったら、地図を作り直すのを的や塞がれたマスが変わった手番だけにするか、広げる範囲を的の周りに絞る
