# 脱出の鍵・作る段・アイテムの分解を足し、ゲームループを閉じる

## 背景

ruins には空腹・寒さ・怪我・天候・焚き火・家の探索・北進が一通りそろっているが、遊んでも判断が生まれない。ループの部品が3つ欠けている。

**向かう先が無い。** 負けの条件はゲームオーバーとしてあるが、勝ちの条件が無い。北へ進むほど寒くなり、`latitudeColdForDepth` が1チャンクごとに1℃下げる。危険度も `DangerLevelForDepth` が3チャンクごとに上げる。北へ進む見返りが無いので、進む理由が無い。参考 codebase: `internal/world/query/temperature.go`、`internal/world/query/danger.go:31`。

**作る段が途切れている。** 集められる素材と、レシピが使う素材が `iron` 以外重ならない。

| | 素材 |
|---|---|
| 分解で手に入る素材 | `firewood` `branch` `stone` `sharp_stone` `scrap_iron` `iron` `rusted_chain` `electric_wire` `cord_bundle` |
| レシピが使う素材 | `wooden_stick` `iron` `ferrite_core` `green_herb` `yellow_herb` `ashes` `crystal_powder` |

木の剣と鉄のナイフの材料 `wooden_stick` は、武器のグループ `early_melee_weapon` と `tree_spirit` のドロップからしか出ない。武器を作る材料が武器と同じ場所でしか拾えない。木と岩の分解には伐採と採掘の道具が要り、序盤は持っていない。避難民と医者は武器を持たずに始まる。結果として、序盤の武器が運で決まり、進行が安定しない。

**拾った物を別の物に換えられない。** 分解は設置物を殴って壊す `salvage` だけで、拾ったアイテムを素材に戻す手段が無い。参考 codebase: `internal/activity/salvage.go`。要らない武器や防具を拾っても、使うか捨てるかしかない。ランダムに拾った物が、そのまま進行の運になる。

## 要件

1. 惑星を脱出するための鍵のアイテムを拾い、それを修理して使うとクリアになる。鍵は北のある程度の深さから稀に出る通信施設で拾いやすく、修理の部品は軍基地のような難しい施設で拾う。目的地までの距離は表示しない。
2. 道具を持たずに始めても、茂みと木箱から最初の武器と道具が作れる。作った道具で木と岩が開き、次の素材が取れる。
3. 拾ったアイテムを分解して素材に戻せる。要らない物も、作る段の材料として必要な物に換えられる。

## 設計

### 1. 脱出の鍵とクリア

壊れた脱出の鍵のアイテムを拾い、修理して使うとクリアになる。鍵も修理の部品も、特別な1か所に置くのでなく、施設の戦利品として拾う。

```
北へ進む → 通信施設を見つけ、broken_escape_core を拾う
        → 軍基地などで修理の部品を拾う。通信施設より先に見つかることもある
        → escape_core に修理する → 使う → クリア
```

**通信施設**

- 通信施設 `comms` は、ほかの店や軍基地と同じ普通の施設にする。raw の `facilities` に1行足し、間取りと中身と敵の表は既存の施設の仕組みで作る。目的地として特別扱いしない。
- ある程度の深さから稀に出る。施設の出現に深さの下限を足し、通信施設はその下限を高く、重みを低くする。条件を満たす市街地なら1つの帯に複数出てもよい。
- 深さの下限は、施設が出る場所の危険度で表す。危険度は北へ3チャンク進むごとに1上がる。参考 codebase: `internal/world/query/danger.go:31`。

```tsp
/** 施設が出現する地区と抽選重み。市街地の一辺が minSpan 以上、危険度が minDanger 以上のときだけ抽選対象になる */
model FacilityZone {
  zone: Zone;
  @minValue(1) weight: int32;
  minSpan: int32;
  minDanger?: DangerLevel;
}
```

- 深さの下限は通信施設のためだけでなく、軍基地のような難しい施設にも使う。設計 doc 261108165219 の「日数で危険な施設を増やす案」と同じ軸の仕組みなので、そちらと揃える。

**鍵のアイテム**

- `broken_escape_core` は、通信施設の戦利品の表に高い重みで入れる。必ず出るのでなく、出やすいだけにする。ほかの施設の表には入れない。
- 鍵は1つの帯から複数拾えてよい。修理に使えるのはどれか1つで、余った鍵は使い道が無いだけにする。

**修理の部品とヒント**

- 修理の部品は、軍基地のような難しい施設の戦利品の表に入れる。通信施設の表には入れない。鍵を拾ったあとも、別の難しい施設を探して漁る理由が続く。
- 部品の施設は通信施設より先に見つかることもある。部品だけを先に拾っても、何に使うかが分かるようにする。
- ヒントは説明文で出す。鍵の説明は、直すのに要る部品と、それが見つかりそうな施設の種類を伝える。部品の説明は、脱出の鍵の修理に使えそうだと伝える。新しい UI は作らず、所持品の詳細に出る説明文だけで足りる形にする。

```toml
[[items]]
  id = "broken_escape_core"
  name = "Broken Escape Core"
  description = "A damaged core of an escape device. Military-grade parts might fix it."

[[items]]
  id = "signal_amplifier"
  name = "Signal Amplifier"
  description = "A military signal amplifier. It looks like it could repair an escape device."

[[items]]
  id = "power_cell"
  name = "Power Cell"
  description = "A high-capacity power cell. It could power an escape device."

[[items]]
  id = "escape_core"
  name = "Escape Core"
  [items.escapeDevice]

[[recipes]]
  id = "escape_core"
  name = "Escape Core"
  [[recipes.inputs]]
    amount = 1
    id = "broken_escape_core"
  [[recipes.inputs]]
    amount = 1
    id = "signal_amplifier"
  [[recipes.inputs]]
    amount = 2
    id = "power_cell"
  [[recipes.inputs]]
    amount = 4
    id = "electric_wire"
```

- 修理は既存の合成で表す。壊れた鍵と部品と素材から、直った鍵を作るレシピを1つ足す。合成の UI はそのまま使える。
- `electric_wire` は2の作る段と3の分解で集める共通の素材にする。レジの分解で手に入る。
- 直った鍵には、使うとクリアになる印 `escapeDevice` を付ける。tsp の `Item` に任意の欄として足す。所持品から使うと、ゲームオーバーと同じ形でクリアの画面へ移る。
- 部品と素材の個数、アイテムの名前と説明文は仮。実プレイで振る。

**冬を越す距離**

- 通信施設の深さの下限は、途中で冬を越すことになる深さに振る。季節は32日で1周し、冬の底は -30℃ になる。参考 codebase: `internal/components/game_time.go`。冬の前に駆け抜ける遊びにはせず、物資を蓄え、燃料と防寒を整えて冬を越すことを道中の山場にする。
- 目的地までの残りの距離は HUD に出さない。通信施設がどこに出るかも決まっていないので、どこまで行けば見つかるかが見えないまま、備えて進む。

### 2. 序盤の作る段

道具なしで取れる素材から始め、作った道具で次の素材を開く。

```
茂み → branch ─→ wooden_stick ← branch x2
木箱・冷蔵庫 → scrap_iron
wooden_stick x2 → wooden_sword
scrap_iron x2 + wooden_stick x1 → iron_knife
scrap_iron x2 + wooden_stick x1 → hammer   採掘の等級1。岩が開く
scrap_iron x2 + wooden_stick x1 → cleaver  伐採の等級1。木が開く
```

- 新しいアイテムは作らない。`hammer` と `cleaver` は等級1の道具として既にある。
- 足すレシピは `wooden_stick`、`hammer`、`cleaver` の3つ。`iron_knife` の材料を `iron` と `wooden_stick` から、`scrap_iron` と `wooden_stick` に改める。
- `wooden_stick` は武器のグループ `early_melee_weapon` から外す。棒は材料であって、拾える武器ではなくする。

```toml
[[recipes]]
  id = "wooden_stick"
  name = "Wooden Stick"
  [[recipes.inputs]]
    amount = 2
    id = "branch"
```

素材から完成品までの流れが途切れないことを、テストで固定する。

```go
// TestRecipes_序盤の武器と道具は道具なしで取れる素材から作れる は、wooden_sword・iron_knife・hammer・cleaver の材料を
// レシピで遡ると、道具の要らない分解の産出に行き着くことを確かめる
```

### 3. アイテムの分解

拾ったアイテムを素材に戻す。出る素材と個数は、燃料の熱を `HeatOf` で出しているのと同じく、材質と重さから導く。595 種のアイテムに1件ずつ分解の定義を書かずに済む。

```go
// salvageMaterial は材質ごとに、分解で戻る素材の id と、その素材1個に要るアイテムの重さを持つ。
// ここに載らない材質は分解できない
var salvageMaterial = map[oapi.Material]salvageRule{
	oapi.METAL:   {id: "scrap_iron", per: 1 * consts.MilligramPerKg},
	oapi.WOOD:    {id: "branch", per: 300 * consts.MilligramPerGram},
	oapi.STONE:   {id: "stone", per: 1 * consts.MilligramPerKg},
	oapi.CRYSTAL: {id: "crystal_powder", per: 100 * consts.MilligramPerGram},
	oapi.BONE:    {id: "ancient_bone", per: 200 * consts.MilligramPerGram},
}

type salvageRule struct {
	id  string
	per consts.Milligram
}

// SalvageYield は材質と重さから、分解で出る素材の id と個数を導く純関数。分解できなければ ok は false
func SalvageYield(material oapi.Material, weight consts.Milligram) (id string, count int, ok bool)
```

- 個数は重さを `per` で割って切り捨てる。0個になる軽い物は分解できない。
- 戻し先の素材そのものは分解できない。`scrap_iron` を分解して `scrap_iron` に戻すような空回りを防ぐ。
- 分解は所持品の操作として足す。道具は要らない。重さに応じたターンを使う。
- 金属の 199 種が `scrap_iron` に戻るので、要らない武器や防具が、`iron_knife`・`hammer`・`cleaver` の材料になる。2の作る段とつながり、拾った物が運でなく総量で効くようになる。
- CLOTH と LEATHER は数が多いが、戻し先の素材がまだ無い。戻し先の素材を足すかは、それを使うレシピと一緒に決める。最初は既存の素材がある5つの材質に絞る。

## 採用しなかった方法

- **目的施設を決まった深さに1棟だけ置く**: 目的地が1点に決まると、そこへ向かうだけの遊びになり、ほかの施設と別の仕組みも要る。通信施設を普通の施設として稀に出す形なら、見つかるかどうか自体が探索の判断になり、施設の仕組みもそのまま使える。
- **鍵と部品を同じ施設に置く**: 1か所を漁れば終わる。部品を別の難しい施設に分けると、通信施設を見つけたあとも、危険な施設へ挑む理由が残る。
- **ヒントの専用 UI を作る**: 説明文で施設の種類と使い道を伝えれば足りる。UI は、説明文で伝わらないと分かってから足す。
- **目的の深さの線を越えたらクリア**: 歩くだけで終わり、北へ進む以外の判断が要らない。鍵を拾って修理する形にすると、施設の守りを抜けることと、修理の部品を集めることが最後の山場になる。
- **鍵を拾った時点でクリア**: 作る段と分解がクリアに結びつかない。修理を挟むと、集めた素材がそのまま脱出の手段になる。
- **一定の日数を生き延びたらクリア**: 北へ進む理由にならない。北進の軸と「移動する拠点」につながらない。
- **目的地までの残りの距離を HUD に出す**: 残りが見えると、備えるより数字を削る遊びになる。どこまで行けば終わるかが見えないまま、手持ちで次の冬を越せるかを考えさせる。
- **冬の前に着ける距離にする**: 冬を避けて駆け抜けるだけになる。物資を蓄えて冬を越すことが、ループの中で一番判断の重い場面になる。
- **目的地を置かず、どこまで北へ行けたかを記録する**: 終わりが無いと、判断の基準が生まれない。記録はクリアの後に足せる。
- **新しい石器のアイテムを足す**: `hammer` と `cleaver` が等級1の道具として既にある。アイテムは増やさず、レシピでつなぐ。
- **初期の持ち物に武器を足す**: 職業ごとの差が消え、作る段を踏む理由も無くなる。
- **アイテムごとに分解の産出を raw に書く**: 595 種に1件ずつ書くのは重く、書き漏れで分解できない物が残る。材質と重さから導けば全アイテムに一度で効く。特定のアイテムだけ別の物を出したくなったら、そのとき raw に上書きの欄を足す。
- **分解に道具を要求する**: 序盤に道具が無いので、作る段の材料を取る手段にならない。
- **キューブの部位と変異を先に入れる**: ループが回る前に足すと、また「仕組みはあるが遊びが無い」状態に戻る。部位は、北の障害を越える手段としてループの後に載せる。

## コメント

- ゴールの形は「脱出の鍵を拾い、修理して使うとクリア」で合意済み。通信施設は深さで稀に出る普通の施設で複数出てよい。鍵はそこで拾いやすいだけで複数拾える。修理の部品は軍基地のような難しい施設で拾い、説明文でヒントを出す。
- 主体は人で、キューブは移動する拠点という前提を保つ。
- 通信施設の深さの下限と重みは仮。実プレイで、冬を一度越すことになる深さかを見て振る。
- 軍基地と発電施設は設計 doc 261108165219 の2段目で足す。修理の部品はそれらの戦利品の表に入れるので、そちらの実装を先に進める。
- 合成の UI は動いている。成り立っていないのはバランスと中身で、作れる物が序盤の役に立たず、材料も手に入らない。
