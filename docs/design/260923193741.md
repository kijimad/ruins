# 深度=北進度で難易度を変える。敵・アイテム・施設・天候・温度

## 背景

北進サバイバルは「北へ進むほど厳しい」を核にする。参考 memory: north-progression-cosmetic-direction, overworld-main-no-depth。しかし現状、難易度を決める軸が2系統に分裂している。

- **北進度 `NorthDepthChunks`（空間軸）** は **天候と温度にしか効いていない**。しかも係数は暫定で穏やか。参考 codebase: `internal/world/query/temperature.go:108-141`（`NorthDepthChunks`・`latitudeCold`）、`internal/world/query/weather.go:45-52,117-135`（`placeFactor`・`RollSpellTurns`）。
- **敵・アイテム・施設内の敵** は `DangerLevelAt`（＝経過日数、時間軸）だけで決まる。参考 codebase: `internal/world/query/danger.go:13-23`、`internal/overworld/urban.go:271-272`、`internal/mapplanner/hostile_npc_planner.go`、`internal/mapplanner/item_planner.go`。

つまり「北へ進むほど敵が強く、良い loot が出る」は**未実装**。北進度を難易度の主軸に据え、敵・アイテム・施設へ配線するのが本設計の主眼。天候・温度は既に深度依存なので係数を強める調整に留まる。

データ側は既に難易度帯を持つ。`[[enemyTables]]`（123個）と `[[itemTables]]`（61個）の各 entry が `minDanger/maxDanger` を持ち、`raw.SelectEnemyByWeight` / `raw.SelectItemByWeight` が danger でフィルタする。参考 codebase: `internal/raw/raw.go:822-877`。**深い場所に大きい danger を供給するだけで、強敵・良 loot がデータ駆動で解禁される**。

## 要件

1. 北進度で敵の強さ・種類が上がる。
2. 北進度で loot の価値・種類が上がる。
3. 北進度で施設の出方が変わる。奥ほど危険な施設や強い敵を抱える。
4. 天候・温度の深度勾配を難易度として体感できる強さにする。
5. **再訪一致を壊さない**。オーバーワールド生成は座標の純関数で、同じ座標は同じ結果を返す不変条件を守る。参考 codebase: `internal/overworld/feature.go:26-31`。

## 設計

### 核。深度を危険度へ変える純関数を1つ足す

日数版 `DangerLevelForDay(days)` と対になる**深度版**を `query/danger.go` に置く。これが5系統の共通ノブになる。

```go
// query/danger.go に追加
// dangerChunksPerLevel は危険度が1段上がる北進チャンク数。値は暫定
const dangerChunksPerLevel = 3

// DangerForDepth は北へ chunksNorth チャンク進んだ場所の危険度を返す。空間の難易度勾配。
// 生成の再訪一致のため world を引かない座標の純関数にする。日数版 DangerLevelForDay と対
func DangerForDepth(chunksNorth int) int // 1 + chunksNorth/dangerChunksPerLevel、1始まり
```

生成側は絶対チャンク行 `c.Y` から深度を純粋に引く。深度 = 湧き位置の起点チャンク行 - 絶対チャンク行。`SpawnChunkY` は帯の不変量なので座標のみで決まる。

```go
// components/dungeon.go の SeamlessBand に追加
// DepthOfChunkRow は絶対チャンク行の北進深度を返す。生成側が ChunkGen の c.Y から純粋に引く。
// world を引く NorthDepthChunks の座標版で、再訪一致な生成に使う
func (b *SeamlessBand) DepthOfChunkRow(absChunkRow consts.Chunk) int // int(SpawnChunkY()) - int(absChunkRow)
```

### 時間軸との合成

`DangerLevelAt`（日数）は残すが、役割を分ける。

- **持続する生成**（オーバーワールドのチャンク、敵・loot・施設）は**深度 danger のみ**で決める。日数は可変で再訪一致を壊すため生成には混ぜない。
- **その場限りの湧き**（ダンジョン床の生成、来訪時の敵湧き）は `max(深度 danger, 日数 danger)` で、空間と時間のどちらでも難易度が上がる。

深度を場所の主難易度に、日数を全体の底上げに使う。北進が主軸で、長居も罰する。

### 要件1・2。敵とアイテムに深度 danger を配線

現状オーバーワールドの敵は市街地の `spawnUrbanEnemies` だけが湧かし、平地チャンクは `EnemyTableName=""` で敵0。参考 codebase: `internal/overworld/urban.go:263-298`、`internal/mapplanner/lib.go:376-380`。

- **市街地の敵**: `spawnUrbanEnemies` の `danger := query.DangerLevelAt(world)` を、チャンク座標由来の深度 danger へ置換。`c` を関数まで引き回す。数 `count` も深度でスケール可。
- **平地チャンクの敵・アイテム**: `NewChunkGen` の固定 planner をやめ、`c.Y` から深度→`Danger` を計算して `PlannerTypeOverworldField` に `EnemyTableName/ItemTableName` と `Danger` を与える。これで `HostileNPCPlanner`/`ItemPlanner` が帯でも機能する。参考 codebase: `internal/overworld/chunkgen.go:40-42`、`internal/mapplanner/plan.go:75-76`。
- **屋外/建物 loot**: `scatterOutdoorLoot` へ深度を渡し、深いほど価値ある itemGroup を選ぶ。現状 zone のみ。参考 codebase: `internal/overworld/loot_scatter.go:35-43`。
- **ダンジョン入口の深度継承**: 入口チャンクの深度を進入先ダンジョンの `Danger` に加味。深い北で入った遺跡ほど強い。参考 codebase: `internal/overworld/dungeon_floor.go:75-76`。

データ（`enemyTables`/`itemTables`）は変更不要。敵個体そのものを深度で強化したい場合のみ、`lifecycle.SpawnEnemy` に danger 引数を足してステータス倍率をかける拡張が要る。参考 codebase: `internal/world/lifecycle/spawn.go:153-191`。

### 要件3。施設の出方を深度で変える

チャンク種別・施設種別の抽選 gate に深度を足す。深度も座標の純関数で与える（再訪一致）。

- `chunkTypeAt`（`internal/overworld/schematic.go:146-160`）や `rollFacilityInZone`（`internal/overworld/urban.go:135-174`）に深度項を足し、奥ほど危険な施設や大規模市街を出やすくする。
- 深度は `c.Y` から `DepthOfChunkRow` で引く。`world` を引く `NorthDepthChunks` は使わない。

### 要件4。天候の深度勾配を強める（既存の係数調整）

天候は既に深度依存。`placeFactor = 1 + Severity×northDepth×placeSeverityCoef`（`placeSeverityCoef=0.05`）と `RollSpellTurns` の `stretch = 1 + northDepth×harshSpellStretchPerChunk`（`0.02`）。参考 codebase: `internal/world/query/weather.go:27,45-52,113,117-135`。難易度カーブを立てるなら2定数と `seasonAffinity` を振り直す。コード構造の変更はほぼ不要。

### 要件5。温度の深度勾配を強める（既存の係数調整）

温度も既に深度依存。`latitudeCold = chunksDeep × latitudeColdPerChunk`（`1℃/chunk`、上限 `latitudeColdMax=40`）。参考 codebase: `internal/world/query/temperature.go:100-141`。寒さの北進勾配を強めるなら `latitudeColdPerChunk`/`latitudeColdMax` を上げる。基準気温 `baseTemp` は dungeon 定義由来で帯一定なので触らず、`latitudeCold` 側で深度勾配を持たせる現設計を維持する。

## なぜこの形か

- **深度 danger を単一の純関数に集約**。5系統が同じノブ `DangerForDepth` を共有し、難易度カーブの調整を1箇所に閉じる。バランス導出が world 抜きで深度カーブを引ける。日数版 `DangerLevelForDay` と対称。
- **データを変えずノブで解禁**。`minDanger/maxDanger` の難易度帯は既にデータにある。深い場所に大きい danger を渡すだけで強敵・良 loot が出る。テーブルを深度ごとに二重管理しない。
- **生成は座標の純関数を保つ**。深度も `c.Y` の純関数で与え、再訪一致の不変条件を壊さない。日数など可変値は持続生成に混ぜない。
- **既に深度依存な天候・温度は係数調整だけ**。構造を作り直さず、効き幅を難易度として立てる。

## 採用しなかった代替

- **時間軸 `DangerLevelAt` を敵・アイテムでも使い続ける**。現状のまま。北進しても敵が強くならず「北進サバイバル」の核が立たない。却下。
- **深度でテーブルを別途用意する**（浅い用・深い用の enemyTable を分ける）。データが深度ごとに二重化し、`minDanger/maxDanger` の仕組みと重複する。danger を上げるだけで解禁される既存機構を使う方が単純。却下。
- **敵個体を深度で一律ステータス倍化する**。まず「どの敵種が出るか」を danger 帯で変える方が既存機構に乗る。個体倍率は種の解禁で足りない場合の追加拡張として保留。
- **温度の基準気温 `baseTemp` を深度で下げる**。`baseTemp` は dungeon 定義由来で query から深度を読めない層分離。深度勾配は `latitudeCold` 側に持たせる現設計が整合。却下。
- **日数 danger を廃止して深度一本にする**。長居のリスクが消える。空間を主軸にしつつ時間を底上げに残す `max` 合成の方が、留まる罰と進む罰を両立できる。却下。

## コメント

- **needs-decision は3つ**。`dangerChunksPerLevel`（深度→危険度の傾き）、天候・温度の深度係数、深度と日数の合成方法（`max` か加算か）。いずれもバランス値なので実プレイで測って振る。バランス値一元化の将来方針に沿う。参考 memory: balance-consts-centralize-deferred。
- **段階着手を推奨**。まず核（`DangerForDepth`・`DepthOfChunkRow`）と敵配線（要件1）を1PRで通し、体感を見てからアイテム・施設・係数調整へ広げる。1PRで5系統を同時に動かすと golden とバランスの爆心地が大きい。
- 既存の日数 danger の長期的な扱い（残す/縮小/廃止）は本設計では `max` 合成で残す。確定は着手後の体感で。
