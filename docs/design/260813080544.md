# 食料の腐敗

## 背景

食料を早く取るインセンティブが無く、拾った食料を永遠に溜め込める。時間経過で食料が劣化し、やがて食べる価値を失う仕組みを入れて、次の2つを満たす。

- 早取りのインセンティブ。新鮮なうちに食べるほど得
- 溜め込み防止。放置した食料は栄養を失い、腐敗すると食べると害になる。溜める利点が消える

丸ごとの模倣はせず、ruins の既存基盤に載る最小形にする。

既存の足場:

- `GameTime.TotalTurns` が遺跡内で永続する総ターン数。1500 ターン/日、250 ターン毎に時間帯が変わる。腐敗の時刻基準に使う
- `Hunger` プールに `use_item.go` の `applyNutrition` が `hunger.Increase(栄養)` する。栄養は raw の `providesNutrition`
- 食料は `assets/metadata/entities/raw/raw.toml` に定義。`stackable` な食料が多い
- 状態異常の仕組みは無い。腐敗食の「不調」は当面 Hunger を削る負効果で表現する

## 要件

- 腐敗する食料は3段階で遷移する。新鮮 → 劣化 → 腐敗。腐敗が終端で、それ以上は変化しない
  - 新鮮: 栄養 100%
  - 劣化: 栄養 50%、無害
  - 腐敗: 栄養ほぼ 0、食べると軽い不調。無価値で有害な重りとして残り続ける
- 溜め込み防止はエンティティの撤去では行わない。腐敗食が無価値かつ有害になることで、溜める利点を消す。ゲームは持ち物を勝手に消さない
- 保存食は腐敗しない。食料ごとに保存期間を宣言し、未指定は非腐敗とする
- 気温非依存の固定速度。寒冷・保存容器による減速は将来拡張
- セーブ/ロードで鮮度が保たれる
- 毎ターン全食料を走査しない。鮮度は参照時に遅延評価する

## 設計

### 時刻基準と遅延評価

各食料に生成時刻と保存期間を持たせ、鮮度は「現在の総ターン数 − 生成時刻 = 経過ターン」で都度求める。カウンタを毎ターン減算する走査を持たないため O(食料数)/ターンの負荷が無く、保存も int 2つで済む。

段階の境界は保存期間 `ShelfLife` の倍数で表す。

| 経過ターン | 段階 | 栄養倍率 |
|---|---|---|
| `[0, ShelfLife)` | 新鮮 | 1.0 |
| `[ShelfLife, 2*ShelfLife)` | 劣化 | 0.5 |
| `>= 2*ShelfLife` | 腐敗 | ~0 + 不調 |

腐敗が終端で、以降は状態も見た目も変わらない。倍率と倍数はバランス調整用の定数にする。例えばパンの `ShelfLife = 1500`、すなわち1日なら、1日目は新鮮、2日目は劣化、3日目以降は腐敗のまま残る。

### コンポーネント

```go
// Perishable は腐敗する食料が持つ。生成時刻と保存期間から鮮度を遅延評価する。
// 気温非依存の固定速度で、保存する値は consts.Turn だけなので serde 安全
type Perishable struct {
	SpawnedAtTurn consts.Turn // 生成時の GameTime.TotalTurns
	ShelfLife     consts.Turn // 新鮮でいられるターン数。これを基準に段階が決まる
}
```

```go
// FreshnessStage は鮮度の段階
type FreshnessStage string

const (
	FreshnessFresh  FreshnessStage = "fresh"  // 新鮮
	FreshnessStale  FreshnessStage = "stale"  // 劣化
	FreshnessRotten FreshnessStage = "rotten" // 腐敗
)

// Stage は経過ターンから鮮度段階を返す。now は GameTime.TotalTurns。
// 値レシーバで十分。int 2つしか持たず変更もしない
func (p Perishable) Stage(now consts.Turn) FreshnessStage {
	age := now - p.SpawnedAtTurn
	switch {
	case age < p.ShelfLife:
		return FreshnessFresh
	case age < 2*p.ShelfLife:
		return FreshnessStale
	default:
		return FreshnessRotten
	}
}
```

`consts.Turn` だけを持つため serde 安全。`skipComponents()` に入れず保存対象にする。GameTime と同じく遺跡内で永続する。撤去は行わないため `Expired` 相当の判定は持たない。

`SpawnedAtTurn` は生成時に必ず刻印される前提で、`Stage` はそれを刻印済みの値として扱う。ターン 0 に生成した食料の `SpawnedAtTurn` は 0 で、これは正当な値であり `Stage(0)` は新鮮を返す。0 を未刻印のセンチネルにはしないため `== 0` の特別扱いは持たない。未刻印のまま `Stage` を呼ばないことは、刻印を生成の一点に集約し、テストで担保する。

### raw スキーマと生成時の刻印

食料 raw に保存期間 `shelfLife`、ターン数、任意、を追加する。腐敗するかどうかは shelfLife の有無だけで表す。省略した食料は非腐敗として `Perishable` を付けない。0 のような特別値は使わず、スキーマも `@minValue(1)` で正の値だけ受ける。保存食のビスケットは省略する。

腐敗の速さは食料ごとの `shelfLife` で決まる。傷みやすい食料ほど小さく、日持ちする食料ほど大きくする。段階境界は `shelfLife` の倍数なので、小さいほど早く劣化・腐敗する。食べ物ごとに腐敗のしやすさが違うのはこの1つの値で表す。

生成時刻はワールドの時計を読むため、raw→エンティティ変換では確定できない。変換では `shelfLife` を持つ食料に `Perishable{ShelfLife}` を載せ、`SpawnedAtTurn` は 0 のままにする。生成時に `Perishable` を持つエンティティへ `SpawnedAtTurn = GetGameTime(world).TotalTurns` を刻印する。全アイテム生成が通る `spawnItemBase` の1箇所で行う。`spawnItemBase` は `world` を受け取るため `GetGameTime(world)` で時計を引け、シグネチャは変えない。

### 食べる効果

`use_item.go` の `applyNutrition` を鮮度で分岐する。

- 新鮮: 従来どおり満額
- 劣化: 栄養 0.5 倍
- 腐敗: 栄養を得られず、満腹を一定量下げる不調。満腹を下げるのは `Hunger.Decrease` を使う。`Increase` に負数を渡すのはクランプで意図が曖昧なため避ける。ログに「傷んでいた」と出す

鮮度補正は `applyNutrition` の内部で計算する。`applyNutrition` は既に `world` と `item` を受け取るため、`Perishable` と `GameTime` をそこから引けて引数は増えない。呼び出し元は素の栄養値を渡し、鮮度による補正と不調の適用は `applyNutrition` に閉じる。差し替え点が1箇所に収まる。

`Perishable` を持たない食料は従来どおり満額。栄養段階の算出は `Perishable.Stage(現在ターン)` に集約し、食べる処理と表示が同じ判定を通す。

将来 状態異常システムができたら、腐敗の不調を毒や食中毒に載せ替える。差し替え点は `applyNutrition` の1箇所に閉じる。

### スタックの合流

スタック可能な食料は、同定キーだけでなく `SpawnedAtTurn` も一致するときに限って合流する。すなわちスタックキーを RawID から RawID + SpawnedAtTurn へ広げる。生成や取得のタイミングが同じ食料は1つの束にまとまり、鮮度が違えば別々の束として残る。1束は1つの `SpawnedAtTurn` を持ち、束の中の鮮度は常に揃う。

鮮度が違うものを1束に畳んで古い側へ寄せる案は採らない。新鮮な食料を古い束へ足すと全部が古くなり、per-item の鮮度という情報を捨てるため。保持は鮮度で厳密に分け、見やすさは表示側に委ねる。

合流は既存の在庫合流処理に相乗りし、スタックキーの一致判定に `SpawnedAtTurn` を足す。非腐敗アイテムは `Perishable` を持たないため従来どおり RawID だけで合流する。

同じ鮮度段階でも生成タイミングが違えば別の束になる。段階が同じ束を表示だけまとめるのは将来の改善余地とし、v1 は束ごとに鮮度を示すに留める。

### 表示

アイテムのメニュー行と詳細で鮮度を示す。

- 新鮮: 表示なし、または通常色
- 劣化: 「劣化」を色付きで添える
- 腐敗: 「腐敗」を警告色で添える

腐敗食は自動で消えないため、プレイヤーが状態を見て捨てるか食べるか判断できるよう、表示で鮮度を明確にする。表示は `Perishable.Stage` を通し、食べる処理と判定を共有する。

## 採用しなかった方法

- **腐敗品を消滅、自動撤去、させる**: 腐敗のさらに先で食料を消す案。溜め込み在庫を機械的に片付けられるが、ゲームがプレイヤーの持ち物を勝手に消すのは理不尽に感じられ、うっかり撤去された不満を生む。腐敗食は無価値で有害な重りとして残し、捨てるかどうかは player に委ねる。溜め込み防止は撤去でなく無価値化で満たす。撤去用の走査、`Expired` 判定、End フェーズ処理も不要になる
- **2段階、新鮮→腐敗**: 実装は最軽量だが、劣化の緩衝が無く早取りの勾配が急。3段階で滑らかにする
- **連続劣化**: 栄養を経過で線形に減衰させる案。最も滑らかだが段階がプレイヤーに見えにくく、UI で鮮度を伝えづらい。離散3段階にする
- **毎ターンのカウンタ減算**: 各食料の残り時間を毎ターン減らす案。O(食料数)/ターンの走査が要る。生成時刻の遅延評価にして走査を消す
- **気温連動**: 寒冷で腐敗を遅らせる案。可動部が増えるため v1 では入れず、`GetTemperatureModifier` を使う拡張として残す。保存容器も同様
- **状態異常システムを新設して腐敗の不調を毒/病気にする**: v1 の範囲を超える。当面 Hunger を削る負効果で表し、後から差し替える

## コメント

- 段階境界の倍数と栄養倍率、各食料の `shelfLife` は balance で調整する前提。まずは仮値で通し、プレイして詰める
- `SpawnedAtTurn` の刻印を生成経路ごとに散らすと漏れやすい。刻印を1箇所にして、新しい生成経路が増えても担保する
- 腐敗の不調の具体量、腐敗時の栄養下限は未確定。実装時に仮値を置いて調整する
