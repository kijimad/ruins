# 食料の腐敗

## 背景

食料を早く取るインセンティブが無く、拾った食料を永遠に溜め込める。時間経過で食料が劣化し、やがて食べられなくなる仕組みを入れて、次の2つを満たす。

- 早取りのインセンティブ。新鮮なうちに食べるほど得
- 溜め込み防止。放置した食料はいずれ栄養を失い消滅する

CDDA の「食品ごとの生成時刻を暦時間と比較して腐敗を判定する」方式と、Elona の「腐った食料は栄養が無く不調を招く」方式を参考にする。丸ごとは持ち込まず、ruins の既存基盤に載る最小形にする。

既存の足場:

- `GameTime.TotalTurns` が遺跡内で永続する総ターン数。1500 ターン/日、250 ターン毎に時間帯が変わる。腐敗の時刻基準に使う
- `Hunger` プールに `use_item.go` の `applyNutrition` が `hunger.Increase(栄養)` する。栄養は raw の `providesNutrition`
- 毎ターンの全体処理は `systems/turn_system.go` の End フェーズ。空腹・気温・`GameTime.Advance` をここで回す
- 食料は `assets/metadata/entities/raw/raw.toml` に定義。`stackable` な食料が多い
- 状態異常の仕組みは無い。腐敗食の「不調」は当面 Hunger を削る負効果で表現する

## 要件

- 腐敗する食料は3段階で遷移する。新鮮 → 劣化 → 腐敗。腐敗のさらに先で消滅する
  - 新鮮: 栄養 100%
  - 劣化: 栄養 50%、無害
  - 腐敗: 栄養ほぼ 0、食べると軽い不調
  - 消滅: エンティティを撤去する
- 保存食は腐敗しない。食料ごとに保存期間を宣言し、未指定は非腐敗とする
- 気温非依存の固定速度。寒冷・保存容器による減速は将来拡張
- セーブ/ロードで鮮度が保たれる
- 毎ターン全食料を走査しない。鮮度は参照時に遅延評価する

## 設計

### 時刻基準と遅延評価

各食料に生成時刻と保存期間を持たせ、鮮度は「現在の総ターン数 − 生成時刻 = 経過ターン」で都度求める。カウンタを毎ターン減算する走査を持たないため O(食料数)/ターンの負荷が無く、保存も int 2つで済む。

段階の境界は保存期間 `ShelfLife` の倍数で表す。

| 経過ターン | 段階 | 栄養倍率 |
|---|---|---|
| `[0, ShelfLife)` | 新鮮 | 1.0 |
| `[ShelfLife, 2*ShelfLife)` | 劣化 | 0.5 |
| `[2*ShelfLife, 3*ShelfLife)` | 腐敗 | ~0 + 不調 |
| `>= 3*ShelfLife` | 消滅 | 撤去 |

倍率と倍数はバランス調整用の定数にする。例えばパンの `ShelfLife = 1500`（1日）なら、1日目は新鮮、2日目は劣化、3日目は腐敗、4日目に消滅する。

### コンポーネント

```go
// Perishable は腐敗する食料が持つ。生成時刻と保存期間から鮮度を遅延評価する。
// 気温非依存の固定速度。ShelfLife は raw の shelfLife 由来
type Perishable struct {
	SpawnedAtTurn consts.Turn // 生成時の GameTime.TotalTurns
	ShelfLife     consts.Turn // 新鮮でいられるターン数。これを基準に段階が決まる
}
```

```go
// FreshnessStage は鮮度の段階
type FreshnessStage int

const (
	FreshnessFresh  FreshnessStage = iota // 新鮮
	FreshnessStale                        // 劣化
	FreshnessRotten                       // 腐敗
)

// Stage は経過ターンから鮮度段階を返す。now は GameTime.TotalTurns
func (p *Perishable) Stage(now consts.Turn) FreshnessStage {
	age := now - p.SpawnedAtTurn
	switch {
	case age < p.ShelfLife:
		return FreshnessFresh
	case age < 2*p.ShelfLife:
		return FreshnessStale
	default:
		return FreshnessRotten
	}
}

// Expired は消滅すべきかを返す。腐敗のさらに先で true
func (p *Perishable) Expired(now consts.Turn) bool {
	return now-p.SpawnedAtTurn >= 3*p.ShelfLife
}
```

`consts.Turn` だけを持つため serde 安全。`skipComponents()` に入れず保存対象にする。GameTime と同じく遺跡内で永続する。

### raw スキーマと生成時の刻印

食料 raw に保存期間 `shelfLife`（ターン数、任意）を追加する。省略または 0 は非腐敗とし `Perishable` を付けない。保存食のビスケットは省略する。

生成時刻はワールドの時計を読むため、raw→エンティティ変換では確定できない。`shelfLife > 0` の食料を生成する箇所で `SpawnedAtTurn = GetGameTime(world).TotalTurns` を刻印する。EntitySpec には `Perishable{ShelfLife: shelfLife}` を載せ、`SpawnedAtTurn` は生成時に埋める。生成経路はフィールド配置・戦利品・店・初期配置に分かれるため、刻印を1つのヘルパに集約する。

### 食べる効果

`use_item.go` の `applyNutrition` を鮮度で分岐する。

- 新鮮: 従来どおり満額
- 劣化: 栄養 0.5 倍
- 腐敗: 栄養に小さな下限、加えて不調。不調は当面 Hunger を一定量削る負効果で表現し、ログに「傷んでいた」と出す

`Perishable` を持たない食料は従来どおり満額。栄養段階の算出は `Perishable.Stage(現在ターン)` に集約し、食べる処理と表示が同じ判定を通す。

将来 状態異常システムができたら、腐敗の不調を毒や食中毒に載せ替える。差し替え点は `applyNutrition` の1箇所に閉じる。

### 消滅の掃除

腐敗のさらに先に達した食料はエンティティごと撤去する。鮮度は遅延評価だが、放置された食料の物理的な撤去には走査が要る。毎ターンではなく時間帯が変わる 250 ターン毎に、`Perishable` を持つ食料だけを対象に `Expired` を判定して消す。腐敗の粒度は粗いため、この頻度で十分に「溜め込み防止」を満たす。走査対象は食料に限られ規模も小さい。

クエリ反復中の削除は Ark で禁止のため、collect-then-mutate で一旦集めてからループ外で消す。

### スタックの合流

スタック可能な食料は同定キーで合流する。鮮度が違う束を混ぜると鮮度がぼやけるため、合流時は古い方の `SpawnedAtTurn`、すなわち小さい値を採る。新鮮な1個を古い束に足すとその1個も古い側に寄るが、鮮度ロンダリングを防ぎ、束あたり1つの時計で済む。合流は既存の在庫合流処理に相乗りする。

### 表示

アイテムのメニュー行と詳細で鮮度を示す。

- 新鮮: 表示なし、または通常色
- 劣化: 「劣化」を色付きで添える
- 腐敗: 「腐敗」を警告色で添える

詳細モーダルには段階、または消滅までの目安ターンを出す。表示は `Perishable.Stage` を通し、食べる処理と判定を共有する。

## 採用しなかった方法

- **2段階（新鮮→腐敗）**: 実装は最軽量だが、劣化の緩衝が無く早取りの勾配が急。3段階で滑らかにする
- **連続劣化**: 栄養を経過で線形に減衰させる案。最も滑らかだが段階がプレイヤーに見えにくく、UI で鮮度を伝えづらい。離散3段階にする
- **毎ターンのカウンタ減算**: 各食料の残り時間を毎ターン減らす案。O(食料数)/ターンの走査が要る。生成時刻の遅延評価にして走査を消す
- **気温連動**: 寒冷で腐敗を遅らせる CDDA 的な案。可動部が増えるため v1 では入れず、`GetTemperatureModifier` を使う拡張として残す。保存容器も同様
- **腐敗品を消さず無価値で残す**: 溜め込み防止にならず在庫を圧迫する。消滅させる
- **スタックを鮮度別に分割**: 鮮度ごとに束を分ける案。束が増え管理が煩雑。合流時に古い側へ寄せて1束1時計にする
- **状態異常システムを新設して腐敗の不調を毒/病気にする**: v1 の範囲を超える。当面 Hunger を削る負効果で表し、後から差し替える

## コメント

- 段階境界の倍数と栄養倍率、各食料の `shelfLife` は balance で調整する前提。まずは仮値で通し、プレイして詰める
- `SpawnedAtTurn` の刻印を生成経路ごとに散らすと漏れやすい。刻印ヘルパを1つにして、新しい生成経路が増えても1箇所で担保する
- 腐敗の不調の具体量、腐敗時の栄養下限は未確定。実装時に仮値を置いて調整する
