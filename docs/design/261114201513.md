# 区域の作りを、地区の並べ方・地区の層・塀・植え込みの組み合わせにする

## 背景

区域の種類は raw の行で定義するが、作りは `layout` の列挙 `town` と `campus` で決めている。設計 doc 261113205202 の形。参考 codebase: `internal/overworld/urban.go`、`internal/raw/validate.go`。

列挙の値ごとに、次の規則がコードに書かれている。

| 規則 | town | campus |
|---|---|---|
| 地区の並べ方 | 中心を都心、外側を区域の seed で住宅地か産業区 | 南の端の行を門、北の端の行を閉鎖区画、残りを中ほど |
| 区域が使う地区 | 都心・住宅地・産業区 | 門・中ほど・閉鎖区画 |
| 塀と門、道が門を通る | 無し | 有り |
| 街路の植え込み | 無し | 有り |
| 高さの検証 | 無し | 地区の数以上 |

本当に振る舞いが違うのは地区の並べ方だけで、塀と植え込みは有無の値、どの地区を使うかは id の並びにすぎない。今の形では、軍の基地や工業団地のような区域を足すたびに列挙を増やし、全ての分岐を直すことになる。

## 要件

1. 塀・植え込み・使う地区を、区域の行の値で決める。
2. 地区の並べ方だけを列挙に残し、コードに部品として持つ。
3. 並べ方と値の組み合わせで、新しい区域を raw の行だけで足せる。
4. 今の町と研究所の敷地の生成結果を変えない。

## 設計

### 区域の行

```cue
#District: {
	id!: #EntityID
	spacing!:    int & >=1
	separation!: int & >=0
	sizes!: [...#DistrictSize] & [_, ...]
	landmark?: #EntityID

	// 地区の並べ方
	pattern!: #DistrictPattern
	// 地区の層。プレイヤーが入ってくる側から順に並べる。rings は外から内へ、rows は南から北へ
	layers!: [...#DistrictLayer] & [_, ...]
	// 外周に塀を巡らせ、北と南に門を開ける。道は門を通って区域を抜ける
	fence?: bool
	// 街路の両端を植え込みにして、建物と道の間を空ける
	verge?: bool
}

// 地区の並べ方。rings は中心からの距離で層を分け、rows は行で層を分ける
#DistrictPattern: "rings" | "rows" @rawgen(prefix)

// 地区の層。候補の地区から区域の seed で1つ選ぶ
#DistrictLayer: {
	zones!: [...#Zone] & [_, ...]
	// rows で、この層が占める行の数。省いた層は残りの行を全て占める
	rows?: int & >=1
}
```

- `rings` は層を2つ持つ。1つ目が外側、2つ目が中心で、中心の判定は今の都心の判定のまま使う。`rows` は使わない。
- `rows` は層を2つ以上持つ。`rows` を省いた層をちょうど1つ持ち、その層が残りの行を占める。区域の高さは、`rows` の和に1を足した値以上にする。
- 層の候補が複数あるときは、区域の seed の上位の決まったビットから1つ選ぶ。今の町の、住宅地と産業区を選ぶビットと同じ選び方にする。

今の2つの区域は次のように書ける。

```toml
[[districts]]
id = "town"
pattern = "rings"
  [[districts.layers]]
    zones = ["residential", "industrial"]
  [[districts.layers]]
    zones = ["downtown"]

[[districts]]
id = "lab_campus"
pattern = "rows"
fence = true
verge = true
  [[districts.layers]]
    zones = ["campus_gate"]
    rows = 1
  [[districts.layers]]
    zones = ["campus_inner"]
  [[districts.layers]]
    zones = ["campus_quarantine"]
    rows = 1
```

### 区域の当選

区域の当選は、作りの列挙の代わりに区域の行を指す。行は raw の表の中の要素を指すポインタにする。同じ raw から引いた当選どうしは今と同じく `==` で比べられる。

```go
// 変更前
type districtRegion struct {
	layout   rawschema.DistrictLayout
	anchor   consts.Coord[consts.Chunk]
	w, h     consts.Chunk
	seed     uint64
	landmark string
}

// 変更後
type districtRegion struct {
	// kind は区域の種類の行
	kind   *rawschema.District
	anchor consts.Coord[consts.Chunk]
	w, h   consts.Chunk
	seed   uint64
}
```

- 地区は `zoneAt` が並べ方で層を決め、層の候補から1つ選ぶ。
- 区域が使う地区の一覧 `raw.DistrictZones` は、層の候補を全て集めて返す。施設の検証と、地区の網羅のテストが使う。
- 塀と門、道が門を通ることは `kind.Fence`、植え込みは `kind.Verge` で決める。

### 検証

- `rings` の層は2つで、`rows` を書かない。
- `rows` の層は2つ以上で、`rows` を省いた層がちょうど1つある。
- `rows` の区域の高さは、層の `rows` の和に1を足した値以上にする。今の研究所の敷地の高さの検証を、この一般の規則に置き換える。
- 層の地区が `#Zone` の値であることは CUE の型で検査する。

## 採用しなかった方法

- **作りの列挙 `layout` を保つ。** 区域を足すたびに列挙と全ての分岐を直す。並べ方2通りと塀・植え込みの有無で、組み合わせは8通りになる。
- **並べ方ごとに名前の付いた欄を持つ。** `core`・`outer`・`south`・`middle`・`north` のように並べ方で使う欄が変わり、どの欄が要るかを並べ方ごとに検証することになる。層の並びなら、2つの並べ方が同じ形で書ける。
- **地区の配置を絵のように raw に描く。** 区域の大きさが可変なので、描いた配置を大きさに合わせて伸ばす規則が別に要る。
- **`rings` の層も幅を持たせて何層にもできるようにする。** 今の都心の判定は辺の短い方に合わせた中心の矩形で、外周からの幅では表せない。使う区域が出てから足す。
- **地区を CUE の列挙から raw の表へ移す。** 地区は6つで頻繁には増えない。要るときに別に行う。

## コメント

- 層を、プレイヤーが入ってくる側から並べる。研究所の敷地は南の門から入り、町は外から中心へ入る。どちらも1つ目の層が入口になり、読む順と歩く順が揃う。
