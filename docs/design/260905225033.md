# 移動拠点キューブを燃料ドライブ式の乗り物にする

## 背景

移動拠点キューブは現在、オーバーワールド帯の上に置く `Pushable` のプロップである。動かすには
隣接して押す・引くを行う。これは分解と同じ多ターンの Activity で、毎ターンプレイヤーの AP を
進捗へ注ぎ、必要総コストは内部ステージに積んだ物の総重量で決まる。プレイヤーは乗らず、
押すとキューブが1タイル進み、次の移動入力で空いたタイルへ自分が歩く。

内部は `Depth:1` の別ステージで、キューブに隣接して入り `SwapTo` で切り替える歩ける空間である。
この歩ける内部には次の課題がある。

- どこでも入れる安全な部屋になり、危険地帯が無効化されうる。安全の希少性が崩れる。
- 別ステージなので `SwapTo`・`Suspended`・内部テンプレ・ポータルの機構を要し、運転を足すと
  徒歩・運転・内部の3状態のモード切替が複雑になる。
- overworld を主軸に深さ層を畳む方針に対し、内部は残った `Depth:1` の階層である。

そこで、キューブを「乗り込んで運転する燃料式の乗り物」へ作り替える。あわせて歩ける内部を
やめ、キューブに付属する収納へ畳む。収納した工具はキューブに隣接している間だけ自動で
使われる。歩ける安全な部屋が無くなるので安全の希少性が保たれ、深さ層も1つ畳める。

移動コストは燃料へ移し、収納が重いほど1タイルの燃料が増える。溜め込むほど機動が落ちる
備蓄と機動のジレンマを、単一の物理キューブへ束ねる。

## 要件

- プレイヤーはキューブに乗り込んで直接運転する。運転中は移動入力がキューブを動かす。
- キューブに戦闘力は持たせない。敵と戦う・調べるには降車する。
- キューブは耐久を持たず壊れない。運転中もプレイヤーは通常どおり被弾するが、反撃はできない。
  危険地帯の突破は一方的に殴られるので、降車して戦うのが安全。
- 移動1タイルごとに行動ターンと燃料の双方を消費する。燃料消費量はキューブ収納の総重量に比例する。
- 燃料はキューブ収納に入れた燃料アイテムから引く。燃料定義は火への給油 FeedFuel と共通にする。
- 燃料が尽きたら運転できず立往生する。押し・引きは廃止し、燃料確保が唯一の移動手段とする。
- 歩ける内部ステージは持たない。キューブは付属の収納を持ち、収納の開閉はメニューで行う。
- キューブは受動的な暖やシェルターを与えない。暖は火からのみ得る。持ち運べる安全地帯を
  温度的にも作らず、寒さの緊張を保つため。睡眠もキューブでなく都度確保する仮拠点で行う。
- 収納に入れた工具は、プレイヤーがキューブに隣接している間だけ工具解決の候補へ加わる。
  離れれば使えない。溶接機・調理器具などの重い能力は拠点の傍らでのみ使える。
- 運転移動は帯シフトを駆動し、帯は東進のみ、西へ戻れない制約を保つ。
- キューブは1タイルの footprint を保つ。壁・敵など通行不可の先へは進めず停止する。
- 立往生は詰みにしない。降車したプレイヤーは通常どおり歩けるので、燃料を探して収納へ入れ再開できる。

## 設計

### 状態モデル

運転状態はプレイヤー側の一時コンポーネントで表す。運転中はプレイヤーをキューブへ同乗させ、
座標をキューブに同期し、スプライトを隠す。

```go
// Driving はプレイヤーが運転中であることと運転対象の乗り物を表す。
// 運転中は移動入力を乗り物へ委譲し、プレイヤーは同乗して座標を乗り物に同期する。
// 一時状態なので保存しない。運転中にセーブしたら自動で降車扱いにし、entity 参照の serde を避ける。
type Driving struct {
	Vehicle ecs.Entity // 運転中の乗り物
}
```

```go
// Drivable はキューブが運転可能であることを表すマーカー。押し引きの Pushable を置き換える。
// SpawnCube が付与する。
type Drivable struct{}
```

- キューブは既存の収納機構を使い、アイテムをキューブへ紐付けて持つ。収納箱や出荷場所と同じ
  entity スコープの収納で、新しい保存構造を増やさない。
- `Driving` は `skipComponents()` へ入れて保存対象から外す。セーブ時に運転中なら降車させ、
  ロード後はキューブ隣接で歩き状態から再開する。これにより entity 参照の ID 空間整合を持ち込まない。
- 運転中はプレイヤーの `GridElement.Coord` を毎ステップ キューブへ一致させる。帯シフト判定
  `Driver.MaybeShift` はプレイヤーのローカル X を見るため、同乗で座標が一致していればキューブの
  移動がそのまま帯シフトを駆動する。既存のシフト機構を変えずに運転へ流用できる。

### モード遷移

歩ける内部を持たないので、プレイヤーの状態は徒歩と運転の2つだけになる。どちらも同じ
オーバーワールド帯ステージ上の制御モードの違いで、ステージ切替 `SwapTo` は挟まない。
収納の開閉は別ステージへの遷移でなく、その場のメニューを重ねるだけである。

```
徒歩(帯) ──直上でEnter・乗車──▶ 運転(帯)
徒歩(帯) ◀── 同じキーで降車 ───── 運転(帯)

徒歩(帯) ──隣接でspaceコンテキストメニュー──▶ キューブメニュー(重ね表示)
                                          ├ 収納
                                          ├ オークション
                                          └ キューブ情報
```

- 新規の遷移は乗車・降車だけ。ステージ切替は一切増えない。
- `Driving` はステージ境界を跨がない。運転はオーバーワールド帯の上だけで完結するので、
  保存しない一時状態のまま復元処理も要らない。

### 乗降とキューブメニュー

乗降とキューブメニューは、発動範囲の違う別々の相互作用にする。乗降はキューブの直上で、
キューブメニューは隣接で発動する。既存の相互作用機構がちょうどこの2範囲を持つので、
発動プロトコルを新設せず `InteractionKind` を2種足すだけで表せる。

- 乗車は `InteractionDrive` を SameTile・Manual で持たせる。キューブの直上に立って Enter を
  押すと運転を始める。ワープの直上で Enter を押して階層移動するのと同じ発動で、乗車専用の
  入力経路を足さない。乗車でプレイヤーへ `Driving{Vehicle}` を付ける。
- 降車は運転入力の処理で、乗車と同じキーをトグルとして解釈する。運転中は移動入力と降車
  入力だけを解釈するので、同じキーの再入力は相互作用でなく降車になる。キューブ隣の歩行可能
  タイルへプレイヤーを置き、`Driving` を外す。
- キューブメニューは `InteractionOpenCubeMenu` を Adjacent・Manual で持たせ、隣接時の space
  コンテキストメニューから開く。個別の相互作用を並べず、1つの入口から下位項目へ入る。
- キューブメニューはデバッグメニューと同じ `ChoiceMenu` を流用し、次の項目を並べる。運転は
  メニューに含めない。乗降は直上の Enter で完結するため。
  - 収納: アイテムの出し入れ。既存の収納 UI を流用する。
  - オークション: 出荷・売却。既存のオークション UI を流用し、対象収納をキューブにする。
  - キューブ情報: 総重量と燃料残量を表示する。既存の `CubePanelState` を流用する。耐久は持たないので出さない。
- オークションはキューブへ集約し、固定の出荷場所 `shipping_station` プロップは廃する。オーバー
  ワールドは東進のみで固定の市場へ戻れないため、移動する拠点が交易窓口を兼ねるのが自然。
- 運転中はキューブメニュー・戦闘・調べるを受け付けない。移動入力と降車入力だけを解釈する。

### 移動と課金

運転中の移動入力1回で、キューブを1タイル進めようとする。

1. 進行先が通行可能か `CanMoveTo` で判定する。壁・敵など不可なら停止し、ターンも燃料も消費しない。
2. 収納の燃料残量が必要量以上かを確かめる。足りなければ運転不可のメッセージを出し停止する。
3. 行動ターンを1つ消費する。押しと同じく移動の脆弱時間を残し、敵が寄れる隙を保つ。
4. 燃料を消費する。消費量は収納の総重量に比例する。
5. キューブとプレイヤーを進行先へ動かし、帯シフトを判定する。

燃料消費量は総重量から求める。押しの `PushCost` が担っていた「重いほど高コスト」を、AP でなく
燃料へ移す。総重量は `query.CubeWeight` を収納集計へ更新して流用する。

```go
// DriveFuelCost はキューブ収納の総重量から1タイル運転の燃料消費量を返す。空でも基準量が
// かかり、総重量に比例して増える。PushCost が AP で表していた重量ペナルティを燃料へ移した対応物。
func DriveFuelCost(total consts.Milligram) int {
	kg := int(total / consts.MilligramPerKg)
	return consts.DriveFuelBase + consts.DriveFuelPerKg*kg
}
```

### 燃料源と消費

- 燃料はキューブ収納に入れた燃料アイテムから引く。収納の総重量を数える `CubeWeight` と同じ
  対象、すなわちキューブへ紐付いた収納アイテムのうち燃料値を持つ物を燃料源にする。
- 燃料値の定義は火への給油 FeedFuel と共通にする。coal・wood_log・torch などが持つ燃料値を
  同じ経路で参照し、二重定義を避ける。
- 消費は必要量に達するまで燃料アイテムのスタックを減らし、尽きたスタックは削除する。
- 収納燃料の総量を返す `query.CubeFuelTotal(world, cube)` と、必要量を消費する
  `lifecycle.ConsumeCubeFuel(world, cube, amount)` を用意する。

### 収納工具の近接発動

- 分解などの工具を要するアクションは、開始時に固定せず毎ターン actor の所持品から適合する
  工具を解決する。この解決元を拡張し、プレイヤーがキューブに隣接しているときはキューブ収納の
  工具も候補へ加える。出荷場所が隣接判定で station 収納を扱うのと同じ近接ゲートである。
- 隣接から離れれば収納工具は候補から外れる。溶接機・調理器具などの重い能力は拠点の傍らでのみ
  使え、遠出時は個人の所持品だけで動く。located-capability を歩ける内部なしで成立させる。
- 工具候補を集める共通ヘルパーへ集約し、分解・調理・製作など工具ゲートのアクションが同じ経路で
  近接キューブ収納を見るようにする。個別のアクションへ散らさない。

### 運転中の被弾

キューブ自身は耐久を持たず壊れない。危険への脆弱性はプレイヤー本人が負う。

- キューブに HP や耐久は持たせない。破壊もゲームオーバー経路も作らない。
- 運転中もプレイヤーは同乗しつつ被弾対象のまま。座標同期でキューブの位置にいるので、隣接した敵は
  プレイヤーを普通に殴れる。既存のプレイヤー被弾・死亡機構をそのまま使う。
- 運転中は反撃・調べる・収納を受け付けない。移動入力と降車入力だけ。危険地帯を突っ切ると
  一方的に被弾するので、降りて敵を掃除するのが安全。ゲームオーバーは通常のプレイヤー死亡で起きる。
- 描画でスプライトを隠しても entity は残し、被弾・狙いの対象にする。被弾表示は同乗位置に出す。

### 押し引きの廃止

- `internal/activity/push.go` の `PushBehavior`・`PullBehavior` を削除する。
- `BehaviorPush`・`BehaviorPull`、および相互作用・プレイヤーアクションの押し引き項目を削除する。
- `query.PushCost`・`query.PushPower`・`cubePushCost` を削除する。`query.CubeWeight` は
  燃料コスト算出のため残し、集計対象を収納へ更新する。
- `Pushable` コンポーネントがキューブ専用なら削除する。他プロップが使っていないか確認する。
  使っている物があれば、その用途を残したまま `Drivable` を別に足す。
- キューブから `BlockPass` を外し、直上に立てる通行可能な地物にする。乗車は SameTile 発動で
  プレイヤーがキューブのタイルへ乗る必要があり、`BlockPass` のままでは乗れない。押しの廃止で
  `BlockPass` が担っていた歩き込みを押しへ分岐させる用途も消えるので、外してワープと同じ
  通行可能な直上インタラクションへ揃える。帰結として駐車中のキューブは通行可能になり、敵が
  そのタイルへ入りうる。キューブは壁でなく乗り物なので受け入れる。
- 詰み防止の Pull は運転では不要になる。運転は毎タイル方向を選び、不可なら停止するので
  キューブを壁際へ食い込ませない。

### 歩ける内部ステージの撤去

- キューブ内部の別ステージ定義 `DungeonCubeInterior` と、その内部テンプレを撤去する。
- キューブへの `SwapTo` の往復、`InteractionEnterCube`・`WarpCubeEnter`・`WarpCubeExit`、
  ポータルを兼ねる `cube_exit`・`control_panel` プロップを撤去する。
- `CubeWeight` は内部ステージの床エンティティ集計から、キューブ収納の集計へ更新する。
- 撤去で `Suspended` を使う他ステージ、遺跡・オーバーワールドの共存機構には触れない。
  キューブ内部だけが `SwapTo` を使わなくなる。

### 描画・カメラ

- 運転中はプレイヤースプライトを隠し、カメラはキューブを追尾する。座標同期により既存の
  プレイヤー追尾カメラをそのまま使える見込み。差異が出れば運転中だけキューブ追尾へ切り替える。

## 採用しなかった方法

- 押しのまま燃料課金にする案。差分は小さいが、拠点に住んで動かす手応えが出ず、押し引きの
  微操作も残る。乗り物化の要件を満たさないため不採用。
- 燃料切れで手動押しへ縮退する案。push/pull を保険として残せるが、燃料確保という唯一の
  緊張を薄める。立往生を許し、降車して歩いて燃料を探す方がサバイバルとして効くため不採用。
- 専用の燃料タンクをキューブに持たせる案。UI は分かりやすいが、給油という別機構が増える。
  収納の燃料アイテムを直接消費すれば重量と燃料が同じ場所で管理され直感的なため不採用。
- 運転を無ターンの即時移動にする案。移動が速いが、押し中に敵が寄る脆弱時間が消える。
  survival の緊張を残すため、毎タイル行動ターンを消費する。
- キューブをマルチタイル、たとえば 2x2 の footprint にする案。乗り物としての存在感は増すが、
  グリッドが単一タイル前提のため、当たり判定・通行索引・描画・湧き・隣接をすべて footprint へ
  一般化する必要がある。乗る・燃料・移動の本質と直交する重い機構追加なので、キューブは
  1x1 のまま据える。なお 2x2 の正方形なら向きで占有形が変わらず、2x1 の長方形より実装は軽い。
  将来サイズが必要になれば別設計で単一エンティティ + Footprint として足す。
- 歩ける内部ステージ、すなわち別空間の拠点を残す案。基地の居心地や室内建築の余地は生むが、
  内部は `Depth:1` の階層で `SwapTo`・`Suspended`・内部テンプレ・ポータルの機構を要する。
  さらに「どこでも安全な部屋に入れる」緊張の破れと、徒歩・運転・内部のモード切替の複雑さを
  持ち込む。収納と近接工具へ畳めばこれらが消えつつ、重量移動コストと備蓄と機動のジレンマは
  保たれ、overworld を主軸に深さ層を畳む方針にも沿うため、歩ける内部は採らない。
- キューブに耐久 HP を持たせ、被弾や破壊で管理する案。拠点防衛の緊張は出るが、HP・破壊 `Cause`・
  修理・被弾AIと機構が増える。運転中はプレイヤー本人が普通に被弾する形にすれば、危険突破の
  リスクを既存のプレイヤーダメージと死亡でそのまま表現でき単純なため、キューブは耐久を持たせない。
- 隣接時にキューブの各機能を個別の相互作用として並べる案。収納・オークション・情報が
  隣接の選択肢に一度に並び雑然とする。1つのキューブメニューを入口にし下位項目へ分岐する方が
  入口が1つで見通しがよいため、個別相互作用は並べない。
- 乗車もキューブメニューの一項目にする案。入口が1つに揃うが、乗るたびに隣接して space から
  メニューを開き運転を選ぶと操作段数が増える。乗降は最頻の操作なので、直上 Enter の1操作で
  完結させる方が軽い。ワープの階層移動と同じ発動で学習も要らないため、乗車はメニューから外し
  直上の `InteractionDrive` にする。収納・オークション・情報は頻度が低く隣接メニューで足りる。
- 乗車を隣接発動にする案。キューブを `BlockPass` のまま残せるが、乗るのに隣接と直上の2つの
  発動範囲が混在し分かりにくい。直上に揃えればワープと同じ体験になり、押し廃止で不要になった
  `BlockPass` も外せて一貫する。壁としての当たりは失うが、キューブは乗り物なので許容する。
- オークションを固定の出荷場所に据え置く案。市場らしさは出るが、オーバーワールドは東進のみで
  固定地点へ戻れず、通り過ぎた市場は使えない。移動する拠点が交易窓口を兼ねる方が動線に合うため、
  出荷場所はキューブメニューへ集約する。

## コメント

- キューブは受動的な暖・シェルターを持たないと決めた。持たせると持ち運べる安全地帯が温度的にも
  復活し、寒さの緊張が崩れる。暖は火からのみ得るので、キューブの傍らでも火が要り、火の燃料と
  運転の燃料が同じ燃料経済を取り合う緊張が保たれる。
- 睡眠はキューブで行わず、都度確保する仮拠点で行う。寝袋の設置と火による暖の確保など、
  休むたびに手間と資源と露出を伴う。詳細は睡眠の設計で詰める。撤去の前に睡眠側の依存を確認する。
- 立往生の詰み回避を実装で担保する。降車後に歩いて燃料を集め収納へ入れ再開できる導線を確認する。
- `InteractionKind` は複数スイッチで exhaustive 強制されている。`InteractionDrive`・
  `InteractionOpenCubeMenu` の追加と、`InteractionEnterCube`・`InteractionExitCube`・
  `InteractionPullCube`・`InteractionCubePanel`・`InteractionAuction` の撤去は、該当する全スイッチへ
  反映する。ruins-review 参照。
- 乗車 `InteractionDrive` は SameTile・Manual で、ワープ系 `InteractionPortalNext` らと同じ発動範囲。
  乗車にはキューブが通行可能である必要があるため、`SpawnCube` から `BlockPass` を外す作業と対で扱う。
  外し忘れると直上に立てず乗車が発動しない。
- entity 参照を持つ `Driving` は保存しない方針だが、運転中セーブの自動降車が座標をずらす。
  ロード直後にキューブ隣で歩き状態から再開する挙動をテストで固定する。
- 運転中もプレイヤーは被弾対象のまま。スプライトを隠しても entity を消さず、隣接した敵が狙える
  ことをテストで固定する。反撃だけできない非対称を崩さない。
