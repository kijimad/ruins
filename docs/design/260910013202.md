# 地図ステートを他メニューと同じモーダルにする

## 背景

N キーで開く地形俯瞰図 `OverworldMapState` は、`Draw` の冒頭で `screen.Fill(theme.OverworldMapBackground)` と画面全体を不透明の暗色で塗りつぶし、その上へチャンク格子と凡例を `ebiten` の `text.Draw`/`vector.FillRect` で直描きする。背後のダンジョンは完全に隠れる。

一方、他のメニュー系モーダルはこれと作法が違う。状態機械の描画 `StateMachine.Draw` はスタックの全ステートを下から上へ同じ `screen` に重ね描きする。push されたモーダルは下のステートを残す。透過フラグの類は無く、モーダルは「画面全体を塗らず、`menuframe` のパネルだけを game の上に重ねる」ことで背後を透かしている。`DungeonMenu`/`KeyHelp`/`ItemAction`/`Message`/`CubeMenu` はいずれも `menuframe` のパネルを組み、`st.body.Draw(uicore.NewEbitenCanvas(screen))` で描くだけで、`screen.Fill` はしない。背後を暗くする dim も現状どのモーダルも掛けていない。`theme.Overlay` は定義のみで参照ゼロ。

つまり画面全体を黒く塗るのは `OverworldMapState` だけで、これが「黒背景が他と一貫していない」の正体である。地図を他メニューと同じモーダル、すなわち PanelBG のパネルを game の上に重ねる形へ揃える。

## 要件

- 地図ステートを他のメニュー系画面と同じモーダルにする。画面全体の塗りつぶしを廃し、背後のダンジョンを透かす。
- パネルは他モーダルと同じ意匠にする。`menuframe` の PanelBG テクスチャを標準の `ModalRect` に敷く。
- 背後を暗くする dim は掛けない。既存モーダルの規約に合わせる。ユーザー確定。
- 凡例・キューブ/現在地マーカー・探索フォグ・タイトルは残す。
- 全画面図はモーダルいっぱいに大きく見せる。帯全体窓でなくプレイヤーを横の中心に据えた窓にし、セル寸法と半径をモーダル寸法から決めて大きなセルで描く。探索フォグは維持する。帯は縦が短いので縦は帯全高が上限、横はモーダル幅いっぱいになる。
- 開閉導線は変えない。N での push、N/Esc での pop。

## 設計

### 描画をモーダル規約へ寄せる

`KeyHelpState` を手本にする。`OverworldMapState` に `body uicore.Widget` を持たせ、`OnStart` で1度だけ組み、`Draw` はそれを描くだけにする。

```go
type OverworldMapState struct {
	es.BaseState[w.World]

	view      overworld.MacroView        // 帯全体のチャンク俯瞰。従来どおり OnStart で算出
	playerAbs consts.Coord[consts.Chunk] // ヘッダの現在チャンク座標
	body      uicore.Widget              // モーダルのパネル。OnStart で組み Draw で描く
}
```

`Draw` から `screen.Fill` を外し、`KeyHelp` と同じ形にする。背後のダンジョンは状態機械が重ね描きするので透ける。

```go
func (st *OverworldMapState) Draw(_ w.World, screen *ebiten.Image) error {
	st.body.Draw(uicore.NewEbitenCanvas(screen))
	return nil
}
```

### パネルの中身をどう描くか

格子は色セルの並びで、`menuframe` のリスト行に素直に乗る形ではない。表示中はプレイヤーが動かず `view` は不変なので、`OnStart` で格子・凡例・タイトルを**オフスクリーン画像へ1度だけ描き**、`uicore.NewGraphic` で包んでパネルへ入れる。

- 現状 `screen` へ直描きしている格子・凡例・マーカーの描画を、そのままオフスクリーンの `*ebiten.Image` へ原点ローカルで描くだけに変える。描画ロジックは不変で、描き先を screen から画像へ移す。
- 画像を `uicore.NewGraphic(img)` にし、`menuframe.PanelBox(res, graphic)` で PanelBG のパネルへ収め、`ModalRect(world)` へ配置して `st.body` に持つ。PanelBox は「PanelScreen/TabScreen に収まらない独自配置の画面が意匠だけを部品へ合わせる」ための入口で、まさにこの用途。
- パネル寸法に対し画像が大きいときの収まりは実装で詰める。フォグで序盤は小さく、`ModalRect` は画面いっぱいに近いので通常は収まる。帯が広い場合の縮小・切り詰めは既存でも起きうる別問題で本 PR の対象外。

### 撤去

- `theme.OverworldMapBackground`（全画面塗り用の不透明暗色）は唯一の参照 `screen.Fill` が消えるので撤去する。
- `drawLegend`・`glyphColor` などの格子描画ヘルパは、描き先が screen からオフスクリーン画像へ変わるだけで残す。

### モーダルいっぱいのプレイヤー中心窓

全画面図はモーダルを大きく使う。帯全体窓 `FullBandWindow` をやめ、プレイヤーの絶対チャンク列を横の中心に据えた `overworld.PlayerCenteredWindow` にする。セル寸法 `st.cellPx` は帯の行数からモーダル内側高さを割って大きめに決め、半径はモーダル幅に収まるチャンク数から決める。どのチャンクを見せるか窓はモデル、何 px で描くかセル寸法は描画だが、両者は一致させる必要があるので `cellPx` を state に持ち `OnStart` の半径算出と `renderMap` で共有する。フォグは HUD と同じ `query.DiscoveredChunks` を渡して維持する。格子は横をモーダル内側の中央へ寄せて描く。帯は縦が短いので縦は帯全高が上限で、横はモーダル幅いっぱいになる。

### 変えないもの

- `overworldMapBindings`（N/Esc → `ActionCloseMenu`）と `Update` の pop。
- 開く導線 `dungeon_input.go` の `ActionOpenOverworldMap` による push。
- `OnStart` の `playerAbs` 算出とフォグ、`BuildMacroView` によるモデル生成。窓だけがプレイヤー中心へ変わる。

## 採用しなかった方法

- **格子・凡例を uicore ウィジェットツリーへ全面書き換え**: 色セルの格子はリスト/行の部品に馴染まず、`menuframe` のリストへ載せると不自然。描画ロジックを大幅に作り替える割に得るものが少ない。オフスクリーン画像＋Graphic で意匠だけ合わせるほうが小さく済む。
- **`screen.Fill` を外すだけでパネルを重ねない**: 格子が枠なしでダンジョンの上に浮き、「他メニューと同じモーダル」にならない。パネル意匠が要件。
- **背後に半透明 dim を敷く**: 読みやすさは上がるが、既存モーダルはどれも dim を掛けておらず、`theme.Overlay` も未使用。新しい見せ方を1画面だけに入れるのは非一貫。ユーザーも dim なしを選択。
