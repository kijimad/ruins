# オーバーワールドの屋内外を判定し温度を場所依存にする

## 背景

温度はオーバーワールド上で空間的に一律で、雪原の真ん中の小屋の中も外と同じ寒さになる。場所によって寒暖を変えたい。とくに「屋内は暖かく屋外は寒い」を成立させたい。

現状の周囲気温は `AmbientTemperatureAt`（`internal/systems/temperature.go:57-82`）が返す。屋内外は**ステージ種別**で決まり、タイルごとの判定はしない、とコメントに明記されている。

```go
worldTemp := gt.GetSeasonalTemperature() + gt.GetTemperatureModifier() // 季節 + 時間帯
tileMod := getTileTemperatureAt(world, x, y)                           // Shelter や水草の加算
if query.IsOnOverworld(world) {                                       // singleton.go:140
    return worldTemp + tileMod, nil                                   // 屋外一律。Shelter は単純加算
}
return def.BaseTemperature() + worldTemp/dungeonWorldInfluenceDivisor + tileMod, nil // 屋内は世界温度を割って受ける
```

判明した現状:

- **per-tile の屋内属性は既に存在する**。`TileTemperature.Shelter`（`internal/components/tile_temperature.go`、`ShelterNone=0 / ShelterPartial=5 / ShelterFull=10`、値がそのまま加算℃）。
- **屋内判定アルゴリズムも存在する**。`EnvironmentPlanner.floodFillOutdoor`（`internal/mapplanner/environment_planner.go:34-88`）がマップ端から壁を越えず到達できるかで屋内/屋外を決め、生成時に Shelter へ焼く。spawner が転写する（`internal/mapspawner/spawner.go:69-73`）。
- **ただしオーバーワールド生成経路が EnvironmentPlanner を通さない**。`internal/mapplanner/overworld_field.go` は dirt で埋めるだけで、建物内部を作る `internal/overworld/interior_furnish.go` の `replaceTile`（`internal/overworld/urban.go:338-351`）は Shelter を焼かない。結果、オーバーワールド上の建物内部はすべて `ShelterNone`＝屋外扱いになる。屋内 Shelter が正しく付くのは EnvironmentPlanner を通るダンジョン系ステージだけ。
- **季節変化は実装済み**。`GetSeasonalTemperature`（`internal/components/game_time.go:92`）が32日周期の正弦波で夏 +22℃・冬 −30℃。時間帯補正 `GetTemperatureModifier` が昼 +10〜深夜 −10℃。

つまり「屋内外を区別する仕組み」はほぼ完成していて、オーバーワールドに配線されていないだけ。そのうえで、現状の Shelter は固定加算℃で季節にスケールしない、という別問題がある。冬 −30℃ に +10 しても屋内 −20℃ で生存できない。

## 要件

- オーバーワールド上の建物内部を屋外と区別し、屋内は寒暖を緩めて受ける。
- 屋内温度は季節にスケールする。既存ダンジョン式 `worldTemp/divisor` に統一する。冬の屋外は死ぬが屋内なら耐えられる、夏は屋外より涼しい、を成立させる。
- 季節変化は既存 `GetSeasonalTemperature` を流用し、追加しない。
- 熱源での能動的な暖房（暖炉に火を焚く）は将来の上乗せ余地として設計を塞がない。本ドキュメントの必須スコープには含めない。

## 設計

2つに分ける。**(1) 屋内検知の配線**（マップ生成側、健康系と直交）と、**(2) 温度式の一般化**（`temperature.go`、健康系と要調整）。

### (1) 屋内検知をオーバーワールド建物へ配線する

`interior_furnish` は既に庭・壁・床を区別して `replaceTile` している。建物内部の床タイルを屋内としてマークし、既存の `TileTemperature.Shelter` へ `ShelterFull` を焼く。転写経路 `spawner.go:69-73` はそのまま使える。壁で囲われた床＝屋内、という意味論は建物が実際に壁で閉じているため成立する。

新規コンポーネントは足さない。屋内属性は既存の `Shelter` に集約する。

### (2) 温度式を per-tile の屋内緩和へ一般化する

`Shelter` を「加算℃」でなく「世界温度の受け方を決める緩和度」として再解釈する。屋内度に応じて `worldTemp` の受け方をタイル単位で変える。

```go
// shelter がタイルの屋内度。worldTemp の受け方を切り替える
func AmbientTemperatureAt(world w.World, x, y consts.Tile) (int, error) {
    worldTemp := gt.GetSeasonalTemperature() + gt.GetTemperatureModifier()
    baseTemp := currentStageBaseTemperature(world) // 屋外(overworld)=0、ダンジョンは種別ごと
    heat := heatModifierAt(world, x, y)            // 熱源など、屋内外に依らない局所加算
    switch shelterAt(world, x, y) {
    case gc.ShelterNone: // 屋外
        return baseTemp + worldTemp + heat, nil
    case gc.ShelterPartial: // 半屋外。中間の受け方
        return baseTemp + worldTemp*3/4 + heat, nil
    case gc.ShelterFull: // 屋内。世界温度を割って受ける
        return baseTemp + worldTemp/indoorInfluenceDivisor + heat, nil
    }
}
```

これで屋内外は**per-tile の shelter だけ**で決まり、ステージ種別の分岐 `IsOnOverworld` は温度計算から外せる。ダンジョンのタイルは EnvironmentPlanner が `ShelterFull` を焼いているので、緩和は自然に効く。オーバーワールド建物も (1) で `ShelterFull` を持てば同じ式で暖まる。既存の `dungeonWorldInfluenceDivisor` は屋内共通の `indoorInfluenceDivisor` に一般化する。

数値イメージ（`indoorInfluenceDivisor=2`、baseTemp=0 の街）:

```
冬 worldTemp -30:  屋外 -30℃ / 屋内 -15℃
夏 worldTemp +22:  屋外 +22℃ / 屋内 +11℃
```

### 季節

追加なし。`worldTemp` に既に季節が入っており、屋内緩和と掛け算で survivability を作る。

## 採用しなかった方法

- **固定加算 Shelter の値を上げるだけ**（最小変更）。実装は最小だが固定℃なので季節にスケールしない。冬を救う値にすると夏が灼熱になる。屋内緩和を式で表す本案を採る。
- **熱源駆動のみ**（屋内は素の世界温度、暖炉に火を焚けば暖かい）。屋内そのものは寒いままで「屋内に避難する」が成立しない。火必須の survival は一案だが、まず「屋内は穏やか」の土台を作り、熱源は将来その上へ乗せる。
- **実行時 flood-fill で毎ターン屋内判定**。アルゴリズムは既存だが、オーバーワールドのストリーミング生成と相性が悪く毎ターンのコストもかかる。生成時に一度焼く現行方式で足りる。
- **屋根被覆で屋内判定**。屋根の表現がコードに一切無く、載せる先が無い。

## コメント

- **コンフリクト境界**。`temperature.go` は健康系（低体温）が `worktree-injury-combat` で改修中で衝突しうる。(1) の配線側（`overworld`・`mapplanner`・`spawner`）は健康系と直交するので先行できる。(2) の式変更は injury-combat のマージ後に調整して入れる。
- **ダンジョン挙動の変化リスク**。統一式は `ShelterNone` のダンジョンタイル、たとえば洞窟の開口部を、従来のステージ一律緩和から「屋外扱い」に変える。ダンジョンの温度テストとゴールデンで挙動を確認する。挙動を変えたくなければ、baseTemp と `IsOnOverworld` を残したまま屋内緩和だけ per-tile に足す保守案もある。
- **熱源の未実装**。`hearth`・`fireplace` は現状 `heatSource` を持たず装飾で、暖房にならない（`assets/metadata/entities/raw/raw.toml:14802`）。屋内で能動的に暖を取る体験は、この設計の上に heatSource を与えて別途乗せる。
