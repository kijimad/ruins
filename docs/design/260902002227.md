# オーバーワールドの屋内外を判定し温度を場所依存にする

## 背景

温度はオーバーワールド上で空間的に一律で、雪原の真ん中の小屋の中も外と同じ寒さになる。場所によって寒暖を変えたい。とくに「屋内は暖かく屋外は寒い」を成立させたい。

現状の周囲気温は `AmbientTemperatureAt`（`internal/systems/temperature.go:57-82`）が返す。屋内外は**ステージ種別**で決まり、タイルごとの判定はしない、とコメントに明記されている。

```go
worldTemp := gt.GetSeasonalTemperature() + gt.GetTemperatureModifier() // 季節 + 時間帯
tileMod := getTileTemperatureAt(world, x, y)                           // Shelter や水草の加算
if query.IsOnOverworld(world) {                                       // singleton.go:140
    return worldTemp + tileMod, nil                                   // 屋外一律。Shelter は単純加算
}
return def.BaseTemperature() + worldTemp/dungeonWorldInfluenceDivisor + tileMod, nil // 屋内は世界温度を割って受ける
```

判明した現状:

- **per-tile の屋内属性は既に存在する**。`TileTemperature.Shelter`（`internal/components/tile_temperature.go`、`ShelterNone=0 / ShelterPartial=5 / ShelterFull=10`、値がそのまま加算℃）。
- **屋内判定アルゴリズムも存在する**。`EnvironmentPlanner.floodFillOutdoor`（`internal/mapplanner/environment_planner.go:34-88`）がマップ端から壁を越えず到達できるかで屋内/屋外を決め、生成時に Shelter へ焼く。spawner が転写する（`internal/mapspawner/spawner.go:69-73`）。
- **ただしオーバーワールド生成経路が EnvironmentPlanner を通さない**。`internal/mapplanner/overworld_field.go` は dirt で埋めるだけで、建物内部を作る `internal/overworld/interior_furnish.go` の `replaceTile`（`internal/overworld/urban.go:338-351`）は Shelter を焼かない。結果、オーバーワールド上の建物内部はすべて `ShelterNone`＝屋外扱いになる。屋内 Shelter が正しく付くのは EnvironmentPlanner を通るダンジョン系ステージだけ。
- **季節変化は実装済み**。`GetSeasonalTemperature`（`internal/components/game_time.go:92`）が32日周期の正弦波で夏 +22℃・冬 −30℃。時間帯補正 `GetTemperatureModifier` が昼 +10〜深夜 −10℃。

つまり「屋内外を区別する仕組み」はほぼ完成していて、オーバーワールドに配線されていないだけ。そのうえで、現状の Shelter は固定加算℃で季節にスケールしない、という別問題がある。冬 −30℃ に +10 しても屋内 −20℃ で生存できない。

## 要件

- オーバーワールド上の建物内部を屋外と区別し、屋内は寒暖を緩めて受ける。
- 屋内温度は季節にスケールする。既存ダンジョン式 `worldTemp/divisor` に統一する。冬の屋外は死ぬが屋内なら耐えられる、夏は屋外より涼しい、を成立させる。
- 季節変化は既存 `GetSeasonalTemperature` を流用し、追加しない。
- 熱源での能動的な暖房（暖炉に火を焚く）は将来の上乗せ余地として設計を塞がない。本ドキュメントの必須スコープには含めない。

## 設計

2つに分ける。**(1) 屋内検知の配線**（マップ生成側、健康系と直交）と、**(2) 温度式の一般化**（`temperature.go`、健康系と要調整）。

### (1) 屋内検知をオーバーワールド建物へ配線する

`interior_furnish` は既に庭・壁・床を区別している。建物内部の床タイルを屋内としてマークし、既存の `TileTemperature.Shelter` へ `ShelterFull` を焼く。壁で囲われた床＝屋内、という意味論は建物が実際に壁で閉じているため成立する。新規コンポーネントは足さない。屋内属性は既存の `Shelter` に集約する。

配線方法。建物タイルは `furnishBuilding`（`interior_furnish.go:46`）が `replaceTile`（定義は `urban.go:338`）を呼んで置き換える。`replaceTile` は現状 `error` だけを返しタイル実体を返さないため、生成後に外から Shelter を設定できない。戻り値に `ecs.Entity` を足す。`replaceTile` は既に `tiles[g] = e` で実体を索引へ書き戻しており、その `e` を返すのは自然な拡張。`furnishBuilding` の床配置で受けた実体へ `TileTemperature.Shelter` を設定する。ダンジョン系の `spawner.go:69-73` はプラン経由の別経路で、そちらは従来どおり EnvironmentPlanner の値を転写する。

### (2) 温度式を per-tile の屋内緩和へ一般化する

`Shelter` を「加算℃」でなく「世界温度の受け方を決める緩和度」として再解釈する。屋内度に応じて `worldTemp` の受け方をタイル単位で変える。

```go
// shelter がタイルの屋内度。worldTemp の受け方を切り替える
func AmbientTemperatureAt(world w.World, x, y consts.Tile) (int, error) {
    worldTemp := gt.GetSeasonalTemperature() + gt.GetTemperatureModifier()
    baseTemp := currentStageBaseTemperature(world) // 屋外(overworld)=0、ダンジョンは種別ごと
    heat := heatModifierAt(world, x, y)            // 熱源など、屋内外に依らない局所加算
    switch shelterAt(world, x, y) {
    case gc.ShelterNone: // 屋外
        return baseTemp + worldTemp + heat, nil
    case gc.ShelterPartial: // 半屋外。中間の受け方
        return baseTemp + worldTemp*3/4 + heat, nil
    case gc.ShelterFull: // 屋内。世界温度を割って受ける
        return baseTemp + worldTemp/indoorInfluenceDivisor + heat, nil
    }
}
```

これで屋内外は**per-tile の shelter だけ**で決まり、ステージ種別の分岐 `IsOnOverworld` は温度計算から外せる。ダンジョンのタイルは EnvironmentPlanner が `ShelterFull` を焼いているので、緩和は自然に効く。オーバーワールド建物も (1) で `ShelterFull` を持てば同じ式で暖まる。既存の `dungeonWorldInfluenceDivisor` は屋内共通の `indoorInfluenceDivisor` に一般化する。

数値イメージ（`indoorInfluenceDivisor=2`、baseTemp=0 の街）:

```
冬 worldTemp -30:  屋外 -30℃ / 屋内 -15℃
夏 worldTemp +22:  屋外 +22℃ / 屋内 +11℃
```

`Shelter` を緩和度にするので、`TileTemperature.Total()`（`tile_temperature.go:45`、`Shelter + Water + Foliage` の合算）から `Shelter` を外す。`Total()` は温度計算 `getTileTemperatureAt`（`temperature.go:216`）と HUD のホバー表示（`look_around.go:263` の「Temperature modifier」）の2箇所で純粋な加算℃として使われている。`Water`・`Foliage` は加算℃のまま上式の `heat`（`heatModifierAt`）へ集約し、`Shelter` は `shelterAt` で緩和度として別経路で扱う。HUD 表示は加算℃分だけを示す。屋内緩和は環境気温そのものに現れるので、別行で示すかは実装時に決める。

`ShelterPartial` の `worldTemp*3/4` は暫定値で実プレイで調整する。現状オーバーワールド建物では `ShelterFull` しか使わない。

### (3) 動的な囲われの変化への対応

現状の Shelter は生成時の flood-fill を焼いた静的値で、実行時の構造変化に追従しない。しかも `floodFillOutdoor`（`internal/mapplanner/environment_planner.go:34`）は生成時のプラン `mp.Tiles[].BlockPass`、すなわちタイルの壁だけを見ており、扉エンティティを見ていない。

扉は既に実行時に開閉して通行可否が変わる（`internal/activity/door.go`、`lifecycle.OpenDoor`）。将来は壁の破壊で半開放にもなりうる。耐久値 `HitPoints` による破壊可能の基盤は既に prop に存在する。したがって、扉を開けても室内が寒くならない、という齟齬が**将来ではなく現時点で**起きうる。囲われを生成時に凍結する設計はここで破綻する。

方針: 囲われ判定を「生成時に凍結した値」でなく「現在のマップ状態から導ける純関数」に位置づける。ruins の「導出可能な一時状態は保存せず読み取り時に導く」方針に沿う。

- flood-fill を、プランでなく**現在のタイル壁と扉の開閉状態**を入力に取る再利用可能な関数へ切り出す。
- `Shelter` は温度系の線形走査を速く保つためのキャッシュとして持ち、**構造変化イベントで対象領域を dirty にして再計算**する。トリガは扉の開閉と、将来の壁・prop 破壊で共通の再計算経路を呼ぶ。扉は `OpenDoorBehavior.DoTurn` と `CloseDoorBehavior.DoTurn` の両方が既に `VisionState.RequestUpdate()` を発行しており、その同じ箇所で Shelter の dirty も立てる。開閉どちらも通すこと。
- これにより「扉を開けると冷気が入る」が創発的に成立する。−15℃ の室内が扉開放で屋外の −30℃ へ近づく、という遊びになる。

スコープ判断: 破壊可能な壁はまだ無いので専用機構は作らない。ただし `Shelter` を再計算可能な形にし、既存の動的ケースである扉開閉を最初のトリガとして繋ぐ。壁破壊が入ったら同じ再計算経路を呼ぶだけにする。

### 季節

追加なし。`worldTemp` に既に季節が入っており、屋内緩和と掛け算で survivability を作る。

## 採用しなかった方法

- **固定加算 Shelter の値を上げるだけ**（最小変更）。実装は最小だが固定℃なので季節にスケールしない。冬を救う値にすると夏が灼熱になる。屋内緩和を式で表す本案を採る。
- **熱源駆動のみ**（屋内は素の世界温度、暖炉に火を焚けば暖かい）。屋内そのものは寒いままで「屋内に避難する」が成立しない。火必須の survival は一案だが、まず「屋内は穏やか」の土台を作り、熱源は将来その上へ乗せる。
- **実行時 flood-fill で毎ターン屋内判定**。アルゴリズムは既存だが、オーバーワールドのストリーミング生成と相性が悪く毎ターンのコストもかかる。生成時に一度焼く現行方式で足りる。
- **屋根被覆で屋内判定**。屋根の表現がコードに一切無く、載せる先が無い。
- **動的変化を無視し生成時焼きのままにする**。扉が既に実行時に開閉するので、扉を開けても室内が寒くならない齟齬が現時点で起きる。最小だが要件に反する。
- **完全な derive-on-read、キャッシュせず毎クエリ flood-fill する**。純粋だが温度系の線形走査で毎回コストがかかる。キャッシュと dirty 無効化で十分。
- **RimWorld 式のフル温度シミュレーション**。室温を状態として持ち、熱慣性で目標へ徐々に収束させ、素材ごとの断熱値でセル間を熱拡散させる方式。ターン制ローグライクにはオーバーキルで、探索主軸の ruins は基地運営ゲーのような精密な室内気候管理を要求しない。さらに「保存された室温状態」は ruins の『導出可能な一時状態は保存せず導く』方針に反し、廃止した TemperatureTrend と同じ陳腐化する派生状態になる。忠実度は下記コメントの範囲に留める。

## コメント

- **コンフリクト境界**。`temperature.go` は健康系（低体温）が `worktree-injury-combat` で改修中で衝突しうる。(1) の配線側（`overworld`・`mapplanner`・`spawner`）は健康系と直交するので先行できる。(2) の式変更は injury-combat のマージ後に調整して入れる。
- **ダンジョン挙動の変化リスク**。統一式は `ShelterNone` のダンジョンタイル、たとえば洞窟の開口部を、従来のステージ一律緩和から「屋外扱い」に変える。ダンジョンの温度テストとゴールデンで挙動を確認する。挙動を変えたくなければ保守案へ退避する。保守案の式は、`IsOnOverworld` 分岐を残し、屋外は従来どおり `worldTemp + tileMod`、ダンジョンは `baseTemp + worldTemp/divisor + tileMod` のまま、オーバーワールドの屋内タイルにだけ per-tile shelter 緩和を足す。統一案を優先する判断軸は、ステージ種別分岐 `IsOnOverworld` を温度計算から消し、屋内外を per-tile shelter の1軸へ集約できること。ステージ種別と per-tile が併存する2系統の技術的負債を避けたい。ダンジョンの golden を確認し、挙動差が許容できれば統一案、できなければ保守案とする。
- **熱源の現状**。`hearth`・`fireplace` は現状 `heatSource` を持たず装飾で、暖房にならない（`assets/metadata/entities/raw/raw.toml:14802`）。既存の `heatSource` も体温を直接動かすだけで環境温度には効かない。屋内で火を焚いて暖を取る体験は L2 として本設計の忠実度に含め、熱源を環境温度へ効かせる。
- **囲われは導出可能な状態**で、生成時に凍結すると動的変化で陳腐化する。ruins の「一時状態は保存せず導出する」方針に従い、`Shelter` はキャッシュと位置づけ構造変化で再計算する。扉が既に動的なので、この再計算の仕組みは将来の壁破壊のためだけでなく現時点の正しさのために要る。
- **忠実度の範囲**。RimWorld のような温度システムが理想だが、フル実装は重くオーバーキル。忠実度を段で捉え、採る範囲を明示する。L0=グローバル一律（従来）／ L1=per-tile 囲われ＋屋内緩和＋扉で動的（本設計の中心）／ L2=熱源が囲われた領域の環境温度を押す（RimWorld のヒーター感を、状態を持たずターンごとの平衡で再現）／ L3=熱慣性・セル間拡散・室温状態（フル RimWorld）。**本設計は L1 と L2 までを採り、L3 はやらない**。L2 は温度式の熱源加算 `heatModifierAt` がそのまま担い、火を焚けば屋内が暖まるが、状態は持たずターンごとに平衡値を出す。L3 を再検討するのは、冷蔵保存で食料腐敗を遅らせる等の明確な用途が出たときに限る。
