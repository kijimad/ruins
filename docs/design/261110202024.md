# コードに残るゲームデータを raw へ移す

## 背景

設計 doc 261109215116 で、不調・スキル・攻撃の種類・内装・天候・空腹と疲労の識別子と調整値を raw へ移した。その後コード全体を洗い直すと、ゲームデータがまだ Go に残っていた。

- raw の行の id を文字列で直書きしている。例 最初の持ち物の `"torch"`、商人の在庫、`if name == "merchant"`。参考 codebase: `internal/world/lifecycle/spawn.go:80,93,142`、`merchant.go:17`
- 種類ごとの値の表を map や switch で持つ。例 ダンジョンの定義、集落の構成、時間帯ごとの気温と明るさ。参考 codebase: `internal/dungeon/registry.go`、`internal/overworld/settlement.go`、`internal/components/game_time.go:189`、`internal/systems/vision.go:334`
- raw の行が表示名を持たず、Go が持つ。例 天候、空腹と疲労の段階。参考 codebase: `internal/components/weather.go:51`、`hunger.go:28`、`fatigue.go:15`
- 調整用の数値の定数が、ゲーム本体だけで約250個ある。マップ生成が約155個で最も多い

文字列で書いた参照は検証から見えず、id が変わると黙って外れる。実際に、環境のプランナーが存在しないタイル名で判定していて、植生と水がいつも無しになっていた。これは 261109215116 の PR で直した。

## 要件

1. 261109215116 の方針をそのまま使う。値と参照は持ち主の行に書き、識別子と表示名を分け、コードが名前で分岐する識別子だけを Go に残す。
2. raw の id をコードに文字列で書かない。コードが特定の行を必要とするなら、行の側に役割を書き、コードは役割から引く。不調の `onset` と同じ形にする。
3. 段ごとに挙動を変えない。golden とバランスのベースラインが変わらないことで確かめる。
4. デバッグメニューとデバッグステージの中身は対象外にする。

## 設計

### 方針

- **既存の行に足せるものから移す。** 新しい行の種類は、既存の行に収まらないときだけ作る。
- **コードが特定の行を必要とするときは、役割を行に書く。** 商人を名前で探さず、在庫を持つ member が店を開く。プレイヤーのキャラクターは職業の行が指す。
- **表示名は行の `name` にする。** 天候や段階のように enum の値を表示に使っていたものも、行に `name` を足して訳の網羅テストに載せる。
- **間取りの形とアルゴリズムの係数は Go に残す。** 移すのは、遊びの手触りを調整するときに触る値だけにする。

### 1段目: 既存の行に足す

```toml
[[professions]]
id = "evacuee"
member = "ash"
items = [{ id = "bandage", count = 2 }, { id = "splint", count = 1 }]
equips = [{ id = "torch", slot = "weapon1" }]

[[members]]
id = "merchant"
stock = "merchant_stock"

[[itemCollections]]
id = "merchant_stock"

[[attackTypes]]
id = "bow"
name = "Bow"
injury = "laceration"
range = "ranged"
optimalRange = 4
maxRange = 10
penaltyPerTile = 5

[[weathers]]
id = "blizzard"
name = "Blizzard"

[[hungerStages]]
id = "starving"
name = "Starving"

[[props]]
id = "door"
[props.door]
horizontalOpen = "door_horizontal_open"
horizontalClosed = "door_horizontal_closed"
verticalOpen = "door_vertical_open"
verticalClosed = "door_vertical_closed"

[[props]]
id = "fire"
burnoutItem = "ashes"

[[props]]
id = "cube"
hp = 200

[[props]]
id = "dungeon_entrance"
```

- 最初の持ち物は職業によらず全プレイヤーに配るので、職業の行でなくプレイヤーの member の行の `startingEquips` と `startingItems` に書く。職業の行へ写すと6行に重複し、職業を経ずに作るプレイヤーが持ち物を失う。プレイヤーのキャラクターは member の行の既存の `player` で示し、`raw.PlayerMemberID` で引く。ちょうど1つあることを読み込み時に確かめる。
- 商人の在庫を member の行の `stock` から引く。店を開く判定は `stock` を持つかにし、`name == "merchant"` を消す。
- 攻撃の種類に表示名、近接と遠距離の区分、射程の値を足し、`rangeParamsMap` と `AttackType` の値の表を消す。
- 天候、空腹と疲労の段階に `name` を足し、Go の表示名の表を消す。
- 扉の開閉と向きごとの見た目を door の行へ移す。キューブとダンジョン入口に prop の行を作り、`warp_next` を流用して名前を上書きする作りをやめる。
- 燃え尽きた火が残すアイテムを fire の行へ移す。

### 2段目: 新しい行の種類

```toml
[[dungeons]]
id = "dead_forest"
name = "Dead forest"
description = "..."
imageKey = "forest1"
enemyTable = "forest"
itemTable = "forest"
baseTemp = 0
planners = [{ id = "forest", weight = 5 }, { id = "small_room", weight = 2 }, { id = "big_room", weight = 1 }]

[[settlements]]
id = "village"
weight = 6
members = [{ name = "merchant", dx = -2, dy = -1 }]
props = [{ name = "hearth", dx = 2, dy = -2 }]

[[timesOfDay]]
id = "dawn"
name = "Dawn"
tempModifier = 0
daylight = 0.65
ambientColor = { r = 1.0, g = 0.8, b = 0.72 }

[[seasons]]
id = "winter"
name = "Winter"
temp = -30

[[freshnessStages]]
id = "rotten"
name = "Rotten"
nutritionPercent = 30

[[materials]]
id = "coal"
name = "Coal"
heatPerKg = 800
```

| 行 | 移すもの | 参考 codebase |
|---|---|---|
| `dungeons` | ダンジョンの名前・説明・絵・敵とアイテムの表・基準の気温・マップ生成の重み | `internal/dungeon/registry.go` |
| `settlements` | 村と集落の住人と置物の配置、出現の割合 | `internal/overworld/settlement.go` |
| `scatterZones` に足す | 地面を覆う草と土の種類と重み | `internal/overworld/scatter.go:60` |
| `interiorProfile` に足す | 損傷・散らかり・変種ごとの効果、外観と区画の置物、目玉の置物の頻度 | `internal/mapplanner/interior/age.go`、`profile.go`、`facade.go`、`lot.go`、`site_type.go`、`hero.go` |
| `timesOfDay`、`seasons` | 時間帯と季節の表示名、気温、明るさ、環境光の色 | `internal/components/game_time.go`、`internal/systems/vision.go` |
| `freshnessStages` | 鮮度の段階の表示名と栄養の倍率 | `internal/components/perishable.go`、`internal/activity/use_item.go:232` |
| `materials` | 材質の表示名と燃焼の熱量 | `internal/widgets/entityspec/spec.go:284`、`internal/world/query/fuel.go:14` |
| `toolCategories` | 工具の種類と伸びるスキル | `internal/activity/salvage.go:63` |
| `dialogues` | NPC の会話文 | `internal/messagedata/dialogues.go` |
| `tiles` に足す | 生成するときの見た目とオートタイル | `internal/mapspawner/spawner.go:89` |

- 季節と時間帯はすでに enum があり、天候の行が季節の id を使っている。行の id は enum の値で書き、行が enum の全値を1回ずつ持つことを検証する。
- 会話文は訳を通す経路を決めてから移す。会話の文は今 Go の関数で組んでいる。
- 鮮度の段階の境目と並び順は Go の `Perishable` と `FreshnessRank` に残す。境目は保存期間の倍数で決まる形で、行が持つのは表示名と栄養の割合だけにする。段階の id は生成された `oapi.FreshnessStageId` を使い、Go の写しの型を消す。表は空腹の生理値に効くので `NeedDefs` が持つ。
- ダンジョンの行の id がステージの識別名になり、遺跡の入口とステージのキーが持つ。表示名は `name` に分ける。間取りの種類は新しい enum `DungeonPlanner` で書き、Go が `mapplanner.PlannerType` へ写す。オーバーワールドの定義は帯の形状を持つ構造の設定で、デバッグ用の定義は要件4で対象外なので、どちらも Go に残す。`description` と `imageKey` は今表示する経路が無いので、行が持つだけで Go は読まず、訳の網羅にも載せない。
- 集落の住人と prop はランドマークと同じ `PropSpot` で書き、キーは `name` にそろえる。集落の行の id は地図の記号の id を兼ねる。種類は行の重みの比で選び、村6と一軒家4は今までの割合と同じ結果になる。
- 地面を覆う草と土の飾りは `scatterZones` の行の `grass` と `soil` に書き、土の飾りを置く確率も `soilDensity` として行へ移す。今は道沿いと奥地で同じ値を持つ。
- 内装の効果は `interiorProfile` の既存の行に足す。損傷の行は略奪の割合と瓦礫の種の割合、散らかりの行は家具の隣と床へ小物を落とす割合、変種の行は損傷と家具量の上書きと散らかりの下限を持つ。敷地の類型は新しい enum `SiteType` の行 `sites` にし、民家と店それぞれの重みと前庭の奥行きを持つ。外皮と外構の置物は `facade` と `lot` に interiorRefs の id で書き、生活痕の割合 `wearPercent` と目玉の頻度 `heroOneIn` も表に移す。無傷の建物に経年を掛けない分岐と、分割と配置のアルゴリズムは Go に残す。生活痕と瓦礫と散らかりの小物の Ref はこの段で移していない。
- 時間帯の id は新しい enum `TimeOfDayId` にする。Go の `TimeOfDay` と `Season` は順序数の enum のまま残し、天候と同じく raw の id から写す。時間帯と季節の表は `CalendarDefs` が持つ。季節の行の `temp` は、春と秋が年の前半と後半の中点、夏が頂、冬が底の温度で、間を正弦波でつなぐ式は Go に残す。
- 材質は `MaterialDefs` が表示名と kg あたりの熱量を持つ。不燃の材質も行を持ち、熱量を0にする。道具の分類が伸ばすスキルは `SkillDefs.ToolSkills` が持ち、スキルを省いた分類は伸ばさない。

### 3段目: 調整用の数値の定数

約250個ある定数の置き場を決める。設計を決める前に、次の分け方を判断する。

- **行に属する値は行へ移す。** 例 部位ごとの値、ダンジョンごとの値。1段目と2段目に含める。
- **全体に1つの値は、全体の調整の表にまとめるか、所属するパッケージに残す。** 例 フロアの敵の数、空腹の上限、戦闘の命中の式の係数。PR #824 のとき、これらを `consts` へ集める方針で合意したが、規模を理由に保留している。

```toml
[tuning]
floorEnemyBase = 5
floorEnemyRandom = 4
hungerMax = 500
```

全体の調整の表を作るかどうかは人が決める。作らないなら、3段目は #824 と合わせて閉じる。

### Go に残すもの

- コードが名前で分岐する識別子。スキル、熟練の効果、不調を起こす仕組み、ワープの `warp_next`、基本タイルの壁と床。
- 間取りの形と区画の名前。部屋の割り方はアルゴリズムで、区画の名前は形と1対1に結びつく。
- 画面の表示に使う enum のラベル。重症度、装備の部位、AI の方針など。
- デバッグメニューとデバッグステージの中身。
- アルゴリズムの係数。洞窟のセル・オートマトンの閾値、マップ生成の試行回数の上限など。

## 採用しなかった方法

- **1つの PR でまとめて移す**: 行の種類が10を超え、レビューできない。既存の行に足す1段目と、新しい行の種類の2段目を分ける。
- **コードが特定の行を id で探す形を残し、id を定数にする**: 定数にしても、行の役割がコードに埋まったままになる。不調の `onset` と同じく、役割を行に書く。
- **デバッグの中身も raw へ移す**: 遊びの調整で触らず、raw の行が増えるだけになる。
- **アルゴリズムの係数も raw へ移す**: 触ると生成の形が壊れる値で、調整のための値ではない。
