# 新規開始時と入眠時のオートセーブ

## 背景

オートセーブ機構 `SerializationManager.AutoSave` は実装済みだが、ゲームプレイからの発火点が
一つも無い。手動セーブだけがセーブメニューのスロット選択で書かれる。クラッシュや不意の終了で
進捗が失われる。

Continue 機能は起動時に最新オートセーブを読み込むが、書き込み契機が無いため読むデータが生まれ
ない。書き込みと読み込みは相補的で、両方揃って初めて機能する。

本タスクは書き込み契機を足し、あわせて Continue のロード対象を手動と自動の全スロットから最新を
選ぶ形に広げる。

## 要件

- **新規ゲーム開始直後**にオートセーブし、最初の復帰点を作る。
- **入眠時**にオートセーブする。入眠は安全・気温・疲労を検証した安全な瞬間で、チェックポイントに
  向く。ターン数で間隔を刻むより、こうしたゲーム上の節目で保存するほうがシンプルで直感的。
- オートセーブ失敗はゲーム進行を止めない。ログに残して続行する。
- 体験版などセーブ無効時、`SaveLoadEnabled=false` では何もしない。
- 再生 VRT やベンチはオートセーブの副作用でセーブファイルを書かない。
- Continue は手動と自動の全スロットから最新のデータを読み込む。

## 設計

### 契機は2つ。イベント駆動にする

ターン間隔でなく、ゲーム上の節目で保存する。毎フレームの判定も間隔の記録も要らず、契機の起きた
1点で `save` を呼ぶだけになる。

- **新規開始**: `DungeonState.OnStart` の `newGame != nil` の分岐で `save` する。ロード復帰では
  `newGame` が nil なので保存しない。
- **入眠**: 睡眠プロンプトの Sleep 選択肢が `activity.Execute(NewSleepActivity())` に成功した直後に
  `save` する。入眠可否は `SleepBehavior.Validate` すなわち `EvaluateSleepConditions` が安全・気温・
  疲労で保証しているので、ここは検証済みのチェックポイントになる。

### autoSaver が保存機構を所有する

`SerializationManager` を `Resources` に置くと `save → world → resources → save` の import 循環に
なる。`systems`/`maingame` も `save.test → vrt → systems/maingame → save` のテスト循環になる。
`states` は `save` を既に import しており循環しないので、`internal/states/autosave.go` に置き、
`DungeonState` が所有して契機の箇所から呼ぶ。

```go
// autoSaver は SerializationManager を1つ所有し、セーブ無効や再生、生成失敗のときは何もしない。
type autoSaver struct {
	manager *save.SerializationManager // nil なら no-op
}

func newAutoSaver(world w.World) *autoSaver {
	if !world.Resources.Config.SaveLoadEnabled || world.Resources.Config.DisableAutoSave {
		return &autoSaver{}
	}
	m, err := save.NewSerializationManager()
	if err != nil {
		logger.New(logger.CategorySave).Warn("autosave: failed to init manager", "error", err.Error())
		return &autoSaver{}
	}
	return &autoSaver{manager: m}
}

// save は現在のワールドをオートセーブする。契機は呼び出し側が持つ。失敗はログに残すだけにする。
func (a *autoSaver) save(world w.World) {
	if a.manager == nil {
		return
	}
	if err := a.manager.AutoSave(world); err != nil {
		logger.New(logger.CategorySave).Warn("autosave failed", "error", err.Error())
	}
}
```

### 再生時は書かない

VRT とベンチも入眠や新規開始を通ると副作用でセーブを書いてしまう。全ての再生は
`vrt.InitReplayWorld` を単一の入口として通るので、そこで config の `DisableAutoSave` を立て、
`newAutoSaver` がこれを見て no-op になる。`SaveLoadEnabled` を落とすと Load や Save のメニュー
項目が消えて別の golden とシナリオが壊れるため、UI に影響しない専用フラグにする。

### Continue のロード対象を広げる

`ResumeFromLatestSave` は `ListSaves()[0]` を読む。`ListSaves` は手動と自動を混ぜてタイムスタンプ降順で
返すので、全スロットから最新になる。

## なぜこの形か

- **イベント駆動にする**: 新規開始と入眠という節目で保存すれば、間隔の記録や毎フレームの判定が要らず
  契機の1点で `save` を呼ぶだけになる。ターン間隔は「いつ保存されるか」がプレイヤーから見えにくいが、
  入眠は明示的な行動で、そこに復帰点が生まれるのは直感的。
- **入眠時に保存する**: 入眠は `Validate` が安全・気温・疲労を保証した瞬間で、安全地帯での休息に相当
  する。survival の「睡眠は都度の仮拠点」という位置づけと合う。
- **autoSaver を states に置く**: import 循環を避けつつ、契機の起きる `DungeonState` から呼べる。
- **再生の抑止は `DisableAutoSave`**: `SaveLoadEnabled` を落とすと UI が変わり golden が壊れる。UI に
  影響しない専用フラグを全再生の入口 `InitReplayWorld` で立てる。
- **Continue は `ListSaves`**: 最新の復帰点が手動か自動かに依らず一番新しいものを読むのが期待。

## 採用しなかった方法

- **一定ターンごとに保存する**: 間隔の記録 `LastAutoSaveTurn` と毎フレームの経過判定、fast-forward 中の
  抑止が要る。保存タイミングがプレイヤーに見えず、機構も重い。ゲーム上の節目で保存するほうが単純。
- **`Resources`/`systems`/`maingame` に保存機構を持たせる**: いずれも import 循環。`states` に置く。
- **入眠でなく起床時に保存する**: 起床は活動システム内の完了契機で、states から観測するにはフレーム跨ぎの
  差分検出が要る。入眠は選択肢の1点で拾えるので単純。中断された睡眠でも入眠時点の復帰点は残る。
- **再生抑止に `SaveLoadEnabled=false` や `InputSource!=nil`**: 前者は UI を変え、後者は単フレーム golden を
  取りこぼす。全再生が通る `InitReplayWorld` のフラグにする。

## リスク・影響範囲

- 未リリースなのでセーブ後方互換は考慮不要。
- 保存契機が入眠と新規開始に限られるので、長時間眠らずに進めるとその間は復帰点が増えない。必要なら
  手動セーブで補う。頻度を上げたくなったら別の節目を契機に足す。
