# 北進サバイバル。寒冷勾配・深部施設・キューブ修理でクリアする

## 背景

現状は worldstream が東西へ無限ストリーミング・南北を rows で有界とする帯で、進行軸は東。だが東進に意味づけが無く、世界に終点も勝利条件も無い。プレイヤーは「何を目指すのか」が分からず、ゲームとして完結しない。

ゲームの目的を次に定める。

> あなたは宇宙トラベラー。汎用個人船「キューブ」が故障し、極寒の惑星に墜落した。北へ進むほど寒さは厳しくなる。深部の極寒地帯には施設が残っており、そこで得たアイテムや設備でキューブを修理し、惑星から脱出＝クリアする。

進行軸を東から北へ回すことで、「北ほど寒い」という直感的な難易度勾配と、「北極に近い極寒地帯の施設を目指す」という目的が自然に説明できる。

## 要件

1. worldstream の無限進行軸を東から北へ回す。南北が無限、東西が有界になる。
2. 北進距離が増えるほど周囲気温が下がる緯度勾配を気温計算に加える。
3. 北進距離が一定しきい値を超えた深部でのみ施設が出現し始める。
4. 施設で得たアイテムや設備でキューブの修理を進められる。
5. キューブの修理が完了したら脱出でき、クリアとなる。
6. オープニングの進路説明を「東」から「北」へ更新する。

## 設計

### 進行軸の反転

`internal/worldstream/band.go` の無限軸を北へ回す。現在の `eastIndex`／東端生成・西端破棄・リベースを、北端生成・南端破棄へ置き換える。帯の抽象は「一軸無限・他軸有界」で方向非依存なので、無限軸と有界軸を入れ替える形になる。

```go
// 変更前: 東西無限・南北有界。変更後: 南北無限・東西有界。
// eastIndex（東進チャンク数）は northIndex（北進チャンク数）へ。
// ShiftEast 相当を ShiftNorth に、有界軸は cols(東西) が rows(南北) の役割を担う。
type Band struct {
	chunkW, chunkH consts.Tile
	cols, rows     consts.Chunk // 有界軸=東西(cols)、無限軸=南北(rows 方向へ流す)
	northIndex     consts.Chunk // 北進したチャンク数。帯南端チャンクの絶対インデックス
}
```

座標・カメラ・ミニマップ・道路・セーブ（`northIndex`）が北進前提へ追随する。生成は runSeed とチャンク座標の純関数のままにする。

### 寒冷の緯度勾配

`query.AmbientTemperatureAt` へ北進距離ベースの項を足す。現状の式は ステージ基準 + 季節/時間 + タイル遮蔽 + 焚き火熱 で、緯度勾配が無い。

```go
// 北進距離 northDist（絶対タイル）が増えるほど気温を下げる。coldPerTile は勾配の急さ。
// baseTemp + shelteredWorldTemp + tileModifier + ambientHeat - latitudeCold(northDist)
func latitudeCold(northDist consts.Tile) int // = northDist * coldPerTile を上限付きで返す
```

### 深部での施設出現

overworld 生成に「北進距離がしきい値以深のチャンクにだけ施設種を出す」規則を足す。しきい値までは寒さが増すだけで施設は出ず、深部で救済/目的地としての施設が現れる。

```go
// 北進距離 northDist がしきい値以上のチャンクでのみ施設を配置対象にする。
const facilityNorthThreshold consts.Tile = 0 // TBD: 実プレイで調整

func facilityAllowedAt(northDist consts.Tile) bool { return northDist >= facilityNorthThreshold }
```

### キューブ修理

キューブの修理進捗を持つコンポーネントを新設する。施設で得たアイテムや設備で進捗を進める。

```go
// CubeRepair はキューブ修理の進捗。必要素材が揃い進捗が満ちると修理完了。
type CubeRepair struct {
	Progress int // 現在の修理進捗
	Required int // 完了に要する進捗
}
```

コンポーネント追加は add-component の手順（登録表 + make generate + serde 判断）に従う。

### クリア判定

修理完了で脱出可能になり、クリア状態へ遷移する。既存の撤退/クリア機構（docs の「クリア時ボーナス通貨」）と接続するかは要検討。

## 採用しなかった方法

- **B. 有限の緯度世界**（南=温暖・開始 → 北=北極点=施設=脱出の有限マップ）。「北極点＝固定終点」を素直に実装できるが、無限ストリーミングの帯機構を丸ごと捨てる最大の改修になる。深部施設でAでもゴールが成立するため不採用。
- **C. 別案としての北ストリーミング＋しきい値ゴール**。本設計Aが「深部で施設が出現」を含むので、実質Aに統合された。
