# 北進サバイバル。寒冷勾配・深部施設・キューブ修理でクリアする

## 背景

現状は worldstream が東西へ無限ストリーミング・南北を rows で有界とする帯で、進行軸は東。だが東進に意味づけが無く、世界に終点も勝利条件も無い。プレイヤーは「何を目指すのか」が分からず、ゲームとして完結しない。

ゲームの目的を次に定める。

> あなたは宇宙トラベラー。汎用個人船「キューブ」が故障し、極寒の惑星に墜落した。北へ進むほど寒さは厳しくなる。深部の極寒地帯には施設が残っており、そこで得たアイテムや設備でキューブを修理し、惑星から脱出＝クリアする。

進行軸を東から北へ回すことで、「北ほど寒い」という直感的な難易度勾配と、「北極に近い極寒地帯の施設を目指す」という目的が自然に説明できる。

## 要件

1. 進行の奥行きを「北/奥地」として物語と方位表示で示す。物理ストリーミング軸は東のまま保つ。
2. 奥へ進んだ距離が増えるほど周囲気温が下がる緯度勾配を気温計算に加える。
3. 奥へ進んだ距離が一定しきい値を超えた深部でのみ施設が出現し始める。
4. 施設で得たアイテムや設備でキューブの修理を進められる。
5. キューブの修理が完了したら脱出でき、クリアとなる。
6. オープニングの進路説明を「東」から「北」へ更新する。

要件1は当初 worldstream の無限軸を物理的に東から北へ回す案だったが、ストリーミング核は東で実績があり、
気温勾配・施設・修理・クリアはいずれも「奥へ進んだ距離」だけに依存し進行の物理方向に依らない。
物理反転はストリーミング核・カメラ・ミニマップ・セーブ項目改名・VRT golden を広範に書き換える最大の
改修で、買えるのは「上キーで進む」直感だけになる。そこで物理軸は東のまま保ち、方向は方位表示と
物語で北と示す低リスク案を採る。物理反転は後日の任意ポリッシュに回す。

## 設計

### 進行方向の提示

物理ストリーミング軸は東のまま保つ。プレイヤーの進行の奥行きは無限軸の絶対距離、すなわち
`SeamlessBand.EastIndex` 由来の距離で測る。これを物語と方位表示で「北/奥地」と示す。band.go・
セーブ・カメラ・VRT golden には手を入れない。

### 寒冷の緯度勾配

`query.AmbientTemperatureAt` へ奥行き距離ベースの項を足す。現状の式は ステージ基準 + 季節/時間 +
タイル遮蔽 + 焚き火熱 で、緯度勾配が無い。実装済み。

```go
// 奥地ほど寒い緯度勾配を世界温度に折り込む。屋内は shelteredWorldTemp で緩和され、
// 深部の施設が暖を取れる避難所になる。末尾で引くと屋内外が同じだけ寒くなり避難所にならない。
// worldTemp = 季節 + 時間帯 - latitudeCold(world, x)
const (
	latitudeColdPerChunk = 1  // 1チャンク奥へ進むごとに下がる℃
	latitudeColdMax      = 40 // 下げ幅の上限
)

// 起点は初期帯の中央列 cols/2。開始地点を穏やかに保ち、緯度勾配は「そこからさらに奥ほど寒い」加算分。
// 絶対軸 X で測るので帯シフトをまたいでも連続で、シフトの瞬間に気温が飛ばない。
func latitudeCold(world w.World, x consts.Tile) int
func latitudeColdForDepth(chunksDeep int) int // 単調増加し latitudeColdMax で頭打ち
```

### 深部での施設出現

overworld 生成に「北進距離がしきい値以深のチャンクにだけ施設種を出す」規則を足す。しきい値までは寒さが増すだけで施設は出ず、深部で救済/目的地としての施設が現れる。

```go
// 北進距離 northDist がしきい値以上のチャンクでのみ施設を配置対象にする。
const facilityNorthThreshold consts.Tile = 0 // TBD: 実プレイで調整

func facilityAllowedAt(northDist consts.Tile) bool { return northDist >= facilityNorthThreshold }
```

### キューブ修理

キューブの修理進捗を持つコンポーネントを新設する。施設で得たアイテムや設備で進捗を進める。

```go
// CubeRepair はキューブ修理の進捗。必要素材が揃い進捗が満ちると修理完了。
type CubeRepair struct {
	Progress int // 現在の修理進捗
	Required int // 完了に要する進捗
}
```

コンポーネント追加は add-component の手順（登録表 + make generate + serde 判断）に従う。

### クリア判定

修理完了で脱出可能になり、クリア状態へ遷移する。既存の撤退/クリア機構（docs の「クリア時ボーナス通貨」）と接続するかは要検討。

## 採用しなかった方法

- **物理的な軸反転**（無限軸を東→北へ回し、上キーで進む直感を得る）。band.go のストリーミング核・カメラ・ミニマップ・セーブ項目改名・VRT golden を広範に書き換える最大かつ最risky な改修。ゲーム内容は進行の物理方向に依らないため、買えるのは操作の直感だけ。低リスクな提示のみの案を採り、物理反転は後日の任意ポリッシュに回す。
- **B. 有限の緯度世界**（南=温暖・開始 → 北=北極点=施設=脱出の有限マップ）。「北極点＝固定終点」を素直に実装できるが、無限ストリーミングの帯機構を丸ごと捨てる最大の改修になる。深部施設でAでもゴールが成立するため不採用。
- **C. 別案としての北ストリーミング＋しきい値ゴール**。本設計Aが「深部で施設が出現」を含むので、実質Aに統合された。
