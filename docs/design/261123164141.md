# 道を先に通し、場所を道につなぐ

## 背景

地上の道は、隣り合うリージョンで当選した集落どうしを結ぶ線として決まる。区域・墜落現場・点在ランドマークは道の行き先でなく、道がぶつかると避けるか途切れる。場所を先に置き、後から引いた道で場所の間を埋める作りなので、どの場所が道につながるかは配置の偶然で決まる。

この作りで次の不具合が続いた。

- 集落のチャンクの中心に施設を置いたため、道の突き当たりや道の上に家が建つ
- 道をチャンクの境目に通すと、区域の外周の塀と通りに道が掛かり、道の幅が欠けて塀が道の上に立つ
- 道をチャンク単位で通し、道のチャンクを他の地物と分けると重なりは消えるが、区域で道が途切れ、多くの場所が道とつながらない
- 地図では区域の中に道の線を描くが、区域の中は道を舗装しないので、地図と地面が食い違う

重ならないことは場所ごとの排他で守れるが、つながることは道の網全体で守る必要がある。チャンクごとに周りから自分の中身を割り出す作りでは、網全体の性質を守れない。

## 要件

- 区域・集落・墜落現場は、どれも道につながる
- 道と施設・区域の塀は重ならない。1チャンクの持ち主は1つにする
- 道は南北にどこまでも続き、北へ進むほど新しい場所に出会う
- 道と場所の置き方は位置の純関数のままにする。どのチャンクから生成しても同じ道と場所になり、地図は生成せずに描ける
- 地図に描く道と舗装する道は同じ計算から出す
- 点在ランドマークは景色の脇役なので、道につながらなくてよい

## 設計

地上を南北に計画区間へ分け、計画区間ごとに場所と道を一度に計画する。計画区間の計画は計画区間の番号と seed の純関数なので、どのチャンクから引いても同じ計画になる。計画は覚えておき、同じ計画区間を二度計画しない。

### 計画区間

計画区間は raw の道の表 `road` の `spanRows` 行 × 全列。計画区間 k は行 `[k*spanRows, (k+1)*spanRows)` を持つ。道のタイル・幅・計画区間の行数は、集落の地物の行でなく、raw の最上位の表 `road` に置く。計画区間の行数が集落のリージョンの行数で割り切れることは、CUE の制約 `roadSpanRows_divisible` で確かめる。プレイヤーは北へ進み戻らないので、計画区間どうしは南北の境目だけで道を引き継ぐ。

### 計画区間の境目の通り道

計画区間の境目の行 b で道が越える列を、b と seed の純関数で決める。境目の両側のチャンクがどちらも区域でも墜落現場でもない列から引く。区域が境目をまたぐなら、その区域の門と通りが通り道になり、列は引かない。境目の通り道は両側の計画区間の計画が同じ値を引くので、計画区間をまたいで道が途切れない。

### 計画の順

1. 区域と墜落現場を置く。区域の置き方は今と同じで、計画区間と重なる区域を集める
2. 道の行き先を点として集める。計画区間の北と南の境目の通り道、区域の北と南の門の外のチャンク、墜落現場の北と南の隣のチャンク
3. 行き先を1つずつ網へ加える。網に近い行き先から順に、チャンク単位の経路探索で網へつなぐ。区域と墜落現場のチャンクは通れない。曲がるごとに費用を足し、まっすぐな道を好む。区域は門の1つが網につながれば、通りでもう1つの門もつながったものとして扱う
4. 集落を置く。集落のリージョンごとに、道のチャンクに接する空いたチャンクから1つを引く。道のチャンクから集落の側へ出入り口を足し、施設は扉が道の側を向く向きから引く
5. 点在ランドマークは、道・集落・区域・墜落現場の無いチャンクにだけ置く

### 道の形

道はチャンク単位の経路で表す。経路が通るチャンクは道のチャンクで、他の地物を置かない。チャンクの縁を道が越える所を出入り口と呼び、出入り口ごとに縁に沿った道の位置を持つ。普通は縁の中央で、区域の門に面する縁だけ門の通りの位置にする。道のチャンクの中は、各出入り口からチャンクの中心までを幅 `road.Width` で舗装する。

```go
// roadPort は道のチャンクの縁を道が越える所。lane は縁に沿った位置で、チャンク内の座標
type roadPort struct {
	dir  RoadDir
	lane consts.Tile
}

// roadPlan は計画区間1つの計画。道のチャンクと集落のチャンクを持つ
type roadPlan struct {
	roads       map[consts.Coord[consts.Chunk]][]roadPort
	settlements map[consts.Coord[consts.Chunk]]RoadDir // 集落と、道のある側
}

// planAt は c の行を持つ計画区間の計画を返す。計画区間ごとに一度だけ計画し、覚えておく
func planAt(raws rawschema.Raws, runSeed uint64, c consts.Coord[consts.Chunk], cols, spawnRow consts.Chunk) *roadPlan
```

### チャンクの種類の優先

墜落現場 > 市街地 > 道 > 集落 > 点在ランドマーク > 荒れ地。道と集落は計画から引き、重ならない。

### 横幅

地上の列を7から9へ増やす。区域が並んでも、経路が回り込む余地を作る。

### 地図

地図の道の線は計画の出入り口から引く。区域の中は区域の通りなので線を引かない。舗装と同じ計画なので食い違わない。

## 採用しなかった方法

- 集落どうしを結び、ぶつかる所を避ける作り。つながるかが配置の偶然で決まる
- チャンクごとに前後の区域から幹線と枝道を割り出す作り。区域が同じ行に並ぶ場合や枝道が他の場所にぶつかる場合ごとに規則が増え、網全体のつながりを守れない
- 道をチャンクの境目に通す。施設の余白には収まるが、区域は外周の端まで塀と通りを置くので、道と重なる
- 全ての地物がチャンクの外周を空ける。区域の塀と通りの並びを作り直す必要がある

## コメント

- 地図の計画区間を丸ごと計画し、場所を置いてから行き先を近い順に網へつなぎ、後から置く場所を道に接する所へ置く流れは、Cataclysm: Dark Days Ahead の地上地図の生成を参考にした
- 種類の違う区域どうし、区域と墜落現場の間には1チャンクの隙間を必ず空ける。区域の幅は帯の幅より狭いので、区域の外がひと続きになり、どの行き先にも経路がある。区域が隙間なく接すると、門の外が隣の区域になって網から切れた
- 9列にしたことで、開始から通信施設までの距離は seed 300個で中央値22、95%で44、最大79チャンクになった。確かめる範囲を seed 100個の全てで70チャンク以内にした
- 区域の中で北の門と南の門が通りでつながることを前提にする
- 集落はリージョンごとに道に接するチャンクから1つ引くので、raw の集落の行の `separation` は使わない。リージョンの境目の行どうしで集落が隣り合うことがある
- 集落の施設の向きを扉で絞るので、扉の無い絵は集落に使えない。今は全ての集落の絵が扉を持つことをテストで確かめている
