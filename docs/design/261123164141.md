# 道を先に通し、場所を道につなぐ

## 背景

地上の道は、隣り合うリージョンで当選した集落どうしを結ぶ線として決まる。区域・墜落現場・点在ランドマークは道の行き先でなく、道がぶつかると避けるか途切れる。場所を先に置き、後から引いた道で場所の間を埋める作りなので、どの場所が道につながるかは配置の偶然で決まる。

この作りで次の不具合が続いた。

- 集落のチャンクの中心に施設を置いたため、道の突き当たりや道の上に家が建つ
- 道をチャンクの境目に通すと、区域の外周の塀と通りに道が掛かり、道の幅が欠けて塀が道の上に立つ
- 道をチャンク単位で通し、道のチャンクを他の地物と分けると重なりは消えるが、区域で道が途切れ、集落とも約10マス離れ、多くの場所が道とつながらない
- 地図では区域の中に道の線を描くが、区域の中は道を舗装しないので、地図と地面が食い違う

重ならないことは場所ごとの排他で守れるが、つながることは道の網全体で守る必要がある。場所から道を導く作りでは、つながることが構造上保証されない。

## 要件

- 区域・集落・墜落現場は、どれも道につながる
- 道と施設・区域の塀は重ならない。1チャンクの持ち主は1つにする
- 道は南北にどこまでも続き、北へ進むほど新しい場所に出会う
- 道と場所の置き方は位置の純関数のままにする。どのチャンクから生成しても同じ道と場所になり、地図は生成せずに描ける
- 地図に描く道と舗装する道は同じ計算から出す
- 点在ランドマークは景色の脇役なので、道につながらなくてよい

## 設計

道を先に決め、場所を道に付ける。

### 幹線

幹線は帯を南北に貫く1本の道。基本は開始チャンクの列 `cols/2` をまっすぐ通る。

- 区域が幹線の列を塞ぐ所では、区域の手前の行で区域の北の門の列へ折れ、門から区域へ入る。区域の中は区域の通りが北の門から南の門へつなぐ。南の門から出て、区域の向こうの行で幹線の列へ戻る
- 墜落現場は幹線の列にあるので、幹線は墜落現場のチャンクの北と南の縁まで来て止まる。墜落現場の絵はチャンクの中央にあり、縁まで道が届けば墜落現場につながる

### 枝道

幹線の列に掛からない区域へは、区域の手前の行で幹線から横へ枝道を出し、北の門の列で区域へ入る。

### 集落

集落の置き方を、道に付ける形へ変える。集落のリージョンごとに、リージョンの行の中の幹線のチャンクから1つを引き、その東か西の隣を集落のチャンクにする。幹線のチャンクから集落の側の縁へ短い枝道を出す。施設の絵は、扉が枝道の側を向く向きだけから引く。

### 道の形

道はチャンク単位の経路で表す。経路が通るチャンクは道のチャンクで、他の地物を置かない。チャンクの縁を道が越える所を出入り口と呼び、出入り口ごとに道が通る列か行を持つ。普通は縁の中央で、区域の門に面する縁だけ門の通りの位置にする。道のチャンクの中は、各出入り口からチャンクの中心までを幅 `road.Width` で舗装する。

```go
// roadPort は道のチャンクの縁を道が越える所。lane は縁に沿った位置で、チャンク内の座標
type roadPort struct {
	dir  RoadDir     // どの縁か
	lane consts.Tile // 縁の中央なら chunkW/2、区域の門に面するなら門の通りの真ん中
}

// roadChunk は道のチャンク1つの中身。舗装と地図の線の唯一の出典
type roadChunk struct {
	ports []roadPort
	road  rawschema.Road
}

// roadChunkAt は c が道のチャンクなら中身を返す。位置の純関数で、生成しない
func roadChunkAt(raws rawschema.Raws, runSeed uint64, c consts.Coord[consts.Chunk], cols, spawnRow consts.Chunk) (roadChunk, bool)
```

幹線の経路は、c の行の前後の区域だけを見れば決まる。

```go
// trunkStop は幹線が立ち寄る区域。幹線の列を塞ぐ区域は通り抜け、塞がない区域へは枝道を出す
type trunkStop struct {
	region        districtRegion
	north, south  consts.Chunk // 北と南の門の列
	onTrunkColumn bool         // 幹線の列を塞ぐなら true
}

// trunkStopsAround は行 y の前後で幹線が立ち寄る区域を、北から順に返す。区域の種類ごとのリージョンの大きさの範囲だけを見る
func trunkStopsAround(raws rawschema.Raws, runSeed uint64, y, cols, spawnRow consts.Chunk) []trunkStop
```

### チャンクの種類の優先

墜落現場 > 市街地 > 道 > 集落 > 点在ランドマーク > 荒れ地。集落は道の脇にだけ置くので、道と集落は重ならない。道が点在ランドマークの当選と重なれば道を優先する。

### 地図

地図の道の線は `roadChunkAt` の出入り口から引く。区域の中は区域の通りなので線を引かない。舗装と同じ計算なので食い違わない。

## 採用しなかった方法

- 集落どうしを結び、ぶつかる所を避ける今の作り。つながるかが配置の偶然で決まる
- 場所を先に置き、全ての行き先をチャンク単位の探索で結ぶ。今の置き方を活かせるが、探索の結果が隣のチャンクの種類に依存し、計算が重い。行き止まりや遠回りが残りうる
- 道をチャンクの境目に通す。施設の余白には収まるが、区域は外周の端まで塀と通りを置くので、道と重なる
- 案 A に門への迂回と集落への引き込み道を足す。集落どうしを結ぶ経路が区域や他の集落にぶつかる場合ごとに例外が増える

## コメント

- 区域どうしが同じ行に並ぶと、幹線の列を塞がない方へは枝道でつなぐ。枝道が別の区域にぶつかる場合の扱いは実装で確かめる
- 区域の中で北の門と南の門が通りでつながることを前提にする。前提が崩れる区域の形があれば、テストで見つける
- 集落の施設の向きを扉で絞るので、扉の無い絵は集落に使えない。今は全ての集落の絵が扉を持つことをテストで確かめている
