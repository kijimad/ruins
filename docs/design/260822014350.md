# 逓増: 危険と希少性の軸を深さから経過日数へ移す

## 背景

危険と希少性の軸を、深さから経過日数へ移す。現状の難易度軸は深さ `Depth` で、`raw.go` の spawn テーブルが `MinDepth`/`MaxDepth` でエントリをゲートし、`consts.GameClearDepth` がクリア判定に使われている。これは旧ダンジョン潜降型の軸で、縦へ深く潜るほど難しくなる。ruins は縦深より横広の1世界を主軸にするので、この軸を**経過日数**へ移す。日が経つほど危険と報酬が増す。

当初は前進距離と経過日数の2軸を検討したが、留まれない世界では時間の経過が前進とほぼ等しく、距離は日数の焼き直しになる。詳細は採用しなかった方法に記す。時間だけを軸にし、前進の空間勾配は時間と移動が結合することで体感として立てる。

将来方針としても深さは廃していく。オーバーワールドを主軸に、縦の depth 層は過渡的なものとして扱う。

## 要件

**Hard**

- 危険と希少性は経過日数の関数で決まる。`Depth` を軸に使わない。
- 危険度は決定論の純関数で出す。保存状態を増やさない。
- spawn テーブルのゲートを危険度基準へ移す。敵の強さ・数・アイテムの希少度が日数で変わる。
- `consts.GameClearDepth` を退役させる。クリア判定は廃し、run は終端 doc `260822014348` の死の終端で締まる。生還は当面無い。

**Soft**

- 日が経つほど良い物が出る。危険と報酬が同じ軸で伸び、長く生き延びる賭けが成立する。
- 留まれない世界なので、日数の経過は東への前進とほぼ等しい。時間の危険度が、体感としては奥ほど危険という空間勾配を生む。
- 危険は施設の種別と雰囲気で伝わる。軍事施設のような場所や荒れた景観が危険を示し、数値では読ませない。

**Anti**

- 距離を軸に足さない。時間と移動が結合するので距離は冗長になり、二重計上と座標の綱渡りを招く。
- 深さと距離の二軸を併用しない。旧軸の綱引きを温存しない。
- プレイヤーレベルへの動的スケーリングをしない。世界の危険は時間で決まり、育成の意味を守る。
- 危険度を数値で表示しない。危険は施設種別と雰囲気で diegetic に伝える。

## 設計

### 危険度の純関数

```go
// DangerLevel は経過日数から危険度を返す純関数。
// 単調非減少で、同じ入力は常に同じ危険度を返す
func DangerLevel(days int) int

// DangerLevelAt は world から経過日数を引いて DangerLevel を呼ぶラッパー
func DangerLevelAt(world w.World) int
```

時間だけを軸にする。ruins は資源が枯れ暖が減り左に戻れない世界で、留まれず東へ進み続けるほかない。時間を進めることが前進とほぼ等しいので、`DangerLevel(days)` でも体感は奥ほど危険になる。距離を式に入れると、結合済みの同じ進行を二重に数えるだけで、遺跡内では帯が引けないため入口の絶対Xを捕まえて配る座標の綱渡りも要る。時間一軸はこれらを避ける。配合比とカーブは実測で決める。

### spawn テーブルの移行

`raw.go` のゲートを深さから危険度へ移す。スキーマは tsp が源泉なので、`ruins-tsp` の手順で変更する。

```
変更前: minDepth / maxDepth  でエントリをゲート
変更後: minDanger / maxDanger でエントリをゲート
```

`PlannerType` と `MetaPlan` の湧きゲート入力を `Depth` から `Danger` へ改める。ダンジョンは入場時の経過日数から危険度を確定し、全階へ配る。階を降りても変わらない。overworld の敵と loot は生成時の経過日数で引く。raw.toml は全 entry が `minDanger>=1` の1始まり設計なので、spawn 境界で危険度を最小1にクランプし、序盤でも最も浅い湧きが出るようにする。

### 退役

- `consts.GameClearDepth` を削除する。参照点はクリア判定で、終端 doc の死の終端へ置き換わる。run は死で終わり生還は当面無い。
- `DungeonState.Depth` は当面残る。ダンジョン内の階層識別としての深さは残り、**難易度軸としての参照だけを外す**。全廃は縦深の扱いを決める将来 doc に委ねる。

### 危険は施設の種別と雰囲気で伝える

危険度は内部値に留め、数値では見せない。プレイヤーは**どんな場所か**と**中身の手強さ**で危険を読む。危険度は2つの効き方をする。

- **同じ施設でも中身が日数で難化する**。建物 loot とダンジョンの敵は生成時の経過日数で引くので、日が進むほど希少で手強くなる。これは実装済み。
- **出現する施設の種別が日数で変わる**。軍事施設のような高危険の場所が後半ほど出やすくなる。ただし施設種別の配置は地図表示と生成の両方が呼ぶ純関数で、両者が一致する必要がある。日数を入れると、生成した日と地図を開いた日で表示が食い違う。整合のため、施設種別を生成時に焼き込み、地図は焼かれた実体を読み、未踏は霧にする機構が要る。この型の日数変化は続く作業に切り出す。

## 採用しなかった方法

- **前進距離と経過日数の二軸**。当初案で、距離を主・日数を従にした。却下。気候生存の設計 `260822220253` で世界を留まれないものにした結果、時間の経過が前進とほぼ等しくなり距離は日数の焼き直しになる。距離を式に残すと、遺跡内で帯が引けないため入口の絶対Xを捕まえて全階へ配る座標の綱渡りが要り、施設ゲートも距離で判定して複雑になる。時間一軸にするとこれらが丸ごと消え、体感の空間勾配は結合が生む。
- **距離だけを軸にする**。却下。同上の理由で距離は時間と冗長。かつ籠もりを罰する時間圧が出ない。
- **深さと距離の二軸併用**。却下。旧軸が残ると spawn 定義が二重になり新旧の綱引きを温存する。
- **プレイヤーレベルへの動的スケーリング**。却下。世界の危険が育成に追随すると、強くなる意味と場所の個性が消える。
- **危険度を数値で表示する**。却下。ゲームっぽく没入を削ぐ。危険は施設種別と、中身の手強さと、荒れた景観や雰囲気で伝えるほうが、探索の読みが世界の観察になる。
- **施設種別を日数で変えるとき純関数のまま日数を混ぜる**。却下。地図表示と生成が同じ座標で違う日数を見て食い違う。焼き込みと霧で整合させる。

## コメント

日数あたりの危険の伸びとカーブ、危険帯の刻みは実測で決める。移行の機械置換では体感を変えないことを優先し、危険の伸びの調整は実プレイで行う。施設種別の日数変化は地図の焼き込みと霧の機構を伴うので、続く作業として切り出す。
