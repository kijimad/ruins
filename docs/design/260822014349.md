# 経済: 行商人と遠隔注文で金を前方へ流す

## 背景

マクロループ設計 `260821223229` の③経済を詳細化する。売りは通信販売 `260814170822` で実装済みで、タグ貼付から出荷・集金まで回る。欠けているのは買いの向きで、金が前進の糧へ消える閉環が無い。

コードで確認済みの前提: `ShopMenuState` は固定の拠点 State ではない。`NewShopMenuState(merchant ecs.Entity)` が商人エンティティの在庫を読み、会話から開く。つまり「戻れる固定拠点」になるかは商人の配置だけで決まり、State の作り直しは要らない。

不変条件はビジョン doc `260813235334` の Anti を継承する。戻る固定市場を作らない。代金を安全へ貯めさせず前方の一歩へ消費させる。

## 要件

**Hard**

- 戻って会える固定配置の商人を無くす。買いの機会は前方にだけある。
- 金の使い道は前進の糧に向く。薬・食料・燃料・弾・装備。
- 売りの通販と買いが同じ世界観で繋がる。注文は遠隔で届き、受け取りは歩く世界の中で起きる。
- 既存の `ShopMenuState`・`BuyPrice` の仕組みを再利用する。買いの機構を二重に作らない。

**Soft**

- 受け取りまでのリードタイムが計画の読みを生む。今注文して、次の駅で受け取る。
- 行商人との出会いが一期一会の彩りになる。品揃えに当たり外れがある。
- 出費が近視眼的な延命でなく、装備と備えという投資にもなる。

**Anti**

- 戻る固定市場・据え置きショップ拠点を作らない。
- その場で品が湧く即時購入にしない。遠隔注文は届くまで待つ。
- 貯金の利子や倉庫など、貯め込みを報いる装置を作らない。
- 買いの別 UI 体系を新設しない。既存のメニュー骨格に載せる。

## 設計

### 全体像: 買いの2チャンネル

買いは2つのチャンネルで提供し、どちらも「前方にしかない」構造にする。

1. **行商人**。世界に点在する商人エンティティ。既存の会話→`ShopMenuState` をそのまま使う。変えるのは配置だけで、プレイヤーと同じく前線に追われて東へ移ろう世界の住人にする。すれ違ったら次は無い。
2. **遠隔注文**。通販の買い側。カタログから注文し、前方の受取場所で受け取る。売りの出荷場所と同じ駅設備を受け取りにも使い、世界の中を歩いて取りに行く手触りを保つ。

### 行商人: 配置で Anti を満たす

商人の実装は変えない。配置データを変え、戻れない位置関係にする。プレイヤーの前方に散発的に湧き、前線が飲み込めば消える。同じ商人に二度会えないことは一方向性が保証するので、専用の管理は要らない。

### 遠隔注文: 通販の対称形

売りの通販と対称の買いを足す。データは注文1件を表す最小にする。

```go
// MailOrder は遠隔注文1件。注文時に代金を即時に払い、受取場所で品を受け取る
type MailOrder struct {
	RawID       string // 注文した品
	Count       int
	PlacedTurn  int // 注文したターン
	ArriveTurns int // 届くまでのリードタイム。注文時に確定する
}
```

- 注文は出荷場所の駅メニューに注文タブを足して行う。既存の `auction_menu.go` のタブ骨格に載せる。
- 代金は注文時に即時払い。これが金の sink であり、貯め込みを防ぐ即消費の実装になる。
- 品は `PlacedTurn + ArriveTurns` 以降、**前方の**受取場所で受け取れる。過ぎた駅では受け取れないので、注文は常に前進を前提にした投資になる。
- 価格は既存 `BuyPrice` を使い、遠隔の手数料を上乗せする。行商人より割高にし、行商人との出会いに価値を残す。

### カタログ

注文できる品は生存と前進の糧に絞る。薬・食料・燃料・弾・基本装備。豪華な品は行商人の当たり品に置き、遠隔は命綱、行商人は僥倖、と役割を分ける。カタログは `raw.toml` のフラグで指定する。

## 採用しなかった方法

- **固定拠点ショップを維持する**。却下。ビジョンの Anti「戻る固定市場を作らない」に反し、一方向逃避の緊張を殺す。
- **即時購入にする**。注文した品がその場で手に入る。却下。リードタイムと前方受け取りが「今の金で未来に備える」読みを作る。即時では単なる自販機になる。
- **買い専用の新 UI 体系を作る**。却下。駅メニューのタブ骨格と `ShopMenuState` が既にあり、二重の UI は保守を重くする。
- **通貨を廃して物々交換にする**。却下。売りの通販が通貨建てで完成しており、対称性を壊すと売買の読みが二重になる。

## コメント

リードタイムの長さ・遠隔手数料・行商人の出現密度は数値なので実プレイで測る。最初の実装は注文タブと受け取りだけの最小にし、カタログは薬と食料の数品から始める。

受取場所を過ぎた駅で受け取れない仕様は、注文が無駄になる失敗を許す。これは意図した緊張であり、救済を足すかは実プレイの手触りで決める。
