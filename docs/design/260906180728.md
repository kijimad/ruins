# 意識を master 乗数に戻し全出力を身体機能 funnel に一本化する

## 背景

疲労・空腹・怪我・病気を不調へ束ね、身体機能 BodyFuncs 経由で行動へ効かせるところまで来た。だが回復だけは
funnel に載らず量の直読みで、1つの need が「行動=不調経由・回復=直読み」の2経路に割れている。これが不整合。

方針として RimWorld 型に寄せる。RimWorld は need も怪我も Hediff に束ね、身体機能へオフセットし、Consciousness を
master 乗数として全出力へ掛ける。回復も同じ土俵で、栄養・休養が治癒速度に効く。ruins も同じく、全出力を身体機能
funnel の1経路にし、意識を master 乗数に戻す。回復も意識に載せる。

以前 `WithConsciousnessPenalty` を「ややこしい」として撤去したが、あれは算出済みの局所機能を後から比率で再スケール
する別関数だったのが問題だった。今回は `BodyFuncs` の導出の中で意識を一度だけ掛けるので、後付け再スケールは無い。
疲労・空腹は既に不調なので、master 乗数を導出へ戻すだけで need も怪我も自動で意識へ集約される。

## 要件

- 全出力(速度・命中・回復)を身体機能 funnel の1経路にする。回復の直読み専用パスを撤去する。
- Consciousness を master 乗数に戻す。局所機能 Manipulation・Moving・Sight は意識で乗算される。
- 怪我・病気が回復を鈍らせる自己参照を許容する。ただし整数切り捨てで治癒が完全停止しないよう、不調の治癒量は
  float で計算し停止を防ぐ。RimWorld が float で扱うのに倣う。
- 量 `Fatigue`・`Hunger` は真実として残す。不調は毎ターン導出。挙動変化と VRT golden 再生成を許容する。

## 設計

### 意識を master 乗数に戻す

`HealthStatus.BodyFuncs` の導出で、意識を全身性から出し、局所機能へ乗算する。疲労・空腹は不調として既に全身性へ
入っているので、追加の直読みは不要。

```go
consciousness := clamp(100-systemic-pain/painConsciousnessDivisor, 0, 100)
withConsciousness := func(local int) consts.Percent {
	return consts.Percent(clamp(local, 0, 100) * consciousness / 100)
}
return BodyFuncs{
	Pain: ..., Blood: ..., Consciousness: consts.Percent(consciousness),
	Manipulation: withConsciousness(100 - manip),
	Moving:       withConsciousness(100 - moving),
	Sight:        withConsciousness(100 - sight),
}
```

`EffectiveBodyFuncs` は全身性の加算畳み込みが不要になり、`HealthStatus.BodyFuncs`、非所持なら `HealthyBodyFuncs`、を
返す薄いラッパになる。消費側は従来どおり Moving・Manipulation・Sight を読むだけ。

### 回復を funnel へ載せる

`Metabolism` は実効意識を基準に、VIT と睡眠を足す。疲労・空腹・怪我・病気はすべて意識を通じて回復を鈍らせる。
量の直読みの `fatigueRecoveryPenalty`・`hungerRecoveryPenalty` を撤去する。

```go
rate := int(EffectiveBodyFuncs(world, entity).Consciousness) // 100 が健康。全 need・怪我で下がる
rate += VIT*coeff + 睡眠ボーナス
return max(rate, 0)
```

### 自己参照停止を float で防ぐ

不調の治癒は意識で鈍るが、`conditionTimerDelta` の治癒量を int 切り捨てから float へ改め、代謝が低くても
治癒が 0 で止まらないようにする。RimWorld が治癒を float 率で扱うのと同じ。HP の自然回復は整数のままでよい。
極度に不調なら回復しないのは自然で、停止でなく一時的な鈍化。

## 採用しなかった方法

- **CDDA 寄り**: need を中間層に通さず各出力へ名前付き加算で直接当てる。need と怪我は独立。回復の自己参照は
  構造から消えるが、master 乗数と funnel を捨てることになる。今回は funnel 一本化と意識の中心性を採る。
- **ハイブリッド維持**: 行動は不調経由・回復は直読み。1 need 2経路の不整合が残る。不採用。
- **回復を意識に載せるが float 化しない**: 整数切り捨てで治癒が停止する悪循環が残る。float で防ぐ。

## コメント

外部ツールを組織原理にはしない。RimWorld から借りるのは構造でなく原理、「need と怪我を同一の状態機構に束ね、
意識を全出力へ掛ける」。係数と master 乗数の掛かり方は実プレイで調整する。
