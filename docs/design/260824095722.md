# 熱源メカニクス: 焚き火をプレイヤーの体温へ直接効かせる

## 背景

温度モデルの土台 [260822220253](260822220253.md) は屋外の季節寒冷と屋内退避までを範囲にし、段階3 の焚き火を別作業として切り出した。この doc がその段階3 を引き取る。

温度 doc は当初、焚き火が既に周囲気温を上げているのをプレイヤーの体温へ移すと見込んでいた。だが実装を確認すると、焚き火 `bonfire` は光源 `LightSource` としてのみ存在し、温度システムには一切寄与していない。`TileTemperature` のフィールドは Shelter・Water・Foliage だけで熱源の項が無く、`getTileTemperatureAt` も `AmbientTemperatureAt` も熱源を参照しない。したがって段階3 は既存寄与の移し替えでなく、熱源から体温への暖房を新規に作る。

目指すのは、熱源のそばに居ると低体温がゆっくり回復する効果。屋外は寒さで体温を奪われるが、火を焚けば奪われを相殺できる。屋内は奪われが遅いので、同じ火でも回復が上回りやすい。この非対称が「寒い外では火でしのぎ、暖かい中ではより早く立て直す」というリズムを補強する。

## 要件

**Hard**

- 熱源は周囲気温を変えない。熱源のそばに居るキャラの低体温を毎ターン固定量回復する。周囲気温由来の奪われる速さとは別に効く。
- 熱源のもたらす回復量は屋内でも屋外でも同じ。屋内が得になる非対称は熱源側でなく、屋外のほうが周囲気温が低く奪われが速いことから創発させる。
- 熱源はデータ駆動で表す。任意の置物を熱源にできるよう、raw に熱源設定を持たせる。名前で分岐する特殊対処にしない。
- 熱源は近接だけで効く。熱源の座標からチェビシェフ距離で半径内のキャラに効く。半径は熱源ごとに持つ。
- 効果は既存の体温経路に載せる。低体温タイマー `HealthStatus` の全身部位 `BodyPartWholeBody` の `ConditionHypothermia` を回復方向へ動かす。凍傷や高体温の経路は変えない。

**Soft**

- 距離による減衰は持たない。半径内なら固定量、半径外なら効果なしの離散で始める。連続的な減衰が要るとわかったら後で足す。
- 複数の熱源が半径内にあれば回復量は加算する。火を重ねるほど暖かいという素直な挙動にする。

## 設計

### 熱源の表現はデータ駆動のコンポーネント

熱源は専用コンポーネント `HeatSource` で表す。光源 `LightSource` と同じく raw の置物設定に `heatSource` ブロックを足し、`lightSource` と対称にする。任意の置物を熱源にでき、名前による分岐を持たない。

光源を熱源に流用しない。光と熱は別の軸で、装備した携行光源が owner を照らす経路が既にある。光源を熱源に流用すると、トーチを持つだけで常時暖まるといった破綻が起きる。熱は独立の概念として別コンポーネントに分ける。

```go
// HeatSource は近接するキャラの低体温を毎ターン回復する熱源。
// 周囲気温は変えず、体温タイマーへ直接効く。回復量は屋内外で同じ。
type HeatSource struct {
	Radius consts.Tile // 熱の到達半径。チェビシェフ距離
	Warmth float64     // 毎ターンの低体温タイマー回復量
}
```

半径は熱の到達距離で、光の到達半径より小さく取る。火は遠くから見えても、暖まるには近づく必要がある。回復量は低体温タイマーを1ターンに下げる量。タイマーは0から100の float で、快適圏の自然回復が毎ターン 0.25、厳しい寒さの悪化が毎ターン 0.5 から 1.0 の刻みで動く。回復量もこの刻みに合わせた float にする。半径と回復量はいずれも実プレイで調整する初期値で、raw に置く。初期値は bonfire で半径1、回復量 0.5。

### raw と生成

raw の置物に熱源設定を足す。tsp の `Prop` モデルへ `heatSource` を足し、`HeatSource` モデルと `HeatRadius`・`HeatWarmth` のスカラーを定義する。`lightSource` と同じ構造にする。生成された `oapi.HeatSource` を `raw.go` の `toGCHeatSource` で `gc.HeatSource` へ写す。

```toml
# raw.toml の bonfire へ足す
[props.heatSource]
radius = 1
warmth = 0.5
```

`HeatSource` は永続コンポーネント。焚き火はワールドに配置され保存対象になるので、serde 除外には入れない。フィールドは int と float だけで serde 安全。エディタの save スキーマ整合のため、save.tsp にも `HeatSourceComponent` を `LightSourceComponent` と対称に足す。

### 効果は既存の体温経路へ

`TemperatureSystem.Update` は `HealthStatus` と `GridElement` を持つ全キャラを毎ターン舐め、`updateTemperatureConditions` で周囲気温と断熱から低体温を進める。熱源の回復はこの直後に足す。周囲気温由来の悪化を先に効かせ、次に熱源の回復を引く。両者は別々に効く。

```
1. updateTemperatureConditions: 周囲気温と断熱で低体温タイマーが進む
2. 熱源の回復: 半径内の熱源の Warmth 合計ぶん、低体温タイマーを下げる
```

回復は全身部位の `ConditionHypothermia` のタイマーを下げる。既存の `UpdateConditionTimer` に負の delta を渡せばタイマーが減り、0 で状態が自動的に消える。低体温の状態が無いときは回復するものが無いので何もしない。回復で Severity が変わったら、プレイヤーは既存の低体温更新と同じく `StatsChanged` を付け、ログを出す。

熱源の合算は、プレイヤー座標と各熱源の座標のチェビシェフ距離を測り、半径内の `Warmth` を足す。プレイヤーだけでなく敵も同じ経路で回復する。熱源のそばは誰でも暖かいという素直な挙動にする。

### 屋内外の非対称は創発させる

熱源の回復量は屋内外で同じにする。屋内が得になるのは、屋外のほうが周囲気温が低く `updateTemperatureConditions` の悪化が速いから。同じ回復量でも、悪化が緩い屋内では回復が上回りやすい。非対称を熱源側の条件分岐で作らず、周囲気温の差から自然に出す。これで「もたらす熱量は屋内外で同じ、奪われ方だけが屋内外で違う」という切り分けが保てる。

## 採用しなかった方法

- **光源 `LightSource` を熱源に流用する**。却下。光と熱は別軸で、携行光源で常時暖まるなどの破綻が起きる。熱は独立コンポーネントに分ける。
- **熱源設定を Go のテーブルに持つ**。却下。raw の `lightSource` と設定の置き場が分かれて非対称になる。データ駆動で raw に寄せ、置物追加だけで熱源にできるようにする。
- **熱源で周囲気温を上げる**。却下。周囲気温を上げる形だと火の恩恵が体温進行の式や断熱と絡み、屋内外の差が読みにくい。火は体温へ固定回復で直接効かせ、奪われる速さと分けて考えられるようにする。
- **距離で回復量を減衰させる**。却下。まずは半径内で固定、半径外で無効の離散で足りる。連続的な減衰が要るとわかったら後で足す。
- **熱源を Item にも持たせる**。見送り。携行熱源はまだ要らない。Prop だけに絞り、必要になったら Item へ広げる。

## コメント

- 熱源の回復量。屋外で焚いてやっと相殺、屋内で焚いて回復が上回る、という関係に収める。周囲気温の悪化速度と断熱との兼ね合いで実プレイ調整する。
- 熱源の半径。光の半径より小さく、そばに寄って初めて暖まる距離にする。
