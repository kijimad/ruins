# マップ生成の種類ごとの値を raw へ移す

## 背景

マップ生成の設計の指針は、生成の内容を TOML で表現でき、組み合わせやすいことである。コードには振る舞いの違う部品だけを持つ。地上の区域・施設・散布・ランドマークはこの形になったが、マップ生成まわりを洗うと、種類ごとの値がまだ Go に残っている。

- 地上: 集落・遺跡の入口・ランドマークの間隔、集落を結ぶ道のタイルと幅、区域の塀の家具、屋外の戦利品の密度、遺跡の入口が選ぶダンジョン、街路の敵の数。参考 codebase: `internal/overworld/feature.go:85`、`urban.go:238`、`road.go:81`、`loot_scatter.go:23`、`dungeon_entrance.go:32`、`urban.go:321`。
- ダンジョン: raw の `[[dungeons]]` が選べるのは間取りの列挙5つだけで、各間取りの数値とタイルは Go の関数に固定されている。参考 codebase: `internal/mapplanner/lib.go`、`cave_planner.go`、`forest_planner.go`、`ruins_planner.go`、`rect_room.go`、`big_room.go`。
- 周辺: フロアの敵と品目の数、デバッグ用のダンジョンの定義、デバッグの町の中身。参考 codebase: `internal/consts/consts.go:99`、`internal/dungeon/registry.go`、`internal/states/dungeon_floor.go:112`。

## 要件

1. 種類ごとの値、すなわち数・大きさ・確率・タイル・家具・品目を raw の行に書く。
2. 振る舞いの違う部品と、全体に1つの値、乱数の塩、試行の上限はコードに残す。
3. 今の値をそのまま raw へ移し、ダンジョンの地図の生成結果を変えない。

## 設計

### 地上の地物の間隔と道

```cue
// 区域でない地物の置き方。リージョンに1つ当選を置く
#PointFeature: {
	id!:         #PointFeatureKind
	spacing!:    int & >=2
	separation!: int & >=0 & <spacing
	salt!:       int & >=1
	// この地物の当選どうしを結ぶ道。省けば道を引かない
	road?: #Road
}

#PointFeatureKind: "settlement" | "dungeon_entrance" | "landmark" @rawgen(prefix)

#Road: {
	tile!:  #EntityID
	width!: int & >=1
}
```

- 乱数の塩も行に持つ。raw に行を持つ列挙の値と Go で比べることを lint が禁じるので、種類ごとの値は全て行に書く。区域と散布の塩は Go に残り、行の塩と重ならないことをテストで確かめる。
- 道は、道を持つ地物の当選どうしを結ぶ。今は集落だけが道を持つ。

### 地上のその他

- 区域の `fence` を真偽値から家具の id にする。省けば塀を巡らせない。
- 散布の地帯に `lootDensity` を足す。
- ダンジョンの行に `entranceWeight` を足し、遺跡の入口が重みでダンジョンを引く。0 なら入口に出ない。
- 区域の行に `streetEnemies` を足し、チャンクごとの街路の敵の数をダイスで書く。

### ダンジョンの間取り

間取りの作り方ごとに表を分ける。各表は、その作り方の数値とタイルを型付きの欄で持つ。段の並びは作り方そのものの手順なので、作り方の種類ごとに Go に残す。

```cue
#CaveLayout: {
	id!: #EntityID
	tiles!: #LayoutTiles
	wallChance!: number & >=0 & <=1
	iterations!: int & >=0
	...
}

// 間取りが置くタイル
#LayoutTiles: {
	floor!: #EntityID
	wall!:  #EntityID
	void!:  #EntityID
}
```

- 表は `roomLayouts`・`bigRoomLayouts`・`caveLayouts`・`forestLayouts`・`ruinsLayouts`・`templateLayouts`。`templateLayouts` は施設の絵の名前を持つ。
- ダンジョンの行の間取りの抽選 `planners` は、間取りの行の id を指す。間取りの id は全ての表で一意にする。
- 間取りの行から `PlannerType` を作る。間取りの id から行を引き、作り方の関数に行を渡す。
- ランダムに選ぶ間取りの候補は、絵を使わない間取りの全ての行から作る。

### フロアの敵と品目の数

ダンジョンの行に `enemyCount` と `itemCount` をダイスで書く。戦利品の試算も同じ行を読む。

### デバッグのダンジョンと町

- デバッグ用の2つのダンジョンを raw の行にし、`hidden` で一覧に出さない。敵と品目の表を省けるようにする。
- デバッグの町の中身は、絵とパレットと戦利品表で表す。

## 採用しなかった方法

- **段の並びを1つの表に書く。** `kind` の値で欄が変わる条件付きの型になり、欄の検証が弱くなる。段の並びは作り方の手順で、種類をまたいで組み替えても意味のある地図になりにくい。
- **全体の設定を1つの単独の表に置く。** raw は全て行の配列で書いていて、単独の表の前例が無い。地物の行に置けば、地物ごとに値を変えられる。

## コメント

- 今の値をそのまま移すので、ダンジョンの地図の生成結果は変わらない。地図のスナップショットのテストで確かめる。
- 街路の敵の数は、今の「区域の大きさに比例する」式をダイスで表せないので、値が少し変わる。
