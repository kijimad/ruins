# 重み付きの抽選を1つにまとめ、表の書き方をそろえる

## 背景

### 抽選のコードが散らばっている

重み付きの抽選が、書き方の違う形で各所にある。

| 書き方 | 場所 |
|---|---|
| 浮動小数の重みで共通関数を使う | `raw.SelectByWeightFunc`。敵・アイテム・行動・ドロップの表。参考 codebase: `internal/raw/weighted.go`、`internal/raw/raw.go:886-970` |
| 浮動小数の重みを手で書く | 天候の遷移 `drawWeighted`。参考 codebase: `internal/world/query/weather.go:69` |
| 整数の重みを手で減算する | 部屋の内装 `weightedIndex`、施設 `rollFacilityInZone`、散布物 `pickScatterEntry`。参考 codebase: `internal/mapplanner/interior/resolve.go:75`、`internal/overworld/urban.go:122`、`internal/overworld/scatter.go:256` |
| 確率を switch の境界値で直書きする | 建物の生活感 `rollDamage`・`rollClutter`・`rollVariant`。参考 codebase: `internal/mapplanner/interior/profile.go:81-119` |
| 一様に選ぶのを剰余で書く | 施設の主室の変種、雰囲気、家具の候補など6か所。参考 codebase: `internal/mapplanner/interior/content_lookup.go:61` ほか |
| その他の手書き | 部屋の面積の重み `selectRoom`、ランドマーク、マップテンプレートのチャンク、怪我の命中部位。参考 codebase: `internal/mapplanner/lib.go`、`internal/overworld/landmark.go`、`internal/maptemplate/template.go`、`internal/activity/injury.go` |

短い処理なので各所で書き直され、端の扱いがまちまちになっている。候補が空のとき、重みの合計が0のとき、到達しない末尾で、ゼロ値を返す、末尾を返す、panic する、と分かれる。危険度で絞る処理も、raw の抽選、マップの計画、バランスの計算に同じ形が7つある。

### 表の書き方がそろっていない

| 問題 | 例 |
|---|---|
| 選ばれる物を指すフィールドの名前が違う | 敵・アイテムの表は `id`、行動の表は `weapon`、ドロップの表は `material` |
| 何も出ないことを空文字で表す | ドロップの表の `material = ""` |
| 同じ `weight` が表の種類で意味を変える | アイテムグループの `distribution` では重みの比、`collection` では 0〜100 の確率 |

1行1エントリの書き方は採れない。raw.toml は yq で整形しており、yq は1行ずつ書いたインラインの表を全エントリ1行に詰める。手元で確かめた。

## 要件

1. 重み付きの抽選を1つの関数にまとめ、上の全箇所で使う。
2. 候補が空、または重みの合計が0なら「選べなかった」を返す。扱いを1つにする。
3. 乱数は `*rand.Rand` と、座標などから作るハッシュ値の両方から引ける。
4. 危険度で絞ってから引く処理を1つにする。
5. 確率の直書きと、一様に選ぶ剰余も、同じ関数で引く形にする。
6. 表の、選ばれる物を指すフィールドを `id` にそろえる。
7. 何も出ないことを空文字でなく、表の `nothing` の重みで表す。
8. アイテムグループの `collection` の確率を `chance` に分け、`weight` は重みの比だけを意味する。

## 設計

### 抽選の関数

```go
// Roller は [0,1) の値を1つ返す。*rand.Rand はそのまま満たす
type Roller interface {
	Float64() float64
}

// HashRoll はハッシュ値を [0,1) の値にする。座標などから決定的に引くときに使う
type HashRoll uint64

func (h HashRoll) Float64() float64

// Pick は重みに比例して entries から1つ選ぶ。候補が空、または重みの合計が0なら false
func Pick[T any](r Roller, entries []T, weight func(T) float64) (T, bool)

// PickUniform は entries から一様に1つ選ぶ。空なら false
func PickUniform[T any](r Roller, entries []T) (T, bool)
```

- 置き場所は、依存の最も下にある `internal/consts` にする。`consts.Dice` と同じく、どのパッケージからも使える。raw・内装・地上・天候のどれもが `consts` を使っている。
- 重みは `float64` にそろえる。整数の重みは呼び出し側で変換する。
- 重みが0以下の要素は選ばない。
- 累積和の走査を抜けたら、最後の正の重みの要素を返す。`Float64` が1に十分近いと、丸めで引いた値が合計と等しくなるため。

### 危険度で絞る

```go
// EnemyEntriesAt は敵テーブルのうち、危険度 danger で出る行を返す。
func EnemyEntriesAt(et oapi.EnemyTable, danger int) []oapi.EnemyTableEntry

// ItemEntriesAt はアイテムテーブルのうち、危険度 danger で出る行を返す。
func ItemEntriesAt(it oapi.ItemTable, danger int) []oapi.ItemTableEntry
```

危険度の範囲を持つのは敵とアイテムの表だけなので、`consts` に汎用の関数を置かず raw に置く。raw の抽選、マップの計画、バランスの計算がこれを使う。`MinDanger` 未満の危険度をエラーにする今の検査は残す。

### 直書きの確率を表にする

```go
// 変更前
switch r := childSeed(seed, 1) % 10; {
case r < 6:
	return clutterTidy
case r < 9:
	return clutterMessy
default:
	return clutterFilthy
}

// 変更後
return pickChoice(childSeed(seed, 1), []choice[clutterLevel]{
	{clutterTidy, 6}, {clutterMessy, 3}, {clutterFilthy, 1},
})
```

境界値ではなく重みとして読めるようになる。

### 表の書き方

変更前は次のとおり。

```toml
[[dropTables]]
id = "bat"
[[dropTables.entries]]
material = ""
weight = 0.9
[[dropTables.entries]]
material = "scrap_iron"
weight = 0.1
```

変更後は次のとおり。

```toml
[[dropTables]]
id = "bat"
nothing = 0.9
[[dropTables.entries]]
id = "scrap_iron"
weight = 0.1
```

- 行動の表 `weapon` とドロップの表 `material` を `id` に改める。
- `nothing` は、どの行も選ばれない重み。省略すれば0で、必ずどれかが出る。何も出ないことがあるのはドロップの表だけなので、ドロップの表にだけ持たせる。
- アイテムグループの行は、`distribution` なら `weight`、`collection` なら `chance` を持つ。片方だけを持つことを、読み込み時に `subtype` と突き合わせて検証する。
- アイテムテーブルから引く経路を、マップのアイテム配置と同じ `SelectFromItemGroup` にそろえる。`SelectItemByWeight` は `collection` の確率を重みの比として読んで1つだけ引き、`pack` も無視していた。`DrawFromItemTable` に置き換え、グループの `subtype` と `pack` に従って引く。収納家具の中身とバランス計算がこれを通る。
- バランス計算の1個あたりの期待価値は、各行が1回の抽選で出る個数の期待値で重み付けする。distribution は重みの比に `pack` の期待値を掛け、collection は出現確率に `pack` の期待値を掛ける。

```go
// DrawFromItemTable はアイテムテーブルから危険度に合うグループを重みで1つ選び、そのグループから1回ぶんを引く。
func DrawFromItemTable(raws oapi.Raws, it oapi.ItemTable, rng *rand.Rand, danger int) ([]DrawnItem, error)
```

### 生成結果が変わる

乱数の引き方、すなわち `Float64` か `IntN` か、何回引くかが変わるので、同じシードでも生成結果が変わる。golden 画像と分布の golden を作り直す。未リリースなのでセーブの互換は考えない。

## 採用しなかった方法

- **1行1エントリのインラインの表にする**: 表らしく見えるが、yq が全エントリを1行に詰める。
- **危険度の範囲を `danger = [1, 6]` の1つにまとめる**: 配列は yq で崩れないが、tsp の二要素の組を oapi-codegen がどう生成するかを確かめておらず、型の検証を失うおそれがある。今の `minDanger` と `maxDanger` のまま並びをそろえる。
- **何も出ないことを予約した id の行で表す**: 予約語が id の空間に混ざり、ほかの表の id と紛れる。表のフィールドにする。
- **整数の重みにそろえる**: 小数の重みが raw に多く、全表の書き換えになる。
- **乱数の引き方を今のまま保って結果を変えない**: 各所の引き方の違いを残すことになり、まとめる意味が薄れる。

## コメント

- 表の割合は、エディタの表の表示ページで計算して見せる。表示ページは存在しない `enemyName` や `itemName` を読んでいて、敵とアイテムの名前が空で表示されていたので、生成された型で読むよう直した。
- エディタの汎用の編集ページの参照先の選択欄は、選択肢に表示名の `name` を並べていて、`id` で参照する今のスキーマと合っていなかった。参照するフィールド名も `weapon`・`enemyName`・`commandTableName` など古い名前のままだった。データ上の参照はすべて `id` なので、選択肢を `id` の一覧に、フィールド名を今のスキーマに直した。
- 収納家具の中身は、`collection` のグループが複数のアイテムを `pack` の個数で出すようになり、以前より多くなる。廃墟の危険度8で拾う1個あたりの期待手取りは 46 から 47 に変わった。
- `nothing` と `chance` の値は今の値をそのまま移すので、出現の割合は変わらない。
- 抽選の結果が変わったことで、店の倉庫に玄関から入れない配置が seed 7 に出た。玄関ポーチの側壁が部屋の内側に食い込むのに、部屋ごとの到達検査が側壁を床とみなしていたのが原因で、元のコードでも seed 270 で起きていた。`Room.Walls` で直し、1000 seed で全室に入れることを確かめた。
