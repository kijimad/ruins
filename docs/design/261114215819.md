# 軍基地・発電施設の区域と、銃砲店・通信施設を足す

## 背景

施設の多様化 261108165219 の2段目と3段目のうち、残りの施設を足す。区域の作りは設計 doc 261114201513 で、並べ方・層・塀・植え込みの組み合わせになった。軍基地と発電施設は、この組み合わせに raw の行を足して置く。参考 codebase: `internal/overworld/district.go`、`internal/overworld/building.go`。

脱出の道筋 261111002908 は、壊れた鍵と修理の部品を研究所の機密ケースに仮置きしている。鍵は深い所で稀に出る通信施設へ、部品は軍基地の武器庫へ移す。

- 施設の出現は地区と規模だけで決まり、深さで絞れない。通信施設を深い所でだけ出せない。
- 銃架・弾薬箱・無線塔の絵が無い。

## 要件

設計の指針は、施設と区域を TOML で表現でき、組み合わせやすいこと。新しい施設や区域は raw の行と絵とパレットの組み合わせで足し、コードには部品だけを持つ。


1. 軍基地を、塀に囲まれた区域として置く。南の門から検問所、兵舎と練兵場、北の奥に武器庫が並ぶ。兵士系の敵が出て、銃と軍用の防具が出る。
2. 発電施設を、塀に囲まれた区域として置く。中心に吹き抜けのタービン建屋、周りに制御棟と貯炭場が並ぶ。電気系の敵が出て、電子部品と燃料が出る。
3. 銃砲店を市街地の施設として足す。銃と弾薬が出る。
4. 通信施設を市街地の施設として足し、深い所で稀に出す。壊れた鍵が出る。
5. 修理の部品を軍基地の武器庫へ移す。
6. 地図の表示と生成で施設が一致し続ける。施設の出現の深さは座標の純関数で決める。

## 設計

### 施設の出現の深さの下限

施設が出る地区の行に、深さの下限を書く。区画を割り振るときに、区域の北の端の行の危険度で施設の抽選を足切る。危険度は今の敵の危険度と同じ `query.DangerLevelForDepth` で、帯の深さの起点の行 `SeamlessBand.SpawnChunkY` からの北進チャンク数で決まる。

```cue
#FacilityZone: {
	zone!:    #Zone
	weight!:  int32 & >=1
	minSpan!: int32
	// 区域の北の端の危険度がこの値以上のときだけ抽選する。省けば1で、どの深さでも抽選する
	minDanger?: #DangerLevel
}
```

```go
// 変更前
func lotsOf(raws rawschema.Raws, cat zoneCatalog, r districtRegion) []buildingLot

// 変更後。深さの起点の行 spawnRow から区域の危険度を測る
func lotsOf(raws rawschema.Raws, cat zoneCatalog, r districtRegion, spawnRow consts.Chunk) []buildingLot
```

- 区域は1回で割り振るので、区域の全ての区画を北の端の1つの危険度で抽選する。背の高い区域では、南の端の施設も北の端の深さで抽選される。
- 施設の出現は座標の純関数なので、日数の危険度は見ない。敵は日数と深さの大きい方を見るので、同じ場所でも施設と敵の危険度が違いうる。
- 区域の目玉の施設は抽選を通らず必ず1つ建つので、深さの下限を書いても効かない。raw の検証で、目玉の施設が深さの下限を持たないことを確かめる。
- 深さの起点の行は、区画を割り振る経路にだけ届ける。生成と道と散布は world の帯から取り、地図は `BuildMacroView` の引数で受ける。
- 施設の抽選は、規模の足切り `minSpan` と同じ所で `minDanger` も足切る。
- 区域の全ての地区に、一番小さく一番浅い所でも建てられる施設があることを、今の検証と同じく raw で確かめる。

### 軍基地

```toml
[[districts]]
id = "military_base"
pattern = "rows"
fence = true
verge = true
landmark = "military_armory"
  [[districts.layers]]
    zones = ["military_gate"]
    rows = 1
  [[districts.layers]]
    zones = ["military_inner"]
  [[districts.layers]]
    zones = ["military_armory"]
    rows = 1
```

| 施設 | 地区 | 大きさ | 中身 |
|---|---|---|---|
| `military_checkpoint` | 門 | 1×1 | 検問所。1棟の絵 |
| `military_barracks` | 中ほど | 2×1・2×2 | 兵舎。寝台とロッカー。部屋の絵 |
| `military_yard` | 門・中ほど | 1×1 | 練兵場と車両置き場。屋外の絵 |
| `military_armory` | 奥 | 3×1・4×1 | 武器庫。目玉の施設。銃架と弾薬箱。部屋の絵 |

- 敵は兵士系の表 `military_enemies` と、武器庫の強い表 `military_armory_enemies`。
- 戦利品は兵舎のロッカー `military_locker` と、武器庫 `military_armory`。修理の部品は武器庫の表へ移す。

### 発電施設

```toml
[[districts]]
id = "power_plant"
pattern = "rings"
fence = true
landmark = "power_turbine"
  [[districts.layers]]
    zones = ["plant_outer"]
  [[districts.layers]]
    zones = ["plant_core"]
```

| 施設 | 地区 | 大きさ | 中身 |
|---|---|---|---|
| `power_turbine` | 中心 | 3×3・2×2 | タービン建屋。目玉の施設。吹き抜け hall |
| `power_control` | 外側 | 2×1 | 制御棟。制御盤。部屋の絵 |
| `power_coalyard` | 外側 | 1×1 | 貯炭場と変圧器。屋外の絵 |

- 大きさは 5×5 と 6×5。中心は 3×3 になる。
- 吹き抜けは初めて使うので、吹き抜けの辺を持つ部屋の絵を、要る辺の組の全てに描く。辺の組は回転と反転を除いて11通りある。
- 敵は電気系の表 `power_plant_enemies`。戦利品は制御盤 `power_control` と燃料の樽 `power_fuel`。

### 銃砲店と通信施設

- 銃砲店 `gunshop` は都心と産業区に出る 1×1 の施設。銃架の戦利品表 `gunshop_rack` から銃と弾薬が出る。敵は `gunshop_enemies`。
- 通信施設 `comms` は都心と産業区に出る 1×1 の施設。重みを低くし、`minDanger` で深い所だけに出す。無線機の戦利品表 `comms_console` に壊れた鍵を高い重みで入れ、研究所の機密ケースから外す。

### 家具の絵

絵の無い家具は、名前を書いた 32×32 のダミーの絵と raw の行を足す。今のダミーの家具と同じ作り。

| 家具 | 収納 | 使う施設 |
|---|---|---|
| `gun_rack` | あり | 銃砲店・武器庫 |
| `ammo_crate` | あり | 武器庫・銃砲店 |
| `radio_console` | あり | 通信施設 |
| `radio_mast` | なし | 通信施設 |
| `control_panel` | あり | 発電施設の制御棟 |

## 採用しなかった方法

- **深さの下限を、区域の種類に持たせる。** 通信施設は町の中の1棟なので、区域でなく施設の地区の行で絞るのが素直。
- **帯の形 `bandShape` を区域を引く全ての関数へ通す。** 約26の関数の引数が変わる。深さが効くのは区画の割り振りだけなので、そこへ至る経路にだけ届ける。
- **深さを生成の時だけ見る。** 地図の表示は world を引かずに施設を決めるので、表示と生成で施設が食い違う。
- **深さの起点を絶対の行0にする。** 敵の危険度と起点がずれ、同じ場所で敵と施設の深さが別の値になる。
- **発電施設のタービン建屋を部屋の迷路にする。** 吹き抜けを描く手間は省けるが、タービンの並ぶ広い空間にならない。

## コメント

- 地区ごとの特殊な施設の重みの見直しと、日数で危険な施設を増やす案は、施設の多様化 261108165219 の残りとして別に扱う。
