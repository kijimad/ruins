# 駆動: 冷気前線は極寒の場であり、死は低体温から訪れる

## 背景

マクロループ設計 `260821223229` の①駆動を詳細化する。方針を1つ確定する。**前線に追いつかれても即ゲームオーバーにしない**。前線は極端な冷たさを提供する場であり、プレイヤーはその中で低体温が進んで死にやすくなるだけである。死は既存の体温系から身体モデル `260821232324` の血経路を通り、凍死として訪れる。

コードを確認した結果、前線の物理は大部分が実装済みだった。

- `SeamlessFront{Active, ColdWidth, AdvanceTurns, ...}`。現在位置 `EastAbsX` は保存せず、config と総ターン数から毎ターン導出する。冪等で決定論的。
- `frostZoneModifier` が極低温ゾーン内タイルへ `FrostZoneTempModifier` を返し、`CalculateEnvTemperature` に注入済み。ゾーン内は生存不能な極寒として `TemperatureSystem` が低体温を進める。
- `IsWestOfFront` が進入不可ラインを判定する。
- `FrostRenderSystem` が氷白のオーバーレイを描く。
- 腐敗速度も極寒で -1.0 に落ちる接続がある。

つまり「前進する極寒の場」は既にある。欠けているのは次の3つで、この doc は前2つを設計し、死の終端接続は終端 doc `260822014348` へ委ねる。

1. **崖の問題**。`InColdZone` は二値で、ゾーンの外は平常・内は即極寒。予兆が無く、境界をまたいだ瞬間に世界が反転する。読みと駆け引きが生まれない。
2. **予報が無い**。前線位置は純関数導出なのに、プレイヤーは前線がいつ届くかを読めない。
3. 死んでも汎用ゲームオーバーで、到達距離が記録されない。終端 doc の領分。

## 要件

**Hard**

- 追いつかれても即ゲームオーバーにしない。前線の圧力は温度だけで表す。
- 死は極寒 → 低体温 → 血の既存経路で訪れる。前線専用の死亡判定を作らない。
- 決定論を保つ。前線位置と気温修正は config と総ターン数の純関数のまま。
- 極寒は二値の崖でなく勾配にする。前線に近づくほど冷え、予兆が読める。

**Soft**

- 予報が読める。前線がいつここへ届くかを見て、漁りの切り上げ時を判断できる。
- 断熱・焚き火・シェルターで粘れる。装備と資源が前線への滞在猶予を決め、対抗手段に意味が出る。
- ゾーン奥ほど寒い。深追いの度合いがリスクの度合いになる。

**Anti**

- 即死判定・強制移動・演出の壁を足さない。圧力はすべて温度と既存機構で表す。
- 進入不可ライン以外の人工的な制約を増やさない。
- 前線位置の新しい算出源を作らない。`EastAbsX` の導出を唯一の真実に保つ。

## 設計

### 勾配: 崖をやめ、近づくほど冷える

二値の `frostZoneModifier` を勾配に置き換える。ゾーン東側に勾配帯を設け、前線に近づくほど線形に冷える。ゾーン内はさらに西へ深いほど冷える。

```go
// SeamlessFront へ勾配帯の幅を足す
type SeamlessFront struct {
	// 既存フィールドは不変
	GradWidth int // 極低温ゾーン東側の勾配帯の幅タイル。この帯で平常から極寒へ線形に落ちる
}

// frontChill は前線からの位置に応じた気温修正を返す純関数。
// ゾーン西奥 < ゾーン東端 < 勾配帯 < 平常 の順に緩む。数値は実測で決める
func frontChill(front SeamlessFront, absX consts.AbsTileX) int
```

`frostZoneModifier` の呼び出し面は変えず、内部を `frontChill` にする。`CalculateEnvTemperature` への注入点も既存のまま。勾配帯では快適域を下回るが即致死ではない温度にし、断熱と焚き火で粘れる。ゾーン内は従来どおり生存不能な極寒へ収束させる。

これで境界の反転が消え、「寒くなってきた、そろそろ潮時だ」という予兆の体験が生まれる。深追いはより深い寒さという連続的な代償を払う。

### 予報: 純関数を将来時刻で評価する

前線位置の導出は config と総ターン数の純関数なので、将来の総ターン数を入れるだけで予報になる。保存状態は増えない。

```go
// ForecastFrontArrival は絶対 X へ前線の勾配帯が届くまでの残りターン数を返す。
// 既存の導出を将来時刻で評価するだけで、新しい状態を持たない
func ForecastFrontArrival(world w.World, absX consts.AbsTileX) int
```

表示は観察と HUD に出す。例として「冷気前線: 西 12 タイル。約2日で到達」。予報の精度をぼかすかは演出の問題なので着手時に決める。

### 死の帰結

勾配帯とゾーンで低体温が進み、`Hypothermia` が振り切れた先は身体モデル `260821232324` の経路に任せる。低体温の重症化が血を減らし、血が尽きれば凍死。`DeathCause` は凍死として終端 doc `260822014348` の `RunOutcome` に記録される。前線はどこにも死亡判定を持たない。

## 採用しなかった方法

- **追いつき即敗北の `ColdPursuitSystem`**。前線とプレイヤーの X を比較し追いつかれたら run を終える。却下。唐突で理不尽なうえ、断熱・焚き火・シェルターという既存の対抗手段を無意味化する。温度場なら装備と資源で粘る読みが生まれ、死も低体温から血へという既存経路で説明がつく。専用の裁定 system が1つ消え、実装も軽い。
- **二値の極寒を維持する**。ゾーン境界で平常と極寒が切り替わる現状のまま。却下。予兆が無い崖は読みを生まず、境界をまたいだ瞬間の反転が理不尽に感じられる。
- **強制スクロールや移動不能の壁**。却下。移動の自由を奪う人工的な圧力は一方向逃避の「選んで前へ進む」体験を壊す。圧力は温度で十分。
- **前線位置の新算出関数を別途作る**。却下。`EastAbsX` は config と総ターン数から毎ターン導出済みで冪等。二重の真実を作らない。予報も同じ導出の将来時刻評価で足りる。

## コメント

勾配帯の幅・勾配の傾き・ゾーン内の温度カーブは数値なので、最小で組んで実プレイしてから測る。低体温の進行速度と断熱の効きは既存バランスがあるため、勾配導入で「粘れる時間」がどう変わるかを最初に確認する。
