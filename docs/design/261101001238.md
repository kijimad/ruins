# OSS 調査 2026-11

## 背景

月次の OSS 調査ルーチン。GitHub Trends と `gh search repos` で ruins に役立ちそうな OSS を探し、採否の判断材料をまとめる。コードや依存の変更は行わず、調査結果の提示に留める。

### 調べ方

1. `go.mod` を読み、既存依存を把握した。Ebiten・Ark・ark-serde・testify・goldie・urfave/cli・furex・go-text/typesetting・tablewriter などが既にある。
2. `gh search repos` でドメインごとに検索した。クエリ: `ebiten`、`"ecs entity component"`、`roguelike`、`"procedural generation"`、`"dungeon generation"`、`"astar pathfinding"`、`"behavior tree"`、`"finite state machine" game`、`"property based testing"`、`fuzzing testing`、`ebitengine animation`、`tween go`、`"wave function collapse"`、`"perlin noise"`、`"field of view" roguelike`。
3. GitHub Trends 月間 Go を WebFetch で取得した。上位20件は ollama・caddy・trivy・kubernetes など汎用インフラ・AI エージェント系で占められ、ゲーム・ECS・ローグライク関連は無かったため、今回は候補として採用しない。
4. ruins の既存実装も確認した。`internal/mapplanner/pathfinder.go` に4方向 BFS の自前パスファインダー、`internal/systems/vision.go` に自前の視界計算、`internal/aiinput` に自前のステートマシン AI、`internal/widgets` に furex ベースの自前ウィジェット群がすでにある。これらと重複・競合する候補は、置き換えの大きさを明記した上で評価する。

## 候補

### quasilyte/pathing

- リポジトリ: https://github.com/quasilyte/pathing
- 概要: グリッドベースのパスファインディングライブラリ。ゼロアロケーションを志向し、重み付きコストや複数ゴールの探索に対応する。
- ruins での用途: `internal/mapplanner/pathfinder.go` は4方向 BFS のみで、コスト無視・斜め移動非対応。タクティカル戦闘でのAI移動や、将来斜め移動・移動コスト地形を入れる際の置き換え候補になる。
- 成熟度: 137 スター、2026-10-27 更新。quasilyte は Ebitengine 関連ライブラリを複数メンテしており活発。
- ライセンス: MIT
- 採用時の注意: 既存 BFS の置き換えになるため、移行は設計ドキュメントを別途立てて段階的に行う。今は機能的に BFS で足りているなら保留でもよい。

### norendren/go-fov

- リポジトリ: https://github.com/norendren/go-fov
- 概要: グリッドマップ向けの再帰的シャドウキャスティングによる視界計算ライブラリ。
- ruins での用途: `internal/systems/vision.go` に自前の視界計算がすでにあるため、新規導入ではなく実装の正しさを比較検証する参考実装、または将来的な置き換え候補として位置づける。
- 成熟度: 43 スター、2026-02-24 更新。更新は止まっているが、再帰的シャドウキャスティングという単機能のアルゴリズム実装なので腐りにくい。
- ライセンス: MIT
- 採用時の注意: 既存実装を置き換える動機、具体的には遮蔽の不具合や拡張性の不足があるかを先に確認する。無ければ現状維持でよい。採用を決める設計docを立てる際は、Ebitengine がターゲットとする WebAssembly・モバイル環境での動作が確認できるか README を確認しておく。

### quasilyte/ebitengine-input

- リポジトリ: https://github.com/quasilyte/ebitengine-input
- 概要: Godot の入力アクションに似た、キーボード・マウス・ゲームパッドを抽象化する入力ハンドリングライブラリ。キー割り当ての変更にも対応する。
- ruins での用途: `internal/input/keyboard.go` は `ebiten.IsKeyPressed` などを直接叩く自前実装で、入力の抽象化層が無い。アクション名ベースの入力や、将来のキーバインド変更・ゲームパッド対応を入れる際の土台になる。
- 成熟度: 99 スター、2026-10-01 更新。活発にメンテされている。
- ライセンス: MIT
- 採用時の注意: 既存の `internal/input` を置き換える規模の変更になるため、キーバインド変更やゲームパッド対応のニーズが実際に出てから検討するのが安全。

### flyingmutant/rapid

- リポジトリ: https://github.com/flyingmutant/rapid
- 概要: Go のプロパティベーステストライブラリ。入力を自動生成し、不変条件を満たすかを検証する。シュリンクにも対応する。
- ruins での用途: serde のラウンドトリップや ECS のクエリ、`internal/mapplanner` のパス探索・接続性チェックなど、「どんな入力でも成り立つべき性質」を持つ箇所のテストに testify を補完する形で使える候補。
- 成熟度: 906 スター、2026-10-30 更新。活発にメンテされている。
- ライセンス: MPL-2.0。MPL 対象ファイルを改変した場合はそのファイル単体のソース公開義務が生じるファイル単位の弱いコピーレフトで、MIT/BSD/Apache と比べて制約が強い。テスト専用依存のため製品バイナリに含まれず、ruins のソースは既に MIT で公開済みのため、この開示要件は実質的に満たされる。
- 採用時の注意: テスト専用依存として `go.mod` の require に加わる。ビルドする製品バイナリには含まれないため実配布への影響は小さいが、ライセンス差異は PR レビューで明示する。

### tanema/gween

- リポジトリ: https://github.com/tanema/gween
- 概要: シンプルなインターフェースのトゥイーンアニメーションライブラリ。イージング関数を多数含む。
- ruins での用途: 現状 ruins にイージング・トゥイーンの仕組みは見当たらない。UI のフェードやカメラ遷移、`internal/widgets` 配下のアニメーションに使える。
- 成熟度: 104 スター、2026-10-09 更新。
- ライセンス: MIT。tween.lua 由来の BSD 3条項ライセンス表記も同梱されるが、再配布条件は満たしやすい。
- 採用時の注意: 小さな単機能ライブラリなので導入コストは低い。採用時は LICENSE に同梱される tween.lua 由来の BSD 3条項ライセンス表記の帰属表示要件を満たす形で同梱する。UI アニメーションの必要が出た時点で検討すればよい。

## 採用しなかった観点

- **ebitenui/ebitenui**: Ebitengine 向けウィジェットライブラリとして最有力候補ではあるが、ruins は `internal/widgets` に furex ベースの自前ウィジェット一式、テーマ・ページネーション・メニューフレームなどをすでに持つ。導入すると二重のウィジェット基盤を抱えることになるため、今回は候補から外した。
- **ビヘイビアツリー系**（magicsea/behavior3go、joeycumines/go-behaviortree 等）: ruins の AI は `internal/aiinput` の自前ステートマシンで動いている。ビヘイビアツリーへの置き換えは AI 設計全体に関わる大きな変更になり、現状の複雑度ではその投資に見合う根拠が無いため見送った。
- **Wave Function Collapse / Perlin ノイズ系**（shawnridgeway/wfc、zfedoran/go-wfc、aquilax/go-perlin 等）: マップ生成の高度化に使える可能性はあるが、スター数・メンテ状況が弱く、ruins の `mapplanner` が具体的にどう手詰まりかが今は無いため見送った。将来マップ生成を拡張する設計docが立った時点で再検討する。
- **ダンジョン生成単体ライブラリ**（"dungeon generation" 検索上位）: いずれもスター数が極少または0で成熟度が無いため見送った。
- **GitHub Trends 月間 Go**: ollama・caddy・trivy・kubernetes・oauth2-proxy など、いずれも ruins のドメインと無関係な汎用インフラ・AI エージェント系だったため候補に採らなかった。
