# 疲労・空腹の効果を修飾子パイプラインへ統一する

## 背景

疲労と空腹の効果が3系統に散らばり、機構も別々になっている。

- 命中: `query/modifiers.go` の `fatigueAccuracyDelta` が修飾子パイプラインに**特別扱い**で挿入される。空腹は命中に効かないので未対応。
- 行動速度: `query/turn.go` の `calculateStatusSpeedPenalty` が加算APで直接引く。ModifierKey ではない。空腹は `HungerSpeedPenalty`、疲労は `FatiguePenalty().SpeedAdd`。
- 回復: `query/metabolism.go` の `Metabolism` が base 100 に加算する。ModifierKey ではない。空腹は `HungerRecoveryDelta`、疲労は `FatiguePenalty().RecoveryAdd`。

係数自体は `FatiguePenalty` 表・`HungerSpeedPenalty`・`HungerRecoveryDelta` に集約済みだが、適用が3箇所に分かれ、疲労と空腹が別の関数・別の合流点を通る。新しい状態を足すたびに全系統へ手を入れる必要があり、Effects タブの内訳にも命中しか出ない。

空腹の速度ペナルティは軸ずれで実質無効だったが、本統一に先行して段階基準へ是正済み。以前は `HungerSpeedPenalty(Hunger.Current)` が生の Current を 75/50/25/10 の閾値で見ており、`Hunger.Current` は Max=500 を動くため `Current≥75` で常にペナルティ0、`Hungry` 段階でも鈍らなかった。加えてレベル基準の `Hunger.GetStatusPenalty` が二重定義で死んでいた。現在は `HungerSpeedPenalty(HungerLevel)` に統一し、命中・回復と同じ段階基準にした。残る課題は3系統の適用が別合流点に散っていることで、本統一で修飾子パイプラインへ寄せる。

CharModifiers は #751 で「保存コンポーネントをやめ、Skills・Abilities・HealthStatus から都度計算する修飾子ビュー」に移行済みで、`CalcModifierValue` が **base 100 に各ソースの delta を加算する加算モデル**になっている。疲労・空腹の効果もこの1つの機構へ寄せれば、適用・表示・拡張が一本化できる。

## 要件

- 疲労・空腹の全効果を1つの修飾子パイプラインで計算する。命中の特別扱いを撤去する。
- 適用と表示が同じ値を読む。Effects タブの内訳に疲労・空腹の寄与が全効果ぶん出る。
- 新しい状態や効果は、係数表とソース列挙に1行足すだけで全系統へ反映される。
- ゲーム挙動は据え置き。行動速度・回復も剣攻撃力と同じ「基準100＋Σ加算差分」の単機能倍率にし、特別扱いを作らない。

## 設計

### 修飾子の合成モデル

`CalcModifierValue` は base 100 に各ソースの `Value` を加算する。回復・命中も加算 delta で適合する。速度は従来「基準100＋能力値ボーナス」に状態ペナルティを別途足す形だったが、これは加算モデルそのものなので、行動速度・回復を剣攻撃力と同格の単機能倍率として spec 表へ載せる。`CalculateSpeed` は `ModActionSpeed` の値をそのまま速度に使い、能力値ボーナスの手書きを撤去する。

### 新しい ModifierKey

```go
// internal/components/modifiers.go
const (
	ModActionSpeed ModifierKey = "action_speed" // 行動速度%。低いほど遅い
	ModRecovery    ModifierKey = "recovery"     // 自然回復・治癒の速度%。Metabolism の後継
)
```

### 状態を修飾子ソースにする

`modifierInputs` が Fatigue・Hunger・Sleeping も集め、`forEachModifierSource` が状態ソースを列挙する。これで `ModifierValue` も `ModifierSources` も状態を自動で含み、命中の特別扱い `fatigueAccuracyDelta` を撤去できる。

```go
// 状態の各段階が各 ModifierKey へ与える加算 delta の1表。
// FatiguePenalty / HungerSpeedPenalty / HungerRecoveryDelta を統合する。
type statusModifier struct {
	Key   ModifierKey
	Value int // base 100 への加算 delta
}

// 例: 疲労段階ごとの寄与
var fatigueModifiers = map[FatigueLevel][]statusModifier{
	FatigueTired: {
		{ModSwordAccuracy, -10}, /* ... 全命中キー ... */
		{ModActionSpeed, -15},
		{ModRecovery, -20},
	},
	FatigueExhausted: {
		{ModSwordAccuracy, -25}, /* ... */
		{ModActionSpeed, -35},
		{ModRecovery, -40},
	},
}
```

### 適用側の付け替え

- `Metabolism(world, e)` は `ModifierValue(world, e, ModRecovery)` を読むだけにする。VIT は spec の ability ソース、空腹・疲労・睡眠は状態ソースとして ModRecovery に合流する。
- `CalculateSpeed(world, e)` は `ModifierValue(world, e, ModActionSpeed)` の値をそのまま速度の土台にする。AGI・DEX の能力寄与は spec の ability ソースになり、`calculateStatusSpeedPenalty` の加算AP経路と手書きの能力値ボーナスを撤去する。過積載・移動コスト・身体機能はこれまでどおり後段で掛ける。

### 表示

Effects タブは `ModActionSpeed`・`ModRecovery`・命中キーを既存の `details(key)` で出すだけで、疲労・空腹の寄与が内訳に並ぶ。Basic タブの疲労・空腹行は段階表示のまま。

## 採用しなかった方法

- **状態ペナルティ集約層のみ**: `StatusSpeedPenalty`・`StatusRecoveryDelta` を作り速度・回復は加算のまま。散らばりは消えるが CharModifiers とは別機構が並立し、内訳表示も統一されない。統一の目的を満たさないため不採用。
- **行動速度を状態専用の乗算倍率にする**: 当初は `ModActionSpeed` を spec に持たせず状態ソースだけで組み、`CalculateSpeed` で乗算適用した。だが剣攻撃力など他の倍率は「スキル・能力値を土台に持つ単機能倍率」で、行動速度だけ土台を持たず状態専用という非対称になる。能力値ボーナスも `CalculateSpeed` に手書きで残り、`isStatusDerivedKey` の特別ガードも要った。剣攻撃力と同格の一級キーへ寄せる方が一貫するため不採用。
- **今はしない**: 係数は集約済みだが適用の散らばりが残り、Effects タブの内訳も命中限定のまま。統一要件を満たさない。

## コメント

行動速度・回復は剣攻撃力と同じ加算モデルなので、乗算へ改めず spec の単機能倍率に載せる。ModRecovery は Metabolism を完全に置換し、Metabolism は `ModifierValue(ModRecovery)` の薄いラッパとして残す。

## 実装メモ

状態寄与は当初案の components 層 `forEachModifierSource` でなく、world を持つ query 層の
`statusSources` に集約した。状態コンポーネント Fatigue/Hunger/Sleeping は components 層へ渡って
いないため。新しい係数表 `fatigueModifiers`/`hungerModifiers` は作らず、既存の `FatiguePenalty`・
`HungerRecoveryDelta` を係数の単一ソースとして `statusSources` が読む。`fatigueAccuracyDelta` は
撤去でなく `statusSources` 経由へ一般化した。命中は base 依存の乗算、回復・行動速度は加算、と寄与の
型が違うのを `statusSources` の1関数で扱う。

行動速度・回復は剣攻撃力と同格の一級キーにした。`modifierSpec` を能力値の直接寄与も持てるよう
`abilityTerm` で拡張し、`ModActionSpeed`(AGI×2・DEX×1)・`ModRecovery`(VIT×3) を spec 表へ1行ずつ
足した。`CalculateSpeed` の能力値ボーナス手書きと `calculateStatusSpeedPenalty` は撤去し、
`ModifierValue(ModActionSpeed)` の値をそのまま速度の土台にする。回復の VIT も spec の能力ソースへ
移し、`recoverySources` からは外した。これで剣攻撃力と同じ「基準100＋Σ加算差分」に一本化され、
乗算モデルは不要になった。VRT golden はどのリプレイでも変化せず再生成は不要だった。

Skills 非所持でも能力値ベースの倍率を算出できるよう、`modifierInputs` は各コンポーネントを独立に
集める。ガードは spec 由来の `KeyRequiresSkill` に一般化し、状態専用キーの手書きリスト
`isStatusDerivedKey` は撤去した。スキルを土台に持つキーだけ Skills 非所持で等倍を返す。
