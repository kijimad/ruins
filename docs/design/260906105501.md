# 疲労・空腹の効果を修飾子パイプラインへ統一する

## 背景

疲労と空腹の効果が3系統に散らばり、機構も別々になっている。

- 命中: `query/modifiers.go` の `fatigueAccuracyDelta` が修飾子パイプラインに**特別扱い**で挿入される。空腹は命中に効かないので未対応。
- 行動速度: `query/turn.go` の `calculateStatusSpeedPenalty` が加算APで直接引く。ModifierKey ではない。空腹は `HungerSpeedPenalty`、疲労は `FatiguePenalty().SpeedAdd`。
- 回復: `query/metabolism.go` の `Metabolism` が base 100 に加算する。ModifierKey ではない。空腹は `HungerRecoveryDelta`、疲労は `FatiguePenalty().RecoveryAdd`。

係数自体は `FatiguePenalty` 表・`HungerSpeedPenalty`・`HungerRecoveryDelta` に集約済みだが、適用が3箇所に分かれ、疲労と空腹が別の関数・別の合流点を通る。新しい状態を足すたびに全系統へ手を入れる必要があり、Effects タブの内訳にも命中しか出ない。

さらに空腹の速度ペナルティは軸がずれていて実質無効になっている。命中・回復は空腹レベル基準だが、速度は `HungerSpeedPenalty(Hunger.Current)` が生の Current を 75/50/25/10 の閾値で見る。`Hunger.Current` は Max=500 を動くので `Current≥75`、すなわちレンジ上位85%で常にペナルティ0になり、`Hungry` 段階でも鈍らない。加えてレベル基準の速度ペナルティ `Hunger.GetStatusPenalty`(-20/-10) が本番未使用のまま二重定義で残っている。統一時に速度も段階基準へ揃えてこのスケール不整合を正し、死んでいる `GetStatusPenalty` を1本化して除去する。

CharModifiers は #751 で「保存コンポーネントをやめ、Skills・Abilities・HealthStatus から都度計算する修飾子ビュー」に移行済みで、`CalcModifierValue` が **base 100 に各ソースの delta を加算する加算モデル**になっている。疲労・空腹の効果もこの1つの機構へ寄せれば、適用・表示・拡張が一本化できる。

## 要件

- 疲労・空腹の全効果を1つの修飾子パイプラインで計算する。命中の特別扱いを撤去する。
- 適用と表示が同じ値を読む。Effects タブの内訳に疲労・空腹の寄与が全効果ぶん出る。
- 新しい状態や効果は、係数表とソース列挙に1行足すだけで全系統へ反映される。
- ゲーム挙動は原則据え置き。ただし行動速度は加算APから速度%へモデルを改める。

## 設計

### 修飾子の合成モデル

`CalcModifierValue` は base 100 に各ソースの `Value` を加算する。回復(Metabolism)は既にこの形、命中も加算 delta で適合する。速度だけ「加算AP」なので、行動速度%の ModifierKey へ改め、AP計算側で % として効かせる。

### 新しい ModifierKey

```go
// internal/components/modifiers.go
const (
	ModActionSpeed ModifierKey = "action_speed" // 行動速度%。低いほど遅い
	ModRecovery    ModifierKey = "recovery"     // 自然回復・治癒の速度%。Metabolism の後継
)
```

### 状態を修飾子ソースにする

`modifierInputs` が Fatigue・Hunger・Sleeping も集め、`forEachModifierSource` が状態ソースを列挙する。これで `ModifierValue` も `ModifierSources` も状態を自動で含み、命中の特別扱い `fatigueAccuracyDelta` を撤去できる。

```go
// 状態の各段階が各 ModifierKey へ与える加算 delta の1表。
// FatiguePenalty / HungerSpeedPenalty / HungerRecoveryDelta を統合する。
type statusModifier struct {
	Key   ModifierKey
	Value int // base 100 への加算 delta
}

// 例: 疲労段階ごとの寄与
var fatigueModifiers = map[FatigueLevel][]statusModifier{
	FatigueTired: {
		{ModSwordAccuracy, -10}, /* ... 全命中キー ... */
		{ModActionSpeed, -15},
		{ModRecovery, -20},
	},
	FatigueExhausted: {
		{ModSwordAccuracy, -25}, /* ... */
		{ModActionSpeed, -35},
		{ModRecovery, -40},
	},
}
```

### 適用側の付け替え

- `Metabolism(world, e)` は `ModifierValue(world, e, ModRecovery)` を読むだけにする。VIT は ability ソース、空腹・疲労・睡眠は状態ソースとして ModRecovery に合流する。
- `calculateStatusSpeedPenalty` は `ModifierValue(world, e, ModActionSpeed)` を速度%として読む。AP計算を % で効かせる。

### 表示

Effects タブは `ModActionSpeed`・`ModRecovery`・命中キーを既存の `details(key)` で出すだけで、疲労・空腹の寄与が内訳に並ぶ。Basic タブの疲労・空腹行は段階表示のまま。

## 採用しなかった方法

- **状態ペナルティ集約層のみ**: `StatusSpeedPenalty`・`StatusRecoveryDelta` を作り速度・回復は加算のまま。散らばりは消えるが CharModifiers とは別機構が並立し、内訳表示も統一されない。統一の目的を満たさないため不採用。
- **行動速度を加算APのまま ModifierKey にする**: 修飾子パイプラインは base 100 加算%なので、加算APは載らない。速度%へ改める方が機構と一致する。
- **今はしない**: 係数は集約済みだが適用の散らばりが残り、Effects タブの内訳も命中限定のまま。統一要件を満たさない。

## コメント

行動速度のモデル変更(加算AP→速度%)はバランスに影響しうるので、既存の速度感を保つ係数に調整する。ModRecovery が Metabolism を完全に置換するか、当面は Metabolism をラッパとして残すかは実装時に決める。
