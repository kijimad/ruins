# 疲労・空腹を身体機能 capacity 経由へ一本化する

## 背景

疲労と空腹の効果が3系統に散らばり、機構も別々になっている。

- 命中: `query/modifiers.go` の疲労畳み込みが修飾子パイプラインへ特別扱いで挿入される。空腹は命中に効かない。
- 行動速度: `query/turn.go` が能力値ボーナスに状態ペナルティを足して直接引く。
- 回復: `query/metabolism.go` の `Metabolism` が base 100 に空腹・疲労・VIT・睡眠を加算する。

当初はこれらを1つの修飾子パイプラインへ寄せ、行動速度・回復を `ModActionSpeed`・`ModRecovery` という
キーにした。だが修飾子キーは本来「特定の行動の結果や費用」に閉じたスコープ、すなわち剣攻撃力は剣攻撃だけ、
移動コストは移動だけ、を対象にする。行動速度は全行動の AP レートに効く横断的なステータスで、この枠に
収まらない。回復も受動レートで行動ではない。行動速度・回復を剣攻撃力と同列のキーにするのはカテゴリ違いで、
`ModActionSpeed` を状態専用に扱う特別ガードや、能力値ボーナスの手書きといった歪みを生んでいた。

ruins には既に「身体状態が行動へ効く」経路がある。身体機能 capacity である。`HealthStatus` の部位の不調が
Consciousness・Manipulation・Moving・Sight を下げ、Consciousness は master 乗数として他の全機能に掛かる。
Moving は `CalculateSpeed` に、Manipulation・Sight は命中の畳み込みに既に流れている。つまり怪我・病気は
capacity 経由で行動へ波及する。**疲労・空腹も capacity を下げるだけにすれば、この既存の連鎖が速度・命中・
回復を自動で処理し、横断ステータスのキーを新設せずに済む。**

## 要件

- 疲労・空腹は capacity だけに作用させる。速度・命中・回復への効果はすべて capacity 経由で導く。
- `ModActionSpeed`・`ModRecovery` の横断ステータスキーと、命中の疲労特別扱いを撤去する。修飾子 spec 表は
  スキル・能力値ベースの倍率に純化する。
- 睡眠の回復ボーナスと VIT の回復寄与は capacity の対象外の直接入力として残す。要件は疲労・空腹の一本化。
- ゲーム挙動の変化を許容する。空腹が命中にも効くようになる、効果ごとの微調整が Consciousness 1本へ集約される、
  など。バランス調整と VRT golden 再生成を伴う。

## 設計

### capacity を唯一の合流点にする

疲労・空腹は Consciousness を下げる。Consciousness は master 乗数なので Manipulation・Moving・Sight が
連動して下がり、命中と速度が同時に落ちる。回復も Consciousness に比例させる。これで状態1つにつき
Consciousness オフセット1つを決めれば、速度・命中・回復のすべてが決まる。

睡眠は capacity を下げない。ruins の capacity は `HealthStatus`、すなわち怪我・病気だけから算出され、
睡眠状態 `Sleeping` は capacity に触れない。したがって「睡眠中は意識が低いのに回復は上げたい」という
矛盾は起きず、回復 ∝ Consciousness と睡眠ボーナスは両立する。睡眠ボーナスは睡眠状態の別乗数として残す。

### 状態から capacity へのオフセット

段階ごとの Consciousness 低下量を1表に持つ。値は実プレイで調整する初期値。

```go
// internal/components/fatigue.go
// 疲労段階が Consciousness へ与える低下量。master 乗数なので速度・命中・回復すべてへ波及する
func (f *Fatigue) ConsciousnessPenalty() int {
	switch f.GetLevel() {
	case FatigueRested, FatigueNormal:
		return 0
	case FatigueTired:
		return 10
	case FatigueExhausted:
		return 25
	}
	panic("invalid FatigueLevel value")
}
```

```go
// internal/components/hunger.go
// 空腹段階が Consciousness へ与える低下量
func HungerConsciousnessPenalty(level HungerLevel) int {
	switch level {
	case HungerSatiated, HungerNormal:
		return 0
	case HungerHungry:
		return 10
	case HungerStarving:
		return 20
	}
	return 0
}
```

### 実効 capacity を query 層で算出する

`HealthStatus.Capacities()` は怪我・病気だけを見る純関数のまま残す。query 層に実効 capacity を置き、
基礎 capacity の Consciousness を疲労・空腹ぶん下げ、Consciousness に連動する Manipulation・Moving・Sight を
再計算する。`CalculateSpeed` と命中の畳み込みはこの実効 capacity を読む。

```go
// internal/world/query/capacity.go
// EffectiveCapacities は怪我・病気に加え疲労・空腹の Consciousness 低下を畳んだ実効身体機能を返す。
// 速度・命中・回復がこの1関数を読むので、身体状態の効き方が1経路に集約される
func EffectiveCapacities(world w.World, entity ecs.Entity) gc.BodyCapacities
```

内訳表示のため、Consciousness の低下要因、すなわち怪我・病気・疲労・空腹、を列挙する導出も持つ。
Effects タブの Body function は既に capacity を出しているので、疲労・空腹の寄与はそこへ並ぶ。

### 適用側

- 速度: `CalculateSpeed` は AGI・DEX の素の速度に移動コストを掛け、実効 Moving を掛ける。疲労・空腹は
  Moving 経由で効くので、状態を直接読む経路を撤去する。
- 命中: `forEachModifierSource` の capacity 畳み込みが実効 Manipulation・Sight を読む。疲労の命中特別扱い
  `fatigueAccuracyDelta` を撤去する。
- 回復: `Metabolism` は実効 Consciousness と睡眠ボーナスと VIT から回復レートを導く。空腹・疲労の直読みを撤去する。

## 採用しなかった方法

- **修飾子パイプラインへ一本化する**: 行動速度・回復を `ModActionSpeed`・`ModRecovery` のキーにして spec 表へ
  載せる。だが修飾子キーは行動スコープの倍率が前提で、全行動へ効く横断ステータスは枠が合わない。`ModMaxWeight`
  という前例はあるが、状態専用ガードや能力値ボーナスの手書きなど歪みが残る。capacity という既存の身体→行動の
  経路があるので、そちらへ寄せる方が一貫する。
- **回復を Blood 駆動にする**: Blood は `BloodLossHPDrain` で HP 減少に直結する。空腹→Blood にすると餓死の
  直接ダメージが付いてくる。今は餓死の直接ダメージは無く回復不能で間接的に死ぬだけなので、副作用の無い
  Consciousness を選ぶ。餓死ダメージの新設は別途 gamedesign で検討する。
- **効果ごとに別係数を残す**: 現状は疲労Tiredが命中×90・速度−15・回復−20 と非対称。Consciousness 1本に
  集約すると全機能が同率で落ち、微調整が効かなくなる。単純さと1経路化を優先し、この非対称は捨てる。

## コメント

Consciousness 1本化により、状態ごとに決めるのは「どれだけ意識を鈍らせるか」だけになる。効果別の
細かな重み付けは失われるが、身体状態が行動へ効く経路が capacity ただ1つになる価値を優先する。
初期オフセットは現状の効き目に近い値を置き、実プレイで調整する。餓死の直接ダメージと、VIT・睡眠の
回復寄与の最終的な重みは実装時に詰める。

## 実装メモ

速度・命中は実効 capacity 経由で一本化した。`CalculateSpeed` は能力値の素の速度に実効 Moving を掛け、
命中は `forEachModifierSource` が実効 Manipulation・Sight を畳む。疲労・空腹は Consciousness を下げ、
Consciousness が Moving・Manipulation・Sight を連動させるので、速度も命中も自動で下がる。命中の疲労
特別扱いと `ModActionSpeed`・`ModRecovery` は撤去した。

回復だけは実効 Consciousness の全量でなく、疲労・空腹の意識低下ぶんだけを読む。Consciousness は怪我・
病気でも下がるため、全量を読むと自分の不調が自分の回復を鈍らせ、回復量の整数切り捨てと重なって
治癒が止まる悪循環になる。怪我・病気は従来どおり回復レートに効かせず、疲労・空腹の効き目だけを
その Consciousness 低下量で表す。速度・命中は行動性能なので怪我の Moving 低下がそのまま効いてよく、
回復は受動レートなので自己参照を避ける、という非対称は意図したもの。
