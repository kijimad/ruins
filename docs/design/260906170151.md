# 疲労・空腹を不調として低体温と同じ経路へ寄せる

## 背景

身体状態が行動へ効く経路は身体機能 BodyFuncs に一本化した。全身性の低下は `EffectiveBodyFuncs` の
1箇所で各機能へ加算で畳む。だが全身性の入力がまだ2系統ある。

- 低体温: 体温 → `TemperatureSystem` が `Hypothermia` 不調を進める → `HealthStatus.BodyFuncs` の
  全身性 → 意識。怪我・病気と同じ不調機構に合流している。
- 疲労・空腹: `Fatigue`・`Hunger` 量 → `EffectiveBodyFuncs` が量を直読みして意識を下げる。
  不調にならず、専用パス `consciousnessPenalty`・`ConsciousnessSources` を通る。

同じ「量由来の全身性」なのに、低体温だけ不調経由で、疲労・空腹は量の直読みという非対称がある。
入力を不調ただ1つに揃えれば、全身性の合流点が完全に1本になり、内訳表示も他の不調と同じ列に並ぶ。

## 要件

- 疲労・空腹も低体温に倣い不調として立て、`HealthStatus.BodyFuncs` の全身性へ合流させる。
- `EffectiveBodyFuncs` の量の直読み `consciousnessPenalty`・`ConsciousnessSources` を撤去する。
  全身性の入力は不調だけになる。
- 量 `Fatigue`・`Hunger` は真実の状態として残す。不調は低体温と同じく量から毎ターン導出する。
- 回復は疲労・空腹で鈍り、怪我・病気では鈍らない、の非対称を維持する。
- ゲーム挙動は原則据え置き。VRT golden 差分が出たら再生成する。

## 設計

### 不調種別を足す

```go
// internal/components/health_status.go
const (
	ConditionExhaustion  ConditionType = "Exhaustion"  // 疲労困憊。疲労の量から毎ターン導出
	ConditionMalnutrition ConditionType = "Malnutrition" // 栄養失調。空腹の量から毎ターン導出
)

// conditionDefs へ追加。全身性なので WholeBody に立て、意識を下げる。
// 低体温と同じく Recovery を持たず、量由来のシステムが severity を管理する
ConditionExhaustion: {
	displayName: "Exhaustion", description: "Worn out. Rest to recover.",
	painPerSeverity: 0, bodyFuncDropPerSeverity: <調整>,
},
ConditionMalnutrition: {
	displayName: "Malnutrition", description: "Starving. Eat to recover.",
	painPerSeverity: 0, bodyFuncDropPerSeverity: <調整>,
},
```

痛みは出さず全身性の機能低下だけ与える。値は現在の意識低下量、疲労 Tired/Exhausted=10/25、
空腹 Hungry/Starving=10/20、に相当する severity へ対応づける。

### 量から不調を同期する

低体温の `TemperatureSystem` に倣い、疲労・空腹のシステムが毎ターン WholeBody の該当不調の severity を
量の段階から立て直す。段階が無害なら不調を外す。量が段階そのものなので Timer 累積でなく
段階から severity を直接設定する。

```go
// 疲労・空腹のシステム内。段階 → severity を立てる。0 段階なら不調を外す
syncGaugeCondition(hs, gc.BodyPartWholeBody, gc.ConditionExhaustion, fatigueSeverity(level))
syncGaugeCondition(hs, gc.BodyPartWholeBody, gc.ConditionMalnutrition, hungerSeverity(level))
```

### 全身性の合流を不調1本にする

`EffectiveBodyFuncs` から疲労・空腹の量の直読みを撤去する。全身性は `HealthStatus.BodyFuncs` が
不調から算出したぶんだけになる。`consciousnessPenalty`・`ConsciousnessSources` は不要になり削除する。
`EffectiveBodyFuncs` は実質 `HealthStatus.BodyFuncs`、非所持なら `HealthyBodyFuncs`、へ縮む。

### 回復は据え置き

`Metabolism` は従来どおり `Fatigue`・`Hunger` 量の段階を直読みして回復ペナルティにする。回復を
不調・意識に載せると怪我・病気でも鈍り、自分の不調が自分の回復を止める悪循環になるため、回復だけは
量の直読みを保つ。速度・命中は不調経由、回復は量経由、の非対称は意図したもの。

## 採用しなかった方法

- **量の直読みを残す（現状）**: `EffectiveBodyFuncs` が疲労・空腹の量を読む。低体温と非対称のまま。
  合流点は1つでも入力が不調と量の2系統に割れる。統一要件を満たさない。
- **低体温を量の直読みへ寄せる（逆方向）**: 不調をやめ全身性をすべて量の直読みにする。だが不調は痛み・
  血液・死因・部位別表示という共有機構を持ち、怪我・病気がすでに乗っている。量側へ寄せると失うものが
  多い。不調側へ揃える方が自然。
- **回復も不調・意識経由にする**: 全身性を完全に1経路へ寄せられるが、怪我・病気が回復を止める悪循環と
  回復量の整数切り捨てで治癒停止が起きる。回復だけ量の直読みを残す非対称を選ぶ。

## コメント

不調は「量由来（低体温・疲労・空腹）」と「イベント駆動（骨折・切り傷）」に分かれるが、`HealthStatus`
への合流と `BodyFuncs` の算出は共通。量由来の同期はどれも「量 → severity を毎ターン立て直す」で
揃う。severity 対応と `bodyFuncDropPerSeverity` は現在の意識低下量に合わせた初期値を置き、実プレイで調整する。
不調名 Exhaustion・Malnutrition は仮。既存の Fatigue・Hunger 表記と揃えるかは実装時に決める。

## 実装メモ

不調は severity を Timer 累積でなく量段階から毎ターン直接立てる。`BodyPartHealth.SetGaugeCondition`
が SeverityNone なら外し、それ以外は severity と整合する Timer を付けて上書きする。疲労 Tired/Exhausted →
Minor/Severe、空腹 Hungry/Starving → Minor/Severe に対応づけ、`bodyFuncDropPerSeverity` は Exhaustion=10・
Malnutrition=8 を初期値にした。severity 倍率は Minor×1・Severe×3 なので全身性は疲労 10/30、空腹 8/24 になる。

効果は不調がシステムで立って初めて出る。量を足しただけの単体テストでは効かないので、query 側の効果
テストは同期後の状態、すなわち WholeBody の Exhaustion・Malnutrition 不調、を直接立てて検証する。量→不調の
同期は systems 側のテストで担保する。

`EffectiveBodyFuncs` は疲労・空腹の量の直読みを撤去し、`raw.Consciousness` に集約された全身性を各機能へ
配るだけになった。回復 `Metabolism` は不調・意識を経由せず `fatigueRecoveryPenalty`・`hungerRecoveryPenalty` で
量を直読みする。Consciousness の内訳は Health タブの不調一覧に出るので、Effects タブの専用内訳は撤去した。
派生不調は HealthStatus に載るので既存の serde でそのまま保存され、ロード後は次ターンの同期で立て直る。
保存方針の追加変更は不要だった。
