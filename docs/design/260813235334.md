# 使う・送る・捨てる: 通信販売による第二の需要をコアに足す

## 背景

ruins の土台は既に固まっている。冷気に呑まれた世界を一方向へ逃げ、道中で漁り、積載の重さがコストを決め、連れ歩く家に暮らし、拾った物で生き延びる。

この土台には一つ穴があった。**拾った物の需要が「自分の生存」ただ一つ**しか無い。食う、燃やす、装備する、直す。そのため一個ごとの判断は二択に痩せる。自分に要るか、要らないか。要らなければ重荷でしかなく、氷へ捨てるだけ。決断が薄く、他のインディーと比べたインパクト不足の一因にもなっていた。

議論の末に出た答えは、コアを差し替えることではなく、**第二の需要を足す**ことだった。線の向こうの買い手へ、通信販売で捌く。同じ一個の物に、自分の身体と市場という二人の需要者が付き、判断が三択に開く。これは土台の置き換えでなく、既存の scavenge ループへ選択肢を一つ足す**加算**である。

コアの決断がより具体になった一方、その面白さはまだ検証されていない。三択が毎ループ悩ましく新鮮かは、遊んで測る以外に確かめようがない。この doc は企画段階の方向整理であり、実装の確定ではない。

## 要件

土台とコアが満たすべき抽象条件。Hard は満たさねば ruins でない、Soft は最大化したい、Anti は踏んではいけない罠。

**Hard**

- アイテムは自分の生存と市場の二つの需要を持つ。同じ物を、使う・送る・捨てるで奪い合う。これが新しいコア
- 一方向で後退は死。戻れる網や循環を作らない
- 移動コストは積載に依存する。重さがコストを決め、何を持つかが決断になる
- footprint は 1x1、自由歩行の単一解像度ワールドを壊さない。売りもこの歩ける世界の中で起きる。歩いて棚から取る
- 持続しカスタム可能な内部空間を持つ。ここが在庫を置きピッキングする場になり、並べ方が取り出しやすさを決める
- 家を連れ歩く。移動拠点が自分と共に動く感触を保つ

**Soft**

- 署名イメージ。一目で読め、他で見ない外観。インパクトの源
- 喪失の情感。運べるのはわずかで二度と戻れない。コアが既に意味していることであり、theme はこれを塗るのでなく露出させる
- 冷気に呑まれた世界、暖が生である premise と一致する
- 孤独で瞑想的な register。注文が遠隔で届くので、世界は空のまま保てる
- 収集がコアに直結する。自分に要らないが売れるかもしれない物を投機的に担ぐと、漁る行為に賭けが生まれる

**Anti**

- 戻る固定市場を作らない。注文は遠隔で届く
- 代金を安全へ貯めさせない。前方の一歩へ即消費する
- 倉庫経営に落とさない。第二の需要はコアの追加であって置き換えでない
- 別画面の店 UI に抽象化しない。ピッキングは歩いて取る手触りが要
- 自分用の消耗品と売却用の loot を別カテゴリに分けない。同じ物を競合させるのが要点
- 乗り物にしない。あらかじめ在る容れ物を動かし内部を飾るだけの着せ替えにしない

## 設計

現時点の傾き。いずれもコア検証を通してから確定する未検証の仮説である。

**1. 第二の需要としての通信販売**

物理世界は凍って死んでも、通信網は生き残っている。散った避難所の生存者が、最後の移動商人であるあなたへ発注する。あなたは彼らを見ない、荷を虚空へ送るだけ。孤独なまま、遠くの誰かが依存している。

注文が遠隔で届くので、物理的な客を歩かせる必要が無く、世界は空で瞑想的なまま保てる。以前は売りに客が要り、孤独な凍原が難民の road になってしまうのが難点だった。通信販売はこれを回避する。

**2. 三択の綱引き**

需要が二つになった瞬間、一個ごとの判断が開く。

```go
// 概念スケッチ。実装の struct でなく、需要の形を示すためのもの。
// アイテムは二つの需要を持つ。
//   自分の生存: 食う・燃やす・装備する・直す
//   市場:       遠隔の注文が来たとき、送って対価を得る
//
// 毎個の判断は三択になる。
//   使う   自分の生存を満たす。物は消える
//   送る   注文を満たし、対価は前方の一歩へ消える。物は消える
//   捨てる 誰も要らない、または重すぎる。氷へ置いていく。物は消える
```

肝は、自分と市場が同じ物を奪い合うこと。多くのゲームは自分用の消耗品と売る用の loot を別カテゴリに分けるが、ruins は同じ一個で競合させる。拾ったパンは、空腹だから食うか、注文が来て通行の対価が要るから送るか、迷ううちに腐るか。生存と経済が同じ資源で綱を引く。

**3. ピッキングとシームレス**

注文が来たら、キューブ内部を歩いて品を取り出し、発送する。別画面の店 UI に抽象化せず、歩ける世界の中で完結させる。これで内部空間が初めて機能を持つ。どう並べたかが取り出し速度を決め、整理そのものが gameplay になる。カスタマイズにやっと意味が宿る。

**4. 腐敗の二重締切**

在庫は shelfLife で傷む。自分が食う前にも、市場へ送る前にも腐る。ピッキングは締切下の判断になり、単なるお使いに落ちない。腐敗が fetch の退屈を救う。

**5. 均衡の不可能さを保つ**

代金は暖・通行・次の一歩を買うだけで、貯めて安全にはできない。留まれば呑まれ、前進しかできず、背後の世界は消える。安住を目指すのでなく、どこまで行けるかを問う。押し返す敵対性は戦闘でなく、寒気と腐敗と積載、そして注文の締切という反応する系が担う。

売りは尊厳ある手放しである。氷に無為に捨てるでなく、誰かに届く価値へ換える。ただし捨ては消えない。全部は捌けず、注文の来ない物や重すぎる物は結局氷へ置いていく。売る手放しと捨てる手放しが共存し続ける。売りが全在庫を掃くようになれば喪失の情感が死ぬ。

**6. 検証を設計判断より先に置く**

上の1から5は全て未検証の仮説である。次の一手は、アートとテーマを剥いだ最小の遊べる形で、三択が毎ループ悩ましく新鮮かを実測すること。数個のアイテムに自分の必要・注文・重量・腐敗を与え、一本道で使う・送る・捨てるを選ばせる。装飾ゼロでも悩ましい良い決断があり、もう一度やりたいと感じるなら、コアは本物であり着飾る意味が生まれる。感じないなら、どの skin も救わないので仮説を替える。

## 採用しなかった方法

- **物理的に陳列して対面で売る**。並べて見せる手触りは良いが、客が要り、孤独な凍原が populated な難民の road になる。瞑想的な register を崩す。通信販売は遠隔注文でこれを回避する。
- **拠点市場へ戻って売る**。売りは厚くなるが、戻る循環を作り、一方向で後退は死という芯と均衡の不可能さに反する。
- **売りをコアに据える店番**。面白く実証済みだが、生存の土台を置き換えてしまう。第二の需要は追加であって置き換えでない。獲得と保持のループに戻れば ruins の固有性が消える。
- **別画面の店 UI に抽象化する**。実装は楽だが、シームレスなタイル歩行と、歩いて取る手触りを捨てる。内部の並べ方が意味を持たなくなる。
- **自分用の消耗品と売却用の loot を別カテゴリにする**。一般的な RPG の作法だが、綱引きが生まれない。同じ物を自分と市場で競合させるのが要点。
- **量そのものを identity にするコンテンツ先行**。砂上の楼閣になる。ただし相互作用の深さを、検証済みコアの乗数として使うのは正当。2D でアニメ不要ゆえ動詞と組み合わせの定義が安く、ターン制ゆえ広い行動空間が可用になる。順序はコア検証が先。

## コメント

- この doc は結論でなく現状の整理である。最大の学びは、拾った物の需要が自分だけだったこと、第二の需要を足すと判断が二択から三択へ開き、それが土台の置き換えでなく加算でコアを厚くすること。
- 三択の面白さはまだ検証されていない。的は鋭くなった。使う・送る・捨ての綱引きが毎ループ悩ましく新鮮か。これは議論で詰めきれず最小形でしか分からない。
- 通信販売の遠隔注文が、世界を空で孤独なまま保つ。populated な road も戻る市場 hub も要らない。ここが対面の陳列売りより ruins の魂に合う。
- 売りは尊厳ある手放しだが、捨ては残さねばならない。売りが全在庫を掃けば喪失テーマが死ぬ。有限容量と腐敗が、常に氷への投棄を残す。
- 外部作品を枠組みには据えない。通信販売とピッキングと腐敗は、ruins 固有の凍原と一方向の逃避の中で自己完結させて設計する。
