# セーブ画面に保存時刻でなくプレイ実時間を表示する

## 背景

セーブ・ロード画面のスロットラベルは現在、保存時刻を `プレイヤー名  MM/DD HH:MM` の形で表示している。
保存時刻より、そのセーブでどれだけ遊んだかの累積プレイ実時間のほうが、続きを選ぶ判断に役立つ。

プレイ実時間は保存時刻から導けない累積量なので、計測して保存する機構が要る。ゲーム内時間 GameTime は
日数・季節を表す別物で、実時間ではない。

## 要件

- プレイ実時間はゲームを遊んでいた wall-clock の累積。ゲーム内経過ではない。
- ラン進行中だけ加算する。メインメニュー滞在は数えない。ラン中のサブメニューは数える。
- セーブに保存し、ロードで継続する。新規開始で0に戻る。
- スロットラベルに `時:分:秒` で表示する。時は無制限、分と秒は0埋め。例 `101:34:07`。
- 保存時刻 Timestamp は残す。ListSaves の最新ロード並べ替えに使うため。

## 設計

### 保存はセーブ封筒、現在値は Resources のセッション状態

累積プレイ実時間の永続の実体は `saveEnvelope.PlayTime`。封筒はラベルの高速部分読みのために既に
PlayTime を持つので、これを唯一の保存先にする。専用の ECS コンポーネントは持たない。持つと封筒と
world スナップショットに二重保存になる。

セッション中の現在値は `Resources` に持つ。`GameTime` のようなシングルトンにはしない。

```go
type Resources struct {
	// ... 既存 ...
	PlayTimeTotal        time.Duration // 累積。ロード時に封筒から seed する
	PlayTimeSessionStart time.Time     // 計測基準。ゼロ値はラン外
}
```

- 新規開始 `ResetForNewGame` で `PlayTimeTotal = 0`、基準を今にセット。
- 再開 `RestoreWorldFromJSON` で `PlayTimeTotal = env.PlayTime` と封筒から seed、基準を今にセット。
- Resources は serde 非対象。封筒が保存を担うので継続できる。

### 加算 — セッション基準からセーブ時に1度畳む

PlayTime はセーブ画面のラベルでしか読まないので、毎フレーム積算する必要はない。セッションの計測基準
`PlayTimeSessionStart` を持ち、セーブのたびに経過を1度だけ畳む。毎フレーム積算の総和は telescoping で
「基準→セーブの経過」に等しく、結果は一致する。

基準は `Resources` に持つ。serde 非対象のセッション状態で、`InputSource` と同じく world 単位で持ち
グローバル可変を作らない。

```go
// セーブ時に畳む。GenerateWorldJSON で呼び、封筒へ書く前に現在値を確定させる
func accruePlayTime(world w.World) {
	start := world.Resources.PlayTimeSessionStart
	if start.IsZero() {
		return // 基準ゼロのラン外は数えない
	}
	now := time.Now()
	world.Resources.PlayTimeTotal += now.Sub(start)
	world.Resources.PlayTimeSessionStart = now
}
```

メインメニュー滞在は基準が未設定なので自然に除外され、ラン中のサブメニューは基準セット後なので数えられる。

### 保存 — envelope が唯一の保存先

`saveEnvelope` に `PlayTime` を足し、保存時に `accruePlayTime` で畳んだ現在値を書き出す。`PlayerName` と
同じくラベル表示で world 全体をロードせずに読める。累積の永続はこの封筒だけが担い、world スナップショットへは
重複させない。

```go
type saveEnvelope struct {
	Version    string          `json:"version"`
	Timestamp  time.Time       `json:"timestamp"`
	PlayTime   time.Duration   `json:"playTime"`
	Checksum   string          `json:"checksum"`
	PlayerName string          `json:"playerName"`
	World      json.RawMessage `json:"world"`
}
```

- 保存時 `PlayTime: extractPlayTime(world)`。`extractPlayTime` は singleton の Duration を返す。
- `GetSavePlayTime(slot) (time.Duration, error)` を足し、`env.PlayTime` だけ部分 unmarshal する。

### 表示 — 時:分:秒

`formatSaveSlotLabel` を保存時刻でなくプレイ時間にする。

```go
d, ptErr := saveManager.GetSavePlayTime(slotName)
if nameErr == nil && ptErr == nil {
	h := int(d / time.Hour)
	m := int(d%time.Hour / time.Minute)
	s := int(d%time.Minute / time.Second)
	return fmt.Sprintf("%s  %d:%02d:%02d", playerName, h, m, s)
}
```

## なぜこの形か

- **保存先を封筒に一本化する**: 封筒はラベルの高速部分読みのため PlayTime を既に持つ。累積を専用コンポーネント
  にも持つと封筒と world スナップショットへ二重保存になる。封筒を唯一の保存先にし、ロード時にセッションへ
  seed する。専用コンポーネント・登録表・生成コード・デバッグ一覧の1行が不要になる。
- **Timestamp を残す**: `ListSaves` の最新ロード並べ替えは Timestamp 降順に依存する。表示をプレイ時間に
  替えても、同定・並べ替えのキーは時刻のまま分離する。
- **セーブ時に1度だけ畳む**: PlayTime はセーブ画面でしか読まないので、毎フレーム積算は不要。基準からの
  経過をセーブ時に1度足せば同じ結果になる。計測基準を run 開始と再開でセットするので、メインメニュー滞在は
  基準未設定で数えず、ラン中のサブメニューは基準セット後なので数える。プレイヤー存在の毎フレーム判定は要らない。

## 採用しなかった方法

- **ゲーム内時間 GameTime を表示する**: 実時間でなく日数・季節。要件と異なる。GameTime とは別に持つ。
- **累積を専用シングルトンコンポーネントに持つ**: world スナップショットへ保存されるが、封筒も同じ値を持つので
  二重保存になる。封筒が保存を担い、ロードで封筒からセッションへ seed すればコンポーネントは要らない。
- **保存時刻 Timestamp を廃してプレイ時間で並べ替える**: プレイ時間は「最後にセーブした順」を表さない。
  最新ロードの意味が壊れる。Timestamp を並べ替えに残す。
- **毎フレーム `time.Since` を積算する**: 総和は telescoping で基準→セーブの経過に等しく結果は同じだが、
  読むのはセーブ時だけなので毎フレームの計測は無駄。基準からセーブ時に1度畳む。
- **フレーム数 × 1/TPS で近似する**: フレーム落ち時に wall-clock からずれる。`time.Since` の実測にする。
