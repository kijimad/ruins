# セーブ画面に保存時刻でなくプレイ実時間を表示する

## 背景

セーブ・ロード画面のスロットラベルは現在、保存時刻を `プレイヤー名  MM/DD HH:MM` の形で表示している。
保存時刻より、そのセーブでどれだけ遊んだかの累積プレイ実時間のほうが、続きを選ぶ判断に役立つ。

プレイ実時間は保存時刻から導けない累積量なので、計測して保存する機構が要る。ゲーム内時間 GameTime は
日数・季節を表す別物で、実時間ではない。

## 要件

- プレイ実時間はゲームを遊んでいた wall-clock の累積。ゲーム内経過ではない。
- ラン進行中だけ加算する。メインメニュー滞在は数えない。ラン中のサブメニューは数える。
- セーブに保存し、ロードで継続する。新規開始で0に戻る。
- スロットラベルに `時:分:秒` で表示する。時は無制限、分と秒は0埋め。例 `101:34:07`。
- 保存時刻 Timestamp は残す。ListSaves の最新ロード並べ替えに使うため。

## 設計

### 保存は envelope、現在値は skipComponents のシングルトン

累積プレイ実時間の永続の実体は `saveEnvelope.PlayTime`。envelope はラベルの高速部分読みのために既に
PlayTime を持つので、これを唯一の保存先にする。world スナップショットへは二重保存しない。

セッション中の現在値は `PlayTime` シングルトンコンポーネントに持ち、`skipComponents` に入れて直列化しない。
`VisionState`・`SpatialIndex` と同じ「world 単位・serde 非対象のセッション状態」の置き場に揃える。

```go
// serde 非対象。永続は envelope。SessionStart は累積が0になる仮想の基準時刻でゼロ値はラン外
type PlayTime struct {
	SessionStart time.Time
}
```

- 登録表に `{Field: "PlayTime"}` を足し `make generate`。`InitSingleton` で付与する。
- `skipComponents` に入れる。ロードでは `reestablishSingleton` が付け直し、`RestoreWorldFromJSON` が基準を
  `now - env.PlayTime` に置いて envelope から復元する。`VisionState` の再構築と同じ流儀。
- 新規開始 `ResetForNewGame` で `SessionStart` を今にセット。以後の経過が累積になる。

### 測る — 基準からの経過を1フィールドで

毎フレーム積算も累積フィールドも要らない。基準時刻 `SessionStart` を「累積が0になる仮想の開始点」とし、
プレイ実時間は `time.Since(SessionStart)` で求める。ロードでは基準を保存値ぶん過去へずらすので、`time.Since`
がそのまま復元後の累積になる。この導出を `query.PlayTimeElapsed` に一本化し、保存と統計表示の両方から使う。

```go
func PlayTimeElapsed(world w.World) time.Duration {
	pt := GetPlayTime(world)
	if pt == nil || pt.SessionStart.IsZero() {
		return 0 // 基準ゼロのラン外は数えない
	}
	return time.Since(pt.SessionStart)
}
```

メインメニュー滞在は基準が未設定なので自然に除外され、ラン中のサブメニューは基準セット後なので数えられる。
`time.Now` の単調時計が効くので、セッション中の壁時計調整にも影響されない。

### 保存 — envelope が唯一の保存先

`saveEnvelope` に `PlayTime` を足し、保存時に `query.PlayTimeElapsed(world)` の値を書き出す。`PlayerName` と
同じくラベル表示で world 全体をロードせずに読める。累積の永続はこの envelope だけが担い、world スナップショットへは
重複させない。

### 統計画面にも出す

`RunStatsState` の Summary タブに「Play time」行を足し、`query.PlayTimeElapsed` を `formatPlayTime` で
時:分:秒に整形して見せる。値は live で、セーブ画面ラベルと同じ導出を共有する。

```go
type saveEnvelope struct {
	Version    string          `json:"version"`
	Timestamp  time.Time       `json:"timestamp"`
	PlayTime   time.Duration   `json:"playTime"`
	Checksum   string          `json:"checksum"`
	PlayerName string          `json:"playerName"`
	World      json.RawMessage `json:"world"`
}
```

- 保存時 `PlayTime: query.PlayTimeElapsed(world)`。`time.Since(SessionStart)` を返す。
- `GetSavePlayTime(slot) (time.Duration, error)` を足し、`env.PlayTime` だけ部分 unmarshal する。

### 表示 — 時:分:秒を右寄せ

`formatSaveSlotLabel` は左ラベル(プレイヤー名)と右寄せのプレイ時間を返す。`formatPlayTime` が時:分:秒へ
整形する。時は無制限、分と秒は0埋め。

```go
func formatPlayTime(d time.Duration) string {
	h := int(d / time.Hour)
	m := int(d % time.Hour / time.Minute)
	s := int(d % time.Minute / time.Second)
	return fmt.Sprintf("%d:%02d:%02d", h, m, s)
}
```

`Choice.Right` に時間を渡すと、`ChoiceMenuState.ViewUI` が `[Name(左), Num(右寄せ)]` の2列で描き、時間が
右端へ揃う。1文字列を空白で押し出すのは比例フォントで崩れるため、列の整列で表す。`Right` を使わない他メニューは
1列のまま。

## なぜこの形か

- **保存先を envelope に一本化する**: envelope はラベルの高速部分読みのため PlayTime を既に持つ。`skipComponents`
  に入れて world スナップショットへは直列化せず、二重保存を避ける。ロードで envelope から seed する。
- **セッション状態は skipComponents のシングルトンに置く**: `VisionState`・`SpatialIndex` と同じく、world 単位で
  serde 非対象のセッション状態はシングルトンコンポーネントに持つのが既存の流儀。Resources はアセット・config 置き場で
  収まりが悪い。
- **Timestamp を残す**: `ListSaves` の最新ロード並べ替えは Timestamp 降順に依存する。表示をプレイ時間に
  替えても、同定・並べ替えのキーは時刻のまま分離する。
- **基準1つで測る**: PlayTime はセーブ画面でしか読まないので、累積フィールドも毎フレーム積算も要らない。基準時刻
  `SessionStart` を「累積が0になる仮想の開始点」とし `time.Since(SessionStart)` で求める。基準を run 開始と再開で
  セットするので、メインメニュー滞在は基準未設定で数えず、ラン中のサブメニューは基準セット後なので数える。

## 採用しなかった方法

- **ゲーム内時間 GameTime を表示する**: 実時間でなく日数・季節。要件と異なる。GameTime とは別に持つ。
- **PlayTime を serde 対象コンポーネントにする**: world スナップショットへ保存されるが envelope も同じ値を持つので
  二重保存になる。`skipComponents` に入れて envelope から復元すれば重複しない。
- **累積とセッション基準を Resources に持つ**: Resources はアセット・config 置き場で、セッション進行状態の収まりが
  悪い。既存の serde 非対象セッション状態は skipComponents のシングルトンに揃える。
- **累積 `Total` と基準 `SessionStart` を両方持つ**: セーブ時に `Total += now - SessionStart` と再ベースする形。
  でもプレイ時間を読むのはセーブ時だけなので、基準を仮想の開始点にすれば `time.Since` の1フィールドで足りる。当初この
  形で、指摘を受け畳んだ。
- **保存時刻 Timestamp を廃してプレイ時間で並べ替える**: プレイ時間は「最後にセーブした順」を表さない。
  最新ロードの意味が壊れる。Timestamp を並べ替えに残す。
- **毎フレーム `time.Since` を積算する**: 読むのはセーブ時だけなので毎フレームの計測は無駄。基準からの `time.Since`
  をセーブ時に1度求める。
- **フレーム数 × 1/TPS で近似する**: フレーム落ち時に wall-clock からずれる。`time.Since` の実測にする。

## リスク・影響範囲

- 未リリースなのでセーブ後方互換は考慮不要。旧セーブに PlayTime が無くてもゼロ値に落ちるだけ。
- セーブ時に `time.Now` を1度呼ぶだけで、毎フレームの計測は無い。
