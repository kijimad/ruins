# セーブ画面に保存時刻でなくプレイ実時間を表示する

## 背景

セーブ・ロード画面のスロットラベルは現在、保存時刻を `プレイヤー名  MM/DD HH:MM` の形で表示している。
保存時刻より、そのセーブでどれだけ遊んだかの累積プレイ実時間のほうが、続きを選ぶ判断に役立つ。

プレイ実時間は保存時刻から導けない累積量なので、計測して保存する機構が要る。ゲーム内時間 GameTime は
日数・季節を表す別物で、実時間ではない。

## 要件

- プレイ実時間はゲームを遊んでいた wall-clock の累積。ゲーム内経過ではない。
- ラン進行中だけ加算する。メインメニュー滞在は数えない。ラン中のサブメニューは数える。
- セーブに保存し、ロードで継続する。新規開始で0に戻る。
- スロットラベルに `時:分` で表示する。時は無制限、分は0埋め。例 `101:34`。
- 保存時刻 Timestamp は残す。ListSaves の最新ロード並べ替えに使うため。

## 設計

### PlayTime シングルトンコンポーネント

累積プレイ実時間を持つ。`GameTime` と同じくシングルトンに載せ、serde 保存対象にする。

```go
// PlayTime はそのランの累積プレイ実時間を保持するシングルトン。ゲーム内時間 GameTime とは別で、
// wall-clock で遊んだ時間を溜める。
type PlayTime struct {
	Duration time.Duration
}
```

- 登録表 `genspec/registry.go` に `{Field: "PlayTime"}` を足し `make generate`。
- `world.go` の `InitSingleton` で `world.Components.PlayTime.Add(singleton, &gc.PlayTime{})` を追加。
  `ResetForNewGame` は `InitSingleton` を呼ぶので、新規開始で0に戻る。
- `skipComponents` には入れない。ロードで継続させるため保存する。

### 加算 — MainGame.Update で実時間を溜める

`MainGame` に前回計測時刻を持ち、毎フレーム `time.Since` を PlayTime へ足す。プレイヤーが存在する
ときだけ加算し、メインメニュー滞在を数えない。

```go
type MainGame struct {
	// ... 既存 ...
	lastPlayTick time.Time // プレイ時間加算の前回計測時刻
}

func (game *MainGame) Update() error {
	// ... 既存 ...
	game.accumulatePlayTime()
	// ...
}

// accumulatePlayTime はラン進行中だけ経過実時間を PlayTime へ足す。プレイヤー不在のメニューでは
// 計測時刻だけ進めて加算しない。
func (game *MainGame) accumulatePlayTime() {
	now := time.Now()
	last := game.lastPlayTick
	game.lastPlayTick = now
	if last.IsZero() {
		return // 初回は基準だけ置く
	}
	if _, err := query.GetPlayerEntity(game.World); err != nil {
		return // ラン外は数えない
	}
	query.GetPlayTime(game.World).Duration += now.Sub(last)
}
```

`query.GetPlayTime(world) *gc.PlayTime` を singleton.go に足す。

### 保存 — envelope へコピー

`saveEnvelope` に `PlayTime` を足し、保存時に singleton から書き出す。`PlayerName` と同じ2段構え
にし、ラベル表示で world 全体をロードせずに読めるようにする。

```go
type saveEnvelope struct {
	Version    string          `json:"version"`
	Timestamp  time.Time       `json:"timestamp"`
	PlayTime   time.Duration   `json:"playTime"`
	Checksum   string          `json:"checksum"`
	PlayerName string          `json:"playerName"`
	World      json.RawMessage `json:"world"`
}
```

- 保存時 `PlayTime: extractPlayTime(world)`。`extractPlayTime` は singleton の Duration を返す。
- `GetSavePlayTime(slot) (time.Duration, error)` を足し、`env.PlayTime` だけ部分 unmarshal する。

### 表示 — 時:分

`formatSaveSlotLabel` を保存時刻でなくプレイ時間にする。

```go
d, ptErr := saveManager.GetSavePlayTime(slotName)
if nameErr == nil && ptErr == nil {
	h := int(d / time.Hour)
	m := int(d%time.Hour / time.Minute)
	return fmt.Sprintf("%s  %d:%02d", playerName, h, m)
}
```

## なぜこの形か

- **PlayerName の2段構えを踏襲する**: 累積は world の singleton に持ち、表示用に envelope へコピーする。
  ラベル表示で world 全体をロードしないという既存の効率を保つ。
- **Timestamp を残す**: `ListSaves` の最新ロード並べ替えは Timestamp 降順に依存する。表示をプレイ時間に
  替えても、同定・並べ替えのキーは時刻のまま分離する。
- **プレイヤー存在で加算をゲートする**: ランの有無を表す最も単純な述語。メインメニューは数えず、ラン中の
  サブメニューは数える、という要件をフラグ無しで満たす。

## 採用しなかった方法

- **ゲーム内時間 GameTime を表示する**: 実時間でなく日数・季節。要件と異なる。GameTime とは別に持つ。
- **PlayTime を Resources に持つ**: Resources は serde 非対象なので保存されない。継続に singleton
  コンポーネントが要る。
- **保存時刻 Timestamp を廃してプレイ時間で並べ替える**: プレイ時間は「最後にセーブした順」を表さない。
  最新ロードの意味が壊れる。Timestamp を並べ替えに残す。
- **フレーム数 × 1/TPS で近似する**: フレーム落ち時に wall-clock からずれる。`time.Since` の実測にする。
