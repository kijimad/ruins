# 疲労と睡眠を追加する

## 背景

眠る必要が無い世界では夜は単なる暗い時間で、拠点・寝具・安全の確保に意味が生まれない。疲労を蓄積させ、睡眠でしか返済できなくすることで、「安全で適温の寝床を確保する」というサバイバルの中核行動を作る。

前提の環境系は揃っている。周囲気温は場所依存（`AmbientTemperatureAt`、doc 260902002227）、快適帯は装備断熱込みで導出でき（`ComfortableRange`）、健康系は condition/回復/代謝が確定済み。生理系の駆動はターン終了バッチ（`runTurnEndSystems`: Temperature→HealthRegen→Condition→Fire→DeadCleanup）と `progressTurnHunger` にある。

既存の関連機構:

- `Hunger`（`internal/components/hunger.go`）: Current/Max + 比率しきい値の `GetLevel()`。疲労はこれと同型にする。
- `query.Metabolism`（`internal/world/query/metabolism.go`）: 保存 component を持たない都度計算ビュー。VIT と空腹段階から HP 回復・病気回復の速度係数を返す。呼び出し元は health_regen.go と condition.go の2つ。
- 効果倍率ビュー `query.ModifierValue(world, entity, key)`（`internal/world/query/modifiers.go`）: 空腹進行 `ModHungerProgress`・移動コスト `ModMoveCost`・武器命中 `Mod*Accuracy` などを Skills・Abilities・HealthStatus から都度計算する。CharModifiers は #751 で保存 component から都度計算ビューへ移行済みで、命中は既に HealthStatus の身体機能を畳んでいる。読み取り時導出なので毎ターン変わる入力を足しても再計算コストや dirty 管理の問題が無い。疲労のペナルティはこのビューに乗せられる。
- `RestBehavior`（`internal/activity/rest.go`）: 複数ターンの休息 activity。安全検査・中断・再開の枠組みは流用できるが、生理系に未接続の別概念。
- 寝具: prop `bed` は寝室生成で配置済み。現状は装飾で、相互作用を持たない。

## 要件

- 疲労が起きている間に蓄積し、睡眠でのみ回復する。寝ないと段階的にペナルティを受ける。だから眠らないといけない。
- 温度が快適帯に近くないと入眠できない。
- 睡眠中は代謝が下がって消費を抑えつつ、回復効果が高い。消費抑制と回復増加は別係数にする。
- 寝具によって睡眠効率が変わる。
- 起きる時間は指定できない。疲労が抜けるか、外因で中断されるまで眠る。
- 昼寝しすぎると夜眠れなくなる。
- 敵も NPC も同じ機構に乗れる余地を残すが、必須スコープはプレイヤーのみ。

## 設計

新しい状態は2つだけ。蓄積量 `Fatigue` と、睡眠中マーカー `Sleeping`。それ以外はすべて既存の都度計算経路への分岐追加で実現し、保存 component を増やさない方針（doc 260830 系、TemperatureTrend 廃止と同じ線）を守る。

### データ定義

```go
// Fatigue は蓄積した疲労を持つコンポーネント。起きている間に増え、睡眠でのみ減る
type Fatigue struct {
	Current int // 蓄積した疲労
	Max     int // 上限。到達すると行き倒れる
}

// FatigueLevel は疲労の段階
type FatigueLevel string

const (
	FatigueRested    FatigueLevel = "Rested"    // 快調。眠れない（寝すぎ防止）
	FatigueNormal    FatigueLevel = "Normal"    // 普通。眠れる
	FatigueTired     FatigueLevel = "Tired"     // 疲労。回復が落ちる
	FatigueExhausted FatigueLevel = "Exhausted" // 過労。重いペナルティ
)

// GetLevel は Current/Max の比率から段階を返す。しきい値は Hunger と同じ形式
// Rested: <30% / Normal: <50% / Tired: <80% / Exhausted: >=80%
func (f *Fatigue) GetLevel() FatigueLevel

// Sleeping は睡眠中マーカー。SleepBehavior の開始で付き、起床・中断で外れる。
// 空腹進行と Metabolism がこの有無で分岐する
type Sleeping struct {
	Quality consts.Percent // 寝具の睡眠効率。地べた100
}
```

数値の初期案（すべて実プレイで調整する暫定値）:

| 定数 | 値 | 意味 |
| --- | --- | --- |
| `DefaultMaxFatigue` | 2000 | 起床 +1/ターンで約1.3日ぶん |
| 蓄積 | +1/ターン | 起きている間。fast-forward 中も同じ |
| 睡眠回復 | −6/ターン × Quality% | 地べたで約330ターン、bed で約220ターンの本睡眠 |
| 入眠しきい値 | 30%（Rested の上限） | これ未満では眠れない |

### 疲労の蓄積とペナルティ

蓄積はターン終了バッチの `progressTurnHunger` と並ぶ `progressTurnFatigue` で行う。`Sleeping` が無ければ +1。

ペナルティは既存の都度計算経路への写像で、専用機構を作らない。段階が上がるほど回復が鈍り、動きが遅くなり、手元が狂う。疲労は空腹と対の生理ゲージなので、空腹が既に効いている経路にそのまま並べる。

| 段階 | 回復（`Metabolism`） | 行動速度（`Speed`） | 命中（`Mod*Accuracy`） | HUD |
| --- | --- | --- | --- | --- |
| Rested / Normal | ±0 | ±0 | ±0 | なし |
| Tired（50%〜） | −20% | −15 | ×90% | バッジ黄 |
| Exhausted（80%〜） | −40% | −35 | ×75% | バッジ赤 |
| Max 到達 | 強制入眠。温度・安全条件を無視し Quality 50% の行き倒れ | | | |

- **回復の鈍り**は `query.Metabolism` に段階分岐を足す。すでに Hunger の段階で分岐しており、同じ形で `Fatigue.GetLevel()` を読む。HP 自然回復と病気回復が遅くなる。
- **行動速度の低下**は `calculateStatusSpeedPenalty`（`internal/world/query/turn.go`）に足す。ここは既に空腹が速度を落としている関数で、疲労は空腹のすぐ隣に段階ペナルティを並べる。行動速度は移動だけでなく全行動のターン頻度に効くので、「疲れると何をするのも遅い」が成立する。移動コスト `ModMoveCost` は速度の一入力にすぎず、疲労で狙うのは全体の行動速度なのでこちらの上位経路を使う。
- **命中の低下**は #751 で解けた。CharModifiers が都度計算ビューへ移行し、効果倍率は `query.ModifierValue` が Skills・Abilities・HealthStatus から読み取り時に導出する形になった。疲労は entity が持つもう1つの入力として、各武器の命中キーにだけ段階倍率を掛ける。命中が既に HealthStatus の身体機能を畳んでいるのと同じ畳み方で、疲労は独自の内訳ソースとして加える。値と内訳を同じ関数から導く不変条件を保つため、query 層で最終値だけ後掛けするのでなく、ビューの導出に疲労を入力として通す。

空腹と疲労は同じ2経路（回復と速度）を共有し、疲労はさらに命中にも効く。回避は対応する身体機能が現状のコードに無いため対象から外す。

疲労を身体機能そのもの（`HealthStatus.Capacities()`）の入力にはしない。疲労は時間で満ち欠けする生理ゲージで、器質的な体の状態とは層が違う。ビューの独立した内訳ソースとして扱うことで、この区別を保ったままペナルティを乗せる。

### 入眠条件

「眠る」の Validate は3条件の AND。1つでも欠けると理由付きの UserError を返す。

1. **疲労がある**: `GetLevel() != FatigueRested`。回復しきった直後や昼寝で疲労を抜いた後は眠れない。「昼寝しすぎると夜眠れない」はこの1条件から創発する。昼に疲労を使い切れば、夜に蓄積が戻るまで入眠できない。
2. **適温に近い**: 新設の述語 `CanSleepTemperatureAt(world, entity)` を `internal/systems/temperature.go` に置く。`AmbientTemperatureAt` と `ComfortableRange(CalculateEquippedInsulation)` を組み、快適帯を margin ぶん広げた範囲に周囲気温が入っているかを返す。margin は寒側 5℃・暑側 5℃ の暫定。寒すぎる屋外では火を焚くか屋内に入らないと眠れない。
3. **周囲が安全**: 既存の `isAreaSafe`（rest と同じ）。

### 睡眠アクティビティ

`SleepBehavior` を `internal/activity/sleep.go` に新設する。rest の枠組みを流用するが、進行の意味論が違う。rest は必要 AP を消化して終わる作業で、睡眠は**疲労が抜けるまで続く**。TotalRequiredAP は使わず、DoTurn ごとに疲労を減らし、起床条件で Complete する。

継続アクティビティの規約（ruins-review）どおり、DoTurn 冒頭で毎ターン検査する:

- **起床（正常終了）**: `Fatigue.Current <= 0`。起きる時間は指定できない。
- **中断**: 敵が近づいた（isAreaSafe 否定）/ 低体温 condition が発生した（火が消えて冷えたら目が覚める）/ 空腹が飢餓段階へ落ちた。
- 睡眠中も世界は毎ターン進む。温度・回復・火の燃焼は通常どおりターン終了バッチが回す。

`Start` で `Sleeping{Quality}` を付け、`Finish`/`Canceled` で外す。マーカーの Add は `Has` ガード付き（二重 Add パニック回避）。エンティティ参照は持ち越さない。寝具は開始時に足元・隣接から解決して Quality だけを写す。

### 寝具

寝具の質は raw の prop へ新フィールドで持たせる:

```toml
[[props]]
id = "bed"
[props.bedding]
quality = 150
```

`Bedding` component（`Quality consts.Percent`）を追加し、raw→spec の写像と tsp スキーマ（`oas/typespec`）を拡張する。眠る場所の解決は「自タイルか隣接に Bedding prop があれば最大の Quality、なければ地べた 100%」。bed は blockPass なので上に立てず、扉と同じ隣接相互作用 `InteractionSleep` で眠る。地べた寝はアクションメニューから。

Quality の効き先は2つで、どちらも乗算:

- 疲労回復速度: −6 × Quality/100 /ターン。良い寝具ほど短時間で疲労が抜ける。
- 睡眠中の回復ボーナス（下記）にも乗る。

### 睡眠中の代謝と回復。別係数の2チャネル

「消費を抑える」と「回復を高める」は独立した既存チャネルに分岐を1つずつ足す。Metabolism を一括で動かすと両方が連動してしまうため、分ける。

| 効果 | チャネル | 分岐 |
| --- | --- | --- |
| 腹が減りにくい | 空腹進行 `progressTurnHunger`（`query.ModifierValue(ModHungerProgress)` を読む） | `Sleeping` があれば進行 ×50% |
| 回復が高い（免疫上昇） | `query.Metabolism` | `Sleeping` があれば +50% × Quality/100 |

Metabolism は HP 自然回復（health_regen.go）と病気回復（condition.go）の両方の速度係数なので、この1分岐で「傷も病気も寝ると治りやすい」が同時に成立する。疲労ペナルティ（Tired/Exhausted の減算）とは加算合成になるが、Sleeping 中は疲労が減っていく途中なので、眠り続ければペナルティ帯を自然に抜ける。

### HUD

空腹バッジと同型で、Tired/Exhausted のとき `StatusBadges` に段階名を出す（黄/赤）。Rested/Normal は出さない。睡眠中は activity の進行表示に任せ、専用 UI は作らない。

## 採用しなかった方法

- **疲労を HealthStatus の condition として表現する**。condition は部位・重症度・タイマーを持つ傷病の意味論で、全身の生理蓄積量とは形が合わない。Hunger が独立 component である以上、対になる疲労も同型が一貫する。
- **疲労を身体機能（`HealthStatus.Capacities()`）の入力にする**。身体機能は器質的な体の状態の写像で、時間で満ち欠けする生理ゲージとは層が違う。Hunger も身体機能に入れず段階をビューが読む形であり、疲労も同じ側に置く。命中・行動速度のペナルティは身体機能を経由せず、効果倍率ビューの独立した内訳ソースとして加える。なお #751 以前は「毎ターン変わる値を保存型 CharModifiers の入力にすると再計算が毎ターン dirty になる」頻度問題も理由だったが、都度計算ビューへの移行で解消した。残る理由は生理ゲージと器質的状態の層の違いだけで、これは移行後も変わらない。
- **概日リズム（体内時計）を持つ**。時間帯で入眠可否を直接制御する案。閾値式（Rested では眠れない）だけで「昼寝しすぎると夜眠れない」が創発するため、状態を増やす理由がない。
- **行動で消費するスタミナ**。ダッシュや強撃のゲーティングに使う消費資源は疲労と別機能で、要件にも無い。疲労は時間蓄積のみとし、混ぜない。
- **起床時間の指定**。要件で明示的に不可。中断可能な本睡眠のみ。
- **rest（休息）への統合**。rest は「AP を消化する短い作業」で、疲労も温度条件も持たない。意味論を混ぜると両方の Validate と進行が分岐だらけになる。睡眠を別 Behavior にし、将来 rest を廃止するかは実プレイで判断する。
- **睡眠専用の早送り機構**。ターン終了バッチは fast-forward で毎ターン回る前提が既にあり、燃え尽きた火が数ターン残らない保証もそこにある。既存の複数ターン activity 進行に乗るだけでよい。

## コメント

- **#751 で凍結が解けた**: CharModifiers の都度計算ビュー化が main に入り、行動能力ペナルティを本ドキュメントのスコープへ戻した。当初はビュー化中の worktree と衝突するため Metabolism 減算までに留め、命中・速度を別 doc へ先送りしていた。移行完了により効果倍率ビュー `query.ModifierValue` へ疲労を入力として通せるようになり、回復・速度・命中の3軸を1つの doc で扱える。
- **敵・NPC への適用**: 機構は entity 単位で対称だが、敵 AI に睡眠行動を組む価値は現状ない。Fatigue を持たせなければ何も起きないので、余地だけ残して実装しない。
- 温度系との噛み合いが本命。冬の屋外では眠れず、屋内か火のそばを確保して初めて眠れる。凍える夜に火が消えると目が覚める。場所依存温度（doc 260902002227）が睡眠の前提条件として効き始める。
