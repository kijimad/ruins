# 体温ステータスの導入

## 背景

温度まわりは環境からダメージタイマーへ直結しており、体温という中間状態が無い。このため次の問題が繰り返し出た。

- HUD の変化矢印が「環境圧力」と「実際の変化」のどちらを示すべきか定まらない。火のそばで矢印が動かない、逆に実変化が無いのに動く、の間で揺れた
- タイマー更新の合成規則が実処理と表示側に鏡写しで重複し、片方だけ変えると表示が黙ってずれる
- 熱源が「低体温タイマーの回復」専用で、体温が正常だと何も起きず、火の存在がプレイヤーに伝わらない

体温を実在の値として持てば、矢印は「実在の値の実変化」になり意味論の議論が消える。熱源は体温を上げる存在になり、回復はその結果として導かれる。

## 要件

- 体温を全身の状態として保持し、HP ゲージの下にゲージ表示する
- 環境と熱源が体温を動かし、体温が正常帯を外れたときだけ低体温・高体温タイマーが進む
- 体温の1ターン変化は1つの純関数にまとめ、実処理と HUD 矢印が同じ関数を使う

## 設計

### データ

体温は平熱からのオフセットで持つ。ゼロ値が平熱という中立を意味し、ロジックは偏差だけを扱えて表示用の基準温度が混ざらない。

```go
// HealthStatus は部位ごとの健康状態を管理するコンポーネント
type HealthStatus struct {
	Parts [BodyPartCount]BodyPartHealth
	// BodyTempOffset は平熱からの体温のずれ。摂氏。0 が平熱で、寒さで負、暑さで正へ動く。
	// bodyTempMin..bodyTempMax にクランプする
	BodyTempOffset float64
}
```

表示は `36.5 + BodyTempOffset` を1桁小数で出す。

### 体温の1ターン変化

環境レートと熱源を合算した純関数を1つ置き、実処理の適用と HUD 矢印の表示が同じ関数を読む。

```go
// bodyTempRate は現在地の環境が1ターンに動かす体温変化を返す。温まる向きが正
func bodyTempRate(world w.World, entity ecs.Entity) float64
```

- レートは有効温度の区分ごとの離散値。寒い -0.1、非常に寒い -0.2、極寒 -0.5、暑い +0.1、非常に暑い +0.2 °C/ターン。有効温度は従来どおり装備断熱を適用する
- 熱源は `heatSourceWarmthAt` の距離減衰値をそのまま加算する。ただし平熱以上では効かせず、焚き火で高体温になる事故を防ぐ
- 環境も熱源も動かさないときは平熱へ向けて毎ターン 0.1 戻る。恒常性の表現

### タイマーの発動

体温が正常帯 ±2.0 を外れたときだけ従来のタイマー機構が進む。帯からの超過が深いほど速く進み、帯内では従来どおり自然回復する。熱源による直接のタイマー回復 `applyHeatSourceRecovery` は廃止し、回復は体温が帯内へ戻った結果として導かれる。

```go
// 帯外の超過 excess °C に応じたタイマー進行。帯の縁で 0.25、超過1°Cごとに +0.25、上限 1.0
timerDelta = min(0.25+0.25*excess, 1.0)
```

CharModifiers の進行倍率はタイマー進行に掛ける。体温の物理は倍率の影響を受けない。

### HUD

- HP ゲージの下に体温ゲージを表示する。中央が平熱で、左へ冷え、右へ火照る。クランプ幅を 0..1 に写した割合で描き、塗り色は平熱の白から冷えるほど青、火照るほど赤へ寄せる
- 抽出は `GameInfoData` に割合を追加し、描画は `game_info.go` が既存の `drawGaugeBar` を流用する
- 変化矢印の delta は `bodyTempRate` の戻り値に置き換える。向き・色・常時表示の仕様は変えない
- 状態バッジは従来どおり condition を読むだけで変更しない

## 採用しなかった方法

- **絶対温度で保持する**: ゼロ値が 0°C という異常値になり、生成時の初期化を忘れると凍死状態から始まる。平熱オフセットならゼロ値=健康で初期化が不要
- **平衡温度への漸近モデル**: 環境から平衡体温を算出し差分比例で近づける。滑らかだが平衡式とゲイン調整という新しいバランス面が2つ増える。刻みレート方式は既存 calcTimerDelta の実績値を流用でき調整項が少ない
- **専用コンポーネント化**: 体温は導出不可能な積分状態なので保存は必要だが、身体状態として HealthStatus に置けば serde 追加登録も新規クエリも要らない
- **タイマー直結の現状維持+規則の関数共有**: 重複は消えるが、矢印の意味問題と火の無反応は残る

## コメント

- 帯 ±2.0、クランプ、レート値は実プレイで調整する前提の初期値
- 表示の平熱 36.5 は表示だけの basis で、ロジックはオフセットのみを扱う
