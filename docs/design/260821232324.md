# 身体モデル: 部位ごとのHPと傷、そして病気の免疫レース

## 背景

身体ペナルティと病気を、部位ごとの HP と傷で表す。RimWorld と CDDA はどちらも部位ごとに HP を持ち、部位ごとの傷を並べて見せる。単独ターン制サバイバルという同ジャンルの CDDA が、この形で成立している。ruins も同じ土俵なので、この形を採る。着想元は参照するが機構は輸入せず、設計は ruins 既存の語彙で自己完結させる。

現状:

- HP は単一プール `type HP Pool[int]`。ダメージは `gameaction.ApplyDamage` の1経路で単一プールを削り、0で死亡する。
- 部位 `BodyPart` enum。頭・胴・腕・手・脚・足・全身。`HealthStatus{Parts [BodyPartCount]BodyPartHealth}` が部位ごとに `Conditions` を持つ。部位 HP は無い。
- `HealthCondition`。RimWorld の hediff に相当。`Type`・`Severity`・`Timer`・`Effects []StatEffect`。`StatEffect` は `stats_changed.go` を経て6能力へ配線済みで、ペナルティは戦闘に効く。現状は体温 `Hypothermia`・`Hyperthermia` にしか使われていない。
- `Abilities` 6種 STR/SEN/DEX/AGI/VIT/DEF。ruins はこれを capacity として戦闘式へ流している。

方針転換の核は2つ。**単一 HP を廃し、HP を部位ごとに持たせる**こと。そして**命中部位に傷を残し、部位ごとに並べて見せる**こと。狙いはドラマと手応えである。攻撃が相手のどこに何の傷を残したかが見え、致命部位を狙う意味が生まれる。次のような表示を目標にする。

```
相手
  左腕: 裂傷  出血
  胴体: 刺し傷 出血大
```

ただし**機能低下は引き続き既存6能力への `StatEffect` で表す**。HP は部位へ割るが、capacity 層は新設しない。部位 HP は耐久、機能は6能力、と役割を分ける。これは RimWorld の連続 capacity 層まで作り込まず、CDDA 式の部位 HP に寄せた中庸である。

この身体モデルへ、病気の免疫レースを重ねる。病気と負傷は設計 doc `260821223229` の一方向逃避を削る消耗圧、薬は前方へ消費する資源、致死は run の終端になる。単独機能でなくマクロループの生存圧を厚くする。

## 要件

Hard は満たさねばならない、Soft は最大化したい、Anti は踏んではいけない罠。

**Hard**

- HP を部位ごとに持つ。単一プールを廃す。命中部位が HP・傷・機能に効く。
- 機能低下は既存6能力への `StatEffect` に写す。capacity 層を新設しない。部位 HP は耐久に徹する。
- 命中部位に傷が残り、部位ごとに並べて見せられる。攻撃した手応えとドラマを成立させる。
- 病気は悪化と免疫の競走で決着する。severity が振り切れば悪化継続、免疫が先に満ちれば治癒。
- 発症源を既存機構へ配線する。寒冷は体温系、腐敗食は `Perishable`、負傷は戦闘。新たな乱数源を単独で持ち込まない。
- 致死は run を終える。`260821223229` の `RunOutcome` 終端へ接続する。

**Soft**

- 部位ごとの傷が並び、どこを攻撃したかが読める。戦術の的が生まれる。
- 治療で悪化を鈍らせ部位を癒す counterplay がある。薬は前方消費の資源で、貯め込む装置にしない。
- 予防と対処の読みが生まれる。腐敗食を食うか飢えるか、寒空に留まるか進むかの賭け。
- 既存スキルを再利用する。`SkillHealing` は治療効果、resist 系は発症・進行の鈍化に効かせる。

**Anti**

- capacity 層を輸入しない。機能低下は6能力で表す。部位 HP と混ぜない。
- 全快の安全地帯を作らない。`260821223229` の Anti を継承し、治療は前進の合間に前方資源で行う。
- 発症を完全乱数にしない。曝露や選択に紐づけ決定論寄りに保つ。
- 単一 HP へ戻さない。致命部位の意味と傷のドラマを殺す。

## 設計

### 全体方針

身体を部位ごとに表す。各部位が HP と傷と条件を持つ。HP を部位へ移し、機能低下は既存6能力の `StatEffect` のまま。新概念は病気の免疫レースだけに絞る。

### ① 部位 HP: 単一プールを部位へ移す

`BodyPartHealth` へ HP を足し、ここを HP の source of truth にする。単一プール `HP Pool[int]` は廃す。左右を区別するため、腕・手・脚・足は左右へ分ける。

```go
// BodyPartHealth は1部位の状態。部位ごとの HP と傷と条件を持つ
type BodyPartHealth struct {
	HP         int               // 部位の現在耐久。単一プールを置き換える
	MaxHP      int               // 部位の最大耐久。VIT と部位係数から算出
	Wounds     []Wound           // この部位に残る傷。ドラマと出血の単位
	Conditions []HealthCondition // 病気・体温など部位に付く状態
}
```

`MaxHP` は VIT を基準に部位係数で配分する。胴が最も高く、頭が続き、四肢は低い。

```go
// partHPFactor は部位ごとの最大耐久の配分。VIT に掛けて MaxHP を出す
var partHPFactor = map[BodyPart]float64{
	BPTorso: 1.0, BPHead: 0.6,
	BPArmLeft: 0.5, BPArmRight: 0.5, BPLegLeft: 0.5, BPLegRight: 0.5,
	BPHandLeft: 0.3, BPHandRight: 0.3, BPFootLeft: 0.3, BPFootRight: 0.3,
}
```

**死亡モデルは RimWorld を参考にする**。CDDA のように失血を胴 HP へ畳まず、失血を全身の独立値として持ち、致命部位の破壊とは別チャンネルにする。

```go
// HealthStatus へ全身の失血を足す。出血する傷の合計で増え、止血と安静で減る
type HealthStatus struct {
	Parts     [BodyPartCount]BodyPartHealth
	BloodLoss float64 // 全身の失血 0-100。満ちると失血死
}
```

- **失血死**: 全身の `BloodLoss` が満ちると死亡する。出血する傷の bleed rate の合計が毎ターン加算し、止血と安静で減る。負傷死の主経路で、RimWorld の血液喪失に相当する。
- **即死**: 頭 か 胴 の HP が0で死亡する。RimWorld の脳・心臓の破壊に相当する。器官ツリーは作らず、頭と胴を vital 部位として扱う。
- **四肢の破損**: 腕・手・脚・足の HP が0でも死なない。破損として強い `StatEffect` ペナルティにする。腕は DEX、脚は AGI を大きく削る。

RimWorld の3つ目の死因である意識喪失は、consciousness capacity を新設せず vital 部位の破壊へ畳む。心臓の破壊を胴 HP 0 の即死として直接表し、capacity 層を増やさない Anti を守る。

### ② 傷: 命中部位に残るドラマ

被弾ごとに部位へ傷を残す。傷が芝居と出血の単位になる。

```go
// WoundType は傷の種類。武器の性質から決まる
type WoundType int

const (
	WoundLaceration WoundType = iota // 裂傷。斬撃
	WoundStab                        // 刺し傷。刺突
	WoundBlunt                       // 打撲。打撃
	WoundGunshot                     // 銃創。射撃
	WoundBurn                        // 熱傷。火
)

// Wound は部位に負った1つの傷
type Wound struct {
	Type     WoundType
	Bleeding float64 // 出血の強さ。合算して毎ターン全身の BloodLoss を上げる。0で止血
	Severity float64 // 深さ。機能ペナルティと治療難度に効く
}
```

傷の種類は既存の武器スキルから導く。別テーブルを持たず単一の写像で変換するので、武器を増やせば傷も自然に増える。

```go
// weaponWound は武器スキルから傷の種類を導く
var weaponWound = map[SkillID]WoundType{
	SkillSword:   WoundLaceration, // 斬 → 裂傷
	SkillSpear:   WoundStab,       // 突 → 刺し傷
	SkillFist:    WoundBlunt,      // 打 → 打撲
	SkillBow:     WoundStab,       // 射 → 刺し傷
	SkillHandgun: WoundGunshot,    // 銃 → 銃創
	SkillRifle:   WoundGunshot,
	SkillCannon:  WoundGunshot,
}
```

演出はログと敵ステータスの両方へ出す。命中時に `左腕を切り裂いた！ 出血` とログし、敵ステータス欄へ部位ごとの傷を並べる。深い傷は `StatEffect` で敵の命中や移動を削り、傷が戦術へ跳ね返る。

### ③ ダメージ経路: ApplyDamage を部位対応へ

単一の入口 `gameaction.ApplyDamage` は保ち、その中で部位を扱う。命中部位を選び、その部位の HP を削り、武器由来の傷を残し、致死部位が0になったら死亡させる。命中部位は部位サイズの重み抽選で決める。胴が最も当たりやすい。

```go
// hitWeight は部位サイズで重み付けした命中抽選。胴が最も当たりやすい
var hitWeight = map[BodyPart]int{
	BPTorso: 40, BPHead: 8,
	BPArmLeft: 12, BPArmRight: 12, BPLegLeft: 12, BPLegRight: 12,
	BPHandLeft: 2, BPHandRight: 2, BPFootLeft: 1, BPFootRight: 1,
}
```

将来は狙撃で部位を指定できるよう拡張する。ダメージ入口を1つに保つので、部位ロジックはその中の1ステップに閉じ、rest や回復や serde を巻き込まない。

### ④ 病気の免疫レース

RimWorld の病気は悪化と免疫の競走で、severity が上がりきると死、免疫が先に満ちると治癒する。`HealthCondition` は `Timer` が上下するだけでこの競走が無い。ここだけ足す。

```go
// HealthCondition に免疫を足す。病気系の条件だけが使う
type HealthCondition struct {
	Type     ConditionType
	Severity Severity
	Timer    float64 // 悪化度 0-100。既存のまま
	Effects  []StatEffect
	Immunity float64 // 免疫 0-100。病気系のみ。Timer より先に100へ着けば治癒
}

// DiseaseSystem は病気系条件の悪化と免疫を毎ターン進め決着させる。
// 新規 system なので InitializeSystems へ登録する。呼び出しリストへ足すだけでは黙ってスキップされる。
type DiseaseSystem struct{}
```

### ⑤ 新 ConditionType 群と発症源

病気系の条件を足し、既存の曝露・選択へ発症源を紐づける。新たな乱数源を単独で持たない。

```go
const (
	ConditionInfection ConditionType = "Infection" // 感染創。深手の化膿。免疫レースを持つ
	ConditionFlu       ConditionType = "Flu"       // 風邪。寒冷曝露。免疫レースを持つ
	ConditionPlague    ConditionType = "Plague"    // 疫病。腐敗食の摂取。免疫レースを持つ
)
```

- **寒冷**: `Hypothermia` が Severe まで進んだら風邪の発症判定。体温系の延長。
- **腐敗食**: `Perishable` の rotten 段階を食べたら疫病の発症判定。腐敗 doc `260815125506` の劣化段階を入力にする。
- **負傷**: 深い傷を手当てせず放置したら感染創の発症判定。②の傷から連鎖する。

### ⑥ 治療アクション

薬アイテムを消費して、部位 HP を癒し、出血を止め、病気の悪化を鈍らせる。これが `260821223229` の経済③の sink になる。金で薬を前方注文し、前進の合間に使う。全快の安全地帯は作らない。治療効果は既存 `ModHealingEffect`・`SkillHealing` を再利用して算出する。

### ⑦ 致死から run 終端へ

頭か胴の HP が0、全身の `BloodLoss` が満ちる、病気の悪化が振り切って免疫が負ける、のいずれかで run を終える。`260821223229` の `RunOutcome` に病死・失血死の `OutcomeKind` を足して接続する。消耗が最終的にマクロループの終端へ合流する。

## 採用しなかった方法

- **単一 HP を残し、傷は条件だけで表す**。HP は割らず、命中部位を倍率と条件の宛先にする。却下。攻撃した手応えとドラマが薄く、致命部位の意味が HP のレベルに出ない。同ジャンルの CDDA が部位 HP を採る。部位 HP へ移す判断を優先した。
- **RimWorld の連続 capacity 層を輸入する**。部位機能を Consciousness・Manipulation などの派生層で持つ。却下。ruins は6能力を既に capacity として戦闘式へ流している。機能は6能力への `StatEffect` で表せ、部位 HP と役割を分けたほうが軽い。
- **失血を胴 HP へ畳む CDDA 式**。血液を独立させず、出血を胴の耐久として扱う。却下。RimWorld を参考に失血を全身の独立値にした。出血は構造ダメージと別の脅威で、止血と安静という固有の回復を持つ。胴 HP と分けたほうが挙動が読みやすい。
- **器官ツリーと consciousness capacity まで作り込む**。心臓・肺の器官と、それらから算出する意識を持つ。却下。失血と vital 部位の2チャンネルで RimWorld の死は表せる。器官ツリーと capacity 層は必要が証明されてから。YAGNI。
- **発症を完全乱数にする**。毎ターン一定確率で病気を振る。却下。理不尽で予防と対処の読みが消える。曝露と選択へ紐づける。

## コメント

HP は最も配線された component で、移行は慎重に行う。単一プールの読み手が広いので、移行中は部位 HP の合計を派生値として表示や既存呼び出しへ渡し、段階的に部位対応へ寄せる。serde の影響が大きいので `ruins-review` の serde 観点で必ず点検する。

数値は着手後に測る。部位係数・命中重み・出血の減量・免疫ゲイン速度・薬の効きは、最小で組んで一周遊んでから別 doc で定める。`260821223229` と同じく、まだ触っていない手応えを机上で決め打たない。

死亡モデルは RimWorld を参考に確定した。失血は全身の独立値 `BloodLoss`、即死は頭胴の vital 破壊、意識喪失は vital 破壊へ畳む。`BloodLoss` の上限・加算率・回復率は着手後に測る。
