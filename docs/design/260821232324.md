# 身体ペナルティと病気: 既存 hediff エンジンに免疫レースと発症源を足す

## 背景

ruins には既に、部位ごとに健康状態を持ち、重症度に応じて能力へペナルティを与える汎用エンジンが実装済みだった。RimWorld の hediff とほぼ同型で、戦闘への配線まで済んでいる。着想元として RimWorld の病気モデルを参照するが、機構は輸入せず、借りるのは免疫レースという1つのアイデアだけに留める。設計は ruins 既存の語彙で自己完結させる。

既存機構:

- `HealthCondition`。1つの状態を表す。`Type`・`Severity`・`Timer` 0-100・`Effects []StatEffect` を持つ。RimWorld の hediff に相当する。
- `BodyPart` enum。頭・胴・腕・手・脚・足・全身の7部位。`HealthStatus{Parts [BodyPartCount]BodyPartHealth}` が部位ごとに条件を持つ。
- `Abilities` 6種 STR/SEN/DEX/AGI/VIT/DEF。ruins はこれを capacity として全戦闘式に流している。RimWorld の manipulation や moving に相当する役をこの6能力が既に果たす。
- `StatEffect` から `HealthStatus.GetStatModifier` を経て `Abilities.Modifier` へ、`internal/systems/stats_changed.go` が全6能力ぶん配線済み。**条件のペナルティは実際に戦闘へ効く。**
- 進行は `Timer` を delta で上下させる。25/50/75 で Minor/Medium/Severe。

現状、`ConditionType` は `Hypothermia`・`Hyperthermia` の2つだけで、生成しているのも `TemperatureSystem` のみ。汎用エンジンが体温にしか使われていない。目的は、このエンジンへ**新しい ConditionType と、それを生成・進行させる仕組み**を足し、身体ペナルティと病気を成立させること。

この消耗系は設計 doc `260821223229` の一方向逃避と噛み合う。病気と負傷は逃避を削る消耗圧、薬は前方へ消費する資源、致死条件は run の終端になる。単独機能でなくマクロループの生存圧を厚くする。

## 要件

満たすべき抽象条件。Hard は満たさねばならない、Soft は最大化したい、Anti は踏んではいけない罠。

**Hard**

- 新しい健康コンポーネントを作らない。すべて既存 `HealthCondition` エンジンで表す。
- capacity を増やさない。部位の条件は既存6能力への `StatEffect` に写す。腕を痛めれば命中が落ち、脚を痛めれば移動が鈍る。
- 病気は悪化と免疫の競走で決着する。severity が振り切れば悪化継続、免疫が先に満ちれば治癒。
- 発症源を既存機構へ配線する。寒冷は体温系、腐敗食は `Perishable`、負傷は戦闘。新たな乱数源を単独で持ち込まない。
- 致死条件は run を終える。`260821223229` の `RunOutcome` 終端へ接続する。

**Soft**

- 治療で悪化を鈍らせる counterplay がある。薬は前方消費の資源で、貯め込む装置にしない。
- 部位ごとの被弾が意味を持つ。どこを撃たれたかが持続ペナルティを分ける。
- 予防と対処の読みが生まれる。腐敗食を食うか飢えるか、寒空に留まるか進むかの賭け。
- 既存スキルを再利用する。`SkillHealing` は治療効果、resist 系は発症・進行の鈍化に効かせる。

**Anti**

- 別建ての健康システムを作らない。既存エンジンの二重管理を避ける。
- RimWorld の capacity 表を輸入しない。manipulation や consciousness を別フィールドで足さない。
- 全快の安全地帯を作らない。`260821223229` の Anti を継承し、治療は前進の合間に前方資源で行う。
- 乱数任せの理不尽にしない。発症は曝露や選択に紐づけ、決定論寄りに保つ。

## 設計

### 全体方針: エンジンは既存、足すのは中身と3つの接続

足すのは次の3種。エンジン本体には触れず、その上に載せる。

1. **免疫レース** を病気系の条件へ足す。悪化だけの `Timer` に、対になる免疫を加える。
2. **新 ConditionType 群** をデータで定義する。感染創・風邪・疫病・出血・骨折。
3. **接続** を3方向へ配線する。発症源・負傷・治療、そして致死時の終端。

決定論を尊重する。`260821223229`・天気 `260805144630` と同じく、進行は状態を無闇に増やさず既存の turn 進行に沿わせる。発症の確率ゲートは既存の空腹 `progressHunger` や腐敗が使う確率ゲートと同じ流儀に揃える。

### ① 免疫レース: 病気系条件に Immunity を足す

RimWorld の病気は悪化と免疫の競走で、severity が上がりきると死、免疫が先に満ちると治癒する。ruins の `HealthCondition` は `Timer` が上下するだけでこの二本の競走が無い。ここだけ足す。

```go
// HealthCondition に免疫を足す。病気系の条件だけが使う。既存フィールドは不変
type HealthCondition struct {
	Type     ConditionType
	Severity Severity
	Timer    float64      // 悪化度 0-100。既存のまま
	Effects  []StatEffect
	Immunity float64      // 免疫 0-100。病気系のみ。Timer より先に100へ着けば治癒
}
```

進行を担う system を足す。病気系の条件だけを対象に、毎ターン悪化と免疫を進める。

```go
// DiseaseSystem は病気系条件の悪化と免疫を毎ターン進め、決着させる。
// Timer が振り切れば致死判定、Immunity が満ちれば治癒で条件を除去する。
// 新規 system なので InitializeSystems へ登録する。呼び出しリストへ足すだけでは黙ってスキップされる。
type DiseaseSystem struct{}
```

免疫ゲイン速度・悪化速度・治療による悪化鈍化の係数は数値なので着手後に測る。既存の `SkillHealing` を治療効果に、`SkillColdResist` などの resist 系を発症・進行の鈍化に写して、スキルの意味を広げる。

### ② 新 ConditionType 群

エンジンは既存なので、増やすのはデータと部位割り当てだけ。

```go
const (
	ConditionInfection ConditionType = "Infection" // 感染創。深手の化膿。免疫レースを持つ
	ConditionFlu       ConditionType = "Flu"       // 風邪。寒冷曝露。免疫レースを持つ
	ConditionPlague    ConditionType = "Plague"    // 疫病。腐敗食の摂取。免疫レースを持つ
	ConditionBleeding  ConditionType = "Bleeding"  // 出血。被弾でHPを持続的に失う。免疫でなく止血で消える
	ConditionFracture  ConditionType = "Fracture"  // 骨折。長く残る持続ペナルティ
)
```

各条件は既存の `StatEffect` で6能力へ写す。免疫レースを持つのは病気系だけで、出血は止血、骨折は療養で消えるとし、性質を分ける。部位割り当ての例:

| 条件 | 主な部位 | StatEffect の例 | 発症源 |
|---|---|---|---|
| 出血 | 被弾部位 | VIT-。加えて毎ターンHP減 | 負傷 |
| 骨折 | 腕・脚 | 腕=DEX-、脚=AGI- | 負傷・転倒 |
| 感染創 | 被弾部位 | VIT-・DEX- | 手当てされない負傷 |
| 風邪 | 全身 | SEN-・AGI- | 低体温が Severe まで進む |
| 疫病 | 全身 | VIT-・STR-・AGI- | 腐敗食の摂取 |

### ③ 発症源の配線

新たな乱数源を単独で持たず、既存の曝露・選択へ紐づける。

- **寒冷**: 既存の `Hypothermia` が Severe まで進んだら風邪の発症判定を回す。体温系の延長。
- **腐敗食**: `Perishable` の rotten 段階を食べたら疫病の発症判定。腐敗 doc `260815125506` の劣化段階を入力にする。
- **負傷**: 被弾ダメージ適用時に出血、深手なら感染創のリスク。次項で配線する。

### ④ 負傷から条件を残す

現状、被弾は HP を減らすだけで持続ペナルティを残さない。`internal/activity/attack.go`・`shoot.go` のダメージ適用点で、命中部位に応じた条件を付与する。命中部位の決め方は、既存の命中判定に部位抽選を足すか、単純に確率で振るかを着手時に決める。腕なら DEX、脚なら AGI が落ちるので、どこを撃たれたかが戦術に効く。

### ⑤ 治療アクション

薬アイテムを消費して悪化を鈍らせ、出血を止める。これが `260821223229` の経済③の sink になる。金で薬を前方注文し、前進の合間に使う。全快の安全地帯は作らず、治療は逃避の途中で行う。治療効果は既存 `ModHealingEffect`・`SkillHealing` を再利用して算出する。

### ⑥ 致死条件から run 終端へ

病気の `Timer` が振り切って免疫が負けたとき、あるいは出血が続いて HP が尽きたとき、run を終える。`260821223229` の `RunOutcome` に病死・失血死の `OutcomeKind` を足して接続する。逃避を削る消耗が、最終的にマクロループの終端に合流する。

## 採用しなかった方法

- **新規の健康コンポーネントを別建てする**。病気専用のコンポーネントを作る。却下。既存 `HealthCondition` が同型で戦闘配線済みなのに二重管理になる。エンジンを増やさず中身を入れるのが筋。
- **RimWorld の capacity 表を輸入する**。manipulation・consciousness・moving を別フィールドで持つ。却下。ruins は6能力を既に capacity として戦闘式へ流している。別建ては二重管理で、部位条件は6能力への `StatEffect` で表せる。
- **発症を完全乱数にする**。毎ターン一定確率で病気を振る。却下。理不尽で、予防と対処の読みが消える。曝露と選択へ紐づけ決定論寄りに保つ。
- **負傷を HP だけで表す現状維持**。却下。どこを撃たれても同じで、部位と戦術の意味が生まれない。持続ペナルティを残して初めて身体ペナルティが成立する。

## コメント

数値は着手後に測る。免疫ゲイン速度・悪化速度・発症率・薬の効き・出血のHP減量は、最小で組んで一周遊んでから別 doc で定める。`260821223229` と同じく、まだ触っていない手応えを机上で決め打たない。

`HealthCondition` への `Immunity` 追加は、既存の `HealthStatus` が serde 保存対象かを確認し、保存経路に新フィールドを含める。新規コンポーネントは作らないので `add-component` の登録表は増やさないが、フィールド追加の serde 影響は `ruins-review` の serde 観点で点検する。
