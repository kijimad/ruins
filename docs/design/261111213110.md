# ダンジョンを廃し、すべてをオーバーワールドの複数チャンクの領域で表す

## 背景

世界は2つの形式に分かれている。

- **オーバーワールド**: 北へ伸びる帯で、チャンクごとに地形と地物を作る。市街地、集落、ランドマーク、遺跡の入口が並ぶ。
- **ダンジョン**: 遺跡の入口から入る別のステージ。森・洞窟・廃墟のダンジョンの定義がマップ生成の部品で階を1枚ずつ作り、階段のポータルで階を行き来する。中にいる間、オーバーワールドの帯は退避させる。参考 codebase: `internal/overworld/dungeon_entrance.go`、`internal/components/stage.go`、`internal/states/dungeon_floor.go`

2つの形式が並ぶので、次の仕組みが二重になっている。

- ステージの行き来と退避
- 階の深さ
- ポータル
- ダンジョン専用の画面

横に広い1つの世界で探索させる方針とも合わない。深さの代わりに北への距離で危険度が上がる仕組みは、すでにオーバーワールドにある。参考 codebase: `internal/world/query/danger.go:31`

一方、オーバーワールドで複数のチャンクにまたがる物は市街地しかない。市街地は基点のチャンクから東と南へ最大 3×3 チャンク広がり、どのチャンクからでも同じ市街地に属すると判定できる。参考 codebase: `internal/overworld/urban.go:46` の `urbanRegionOf`。この仕組みを一般化すれば、ダンジョンが表していた森・洞窟・廃墟の地形や、軍基地のような大きな施設を、オーバーワールドの領域として置ける。

## 要件

1. ダンジョンの形式をなくし、すべてをオーバーワールドで表す。ステージの行き来、階の深さ、ポータルを無くす。
2. 施設と地形の領域は、大きさをチャンクの数で持つ。軍基地なら 4×4 チャンクのように、raw の行で決める。
3. 領域はチャンクの境目で途切れない。どのチャンクから作っても、また再び訪れても、同じ形になる。
4. 危険度は北への距離だけで決める。

## 設計

### 1. 複数チャンクの領域の地物

市街地の基点と大きさの仕組みを、汎用の領域の地物として切り出す。

```go
// region は複数チャンクにまたがる地物の1つ。基点のチャンクから東と南へ W×H チャンク広がる
type region struct {
	Anchor consts.Coord[consts.Chunk]
	W, H   consts.Chunk
	Kind   string // raw の行の id
}

// regionOf は c を含む領域を返す。基点の候補を maxSpan の範囲で逆向きに探す、runSeed と座標の純関数
func regionOf(runSeed uint64, c consts.Coord[consts.Chunk], cols consts.Chunk, layer regionLayer) (region, bool)
```

- 領域の種類ごとに、基点の置き方 `Placement` と最大の大きさを持つ層を作る。市街地もこの層の1つとして載せ直す。
- 大きさは raw の行のチャンクの数で決める。

```toml
[[facilities]]
  id = "military"
  span = { w = 4, h = 4 }
```

- 層どうしは重ならないようにする。市街地と同じく、基点の間隔 `Separation` を最大の大きさ以上にとる。

### 2. ダンジョンの地形を領域にする

森・洞窟・廃墟は、オーバーワールドの領域の種類にする。

```toml
[[areas]]
  id = "ash_cave"
  name = "Ash cave"
  planner = "cave"
  span = { w = 4, h = 3 }
  enemyTable = "cave"
  itemTable = "cave"
  minDanger = 3
```

- マップ生成の部品は、領域全体を基点の種の値から1枚で作り、各チャンクはその中の自分の分を切り出す。洞窟の壁がチャンクの境目で途切れず、再び訪れても同じ形になる。
- 同じ領域の全体を、チャンクごとに作り直すと重い。基点ごとに作った結果をキャッシュする。結果は種の値で決まるので、キャッシュしても作り直しても同じになる。
- 領域の外周には入口を開け、周りのオーバーワールドから歩いて入れるようにする。
- 出やすさは施設と同じく、危険度の下限と重みで決める。

### 3. 施設の大きさ

- 施設の行にチャンクの数 `span` を持たせる。市街地の中の施設は今どおり区画に建て、`span` を持つ大きな施設は市街地の外へ単独の領域として置く。
- 間取りの部品は、領域全体に建物と外構を並べる。軍基地なら兵舎と武器庫を複数の建物に分けて置ける。
- 設計 doc 261108165219 の3段目「軍基地と発電施設を市街地の外へ単独で置く」は、この仕組みで行う。設計 doc 261111002908 の通信施設も、同じ仕組みの上に載る。

### 4. ダンジョンの仕組みを消す

- 消すもの:
  - 遺跡の入口
  - 階段のポータル `warp_next` `warp_prev` と、その操作
  - ステージのキーの深さと、ダンジョン用のステージの行き来と退避
  - ダンジョンの階を作る部品の呼び出し口
  - ダンジョン用の画面
  - ダンジョンの定義の階の部分
- アイテムと敵の表は危険度で引く。深さの代わりに北への距離から決まる危険度を使う。
- デバッグ用のステージは、オーバーワールドの決まった場所に領域を置く形に移す。

## 採用しなかった方法

- **ダンジョンを扉から入る別の空間として残す**: 一本化の目的に反する。ステージの行き来と退避の仕組みも残る。
- **チャンクの大きさ自体を大きくする**: ストリーミングとセーブの単位が変わり、影響が世界全体に及ぶ。大きさの違いは、チャンクの数で表せば足りる。
- **領域を分けず、チャンクごとに独立に作る**: 洞窟の壁や施設の建物がチャンクの境目で途切れる。
- **領域を作るたびに全体を作り直し、キャッシュしない**: 1つの領域を作るのに、チャンクの数だけ同じ計算が重なる。
