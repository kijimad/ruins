# 物に性質を持たせ、行動は性質に働きかける

## 背景

ruins は、行動の選択肢が多く、上達するのがキャラクターの数値でなくプレイヤー自身の知識であるローグライクに特化する。知識が積み上がる領域として、物の使い道を選ぶ。一度知れば次の一回で取れる手が増え、初めて見る物にも応用が利くことを狙う。

物の使い道の統計は `internal/raw/item_uses.golden.md` に出す。2026-11-20 時点で、物は 602 種類ある。

| 使い道の数 | 物の数 |
|---|---|
| 0 | 20 |
| 1 | 158 |
| 2 | 300 |
| 3 | 122 |
| 4 以上 | 2 |

数は 2〜3 に寄っているが、厚みは薄い。

- 燃料と解体は素材の表 `materials` で一律に決まる。木の物はどれも、燃やせば同じ熱、解体すれば同じ枝になり、物ごとの個性にならない
- 物ごとに固有の使い道は少ない。道具 15、着火 1、照らす 1、投げる 3、治す 9
- 作成のレシピは 17 で、材料は鉄・枝・布切れ・薬草などに集中している
- 「解体」だけの物が 89、使い道の無い物が 20 ある

物ごとに使い道を書き足す形では、作業量が物の数に比例して増え、プレイヤーにとっても物の名前ごとに覚える暗記になる。

## 要件

- 物を見て「これは布だから包帯にもなる」と推理できる。知識が物の名前でなく性質の単位で積み上がる
- 新しい物は raw の行に性質を書くだけで、既存の行動の対象になる。コードは性質を見る汎用の部品だけを持つ
- 行動は今ある操作の対象を広げる形を優先し、新しい操作を増やしすぎない
- 使い道の統計の golden で、性質を足したときの厚みの変化を確かめられる

## 設計

### 性質

性質は、物の行の任意欄そのものにする。`remedy` を持てば治せ、`tool` を持てば道具として働き、`fireStarter` を持てば火を点けられる。欄は実体のコンポーネントに写り、行動は物の名前でなく欄を見て決まる。性質ごとに要る値は違うので、性質は欄ごとの型で表す。

新しい性質は `#Item` に欄を足し、その欄を見る行動を作る。各行は自分の値を自分で持ち、ほかの行から借りない。

```cue
#Item: {
	// ...今の欄
	remedy?:    #Remedy
	tool?:      #Tool
}
```

布の物に治療を付ける例は次のとおり。包帯と同じ欄を、質を下げて書く。

```toml
[[items]]
  id = "rag"
  [items.consumable]
    targetGroup = "ALLY"
    targetNum = "SINGLE"
    usableScene = "ANY"
  [items.remedy]
    potency = 50
    treats = ["laceration"]
```

性質ごとに働く行動の候補は次のとおり。

| 性質 | 欄 | 物の例 | 行動の候補 |
|---|---|---|---|
| 包める | `remedy` | ぼろ布・タオル | 傷を縛って失血を止める |
| 入れられる | 未定 | 缶・鍋・瓶 | 雪を溶かして水にする・食料を煮る・燃料を運ぶ |
| 切れる | `tool` の `cutting` | ナイフ・ガラス片・斧 | 解体する・布を裂く |
| 重い | 未定 | 石・鉄塊 | 投げて音を立てる・氷を割る |

### 既存の仕組みとの関係

- 道具の分類 `toolCategories` は、すでに「切る・掘る・こじ開ける」という性質になっている。切れる性質は `cutting` で表し、別の欄を作らない
- 燃料と解体は素材で決まるまま残す。性質は素材の上に重ねる層で、素材が持たない使い道を足す
- 作成のレシピは物の id を材料に取る。欄を材料に取るレシピ、たとえば「治療を持つ布の物を1つ」は、この doc では扱わない

### 最初に入れる範囲

- 包める: ぼろ布とタオルに `remedy` と `consumable` を書き、使うと切り傷を治療する。質は 50 で、品質 100 の包帯より劣る。止血と痛みは治療済みになれば質によらず同じだけ収まり、質で変わるのは治るまでの速さだけ。質の高い治療を質の低い物で上書きさせない。発症前の掠り傷は痛みも出血も無く自然に治るので、治療の対象にしない。治療は未治療の傷を先にし、その中で最も重い傷を選ぶ。どの部位のどの不調を治療したかはログに出す。服を分解するとぼろ布になるので、服からぼろ布を作り傷を縛る、という手のつながりができる
- 入れられる: 使い道の無い物 20 の多くはポット・試験管・小瓶のような容器だが、容器を見る行動が無い。水の仕組みから作る必要があり、この doc では扱わない

## 採用しなかった方法

- **物ごとに使い道の欄を足していく**: 物の数だけ作業が増え、プレイヤーにとっても名前ごとの暗記になる
- **性質の表を作り、物の行が id で引く**: 性質ごとに要る値が違うので、表は `#Item` の任意欄の複写になる。物の効き目がほかの行にあり、行だけを読んでも分からない。継承と同じで、raw の各行が自分の値を持つ方針に反する
- **性質を値の無いタグにする**: タグがあることと欄があることが同じ意味になり、二重管理になる
- **治療する傷を使う人が選ぶ**: 「使う」の引数に使う先の欄を足し、効果に候補を答えさせ、画面の戻り方も変える必要があり、共通部分が広がる。今は治療品も傷の種類も少なく、規則で選んでも損はほぼ出ない。どこに効いたかはログで見せる。手当てに時間がかかる、治療品が増えるなど、選ぶ意味が大きくなったら考え直す
- **素材の表に使い道を持たせる**: 素材は燃料と解体を一律に決める粒度で、同じ布でも包帯にできる切れ端と、できない分厚い服を区別できない
