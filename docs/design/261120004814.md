# 物に性質を持たせ、行動は性質に働きかける

## 背景

ruins は、行動の選択肢が多く、上達するのがキャラクターの数値でなくプレイヤー自身の知識であるローグライクに特化する。知識が積み上がる領域として、物の使い道を選ぶ。一度知れば次の一回で取れる手が増え、初めて見る物にも応用が利くことを狙う。

物の使い道の統計は `internal/raw/item_uses.golden.md` に出す。2026-11-20 時点で、物は 602 種類ある。

| 使い道の数 | 物の数 |
|---|---|
| 0 | 20 |
| 1 | 158 |
| 2 | 300 |
| 3 | 122 |
| 4 以上 | 2 |

数は 2〜3 に寄っているが、厚みは薄い。

- 燃料と解体は素材の表 `materials` で一律に決まる。木の物はどれも、燃やせば同じ熱、解体すれば同じ枝になり、物ごとの個性にならない
- 物ごとに固有の使い道は少ない。道具 15、着火 1、照らす 1、投げる 3、治す 9
- 作成のレシピは 17 で、材料は鉄・枝・布切れ・薬草などに集中している
- 「解体」だけの物が 89、使い道の無い物が 20 ある

物ごとに使い道を書き足す形では、作業量が物の数に比例して増え、プレイヤーにとっても物の名前ごとに覚える暗記になる。

## 要件

- 物を見て「これは布だから包帯にもなる」と推理できる。知識が物の名前でなく性質の単位で積み上がる
- 新しい物は raw の行に性質を書くだけで、既存の行動の対象になる。コードは性質を見る汎用の部品だけを持つ
- 行動は今ある操作の対象を広げる形を優先し、新しい操作を増やしすぎない
- 使い道の統計の golden で、性質を足したときの厚みの変化を確かめられる

## 設計

### 性質

性質は raw の表 `itemProperties` の行にし、その性質の物に加わる使い道を行に書く。物の行は `properties` で性質の id を引く。コードは性質の名前も効き目の中身も知らず、性質の行が持つ使い道を物に重ねるだけにする。新しい性質は行を足すだけで入る。

```cue
// 物の性質。布で包める、のように複数の物に共通する使い道を1行に書き、物は properties で引く
#ItemProperty: {
	id!: #EntityID

	// この性質の物を使うと不調を治療する。物は使うと無くなる
	remedy?: #Remedy
}

#Item: {
	// ...今の欄
	properties?: [...#EntityID]
}
```

生成される Go の形は次のとおり。

```go
// ItemProperty 物の性質
type ItemProperty struct {
	Id     EntityID `json:"id"`
	Remedy *Remedy  `json:"remedy,omitempty"`
}

type Item struct {
	// ...今の欄
	Properties *[]EntityID `json:"properties,omitempty"`
}
```

```toml
[[itemProperties]]
  id = "wrap"
  [itemProperties.remedy]
    potency = 50
    treats = ["laceration"]
```

性質の治療を持つ物は、使える消費物になり、今の「使う」で治療する。新しい操作は増やさない。同じ使い道を物の行と性質の両方に書くと、どちらが効くかが読めないので検証で弾く。

性質ごとに働く行動の候補は次のとおり。

| 性質 | 物の例 | 行動の候補 |
|---|---|---|
| 包める `wrap` | 布切れ・服・毛布 | 傷を縛って失血を止める・松明の芯にする・体に巻いて暖を取る |
| 入れられる `container` | 缶・鍋・瓶 | 雪を溶かして水にする・食料を煮る・燃料を運ぶ |
| 切れる `blade` | ナイフ・ガラス片・斧 | 解体する・布を裂いて包帯にする |
| 重い `heavy` | 石・鉄塊 | 投げて音を立てる・氷を割る |

### 既存の仕組みとの関係

- 道具の分類 `toolCategories` は、すでに「切る・掘る・こじ開ける」という性質の一種になっている。`blade` と道具の分類 `cutting` を一本化するかは要判断
- 燃料と解体は素材で決まるまま残す。性質は素材の上に重ねる層で、素材が持たない使い道を足す
- 作成のレシピは物の id を材料に取る。性質を材料に取るレシピ、たとえば「`wrap` の物を1つ」を足すかは要判断

### 最初に入れる範囲

性質の仕組みの形を確かめるため、`wrap` から始める。

- `wrap`: ぼろ布とタオルに付け、使うと切り傷を治療する。質は 50 で、品質 100 の包帯より劣る。服を分解するとぼろ布になるので、服からぼろ布を作り傷を縛る、という手のつながりができる
- `container`: 使い道の無い物 20 の多くはポット・試験管・小瓶のような容器で、付ければ使い道の無い物を減らせる。ただし雪を溶かす水の仕組みが無いので、次の段に回す

## 採用しなかった方法

- **物ごとに使い道の欄を足していく**: 物の数だけ作業が増え、プレイヤーにとっても名前ごとの暗記になる
- **性質を列挙にし、効き目を Go に書く**: 不調の種類は raw の行だけで決まり、Go に定数が無い。効き目を Go に書くと、不調の id と質を Go に直書きすることになる
- **性質ごとに新しい操作を足す**: 「縛る」のような動詞を足すと操作が増える。治療は今の「使う」で足りる
- **素材の表に使い道を持たせる**: 素材は燃料と解体を一律に決める粒度で、同じ布でも包帯にできる切れ端と、できない分厚い服を区別できない
