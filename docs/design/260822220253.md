# 温度モデル: 前線を廃し、屋外の底冷えと屋内の蓄熱を持つ

## 背景

現状の気候圧力は寒波前線 `worldstream.Front` ただ1本に集約されている。幅を持つ極低温ゾーンが総ターン数に応じて東進し、居座るとプレイヤーを飲む。破棄と進入不可ラインもこの前線に統合されている。前線は「後ろから押す強制移動」であり、これがゲーム唯一の実効的な気候圧になっている。

問題は2つ。第一に、前線以外の気候ペナルティが弱く、屋外での探索や滞在にコストが無い。前線から離れていれば自由に振る舞える。第二に、移動が前線による強制であってプレイヤーの意思でない。押されて動くので agency が薄い。

目指すのは、屋外が常時寒く、屋内へ退避すると暖がとれる温度モデル。屋外の寒さが滞在にコストを課し、火を焚いた屋内が休息と回復の場になる。この非対称が「寒い外を進み、暖かい中で立て直す」というリズムを生む。屋外だけを一律に寒くしても、退避先が無ければ理不尽なだけになる。屋内が意味を持つには、外気から遮蔽された空間の判定と、そこに熱が溜まる概念が要る。

この doc は温度モデルの全体を設計する。前線の撤去、屋外の底冷え、屋内と屋外の判定、屋内の蓄熱、体温への効果までを1つのモデルとして定義し、実装は作業ステップで PR を分ける。吹雪の周期イベント、資源枯渇による自主移動、危険度軸との合成は、この温度の土台の上に別 doc で積む。

この doc は spawn の危険度軸を扱う [260822014350](260822014350.md) とは別軸。危険度は敵とアイテムの湧きを、温度は寒暖と生存を扱う。

## 要件

**Hard**

- 寒波前線を廃す。総ターン数に応じた強制的な空間押し出しをやめる。
- 屋外は常時寒い。位置と時刻の決定論で導く底冷えを全屋外へ課し、だらだらした滞在に体温コストを乗せる。屋外の気温は保存しない。
- 屋内と屋外を判定する。壁で外気から遮蔽された閉領域を屋内、外気に通じる空間を屋外とする。
- 屋内は熱を蓄える。部屋ごとに気温を状態として持ち、熱源が押し込み、外気との差に比例して漏れる。瞬時でなく蓄積する。屋内の気温は serde 保存する。
- 寒暖の効果は既存の温度システムに載せる。`updateTemperatureConditions` がタイルの env 気温と装備の断熱から部位ごとの体温を進めるので、env 気温の導出を屋内外で切り替えるだけで既存の体温・凍傷経路が効く。
- 左へは戻れない制約を維持する。破棄と進入不可の境界を前線の時間東進から切り離し、プレイヤーの東進に従わせる。西戻り不可はそのまま残す。

**Soft**

- 屋内判定と蓄熱は重い計算になりうる。部屋検出はキャッシュし、蓄熱の更新はプレイヤー近傍の活性な部屋に絞る。
- 逃げ場なしの理不尽を避ける。屋外でも火を焚けば局所的に暖がとれる余地を残し、屋内退避を唯一解にしない。

## 設計

### 温度は3層

タイルの環境気温 env を次の3層で決める。

1. 屋外 ambient。位置と時刻の決定論。前線を廃した後の全屋外の底冷え。
2. 屋内 accumulated。壁で囲われた部屋ごとの蓄熱。状態を持ち serde 保存する。
3. 効果。タイルが屋内なら部屋気温、屋外なら屋外 ambient を env として既存の体温システムへ渡す。

屋外は決定論で保存不要、屋内は履歴依存で保存必要、という非対称がこのモデルの肝。屋外は `FrontAt` が保存不要だった思想を継ぎ、屋内は熱源を焚いた履歴が気温に効くので状態として持つ。

### 屋外 ambient と前線の撤去

`worldstream.Front` と、driver の `frontCfg`・`UpdateFront`・`front()` を撤去する。温度計算からは前線寄与の `frostZoneModifier` を外す。前線が担っていた時間東進の極寒ゾーンを無くし、強制押し出しを消す。

屋外 ambient は現状の `baseTemp + timeModifier + tileModifier` を土台にする。屋外ステージの `BaseTemperature` を常時寒い値へ下げ、時間帯補正 `timeModifier` が日内の揺れを残す。焚き火などの `tileModifier` は局所の熱源として残り、屋外でも火のそばだけ暖かくなる。位置と時刻だけで決まり保存しない。

```go
// OutdoorAmbientAt は屋外タイルの環境気温を導く決定論の純関数。
// ステージのベース気温に時間帯補正と局所の熱源補正を重ねる。位置と時刻だけで決まり保存しない。
func OutdoorAmbientAt(world w.World, x, y consts.Tile) int
```

### 屋内と屋外の判定

壁で外気から遮蔽された閉領域を屋内、外気に通じる空間を屋外とする。判定はタイルグリッド上の閉包で決める。あるタイルから壁を越えずに辿れる連結領域が、マップ外縁や開けた空へ通じていれば屋外、壁で閉じていれば屋内の1部屋。

```go
// EnclosureKind はタイルが外気に接するか、壁で遮蔽されるか。
type EnclosureKind int

const (
	Outdoor EnclosureKind = iota // 外気に通じる
	Indoor                       // 壁で囲われ外気から切り離された部屋の内側
)
```

閉包の計算は重いので、部屋を検出して RoomID をタイルへ割り当て、キャッシュする。壁の増減が起きたときと、マップのロード時にだけ再検出する。ストリーミングの屋外は広大な単一の外気なので部屋にせず、屋内は建物や遺跡の閉じた空間に限られ数が少ない。判定コストは屋内側の部屋数に比例する。

### 屋内の蓄熱

屋内は熱を蓄える。部屋ごとに気温を状態として持ち、毎ターン熱源から受け取り、外気との差に比例して漏らす。RimWorld の部屋温度を着想に、ruins のタイル部屋へ移す。

```go
// Room は壁で囲われた1部屋の蓄熱状態。屋内の気温は瞬時でなく蓄積する。
// 熱源が押し込み、外気との差と開口の広さに比例して漏れる。実行時状態で serde 保存する。
type Room struct {
	// Temperature は部屋の現在気温。熱源で上がり、外気へ漏れて下がる
	Temperature int
	// FloorTiles は部屋の広さ。広いほど同じ熱源で温まりにくい
	FloorTiles int
	// ExposedTiles は外気に面する開口の量。大きいほど漏れが速い
	ExposedTiles int
}
```

毎ターンの更新は、熱源が押し込む熱と、外気への漏れの差で気温を動かす。漏れは部屋気温と屋外 ambient の差に比例し、開口が広く部屋が大きいほど速い。熱源が無ければ気温は屋外 ambient へ漸近し、熱源があればある平衡へ落ち着く。蓄積するので、入った瞬間に暖かいのでなく、火を焚いて待つと暖まる。

更新はプレイヤー近傍の活性な部屋に絞る。遠方の部屋を常時回すと重いので、プレイヤーが居る、または最近居た部屋だけを進める。

### 効果は既存経路へ

タイルの env 気温を、屋内なら所属部屋の `Temperature`、屋外なら `OutdoorAmbientAt` から出す。これを既存の `updateTemperatureConditions` へ渡す。装備の断熱と体温進行倍率で部位ごとの `HealthStatus` が進む経路は変えない。凍傷も既存の体温割れの経路をそのまま使う。温度の出所を屋内外で切り替えるだけで、効果側は無改造で載る。

```go
// EnvTemperatureAt はタイルの環境気温を返す。屋内なら所属部屋の蓄熱、屋外なら屋外 ambient。
// 既存の updateTemperatureConditions がこれを消費する。
func EnvTemperatureAt(world w.World, x, y consts.Tile) (int, error)
```

### 左戻り不可の維持

現状 `worldstream.Front` の極低温ゾーン西端 `ColdZoneWest` が破棄と進入不可ラインを兼ねる。前線を廃すが、この境界の役割は残す。境界を前線の時間東進から切り離し、帯ストリーミングのプレイヤー東進に従わせる。到達した最西端より西へは戻れず、破棄済みチャンクは復元しない。境界は時間で自走せず後退の封じ込めだけを担うので、強制押し出しにはならない。保持の具体形は帯の西端の流用か薄い境界状態かを実装で確定する。

## 実装の段階

温度モデル全体を一度に入れると差分が大きく検証しづらい。効果側は既存経路を使うので、env 気温の出所を段階的に足す形で PR を分ける。各段階は単体で `make check` が通り、ゲームとして壊れない状態にする。

1. **前線撤去と屋外 ambient**。`worldstream.Front` と driver の前線処理を撤去し、`frostZoneModifier` を外す。屋外ステージの `BaseTemperature` を下げ、`OutdoorAmbientAt` を屋外 env の出所にする。左戻り不可を帯の東進へ従わせて維持する。この段階では全域を屋外扱いにするので、屋内でも寒い。既存の体温システムがそのまま寒さを効かせる。
2. **屋内と屋外の判定**。閉包で部屋を検出し RoomID を割り当てキャッシュする。`EnvTemperatureAt` を足し、屋内タイルは部屋所属を返せるようにする。この段階では屋内の気温は屋外 ambient と同じにしておき、判定だけを入れる。判定の正しさを単体で検証する。
3. **屋内の蓄熱**。`Room` の蓄熱状態と毎ターンの熱源・漏れ更新を足す。屋内タイルの env を部屋気温にする。火を焚いた屋内が暖まり、屋外との非対称が生まれる。serde 保存を接続する。

この3段で温度モデルが揃う。以降の吹雪・枯渇 pull・危険度合成は別 doc で、この土台の上に積む。

## 採用しなかった方法

- **寒波前線を残す**。却下。時間駆動の強制押し出しは agency を奪う。屋外の常時気温へ置換し、退避先として屋内の蓄熱を用意する。
- **屋外だけを一律に寒くし、屋内を作らない**。却下。退避先が無いと屋外の寒さはただの理不尽になる。屋内の蓄熱があって初めて「寒い外を進み暖かい中で立て直す」リズムが生まれる。屋内が温度モデルの半分を担う。
- **屋内の気温を瞬時に切り替える**。却下。屋内へ入った瞬間に暖かいと、火を焚いて備える意味が消える。蓄積にすることで、燃料と時間をかけて部屋を暖める行動に価値が出る。RimWorld の部屋温度が蓄積だったのと同じ理由。
- **屋内の気温も決定論で保存しない**。却下。屋内は熱源を焚いた履歴に依存するので、位置と時刻からは導けない。屋外は決定論で保存不要、屋内は状態で保存必要、と非対称に持つ。
- **全部屋の蓄熱を常時更新する**。却下。遠方の部屋まで毎ターン回すと重い。プレイヤー近傍の活性な部屋に絞る。
- **前線の破棄機構を流用したまま前線だけ止める**。却下。破棄が時間で東進し続け、止まった前線と齟齬が出る。破棄はプレイヤー到達位置に従わせ、時間駆動から切り離す。

## コメント

- 屋外ベース気温をどこまで下げるか。強いと装備が整う前に削られ過ぎ、弱いと圧にならない。装備の断熱値と体温進行の兼ね合いで実プレイ調整する。
- 蓄熱の漏れ係数と熱源の出力。暖まるのが遅すぎると火を焚く気が失せ、速すぎると蓄積の意味が消える。部屋の広さと開口で平衡が決まる関係を調整する。
- 閉包判定の更新契機。壁の増減とロード時に限れば安いが、破壊可能な壁があると頻度が上がる。破壊の頻度を見て再検出の粒度を決める。
- 活性な部屋の範囲。プレイヤーが去った部屋の気温をどこまで保持し、いつ屋外 ambient へ戻すか。
