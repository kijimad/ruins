# 温度モデル: 前線を廃し、屋外の底冷えと屋内退避を持つ

## 背景

現状の気候圧力は寒波前線 `worldstream.Front` ただ1本に集約されている。幅を持つ極低温ゾーンが総ターン数に応じて東進し、居座るとプレイヤーを飲む。破棄と進入不可ラインもこの前線に統合されている。前線は「後ろから押す強制移動」であり、これがゲーム唯一の実効的な気候圧になっている。

問題は2つ。第一に、前線以外の気候ペナルティが弱く、屋外での探索や滞在にコストが無い。前線から離れていれば自由に振る舞える。第二に、移動が前線による強制であってプレイヤーの意思でない。押されて動くので agency が薄い。

目指すのは、屋外が常時寒く、屋内へ退避すると寒さが和らぐ温度モデル。屋外の寒さが滞在にコストを課し、屋内が休息の場になる。この非対称が「寒い外を進み、暖かい中で立て直す」というリズムを生む。ただしそのために部屋ごとの室温を丸ごとシミュレートするのは重い。ここでは室温を持たず、プレイヤーが今いる場所の屋内外だけで寒さの速さを変える最小のモデルにする。

この doc は温度モデル全体を設計し、実装は作業ステップで PR を分ける。吹雪の周期イベント、資源枯渇による自主移動、危険度軸との合成は、この温度の土台の上に別 doc で積む。

この doc は spawn の危険度軸を扱う [260822014350](260822014350.md) とは別軸。危険度は敵とアイテムの湧きを、温度は寒暖と生存を扱う。

## 要件

**Hard**

- 寒波前線を廃す。総ターン数に応じた強制的な空間押し出しをやめる。
- 屋外は常時寒い。位置と時刻の決定論で導く底冷えを課し、だらだらした滞在に体温コストを乗せる。屋外の気温は保存しない。
- 屋内外はステージ種別で決まる。オーバーワールドは屋外、ダンジョンは屋内。タイルごとの屋内外判定はしない。
- ダンジョンにはステージ単位の温度設定があり、全タイルが一律に受ける。ダンジョンの温度はオーバーワールドの世界温度の影響を受けつつ、屋内なので屋外ほど厳しくしない。これが体温の奪われる速さを決める。ダンジョンほど遅い。
- 焚き火などの熱源は室温を変えず、プレイヤーの体温へ直接効く。もたらす熱量は屋内でも屋外でも同じ。屋内は奪われる量が少ないので、屋内で焚くほど得になる。
- 寒暖の効果は既存の体温システムに載せる。`updateTemperatureConditions` が周囲気温と装備の断熱から低体温を進める経路をそのまま使い、周囲気温の出所を屋内外で切り替えるだけにする。
- 左へは戻れない制約を維持する。破棄と進入不可の境界を前線の時間東進から切り離し、プレイヤーの東進に従わせる。西戻り不可はそのまま残す。

**Soft**

- 屋内外はステージ種別で分かるので判定は安い。タイルの連結探索も部屋分けもしない。
- 逃げ場なしの理不尽を避ける。屋外でも火を焚けば体温を保てる余地を残し、屋内退避を唯一解にしない。

## 設計

### 温度の出所

タイルの周囲気温は、現在のステージ種別で出す。オーバーワールドは世界温度そのもの、ダンジョンはダンジョンの温度設定を世界温度で和らげた値。部屋ごとの室温も、タイルごとの屋内外判定も持たない。

```go
// AmbientTemperatureAt はタイルの周囲気温を返す。オーバーワールドは世界温度そのもの、
// ダンジョンはダンジョンの温度設定を世界温度で和らげた値。屋内なので屋外ほど厳しくしない。
func AmbientTemperatureAt(world w.World, x, y consts.Tile) (int, error)
```

世界温度は決定論で保存不要、ダンジョンの温度設定はステージ定義側の固定値。どちらも履歴に依存しないので、状態として持つものは無い。既存の `CalculateEnvTemperature` と引数 `envTemp` も env の名を避け、`AmbientTemperatureAt` と `ambientTemp` へ改める。

### 世界温度と前線の撤去

`worldstream.Front` と、driver の `frontCfg`・`UpdateFront`・`front()` を撤去する。温度計算からは前線寄与の `frostModifier` を外す。前線が担っていた時間東進の極寒ゾーンを無くし、強制押し出しを消す。

世界温度は季節ベースに時間帯補正 `timeModifier` を重ねて決める。オーバーワールドステージの固定 `BaseTemperature` の代わりに、経過日数から導く季節の世界温度を屋外の基本気温にする。時間帯補正が日内の揺れを残す。どちらも時刻と日数だけで決まり保存しない。これが屋外の周囲気温であり、ダンジョンの温度もこれを土台に和らげる。

### 季節による世界温度

世界温度は季節で変わる。トロントの気候をモデルに、夏は暖かく冬は生存が厳しい寒さになる。季節は経過日数 `GetDayNumber` から導く正弦波で、状態として保存しない。日数は既に危険度 `DangerLevel(days)` の軸でもあり、季節をここへ重ねると、日が経つほど危険が増し寒さも深まる二層の時間圧になる。前線が担っていた時間駆動の圧を、空間の強制押し出しでなく屋外気温の季節変動として引き継ぐ。

```go
// 季節ベース。春開始の正弦波で春秋が中点、夏がピーク、冬が底。
// 中点 = (夏+冬)/2、振幅 = (夏-冬)/2。1年 = daysPerYear 日で1周する。
func (gt *GameTime) GetSeasonalTemperature() int
```

春開始にする。ラン開始は春の穏やかな中点で、まず夏へ向かい暖かく、その後 秋 を経て冬の底へ下る。冬の前に夏秋の準備期間が生まれ、装備と暖を整えてから最も厳しい季節を迎える流れになる。夏ピーク・冬底・1年の日数はいずれも実プレイで調整する初期値で、`components/game_time.go` の定数に置く。初期値は夏 +22、冬 -30、1年 32 日、すなわち8日で1季節。

吹雪は季節温度とは別の、体感温度を一時的に下げる天候イベントとして上に積む。冬の深夜に吹雪が重なると極寒バケットへ落ち、シェルターに籠る以外の選択を奪う。吹雪の発生周期・持続・強度はこの温度土台の上に別 doc で設計する。ここでは世界温度に体感オフセットを足す口を残すに留める。

### ダンジョンの温度は世界温度で和らげる

屋内外はタイルでなくステージで決まる。オーバーワールドは屋外で世界温度がそのまま効く。ダンジョンは全体が屋内なので、タイルごとの判定はしない。ダンジョンにはステージ単位の温度設定があり、全タイルが一律にそれを受ける。

ダンジョンの温度は世界温度と無関係の独立値でなく、世界温度の影響を受ける。世界が寒いほどダンジョンも寒くなるが、屋内なので緩和され、屋外ほど厳しくならない。概念的には、世界温度にダンジョンの温度設定ぶんの暖かさを足した値。世界温度が下がってもダンジョンは一定ぶん暖かい床を保つ。屋内なので、そもそも厳しい値にはしない。

判定はステージ種別だけで済む。既存の温度計算が `GetStageDefinition` で現在のステージ定義を引いているので、そこにステージが屋外か屋内かと、ダンジョンの温度設定を載せる。タイルの連結探索も RoomID も要らない。

### 壁の変化と一部開放は局所の冷気源で

ステージ種別の温度はダンジョン全体を一律の屋内として扱う。この粗さゆえに、将来 壁が壊れたり作られたり、扉や窓が開けっ放しや破壊で一部開放になっても、ダンジョンの温度そのものは動かない。壊れた壁の穴から冷気が入る、という局所の効果はこの土台には無い。ここは今回のスコープ外の割り切りで、土台を単純に保つための境界。

壁の破壊や開閉が実際のメカニクスになったときは、全域の閉包判定へ戻さず、局所の冷気源として足す。焚き火が熱源のタイル補正で近傍を暖めるのと対称に、開いた扉や壊れた壁を冷気源のタイル補正にし、近傍のタイルの周囲気温を下げる。開けば冷気源が現れ、閉じれば消える。既存の熱源合算 `getTileTemperatureAt` は正負どちらの補正も足せるので、冷気源は負の補正として同じ経路に載る。動的な壁の増減もエンティティの出入りで表せ、タイルごとの連結の再探索を持たずに済む。

一部開放を「どのくらい開いているか」で連続的に効かせたくなったら、そのとき閉包や熱の流れのモデルを検討する。まずは局所の冷気源で、開放の有無を離散に表すところから始める。

### 体温の効果は既存経路へ

`AmbientTemperatureAt` が返す周囲気温を、既存の `updateTemperatureConditions` へ渡す。装備の断熱と体温進行倍率から `HealthStatus` の低体温タイマーが進む経路は変えない。周囲気温が低いほどタイマーが早く進み、高いほど遅い。屋内は周囲気温が高いので進みが遅い。凍傷も既存の体温割れの経路をそのまま使う。周囲気温の出所をステージ種別で切り替えるだけで、効果側は無改造で載る。

### 焚き火はプレイヤーの体温へ直接

焚き火などの熱源は周囲気温を変えない。代わりに、熱源のそばに居るプレイヤーの低体温タイマーへ固定の回復を毎ターン加える。回復量は屋内でも屋外でも同じ。

周囲気温由来の奪われる速さと、火由来の回復は別々に効く。屋内は周囲気温が高く奪われが遅いので、同じ火でも回復が上回りやすい。屋外は周囲気温が低く奪われが速いので、火はやっと相殺する程度。結果として、火をもたらす熱量は屋内外で同じなのに、屋内で焚くほうが得になる。

「そば」の判定は既存の熱源の仕組みを流用する。焚き火は `TileTemperature` を持つエンティティで、現状 `getTileTemperatureAt` がプレイヤーのタイルの熱源寄与を合算している。段階3ではこの合算を周囲気温へ足すのをやめ、同じ熱源寄与をプレイヤーの低体温タイマーの回復量へ回す。新たな近接判定は足さない。

### 左戻り不可の維持

現状 `worldstream.Front` の極低温ゾーン西端 `ColdZoneWest` が破棄と進入不可ラインを兼ねる。前線を廃すが、この境界の役割は残す。境界を前線の時間東進から切り離し、帯ストリーミングのプレイヤー東進に従わせる。更新はタイル移動ごとでなく、帯が東へシフトする既存の `MaybeShift` の契機に合わせる。シフトで西端チャンクが破棄されるので、境界もそのチャンク単位で東へ動く。到達した最西端より西へは戻れず、破棄済みチャンクは復元しない。境界は時間で自走せず後退の封じ込めだけを担うので、強制押し出しにはならない。保持の具体形は帯の西端の流用か薄い境界状態かを実装で確定する。

## 実装の段階

温度モデルを一度に入れると差分が大きく検証しづらい。効果側は既存経路を使うので、周囲気温の出所と火の扱いを段階的に足す。各段階は単体で `make check` が通り、ゲームとして壊れない状態にする。

1. **前線撤去と世界温度**。まず前線撤去を独立 PR で終える。`worldstream.Front` と driver の前線処理を撤去し、`frostModifier` を外し、左戻り不可を帯の東進へ従わせて維持する。次にオーバーワールドの基本気温を季節の世界温度へ置き換える。固定 `BaseTemperature` の代わりに `GetSeasonalTemperature` を屋外の基本気温にし、既存の体温システムがそのまま季節の寒さを効かせる。ダンジョンはこの段階では現行のステージ定義の基本気温のままで、世界温度による緩和は段階2で足す。屋外と屋内を分ける `IsOnOverworld` の分岐が段階2の `AmbientTemperatureAt` へ育つ。
2. **ダンジョンの温度を世界温度で和らげる**。`AmbientTemperatureAt` を足し、ステージ種別で周囲気温を出し分ける。ダンジョンはステージの温度設定を世界温度で和らげた値にし、屋外より厳しくしない。屋内退避で寒さが和らぐ非対称が生まれる。タイルごとの屋内外判定は作らない。焚き火はこの段階では現状の周囲気温補正のまま。
3. **焚き火をプレイヤーへ直接**。焚き火を周囲気温の `tileModifier` から外し、熱源のそばのプレイヤーの低体温タイマーへ固定回復を加える形へ移す。屋内で焚くほうが得、という非対称を仕上げる。

以降の吹雪・枯渇 pull・危険度合成は別 doc で、この土台の上に積む。

## 採用しなかった方法

- **寒波前線を残す**。却下。時間駆動の強制押し出しは agency を奪う。屋外の常時気温へ置換し、退避先として屋内を用意する。
- **部屋ごとに室温を持ち蓄熱をシミュレートする**。却下。部屋検出と毎ターンの熱収支は実装と検証が重い。ステージ種別と温度設定だけで「屋内は寒さが和らぐ」は十分に出る。蓄積はプレイヤーの体温タイマーが既に担う。
- **タイルごとに屋内外を判定する。`IsIndoorAt` や部屋検出を持つ**。却下。ダンジョンは全体が屋内、オーバーワールドは全体が屋外なので、現在のステージ種別で足りる。タイルの連結探索も外縁定義も要らない。
- **ダンジョンの温度を世界温度と無関係の独立値にする**。却下。世界の底冷えが時間帯で揺れるのにダンジョンだけ固定だと、夜にダンジョンのほうが寒いといった逆転が起きうる。ダンジョンは世界温度に暖かさを足した相対値にし、常に屋外より暖かいを保つ。
- **焚き火を周囲気温の温度補正のままにする**。却下。周囲気温を上げる形だと、火の恩恵が体温進行の式や断熱と絡んで屋内外の差が読みにくい。火はプレイヤーの体温へ固定回復で直接効かせ、周囲気温の奪われる速さと分けて考えられるようにする。もたらす熱量は屋内外で同じ、奪われ方だけが屋内外で違う、という切り分けにする。
- **前線の破棄機構を流用したまま前線だけ止める**。却下。破棄が時間で東進し続け、止まった前線と齟齬が出る。破棄はプレイヤー到達位置に従わせ、時間駆動から切り離す。

## コメント

- 世界温度のベースとダンジョンの温度設定の値。世界が強すぎると装備前に削られ、ダンジョンが暖かすぎると退避が楽すぎる。装備の断熱と体温進行の兼ね合いで実プレイ調整する。
- 焚き火の固定回復量。屋外で焚いてやっと相殺、屋内で焚いて回復が上回る、という関係に収める。
- 世界温度がダンジョンへどれだけ効くか。世界の寒さをそのまま足すか割り引くか、ダンジョンが屋外の揺れをどこまで受けるかの度合いを調整する。
