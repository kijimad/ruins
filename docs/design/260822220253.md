# 温度モデル: 前線を廃し、屋外の底冷えと屋内退避を持つ

## 背景

現状の気候圧力は寒波前線 `worldstream.Front` ただ1本に集約されている。幅を持つ極低温ゾーンが総ターン数に応じて東進し、居座るとプレイヤーを飲む。破棄と進入不可ラインもこの前線に統合されている。前線は「後ろから押す強制移動」であり、これがゲーム唯一の実効的な気候圧になっている。

問題は2つ。第一に、前線以外の気候ペナルティが弱く、屋外での探索や滞在にコストが無い。前線から離れていれば自由に振る舞える。第二に、移動が前線による強制であってプレイヤーの意思でない。押されて動くので agency が薄い。

目指すのは、屋外が常時寒く、屋内へ退避すると寒さが和らぐ温度モデル。屋外の寒さが滞在にコストを課し、屋内が休息の場になる。この非対称が「寒い外を進み、暖かい中で立て直す」というリズムを生む。ただしそのために部屋ごとの室温を丸ごとシミュレートするのは重い。ここでは室温を持たず、プレイヤーが今いる場所の屋内外だけで寒さの速さを変える最小のモデルにする。

この doc は温度モデル全体を設計し、実装は作業ステップで PR を分ける。吹雪の周期イベント、資源枯渇による自主移動、危険度軸との合成は、この温度の土台の上に別 doc で積む。

この doc は spawn の危険度軸を扱う [260822014350](260822014350.md) とは別軸。危険度は敵とアイテムの湧きを、温度は寒暖と生存を扱う。

## 要件

**Hard**

- 寒波前線を廃す。総ターン数に応じた強制的な空間押し出しをやめる。
- 屋外は常時寒い。位置と時刻の決定論で導く底冷えを課し、だらだらした滞在に体温コストを乗せる。屋外の気温は保存しない。
- プレイヤーが今いるタイルが屋内か屋外かを判定する。壁で外気から遮蔽されていれば屋内、外気に通じていれば屋外。部屋ごとの室温は持たない。
- 屋内と屋外の気温差は固定の計算式で出す。屋内は屋外より一定ぶん暖かいだけで、蓄積も履歴もない。これが体温の奪われる速さを決める。屋内ほど遅い。
- 焚き火などの熱源は室温を変えず、プレイヤーの体温へ直接効く。もたらす熱量は屋内でも屋外でも同じ。屋内は奪われる量が少ないので、屋内で焚くほど得になる。
- 寒暖の効果は既存の体温システムに載せる。`updateTemperatureConditions` が env 気温と装備の断熱から低体温を進める経路をそのまま使い、env 気温の出所を屋内外で切り替えるだけにする。
- 左へは戻れない制約を維持する。破棄と進入不可の境界を前線の時間東進から切り離し、プレイヤーの東進に従わせる。西戻り不可はそのまま残す。

**Soft**

- 屋内判定は毎ターン安く済ませる。プレイヤーのタイル1点を見れば足りるので、全タイルの部屋分けはしない。
- 逃げ場なしの理不尽を避ける。屋外でも火を焚けば体温を保てる余地を残し、屋内退避を唯一解にしない。

## 設計

### 温度の出所

タイルの環境気温 env は、屋外 ambient に屋内ぶんの固定補正を足すだけで出す。部屋ごとの室温という状態は持たない。

```go
// EnvTemperatureAt はタイルの環境気温を返す。屋外 ambient に、屋内なら固定の暖かさ補正を足す。
// 室温の状態は持たず、屋内外の別と決定論の屋外 ambient だけで決まる。
func EnvTemperatureAt(world w.World, x, y consts.Tile) (int, error)
```

屋外 ambient は決定論で保存不要、屋内補正は固定値。どちらも履歴に依存しないので、状態として持つものは無い。

### 屋外 ambient と前線の撤去

`worldstream.Front` と、driver の `frontCfg`・`UpdateFront`・`front()` を撤去する。温度計算からは前線寄与の `frostModifier` を外す。前線が担っていた時間東進の極寒ゾーンを無くし、強制押し出しを消す。

屋外 ambient は現状の `baseTemp + timeModifier` を土台にする。屋外ステージの `BaseTemperature` を常時寒い値へ下げ、時間帯補正 `timeModifier` が日内の揺れを残す。位置と時刻だけで決まり保存しない。

### 屋内と屋外の判定

プレイヤーが今いるタイルが、壁で外気から遮蔽された内側か、外気に通じる外かを判定する。あるタイルから壁を越えずに辿れる連結領域が、マップ外縁や開けた空へ通じていれば屋外、壁で閉じていれば屋内。

```go
// IsIndoorAt はタイルが壁で外気から遮蔽された屋内かを返す。屋内なら true、屋外なら false。
// 部屋を作らず、問われたタイルの屋内外だけを答える。主にプレイヤーの現在地に対して呼ぶ。
func IsIndoorAt(world w.World, x, y consts.Tile) bool
```

判定は問われたタイル1点に閉じる。部屋オブジェクトも RoomID も持たない。連結の探索が重ければ結果をタイルへキャッシュし、壁の増減とロードで無効化する。

屋外の定義は世界で異なる。ダンジョンはタイルが有限なので、壁を越えずマップ外縁へ辿れれば屋外とする。オーバーワールドはシームレス帯で外縁を持たないので、外縁到達でなく、壁で閉じた建物の内側だけを屋内とし、それ以外の開けた地面を屋外とする。段階2ではこの建物の閉じた空間を屋内判定の主対象にし、外縁定義に依存する探索はダンジョン側に閉じる。

### 屋内は固定式で暖かい

env 気温は、屋内なら屋外 ambient に固定の暖かさ補正を足す。補正は定数で、部屋の広さや密閉度では変えない。屋内は屋外より一定ぶん暖かいだけ。これで屋内は低体温の進みが遅くなる。屋外との差は固定なので、蓄積も平衡もない。

### 体温の効果は既存経路へ

`EnvTemperatureAt` が返す env 気温を、既存の `updateTemperatureConditions` へ渡す。装備の断熱と体温進行倍率から `HealthStatus` の低体温タイマーが進む経路は変えない。env が低いほどタイマーが早く進み、高いほど遅い。屋内は env が高いので進みが遅い。凍傷も既存の体温割れの経路をそのまま使う。温度の出所を屋内外で切り替えるだけで、効果側は無改造で載る。

### 焚き火はプレイヤーの体温へ直接

焚き火などの熱源は env 気温を変えない。代わりに、熱源のそばに居るプレイヤーの低体温タイマーへ固定の回復を毎ターン加える。回復量は屋内でも屋外でも同じ。

env 由来の奪われる速さと、火由来の回復は別々に効く。屋内は env が高く奪われが遅いので、同じ火でも回復が上回りやすい。屋外は env が低く奪われが速いので、火はやっと相殺する程度。結果として、火をもたらす熱量は屋内外で同じなのに、屋内で焚くほうが得になる。

「そば」の判定は既存の熱源の仕組みを流用する。焚き火は `TileTemperature` を持つエンティティで、現状 `getTileTemperatureAt` がプレイヤーのタイルの熱源寄与を合算している。段階3ではこの合算を env へ足すのをやめ、同じ熱源寄与をプレイヤーの低体温タイマーの回復量へ回す。新たな近接判定は足さない。

### 左戻り不可の維持

現状 `worldstream.Front` の極低温ゾーン西端 `ColdZoneWest` が破棄と進入不可ラインを兼ねる。前線を廃すが、この境界の役割は残す。境界を前線の時間東進から切り離し、帯ストリーミングのプレイヤー東進に従わせる。到達した最西端より西へは戻れず、破棄済みチャンクは復元しない。境界は時間で自走せず後退の封じ込めだけを担うので、強制押し出しにはならない。保持の具体形は帯の西端の流用か薄い境界状態かを実装で確定する。

## 実装の段階

温度モデルを一度に入れると差分が大きく検証しづらい。効果側は既存経路を使うので、env 気温の出所と火の扱いを段階的に足す。各段階は単体で `make check` が通り、ゲームとして壊れない状態にする。

1. **前線撤去と屋外 ambient**。`worldstream.Front` と driver の前線処理を撤去し、`frostModifier` を外す。屋外ステージの `BaseTemperature` を下げる。左戻り不可を帯の東進へ従わせて維持する。この段階では全域を屋外扱いにするので、屋内でも寒い。既存の体温システムがそのまま寒さを効かせる。
2. **屋内と屋外の判定と固定補正**。`IsIndoorAt` を足し、`EnvTemperatureAt` が屋内タイルに固定の暖かさ補正を足すようにする。屋内退避で寒さが和らぐ非対称が生まれる。焚き火はこの段階では現状の env 補正のまま。
3. **焚き火をプレイヤーへ直接**。焚き火を env の `tileModifier` から外し、熱源のそばのプレイヤーの低体温タイマーへ固定回復を加える形へ移す。屋内で焚くほうが得、という非対称を仕上げる。

以降の吹雪・枯渇 pull・危険度合成は別 doc で、この土台の上に積む。

## 採用しなかった方法

- **寒波前線を残す**。却下。時間駆動の強制押し出しは agency を奪う。屋外の常時気温へ置換し、退避先として屋内を用意する。
- **部屋ごとに室温を持ち蓄熱をシミュレートする**。却下。部屋検出と毎ターンの熱収支は実装と検証が重い。プレイヤーの現在地の屋内外と固定補正だけで「屋内は寒さが和らぐ」は十分に出る。蓄積はプレイヤーの体温タイマーが既に担う。
- **屋内の気温を屋外との差でなく独立の値にする**。却下。屋外の底冷えが時間帯で揺れるのに屋内だけ固定だと、夜に屋内のほうが寒いといった逆転が起きうる。屋内は屋外に固定補正を足す相対値にし、常に屋外より暖かいを保つ。
- **焚き火を env の温度補正のままにする**。却下。env を上げる形だと、火の恩恵が体温進行の式や断熱と絡んで屋内外の差が読みにくい。火はプレイヤーの体温へ固定回復で直接効かせ、env の奪われる速さと分けて考えられるようにする。もたらす熱量は屋内外で同じ、奪われ方だけが屋内外で違う、という切り分けにする。
- **前線の破棄機構を流用したまま前線だけ止める**。却下。破棄が時間で東進し続け、止まった前線と齟齬が出る。破棄はプレイヤー到達位置に従わせ、時間駆動から切り離す。

## コメント

- 屋外ベース気温と屋内補正の値。屋外が強すぎると装備前に削られ、屋内補正が大きすぎると屋内が安全すぎる。装備の断熱と体温進行の兼ね合いで実プレイ調整する。
- 焚き火の固定回復量。屋外で焚いてやっと相殺、屋内で焚いて回復が上回る、という関係に収める。
- 屋内判定の更新契機。壁の増減とロードで再評価すれば安いが、破壊可能な壁があると頻度が上がる。破壊の頻度を見てキャッシュ無効化の粒度を決める。
- 屋内外の判定を敵にも適用するか。当面はプレイヤーだけ効けば十分で、敵は屋外扱いのままでもよい。必要が出たら同じ `IsIndoorAt` を敵へ広げる。
