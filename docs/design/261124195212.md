# 湖の区域

## 背景

地上に川・湖・沼のような水面が無い。最初は絶対タイル座標のノイズで湖と沼を荒れ地へ撒いたが、人の手が入った土地に水たまりが散らばるのは現実的でなく、飾りにしかならなかった。

水面は、研究所や発電所と同じ区域として作る。地図の上で1つのエリアに見える大きな湖があり、その周りに湖のための施設が建ち、桟橋が湖へ伸びる。湖が水力発電所や釣り場やキャンプ場の理由になり、北へ進む道中で寄り道する先になる。

水面のタイルは別に用意する。浅瀬 `water_shallow` と深い水 `water_deep` で、どちらも通れ、移動コストは浅瀬 100、深い水 300 を標準の移動に上乗せする。上に立つと水中、隣に立つと水辺の冷えを受ける。

## 要件

- 地図の上で1つのエリアとして見える大きな湖が、研究所や発電所と同じ間隔で北への道中に現れる
- 湖の周りに、湖のための施設が建つ。釣り小屋・広場・キャンプ場・水力発電所
- 湖の岸から桟橋が湖へ伸びる
- 湖の中を街路や道が横切らない。区域の門から入り、岸を回って施設へ行ける
- 湖の岸の線は、チャンクの格子に沿った直線にならない
- 俯瞰図で湖とわかる記号が出る
- 新しい種類は raw の行と絵とパレットで足す。コードは部品だけにする

## 設計

今の区域の仕組みに、2つの部品を足す。水で満たす層と、湖へ向く施設である。湖の区域はこの2つと raw の行で組む。

### 今の区域の仕組み

区域は数チャンク四方の長方形で、`spacing` チャンクのリージョンごとに1つ当選する。地区の並べ方 `pattern` が `rings` なら外の層と内の層の2層になる。層ごとの `zones` がそのチャンクに建てる施設の組を決め、施設は施設の絵を1枚ずつ置く。区域の全てのチャンクは北と西の辺に幅4の街路を持ち、施設の絵は残りの 20x20 に置く。目玉の施設 `landmark` はその層のチャンクの外接矩形の中央に置く。道は区域に入らず、北と南の門の前までつなぐ。

### 層の構成

`rings` の2層で組む。

| 層 | 中身 |
|---|---|
| 内の層 | 湖。水で満たし、街路も施設も置かない |
| 外の層 | 岸。釣り小屋・広場・キャンプ場・水力発電所。湖に接するチャンクの施設は湖へ向き、桟橋を湖へ伸ばす |

湖に接しない外の層の角のチャンクには、湖へ向かない施設を置く。広場やキャンプ場の向かない版にする。

### データ

層に、水で満たす印を足す。

```go
// 変更前
type DistrictLayer struct {

	Rows  *int     `json:"rows,omitempty"`

// 変更後
type DistrictLayer struct {
	// 水で満たす層では省く
	Zones []ZoneId `json:"zones,omitempty"`

type DistrictWater struct {

	Deep    EntityID `json:"deep"`

	Beach   EntityID `json:"beach"`

	ShallowWidth int `json:"shallowWidth"`

	Wobble int `json:"wobble"`
}
```

### 水で満たす層の描き方

水で満たす層のチャンクは、施設の絵を置かずに手続きで描く。岸の向きは保存せず、描くときに上下左右と斜めの隣のチャンクが水の層かどうかから導く。

- チャンク全体を深い水にする。タイルはオートタイルしないものを置くので、行の仕様どおり添字を付けずに置く
- 水で満たさない隣のチャンクへ向く辺は、外から順に、土の浜 `Beach` マス、浅瀬 `ShoreWidth` マスにする。浜は隣の岸のチャンクの街路と湖の間を空け、水際が街路に直に接しないようにする
- 隣も水の層の辺には浜も浅瀬も付けないので、湖の中はチャンクの境目なしに深い水が続く
- 上下左右の隣は水の層で、斜めの隣だけが水でない角は、その角を丸く浅瀬と浜にする。斜めの隣の岸のチャンクの角が、湖の角へ尖って突き出さない
- 浅瀬の幅は、絶対タイル座標の値ノイズで `Wobble` マスだけ増減させる。浜の幅は揺らさない。岸の線がチャンクの格子に沿った直線にならず、座標の純関数なので隣のチャンクとも途切れずにつながる
- 街路の帯を引かず、敵も湧かせない

### 大きさと優先順

区域の大きさは 7x7 にし、湖は中の 5x5 になる。`rings` は中心の層を短い辺から決めるので、正方形でないと外の層が長い辺の側で2チャンクの厚さになる。外の層を幅1の輪に保つため、正方形だけにする。

区域は raw の行の順が優先で、先の種類の区域と重なるか隙間なく接すると、後の種類は丸ごと出ない。帯は9列で、幅7の湖の区域は先の区域とほぼ必ず近くなる。最後に置くと一度も出ない。発電所の後に置くと、およそ250行に1度出て、研究所・軍の基地・発電所の出方は変わらず、町と農場が2割ほど減る。

### 湖へ向く施設

外の層のチャンクのうち、上下左右のどれかに水の層のチャンクが接するものを岸のチャンクと呼ぶ。

- 岸のチャンクでは、`FacingWater` の施設を優先して選ぶ
- 施設の絵は、北の辺を水の側にした1枚だけを描く。描画のときに絵を回し、北を隣の水の層の向きへ向ける。今の施設の絵は向きを乱数で決めているが、湖へ向く施設だけは向きを決めて回す
- 岸のチャンクも、施設の絵より先に、水の層の側の辺へ浜と浅瀬を手続きで描く。描き方は水の層の縁と同じで、水の層の浅瀬とつながる。施設の絵は水際のマスを地形の予約語 `ground` にして下の浜と浅瀬を残し、桟橋の板と建物のマスだけを上書きする。岸の線は絵でなく手続きが決めるので、どの岸のチャンクでも水際が揃う
- 水の層が2方向に接する岸のチャンクは、どちらか一方へ向ける。南と北を西と東より先にする
- 区域の全てのチャンクは北と西の辺に街路を持つ。湖が岸のチャンクの北か西にあると、施設と水の間に岸のチャンク自身の街路が挟まり、南か東にあると施設が浜に直に接する。この非対称の扱いは決めることに挙げる

### 街路と道

- 水で満たす層には街路の帯を引かない
- 外の層には今どおり街路を引く。外の層は湖を囲む輪なので、街路も湖を囲んで一周し、門から全ての岸のチャンクへ行ける
- 道は今どおり北と南の門の前までつなぐ。区域の中へは入らない
- 塀は巡らせない。湖畔は開けた土地にする

### 目玉の施設

水力発電所を目玉にする。今の目玉は層のチャンクの外接矩形の中央に置くので、外の層では中央が湖になって置けない。湖の区域では、目玉を外の層の南の辺の中央に置く。南の門の側で、道から最初に見える位置になる。区域の幅が偶数で中央が2チャンクになるときは、今の目玉の中央の丸め方に合わせる。

### 俯瞰図

水で満たす層のチャンクは、湖の記号を出す。今の記号は施設の id で引くので、水の層には施設が無い。区域の行の id に `_water` を付けた記号の行を引く。

### 施設

| 施設 | 層 | 湖へ向く | 中身 |
|---|---|---|---|
| 水力発電所 `hydro_plant` | 外 | 向く | 目玉。湖の水を引く取水口と発電機の部屋 |
| 釣り小屋 `fishing_hut` | 外 | 向く | 小さな小屋と桟橋。釣り道具と保存食 |
| 桟橋 `pier` | 外 | 向く | 建物の無い長い桟橋と係留の小舟 |
| 広場 `lakeside_plaza` | 外 | 向かない | 舗装の広場と長椅子 |
| キャンプ場 `campsite` | 外 | 向かない | 焚き火の跡とテント |

### 進め方

3段に分ける。各段は単独で地図に出せる。

1. 湖と岸だけの区域。水で満たす層と俯瞰図の記号を作り、外の層には広場とキャンプ場を置く
2. 湖へ向く施設。`FacingWater` と回す向きの決め方を作り、釣り小屋と桟橋を足す
3. 水力発電所を目玉にし、外の層の南の辺に置く

## 採用しなかった方法

| 案 | 理由 |
|---|---|
| 荒れ地にノイズで湖と沼を撒く | 人の手が入った土地に水たまりが散らばるのは現実的でなく、飾りにしかならない。湖を目当てに建つ施設も置けない |
| 湖のチャンクも施設の絵で描く | 隣が湖か岸かで縁の浅瀬の有無が変わり、組み合わせの数だけ絵が要る。手続きで描けば辺ごとに決められる |
| 新しい並べ方 `pattern = "lake"` を足す | 内の層と外の層の2層は `rings` と同じで、違うのは層の中身だけである。層に印を足せば並べ方を増やさずに済む |
| 湖を区域でなく原野の点在ランドマークにする | ランドマークは1チャンクの地物で、地図の上で1つのエリアに見える大きさにならない。周りに施設を建てる層も持たない |
| 道を湖の中に通し、橋で渡る | 区域の中を道が通らない今の決まりから外れる。湖を回り込む岸の街路で足りる |
| 湖を地図全体のノイズのしきい値で決め、つながった範囲を塗り、小さいものを捨てる | 湖の大きさと位置が道の計画や区域の間隔と無関係に決まり、区域や集落と重なる。区域として抽選すれば、他の区域との間隔と道からの入口が今の仕組みのまま保てる |
| 岸の線を、辺を押し込んだ線分の中点を乱数でずらして分割して作る | チャンクごとの乱数で描くと、隣のチャンクとの境目で岸の線が食い違う。絶対タイル座標の値ノイズなら境目で連続する |
| 川も一緒に作る | 帯をまたいで1本につながる曲線の経路と、道と交わる所の橋が要る。湖の区域とは別の段で、湖へ流れ込む川として足す |

## コメント

水域の生成は Cataclysm: Dark Days Ahead を参考にした。岸の向きを隣から導くこと、水と陸の間に浜を挟み角を丸めること、先に岸を描いてから施設の絵を重ねることを借りた。
https://github.com/CleverRaven/Cataclysm-DDA/blob/344bfc4ecd31917628363492a0485f0113de0a15/src/mapgen_functions.cpp

決めることを挙げる。

- 区域の大きさと間隔。7x7 で、優先順は発電所の後に決めた
- 外の層の幅。今の `rings` は外の層を1チャンクの輪にする。湖を大きく見せるため、外の層を細くする仕組みが要るか
- 湖の中の島や、凍った湖面を渡れる冬の扱い
- 釣りの行為。釣り小屋を置くなら釣りを遊びとして足すか、置物と戦利品だけにするか
- 湖の敵。水辺の生き物を湧かせるか
- 岸のチャンクの街路と水の向き。a 岸のチャンクは水の側の辺の街路を引かず、輪の街路が切れないか確かめる、b 街路を挟む前提で桟橋の絵を街路の幅だけ長くする、c 水の側の街路を浜として扱う、のどれにするか
- 敵の AI と経路探索は移動コスト `PassCost` を見ず、通れるかだけで道を選ぶ。敵は深い水へも避けずに入り、1歩に移動コストを払う。敵にも水を避けさせるか
- 深い水の1歩は標準の移動と合わせて AP を 400 使う。AP の最大値と比べて何ターン止まるかを確かめ、移動コストを調整する

注意すること。

- 移動のたびに移動先の移動コストを数える `getPassCostAt` は、`PassCost` を持つ実体を全て走査する。今は移動コストを持つ置物とタイルが少ないが、湖の内の層が 3x3 チャンクならおよそ5000枚の水面のタイルが移動コストを持ち、1歩ごとの走査が重くなる。ベンチで確かめる前から、座標から引く索引に載せるか、タイルの分は行から引く形を前提にする
