# 通貨に専用型 consts.Currency を導入する

## 背景

通貨は現在すべて素の `int` で扱われている。`Wallet.Currency`、`query` の `AddCurrency`/`GetCurrency`/`ConsumeCurrency`/`HasCurrency`、`FormatCurrency`、ショップの価格、HUD、通信販売オークションが個別に `int` を回している。専用型が無いため、重量と金額のような単位の取り違えをコンパイラが弾けない。例えば `AddCurrency(world, e, weightKg)` のような誤りが型検査を素通りする。

一方でリポジトリには名前付き int 型の定石がすでにある。重量の `consts.Milligram`、座標の `consts.Tile`、時間の `consts.Turn` である。`Milligram` は「整数で正確に演算し、float 変換と表示整形を型の内部に閉じる」設計で、通貨にそのまま適用できる。

## 要件

- 挙動を変えない。金額の計算結果は現状と一致する。
- 演算は int のまま正確に行う。float 化しない。丸め誤差を持ち込まない。
- 表示整形はカンマ区切りと通貨記号を型のメソッドに集約する。呼び出し側に散らさない。
- リポジトリ全体へ一貫適用し、`int` と `consts.Currency` の変換境界を残さない。
- 担保は `make check` で完結する。型不整合はコンパイルで止まる。

## 設計

`consts.Currency` を名前付き int 型として定義し、`query.FormatCurrency` のカンマ区切りと通貨記号を `String()` へ移す。`Milligram.String()` と同じ形にする。

```go
// internal/consts/currency.go
type Currency int

// String はカンマ区切り + 通貨記号で整形する。query.FormatCurrency から移設する。
// float 変換や整形はこの内部だけに閉じ、演算は Currency の int で行う。
func (c Currency) String() string { /* 3桁区切り + IconCurrency */ }
```

主要な型の変更前後を示す。

```go
// 変更前
type Wallet struct { Currency int }
func AddCurrency(world w.World, e ecs.Entity, amount int) error
func FormatCurrency(amount int) string

// 変更後
type Wallet struct { Currency consts.Currency }
func AddCurrency(world w.World, e ecs.Entity, amount consts.Currency) error
// 整形は consts.Currency.String() に集約し、FormatCurrency は廃止するか薄いラッパにする
```

## 採用しなかった方法

- **部分適用**。コア通貨層やオークションだけを型付けし、ショップや HUD を `int` のまま残す案。呼び出し口に `int` と `consts.Currency` の変換境界が残り、かえって読みにくくミスの温床になる。一貫適用で境界を消す。
- **float 化**。金額を float で持つ案。丸め誤差が積算で表面化する。`Milligram` 同様、整数で正確に扱い表示だけ整形する。

## コメント

- `consts.Milligram` が手本。整数演算と表示整形の分離、単位取り違えの型検知という利点をそのまま得る。
- 純粋に機械的な型付けで挙動は変わらない。着手時は `make check` で型不整合を洗い切る。
- 別セッションで一括着手する想定。範囲はリポジトリ全体で確定済み。
