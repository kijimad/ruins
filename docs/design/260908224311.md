# 右上のHUD地図をミクロ地図から大域地図へ変える

## 背景

画面右上のHUD地図は現在ミクロ地図である。`internal/widgets/hud/minimap.go` の `Minimap.Draw` が、現ステージの探索済みタイル `ExploredTiles` をプレイヤー中心の相対座標で描く。縮尺は 1タイル = 3px、パネルは 150x150px なので、見えるのはプレイヤー周辺 ±25 タイル程度に限られる。

一方、大域地図は別に存在する。`internal/states/overworld_map.go` の `OverworldMapState` が、シームレスワールドの帯 `SeamlessBand` を源に、1チャンク = 1セルの俯瞰図を N キーで全画面表示する。各チャンクの種別文字は `overworld.ChunkPlace(runSeed, coord, rows)` が純関数で決め、ECS タイルを生成せずに算出できる。プレイヤーとキューブのマーカーも既にある。

移動拠点キューブはオーバーワールドを運転して移動する拠点なので、その位置はタイル粒度の局所地図よりチャンク粒度の大域地図で捉えるほうが自然である。右上に常時見える地図を大域地図にすれば、運転中に自分とキューブが世界のどこにいるかを俯瞰しながら進める。

現状の2つの地図は描画部品を共有していない。ミクロ地図は `uicore.Canvas` でタイルを、大域地図は `ebiten` の `vector`/`text` でチャンクを描く別実装で、チャンクの窓構成・glyph 生成・キューブ/プレイヤーのチャンク割り出しが `OverworldMapState` に直書きされている。

## 要件

- 右上のHUD地図を、ミクロ地図でなくチャンク粒度の大域地図にする。
- 大域地図にキューブを表示する。プレイヤーの現在地マーカーも出す。
- 右上に出すのは N キーで開く地形レベルの俯瞰図と同じチャンク粒度の地図にする。ただし全域は出さず、プレイヤーの近傍だけを大きく描く。近傍はプレイヤーを中心にした数チャンクぶんの窓にする。
- 最初から全域を見せず、探索で徐々に開く。タイル単位のフォグ `ExploredTiles` をチャンク粒度へ畳み込み、探索済みチャンクだけを地形表示する。未探索は伏せる。
- 全画面の N キー俯瞰図は帯全体を窓にするが、フォグは HUD と同じで探索済みチャンクだけを開放する。可視範囲を両地図でそろえる。窓は全域か近傍かで作り分け、フォグは共通にする。
- オーバーワールド外、すなわち `SeamlessBand` が無いダンジョン内部などでは、地図パネルごと出さない。"No Data" の空表示も出さない。ミクロ地図へのフォールバックも持たない。
- オーバーワールドでは階層番号を出さない。階層は深さの概念で、地上の帯には無いため。ダンジョンでは従来どおり階層を出す。
- 全画面の `OverworldMapState` と HUD の大域地図で、窓構成・glyph 生成・マーカー割り出しを共有し、二重実装をなくす。

## 設計

### 全体方針: 描画モデルを純関数へ切り出して共有する

`OverworldMapState` に直書きされているチャンク窓の構築ロジックを、`internal/overworld` の純関数へ切り出す。切り出すのは「どのチャンクにどの glyph が立ち、プレイヤーとキューブが窓内のどのセルにいるか」という描画モデルであって、ピクセルの描き方ではない。全画面ステートと HUD ウィジェットは、この同じモデルを各自の基盤で描く。ピクセル描画は共有せず、モデルだけを共有するのが責務の切れ目である。

`overworld` パッケージは `components` に依存しないので、ビルダは `SeamlessBand` を直接受けずプリミティブを受ける。呼び出し側が `SeamlessBand` からプリミティブを取り出して渡す。

```go
// MacroWindow はマクロ地図の窓。左端の絶対チャンク列と、窓の列数・行数をチャンク単位で持つ。
// 全画面図は overworld.FullBandWindow で帯全体を、HUD は overworld.PlayerCenteredWindow で
// プレイヤー中心の近傍を渡す。窓は overworld のヘルパで帯プリミティブから組む。
type MacroWindow struct {
	OriginX consts.Chunk // 窓左端の絶対チャンク列
	Cols    int          // 窓の列数
	Rows    consts.Chunk // 窓の行数。帯の Rows と同じ
}

// MacroCell は窓内1チャンクの表示情報。今は glyph だけを持つ。色は glyph から引く。
type MacroCell struct {
	Glyph rune
}

// MacroView はマクロ地図の描画モデル。窓内のチャンク格子と、マーカーの窓ローカル座標を持つ。
type MacroView struct {
	Cells      [][]MacroCell                // [row][col] の glyph 格子
	PlayerCell consts.Coord[consts.Chunk]   // 窓ローカル (列,行)。窓外なら {X:-1}
	CubeCells  []consts.Coord[consts.Chunk] // 窓ローカルのキューブ位置。窓内のものだけ
}

// BuildMacroView は帯のプリミティブとプレイヤー・キューブのタイル座標から、指定窓のモデルを組む。
// ChunkPlace を窓の全チャンクへ適用し、マーカーはタイル座標をチャンク幅で割って窓ローカルへ移す。
func BuildMacroView(
	runSeed uint64,
	chunkW, chunkH consts.Tile,
	win MacroWindow,
	playerTile consts.Coord[consts.Tile],
	cubeTiles []consts.Coord[consts.Tile],
) MacroView
```

`glyphColor` も共有する。現在 `overworld_map.go` に閉じている `glyphColorTable`/`glyphColor` を `overworld.GlyphColor(rune) color.RGBA` として `overworld` へ移し、`LegendGlyphs` を源にした色引きを全画面と HUD の双方から使う。theme 色の直書き重複も消える。

### 全画面ステートの追随

`OverworldMapState.OnStart` の窓構築・glyph 生成・プレイヤー/キューブのチャンク割り出しを `BuildMacroView` 呼び出しに置き換える。全画面は帯全体なので窓は `overworld.FullBandWindow` を渡す。フォグは HUD と同じ `query.DiscoveredChunks` を渡し、探索済みチャンクだけを開放する。`Draw` は未開放セルを描かず背景のまま伏せ、開放済みセルだけを `ebiten` で色と記号で描く。可視範囲を HUD の右上地図とそろえる。

### HUD の大域地図化

HUD 抽出器 `extractHUDData` の地図データ生成を、ミクロ地図からマクロ地図へ差し替える。`query.GetSeamlessBand(world)` を読み、`Active` な帯のときだけデータを組む。プレイヤーの絶対チャンク列を中心に `overworld.PlayerCenteredWindow` で近傍窓を組む。フォグは `query.DiscoveredChunks` が `ExploredTiles` を絶対チャンク座標へ畳み込んだ集合を作り、`BuildMacroView` に渡して未探索チャンクを伏せる。全画面図と同じ関数を共有する。帯が無ければ HasBand=false にし、ウィジェットは地図パネルごと描かない。

```go
// MacroMapData は右上のマクロ地図ウィジェットの描画データ。
type MacroMapData struct {
	HasBand bool             // オーバーワールドにいて帯があるか。偽なら地図パネルごと出さない
	View    overworld.MacroView
	Config  MacroMapConfig   // パネル寸法とセル寸法
	Screen  ScreenDimensions // 右上配置に使う画面サイズ
}

// MacroMapConfig はマクロ地図ウィジェットの寸法。
type MacroMapConfig struct {
	Width, Height int // パネルのピクセル寸法。ミクロ地図と同じ 150x150 を踏襲
	MinGlyphPx    int // セル辺がこのpx以上のときだけ glyph を描く。下回れば地形色セルのみで俯瞰を見せる
}

// 近傍窓の半径は consts.MacroMapChunkRadius。プレイヤーの左右へこのチャンク数を見せる。
// MacroCell は種別文字に加え、探索で開放済みかの Discovered を持ち、未開放セルは伏せてフォグにする。
```

HUD の窓はプレイヤー中心の近傍にする。プレイヤーの絶対チャンク列を中心に、左右へ `consts.MacroMapChunkRadius` チャンクの窓を取る。縦は帯全体を見せる。セルの一辺はパネルに窓が収まるよう `cellPx = min(Width/winCols, Height/winRows)` で毎フレーム算出する。近傍窓なのでセルは大きくなり、`cellPx >= MinGlyphPx` を満たして種別記号も描ける。未開放チャンクは描かずパネル背景のまま伏せてフォグにする。プレイヤーとキューブのマーカーは描く。キューブは自分の拠点なので窓内なら常に出す。

ウィジェットは `Minimap` を大域地図用に作り替える。`MacroView` を `uicore.Canvas` で描く。セルごとに `overworld.GlyphColor(cell.Glyph)` で下地を塗り、プレイヤーセルは枠、キューブセルは `consts.IconCube` を暗色の縁取り付きで `theme.OverworldMapCubeMarker` 色に描く。マーカーの意匠は全画面図の考え方に揃える。`HasBand` が偽なら地図パネルごと描かない。右上への配置ロジックは現行踏襲。

### ミクロ地図の撤去

HUD がミクロ地図を描かなくなるので、`extractMinimapData`・`buildTileColors`・タイル色情報 `TileColorInfo`・`MinimapData` のタイル関連と、`Minimap.Draw` のタイル描画経路を撤去する。`ExploredTiles` を読むのは HUD ミクロ地図だけの可能性が高いが、フォグ描画など他用途が無いか確認し、完全に未使用なら `VisionSystem` の `ExploredTiles` 書き込みごと撤去する。使われていれば残す。判断は実装時に grep で確定する。

## 採用しなかった方法

- **オーバーワールド外でミクロ地図へフォールバックする2モード**: ダンジョン内の局所把握には有用だが、地図の意味が文脈で切り替わり実装も2系統になる。ユーザー判断で単一のマクロ地図に決めたので不採用。
- **HUD にチャンク窓・glyph 生成・キューブ割り出しを重複実装する**: 全画面図と同じロジックが2箇所に散り、片方だけの修正で乖離する。純関数 `BuildMacroView` に集約するため不採用。
- **HUD でも帯全体を出す**: 帯は横長なので 150x150 に全域を収めるとセルが潰れ、地形が細い横帯になる。近傍だけを大きく出すほうが読める。全域はいつでも N キーの全画面図で見られるので、常時表示の右上は近傍に絞る。
- **フォグに専用の保存状態を持つ**: 開放済みチャンクを別コンポーネントに保存する案は、タイル単位のフォグ `ExploredTiles` から常に畳み込めるので不要。読み取り時に導出する。
- **チャンク単位の専用フォグを VisionSystem に足す**: タイル単位のフォグが既にあり、チャンクは「探索済みタイルを1つでも含むか」で導ける。二重の可視管理を増やさない。
- **キューブ位置を保持コンポーネントに持つ**: キューブの `GridElement` から常に割り算で導けるので保持しない。読み取り時に計算する。導出可能な一時状態はコンポーネントにしない方針に沿う。
- **地図描画そのものを共通ウィジェット化する**: 全画面は `ebiten` 直描き、HUD は `uicore.Canvas` と基盤が違い、無理に共通化すると両者の制約が絡む。共有するのは描画モデルだけにとどめる。

## コメント

- OpenAPI/セーブのスキーマ変更は無い。`MacroView` はランタイム専用で永続化しない。tsp 生成や serde 除外の対応は不要。
- 新規 ECS コンポーネントは足さない。`Drivable`/`SeamlessBand` の既存で足りる。
- VRT: 右上地図の見た目が変わるので、HUD を含む state の golden は再生成が要る。ミクロ地図の golden は撤去して強制再生成する。
